# spec: kiln_pp — translation phase 4, the preprocessor

Standard: [cpp], the whole clause: cpp.pre, cpp.cond, cpp.include,
cpp.embed, cpp.module, cpp.import, cpp.replace (including `__VA_OPT__`,
cpp.stringize, cpp.concat, cpp.rescan and cpp.scope), cpp.line, cpp.error,
cpp.pragma, cpp.null, cpp.predefined and cpp.pragma.op.

It also covers the clang extensions that libc++ needs:

- the feature tests `__has_include`, `__has_include_next`,
  `__has_cpp_attribute`, `__has_builtin`, `__has_constexpr_builtin`,
  `__has_feature`, `__has_extension`, `__has_attribute`,
  `__has_declspec_attribute`, `__has_warning`, `__has_embed`,
  `__is_identifier` and `__is_target_*` (in C, `__has_c_attribute`
  replaces `__has_cpp_attribute`: "C mode" below);
- the directives `#include_next`, `#import`, `#warning`, `#ident` and GNU
  line markers;
- the pragmas `#pragma once`, `#pragma clang|GCC ...`, `push_macro` and
  `pop_macro`;
- the builtin macros `__COUNTER__`, `__INCLUDE_LEVEL__`, `__BASE_FILE__`,
  `__FILE_NAME__` and `__TIMESTAMP__`, plus `__DATE__` and `__TIME__`
  (both overridable so that tests are reproducible).

Reference behaviour is clang 19 (`clang++-19 -std=c++26`). Output must
match it byte for byte unless a deviation is listed below.

## Architecture: the core and its hooks

The crate root is `crates/kiln_pp/src`. Its modules are:

| Module | Contents |

| `directive.rs` | Directive dispatch ([cpp.pre]); `#define` / `#undef`; the structure and skipping of `#if` groups; `#include` / `#embed` requests; `#line` and GNU line markers; `#error` / `#warning`, `#ident` and the null directive; the module / import directive markers. |
| `expand.rs` | Macro invocation (a port of clang's `TokenLexer`, `MacroArgs` and `PPMacroExpansion`): argument collection, substitution, `#`, `##`, `__VA_OPT__`, rescan and the hide set, and the builtin macro values. |
| `pragma.rs` | `#pragma` and `_Pragma` (destringize, then re-lex), and the pragmas the core handles itself. |
| `cond.rs` | The `IfEvaluator` hook, `IfContext`, and `StubIfEvaluator`. |
| `ifeval.rs` | `IfEval`, the real `IfEvaluator` (WP-015; a port of clang 19's `PPExpressions.cpp`). |
| `features.rs`, `features_table.rs` | `ClangFeatures` and `FeatureFlag`, clang 19's `FeatureQueries` answers (WP-015); the table is generated by `scripts/gen-features.sh`. |
| `include.rs` | The `IncludeResolver` hook, the request types, and `MemoryResolver` (for tests). |
| `builtin.rs` | The `Builtin` macros, the `FeatureQueries` hook, and the C++26 keyword list. |

| `macros.rs` | `MacroDef` and `MacroTable`. |
| `options.rs` | `PpOptions`. |

| `tok.rs` | `PpTok`: a token plus its preprocessor-only flags. |
| `diag_map.rs` | Maps lexer diagnostics to `kiln_diag` ids. |

The core is complete for everything that does not depend on the outside
world. Each of the following is a trait object installed on the
`Preprocessor`, with a default that is enough for the tests. Later work
packages replace the defaults without changing the core.

### `IncludeResolver`: to be implemented by WP-014 (and WP-016 for `#embed`)

```rust
pub trait IncludeResolver {
    fn resolve(&mut self, sm: &SourceManager, req: &IncludeRequest) -> Option<ResolvedInclude>;
    fn resolve_embed(&mut self, sm: &SourceManager, req: &EmbedRequest) -> Option<EmbedData> { None }
    fn suggest_include(&self, sm: &SourceManager, file: FileId, main_dir: Option<&str>)
        -> Option<String> { None }
}
pub struct IncludeRequest { kind: IncludeKind, name: String, angled: bool,
    includer: Option<FileId>, lookup_from: Option<u32>, name_span: Span, directive_span: Span }
pub enum IncludeKind { Include, IncludeNext, Import, HasInclude, HasIncludeNext }
pub struct ResolvedInclude { file: FileId, lookup_index: Option<u32>, system: bool,
    extern_c: bool }
pub struct EmbedRequest { name: String, angled: bool, includer: Option<FileId>,
    limit: Option<u64>, offset: Option<u64>, name_span: Span, query_only: bool }
pub struct EmbedData { bytes: Vec<u8> }
```

`suggest_include` names a header for a diagnostic (clang
`suggestPathToFileForDiagnostics`); `HeaderSearch` implements it with
`search::suggest_include_name`: the file's path relative to the longest
absolute search directory that is a path prefix of it (a relative one is
skipped: the suggestion is for a header of an imported unit, whose path
clang reads back from the BMI as absolute and compares with the search
directories as written) (`<...>` for a system
directory, `"..."` otherwise), else relative to `main_dir`, else the whole
path quoted; paths are compared absolute (against the working directory)
with `.`/`..` removed. The core calls it for each file it leaves with a
controlling macro and records the result with
`SourceManager::mark_include_guarded` (`#pragma once` does not count, as
in clang 22's missing-import diagnostic).

The core does the following itself:

- parses the header name, whether it is a `header-name` token, a
  macro-expanded string, or `<` pieces `>` ([cpp.include]/7);
- passes the `lookup_index` of the includer as `lookup_from` for
  `#include_next`;
- enforces `max_include_depth`, `#pragma once`, `#import` and the
  include-guard optimization (below). The depth check comes after the
  guard and once skips, so a file that would be skipped is never
  reported as too deep. After the first "#include nested too deeply"
  error, a file that was already entered is not entered again (clang
  `HasReachedMaxIncludeDepth`). This keeps an include cycle with several
  back edges linear instead of exponential (WP-971);
- enters the file and reports `FileChange`.

The core marks a header `extern_c` (line-marker flags `3 4`) when the
resolver says so or when its includer is extern-C itself.

The core records file kinds in the source manager (spec/source.md "File
kinds", WP-063), which kiln_diag uses to suppress warnings in system
headers (spec/diag.md §5.4): the start of an inclusion entered as a
system header (the max of the directory's characteristic and the
includer's), the `system_header` token's expansion location for
`#pragma GCC system_header` (ignored, with a warning, in the main file),
and the line after a line marker (flag 3 or `3 4`, else user; `#line`
keeps the kind). When system warnings are suppressed, `#define` skips
the redefinition checks in a system header, as clang does; under
`-Wsystem-headers` it diagnoses them.

#### Header search (WP-014): `HeaderSearch`, `SearchList`, `HeaderFs`

`kiln_pp::HeaderSearch<F: HeaderFs>` is the clang 19
`HeaderSearch::LookupFile` implementation. It runs over a `SearchList`
and a file system seam: `RealFs` is the disk, and `MemoryFs` is a virtual
tree for tests. The driver builds the list (`spec/driver.md` "Toolchain").

**Realizing the list.** `SearchList::build(specs, cplusplus, fs)`
implements clang `InitHeaderSearch::AddPath`, `Realize` and
`RemoveDuplicates`. It takes `SearchDirSpec { path, group }` in `cc1`
order.

- A nonexistent directory is dropped with an
  `ignoring nonexistent directory` note.
- The list is ordered by group:
  1. `-iquote`;
  2. `-I` (`<...>` searches start here: `angled_start`);
  3. `System`, `ExternCSystem` and the language's `-c-isystem` /
     `-cxx-isystem`, in their order of appearance;
  4. `-idirafter`.
- Duplicates (same directory identity) are dropped within the quote group
  and within the rest. A user directory duplicated by a later system
  directory is the one dropped (`as it is a non-system directory that
  duplicates a system directory`).
- `verbose_text()` is clang's `-v` block, byte for byte.

**Lookup.**

- An absolute name is opened as is. `#include_next` of an absolute name
  finds nothing.
- `"..."`, except `#include_next` from a searched header, first tries the
  includer's directory. The header is named `parent(includer)/name`, or
  `./name` when the includer has no directory part (the working directory
  for `<built-in>`). It inherits the includer's characteristic and has no
  `lookup_index`.
- Then the list is searched from index 0 (`"..."`), from `angled_start`
  (`<...>`), or after the includer's index (`#include_next`). A header
  found there is named `dir/name`, joined without normalization as
  `llvm::sys::path::append` does. It takes the directory's characteristic
  (`User`, `System`, or `ExternCSystem`) and that index.
- A header reached by an absolute path keeps the characteristic it was
  last found with (clang `HeaderFileInfo::DirInfo`).
- The name is the `FileManager` name, so `__FILE__`, line markers,
  diagnostics and `-M` output all spell it as clang does.
  `ResolvedInclude::path` carries the path the lookup found the file by.
  A file is one file (`kiln_source` identity: device and inode), so
  `#pragma once`, `#import` and the guard optimization see it through any
  path, and `__FILE__`, line markers and diagnostics keep the name it was
  first loaded by (clang's `ContentCache::OrigEntry`). The `-M` output
  lists every distinct path an `#include` reached it by, skipped or
  entered (clang's per-`FileID` name and `FileSkipped`; `spec/driver.md`
  "Dependency output").

**Lookup caching (WP-820).** Every query below is a system call on
`RealFs`, which costs most on a slow mount, so header search asks each
question once per run:

- Opened paths are cached, and so is the absence of a path.
- Directory existence is cached (`HeaderFs::is_dir`). A name with
  directory components (`boost/x/y.hpp`) checks each intermediate
  directory under the search directory, outermost first, before opening:
  one missing `dir/boost` rules out every `boost/...` header there with a
  single `stat` (clang checks only the parent directory, through its
  `SeenDirEntries` cache).
- A lookup's result is cached per (name, start index), clang's
  `LookupFileCache`: a repeated `#include` or `#include_next` of a name
  makes no query.
- After the fourth failed lookup in one directory
  (`LIST_AFTER_MISSES`), its listing is read once (`HeaderFs::list_dir`)
  and later names it does not hold are misses without a query. Names
  compare ignoring ASCII case, so a case-insensitive file system never
  gets a false miss. A directory holding a non-ASCII name is never
  answered from its listing, nor is a component that is non-ASCII, `.`,
  `..` or empty. A file created during the run in a listed directory is
  not seen (as with clang's caches).

On a tree with 157 `-I` directories (the WP-824 shape) this cut `-E` from
about 204,000 system calls to about 12,400; `docs/status/header-search-syscalls.md`
has the measurements against clang 19.

**`#embed`.** This is clang `LookupEmbedFile`:

- an absolute name is opened as is;
- for `"..."`, the includer's directory, then the working directory;
- then the `--embed-dir` directories.

**Observer.** `set_observer(SearchObserver)` reports what the `-M` output
needs but the `FileChange` callbacks do not see:

- `SearchEvent::HasInclude { file, path, characteristic }` for each successful
  `__has_include` / `__has_include_next`;
- `SearchEvent::Embed { path }` for each `#embed` / `__has_embed` that
  finds a resource.

**Lookup log (WP-1403).** `HeaderSearch::record_lookups()` makes header
search record what the PCH snapshot's lookup-tolerant search path needs
(spec/pch.md); `IncludeResolver::take_lookup_log` (default
`None`) and `Preprocessor::take_lookup_log` hand it over. A
`LookupLog` holds a table of directory names and, in the order first
seen, one `Lookup` per distinct key, and the search list the lookups
used (`list`, `angled_start`):

- the key: the name; the form (`Include` for `#include`, `#import`,
  `__has_include`, and an `_next` form that starts from the beginning;
  `Next` for an `_next` form that continues after a directory; `Embed`
  for `#embed` and `__has_embed`); `<...>` or not; the includer's
  directory where the form tries it (`"..."` includes and embeds); the
  directory a `Next` continues after;
- the result (`Found`): `Missing`; `Includer` (found relative to the
  includer; it inherits the includer's characteristic, which an earlier
  lookup fixed); `Dir { dir, characteristic }` (found in that search
  directory); `Embed { path }` (the path an `#embed` read).

A result is a function of the key, the search list (and the
`--embed-dir` list) and the file system; the header's characteristic as
header search last found it (`HeaderFileInfo::DirInfo`) is not part of
it, because it follows from earlier results. Lookups of absolute names
are not recorded. `LookupLog::check(list, embed_dirs, fs, known,
same_cwd)` repeats every lookup in order over another list and file
system and returns the first whose result differs, named for `-v`. A
directory of the recorded list that the lookup searched before its
result (and the includer's directory of a `"..."` lookup found
elsewhere) is taken to miss again without a query; a relative one only
when `same_cwd`. It asks
`HeaderFs::is_file` (a `stat`, no read) and, after four misses in one
directory, reads that directory's listing once (`HeaderFs::list_dir`);
`known` names files that are known to exist (the record's file list),
which are not asked about. `MemoryFs` counts its queries, which the
tests pin.

For `#embed` the core parses `limit`, `prefix`, `suffix`, `if_empty` and
their `clang::` / `__x__` spellings. It evaluates `limit` and
`clang::offset` with `IfEvaluator::eval_value`. The resolver returns the
bytes, already cut to size.

The default is `NoIncludes`, which finds nothing.

### `IfEvaluator`: to be implemented by WP-015

```rust
pub trait IfEvaluator {
    fn eval(&mut self, cx: &mut dyn IfContext) -> bool;
    fn eval_value(&mut self, cx: &mut dyn IfContext) -> Option<i64> { /* stub grammar */ }
}
pub trait IfContext {
    fn next(&mut self) -> Token;            // macro-expanded; ends with Eod
    fn next_unexpanded(&mut self) -> Token; // the operand of `defined`
    fn is_defined(&mut self, name: Symbol) -> bool;
    fn spelling(&self, tok: &Token) -> String;
    fn interner(&self) -> &Interner;
    fn source_manager(&self) -> &SourceManager;
    fn emit(&mut self, diag: Diag);
    fn is_enabled(&self, id: DiagId) -> bool;
    fn std(&self) -> Std;
}
```

The core keeps the structure of conditional groups: nesting, skipping
(clang's `SkipExcludedConditionalBlock`), `#elifdef` and `#elifndef`, and
the unterminated-conditional and stray-`#else` diagnostics. Only the
value of an expression comes from the evaluator. The `__has_*` operators
expand as builtin macros before the evaluator sees them, as in clang.

`StubIfEvaluator` handles integer literals, `true` and `false`,
identifiers (which are 0), `defined`, parentheses, the unary and binary
operators, and `?:`, in wrapping `intmax_t` arithmetic. It warns when a
macro expansion produces `defined`. Anything else reports
`pp_expr_unsupported`. It remains for hook tests only.

#### `IfEval` (WP-015): the default evaluator

```rust
pub struct IfEval { /* EncodingParams */ }
impl IfEval {
    pub const fn new(params: EncodingParams) -> Self;
    pub fn for_triple(triple: &str) -> Self; // aarch64*/arm64* Linux, *-windows-*, else x86-64 Linux
    pub const fn params(&self) -> EncodingParams;
}
impl Default for IfEval { /* x86-64 Linux */ }
impl IfEvaluator for IfEval { .. }
```

`Preprocessor::new` installs `IfEval::default()`; a driver installs
`IfEval::for_triple(<target>)`, because the signedness and width of
`char` and `wchar_t` decide the value of character literals. `IfEval`
is a port of clang 19's `PPExpressions.cpp` and is normative in the
following respects ([cpp.cond]/13):

- **Values.** Every operand is a 64-bit value with a signedness flag
  (`intmax_t` / `uintmax_t`). Integer literals are typed as in
  [lex.icon] but only signed or unsigned matter: a decimal literal that
  does not fit `intmax_t` is unsigned with the warning "integer literal is
  too large to be represented in a signed integer type, interpreting as
  unsigned" (or the error "integer literal is too large to be represented
  in any integer type" past 64 bits). `true` is 1, `false` 0, and every
  other identifier (keywords included) 0, with `-Wundef` ("'X' is not
  defined, evaluates to 0"). Floating literals, string literals and
  user-defined literals are errors with clang's wording.
- **Conversions.** The usual arithmetic conversions apply to every binary
  operator except `<<`, `>>`, `,`, `&&` and `||`, and to the second and
  third operands of `?:`. Converting a negative signed value to unsigned
  warns ("left side of operator converted from negative value to
  unsigned: -1 to 18446744073709551615"), at the operator.
- **Arithmetic.** Signed `+ - * / % <<` and unary `-` that overflow warn
  "integer overflow in preprocessor expression" and wrap; unsigned
  arithmetic wraps silently. Division and remainder by zero are errors.
  A shift by a negative amount or by 64 or more also warns as an
  overflow (the result is 0, or the sign fill for `>>`). `>>` of a
  signed value is arithmetic.
- **Character literals.** Ordinary literals are `char` (signedness from
  `EncodingParams`; multi-character literals are `int`, with
  `-Wmultichar` and `-Wfour-char-constants`); `u8`, `u`, `U` and `L`
  literals have their types' widths and signedness. The value and the
  lexical diagnostics come from `kiln_lex`'s literal evaluation.
- **Precedence and grammar.** clang's precedence table, including `,` at
  the lowest level. A top-level comma is an error in C++ ("expected end
  of line in preprocessor expression"); inside parentheses in an
  unevaluated operand it is accepted, and in an evaluated one it is a
  `-Wpedantic` extension ("comma operator in operand of #if"). Missing `)` and `:`
  have clang's error-plus-note wording.
- **Unevaluated operands.** The right operand of `&&`/`||` whose result
  is already known and the arm of `?:` not selected are parsed but
  produce no diagnostics and do not mark macros used.
- **`defined`.** `defined X` and `defined ( X )` read their operand with
  `IfContext::next_unexpanded`. A `defined` that came from a macro
  expansion warns `-Wexpansion-to-defined` (from an object-like macro
  by default, from a function-like one under `-pedantic`), and is
  evaluated.
- **Errors.** After the first error the expression's value is false
  (`eval`) or `None` (`eval_value`) and the rest of the line is skipped
  by the core. After a complete expression a further token is "token is
  not a valid binary operator in a preprocessor subexpression" (or
  "expected end of line in preprocessor expression"); the value is kept,
  as in clang.
- **Ranges (WP-1290).** Each value carries clang's `PPValue` range: a
  token's span; a unary operator's from the operator to the end of its
  operand; a parenthesized expression's from `(` to `)`; `defined X`'s
  from `defined` to `X`, and `defined ( X )`'s to the end of the token
  after the `)` (as clang, which has already lexed it); a binary or `?:`
  expression's from its first operand to its last. Division or remainder
  by zero, overflow, "converted to positive", the comma extension,
  expected `:` and `:` without `?` underline both operands; unary minus
  overflow underlines the whole negation; missing `)` underlines the
  parenthesized operand; "not a valid binary operator" underlines the
  value before the token. A bare identifier followed by `(` is instead
  "function-like macro 'x' is not defined" at the identifier
  (`true`/`false` count as identifiers here, as in clang).
- **`eval_value`** evaluates `#embed`/`__has_embed` parameters with the
  same grammar, stopping at the `)` that closes the parameter, and
  returns the value as `i64` (a `uintmax_t` value above `i64::MAX` reads
  as negative and is rejected by the core as "negative").

The tests are `tests/ifeval.rs` (per rule, without clang),
`tests/ifeval_differential.rs` (1228 expression runs against
`clang++-19 -E`, aarch64 and x86-64, default and
`-pedantic -Wundef -Wfour-char-constants`, compared on selected groups and
on every diagnostic's location, level, wording and option: no
differences) and `tests/ifeval_conformance.rs` (the corpus cases below).

### `FeatureQueries`: to be implemented by WP-015 (feature tables)

```rust
pub trait FeatureQueries {
    fn has_feature(&self, name: &str) -> bool { false }
    fn has_extension(&self, name: &str) -> bool { self.has_feature(name) }
    fn has_builtin(&self, name: &str) -> u32 { 0 }
    fn has_constexpr_builtin(&self, name: &str) -> bool { false }
    fn has_attribute(&self, name: &str) -> u32 { 0 }
    fn has_cpp_attribute(&self, scope: Option<&str>, name: &str) -> u32 { /* [cpp.cond] Table 23 */ }
    fn has_declspec_attribute(&self, name: &str) -> bool { false }
    fn is_keyword(&self, name: &str) -> bool { /* C++26 keywords */ }
```

The core parses the operand of each query, including scoped attribute
names and the `__x__` normalisation. It diagnoses malformed operands with
clang's wording and spells the result. Values other than 0 and 1 get an
`L` suffix, as in clang.

`__has_warning` is answered from `kiln_diag`'s group table.

The default is `NoFeatures`, which uses the trait defaults (only Table 23
and the keyword list). A driver installs `ClangFeatures`.

#### Feature queries: `ClangFeatures` (WP-015)

```rust
pub struct ClangFeatures { .. }
impl ClangFeatures {
    pub fn new(triple: &str, std: Std, flags: &[FeatureFlag]) -> Option<ClangFeatures>;
    pub fn from_args<S: AsRef<str>>(triple: &str, std: Std, args: &[S]) -> Option<ClangFeatures>;
    pub fn flags(&self) -> &[FeatureFlag];
}
impl FeatureQueries for ClangFeatures { .. }
#[non_exhaustive] pub enum FeatureFlag { NoExceptions, NoRtti, GnuMode, MsExtensions, SanitizeAddress, .. }
impl FeatureFlag { pub const ALL: &[FeatureFlag]; pub fn options(self) -> &'static [&'static str]; }
```

`ClangFeatures` answers every `FeatureQueries` method exactly as clang
19.1.7 does for the same target, standard and driver options:

- **Configurations.** Targets `aarch64-unknown-linux-gnu` and
  `x86_64-unknown-linux-gnu` (also spelled without the vendor, and with
  `arm64`/`amd64`); `new` returns `None` for any other triple. Standards
  C++98 (and C++03) through C++26. Each `FeatureFlag` is a driver option
  that changes at least one answer (`-fno-exceptions`, `-fno-rtti`,
  `-std=gnu++NN`, `-fms-extensions`, `-fdeclspec`, `-fblocks`,
  `-fopenmp`, `-fno-operator-names`, `-fno-char8_t`, `-pedantic-errors`,
  the sanitizers, the ptrauth options, ...); a flag clang rejects for the
  target (ptrauth on x86-64, `-fsanitize=numerical` on aarch64) is
  dropped. `from_args` maps driver arguments to flags: `-fsanitize=`
  lists, `-fX`/`-fno-X` pairs where the last one wins, and
  `-std=gnu++NN`; other arguments are ignored.
- **Tables.** `features_table.rs` is generated by
  `scripts/gen-features.sh` (needs `clang++-19` and `clang++-22`; about
  15 minutes at `JOBS=2`). It collects candidate spellings (every identifier in
  `libclang-cpp.so`, about 128k, plus every `__has_*` operand in the
  libc++, glibc and clang headers), probes each query kind with
  `clang -E -undef` in all 14 base configurations and with each flag at
  C++98 and C++26 (602 configurations), keeps the nonzero answers, and
  checks that the tables reproduce every probe before writing. The base
  tables hold 128 features, 152 extensions, 2309 builtins, 187 constexpr
  builtins, 338 GNU attributes, 0 declspec attributes, 310 C++
  attributes and 287 keyword spellings, each with a 14-bit mask of the
  configurations it holds in; 1244 overlays give the per-flag answers.
  Lookup is a binary search; nothing is allocated per query.
- **kiln's own C++ attributes.** An unscoped `__has_cpp_attribute`
  query the tables answer 0 then looks in `KILN_CPP_ATTRIBUTES`
  (`features.rs`): standard attributes kiln implements before clang
  does, with the first standard they exist in, answered at every
  compatibility level. Today one row: `indeterminate` = `202403` from
  C++26 (P2795R5, WP-448; clang trunk's spelling is C++26-only too), 0
  before (`tests/conformance/dcl.attr.indet/has-cpp-attribute.cpp`,
  `cxx23-unknown.cpp`).
- **Normalisation** (clang's): `__x__` is `x` for `__has_feature`,
  `__has_extension`, `__has_attribute` and unscoped or `gnu`/`clang`
  scoped `__has_cpp_attribute`; scopes `__gnu__` and `_Clang` are `gnu`
  and `clang`. `__has_builtin`, `__has_constexpr_builtin` and
  `__has_declspec_attribute` are not normalised.
- **`__is_target_*`.** `arch` is true for the target's names
  (`aarch64`/`arm64`, or `x86_64`/`x86_64h`/`amd64`); `vendor` for
  `unknown`; `os` for names starting `linux`; `environment` for names
  starting `gnu` other than the GNU ABI variants (`gnueabi`, `gnux32`,
  `gnu_ilp32`, ...); `variant_os` and `variant_environment` are false.
  Comparisons are case-insensitive. This matches clang over every
  identifier probed (131k), except deviation 18.
- **`__FLT_EVAL_METHOD__`** is 0 on both targets.

Verification: `tests/features.rs` compares every table key, every
`__x__` and scoped variant and absent names against `clang++-19 -E` in
all 16 target and standard configurations, each flag on each target at
C++98 and C++26, nine flag combinations, every `__has_*` operand found in
the system headers, and a curated `__is_target_*` list; it also has

### C mode (WP-1275)

`PpOptions::c: Option<CStd>` (and `gnu`) preprocess C; `std` is the C++
standard C lexes as (spec/lex.md "C mode"), which the preprocessor
copies to `LexOptions` with `c`, `gnu` and `preprocessed_output` (set by
the driver for `-E`, strict C89's `//` rule). In C:
- **No operator names** (C23 6.4.6 has no `and`, `bitor`, …): `#define
  and &&` is `<iso646.h>`'s definition, not an error, and `and` in `#if`
  is an identifier (0).
- **`true`/`false` in `#if`** are 1/0 from C23 only (C23 6.10.2/13);
  before C23 they are identifiers, so 0.
- **`u8'x'`** is unsigned in `#if` from C23 (an `unsigned char`, C23
  6.4.4.5), like C++20's `char8_t`.
- **Hooks**: clang registers `__has_cpp_attribute` in C++ only and
  `__has_c_attribute` in C only (C23 6.10.2), so `defined(...)` and a use
  follow that (`expand.rs`); `FeatureQueries::has_c_attribute`'s default
  answers C23's standard attributes (C23 6.7.13.1).
- **Predefines** are clang's C ones (`__STDC_VERSION__`, no `__cplusplus`
  or `__cpp_*`; `tests/c/predefined/`, differential vs `clang-22 -x c -E`
  at every C standard and gnu17/gnu89).

#### Feature queries in C

`ClangFeatures::with_c(c, gnu)` answers in C: the C++ answer of the
standard `c` lexes as (base, flag overlays and, at 22, the clang 22
deltas and overlays) and then the C deltas of
`features_c_table.rs` (`C19`, or `C22` at `ClangCompat::Clang22`) whose
configuration mask has bit `target * 10 + std * 2 + gnu` (targets
aarch64 0, x86_64 1; stds c89 0 … c23 4). The driver installs it for
every C input (`pp_cmd.rs`). `scripts/gen-features-c.sh` generates the
table: every answer of `clang-19 -x c` (`clang-22 -x c`) that differs from
`clang++-19` (`clang++-22`) at the mapped C++ standard (`gnuNN` against
`gnu++NN`), over the candidates: every key of `features_table.rs`, the
operands of each `__has_*` query in the glibc and clang headers, the
identifier-like strings of each clang's `libclang-cpp` (the C-only
names clang answers 0 for in C++), the C keywords and the C23
attributes, and every `__has_cpp_attribute` key as a
`__has_c_attribute` key. Under a set flag the flag's C deltas
(`C19_FLAGS`/`C22_FLAGS`, `CFlagDelta(flag, kind, key, value, mask)`)
apply last, in flag order: the generator probes `-fblocks`,
`-fno-exceptions`, `-fmodules`, `-fms-extensions` and
`-fsanitize=address|thread|memory|undefined` (one at a time) in all 20
configurations, and each answer of `clang-NN -x c <flag>` that differs
from the prediction (`clang++-NN <flag>` at the mapped standard with the
base C deltas applied) is a flag delta. Other flags get the C++ overlays
then the base C deltas, unprobed; flags are assumed independent.
`crates/kiln_pp/tests/features_c.rs` queries every key of both tables in
all 20 configurations, and under each probed flag, against `clang-19 -x
c` and, at 22, `clang-22 -x c` (a missing clang is skipped); the only
allowed differences are the ACLE header builtins at 22 (above).

### Assembler-with-cpp (WP-1331)

`PpOptions::asm` (a `.S` input; clang `LangOptions::AsmPreprocessor`)
preprocesses assembly, where `#`, `'` and `$` are ordinary characters:

- `#` at the start of a line followed by a token that names no directive
  is not an error (`invalid preprocessing directive`): the `#`, that token
  and the rest of the line are returned to the token stream and
  macro-expanded as text (clang `HandleDirective` re-enters the `#` and
  the token after it). `# <number> ...` is such a line too, except in the
  predefines buffer (where kiln's own line markers are directives): in
  assembly it is usually a comment. A `#` alone on a line is still the
  null directive.
- In a function-like macro's replacement list a `#` not followed by a
  parameter (or `__VA_OPT__`) is kept as an ordinary token, not `'#' is
  not followed by a macro parameter`; it does not stringize, and the `-E`
  printer does not indent it as a `#` (clang turns it into an unknown
  token). A `#` ending the list is still the error.
- The lexer (`LexOptions::asm`) forms an unterminated `'` or `"` literal
  and the empty `''` as an unknown token without the
  `missing terminating` / `empty character constant` diagnostics.
- The driver defines `__ASSEMBLER__ 1` (just before the `<command line>`
  part of the predefines) and turns off `$` in identifiers by default.

Everything else (directives, expansion, `//` and `/* */` comments,
`-E` printing) is the input language's. Tests:
`crates/kiln_driver/tests/asm_inputs.rs` (`-E` text checked against
clang 19 and 22).

### `PpCallbacks`: consumers are WP-014 (`-M`), WP-017 (`-dD`, `-dI`) and phase 7

```rust
pub trait PpCallbacks {
    fn file_changed(&mut self, change: FileChange) {}
    fn inclusion_directive(&mut self, req: &IncludeRequest, result: Option<&ResolvedInclude>) {}
    fn macro_defined(&mut self, name: Symbol, def: &MacroDef) {}
    fn macro_undefined(&mut self, name: Symbol, span: Span, def: Option<&MacroDef>) {}
    fn macro_expands(&mut self, name: &Token, def: &MacroDef, range: Span) {}
    fn pragma(&mut self, info: &PragmaInfo<'_>) -> bool { false }  // true = consumed
    fn pragma_message(&mut self, span: Span, namespace: Option<&str>, kind: PragmaMessageKind, text: &str) {}
    fn ident(&mut self, span: Span, text: &str) {}
    fn source_range_skipped(&mut self, range: Span) {}
}
pub enum FileChange { Enter { file, from: Option<Loc>, system },
    Exit { file, exited, resume: Loc, system },
    Rename { file, at: Loc, system, flag: Option<u8> },  // #line / line marker
    SystemHeader { file, at: Loc } }
```

As in clang, `macro_expands` is also called for builtin macros such as
`_Pragma`.

The core consumes these pragmas:

- `once`, `push_macro`, `pop_macro`, `mark`, `region` and `endregion`;
- `GCC` / `clang` `poison`, `system_header` and `dependency`.

`message`, `GCC warning` and `GCC error` are diagnosed by the core and
become `Marker::PragmaMessage`. `GCC` / `clang` `diagnostic` is validated
by the core, then offered to `pragma`, as is every other pragma. A pragma
that `pragma` does not consume becomes `Marker::Pragma`.

The default is `NoCallbacks`.

### Comment handler: consumer is `-verify` (WP-143)

`Preprocessor::set_comment_handler(Box<dyn FnMut(Span)>)` is clang's
`Preprocessor::addCommentHandler`. The handler is called with the span of
every comment the preprocessor lexes in normal mode, in source order,
whether or not `-C` keeps it as a token. That covers comments on
directive lines, in included files and in macro definitions. It does not
cover comments in skipped conditional groups or in the discarded text of
`#error` / `#warning`, which clang lexes raw and never shows its handler.
Installing the handler also turns recording on for files already entered
(the lexer's `set_record_comments`, spec/lex.md "Comments"). There is at
most one handler; with none, nothing is recorded. Comments lexed in
clang's raw mode (`quiet_lex`: the rest of a `#error` / `#warning` line,
`#pragma GCC poison` operands) are dropped, as clang's raw lexer never
calls its handlers. Test: `tests/cpp_comments.rs`.

`Token::span` is the expansion location. The spelling and the macro
backtrace are reachable through `SourceManager::expansion_info`.

`attr_macros` (WP-234, `macros.rs`) is the history of the object-like
macros whose replacement list starts `[ [`: per definition the name, the
location that put it in effect (the name in `#define`, or the `#pragma
pop_macro`), the location that ended it (`#undef`, a redefinition,
`#pragma pop_macro`; invalid while in effect), and the replacement
list's token spellings joined by single spaces (punctuators in their
primary spelling). The `u32` is a generation that changes whenever the
list does. It exists for Sema's `-Wimplicit-fallthrough` fix-it spelling
(clang `Preprocessor::getLastMacroWithSpelling`, which walks the full
macro history); the parser copies it into `Sema::sync_attr_macros`
before finishing each function or lambda body. Recording costs one
token-kind check per `#define` and nothing per `#undef` while the list is
empty.

### Module and import directives

A `module`, `import` or `export module|import` that starts a line and is
followed by a name, `:`, `;` (for `module`), or a header name (for
`import`) is a directive ([cpp.module], [cpp.import]).

Before C++20, and under `-E`, the core queues a `Marker::Module` and
returns the directive's tokens, macro-expanded, as ordinary tokens for the
parser. With modules enabled (`PpOptions::modules`, C++20 and later for
`-fsyntax-only` and code generation) the directive is consumed by
`modules.rs`: the marker carries a parsed `ModuleDirective` (its `span` is
the first token, `kw` the `module`/`import` keyword), and an import builds
the imported unit in-process between `Marker::UnitBegin` and
`Marker::UnitEnd`, saving and restoring the importer's unit-local state.
Header units export their macros at the import. The full contract
(lookup of module sources, header units, `import std;`) is spec/modules.md
§2-3.

### `kiln_pp::print`

`print_preprocessed(pp, PrintOptions { line_markers, line_directives }, out)`
is a port of clang's `PrintPPOutputPPCallbacks`. It covers:

- **`-E`** with line markers `# <line> "<file>" <flags>`, where flag 1 is
  enter, 2 is exit and 3 is a system header (`line_markers: true`).
- **`#line` spelling** of the markers (`-fuse-line-directives`).
- **`-P`** (`line_markers: false`), with clang's blank-line and
  column-indentation rules.
- **`AvoidConcat` spacing**, including `[:`, `:]` and `^^` (see the
  deviations).
- **`#embed` output** as `b0, b1, ...`.
- **Pass-through pragmas.**
- **`-C`** through `PpOptions::keep_comments`, using the lexer's comment
  tokens.

`print_macros` implements `-dM`. `-dD` and `-dI` are not implemented: they
belong to WP-017, which builds them on `macro_defined` and
`inclusion_directive` (see the open questions).

### Preprocessor-state record (WP-1280)

`kiln_pp::state` writes and installs the preprocessor state a header
leaves behind. The record's contents and byte layout are
spec/modules.md §11.13.

- **Points.** A preprocessor with `StateHooks` (`set_state_hooks`,
  before the first token) counts the *points* of the main file's
  predefines buffer. Point `k` is reached where the buffer's `k`-th
  `#include` (from 0) begins, or at the end of the buffer if it has
  fewer. The driver puts every `-include` (and a PCH's header, when
  it is replayed) there, so point 0 is "the predefines and the command
  line read, nothing `-include`d yet". Points count only in the main
  file's own predefines buffer, not in a header unit's copy of it.
- **Baseline.** `baseline: true` takes `state_baseline()` at point 0.
- **Snapshot.** `state_snapshot(&baseline)` is the state now as the
  difference from the baseline:
  - the definitions made or replaced, and the baseline macros
    undefined;
  - the `push_macro` stacks that changed;
  - the new poisoned identifiers, guards and once files;
  - `__COUNTER__`, the open diagnostic pushes, the new attribute
    macros, and the diagnostic engine's pragma state.

  At the end of the main file, the main file's controlling macro
  counts as its guard. A producer takes the snapshot at the end of
  the TU. A checker (`checkpoint: Some(k)`) takes it at point `k`,
  which is where the replayed header ends.
- **Install.** `install: Some((k, state))` makes `state` the
  preprocessor's state at point `k`, as if the header had been read
  there:
  - it adds the macros, applies the undefs and sets the push stacks,
    poisons and `__COUNTER__`;
  - it marks the guarded and once files as entered, so including them
    again skips them as after a real read, and the `-M` and
    `suggest_include` guard records see them;
  - it adds the diagnostic pushes;
  - it installs the diagnostic pragma state at the point's location
    (`pragma_install`).

  Nothing is lexed: macro bodies are the record's tokens, and their
  spellings are read from their files when printed.
- **Header units.** `end_unit` passes a unit's exported macros through
  a write and a read of the record (`unit_round_trip`), unless
  `ModuleOptions::no_unit_record` is set.
- **`describe`.** `PpState::describe` gives one sorted line per item,
  such as `define Z = 1/0.0 @./x.h+17` or `guard ./g.h G_H`. Sema's
  pragma state is not part of it. The driver's check mode compares
  the record with replay through it.
- **Tests.** `crates/kiln_pp/tests/pp_state.rs` compares replay with
  the installed record on `-E`, `-dM -E` and diagnostics, including
  the whole pp torture corpus.

## Behavior (the standard is normative; clang 19 decides what it leaves open)

- **Directives.** Only a `#` that is physically at the start of a line
  starts a directive (clang `IsAtPhysicalStartOfLine`). `EMPTY # define`
  is text. Directives inside macro arguments are processed, with the
  clang extension diagnostic.
- **Macro expansion.** Expansion follows [cpp.rescan] as clang implements
  it. This covers:
  - the hide set (disabled macros, and `NO_EXPAND` tokens that stay
    unexpandable);
  - placemarkers for `##`;
  - the spacing of `#` results, taken from `LEADING_SPACE` flags rather
    than the source text;
  - `__VA_OPT__`, including P1042's stringify and placemarker cases;
  - GNU `, ## __VA_ARGS__` (clang `MaybeRemoveCommaBeforeVaArgs`): the
    comma is removed when the variadic argument is omitted. `token
    pasting of ',' and __VA_ARGS__ is a GNU extension`
    [-Wgnu-zero-variadic-macro-arguments] is reported at the spelling
    in the definition (`expand.rs::emit_paste_comma`, WP-230): the `,`
    when the argument is omitted, the `##` when it is present. There are
    no "expanded from" notes, and the warning repeats per expansion
    (`allow_duplicate`), as clang's does;
  - a function-like macro name followed by `(` on a later line, or after
    the end of a file.
- **Locations.** Each expanded token has a `Loc` in a macro expansion
  range (`ExpansionKind::Macro` or `MacroArg`), so diagnostics can print
  "expanded from macro" notes like clang's.
- **`__LINE__`.** The presumed line at the end of the outermost expansion
  range of the `__LINE__` token. A `__LINE__` spelled after a line splice
  is on the line after the splice. Both follow clang
  (`AdvanceToTokenCharacter`).
- **`#pragma once` and include guards.** The core ports clang's
  `MultipleIncludeOpt`:
  - Every token lexed in a file counts as read, including directive
    tokens, but not the directive's `#`, comments, `Eod` or `Eof`.
  - A top-level `#ifndef X` with `X` undefined, or a top-level
    `#if !defined(X)` / `#if !(defined X)` that is true and has no tokens
    from a macro expansion, with nothing read before it, is a candidate
    guard.
  - Any other top-level conditional, `#else` or `#elif` invalidates the
    candidate, as does anything read after the matching `#endif`.
  - A file with a guard is not re-entered while the guard macro is
    defined. It produces no `FileChange` events, which changes the output
    of `-P`.
- **Missing `<meta>` (WP-1210, kiln-only).** When an angled
  `#include <meta>` (the name exactly `meta`) is not found and the driver
  set `PpOptions::meta_hint` (C++ at `-std=c++26`/`gnu++26`/`c++2c`, the
  standard library directories searched, and the selected GCC older than
  16), the `pp_file_not_found` fatal error (text and location unchanged)
  carries one location-less note: `note_pp_meta_gcc` (the selected GCC
  installation and its version), `note_pp_meta_libcxx`
  (`-stdlib=libc++`) or `note_pp_meta_no_gcc` (no GCC installation),
  each ending with `; a GCC 16 installation was found at '<prefix>' (from
  <exe> on PATH)` when `MetaHint::probe` (the driver's `g++-16`, then
  `g++`, `-print-search-dirs` probe) finds one. The probe runs only on
  this error path. The library selection itself does not change.
- **`#embed`.** The core produces `prefix`, then the byte tokens
  (`is_embed_byte`: a pp-number per byte and the commas between them,
  spelled in one scratch buffer per embed), then `suffix`. An empty resource produces `if_empty`
  instead. Each embed is preceded by `Marker::Embed`. Its diagnostic
  follows the language (WP-1331, clang 19/22 `ext_pp_embed_directive` /
  `warn_compat_pp_embed_directive`): in C++, at every standard,
  `pp_embed_ext` "#embed is a Clang extension" [-Wc23-extensions]; in C
  before C23, `pp_embed_c23_ext` "#embed is a C23 extension"
  [-Wc23-extensions]; in C23 and later (C2y too) nothing by default, only
  `pp_embed_compat` "#embed is incompatible with C standards before C23"
  under `-Wpre-c23-compat` (also `-Wpre-c2x-compat` and the `-pedantic`
  groups), so `-std=c23 -Werror` compiles an `#embed`.
- **`#line` and line markers.** `#line` operands are macro-expanded; line
  markers are not. Marker flag 2 with no matching flag-1 marker in the
  file is an error. Presumed locations are kept by kiln_source
  (`add_line_directive`).
- **Predefined macros.** The macros of [cpp.predefined], plus those of the
  target and clang compatibility, come from `PpOptions::predefines`. That
  text is normally `resource/predefines/<triple>.<std>.txt`, generated
  with `clang -E -dM`; see `resource/README.md`.

  `kiln_pp::build_predefines(base, &PredefConfig, &[CmdMacro])` (WP-014,
  `predef.rs`) builds the buffer clang's way, in this order:
  - `__KILN__`, `__KILN_MAJOR__`, `__KILN_MINOR__` and `__KILN_PATCH__`
    (`PredefConfig::kiln_version`; spec/driver.md "Version");
  - `# 1 "<built-in>" 3`;
  - the sorted base macros, adjusted for the dialect and the
    macro-changing flags (`PredefConfig`; the effects are measured in
    `resource/README.md`), and the feature-test macros kiln implements
    beyond the clang 19 base, at clang 22's values and at every
    compatibility level (see above; `__cpp_explicit_this_parameter`
    needs `__cplusplus >= 202302L`);
  - clang 19's `#pragma push_macro("__GCC_DESTRUCTIVE_SIZE")` and
    `push_macro("__GCC_CONSTRUCTIVE_SIZE")`, so that `-D` may redefine
    them without a warning;
  - `# 1 "<command line>" 1`;
  - each `-D` (`X` -> `X 1`, `X=v` -> `X v`) and `-U`, in order;
  - the driver's `__GCC_HAVE_DWARF2_CFI_ASM`;
  - `# 1 "<built-in>" 2`.

  Keeping kiln's own macros ahead of the first line marker gives the
  numbered part of `<built-in>` clang's line count. The
  `# N "<built-in>" 3` marker before `<command line>` therefore matches
  clang byte for byte. The printer emits that marker for a flag-1 line
  marker, as clang's `EnterFile` does for its include location. The flag-to-config
  mapping is the driver's (`spec/driver.md` "Predefines").
  The builtin macros are entries in the macro table with
  `MacroDef::is_builtin` set, so `#ifdef __has_include` is true.
  `__DATE__`, `__TIME__` and `__TIMESTAMP__` can be fixed through
  `reproducible_time` and `timestamp`.

## Deviations from clang 19 (each covered by a test or a test note)

1. *(Resolved by WP-014.)* The `# N "<built-in>" 3` marker is now
   printed as clang prints it (see "Predefined macros").
2. *(Resolved by WP-183.)* `#pragma clang|GCC diagnostic` changes the
   diagnostic state from the pragma on (spec/diag.md §5.5); kiln_pp
   reports each push/pop/mapping to the engine and each file exit
   (`pragma_file_exit`).
3. **`#pragma clang deprecated`, `final` and `restrict_expansion` are
   validated and consumed, without effect.** As in clang, `-E` does not
   print them, but kiln does not implement their warnings on later uses
   of the macro.
4. **`#pragma GCC dependency` is consumed without checking the file's
   date.**
5. *(Resolved by WP-014.)* `push_macro` marks the pushed definition as
   redefinable without a warning (clang
   `setIsAllowRedefinitionsWithoutWarning`).
6. **Poisoned identifiers are not checked inside `_Pragma` strings.**
7. **`AvoidConcat` also separates `[:`, `:]` and `^^`.** This is for C++26
   reflection splicers. It always uses the C++11 and later rules, such as
   the ud-suffix and raw-string prefix cases.
8. **The spacing of `#embed` output is empirical.** clang prints it from
   an annotation token. kiln reproduces the observed spacing, including
   the separator before the token that follows the embed. The
   `__has_embed` operand parameters are evaluated with a nested
   `IfEvaluator::eval_value`.
9. **Line marker flag 2 does not check the filename.** clang also checks
   that the name matches the includer.
10. **Module names that are object-like macros are diagnosed.** kiln
    checks every component of a module declaration's name and partition
    ([cpp.module]/2, P3034R1); clang 19 and 22 expand the macros instead
    (`tests/conformance/cpp.module/p3034-probe.cpp` is `xfail(clang)`).
11. **Header units are built in-process from their source** (no
    `-fmodule-header` step, spec/modules.md §3); clang requires a
    prebuilt header unit.
12. **`PpCallbacks::macro_expands` is not delayed.** clang delays the
    callback for function-like macros until the arguments have been
    collected; kiln calls it when the expansion begins.
13. **`contract_assert` is a keyword in `__is_identifier`.** This follows
    C++26 (P2900). clang 19 treats it as an identifier.
14. **The include-guard detector's `DidMacroExpansion` is approximated.**
    kiln uses "no token from a macro location" instead.
15. **`-CC` does not retain comments in `#define` bodies.** Comments in
    macro arguments are retained.
16. **`__FILE__` under `MemoryResolver`.** The test resolver names a
    header by its include spelling: `"b.h"`, not `"inc/b.h"`.
    `HeaderSearch` (the driver's resolver) names it exactly as clang
    does (`dir/name`, `./name`). This is a deviation of the test resolver
    only.

17. **`#if` evaluation (WP-015 `IfEval`) differs from clang 19 in
    these minor respects, none of which change a group selection:**
    `-Wundef-prefix` is not implemented; the `__wb`/`__uwb` (`_BitInt`)
    literal suffixes, a clang extension in C++, are not supported in
    `#if`; `defined X` in an
    unevaluated operand still marks `X` used (for `-Wunused-macros`);
    the C++98 and C++20 compatibility warnings (`-Wc++98-compat*`) are
    not emitted; the `-Wexpansion-to-defined` decision ignores clang's
    per-macro `emitMacroExpansionWarnings` suppression; the location of
    the error for a reflection `^^` operator is the operator, not
    clang's; `\N{...}` errors have no "did you mean" note; the order of
    two diagnostics on the same token can differ; source columns assume
    trigraphs are off; an unterminated delimited escape (`'\x{41'`)
    evaluates to 0 (`kiln_lex`).
18. **`__is_target_arch` accepts only the canonical arch names.** LLVM's
    ARM name parser also accepts suffixed spellings (`aarch64x`,
    `arm64x`, `aarch64v8a`, ...), which clang answers 1 for; kiln
    answers 0.
19. **Feature answers ignore `-march`/`-mcpu`/`-m<feature>`.** The tables
    hold clang's answers for the default CPU, so target builtins enabled
    only by a target feature (SVE, AVX-512, ...) report 0.
20. **Names of builtin macros are not probed through the expanding
    hooks.** `__has_attribute(__FILE__)` and the like macro-expand their
    operand in clang; kiln's core does the same expansion before asking
    `ClangFeatures`, whose tables were probed under `-undef` and exclude
    those names.
21. **`defined` anywhere in an `#embed` parameter is an error.** clang 19
    only rejects it when it leads the expression (its `DefinedTracker`);
    kiln follows [cpp.embed.param.limit]/1.
22. **GCC 14's P1467 macros are predefined** (`__STDCPP_FLOAT32_T__`,
    `__FLT32_*__`, `__BFLT16_*__`, ...; "Predefined macros"). clang 19
    and 22 define none of them, so `-dM -E` output has them in addition
    to clang's.

## Snapshots (WP-1379)

`Preprocessor` is a configured root (spec/snap.md "Configured roots";
prototype, not called by the compiler yet; classification table at
`src/snap.rs`). `MacroDef`, `MacroTable`, `AttrMacro`, `Builtin`, the
preprocessor's token and kiln_lex's `Token`, `TokKind`, `TokFlags`,
`Punct` and `Encoding` derive `Snap`. The record of "Preprocessor-state
record" is separate and unchanged: a snapshot keeps every id as it is,
with no baseline and no remapping.

- **The snapshot point** is the end of the producer's main file (the
  header, read as `-emit-pch` reads it): `end_main_file()` closes it as
  the end of an included file would (its include guard is recorded), so
  no file is open. `enter_next_main_file(file)` then enters another main
  file without reading the predefines again (they are state); the
  `#pragma clang diagnostic` state of the end of the prefix continues at
  its start, as it does in an includer after an `-include`.
- **State**: the macro table (builtins included), `push_macro` stacks
  (sharing the table's `Rc<MacroDef>`, which `Rc::ptr_eq` checks rely
  on), poisoned names, include guards, `#pragma once` files, entered
  files, scratch and `#embed` buffers, GCC directory spellings,
  `__COUNTER__`, the depth-limit flag, the module-directive bookkeeping
  of the main file, the main and predefines buffers, `diag_pushes`, the
  attribute-macro history and, with modules on, the predefines buffer of
  the module state.
- **Consumer-supplied**: the options, the include resolver (its caches
  refill: the restored source manager gives the same `FileId` for the
  same path), the `#if` evaluator, the feature queries, the callbacks,
  the comment handler and the replay record's hooks. Rebuilt: the
  pre-interned symbols and directive table (by `new` from the restored
  interner), `__DATE__`/`__TIME__` (on first use), `module_lines`.
- **Quiescence** (`snap_ready`, called by `snap_put`): no file or macro
  expansion open, no marker queued and no token pending or read ahead,
  no conditional open, no directive, macro argument or `#if` being read,
  no macro being expanded, the declaration-image gate off, and no module
  state beyond the predefines buffer (a prefix that imports or declares
  a module is refused). The error names the first field not at rest.
- **Restore** (`snap_restore`) applies the state to a preprocessor
  built with `new` over the restored source manager, interner and
  engine, before its main file is entered, after validating every
  symbol and file id and each macro definition (parameters consistent,
  replacement-list locations inside one allocated entry).
- **Dependencies.** The producer's dependency list is not part of the
  state; `entered` and the source manager's buffers name every file the
  prefix read (the consumer seeds its `-M` list from its PCH record, as
  today).

## Error recovery

After an error in a directive, the rest of the line is skipped and
preprocessing continues.

`pp_file_not_found` is a fatal error, as in clang. The driver stops after
it through kiln_diag's fatal handling; the core itself carries on.

## Performance obligations

- **Token buffers are recycled.** Expansion token buffers come from
  `Preprocessor::pool`, so there is no fresh `Vec` per expansion in the
  steady state.

  An allocation-count test would need a counting `#[global_allocator]`,
  which needs `unsafe impl GlobalAlloc`. That is impossible under
  `#![forbid(unsafe_code)]` in this crate and its tests. The obligation is
  therefore checked by the bench harness (peak RSS, wall time), not by a
  unit test.
- **Skipped groups are not tokenized** ([cpp.cond]/13; WP-056). In a
  skipped group only lines starting with `#` are lexed, and only up to the
  directive name. When the name does not change the nesting (anything but
  `if`/`ifdef`/`ifndef`/`elif*`/`else`/`endif`), the rest of the line is
  dropped by `Lexer::skip_plain_line_rest` (spec/lex.md) instead of being
  formed into tokens. Lexer diagnostics are never reported in a skipped
  group. `tests/cpp_cond_skip_fuzz.rs` checks that the output equals the
  token-by-token path on random skipped groups.
- **Cheap per-token paths** (WP-056). Hot paths avoid source-manager
  walks and allocations without changing results:
  - `spelling()` returns an identifier's or a clean (no splices, not a
    digraph) punctuator's fixed text without reading the source;
  - `#if` evaluates a clean plain decimal pp-number (at most 18 digits,
    optional `u`/`l` suffixes) without `classify_number`, and compares
    `defined` and directive names by symbol (`DirTable`), not by text;
  - `#define` bodies, macro-argument token buffers and their index
    vectors come from pools (`pool`, `arg_pool`);
  - location arithmetic within one expansion entry or file range uses
    `SourceManager::same_entry_distance` (O(1)) instead of walking
    spelling chains.

  Each fast path has a test comparing it with the general path
  (`cpp_cond_plain_decimal_matches_classify_number`,
  `cpp_pre_dir_table_matches_names`, the debug assertion in `spelling()`,
  and the randomized same-entry tests in kiln_source).
- **Directives cost O(1) in the macro history** (WP-487). Every
  `#define`/`#undef` reports to `Preprocessor::note_macro_change`, which
  keeps the attribute-macro history (`attr_macros`, for
  `-Wimplicit-fallthrough`'s fix-it). The entry still in effect for a
  name is found through the `attr_live` index (name to history index),
  never by scanning the history, and a directive returns at once when it
  neither defines an attribute macro nor touches a live one. Before
  WP-487 each directive scanned the whole history once any attribute
  macro existed, which made `bench/pp/headers.cpp` (5120 re-entries, two
  attribute macros redefined per pass) quadratic: 2.4 s against 0.9 s.
  `hooks.rs` `cpp_scope_attr_macro_history` pins the history's contents
  and `cpp_scope_attr_macro_history_churn` its shape under 4000 redefines.
  The include path itself (header-search cache, `#pragma once`, the
  guard detector) was measured and is not where the time went: the
  libc++-include half of the bench moved 347 to 374 ms over the window.
- **Bench budget.** `bench/pp/headers.cpp` carries a `budget-time:`
  directive (spec/bench.md) at 1.5x its recorded kiln median, so
  `cargo xtask bench` fails, even under `--record`, when `-E` on it
  regresses past that.
- **Speed and memory against clang.** `-E` on all libc++ 19 headers must
  take at most 1.5x clang's time and use no more than clang's peak RSS.
  The baseline is in `bench/baselines/pp.json` (M1 gate).

## Open questions

- **`-dD` and `-dI`.** Should these be WP-017 printer modes driven by
  `macro_defined` and `inclusion_directive`, or should they be markers in
  the item stream? clang interleaves them with the output text, which
  needs the printer to see them in stream order. Today callbacks run
  synchronously, before queued markers are printed.
- **Comments in `#define` bodies under `-CC`** (deviation 15).
- **Streaming `#embed`.** The byte tokens are built eagerly, as a `Vec`
  of about two tokens per byte. A large resource should instead be a
  lazily expanded frame. The printer and the parser only need the byte
  values (clang's `annot_embed`), so a dedicated `PpItem` carrying the
  bytes may be the better interface. This must be decided before M3
  embeds of a megabyte or more.

## Decisions recorded from kiln_source (WP-001): binding for pp

- **One location range per inclusion** (WP-056). The main file and
  virtual buffers (`<built-in>`, scratch) are lexed in the buffer's own
  range (`sm.loc(file, 0)`). Every `#include` lexes the file in a fresh
  `SourceManager::add_inclusion(file, included_from)` range, where
  `included_from` is the expansion location of the header-name token
  (clang's include position); the `FileFrame` keeps that `base` and
  every frame-relative location is `base.with_offset(off)`, never
  `sm.loc(file, off)`. Line markers are unchanged: presumed lookups map
  every range of a file to the same buffer, lines and `#line` state. If
  file location space runs out, the inclusion falls back to the buffer's
  own range (losing only its include stack) instead of failing.
- **Scratch buffers.** The results of `#` and `##`, the values of builtin
  macros such as `__LINE__` and `__COUNTER__`, and `_Pragma` strings are
  spelled in one virtual buffer per distinct string. These buffers are
  interned in `Preprocessor::scratch`, so a string spelled twice reuses
  its buffer.

  Each `#embed` gets its own buffer.
- **Line endings and BOM.** `\n`, `\r\n` and a lone `\r` each end a line,
  matching kiln_source's line tables. A UTF-8 BOM is kept in the text; the
  lexer skips it at offset 0 of a file.
- **`#line`.** pp calls `add_line_directive` with `at_offset` set to the
  first byte after the directive's newline. pp range-checks `new_line`
  itself ([cpp.line]/3).

  `__LINE__` reports the presumed line at the end of the outermost
  expansion range of the `__LINE__` token. This is the expansion location
  for a direct use. For a use in a macro argument, it is the line of the
  invocation's closing `)` (clang behaviour).
- **Invalid UTF-8.** The lexer reports a `load_report(FileId)`
  replacement outside a comment or literal (`lex_invalid_utf8`; dropped
  with the rest of the lexer's diagnostics in a skipped group), and the
  literal decoders report one inside a literal: the `-Winvalid-source-encoding`
  warning in an ordinary literal, an error in a prefixed one (spec/lex.md,
  WP-1267). One in a comment or whitespace is accepted, as clang (whose
  `-Winvalid-utf8` is off by default; WP-803,
  `lex.phases/invalid-utf8-in-comment-run.cpp`). `#if` character literals
  go through `decode_char_from_source`.
