# WP-655 — Declaration and type queries without the full decode

This WP changes no observable behaviour. Diagnostics, AST dumps,
`-fkiln-cfg-stats` numbers, corpus goldens and printed IR are all
byte-identical. What changed is how three hot queries reach their
answers, so their cost no longer grows with how often they are asked.
The measurement and the Ir numbers are in
docs/status/perf-reflection.md, "WP-655: declaration and type
queries".

- **Type kind queries** (spec/types.md §3, §13), in
  `crates/kiln_ast/src/types/context.rs`.
  - These queries read the canonical `TypeNode`, check its kind and
    decode only the field they return: `builtin`, `pointee`, `element`,
    `array_size`, `as_atomic`, `as_complex`, `as_record`, `as_enum`,
    `is_integral` and `effective_quals`. Before this WP, each one built a
    whole `TypeView` first.
  - The decoding is the same as `view`'s. `as_record` through an
    injected-class-name specialization keeps the old path, in the cold
    helper `injected_record`.
  - New functions:
    - `is_error(q)`: the canonical node is the error builtin;
    - `canonical_node(q)`;
    - `view_if(t, kind)`, which decodes `t` only when its kind is `kind`.
  - These callers now use the new functions instead of building a full
    view:
    - sema `is_error_type`, `vector_parts`, `templ/ctad.rs`,
      `templ/pack.rs`, `templ/auto.rs` and `templ/deduce.rs`;
    - the oven's `_BitInt` width;
    - the type printer's sugar walk.
- **First and definition bits** (spec/ast.md §4.1, §4.4).
  - `DeclMisc` bit 14 (`is_first`) records that `Ast::first(d) == d`.
    Bit 15 (`is_definition`) records that `Ast::definition(d) == Some(d)`.
  - Both bits can only go from unset to set. Unset means "ask the
    redeclaration group".
  - `DeclArena::push` ignores the bits in the head it is given and
    computes them:
    - a redeclarable declaration that starts a fresh group gets `first`;
    - a declaration without a group gets `definition`, and also gets
      `first` unless it is a template.
  - Template declarations: `template_decl` and `detached_template_decl`
    set `first` when the pattern has it and the pattern's link was set to
    this template. A concept always has `first`.
  - `Ast::set_definition` sets `definition` once the group accepts it.
  - `Ast::first` and `Ast::definition` test the bit before the group.
    Debug builds assert that the group gives the same answer. `latest`
    is unchanged, because it moves with every redeclaration.
  - `crates/kiln_sema/src/lookup.rs` `filter` keeps the `first` of each
    kept result, so it calls `first` once per result instead of once per
    pair of results.
- **`TypeTable::is_sized`** (spec/llvm.md), in
  `crates/kiln_llvm/src/types.rs`.
  - Each type has a state:
    - `Yes`: sized;
    - `No`: unsized for good;
    - `Pending`: an opaque struct, or an aggregate that contains one and
      nothing that is unsized for good.
  - The state is computed when the type is interned, and when a named
    struct's body is set.
  - A `Pending` type waits on its `Pending` elements. When a body makes
    a struct sized, a worklist re-evaluates the types waiting on it.
  - `is_sized` is one load. The recursive walk remains as the reference.
    Debug builds check every `is_sized` call against it, and every type
    when the table is dropped.
- **Tests:**
  - `crates/kiln_ast/src/types/query_tests.rs`: every query against the
    `TypeView` match, for nodes of every `TypeKind`;
  - `crates/kiln_ast/tests/redecl_queries.rs`: `first`, `latest` and
    `definition` against the pre-WP-655 bodies on every declaration of a
    corpus with redeclaration chains, definitions and class and function
    templates;
  - `crates/kiln_llvm/src/types.rs` `sized_tests`: struct bodies set
    after the aggregates that contain them;
  - the debug assertions above, which every test in the workspace
    exercises.
