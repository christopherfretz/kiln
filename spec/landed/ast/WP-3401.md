# WP-3401 — The shadow a using-declaration named

`Ast::shadow_named(s)` (spec/ast.md §4.2) gives, for a using-shadow whose
using-declarator's lookup found a using-shadow, the shadow it found: the
first link of a chain of using-declarations, for tooling clients that
rename through them. A shadow's target stays the entity (clang coalesces
the same way); the record is beside it.

## Memory

One write-once cold map, `decls.cold.shadow_named`, with a row only for a
shadow that found a shadow; nothing else changes (no hot structure, no
list, no dump). An inheriting constructor's record is the existing
`ctor_shadow_nominated` entry, not a second row.

Measured with `-fkiln-memory-report` on a C++26 `-fsyntax-only` TU that
includes `<bits/stdc++.h>` from libstdc++ (aarch64):

| row | count | live | reserved |
|---|---|---|---|
| `decls.cold.shadow_named` | 49 | 441 B | 576 B |
| total, after | | 43,281,234 B | 64,499,123 B |
| total, before (without the row) | | 43,280,793 B | 64,498,547 B |

The 441 B (0.001%) are the whole difference: sema does the same work
otherwise, so the "before" figures are the "after" ones less the row.
The class-scope path builds a short `(target, found shadow)` vector per
using-declarator instead of cloning the target vector; it is freed when
the declarator ends.

## Module images and snapshots

A PCH snapshot carries the map (format 182). A module image carries it
in each shadow record's fourth word, `named` (`IMAGE_VERSION` 97,
spec/modules.md §11.11 kind 21). The writer refuses a shadow whose named
shadow has no record, so an import gets the link or falls back to replay,
never a dropped link.
