# WP-792 — AST fixes from the wave 4 constexpr projects

## Profiling a reference to a specialization

A `DeclRefExpr` or `MemberExpr` naming a specialization with
non-dependent written template arguments is profiled by the
specialization alone, as clang's canonical `VisitDeclRefExpr`; dependent
argument lists and references to a template keep their arguments
(`crates/kiln_ast/src/types/profile_expr.rs`; spec/types.md). Before,
the non-dependent argument expressions had no profile and compared by
id, so `requires(M != mag<1>)` repeated on a redeclaration was a
different requires-clause (mp-units `scaled_unit`). Test:
`tests/conformance/temp.over.link/requires-clause-specialization-reference.cpp`.

## Printing a pointer to an array member

A pointer constant's designator walk (spec/ast.md, Pointers) stops at a
subobject whose type equals the pointee up to cv, including array
element cv (`AstNames::same_unqualified` now calls
`TypeContext::same_unqualified`; `crates/kiln_ast/src/dump/names.rs`).
Before, the pointee `const int[2][2]` of `&fake.c` (a `const` object)
never matched the member's `int[2][2]`, the walk went down to the first
scalar, and `__PRETTY_FUNCTION__` said `p = &fake.c[0][0]`. reflect-cpp
reads C array field names from it, so its `rfl::make_field<"c", …>`
found no field and a `static_assert` failed
(`tests/json_c_arrays_and_inheritance/test_c_array_class5.cpp`). Test:
`tests/conformance/dcl.fct.def.general/predefined-pointer-to-array-member-arg-run.cpp`.
