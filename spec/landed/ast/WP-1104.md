# WP-1104 — missing `__builtin_` library aliases and the clang-22 IR pins

WP-1073 found that kiln rejects `__builtin_malloc`, `__builtin_calloc`,
`__builtin_realloc`, `__builtin_fscanf` and `__builtin_vfscanf` with
"use of undeclared identifier". This package added them and every other
missing `__builtin_` row. The rules are in spec/sema.md "Library
functions", spec/codegen.md §3 ("library builtins") and spec/oven.md
"Builtins".

## How the list was made

The source of truth is clang 19.1.7's and 22.1.8's `Builtins.td`.

1. Every `__builtin_` name was expanded from it:
   - `Builtin` rows with the `__builtin_` prefix;
   - `LibBuiltin` / `GNULibBuiltin` rows with `AddBuiltinPrefixedAlias`;
   - template-expanded rows.
2. Each name was compiled with kiln as `(void)NAME;`. The names kiln
   reported as undeclared are the missing ones.

`__has_builtin` already answered 1 for all of them, because kiln_pp's
features table follows clang.

## Added (`builtin::LIBC_FWD`, ids 2420–2443)

| builtin | clang row | `NoThrow` | lowering |
|---|---|---|---|
| `__builtin_malloc`, `calloc`, `realloc`, `free` | `LibBuiltin<"stdlib.h">` + alias | yes | call of the library function, no `allocsize` |
| `__builtin_fprintf`, `vfprintf` | `LibBuiltin<"stdio.h">` + alias, `PrintfFormat` | yes | call |
| `__builtin_fscanf`, `vfscanf` | `LibBuiltin<"stdio.h">` + alias, `ScanfFormat` | no | call (an `invoke` under a cleanup) |
| `__builtin_strcpy`, `strncpy`, `strcat`, `strncat`, `strspn`, `strcspn`, `strdup`, `strndup` | `Builtin` | yes | call |
| `__builtin_stpcpy`, `stpncpy`, `index`, `rindex` | `Builtin` | yes | call |
| `__builtin_strcasecmp`, `strncasecmp` | `Builtin` | no | call |
| `__builtin_alloca_uninitialized`, `alloca_with_align_uninitialized` | `Builtin` | yes | dynamic `alloca`, as `__builtin_alloca{,_with_align}` |

Related sema changes:

- A `__builtin_` row whose type names `FILE` is not declared while there
  is no `FILE`. This is clang's `GE_Missing_stdio`, and it also applies
  to the existing `__builtin___{v,}fprintf_chk`.
- The `__builtin_` scanf forms (`scanf`, `sscanf`, `vscanf`, `vsscanf`,
  `fscanf`, `vfscanf`) now get the implicit `format(scanf, F, A)`.

## Not added

These are outside kiln's language:

- `__builtin___get_unsafe_stack_{bottom,ptr,start,top}` (SafeStack);
- `__builtin_matrix_{column_major_load,column_major_store,transpose}`
  (matrix types);
- `__builtin_objc_memmove_collectable` (Objective-C);
- `__builtin_trivially_relocate` (clang 22, P2786: out of the C++26
  scope).

## Constant evaluation

A call of any of these traps in the Oven with clang's "subexpression not
valid in a constant expression". This matches clang 19 and 22
(`ext.gnu.builtins/library-fwd-constexpr.cpp`).

## Oracle pins

These six `expect: ir` tests carry clang 22's IR:

- `library-abort-noreturn-nothrow-ir.cpp`
- `library-abort-plain-invoke-ir.cpp`
- `library-complex-nothrow-ir.cpp`
- `library-gnu-string-nothrow-ir.cpp`
- `library-gnu-string-strict-ir.cpp`
- `library-strlen-fold-ir.cpp`

Clang 19's IR differs from clang 22's for each of them, on both targets.
Under `--compiler clang++-19` the six failed against the clang 22
oracle. They now carry `//@ min-oracle: 22`: they are skipped under
`KILN_ORACLE=19` and `--compiler clang++-19`, and pass under oracle 22.
The new `ext.gnu.builtins` IR tests are pinned the same way, and
`tests/codegen/lib_builtin_fwd.cpp` (ir_vs_clang) covers oracle 19.

## Follow-ups

- Under `-ftrivial-auto-var-init=zero|pattern`, clang `memset`s the
  memory of `__builtin_alloca` / `__builtin_alloca_with_align`. Kiln does
  not (`crates/kiln_codegen/src/checked.rs:250`, `emit_alloca`). The
  `_uninitialized` forms already match clang.
- Clang 22 gives the `FILE` builtins
  `NonNull<NonOptimizing, [0, 1]>` (`-Wnonnull` on a null stream or
  format). Kiln has no non-null attribute on builtin rows
  (`crates/kiln_ast/src/decl.rs`, `LIBC_FWD`). This is a warning only.
