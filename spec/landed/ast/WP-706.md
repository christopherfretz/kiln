# WP-706 — Contract assertions in the AST

The P2900 slots that existed unused since M0 are populated (normative
contract: spec/contracts.md §4, §7).

- `StmtKind::ContractAssertStmt` is every contract assertion: a
  `contract_assert` statement and each `pre`/`post` specifier of a
  function. `a` = predicate, `b` = the postcondition's
  `ContractResultName` (0: none), `aux` = `ContractKind` in bits 0-1
  and the evaluation-semantic slot in bits 2-3 (0 today). Builder
  `contract_stmt`; accessors `contract_kind`, `contract_cond`,
  `contract_result_name`, `contract_semantic_slot`
  (`crates/kiln_ast/src/stmt.rs`).
- `decls.cold.contracts` holds a `ListId` of those statements (not the
  `ContractSpec` record spec/ast.md used to sketch), per declaration
  that writes a seq; `Ast::function_contracts(f)` falls back to the first
  declaration. `has_contracts` is set with it.
- `Ast::contract_semantic: ContractSemantic` (`Ignore`, `Observe`,
  `Enforce` default, `QuickEnforce`; `from_flag`, `checks`).
- ast-dump: the specifiers are children of the `FunctionDecl` /
  `LambdaExpr` after the parameters, `ContractAssertStmt pre|post|assert`,
  a result name as `ContractResultNameDecl`, a reference to it as
  `DeclRefExpr ... ContractResultName 'r'`.

Tests: `tests/conformance/dcl.contract.func/dump-function.cpp`,
`dump-lambda-template.cpp`, `tests/conformance/stmt.contract.assert/dump-assert.cpp`.
