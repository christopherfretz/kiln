# WP-911 — Internal compiler errors: the report and the crash reproducer

A panic used to print Rust's `thread '<unnamed>' panicked at ...` and
exit 70. It is now reported the way clang reports a crash (spec/driver.md
"Internal compiler errors").

## Deliverables

- **The panic hook** (`crates/kiln_driver/src/crash.rs`, installed first
  thing in `main.rs`). The hook records the first panic. `main` catches
  the unwind and prints the report:
  - `<prog>: error: internal compiler error: <message>`;
  - `note: while compiling '<file>' (phase: <p>, at <file>:<l>:<c>)`;
  - the compiler-source location and thread;
  - `kiln <version> (<sha>)` (`kiln_driver::version`, `unknown` without a
    recorded commit);
  - the bug-report URL;
  - the Rust backtrace, only with `KILN_BACKTRACE` / `RUST_BACKTRACE`.

  Exit codes match clang 19: 1 after the reproducer is written, and 70
  (clang's crashed-`-cc1` status, and kiln's old code) under
  `-fno-crash-diagnostics`.
- **The breadcrumb** (`crates/kiln_source/src/activity.rs`). It is a
  thread-local `Cell` holding a phase and a `Loc`. The update points are:
  - `pp_cmd.rs`: preprocess;
  - `kiln_parse` `lib.rs`: the parse phase, plus `activity::at` per
    top-level declaration;
  - `decl.rs`: end-of-TU sema;
  - `kiln_oven` `lib.rs`: one guard per evaluation;
  - `codegen_cmd.rs`: codegen.
- **The reproducer**: `<dir>/<stem>-<random>.ii` (`.i` for C), the input
  preprocessed with the job's own flags, and `.sh`, the command with the
  input replaced. `<dir>` is `-fcrash-diagnostics-dir=`, else `$TMPDIR`,
  else `/tmp`, and is created if missing. The preprocessing runs on its
  own thread with panics caught; if it crashes, only the `.sh` is
  written and the report says so. A crash outside any input also writes
  only the `.sh`.
- **One report for many threads** (`funnel`): only the first panic is
  reported, so a scoped helper thread's panic re-raised on the compile
  thread prints once. A second panic on the same thread while unwinding
  prints the banner at once, because the runtime is about to abort.
  There is no parallel codegen today. The only helper threads are the
  link step's `thread::scope`.
- **Not-supported panic sites**: none of the `panic!`/`unreachable!`/
  `todo!` sites in `crates/*/src` is a "not supported" path; the ones
  that exist are invariant checks. Nothing was converted (see the
  follow-ups).
- **The test hook**: `-fkiln-crash-for-testing=<driver|preprocess|lex|pp|parse|sema|oven|codegen>`.
  It is hidden and per thread.
- **Docs**: spec/driver.md "Internal compiler errors" (with the options
  rows and the exit-status fix), `docs/REPORTING-BUGS.md`, and a README
  section.

## `panic = "unwind"`

Every profile keeps `panic = "unwind"` (`Cargo.toml` now says why).
Under `abort` the hook could still print the banner, but the reproducer
is written after unwinding to `main`, and the exit code would become
`SIGABRT`.

## Harness changes

- `expect: ice` with `ice:` substrings (spec/harness.md "ice tests";
  `xtask/src/test/{directives,runner}.rs`). It checks:
  - the banner;
  - exit 1, or 70 under `-fno-crash-diagnostics`;
  - the messages, in order;
  - that the listed files are exactly the files in a fresh
    `-fcrash-diagnostics-dir`.

  It is skipped for non-kiln compilers.
- Every kiln compile in the corpus harness, `cargo xtask libcxx` /
  `libstdcxx` and `scripts/oss/kiln-cxx` passes `-fno-crash-diagnostics`
  (after `-std=`, so a test's own flags win). A crashing test in a mass
  run therefore leaves nothing in `$TMPDIR`.
- The crash classifiers (`runner.rs` `crashed`, the libc++ cluster key in
  `xtask/src/libcxx/cluster.rs`, `kiln-cxx` classify) recognise the new
  banner. The cluster key is unchanged in shape:
  `crash: panicked at <file>: <message>`, with the location taken from
  the `in compiler source` note.

## Cost

On the non-crashing path the cost is the breadcrumb (one thread-local
eight-byte store per top-level declaration and per constant evaluation,
plus a guard per phase) and one `catch_unwind` frame and input-path copy
per input. Nothing is formatted or allocated until a panic.

The measurement was `cargo xtask bench --runs 7` over all 50 entries,
using `--profile bench` binaries of base 974e0f045 and this branch built
on the same box. Both were run against a baseline recorded from base
moments earlier, on a shared and loaded host:

- Interleaved back-to-back runs, this branch against base, gave a time
  geomean of -1.8% and a peak-RSS geomean of -0.1%. That is inside the
  noise.
- The noise is visible in base run against its own fresh baseline: the
  bench flagged 21 entries regressed and 12 improved. The machine-
  independent counters (oven steps, evaluation bytes, instantiations)
  are identical on every entry.
- The `kiln` binary's text grows by 104 KB (+0.8%).

## Not covered

- Stack exhaustion is not a panic. The stack guard reports it, and a
  missed overflow is a `SIGSEGV` that the hook never sees.
- The `.i` (C) reproducer path has no test, because compiling C with
  `-fsyntax-only` is not implemented yet.

## Follow-ups: the top panic-site classes

Counted in `crates/*/src` with tests included: 63 `unreachable!`,
22 `panic!`, 127 `unwrap()` and 462 `expect(`. None is a
"not supported" path. The classes worth turning into diagnostics or
typed errors, largest first:

1. `kiln_codegen`: kind-mismatch `expect`s and `unreachable!`s, mostly in
   `class.rs` (45 `expect`), `expr.rs` (37), `stmt.rs`, `complex.rs`,
   `cleanup.rs` and `fir.rs`. A sema gap that lets an ill-formed node
   through reaches these as an ICE; an "unsupported construct in code
   generation" diagnostic would be friendlier.
2. `kiln_ast` `builder.rs` (41) and `expr.rs` (23): node-shape `expect`s
   that callers rely on.
3. `kiln_pp` `preprocessor.rs` (8) and `ifeval.rs` (3): token-state
   `unreachable!`s. Check which ones a malformed directive can reach.
4. `kiln_llvm` `module.rs` / `value.rs`: IR-builder invariants.
5. `kiln_sema` `cfg/build.rs` (15 `expect`).

Tests: `crates/kiln_driver/tests/crash.rs` (7), the `crash.rs` unit tests
(5), the `kiln_source::activity` unit tests, the `args.rs`
`crash_diagnostics` test, the xtask `ice_directives` /
`crash_diagnostics_off_takes_the_last_flag` / cluster `crashes` tests,
and `tests/conformance/driver.crash/` (6 `expect: ice` tests).
