# WP-525 — GCC 16.1 libstdc++ headers compile: `--gcc-toolchain`, `__cpp_impl_reflection`, header-compat fixes

Extends spec/driver.md ("Options", "Toolchain", "Predefines"),
spec/reflection.md §1 item 5, spec/parse.md §4 (GNU `__extension__`,
`__restrict` on references), spec/sema.md §4 (`alloc_align`) and §5
(immediate-function references), spec/sema-class.md §2.1, the consteval
override rule and inheriting constructors, spec/sema-templates.md §3.4
and the member partial specialization rules, spec/libstdcxx.md
(`--gcc-toolchain`) and docs/VALIDATION.md "GCC 16.1 header sweep".
Oracles: clang 19/22, GCC 16.1 where GCC's own headers decide (h).

## Driver

- `--gcc-toolchain=<dir>` and `--gcc-install-dir=<dir>` (joined only):
  the GCC installation search of clang `GCCInstallationDetector::init`
  under `<dir>` instead of `<sysroot>/usr`, `lib64` then `lib`, with
  clang's `-v` candidate list; `--gcc-install-dir` names the installation
  (`'<dir>' does not contain a GCC installation` without `crtbegin.o`,
  `drv_invalid_gcc_install_dir`). The libstdc++ `<v>/<triple>/<multilib>`
  directory is listed when the Debian multiarch one is missing, as clang.
  Test: `crates/kiln_driver/tests/driver.rs` `gcc_toolchain_matches_clang`.
- `-freflection` at C++26 predefines `__cpp_impl_reflection 202603L`
  (GCC 16.1). Test: `kiln_pp` `predef::tests::reflection_macro`.
- `cargo xtask libstdcxx --gcc-toolchain <dir>` passes the option to both
  compilers and enumerates `<dir>/include/c++/<newest>`.

## Header fixes (a–i of the work package)

- **a.** `(__extension__ e)` is a parenthesized expression: after `(`,
  `__extension__` starts a type only when a decl-specifier follows it
  (`tentative.rs`). The VLA pointer cast itself already worked.
  `ext.gnu.extension/extension-paren-expr.cpp`.
- **b.** `alloc_align` accepts a `std::align_val_t` parameter
  (`alloc_size` does not, as clang). `dcl.attr/gnu-alloc-align-val-t.cpp`.
- **c.** A member access resolved in the pattern into the class being
  instantiated is rebuilt without a completeness check
  (`pattern_member_access`). `temp.inst/friend-trailing-decltype-current-instantiation.cpp`.
- **d.** In-class partial specializations of a member variable template
  are redeclared per enclosing specialization ([temp.spec.partial.member]).
  `temp.spec.partial.member/member-var-partial-spec-in-class-template.cpp`.
- **e.** `restrict`/`__restrict`/`__restrict__` after `&`/`&&`.
  `dcl.ref/restrict-reference.cpp`.
- **f.** Not a friend bug: `<format>` declares `template<class> class
  _Scanner;` and defines `struct _Scanner`, and an implicit
  specialization kept the forward declaration's class-key, so its members
  were private. An instantiation now takes the class-key of the
  definition it instantiates. `class.access/class-key-of-template-definition.cpp`.
- **g.** References to an immediate function in a dependent context are
  not recorded for the address-of check (clang `MarkDeclRefReferenced`).
  `expr.const/consteval-member-dependent-call.cpp`.
- **h.** A consteval override of a non-consteval virtual is allowed in a
  class of consteval-only type (P2996R13 [class.virtual]/18; GCC 16.1).
  `class.virtual/consteval-override-consteval-only.cpp` (`oracle: gcc`).
- **i.** Second wave, one bug: a member or base subobject initialized
  through an inheriting constructor checked the inheriting constructor's
  copied access against the derived class; it now checks the base
  constructor's ([namespace.udecl]/19), so the befriended `_Scanner`
  may use `basic_format_parse_context`'s private constructor through
  `_Parse_context`. `namespace.udecl/inherited-ctor-subobject-access.cpp`.

## Left open

- kiln accepts a member access into the class being defined through a
  parameter in a non-template friend's trailing return type
  (`struct X { int b() const; friend auto f(const X& l) -> decltype(l.b()); };`),
  which clang rejects as incomplete (`expr.rs` `member_object`,
  `class/mod.rs` `this_outside_member_body`).
- The `protected constructor can only be used to construct a base class
  subobject` note (clang) is `can only access this member on an object
  of type ...` in kiln (wording).
- clang's `<prefix>/include/c++` fallback libstdc++ layout (no
  `lib/gcc/...` include tree) is not searched.
