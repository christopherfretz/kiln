# WP-630 — x86-64 `-march=<cpu>` features and `target("...")`

Before WP-630 an x86-64 `-march=<cpu>` set only `"target-cpu"` (spec/
driver.md deviation 19): no `target-features`, no `__SSE4_2__`-style
predefines, and `target("...")` was ignored off `AArch64`.

## Tables

`crates/kiln_driver/src/x86_targets.rs` is generated by
`scripts/gen-x86-targets.py` from a clang (21) binary:

- `CPUS`: every `-march=` CPU kiln accepts (`features.rs` `X86_CPUS`,
  `X86_CPUS_22`) that clang 21 knows (72; not `wildcatlake`, `novalake`):
  the `"target-features"` clang gives a function under `-march=<cpu>`,
  and its predefined macros against the default's (`clang -march=<cpu>
  -dM -E` against `clang -dM -E`): the macros it (re)defines with their
  values, and the default ones it does not define (`__k8`, `__k8__`,
  `__tune_k8__` for most).
- `IMPLIES`: each feature and the features enabling it enables (LLVM's
  `ImpliedFeatures*`, closed), read from `"target-features"` for
  `target("no-popcnt,no-crc32,no-mmx,no-xsave,<f>")` on `i386` (base set
  `x87`; the `no-` items suppress clang's additions below); 118 features:
  those the CPUs, the builtin table and the headers' `target` attributes
  name, closed. `cmov`, `cx8` and a lone `evex512`, which clang does not
  take there, imply only themselves.

## `-march=<cpu>`

`features::resolve` sets `TargetFeatures::extra` to the CPU's features
(`+name`, sorted) for a CPU in `CPUS`; `native` and the other CPUs keep
the default (deviation). The driver passes them as
`CodegenOptions::target_features` (spec/landed/codegen/WP-630.md), the
`__has_builtin` hook's features (`x86_enabled`), and the predefines:
`PredefConfig::x86_macros` (`features::x86_cpu_macros`), applied over the
base file off `AArch64` (`kiln_pp::build_predefines`). Measured equal to
clang 21's `-dM -E` for the default, `westmere`, `nehalem`, `x86-64-v2`,
`haswell`, `skylake-avx512`, `znver4` and `sapphirerapids`. The tables
are clang 21's at both `-fclang-compat` levels (clang 19 and 22 differ
from it for a few recent CPUs).

A CPU with `cx16` also raises `TargetTypes::max_atomic_inline_bytes` to
16 for sema, the Oven and codegen (clang `X86TargetInfo::setMaxAtomicWidth`:
`__atomic_always_lock_free(16, 0)` is true and a 16-byte `__atomic` CAS
is inline `cmpxchg16b`; `TargetFeatures::x86_cx16`).

`-march=westmere` gives `+cmov,+crc32,+cx16,+cx8,+fxsr,+mmx,+pclmul,
+popcnt,+sahf,+sse,+sse2,+sse3,+sse4.1,+sse4.2,+ssse3,+x87` and
`__SSE3__`, `__SSSE3__`, `__SSE4_1__`, `__SSE4_2__`, `__POPCNT__`,
`__CRC32__`, `__PCLMUL__`, `__LAHF_SAHF__`,
`__GCC_HAVE_SYNC_COMPARE_AND_SWAP_16`, `__corei7`, `__corei7__`,
`__tune_corei7__`, without `__k8`, `__k8__`, `__tune_k8__` (westmere has
no AES).

## `target("...")` (`features::x86_target_attr_features`)

The model of clang 19 to 21's `X86TargetInfo::initFeatureMap` for a
function: the module's features (or, with `arch=<cpu>`, that CPU's),
then the attribute's items:

- Each comma-separated item is a feature, `no-<f>` disabling it;
  `fpmath=` and empty items are skipped. `arch=<cpu>` and `tune=<cpu>`
  name the function's CPU and tune CPU (`TargetAttrFeatures::cpu` /
  `tune`); one naming no x86-64 CPU makes clang ignore the whole
  attribute with a warning, so kiln returns the module's features
  (without the warning).
- The `evex512` items are held back. With `avx512f` in the map or an
  `avx512*` item (and no `avx10.1-512` in the map), `+evex512` is
  applied last, or `-evex512` when an item disabled it. Otherwise, with
  an AVX10 feature in the map or among the items, `evex512` follows
  `avx10.1-512`. The AVX10 items apply after the others.
- Enabling a feature enables what it implies (`IMPLIES`); disabling one
  disables every feature that implies it.
- Then `sse4.2` enables `popcnt` and `crc32`, `sse` `mmx`, and `avx`
  `xsave`, unless an item disabled that feature.

The result is the items' `+` features in order (what an `always_inline`
callee requires first, as on `AArch64`), then the whole map. Verified
against clang 21's `"target-features"` (and `"target-cpu"` /
`"tune-cpu"`) for 25 strings, including the clang 19 headers'
`sse2,no-evex512` and `avx512vl,avx512bw,no-evex512`, under the default,
`westmere`, `skylake-avx512` and `znver4`: equal except
`tune=generic,...`, which clang ignores with a warning (kiln too, but
silently).
