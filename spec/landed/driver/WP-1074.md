# WP-1074 — Module cache: racing misses (entry lock, content-named stamps)

Origin: WP-914 saw `crates/kiln_driver/tests/module_cache.rs`
`racing_misses_all_succeed` fail now and then under load.

## Reproduction and root cause
- A scratch harness ran N `kiln++ -c c.cpp` racers on a cold
  `-fmodules-cache-path` (the test's miniature libc++), then checked the
  exit codes, the entry listing, and that a `-v` re-run only says
  `using`. Before the fix: 2 of 200 races of 4, 4 of 150 of 8, 11 of
  130 of 16 failed. Every failure was the re-run assertion
  (`building 'std.compat' into ...` or `building 'std' into ...`). No
  racer ever failed and no temporary file was ever left.
- Cause: product bug. Every racer built, renamed its module file into
  place, then renamed its stamp. The stamp named the module file by
  size and modification time, and each racer's copy has its own mtime.
  The module file and the stamp left last could come from different
  racers (seen in the snapshots: stamp `...224.235`, module file
  `...224.236`). The entry was then a miss for the next compile, which
  rebuilt it. The other candidates were ruled out: renames are atomic,
  the temporary names carry the pid, `std.compat`'s stamp does not list
  `std.pcm`, the builds are byte-identical (checked with `cmp`), and the
  test's `names` listing is sorted.
- This container's workspace bind mount (macOS host) accepts `flock` but
  does not enforce it between processes. The target directory, where
  the test ran under WP-914, is on that mount.

## Fix (crates/kiln_driver/src/module_cache.rs)
- The stamp's first line is `<size> <checksum> <pcm>`. `<checksum>` is
  the module file's trailing §11.3 checksum, so any racer's identical
  copy matches any racer's stamp. The magic is now
  `kiln-module-cache-stamp 2`.
- `EntryLock`: a miss takes `<name>.lock` (`File::try_lock`, polled with
  a 1–50 ms back-off), rechecks the entry, removes stale
  `<name>.pcm.tmp.*` / `<name>.stamp.tmp.*`, builds, and writes the
  stamp. On drop it removes the lock file, then unlocks. A waiter checks
  the locked file's device and inode against the path and reopens on a
  mismatch. A hit removes a free stale lock file. The wait limit is
  `DEFAULT_WAIT` (120 s), or `KILN_MODULE_CACHE_WAIT_MS`. On timeout or
  a lock error the compile builds the module from its source (part A).
- spec/modules.md §11.12 "Stamp" and "Concurrency" (the rules),
  spec/driver.md "Module cache".

## After
- Same harness, after the fix, 0 failures in every set: 150 races of 16
  and 200 of 4 on `/tmp`, where `flock` excludes; 150 races of 16 and
  200 of 4 on the bind mount, where it does not (the content-named stamp
  alone keeps the entry valid there).
- The module_cache test binary looped under a parallel workspace clippy
  on the shared jobserver: see the handback.

## Tests (crates/kiln_driver/tests/module_cache.rs)
- `racing_misses_all_succeed` (4 racers, now through `race` and
  `check_settled`).
- `many_racing_misses_build_once`: 16 racers. Exactly one
  `building 'std.compat'` where locks exclude.
- `killed_racer_leaves_no_trace`: SIGKILL of one racer out of 6, at 0,
  15 and 40 ms.
- `miss_waits_for_the_lock_holder`: the test holds the lock and plants
  temporary files. The child waits; after the release it builds and
  clears them.
- `stuck_holder_falls_back`: `KILN_MODULE_CACHE_WAIT_MS=200`. The child
  gives up and falls back to part A, and the held entry is untouched.
- `hit_removes_a_stale_lock_file`.
- Unit test `stamps`: an identical copy renamed in still matches; other
  bytes do not.
- The tests use the target directory, or `$TMPDIR` (removed afterwards)
  when locks do not exclude there. The probe locks 8 fresh files: on the
  bind mount a single fresh file sometimes excludes (2 of 25 runs chose
  the target directory with a one-file probe). The tests that need exclusion skip
  when neither directory provides it. The module_cache test binary takes
  about 3 s.

## Not done
- Eviction (WP-1050).
- Locks that do not exclude are not detected at run time. Racers then
  all build, and the content-named stamp keeps the result correct.
