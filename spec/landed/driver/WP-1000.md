# WP-1000 — x86-64 `-m<feature>` flags, feature maps and gating

Before WP-1000 every x86 `-m<feature>` / `-mno-<feature>` flag was an
unknown argument, so CMake's CPU-dispatch probes compiled the SIMD paths
out (x86_64 sweep: Bitcoin Core 12 TUs, OpenCV 64 TUs), and the
`-march=<cpu>` features and macros were clang 21's at both compat levels.
The contract is spec/driver.md "x86-64 target features".

## What landed

- `crates/kiln_driver/src/x86_features.rs`: clang 19's and clang 22's
  flag lists (104 common, 3 clang-19-only, 6 clang-22-only, plus
  `-m[no-]apx-features=` and `-mapx-inline-asm-use-gpr32`), the driver
  spellings and `unifyTargetFeatures` dedup, the per-version implication
  graph (the generated clang 21 table with measured differences), the
  per-version CPU rows (`CPU_19`, `CPU_22`), `-march=native` from
  `/proc/cpuinfo`, `initFeatureMap` (`cpu_map`, `apply_items`: clang 19's
  `evex512` reorder, the `sse4.2`/`sse`/`avx` additions) and
  `getTargetDefines` (`feature_macros`).
- Off x86-64 the flags are clang's `unsupported option '<flag>' for
  target` (or, for `-msse4`, `-msse4.2`, `-m[no-]3dnow[a]`, unused);
  x86 `-mcpu=` is `unsupported option` too (was `unsupported argument`).
- `target("...")` on x86-64 builds clang's `getFunctionFeatureMap`: the
  `arch=` CPU or the module's, then the command line's items as written
  (`CodegenOptions::target_features_written`), then the attribute's. At
  `-fclang-compat=22` `evex512` items are dropped (clang 22 has no such
  feature; the builtin headers are clang 19's and say `no-evex512`).
- The x86 AVX calling-convention check compares the caller's and the
  callee's maps: clang's `-Wpsabi` warning when neither has the feature,
  its `err_avx_calling_convention` (`cg_avx_calling_convention_mismatch`)
  when exactly one has it (spec/codegen.md §7q).

## Interfaces

- `kiln_codegen::TargetAttrModule<'_>` (module features, CPU features,
  features as written, `v22`) and `TargetAttrParser = fn(&str,
  &TargetAttrModule) -> TargetAttrFeatures` (was `fn(&str, &[String],
  bool)`); `kiln_driver::features::target_attr_parser` wraps the AArch64
  parser.
- `CodegenOptions::{target_cpu_features, target_features_written}`,
  `TargetFeatures::{x86_cpu_features, x86_written}`.
- Diagnostic `cg_avx_calling_convention_mismatch` (error).

## Differential results

- Macros (`-E -dM`) and module `"target-features"`/`"target-cpu"`
  against clang++-19 (at `-fclang-compat=19`) and clang++-22: every
  single flag, every `-march=` CPU and 128 flag combinations, 724 cases,
  no mismatch except `-march=native` (host-dependent).
- `target("...")` function attributes (scratch `at.cpp`, 13 command
  lines x 2 versions): no mismatch except `-march=native`.
- Gating and psABI diagnostics: byte-identical stderr with clang++-19
  (`crates/kiln_driver/tests/codegen.rs`).

## Not done

- x86 function multiversioning (`target_clones`): WP-1044, xfail
  `tests/conformance/ext.multiversion/target-clones-x86.cpp`.
- glibc's `_Float128` functions as `__float128` ones: decided to keep
  the types distinct; WP-1043, xfail
  `tests/conformance/basic.extended.fp/float128-glibc-typedef-x86.cpp`.
- The flags listed under spec/driver.md "Not modelled"; clang's
  `-Winvalid-feature-combination`; clang's `unknown target CPU` wording
  for a bad `-march=`, and a bad `-mtune=` is accepted; `-march=native`
  has no host CPU name; `wildcatlake`/`novalake` are not expanded.
- After the first codegen error clang emits no further functions; kiln
  reports the gating errors of every function (diagnostic count only).
- The x86_64 sweep was not re-run (implementers cannot push the sweep
  branch).
