# WP-1023 — Precompiled headers (textual PCH, clang's PCH flags)

This is 1.0 work item A6. CMake's `target_precompile_headers` and clang's
PCH flags work. In 1.0 the PCH gives correctness, not speed. Contract:
spec/driver.md "Precompiled headers (WP-1023)".

## Flags (`crates/kiln_driver/src/args.rs`)
- `PchArgs`:
  - `-include-pch` (separate-only, last wins);
  - `-emit-pch`, `-fno-validate-pch`, `-include` and `-include-pch`,
    each also accepted behind `-Xclang`;
  - the `-f[no-]pch-{instantiate-templates,codegen,debuginfo,
    validate-input-files-content}` flags, accepted with no effect;
  - `-Winvalid-pch` (a known group, empty as in clang).
- `Input::header` and `is_header_input` cover `-x c++-header`,
  `-x c-header`, and the header extensions.
- `split_valued` now takes the longest matching option across all its
  tables (`SEPARATE`, `SEPARATE_OR_EQ`, `JOINED_OR_SEPARATE`). Before, the
  first match won, which depended on table order. Tests:
  `longest_option_wins` (each collision) and `pch_flags` (CMake's command
  lines).

## Producer and consumer (`crates/kiln_driver/src/pch.rs`)
- `Record`: the `KILNPCH 1` text format (see the spec for the line
  grammar). It is written with `kiln_pp::bmi::write_file` (atomic) and its
  `end` line is checked with `bmi::checksum`. The option fingerprint is
  `pp_cmd::Job::fingerprint`, the one module files use.
- `produce`: runs the `-fsyntax-only` path on the header, with
  `main_is_header` set so `#pragma once` gets no warning. It then hashes
  the dependency list, writes the record and writes the user's `-MD`
  depfile. `-o` names the PCH unless a link follows.
- `consumer`: validates in clang's order:
  1. the record;
  2. language options;
  3. target;
  4. macros, by `checkPreprocessorOptions`;
  5. non-system files.

  Wording is per `-fclang-compat` level: the `drv_pch_*` diag ids, and
  `note_pch_rebuild[_19]`. It returns the replayed arguments: the PCH's
  includes and main file, then the consumer's includes minus duplicates,
  with relative paths resolved against the producer's working directory.
  It also returns the seed for the depfile.
- `kiln_driver::run` partitions the inputs into producers and the rest.
  Output for flags that existed before is unchanged.

## Harness
- `pch: <header>` directive (spec/harness.md): the compiler under test,
  and a clang oracle, each build `<scratch>/[oracle-]test.pch`, and the
  test compile adds `-include-pch`. Tests:
  `tests/conformance/cpp.include/pch-{consumer,run,redefinition}.cpp`.
- `scripts/oss/selftest.sh`: a CMake `target_precompile_headers` project
  with an unguarded prefix header and two TUs. It is built and run with
  clang++-19 and with kiln++, and timed with PCH on and with PCH off
  (where `-include` is used instead).

## Evidence
- `crates/kiln_driver/tests/pch.rs`, with 7 tests:
  - CMake's producer and consumer, with the depfiles byte-identical to
    clang++-19's;
  - object and link;
  - output naming;
  - replay order and the producer's working directory;
  - option, target and macro mismatches at compat 19 and 22;
  - stale, deleted, missing and foreign PCH files;
  - `-MMD`.
- Clang's wording was compared live with clang++-19 and clang++-22 for
  every diagnostic. The one deviation: kiln compares content, where clang
  compares mtime.
- OSS: glaze and reflect-cpp build with PCH on (`scripts/oss/projects.toml`;
  docs/status/oss/glaze.md, reflect_cpp.md).

## Follow-ups
- A serialized-AST/Oven-state PCH that shares the module-file format
  (spec/modules.md §11). The goal is that PCH also saves time.
- Probing `-include foo.h` for `foo.h.pch`, as clang's driver does.
- `-fsyntax-only foo.hpp` still warns `#pragma once in main file`, and
  clang++-19 does not, because the input is a header. Only producers set
  `main_is_header` today, and the warning is existing behaviour, left
  byte-identical.
