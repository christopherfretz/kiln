# WP-1115 — `-ftime-trace`: clang's Chrome trace, with Oven events

1.0 work item B2: `-ftime-trace[=<path>]`, `-ftime-trace-granularity=<n>`
and `-ftime-trace-verbose` write the trace clang writes, where clang
writes it, plus the constant evaluator's events. Replaces WP-792's
"accepted, warns, writes nothing" (`drv_time_trace_ignored` is gone).

## Recorder
- `kiln_source::trace` (spec/driver.md "Time trace"): thread-local,
  monotonic (`Instant`), safe Rust, no dependency; the JSON is written
  by hand and read back by a small parser (`trace::Json`) for the
  `opt`/`llc` children's traces and for the tests.
- Off: `trace::begin_on` is `#[inline(never)]` and returns `None` after
  one thread-local read; `Scope::with_detail` computes its detail only
  when recording. Below the granularity an event is counted in its
  `Total` and dropped (memory stays flat on a 3M-call verbose trace).

## Driver
- `time_trace::{writes, unused, settings, path, InputTrace}`: which runs
  write (compiler jobs: `-c`, `-S`, link, `-E`, `-M`), clang's
  `handleTimeTrace` path rules (directory, file, link `-dumpdir`,
  output with `.json`), the unused-argument warnings (`-fsyntax-only`,
  header precompiles), `drv_invalid_int_value` for a bad granularity.
- `ExecuteCompiler`, `Frontend`, `Backend`, `Optimizer` (the `opt`
  child) and `CodeGenPasses` (the `llc` child), whose own
  `--time-trace` output is merged on kiln's time base. No trace for a
  failed input; a write error is `unable to open output file`, exit 1.

## Frontend events
- `kiln_pp`: `Source` (async b/e, per `#include`d file).
- `kiln_parse`: `ParseDeclarationOrFunctionDefinition`,
  `ParseFunctionDefinition`, `ParseClass`, placed where clang records
  them (no event for templates, namespaces, `using`, `static_assert`,
  `export`, late-parsed member bodies).
- `kiln_sema`: `InstantiateClass` / `InstantiateFunction` on the
  instantiation frame (verbose: `file`, `line`),
  `PerformPendingInstantiations`.
- `kiln_codegen`: `CodeGen Function`.

## Oven
- spec/oven.md "Trace hook": `crates/kiln_oven/src/hooks.rs`; five thin
  call sites (`evaluate`, `evaluate_chars`, `vm.rs` `enter` and
  `Op::Ret`, `vm/meta.rs`). Events `EvaluateAsInitializer`,
  `EvaluateAsRValue` (static_assert), `EvaluateAsConstantExpr`,
  `OvenCompile`, `OvenMetaOp`, and with `-ftime-trace-verbose`
  `ConstevalCall` / `ConstexprCall` per VM call. The hook API is the
  entry point for WP-1116's `-fconstexpr-stats` / `-fconstexpr-profile`.

## Overhead
Measured on aarch64 under host load 17-23 (shared host), release
builds, the parent commit f350eb82f's `kiln++` as "base".
- Off, `cargo xtask bench --filter oven/ --compiler <WP-1115 kiln++>
  --compare-with <base kiln++>` (5 runs, min/max dropped), twice:
  geometric mean time 1.015x and 0.99x over the 25 entries (excluding
  `oven/time-trace`, which the base cannot trace), memory 1.00x; the
  per-entry spread under that load is ±25%, with no entry slow in both
  runs.
- Interleaved A/B (`base`, `off`, `on` = `-ftime-trace=/dev/null`,
  `verbose` = `on` + `-ftime-trace-verbose`; each entry's `//@ args`
  with `-std=c++26 -S -emit-llvm -o /dev/null` under `/usr/bin/time -f
  '%e %M'`, the four alternating within each of 7 rounds; median),
  summed over the 11 entries above 150 ms: base 3.32 s, off 3.37 s
  (+1.5%, within the summed 10 ms timer resolution), on 3.38 s (+0.3%
  over off), verbose 4.15 s (+23%; per-call clock reads:
  `oven/time-trace` 0.22 -> 0.43 s, `vector-alloc` 0.48 -> 0.75 s). Max
  RSS within ±0.5 MB in every configuration (after the fix below).
- `oven/time-trace` baseline (verbose, traced): 479 ms, 12.3 MB.
- Found and fixed while measuring: a VM frame unwound without `Ret` (a
  failed `__builtin_constant_p` trial) kept its call open until the
  caller returned, so `oven/trial-rollback` traced verbose held 20 000
  open calls (+4.4 MB, a 2 MB trace); calls now also end at the next
  call entered at their depth (`unwound_calls_end_at_the_next_call`).
