# WP-667 — `-print-resource-dir`, and `-v` reaches the linking `clang++`

Found configuring fmt 12.2.0 with CMake and kiln++ as the C++ compiler
(docs/status/oss/fmt.md). CMake's compiler probes ask the compiler for
`-print-resource-dir` (to drive `clang-scan-deps`) and parse the `-v`
output of a link for the linker, its implicit link directories and
libraries, and from those the library architecture. kiln++ rejected the
first (`unknown argument`) and its `-v` printed only its own `clang++`
command, so CMake recorded no linker id, empty
`CMAKE_CXX_IMPLICIT_LINK_LIBRARIES` / `_DIRECTORIES` and an empty
`CMAKE_LIBRARY_ARCHITECTURE`, where clang++ fills all of them.

## Behaviour

- spec/driver.md "`-v`, `--version`, `--help`": `-print-resource-dir`
  and `--print-resource-dir` print the resource directory
  (`Toolchain::resource_dir`: `-resource-dir`, else the default) and a
  newline to standard output and exit 0, whatever else is given
  (`Args::print_resource_dir`).
- spec/driver.md "Code generation", `-v`: when linking, the `clang++`
  link command gets `-v` first (`codegen_cmd::link_command`), so clang's
  own `-v` output (its banner and the linker's command line) follows
  kiln's. With these, CMake's `CMakeCXXCompiler.cmake` for kiln++ equals
  clang++'s except for the version, the archiver/ranlib/scan-deps it
  picks for that version and the resource directory.

## Tests

- `crates/kiln_driver/tests/driver.rs` `print_resource_dir`.
- `crates/kiln_driver/tests/codegen.rs` `verbose_prints_commands` (the
  link step's `-v` and the linker's own command line).
