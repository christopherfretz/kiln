# WP-1050 — Module cache pruning, as clang prunes its module cache

Origin: WP-984. The cache key covers kiln's identity, so every rebuilt
kiln left a new ~9 MiB entry and nothing removed old ones ("No
eviction"). Operator decision (11-09): keep the cache on by default and
prune like clang.

## clang's rules (the reference)
- clang 22 `maybePruneImpl` (clang/lib/Serialization/ModuleCache.cpp),
  clang 19 `pruneModuleCache` (clang/lib/Frontend/CompilerInstance.cpp,
  called from `createASTReader`); the same rules: no pruning when the
  interval or prune-after is 0; `<cache>/modules.timestamp` missing:
  create it, stop; its mtime no older than the interval: stop; else
  rewrite it ("a benign race" between two compiles noticing at once),
  walk every subdirectory, remove each `.pcm`, `.timestamp` and
  `modules.idx` whose access time is older than prune-after (and its
  `.timestamp`), and remove a directory left empty.
- Flags (clang/include/clang/Options/Options.td): `-fmodules-prune-
  interval=<seconds>` (default `7 * 24 * 60 * 60`) and `-fmodules-prune-
  after=<seconds>` (default `31 * 24 * 60 * 60`), `unsigned`
  (`HeaderSearchOptions`), read with radix auto-detection; `-1`, `+5`,
  `08`, `4294967296` and an empty value are "invalid integral value"
  errors (checked against clang++-22 and clang++-19).

## kiln (crates/kiln_driver/src/module_cache.rs, args.rs, help.rs)
- `Args::modules_prune_interval` / `modules_prune_after`
  (`parse_clang_unsigned`), `module_cache::Prune::from_args`; both flags
  in `--help`.
- `maybe_prune` runs after a compile's first cache lookup, hit or miss.
  The timestamp is clang's; the update is taken under a non-waiting
  advisory lock on it with the age checked again, so one compile prunes
  per interval, and a timestamp that cannot be updated means no pruning.
- Only key directories (32 lowercase hex digits, `lstat`, links never
  followed) other than the compile's own are considered; whole entries
  are removed (`prune_entry`).
- Last use = newest mtime of the entry's non-lock files, not atime
  (unreliable under `noatime`/`relatime`, kept fresh by any reader). A
  hit refreshes its stamp's mtime when older than a day (or half the
  prune-after), never the module file's, which importers' dependency
  files list (WP-1051) (`note_use`).
- Safety: the pruner try-locks every module lock of the entry; contention
  keeps it. Holding them it renames each stamp to `<name>.stamp.pruning`
  and checks the last use again; a hit touches the stamp through its
  handle and then checks the stamp is still at its path, so a hit either
  keeps the entry or becomes a miss that waits for the locks. A miss
  whose fresh directory a pruner removed before its lock makes it again.
  A lock holder removes a dead pruner's `.stamp.pruning`.
- Removal failures are said under `-v` only; `-v` also says `pruning
  '<root>'` and `removed unused '<entry>'`.
