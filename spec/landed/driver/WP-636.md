# WP-636 — `-fkiln-source-path-style={clang,gcc}` selects the file spelling of the source-location builtins

Before WP-636 `__builtin_FILE()`, `__builtin_FILE_NAME()`,
`std::source_location::current()` and `std::meta::source_location_of`
always spelled an included file as GCC 16.1 does (its absolute path with
empty and `.` components dropped and `dir/..` folded through real
directories), while `__FILE__` kept clang's spelling and the specs named
clang's for the builtins.

## Behaviour

- `-fkiln-source-path-style=<clang|gcc>` (`Args::source_path_style`;
  any other value is `invalid value`, the last one wins) is passed to the
  `SourceManager` next to the prefix maps (`pp_cmd.rs`,
  `SourceManager::set_source_path_style`, a `OnceLock`).
- `SourceManager::presumed_file_name(&p, loc)` (was `gcc_presumed_name`):
  `SourcePathStyle::Clang`, the default, is `p.file_name` as written;
  `SourcePathStyle::Gcc` is the simplification above. Both builtins.rs
  users (`record_source_loc`, which also serves default arguments and
  default member initializers, and `meta_source_location`) call it, then
  `remap_macro_path`, so one translation unit is self-consistent.
- `__FILE__` / `__BASE_FILE__` are unchanged (clang's, under both).
