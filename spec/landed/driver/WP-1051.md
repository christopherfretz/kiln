# WP-1051 — `-MD`/`-MMD` with `import std;` and named modules, as clang lists them

Origin WP-984. Rules: spec/driver.md "Dependency output" (module files)
and "Module cache"; spec/modules.md §11.12 "Dependency output".

## Oracle (clang 19 and 22, `--precompile std.cppm` then the importer)
- `import std;` with `-fmodule-file=std=std.pcm` or
  `-fprebuilt-module-path`, `-MD` or `-MMD`: `hello.o: hello.cpp`. No
  module file, no header inside it. A TU's own `#include`s are listed as
  usual (`mixed.o: mixed.cpp user.h`, `-MP` adds `user.h:`).
- `-fmodule-file-deps`: the module files after the files seen so far,
  as spelled (`./` kept) for `-fmodule-file=<name>=`, cwd-joined
  absolute for a prebuilt path; kept by `-MMD`, phony rules under `-MP`;
  transitive imports dependencies first (`std.pcm pb/m.pcm`).
- `--precompile` lists them by default (`pb/m.pcm: m.cppm mhdr.h
  std.pcm`); `-fno-module-file-deps` turns that off. `-c m.cppm`: clang
  19 lists them, clang 22 does not.
- A nameless `-fmodule-file=<path>` is listed first, as spelled, always.

## kiln before
- A module file's capsule replay entered its files through the
  preprocessor, so `import std;` from the cache listed `std.cppm`, every
  `std/*.inc` and every libc++ header (1153 lines under `-MD`; `-MMD`
  kept `std.cppm` and the `.inc` files), the same on a hit and a miss but
  not under `-fkiln-bmi-image`, which lexes nothing. The cache module
  file itself was never listed; `-fmodule-file-deps` was an unknown
  argument.

## Change
- `kiln_pp`: `PpCallbacks::module_file_read(ModuleFileRead)` when an
  import reads a kiln module file (path as clang names it, the cache's
  stamped inputs) and `PpCallbacks::module_unit(begin, from_module_file)`
  around every unit; `StdModuleCache` returns `StdModuleFile { path,
  inputs }`.
- `kiln_driver`: `DepCallbacks` lists nothing inside a module-file unit;
  `DepList::module_file_read` lists module files as spelled under
  `-fmodule-file-deps` (default for `--precompile`) and the cache entry
  unless `-fno-module-file-deps`, plus its inputs as system files;
  nameless `-fmodule-file=` paths first, as spelled. `module_cache`
  returns the stamp's inputs on a hit and the list it stamps on a miss;
  its nested build passes `-fno-module-file-deps`.

## Tests
- kiln_driver `depfiles` `module_imports_list_module_files_as_clang_does`
  (11 command lines, each checked literally and byte for byte against
  clang++-19 on its own module files), `module_cache`
  `depfile_same_on_miss_and_hit` (miss = hit = image under `-MMD`; `-MD`
  miss = hit; `-MP`; `-fno-module-file-deps`; `std.compat`; the listed
  path is the `-v` "using" path), `deps::tests::module_files`,
  `module_cache::tests::stamps` (inputs order).

## Deviations
- Transitive module files in read order, not dependencies first.
- The cache entry is listed without `-fmodule-file-deps` and, under
  `-MD`, its inputs too (clang has no implicit std build to compare).
- clang 19's `-c m.cppm` default listing is not followed (clang 22's is).
