# WP-1096 — modules image gate: a namespace named like its module

Extends spec/modules.md §11.11 "Part 2a", "ODR merging": the gate that
decides whether an imported unit is built from its declaration image
now counts a name as seen only when it is interned **and** not one of
the preprocessor's unseen names. The rule, its reasons and the `-v`
notes are there. This file records what landed and where.

## What landed

- **Unseen names** (`crates/kiln_pp/src/preprocessor.rs`,
  `Preprocessor::unseen_names`): the components of a module or
  partition name that a module or import directive interned for the
  first time. `maybe_module_directive` (`directive.rs`) records the
  interner's length before reading past the keyword; `read_module_name`
  (`modules.rs`) adds a component whose symbol index is at least that
  mark, except `std` (sema declares namespace `std` implicitly).
- **Seen again**: `next_item` removes an identifier it returns, and an
  identifier in a `Marker::Pragma`'s tokens (`seen_name`,
  `marker_out`); an image that is used marks every name it declares.
  The per-token cost is one emptiness check of a vector that is empty
  in a translation unit without imports.
- **Gate** (`modules.rs`, `try_image_unit` / `name_seen`): replays when
  an image's name is seen, as before for every interned name otherwise.
- **Observation**: `Preprocessor::image_imports` (`ImageImport`: key,
  and why the unit was replayed) logs each import whose module file
  holds an image, with the image enabled; with `-v` the driver prints
  `note: imported 'm' from its declaration image` or
  `note: replayed 'm': its image declares 'm', already seen` (also
  "it imports other units", "its image names another main file")
  (`crates/kiln_driver/src/pp_cmd.rs`, `note_image_imports`, called by
  the `-fsyntax-only` and code generation paths).
- No new diagnostic id, no sema change.

## Before and after

Observed with the `-v` notes and by blanking the capsule's source
(only an importer that does not replay still compiles). Before the
change, `image-gate-module-name-run.cpp` and
`image-gate-dotted-run.cpp` replayed (`its image declares 'imgm'` /
`'imga', already seen`), and `kind2_image_gate_module_names` failed at
its first import of the blanked `m`. After it, both corpus tests and
the driver test's plain, dotted and implementation-unit imports are
built from the image (3 hits in the driver test), while its five true
clashes replay.

## Tests

- `crates/kiln_driver/tests/modules_bmi.rs`,
  `kind2_image_gate_module_names`: `export namespace m` in module `m`
  and `a::b` in module `a.b` import from blanked capsules (and the
  first links and runs); `module m;` imports its interface from the
  image; replays for `namespace m` and `int g;` declared before
  `import m;`, for a second module `n` whose image also declares
  `namespace m`, and for a global module fragment `#include` declaring
  `namespace m` in an importing module unit.
- `tests/conformance/module.interface/`:
  `image-gate-module-name-run.cpp` (`Inputs/img-gate.cppm`: constexpr,
  consteval, a static local, a non-inline function and an evaluated
  variable in `namespace imgm`), `image-gate-dotted-run.cpp`
  (`Inputs/img-gate-dotted.cppm`, module `imga.gate`), and
  `image-gate-clash-run.cpp` (the importer's own `namespace imgm` and
  `::twice`, replayed). All pass under kiln (with the clang 22 oracle),
  with `--bmi-kind 2 --bmi-image`, and under `--compiler clang++-19`.

## Deviations and follow-ups

- Names interned only by other directives (macro names, `#if`
  operands, predefined macros) still count as seen: a module declaring
  such a name replays. Making them unseen needs the same exception list
  as `std` for every name sema declares without a token.
- Two images that open the same namespace still replay the second (no
  merging before S5).
