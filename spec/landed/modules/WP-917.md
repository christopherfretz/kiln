# WP-917 — module files and separate module compilation (part B, step 1)

Extends spec/modules.md (§9, §11, "Tests"), spec/driver.md "Modules",
spec/source.md "SourceManager API" and spec/harness.md (`module:`,
`unit:`, `two-step`). The design and its rules are spec/modules.md §11;
this file records what landed and where.

## What landed

- **Module file format** (`crates/kiln_pp/src/bmi.rs`): the source
  capsule of §11.1-§11.3. The magic is `KILNBMI\0`, then the format
  version (1) and the kind (1, capsule). It holds the kiln version and
  sha, the module key and unit kind, the predefines, the fingerprint
  (§11.4), the recorded imports, every file read (path and text), and
  the include and `#embed` logs. A FNV-1a 64 checksum closes it. The
  file is written atomically (a temporary file in the same directory,
  then a rename), and the same command gives the same bytes. The reader
  streams from the file: every length is checked against the bytes left
  before anything is allocated, and every failure is a `BmiError`.
- **Recording and replay** (`kiln_pp`: `preprocessor.rs`,
  `modules.rs`): an interface unit compiled with `--precompile` or
  `-fmodule-output` records what its preprocessing reads. An importer
  rebuilds the unit from the capsule in-process, through part A's
  pipeline. A replayed file whose on-disk copy is unchanged shares its
  `FileId` (`SourceManager::load_regular_file_expecting`). A changed or
  missing file is replayed from the capsule's text.
- **Driver** (`kiln_driver`: `args.rs`, `pp_cmd.rs`, `codegen_cmd.rs`,
  `syntax_cmd.rs`):
  - `--precompile` and `-fmodule-output[=path]`;
  - `-fmodule-file=<name>=<module file or source>` and the nameless
    `-fmodule-file=<path>`, which gives clang's warning;
  - `-fprebuilt-module-path=` (`.pcm` first);
  - `.pcm` inputs;
  - the fingerprint mismatch errors and their fatal error, the
    not-found, wrong-module, foreign (clang), version and corrupt-file
    fatal errors (§11.4). These use new ids in
    `crates/kiln_diag/src/ids/pp.rs` and `ids/drv.rs`.
- **Harness** (`xtask/src/test/`):
  - `run` tests with `module:` lines are always two-step, under kiln
    and the clang oracle alike: each unit is compiled to a module file
    and an object, then the test and its `unit:` files are compiled
    separately and linked;
  - `two-step` gives compile-kind tests module files too;
  - the GCC oracle skips module tests.

## Measured

On libc++ 19's `std.cppm` (spec/modules.md §11.8), importing the module
file costs 1.05x part A's peak RSS (89.5 vs 85.4 MiB with `-c`) in the
same time. Precompiling takes 1.07 s and 96.8 MiB and writes 8.9 MB.

A reader that read the whole file into one buffer measured 1.18x. glibc's
dynamic mmap threshold grew to the freed buffer's size, so the reader now
streams.

## Tests

- `tests/conformance/module.interface/two-step-run.cpp`,
  `two-step-visibility.cpp`;
- `module.unit/two-step-partitions-run.cpp`,
  `two-step-impl-unit-run.cpp`;

All of these pass under kiln, and with clang 19 and 22 as the compiler.

- `crates/kiln_pp/src/bmi.rs` unit tests: round trip, foreign and
  version mismatch, every truncation and byte flip, a damaged body behind
  a valid checksum, and fingerprint comparison.
- `crates/kiln_driver/tests/modules_bmi.rs`: determinism, the lookups,
  `-fmodule-output`, `-c m.pcm` and a link, the mismatch diagnostics,
  and 40 damaged module files.
- `xtask/src/test/directives.rs` `module_and_min_oracle_directives`
  (`unit:`, `two-step`).

## Not in this step

These are covered in spec/modules.md §11.9:

- dependency scanning and CMake;
- header-unit module files;
- an `import std;` module-file cache and harness test (`import std;`
  two-step works by hand: `--precompile std.cppm`, then
  `-fmodule-file=std=std.pcm`, then link `std.o`);
- the serialised-AST format (kind 2).
