# WP-1064 — modules declaration image S2: bodies

Extends spec/modules.md §11.11 "Part 2a" with stage S2 ("Bodies (S2,
WP-1064)", the coverage list, the encoding grammar's body sections and
type tag 12, the label and lifetime-extended-temporary payloads, "What
`import std;` still needs after S2", and the S2 rows of "Measurements").
The design, the encoding and the numbers are there. This file records
what landed and where.

## What landed

- **Records** (`crates/kiln_sema/src/bmi_image/body.rs`): constant,
  string, expression and statement arenas, each an offset table plus a
  blob, so every record is addressable by index (for WP-1069). One
  per-kind schema (`expr_shape`, `stmt_shape`, the `F` field kinds)
  drives the writer, the validator and the reader, so there is no second
  encoding. `EXPR_KINDS` (40) and `STMT_KINDS` (18) are append-only.
  Records are post-ordered; the statement-expression back edge is checked.
- **Writer**: carries the bodies of inline, `constexpr` and `consteval`
  functions (`carries_body`), every variable initializer, every default
  argument, the locals of those bodies (variables, labels,
  lifetime-extended temporaries), and a variable's scalar evaluated value.
  It decodes its own output and falls back on any inconsistency.
  `static_assert` declarations are checked at precompile and skipped.
- **Reader**: builds parameters, locals, expressions and statements
  through `AstBuilder` in index order, then attaches bodies, default
  arguments and initializers and restores evaluated values.
- **Declaration image** (`crates/kiln_sema/src/bmi_image.rs`):
  `IMAGE_VERSION` 2; full `FnSpec`/`VarSpec` words; type tag 12 (the
  builtin sugar types `__size_t`, `__signed_size_t`, `__ptrdiff_t`,
  mapped through the new `Sema::builtin_sugar`); payloads `Label` and
  `Let` (lifetime-extended temporary); parameter default arguments;
  variable initializer and evaluation state; function body kind 2 (a
  statement record).
- **AST** (`crates/kiln_ast/src/{expr,stmt,consts/value}.rs`): raw
  constructors and pushers the loader needs to rebuild nodes from their
  header and slots.
- No new diagnostic id; no driver or harness change (the flag, the
  `--bmi-image` harness option and the fallback note are WP-1048's).

## Deviations

- Bodies are built eagerly with the declarations (WP-1069 makes them
  lazy; the arenas are already indexed).
- Kept on fallback, each a BACKLOG follow-up under WP-1064: lambdas
  (local classes, with S3), `try`/`catch` and function-try-blocks,
  attributes with arguments, lifetime-extended temporaries with a
  constant value, coroutines, `asm`, contract assertions, computed
  `goto`, expansion statements. Class expressions wait for S3,
  template expressions for S4, macro and other-file locations for S7.
- The flag stays off by default.

## Tests

- `crates/kiln_sema/src/bmi_image.rs`: `round_trip`,
  `rejects_out_of_order_references` and `fuzz_never_panics` now run on
  a sample with body sections; the rejects cases add an operand naming
  itself, a block containing itself, a declaration statement naming a
  global, a function body that is not a compound statement, and a label
  outside a function.
- `crates/kiln_driver/tests/modules_bmi.rs`:
  `kind2_declaration_image_bodies` (blanks the capsule's source, so the
  importer's `static_assert`, call and link run from the image alone);
  `kind2_declaration_image_fallback` gains the lambda, `try`, macro and
  class-initializer reasons and drops the inline, `static_assert` and
  initializer cases S2 now carries.
- `tests/conformance/module.interface/`: `image-bodies-run.cpp`
  (`Inputs/img-bodies.cppm`: every carried statement kind, defaults,
  `__func__`, statement expressions, temporaries, `throw`, initialized
  variables) and `image-bodies-odr-run.cpp` (`Inputs/img-bodies2.cppm`,
  `Inputs/img-bodies2-user.cpp`: a `static` local shared by two
  importing units, character and string literal kinds,
  `__builtin_choose_expr`, `__null`, floating and 64-bit arithmetic, a
  `const` variable as an array bound). Both import from the image (no
  fallback) and pass with the image on and off and under clang++-19.

## Gates (image on)

All on the harness, with the image on, before the merge of main
(`cargo xtask test`, `tests/conformance/module.*` and
`tests/codegen/module_*.cpp`, `tests/conformance/module.interface` for
the kind runs):

- `--bmi-kind 1`: 18/18; `--bmi-kind 2 --bmi-image`: 18/18;
  `-fkiln-bmi-image` through the wrapper with `--bmi-kind 1`: 18/18.
- All module directories, image on through the wrapper: 52/52; default
  (image off): 52/52.
- `import std;` does not reach the image: its global module fragment
  falls back (S5). The rest it needs is in spec/modules.md, "What
  `import std;` still needs after S2".
- libc++ m3 gate: see the handback.

Local names are not gated: a local is never seen by an importer's
lookup, so its name goes to the parameter-name table (`pnames`), which
the preprocessor gate does not check. Without this, any importer that
had already used a local's name (`i`, `r`) replayed.
`kind2_declaration_image_bodies` pre-interns `r` and `i` to keep that
covered. The corpus namespaces are `ib` and `ic`, not the module's name,
because `import m;` interns `m` and a namespace `m` always replays
(follow-up).

## Measurements

In spec/modules.md, "Measurements", under "Part 2a, stage S2". In
short: on the S2-eligible module, import goes from 0.16 s to 0.09 s
(`-fsyntax-only`) and from 0.20 s to 0.13 s (`-c`). The file grows from
671,566 B to 4,595,063 B, and the importer's RSS from 16.0 MiB to
25.8 MiB, which is a follow-up. An imported `constexpr` function
evaluates in 0.04 s from the image, against 0.06 s textual. `import std;`
is unchanged (replay).
