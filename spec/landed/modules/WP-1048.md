# WP-1048 — modules kind 2 part 2a: the declaration and type image

Extends spec/modules.md §11.11 (new "Part 2a: the declaration and type
image (WP-1048)", "Part 2a coverage and follow-ups", and the image rows
of "Measurements"), spec/driver.md (the hidden `-fkiln-bmi-image`) and
spec/harness.md (`--bmi-image`, "Module-file kinds"). The design, its
coverage, the encoding and the measurements are in spec/modules.md
§11.11. This file records what landed and where.

## What landed

- **Format** (`crates/kiln_pp/src/bmi.rs`): section tag 2,
  `SECTION_IMAGE`. `image_header()` reads only the section's version,
  main path, module name and declared-name list, which is all the
  preprocessor needs for its gate.
- **Writer and reader** (`crates/kiln_sema/src/bmi_image.rs`): the
  writer walks the purview when the unit ends and either produces the
  image (declarations, the types they name, a per-record offset table and
  the sorted (context, name) lookup table) or the first fallback reason.
  The reader decodes and validates the whole section (every count checked
  against the bytes left, every cross-reference to an earlier record of
  the right kind) before it builds anything, then re-interns the types
  and appends each declaration through `AstBuilder` with its owner point
  set. `Sema::load_module_image`, `record_module_image`,
  `take_module_image`; `ModuleImage { bytes, decls, fallback }`.
- **Preprocessor** (`crates/kiln_pp/src/modules.rs`, `try_image_unit`):
  with `ModuleOptions::image` on, a unit whose file has an image that
  passes the gate (no imports, the image's main path is the capsule's
  main file, no declared name already interned) is not lexed. The section
  is moved out of the capsule, the main file is mapped, and `UnitBegin`
  (carrying the image) and `UnitEnd` are queued back to back.
- **Parser** (`crates/kiln_parse/src/lib.rs`): `ParseOptions::record_image`,
  `ParsedTu::image`, and the `UnitBegin` handling that calls the load.
- **Driver**: `-fkiln-bmi-image` / `-fno-kiln-bmi-image` in `args.rs`
  (default off), threaded to `ModuleOptions` and to `record_image`;
  `write_module_file` adds the section and the `-v` note's image clause.
  No new diagnostic id: damage is the existing `pp_module_file_corrupt`.
- **Harness** (`xtask/src/test/{mod,runner}.rs`): `--bmi-image`.

## Deviations

- The image is materialised eagerly at `UnitBegin` (100% of the records),
  not lazily through the top-level lookup table; the format carries the
  offset and lookup tables for the lazy reader (follow-up S-lazy).
- No ODR merging: any declared name that is already interned makes the
  preprocessor replay instead (follow-up S5).
- The flag stays off by default: the gates are green with it on, but the
  coverage is a subset and `std` itself falls back.
