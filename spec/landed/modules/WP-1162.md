# WP-1162 — modules: the image name gate replays when a declared name is only interned

Narrows spec/modules.md §11.11 "Part 2a", "ODR merging": the gate that
decides whether an imported unit is built from its declaration image
now replays only when one of the image's *gated* names (its
global-scope declarations) reached the parser at the importer's global
scope. Before, any declared name (members and locals included) that the
importer had merely interned forced a replay. The rule and its
soundness argument are in the spec; this file records what landed.

## What landed

- **Gated names in the image** (`crates/kiln_sema/src/bmi_image.rs`,
  `gated_names`, `IMAGE_VERSION` 6): the writer lists, as indices into
  the declared names, the declarations whose context reaches the
  translation unit through export blocks, unnamed namespaces and
  unscoped enumerations. `Image::gated` is encoded after the names;
  `decode` rejects an index out of range.
- **Header** (`crates/kiln_pp/src/bmi.rs`, `image_header`): returns
  the main path and the gated names (was: every declared name).
- **Name gate** (`crates/kiln_pp/src/name_gate.rs`, `NameGate`, new):
  one bit per symbol, set for an identifier returned by `next_item`
  outside every opaque brace (transparent: `extern "..." {`,
  `export {`, an enumeration body, an inline or unnamed namespace), for
  a pragma's identifiers (`marker_out`), and for the gated names of an
  image that is used. Built only under `-fkiln-bmi-image`
  (`Preprocessor::name_gate`); it replaces WP-1096's `unseen_names`,
  whose module-name exception it subsumes (a module directive's tokens
  never reach the parser). The `mark` parameter of `module_directive`,
  `read_directive_body` and `read_module_name` is gone.
- **Gate** (`crates/kiln_pp/src/modules.rs`, `try_image_unit` /
  `name_seen`): replays when a gated name is seen; unchanged `-v`
  notes. No new diagnostic id, no sema lookup change.

## Before and after

Before, an importer that spelled `twice` in a macro body, as a member
(`struct S { int twice; };`), in another namespace or as a local before
`import imgs;` replayed (`-v`: `its image declares 'twice', already
seen`), as did `int g;` against an image declaring `m::g`. After, all
of them use the image; a global `int twice(double)` overload, a global
`namespace m`, `extern "C++" { namespace m {} }`, `inline namespace v
{ namespace m {} }`, `namespace { namespace m {} }`, `enum { m };` and
`using m = T;` still replay. Perf numbers: docs/status/perf.md, WP-1162.

## Tests

- `crates/kiln_driver/tests/modules_bmi.rs`:
  `kind2_image_gate_module_names` (blanked capsules: five mention cases
  now import from the image, five global declarations replay, `int g;`
  now imports) and `kind2_image_gate_scopes` (`-v` notes for the two
  corpus importers below).
- `tests/conformance/module.interface/`: `image-gate-scope-run.cpp`
  (`Inputs/img-gate-scope.cppm`; the importer mentions every exported
  name in a macro, members, another namespace, a global variable of a
  member's name and a local, and the image is used) and
  `image-gate-overload-run.cpp` (the importer declares a global
  overload `twice(double)` and opens `geo2` in a linkage specification:
  replayed, both overloads and both `geo2` members found). Both pass
  under kiln, with `--bmi-kind 2 --bmi-image`, and under
  `--compiler clang++-19`.

## Deviations and follow-ups

- A block-scope `extern` or friend declaration inside an opaque brace
  that redeclares a gated global entity is not counted. Against a
  module-attached image declaration it is ill-formed, no diagnostic
  required ([basic.link]/11); kiln does not diagnose it.
- Uses count like declarations (a global `int x = twice(1);` before an
  import cannot name the import's `twice`, but the token counts): a
  replay, never a wrong merge. Real merging (S5) removes the gate.
