# WP-1132 — modules: `_Generic` bodies are carried by the declaration image

Extends spec/modules.md §11.11 "Part 2a", "Bodies": a body that uses
`_Generic` (clang's `GenericSelectionExpr`, a C11 extension in C++) is
now carried by the kind-2 declaration image instead of falling back
("an expression the image does not carry yet"). `__builtin_choose_expr`
(`ChooseExpr`) was already carried since WP-1064 (condition, both arms,
chosen arm in `aux`); this WP adds its tests. The rule and the encoding
are in the spec; this file records what landed.

## What landed

- **Schema** (`crates/kiln_sema/src/bmi_image/body.rs`): kind 49
  `GenericSelectionExpr` appended to `EXPR_KINDS`; `expr_shape` gives it
  the new fields `F::Gen` (expression control) or `F::GenT` (type-name
  control, bits 16) and `F::OE`, the selected association's expression.
  The writer (`Fv::Gen`, `kids`, `word`), the validator (`tok`; the
  selection must be one of the associations' expressions, at most one
  `default`, a `default` has no qualifiers), the location bound check
  (`body_locs`) and the importer (`image_val`, rebuilding the AST's raw
  operand list) walk the same fields. Value category, type and
  dependence are the record header's.
- **Version** (`crates/kiln_sema/src/bmi_image.rs`): `IMAGE_VERSION` 10 (8 before merging WP-1120, which took 9)
  (WP-1120 takes 9).

## Tests

- `crates/kiln_sema/src/bmi_image/body.rs`, `generic_selection_records`:
  round trips (expression and type-name controls, a result-dependent
  selection) and six damaged records the decoder rejects.
- `crates/kiln_driver/tests/modules_bmi.rs`,
  `kind2_declaration_image_generic_and_choose`: `-v` shows both
  interfaces carried with a declaration image and no fallback reason;
  with the source blanked an importer evaluates, instantiates and runs
  the bodies, and its IR equals the replay's. Covers the type-name
  control form (`_Generic(const int, ...)`, `_Generic(T, ...)`).
- `tests/conformance/module.interface/image-generic-run.cpp`
  (`Inputs/img-generic.cppm`): inline, constexpr and template bodies
  with type and `default` associations, a dependent control, a
  dependent association type, lvalue selections,
  `__builtin_choose_expr` with constant and dependent conditions, and
  implicit move ([class.copy.elision]/3, WP-1176) of a returned
  parameter named through either node, in `static_assert`s and at run
  time. Passes under kiln, `--bmi-kind 1`,
  `--bmi-kind 2`, `--bmi-image` and `--compiler clang++-19`.

## Deviations and follow-ups

- The type-name control form is not in the corpus test: clang 19
  crashes serializing it in a module interface (`serializing
  'qual_tag'`), so it is covered by the kiln-only driver test.
- The implicit-move case returns a parameter, not a local: NRVO may
  elide a local's move at run time (clang 19 does), which makes the
  output unspecified. The move-observing class lives in the importer:
  an exported class with user-declared copy and move constructors makes
  the whole interface fall back ("a class whose implicit special
  members need overload resolution", `crates/kiln_sema/src/bmi_image.rs`
  `any_needs_overload` check), which is outside this WP.
