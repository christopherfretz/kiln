# WP-985 — kind-2 module files, part 1: carried constant results

Extends spec/modules.md (§11.3 "Byte format", §11.6 "Driver surface",
new §11.11 "Kind 2: the serialised-AST module file (WP-985)", the
follow-ups section "Step 2 (follow-up work packages)", "Tests"),
spec/driver.md (the hidden `-fkiln-bmi-kind=`) and spec/harness.md
(`--bmi-kind`, new "Module-file kinds", the `ci` runs). The design, its
rules and the measurements are in spec/modules.md §11.11. This file
records what landed and where.

## What landed

- **Format** (`crates/kiln_pp/src/bmi.rs`): kind 2 is the kind-1 capsule
  followed by a section list (a count, then each section's tag and
  length-prefixed bytes, with tags strictly increasing), all under the
  existing checksum. `Capsule::sections`, `file_kind()`, `section(tag)`;
  `SECTION_CONSTS = 1` is the only tag. Kind-1 files are unchanged, the
  format version stays 1, and the reader accepts both kinds.
- **Carried constants** (`crates/kiln_sema/src/bmi_ast.rs`, hooked into
  `Sema::eval_const` in `oven_bridge.rs`): the recorder keeps each pure,
  self-contained result the main unit's evaluations produce, keyed by
  the evaluation's kind and two replay-stable source positions. The
  encoder is deterministic. The total decoder reports a malformed
  section as the module file's corrupt-file fatal error. During the
  replay of an imported unit, `eval_const` answers from the table, after
  checking each value against its expression's type.
- **Plumbing**: `kiln_pp::modules` hands each unit's section to its
  `UnitBegin` marker (`Marker::UnitBegin.carried`, then
  `Event::UnitBegin.carried` in `kiln_parse`). A `.pcm` main input's
  section is installed by `parse_preprocessed`.
  `ParseOptions::record_carried` turns on recording, and
  `ParsedTu::carried` / `carried_hits` return the results.
- **Driver**: `syntax_cmd.rs` / `codegen_cmd.rs` record when a module
  file is written. `pp_cmd.rs` `write_module_file` adds the section and,
  under `-v`, prints `note: wrote module file '<out>' as <kind>`. The
  hidden `-fkiln-bmi-kind=1|2` is parsed in `args.rs`. No new diagnostic
  id was added.
- **Harness** (`xtask/src/test/{mod,runner}.rs`, `xtask/src/main.rs`):
  `cargo xtask test --bmi-kind 1|2` runs every `module:` test two-step
  under that kind, and `cargo xtask ci` runs both as corpus runs.

## Measured

See the table in spec/modules.md §11.11 "Measurements". A constexpr-heavy
interface's importer drops from 0.25 s to 0.02 s and from 4,074,689 Oven
steps to none, faster than clang 19/22's 0.06 s. For `import std;`
(libc++ 19), 2900 results are carried in a 139,200-byte section (+1.5%),
and the importer makes 17,222 evaluations instead of 20,119, with its
time and memory unchanged within noise: the replay dominates. 10,142 of
`std`'s evaluations that are not carried happen inside template
instantiations.

## Tests

- `crates/kiln_sema/src/bmi_ast.rs`: `round_trip`, `empty_is_not_written`,
  `rejects_malformed`, `fuzz_truncate_flip_lengths`.
- `crates/kiln_pp/src/bmi.rs`: `kind2_round_trip`,
  `kind2_truncate_and_flip`, `kind2_section_framing`.
- `crates/kiln_driver/tests/modules_bmi.rs`:
  `kind2_carries_constant_results` (proves through the importer's
  `-fconstexpr-report` that kind 2 does not evaluate the unit again and
  kind 1 does), `kind2_falls_back_to_kind1`,
  `kind2_damaged_files_are_diagnosed`.
- `cargo xtask test --bmi-kind 1` and `--bmi-kind 2`: the 8 `module:`
  tests of the default roots (run by `ci`); the 8 in `tests/codegen` pass
  too when named.
