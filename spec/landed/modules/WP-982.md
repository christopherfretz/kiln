# WP-982 — dependency scanning and CMake modules builds (part B, step 2)

Extends spec/modules.md (§9, §11, new §11.9 "Dependency scanning and
CMake", the follow-ups now §11.10, "Tests") and spec/driver.md ("Driver
modes", "Installation layout", "Codegen flags", "Modules", new
"Dependency scanning", "Tests"). The design and its rules are
spec/modules.md §11.9; this file records what landed and where.

## What landed

- **Scanner** (`crates/kiln_driver/src/scan_deps.rs`): `kiln-scan-deps`,
  clang-scan-deps for CMake. It is an `argv[0]` mode of the one `kiln`
  binary (`run_as` dispatches on `kiln-scan-deps`, `clang-scan-deps`,
  `clang-scan-deps-<version>`), not a second executable: the scan is
  kiln's own preprocessor on the command after `--`, so it cannot drift
  from the compiler, and the install stays one binary. It prints
  P1689r5 (`-format=p1689`, byte for byte clang-scan-deps 22's
  document) or the make rule (`-format=make`, the default), writes the
  `-MT`/`-MD`/`-MF` dependency file after a clean scan, and fails as
  clang-scan-deps does (the `Diagnostics while scanning dependencies
  for` header, no carets, the empty document, exit 1). It takes
  clang-scan-deps's `-o` and accepts its tuning options as no-ops.
- **Module-scan mode** (`kiln_pp`: `modules.rs`, `directive.rs`):
  `ModuleOptions::scan` records each `import` instead of performing it
  (`Preprocessor::scanned_imports`), skips `#error` / `#warning` (as
  clang's source minimizer), and makes a header-unit import the new
  error `pp_scan_header_unit` (header units are WP-983). The driver sets
  it through `Args::scan_deps` (`pp_cmd.rs`: no module file is recorded
  or read during a scan). New ids: `pp_scan_header_unit`
  (`crates/kiln_diag/src/ids/pp.rs`), `drv_scan_one_job` (`ids/drv.rs`).
- **Install layout**: `kiln-scan-deps`, `clang-scan-deps-22` and
  `clang-scan-deps` are relative links to `kiln` beside `kiln++`, in the
  `cargo xtask dist` tree (`xtask/src/dist.rs` `SCAN_DEPS_NAMES`,
  checked by `dist --check`, smoke-tested by a scan with the installed
  `clang-scan-deps-22`) and in the cargo profile directory
  (`crates/kiln_driver/build.rs`). CMake's `find_program` for the
  scanner looks beside the compiler first, so both trees work with no
  configuration; `-DCMAKE_CXX_COMPILER_CLANG_SCAN_DEPS=` names it
  explicitly.
- **Module maps**: every flag CMake 3.31 writes (`-x c++-module`,
  `-fmodule-output=`, `-fmodule-file=<name>=<bmi>` in the
  `@<obj>.modmap` response file; `-MD`/`-MT`/`-MF`, `-resource-dir`,
  `-Xlinker --dependency-file=`) was already implemented (WP-917,
  WP-799). `-f[no-]modules-reduced-bmi` is new, accepted and ignored
  (`crates/kiln_driver/src/codegen_flags.rs`): kiln's module file has
  one form.

## Measured

Every scan of the test sources gives clang-scan-deps 22's JSON and exit
code byte for byte (interface with partitions, both partition kinds,
implementation unit, consumer, plain TU, `#error`, header unit, missing
file). With CMake 3.31.6 and Ninja 1.12.1 the fixture configures with
`kiln++` alone (CMake finds the dev tree's `clang-scan-deps-22`),
builds, runs, and touching the interface rebuilds its scan, the
collation, the interface, the implementation unit, the consumer and the
link, not the partition.

## Tests

- `crates/kiln_driver/tests/scan_deps.rs`: the documents above against
  clang-scan-deps 22's bytes, the dependency file, the failures, `-o`,
  the make format, the option errors, each scanner name.
- `crates/kiln_driver/src/scan_deps.rs` unit tests: names, options,
  JSON quoting, the empty document.
- `xtask/src/dist.rs`: the layout check and the smoke scan.
- `scripts/oss/selftest.sh` `cmake_modules` on
  `scripts/oss/fixtures/modules` (interface, partition, implementation
  unit, consumer; run, incremental rebuild). Skipped without cmake 3.28+
  and ninja; like the rest of selftest.sh it is run by hand.
