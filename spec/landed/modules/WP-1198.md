# WP-1198 — an imported class with an out-of-line key destructor at -O1

Extends spec/modules.md §3 (a module or import directive ends at its
`;`) and §7 (vtables of imported classes, structor variants of imported
definitions).

## What landed

- **No speculative copy of a named-module class's vtable.** clang 19 and
  22 declare the vtable of a class attached to an imported named module
  `external` at -O1 too: `canSpeculativelyEmitVTable` returns false for
  a definition read from a named module (`shouldEmitInExternalSource`).
  kiln copied it `available_externally` and then failed on its
  destructor slots. `Cg::vtable_in_imported_module`
  (kiln_codegen/src/vtable.rs) now refuses the copy; the importer's IR
  equals clang 22's (`tests/codegen/module_vtable_o1_importer.cpp`).
- **Structor variants of imported definitions are declarations.**
  `Cg::structor_ref` (kiln_codegen/src/class.rs) gave the complete-object
  variant of a non-inline structor that an imported unit defines a
  placeholder for an alias this unit would emit later, which it never
  does (the owning unit's object defines it); in a vtable that is the
  "a vtable references a structor alias defined later" error. It now
  declares the variant at its first use, as clang does, which also fixes
  the `available_externally` vtable of a global-module-fragment class
  with a key destructor
  (`module.interface/vtable-gmf-key-dtor-O1-run.cpp`).
- **The rest of a directive line.** The preprocessor discarded what
  followed a module or import directive's `;` on its line, so
  `import vta; int main() { ... }` silently lost `main` (which is why
  the original repro only failed with `main` on another line).
  `Preprocessor::end_directive_at_semi` (kiln_pp/src/preprocessor.rs)
  ends a valid directive at the `;`, as clang does; an invalid one still
  discards its line.

## Tests

- `module.interface/vtable-alias-O1-run.cpp` (xfail removed),
  `vtable-alias-O1-same-line-run.cpp`, `vtable-gmf-key-dtor-O1-run.cpp`;
- `cpp.module/import-same-line-run.cpp` (a declaration after `import`
  and after `export module` on the same line);
- `class.virtual/key-dtor-other-tu-O1-run.cpp` (the non-module two-TU
  counterpart, which already worked: the destructor has no definition
  in the importing translation unit);
- `tests/codegen/module_vtable_o1_importer.cpp` (IR vs clang).
