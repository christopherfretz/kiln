# WP-1046 — kind-2 module files carry results inside template instantiations

Extends spec/modules.md §11.11 (the introduction, "Identity and
remapping", new "Instantiation keys", "Encoding", "What is carried",
"Fallback", "Measurements", "Part 2" item 1 marked done). The design,
its rules and the measurements are there. This file records what
landed and where.

## What landed

- **Keys** (`crates/kiln_sema/src/bmi_ast/inst.rs`, new): the byte
  string naming the innermost instantiation frame without a `DeclId`.
  `entity_key` covers specializations (`S`: template, canonical
  arguments), members and other instantiated declarations (`M`/`P`:
  context, pattern) and declarations that were not instantiated (`D`:
  kind, name, replay-stable position). `subst_key` covers substitution
  frames that record their arguments (`F`: frame code, template, entity,
  arguments) for depth-0 templates. Types are written structurally,
  argument values with part 1's value encoding. `check_key` parses a key
  in full for the reader.
- **Writer and reader** (`crates/kiln_sema/src/bmi_ast.rs`): `EvalKey`
  gains the instantiation index. The recorder interns keys and caches
  them per frame (`frame_sig`: kind class, entity, template, arguments),
  and the reader does the same per table. Lookups no longer require an
  empty instantiation stack, and inside an instantiation they consult
  every table, so the end-of-TU instantiations an importer performs for
  a unit after its replay are answered too. A duplicate key keeps its result when the
  values agree, and is dropped otherwise. Two new fallback reasons:
  `an evaluation in a substitution that is not an instantiation`, `an
  instantiation whose arguments have no key`.
- **Format**: section version 2 (`0xffffffff` marker, version, path
  table, instantiation-key table, entries with a `u32` index). Version 1
  files (WP-985) are still read; other versions are rejected. The kiln
  version check makes mixed files rare anyway.
- **Driver** (`crates/kiln_driver/src/pp_cmd.rs`): the `-v` note adds
  `, M inside template instantiations`.

## Tests

- `crates/kiln_sema/src/bmi_ast.rs`: `round_trip` (entries inside and
  outside instantiations, an unused key renumbered away),
  `reads_version_1`, `empty_is_not_written`, `rejects_malformed` (version
  3, a bad key tag, an out-of-range index, out-of-range path indices in
  an entry and in a key), `rejects_deep_keys`,
  `fuzz_truncate_flip_lengths` (now also over each instantiation key
  through `check_key`).
- `crates/kiln_driver/tests/modules_bmi.rs`:
  `kind2_carries_instantiation_results`: the importer of the kind-2 file
  re-runs none of the module's instantiation evaluations (kind 1 re-runs
  over 20,000 steps), its diagnostics and IR equal kind 1's, the file is
  deterministic, and a damaged section is a diagnostic or a fallback.
- `tests/conformance/module.interface/carried-instantiations-run.cpp`
  (static_asserts, constexpr variables, `if constexpr`, non-type
  arguments, an alias template over carried values and a body the
  importer instantiates at its end of TU) and
  `carried-instantiations-errors.cpp` (strict diagnostics of failing
  static_asserts reading carried values), with
  `Inputs/ct.cppm`. Both pass under kiln, `--bmi-kind 1`, `--bmi-kind 2`
  and `--compiler clang++-19`.

## Not in this step

- Alias template and default-argument-checking frames record no
  arguments, so their evaluations stay uncarried (most of `std`'s
  remaining ones).
- Substitution frames of templates nested in a template (depth > 0), and
  arguments that are pointers, references or reflections (WP-1047).
