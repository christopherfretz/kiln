# WP-1257 — a failed consteval block in a lambda body does not fail the lambda

Follow-up of WP-1247. The rule is in spec/sema-templates.md §5.5, the
"A lambda body that reports its own error" paragraph.

Cause: `Substituter::consteval_block_decl` (templ/subst/decls.rs)
reported a failed evaluation as an ordinary error of the substituted
body, so `lambda_expr` (templ/subst/lambda.rs) discarded the lambda
exactly as it did for a failed `static_assert` before WP-1247. Uses of
the lambda then cascaded: `static_assert(used<int>() == 7)` over a
local initialized by the lambda became "not an integral constant
expression" with no note, a variable template initialized by the
closure "depends on itself" at a later copy, and a constant evaluation
reading a variable template the lambda initializes ended silently
instead of reporting its next independent error.

Fix: WP-1247's counter, renamed `InstState::checked_decl_errors`, also
counts the errors of a consteval block's evaluation (less those of a
body its evaluation instantiated). A function definition instantiation
still restores it. Errors of substituting the block's expression itself
still fail the body. The non-lambda paths (function template body,
class template member function, generic lambda call operator) already
reported one error per block and nothing more; they are pinned by the
same test.

GCC 16.1 (`oracle: gcc` on all three tests): one error per block. Where
a constant evaluation runs through the lambda, GCC treats the enclosing
body as erroneous; its next error has no note naming the independent
cause, and a consteval caller gets a further "called in a constant
expression" error. kiln reports the independent error instead.

Tests (tests/conformance/dcl.pre/):
`consteval-block-lambda-no-cascade.cpp` (six blocks, six errors, no
follow-on at the uses), `consteval-block-lambda-next-error.cpp` (the
WP-1247 shapes with a consteval block as the first refusal),
`run-consteval-block-lambda-template.cpp` (blocks that pass leave the
closures usable at translation and run time).
