# WP-1362 — pointer and reference subobjects of class-type template arguments; instantiated argument locations

Completes spec/sema-templates.md "Disallowed bases" ([temp.arg.nontype]/6)
and the argument locations of §3.2.

- **Subobjects.** `convert_class_nttp_arg` checks the frozen value with
  `invalid_template_arg_base`, which for an aggregate walks the image's
  relocations (every pointer-like subobject, at any depth; only a
  union's active member has bytes) and reports the first pointer or
  reference whose base is a string literal, a predefined `__func__`
  variable (the `StringLiteral` a `PredefinedExpr` holds), a `typeid`
  result or a temporary, as clang's `CheckEvaluationResult` does. One
  past the end of a string literal is a subobject pointer; one past the
  end of a named array stays valid ([temp.arg.nontype]/6 lists no such
  restriction since C++20; clang agrees, GCC 16.1 rejects).
- **Bit-fields.** A reference parameter's argument naming a bit-field is
  "reference cannot bind to bit-field in converted constant expression"
  (`sema_cce_ref_binds_bitfield`, clang
  `err_reference_bind_to_bitfield_in_cce`), before the conversion is
  formed.
- **Locations.** The parser's argument locations are tagged with the
  instantiation depth they were recorded at; a template-id formed at
  another depth (by an instantiation) ignores them, and
  `check_template_args` then locates each expression argument at its
  begin location (clang's `TemplateArgumentLoc` of the transformed
  argument), any other argument at the template name.
