# WP-1258 — WP-1248 follow-ups: call frames under elision and nested evaluations, never-constant frames, specialization member names

The rules are spec/sema-templates.md §10.2 ("Instantiations a reflection
query requires"), spec/sema.md §5.28 ("Instantiations the check's
evaluation requires"), spec/oven.md "Interface"
(`Oven::paused_call_notes(mark, ..)`) and spec/reflection-repr.md §5.

- **Nested evaluations.** `Sema::meta_call_notes`
  (`crates/kiln_sema/src/templ/stack.rs`) used only the innermost
  `InstState::meta_calls` entry and only while the held Oven's mark
  matched exactly, so in

  ```cpp
  consteval bool inner(int) { return std::meta::is_complete_type(^^Crate<Shape>); }
  template <class T> struct Outer { static_assert(inner(sizeof(T))); };
  consteval bool outer(int) { return std::meta::is_complete_type(^^Outer<int>); }
  static_assert(outer(7));
  ```

  the outer evaluation's `in call to 'outer(7)'` was missing after the
  `Outer<int>` frame. Now every entry whose anchor frame prints
  contributes, and `Oven::paused_call_notes` takes the mark: it prints
  `stack[mark.entry+1 .. mark.frames]` while the Oven still holds that
  evaluation (the mark matches, or a nested evaluation runs above it:
  greater depth, entry at or above the marked frames).
- **Elision.** `InstantiationStack::context_notes` takes a `keep`
  callback beside `extra`: the call frames of an elided frame print
  after the "(skipping K contexts in backtrace; ...)" note, innermost
  first, before the next frame shown; `frame_extra_note` is elided with
  its frame.
- **Never-constant check.** `FrameMark` records whether the evaluation is
  a potential-constant one (`RunState::potential`); such a mark renders no
  notes, so an instantiation error the check's evaluation of a
  parameterless `consteval` function causes no longer shows the check's
  own `in call to 'probe()'` frame.
- **Specialization member names.** `AstNames::write_qualified_spec_name`
  (`crates/kiln_ast/src/dump/names.rs`) prints each class template
  specialization in a declaration's scope with its arguments; the
  `PrintEnv::decl_name` of `AstNames` and `Ast`, enumerators and every
  `Decl`-like reflectee use it, and a `Type` reflectee prints with full
  scope. Before: `X<&ns::R::y>`, `ns::R::e1`, `^^In`, `^^S::m`; clang 19
  and 22 print `X<&ns::R<int>::y>`, `ns::R<char>::e1`; kiln now does, and
  `^^S<int>::In`. `display_string_of` of a variable template
  specialization prints its arguments (`ns::vt<int>`, GCC 16.1;
  `meta/names.rs` `SpellEnv::decl_name`, `meta/gcc_names.rs`
  `dump_decl`: an implicit specialization is a `Var`). A substituted
  pointer-to-member argument is qualified by its class
  (`templ/nttp.rs`, clang's `BuildExpressionFromDeclTemplateArgument`):
  `no<&S<long>::m>`, `no<&ns::R<int>::Q::w>` (clang 22; clang 19 prints
  `&Q::w`).
- **Tests.** `tests/conformance/meta.reflection.queries/`
  `is-complete-type-instantiation-frames-{nested,elided,spec-names}.cpp`,
  `is-complete-type-never-constant-frames.cpp` (`oracle: gcc`,
  `strict-diags`); `meta.reflection.names/display-string-of-specialization-members-run.cpp`
  (run, output compared with GCC 16.1); `temp.arg.nontype/`
  `specialization-member-argument-printing{,-clang22}.cpp` (clang oracle).
- **Deviations.** GCC prints a pointer to an object as `& S<int>::s`
  (and `X<(& S<int>::s)>` as a template argument) in
  `display_string_of`; kiln prints `&S<int>::s`, for non-template
  variables too (pre-existing, not addressed). A member function
  template specialization reflected in a call note prints without its
  own arguments (`^^S<int>::g`; GCC `g<char>`), as clang's
  `printQualifiedName` does. Under the never-constant check, a nested
  evaluation the check's work starts also runs in potential mode, so its
  frames are dropped as well.
