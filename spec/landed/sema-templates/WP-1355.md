# WP-1355 — attributes of a lambda's call operator in a template

Completes spec/sema-templates.md §5.6 "Attributes of a specialization".

A lambda-expression substituted with an enclosing template
(`Substituter::lambda_expr`) rebuilds its call operator from the
lambda's specifiers and declarator, which carry no attributes; the new
call operator then copies the pattern call operator's attributes
(`class_attrs`, the copy every instantiated function gets; clang
`TransformLambdaExpr` → `InstantiateAttrs`). For a generic lambda the new
call operator is the pattern of its own specializations, which take them
from it (`function_spec_attrs`). One mechanism for every function
attribute: `always_inline` (GNU, `[[gnu::]]` and `[[clang::]]` after the
introducer or template parameter list), `noinline`, `flatten`, `cold`,
`hot`. A standard attribute after the parameter list
appertains to the function type and is ignored as before. So at -O0 the
always-inliner removes an `always_inline` lambda's call and definition in
a function template, as clang does (libc++'s `__load_vector` lambdas in
`std::mismatch` on `std::vector<int>`: no call, as clang 22). Tests:
`tests/codegen/always_inline_lambda_template.cpp` (IR, both oracles),
`tests/conformance/expr.prim.lambda.closure/attributes-in-template-run.cpp`.
