# WP-1737 — dependent names: no static gaps (GAP-042..GAP-051)

- **Member friends by operator name** ([temp.friend]/5): `template
  <class T> friend void *A<T>::operator new(std::size_t);` and the other
  operator-function-ids take the member-friend path; a deallocation
  function's implicit `noexcept` does not block the match
  ([except.spec]/9). Local classes of function templates and generic
  lambdas defer member friends with a dependent qualifier ([temp.pre]/8)
  (§4.8). Was "not yet implemented: dependent nested name specifier"
  (g++.dg `template/friend46.C`, `template/new7.C`).
- **Still-dependent qualifiers**: a qualifier a substitution leaves
  dependent (a retained generic-lambda level) is kept as a dependent
  scope, never resolved to a context; a member-rooted qualifier
  (`u.Base::get()`) waits for the object's class
  ([basic.lookup.qual.general]/2, [temp.dep.type]/6) (§3.4). Was "not yet
  implemented: dependent nested name specifier" / "this nested name
  specifier" / "dependent name", or "use of undeclared identifier".
- **Deduction guides naming members** ([over.match.class.deduct]/3): an
  alias template's or inherited constructor's guide whose constructor
  parameter types name members of the class template maps them into the
  substituted specialization, including a member class template of
  another specialization (§3.4). Was "not yet implemented: reference to a
  member of a dependent context" (g++.dg `cpp2a/class-deduction-alias4.C`)
  or an internal error. clang 22 forms no such guide; kiln follows GCC.
- **Dependent destructor names** ([basic.lookup.qual.general]/4): the
  qualified forms the definition cannot look up are kept and looked up at
  instantiation; on a class object without a prefix the error is
  immediate, as clang (§3.4). Was "not yet implemented: a dependent
  destructor name".
- **Dependent using-declarators**: `D::template f<A>` through `using
  B<T>::f;` is a member of an unknown specialization; an implicit member
  access through one in a local class of a generic lambda stays
  dependent (§3.4); a block-scope `using T::operator+;` is diagnosed when
  instantiated ([namespace.udecl]/8, spec/sema.md). Was "not yet
  implemented: implicit dependent member access" or "an operator name
  with a dependent qualifier in a block-scope using-declarator is not
  supported yet".
- **`T::template X<A>` naming a type template** once instantiated:
  clang's "is expected to be a non-type template" (§3.4). Was "not yet
  implemented: a type template-id as an expression".
- **Dead or now handled**: the implicit dependent member template-id site
  (GAP-047) had no producer (`act_on_id_expression_dn` builds those
  nodes without template arguments) and is removed; a destructor or
  constructor name in a dependent member reference (GAP-051) is
  substituted like a conversion's type.
- Follow-up (xfail): an implicit guide keeps its constructor's unresolved
  `explicit(b)` as explicit
  (`over.match.class.deduct/implicit-guide-dependent-explicit-bool-copy-list-run.cpp`).
