# WP-1259 — Program-provided text in diagnostics is escaped as clang escapes it

The `what()` of an exception leaving a constant evaluation (WP-1251)
reached its note raw: control characters printed as is, and a byte that
is not UTF-8 became U+FFFD. It now goes through the function a failed
`static_assert`'s message already used, moved from `kiln_sema` to
`kiln_diag` as `escape_diag_text` so the Oven and Sema share it. The rule
is spec/diag.md §6.2.

The function also now matches clang's `pushEscapedString` (clang 19 and
22 agree) where it did not:

- vertical tab, form feed and carriage return print as is (they were
  `<U+000B>`, `<U+000C>`, `<U+000D>`): clang keeps all ASCII whitespace;
- a code point that is not printable is escaped by the §9.4 printability
  table, not only the Cc controls: U+2028, U+2029, private-use and
  noncharacter code points print as `<U+XXXX>`; format characters (Cf:
  U+00AD, U+200B, U+FEFF) print as is. Unassigned code points stay raw
  (deviation D5; clang escapes U+0378).

Every place program-provided text reaches a diagnostic, each now through
`escape_diag_text`:

- a failed `static_assert`'s `size()`/`data()` message
  (`Sema::static_assert_message_text`, unchanged path) and its string
  literal message (`Sema::string_literal_text` → `Sema::string_msg`);
  neither is truncated;
- the uncaught exception's `what()` (`Oven::exc_what`), which covers a
  `std::meta::exception` and an exception leaving a consteval block (both
  fail through `Fault::Uncaught`); the `WHAT_CAP` cut is applied to the
  bytes before escaping (spec/oven.md §Exceptions);
- the messages of `deprecated`/`unavailable` (`warn_deprecated_use`),
  `nodiscard` on a call and on a construction (`unused_*_result`),
  `= delete("…")` (`delete_message_suffix`), `enable_if`
  (`enable_if_message`) and `diagnose_if`, through the new
  `Sema::string_msg` (escaped from the literal's bytes);
- the name of a `data_member_spec` (`meta/define.rs`) and of
  `__kiln_define_member` (`meta/ext.rs`) that is not an identifier:
  `Oven::meta_c_string` became `meta_c_bytes` and returns the bytes, so an
  invalid byte prints as `<XX>`, not U+FFFD.

Kiln has no compile-time printing builtin (`__kiln_print` does not
exist), so there is nothing else to route.

clang 19 and 22 do not implement P3068; GCC 16.1 renders a `what()` as C
escapes (`\x0a`, `\x09`, `\x01`, `\xff`), keeps valid UTF-8 (U+2028
included) and so prints one line. Kiln follows clang's `static_assert`
rendering: a newline in `what()` continues the note on the next line.

Tests:
`tests/conformance/expr.throw/constexpr-uncaught-what-escape.cpp`
(newline, tab, controls and an ANSI escape, invalid UTF-8 and an encoded
surrogate, U+2028/U+0085/U+00AD),
`tests/conformance/dcl.pre/static-assert-message-escape.cpp`
(whitespace, format, separator, private-use and noncharacter code points,
invalid bytes; also under clang 19 and 22),
`tests/conformance/dcl.attr.deprecated/message-escape.cpp`
(`deprecated`, `= delete`, `nodiscard`; also under clang 19 and 22),
`tests/conformance/meta.reflection.define.aggregate/name-escape.cpp`,
and the unit test `columns::tests::escape_diag_text_as_clang`.
