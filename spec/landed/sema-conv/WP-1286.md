# WP-1286 — C initialization, declarations and statements

C mode wave 2b, after WP-1276 (wave 1) and the WP-1282 measurement (docs/status/c-mode.md, "Wave-2 input"). Every rule is C-only: it is gated on `Sema::is_c()`, mostly in `kiln_sema/src/c_decl.rs`, and C++ behaviour is unchanged. The oracle is clang 19 `-x c`, wording and locations included. Tests live in `tests/c/{decl,stmt,expr}`, and each names its standard section.

## Initialization (C23 6.7.11)

- **No narrowing.** A brace initializer converts each value as if by assignment (6.7.11p11, p13). Implicit-conversion warnings still apply, but there is no C++ narrowing error (`init.rs`). Test: `tests/c/expr/init-list-no-narrowing.c`.
- **Exact-fit strings.** `char a[3] = "abc";` drops the terminating null (6.7.11p15). A longer string is truncated with clang's `-Wexcess-initializers` warning ("initializer-string for char array is too long"). Tests: `decl/char-array-exact-string-init.c`, `decl/string-init-too-long.c`.
- **Wide strings.** A wide string literal initializes an array whose element type is compatible with the literal's. In C, `wchar_t`, `char16_t` and `char32_t` are typedefs (clang `IsStringInit`). Test: `decl/wide-string-init-typedef.c`.
- **GNU array from a compound literal.** An array may be initialized from a compound literal of the same array type (clang `SK_ArrayInit`), and also from a parenthesized string, as in `char a[] = ("x")`. Under `-pedantic` this is diagnosed. Tests: `decl/array-init-compound-literal-{gnu,pedantic,errors}.c`.
- **Flexible array members.**
  - GNU static initialization with elements is supported. The Oven builds the object without the elements, `kiln_codegen` `fold::flexible_elements_init` folds them on their own, and `Cg::record_elems` lays them out past the object.
  - A flexible array member is standard in C99 and later, so there is no `-Wc99-extensions` warning there.
  - Tests: `decl/flexible-array-{static-init,init-diags}.c`.
- **Empty initializer.** `= {}` is a C23 extension before C23.
- **Designators.**
  - C allows designators in any order, mixed with positional initializers, so `-Wreorder-init-list` and `-Wc99-designator` are not emitted (clang checks both only in C++).
  - The GNU old-style field designator `{ y: 2 }` (parsed in C and C++ by WP-1288) gets `-Wgnu-designator` as an ExtWarn, on by default as in clang.
  - Test: `decl/old-style-field-designator.c`.

## Statements

- **Case labels** (C23 6.8.5.3p3, p5). A case value is an integer constant expression, converted to the promoted type of the controlling expression with no narrowing rule (clang `ActOnCaseExpr` outside C++11). A non-integer value is `err_ice_not_integral`. Tests: `stmt/switch-case-value-converted.c`, `stmt/case-label-non-integer.c`.
- **goto** (C23 6.8.7.2p1). A jump past an initialized declaration is valid; only a jump into the scope of a variably modified type is not (`jump_scope.rs`). Tests: `stmt/goto-past-initializer.c`, and `stmt/goto-into-vla-scope.c`, which is shared with WP-1287.

## Declarations

- **Redefinitions** (`c_decl.rs`).
  - **GNU89 extern inline.** Under `-fgnu89-inline`, with a standard before C99, or with `gnu_inline`, an `extern inline` definition is inline-only, and a later definition replaces it (clang `canRedefineFunction`, `Ast::replace_definition`). Test: `decl/gnu89-extern-inline-redefinition.c`.
  - **Composite types.** Compatible prototypes form the composite type (6.2.7p3). Test: `decl/composite-type-redeclarations.c`.
- **Tentative definitions** (6.9.2).
  - A tentative definition's type may stay incomplete until the end of the TU. There, an array of unknown bound becomes `[1]` with `-Wtentative-definition-array`, and any other incomplete type is an error (clang `ActOnEndOfTranslationUnit`).
  - An internal-linkage tentative definition of an incomplete non-array type is warned about.
  - Codegen emits the definition with an initializer, or else the last tentative one.
  - Tests: `decl/tentative-{incomplete-type,completed-later}.c`.
- **main returning void.** `void main` is accepted with a warning in GNU modes and rejected in ISO modes, as clang does. Tests: `decl/main-return-type-void-{gnu,iso}.c`.
- **Other declaration rules.**
  - Qualified anonymous bit-fields are allowed. Test: `decl/anonymous-bitfield-qualified.c`.
  - A reference to an enum that is not yet declared is pedantic-only. Test: `decl/forward-enum-pedantic.c`.
- **Prototype-scope tags** (6.2.1p4).
  - A tag first declared in a parameter list is visible to the later parameters, and to the body when the declarator is a definition, and to nothing else.
  - Such a tag is clang's `-Wvisibility`: "declaration of 'struct S' will not be visible outside of this function". `Sema::c_declare_proto_tag` keeps the tag in `PrototypeFrame::tags`, and `c_inject_param_tags` adds it to the body scope.
  - Tests: `decl/param-scope-tag-{visibility,body}.c`.
- **Storage class on a member** (6.7.2.1p1). This is `err_typename_invalid_storageclass`, emitted by the parser. Test: `decl/member-storage-class.c`.
- **A declaration with no declarators** (6.7p2). `typedef struct S;` is "typedef requires a name" (`-Wmissing-declarations`). An anonymous structure that declares nothing is "declaration does not declare anything" (`Sema::c_decl_spec_only`). Test: `decl/typedef-without-name.c`.
- **`int h(...)` before C23** (C17 6.7.6p1). This is "ISO C requires a named parameter before '...'". It is valid in C23. Tests: `decl/ellipsis-first-param-c17.c`, `decl/ellipsis-only-parameter-c23.c`.
- **Implicit function declarations** (C89 3.1.2.1).
  - An implicit function declaration has block scope.
  - A later use outside that block that finds it through `local_externs` is `-Wout-of-scope-function`.
  - A block-scope `extern` declaration whose type conflicts with an earlier one in another block notes that previous declaration.
  - Tests: `decl/implicit-function-block-scope.c`, `decl/block-extern-conflict.c`.
- **No vexing parse.** C has no `-Wvexing-parse`. Test: `decl/no-vexing-parse.c`.
- **Static in inline functions** (6.7.5p3).
  - Naming an identifier with internal linkage in an inline function with external linkage is `-Wstatic-in-inline` (`Sema::c_check_static_in_inline`). It is pedantic when the use is in the main file or names an inline or `const` function.
  - A modifiable block-scope `static` object in an inline definition that another TU provides is `-Wstatic-local-in-inline` (`c_check_static_local_in_inline`, clang `isFunctionDefinitionDiscarded`).
  - Both add the "use 'static'" note with its fix-it.
  - Test: `decl/static-in-inline.c`.

## Not yet (follow-ups)

- An enumerator of an enum declared in a parameter list stays visible at file scope; clang hides it with the tag.
- An incomplete-type variable that has an initializer is reported at the `{` rather than the name (`init.rs`), followed by a "member access into incomplete type" cascade.
- A redefinition error leaves the declaration valid, so a later use adds a "redeclaration" cascade.
- A `static` declaration after a non-static one says "previous declaration" and adds an extra redefinition error.
- A static-storage initializer with a pointer cast (object to object pointer, integer to pointer, pointer to integer) does not fold, so the variable is initialized dynamically; a block-scope one gets a `__cxa_guard` that a C link cannot resolve (sqlite). Repro: `run/static-local-address-constant-cast.c` (xfail).
- GNU `transparent_union` has no C semantics: a redeclaration with a member type conflicts, and arguments do not convert. Repro: `decl/transparent-union-redeclaration.c` (xfail; gcc.c-torture compile/pr46866.c).
