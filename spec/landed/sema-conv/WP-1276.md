# WP-1276 — C semantics behind Sema::is_c()

C mode wave 1. WP-1275 provided the driver, lexer and preprocessor plumbing and the `tests/c` corpus. This WP adds the C rules on top of the C++ sema, each gated on `Sema::is_c()` (with `Sema::c_at_least(CStd)` for a standard revision). The oracle is clang 19 `-x c -std=<std>`, wording included. C++ behaviour is unchanged: every new path is unreachable outside C.

## Conversions (C17 6.3, 6.5.16.1)

- **Assignment constraints** (`conv/c_assign.rs`, reached from `conv::implicit_convert` for assignment, initialization, argument passing and `return`). These are clang's `CheckAssignmentConstraints`, `checkPointerTypesForAssignment` and `DiagnoseAssignmentResult`.
  - `void *` converts implicitly to and from any object pointer.
  - An integer to a pointer, or a pointer to an integer, is `-Wint-conversion`, an error by default in clang 19.
  - Incompatible pointers are `-Wincompatible-pointer-types`, and incompatible function pointers are `-Wincompatible-function-pointer-types`.
  - Pointers that differ only in sign are `-Wpointer-sign`.
  - Discarding qualifiers is `-Wincompatible-pointer-types-discards-qualifiers`, at the outer level or nested.
  - A null pointer constant that is not a literal gets `-Wnon-literal-null-conversion`.
  - Diagnostics that clang accepts and recovers from come back as a `ConvError` that carries `recovered`. The caller emits the diagnostic and keeps the value.
  - The location is the operator of an assignment, or the start of an argument or `return` operand. An argument notes its parameter.
  - Fix-its follow clang: `&` or `*` hints.
  - A reference target, which only a builtin's parameter has (`va_list &`), never takes this path.
- **Structures.** A structure of a compatible type converts by lvalue-to-rvalue conversion (C17 6.3.2.1p2). A structure argument is that plain copy, with no constructor lookup or reference binding (`Sema::convert_call_args`, C17 6.5.2.2p7). This covers an AArch64 `va_list` passed by value, as in glibc's inline `vprintf` at `-O2`.
- **Compound literals.** An assigned structure prvalue is materialized first, so a compound literal that reads the target is its own object (C17 6.5.2.5p4). An array compound literal decays like any array. Its materialized object has no lifetime markers and no `-Wdangling` warning, because it lives until the end of its block (6.5.2.5p5).
- **Compatibility** (`c_assign::compatible`, C17 6.2.7). A function type without a prototype is compatible with:
  - another function type without a prototype that has a compatible return type;
  - a prototype that is not variadic and whose parameter types are all unchanged by the default argument promotions (C17 6.7.6.3p15).
- **Truth values and enums.**
  - `!`, the relational, equality and logical operators yield `int`.
  - Enum constants are `int`, unless C23 gives a fixed underlying type (`enum E : T`).
  - Inc/dec of an enum or `_Bool` is allowed, and a prefix inc/dec is a prvalue (`ExprArena::set_c_prefix_incdec_prvalue`).
  - `_Generic` matches by C compatibility.
- **Literals.** A character literal is `int` (C17 6.4.4.4p10). A string literal is `char[N]`, not `const` (6.4.5p6).
- **Type printing.** Diagnostics use the C type-printing policy: `struct S`, no `std::`, and `_Bool`.

## Declarations

- **Tag name space** (C17 6.2.3).
  - Tags are hidden from ordinary lookup.
  - A tag first declared in a parameter list or block is injected as clang does.
  - A tag used without its keyword is "must use 'struct' tag to refer to type 'S'" (`Sema::c_tag_without_keyword`).
- **No overloading** (C17 6.7p4). An incompatible redeclaration is "conflicting types for 'f'". `__attribute__((overloadable))` keeps C++ overloading and mangling (spec/abi.md).
- **Tentative definitions** (C17 6.9.2).
  - A file-scope object without an initializer, with no storage class or with `static`, is tentative (`Sema::c_tentative`). It becomes a zero-initialized definition at the end of the TU.
  - `-fcommon` emits it as `common` (`CodegenOptions::common`). `-fno-common` is the default.
  - A `const` object without an initializer is accepted.
- **Inline** (C17 6.7.4).
  - C99 semantics apply: an `inline` definition without `extern` provides no external definition, and `extern inline` provides one.
  - `-fgnu89-inline`, or any C89 standard (`-std=c89`, `gnu89`), gives the GNU89 rules, as in clang (`CodegenOptions::gnu89_inline`). `PredefConfig::gnu89_inline` defines `__GNUC_GNU_INLINE__` instead of `__GNUC_STDC_INLINE__`.
- **Functions without a prototype** (before C23; C17 6.7.6.3p14, 6.5.2.2p6).
  - `f()` declares a function without a prototype (`FuncInfo::no_proto`, `with_no_proto`, `Chunk::Function::no_proto`). It is printed as `int ()`.
  - A call applies the default argument promotions.
  - A redeclaration with a prototype forms the composite type (`Sema::c_no_proto_composite`), with `-Wdeprecated-non-prototype` where clang emits it.
  - Codegen: a defined function without a prototype is not variadic, while a declaration alone is `(...)` (`decl_sig`, `sig_this_va`).
- **K&R definitions** (C17 6.9.1p6-p7).
  - An identifier list is parsed (`Declarator::knr_idents`), then the declaration list. Each parameter has its default-promoted type in the function type and its declared type in the body. The prolog truncates the promoted argument (`Trunc` or `FPTrunc`).
  - An undeclared parameter is `int`, which is an error from C99.
  - An identifier list in a declaration that is not a definition is an error.
  - A call with the wrong count warns "too few/many arguments in call to 'f'".
  - C has no ADL, so a call never sees an argument-dependent overload set.
- **C89 implicit int and implicit function declarations** (C89 3.5.2, 3.3.2.2).
  - A declaration with no type specifier is a valid `int` declaration before C23 (`Sema::untyped_invalid`). This covers parameters (`register r`), at the name, and block-scope `auto`.
  - A call to an undeclared identifier declares `extern int f()` (`Sema::c_implicit_function_decl`).
  - In C89, `-Wimplicit-int` and `-Wimplicit-function-declaration` are off by default and on under `-Wall` (`-Wimplicit` is in `-Wmost`). From C99 they are errors by default, with clang's "ISO C99 and later" wording.
- **`auto` and `register` in C.**
  - `auto` is a storage class (`StorageSpec::Auto`), an error at file scope. In C23 it deduces only when no type-specifier follows.
  - `register` gets no C++17 diagnostic. A `main()` without a prototype is not a variadic `main`.
- **Falling off the end** of a non-void function gets no trap or `unreachable` in C. It returns the uninitialized return slot, since only the caller's use of the value is undefined (C17 6.9.1p12). `main` returns 0.

## Tests

- `tests/c/conv/` covers:
  - void pointers;
  - int conversion errors;
  - incompatible-pointer warnings;
  - assignment hints;
  - booleans;
  - char literals;
  - comparisons;
  - enums;
  - arithmetic promotions.
- `tests/c/decl/` covers:
  - tags (`tag-namespace.c`, `tag-not-typename.c`);
  - overloading (`no-overloading.c`, `overloadable.c`);
  - `tentative-definitions.c`;
  - `unprototyped.c`;
  - `knr-definitions.c`;
  - the implicit-int and implicit-function tests (`c89-implicit.c` is a run test, `c99-implicit-errors.c`).
- `tests/c/run/` holds the run and link tests:
  - `conv-values.c`;
  - `common-tentative.c`;
  - `inline-c99.c` and `inline-gnu89.c`, each with a second TU in `Inputs/`;
  - `struct-by-value.c`, which also passes a `va_list` through `<stdio.h>` at `-O2`.
  - `compound-literal-object.c`;
  - `fall-off-end.c` and `fall-off-end-c89.c`.
- `tests/c/c99/` and `tests/c/c23/` cover the C99, C11 and C23 constructs.

Every test also passes under `cargo xtask test --compiler clang++-19`.

## Not yet (xfail repros, follow-ups)

- `tests/c/c99/compound-literals.c`: a compound literal is not yet an lvalue (C17 6.5.2.5p4), so `&` of one and assignment to one are rejected.
- `tests/c/c99/vla.c`: variable length arrays are missing, as are `[*]` and `static` in array-parameter brackets.
- `tests/c/cxx-only/cxx-syntax-rejected.c`: the C parser still applies C++ parsing to `&` declarators, `template`, `::`, `class` and lambdas. The result is errors with clang-divergent wording and recovery, but no panics.
