# WP-570 — static_assert message is an unevaluated operand when the condition holds

Extends spec/sema.md §4.6 (static_assert, user-generated messages).

[dcl.pre]/12 (P2741R3): a static_assert-declaration whose converted condition is
`true`, or that is in a template definition, has no effect, and its
static_assert-message is an unevaluated operand; only a failing assertion needs
`M.size()` and `M.data()` to be constant expressions. Kiln used to evaluate the
message of a holding assertion as clang 19 and 22 do
(`-Winvalid-static-assert-message`, `DefaultError` there) and so rejected valid
programs, among them consteval message builders in real code
(`define_static_string` over `display_string_of(return_type_of(r))`, which throws
for a data member behind a condition that holds).

`sema_static_assert_message_not_constant` is now `WarningOff`
(crates/kiln_diag/src/ids/sema_s_z.rs): `Sema::check_static_assert_message`
(crates/kiln_sema/src/decl.rs) evaluates a holding assertion's message only while
the group is enabled (`-Winvalid-static-assert-message` for a warning,
`-Werror=invalid-static-assert-message` for clang's error). The type checks of the
message (`static_assert_message_parts`) still run whether or not the assertion
holds, and a failing assertion's message is evaluated and diagnosed once
(`sema_static_assert_message_constexpr` plus notes, then the failed assertion), as
before. GCC 16.1 agrees with kiln; clang is a documented deviation.

Tests (tests/conformance/dcl.pre/): `static-assert-message-unevaluated-when-true.cpp`
(`oracle: gcc`, `xfail(clang)`), `static-assert-message-unevaluated-reflection.cpp`
(`oracle: gcc`), `static-assert-message-not-constant-on-failure.cpp` (clang-checked),
`static-assert-message-not-constant-on-failure-reflection.cpp` (`oracle: gcc`), and
`p2741-static-assert-message-diags.cpp` now opts in with
`-Werror=invalid-static-assert-message`.
