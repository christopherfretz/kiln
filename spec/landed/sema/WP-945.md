# WP-945 — never-constant check: builtins follow clang

This makes the never-constant check (`-Winvalid-constexpr`) follow clang 19's `isPotentialConstantExpr` on builtin calls, `asm` statements and system headers. It also closes WP-990 (missed builtin cases), WP-996 (a decayed builtin in Oven compile) and WP-915 (`asm` in a function with parameters). The contract is spec/sema.md "Never constant"; the code is `never_constant.rs`.

- **Builtins: clang's table, not the Oven.**
  - Root cause, part one: kiln's Oven folds more than clang's evaluator does. It folds the P0533 `<cmath>` builtins and their library twins, as GCC does (spec/oven.md). It also notes some calls its own way: `strlen` gets "declared here", for instance.
  - Root cause, part two: the WP-962 rule reported only the builtin table's `Oven::No` rows and treated every other builtin as opaque. That rule was safe, but it missed `__builtin_floor(2.5) + x`, `__builtin_trap()` and `strlen("ab") + x`.
  - Fix: `Sema::clang_constexpr_builtin` is set by the parser. It asks kiln_pp's `__has_builtin` / `__has_constexpr_builtin` tables, which mirror clang's `Builtins.td` `Constexpr` markers per target, `-std`, GNU mode and compat. `Sema::builtin_call_kind` classifies each direct callee:
    - a non-library builtin clang does not evaluate fails at the callee, before its arguments ("subexpression not valid in a constant expression");
    - any other non-library builtin is opaque. Its arguments are walked, except for clang's unevaluated ones: `__builtin_constant_p`, `object_size`, `classify_type`, `assume`, and the second argument of `expect`;
    - a library builtin that clang evaluates (`strlen`, `memcpy`) always fails with "non-constexpr function", without "declared here";
    - any other library builtin (`fabs`; `abs` at compat 19) fails only once its arguments are known, with "declared here".
  - A parameterless function was evaluated as a call through the Oven. It now first gets a strict walk, in which only those builtin calls can fail, so the Oven never decides a builtin call.
  - `builtin_calls` skips unevaluated operands (`sizeof`, `noexcept`, `typeid`, lambda bodies, `requires`).
- **System headers.** clang skips the check for a function declared in a system header, even under `-Wsystem-headers`. libstdc++'s `<cmath>` `acos(float)` calls `__builtin_acosf`, which gave 19 kiln errors with `-Wsystem-headers`. kiln now skips such functions too.
- **WP-915.** An `asm` statement fails, as in clang's `EvaluateStmt` default case. Functions with parameters were already walked with their parameters unknown (WP-873); the walk had no case for `asm`.
- **WP-996.** Oven compile now gives a `BuiltinFnToFnPtr` cast clang's generic "subexpression not valid" note, where it used to give a kiln "not supported yet" limitation note. No user-code reproducer was found: the walk never evaluates a direct callee, and Sema rejects any other use of a builtin.
- **C++23.** The check stays silent unless `-Winvalid-constexpr` is given (P2448R2), and it is an error when enabled, as in clang.
- **Tests**, in `dcl.constexpr/`:
  - `never-constant-builtin-not-evaluated-cxx20.cpp`;
  - `never-constant-library-builtin-cxx20.cpp`;
  - `never-constant-builtin-abs-clang19.cpp` and `potential-constant-builtin-abs-clang22.cpp`;
  - `never-constant-builtin-cxx23.cpp` and `potential-constant-builtin-cxx23.cpp`;
  - `potential-constant-builtin-off-path-cxx20.cpp`: valid code with builtins on unevaluated paths, in unknown `?:` arms and in `sizeof`/`noexcept`;
  - `potential-constant-system-header-cxx20.cpp`;
  - `constexpr-asm-never-constant.cpp`, flipped from xfail.
  - Each test matches clang++-19, and clang++-22 where it applies.
- **Validation.**
  - clang-neg `CXX SemaCXX`: identical to base, case by case. Accepts-invalid stays at 87 cases in 74 files, rejects-valid at 28 cases, missed errors at 4522.
  - fmt and nlohmann_json build with no new rejections.
  - `cargo xtask bench bench/oven bench/reflect`: constexpr steps and evaluation bytes are identical on all 35 entries. In a back-to-back A/B against the base binary, peak RSS is -5.7% to +0.9%, and wall-time differences on the entries over 100 ms fall within load noise.
- **Known gaps** (WP-945 follow-ups):
  - `bcmp` is missing from the kiln_ast library-builtin table, so `bcmp(p, p, 1) + x` in gnu++ goes unreported;
  - `constexpr int f() { __builtin_unreachable(); }` reports never-constant where clang reports `err_constexpr_body_no_return`.
