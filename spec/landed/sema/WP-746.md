# WP-746 — C++26 DIS: concept and variable-template template parameters (P2841R7)

Part of WP-732 (C++26 DIS todo papers). Implements P2841R7 at
`-fclang-compat=22` (the default) against the Croydon DIS wording; the
paper is `partial` in docs/STANDARD_SUPPORT.md and
`__cpp_template_parameters` stays undefined.

## Changes

- **Parse** ([temp.param]/1; spec/parse.md "Template template parameter
  kinds"). `template<...> concept C` and `template<...> auto V`, named
  or unnamed, packs and defaults; before C++26 clang 22's "is a C++2c
  extension" errors. A bare concept or variable-template name is a
  template-name argument.
- **Kinds and matching** ([temp.arg.template], [temp.param]/5;
  spec/sema-templates.md §2.1.1, §11.2). `TtpKind::{Type, Variable,
  Concept}` on `TemplateParmInfo`; an argument must be of the
  parameter's kind; P0522 "at least as specialized" matching per kind;
  a concept-tt-parameter with associated constraints is an error.
  Uses inside the template are dependent template-ids, substituted to
  the argument's concept-id or variable template specialization;
  deduction from `X<V>` ([temp.deduct.type]).
- **Equivalence** ([temp.over.link]/6.1; §6.8). Two template-heads are
  equivalent only when corresponding template template parameters have
  the same kind (`templ/equiv.rs`, `overload/redecl.rs`,
  `templ/order.rs`).
- **Constraints** ([temp.constr.normal]/1.4, /1.5.3,
  [temp.constr.order]/3-4; §8.2–8.4). A concept-id naming a dependent
  concept is a concept-dependent constraint; a non-dependent concept
  argument normalizes through the argument concept (Example 3);
  a fold over a concept template parameter pack expands (Example 4);
  a fold mixing a concept pack with another kind is an error
  (Example 5); a constraint containing a concept-dependent constraint is
  not eligible for subsumption. Satisfaction is memoised on the
  substituted concept-id.
- **Mangling** (spec/abi.md §8.16). Matches clang 22: a type-constraint
  naming a concept template parameter mangles as the parameter's owner
  name (`TkN2ct1CEi`), using `TemplateTables::ttp_owner`.

## Wording over clang 22

Each is `skip(clang)` with expectations from the wording:
concept-pack folds expand in subsumption (clang leaves them atomic and
reports ambiguity), Example 5 is diagnosed, a concept-tt-parameter with
a requires-clause is an error, a kind change is not a redeclaration,
and `requires C<T>` / `requires D<U>` under renamed heads redeclare.
[temp.constr.order] Example 3's comment ("#1") disagrees with ¶4; kiln
follows ¶4, as clang 22 does.

## Remaining

- `__cpp_template_parameters` (needs the gaps below closed).
- Template template parameters nested in a TTP's own head are not
  compared by kind.
- Atoms from expanded concept-pack folds are identified by expression,
  not by full parameter mapping.
- P2963 fold-expanded constraints over type packs are not used in
  subsumption.
