# WP-1288 — GNU local labels (`__label__`)

Extends spec/sema.md §7.4 (labels and `goto`).

- **Parsing** (`parse_local_labels`, clang `ParseCompoundStatementBody`).
  - `__label__` is a keyword in every language mode (clang `KEYALL`).
  - Only at the start of a compound statement, before its first
    statement: `__label__ a, b;`, repeated.
  - Each one is a `DeclStmt` of `LabelDecl`s, located at the keyword.
  - A missing identifier is "expected identifier". A missing `;` is
    "expected ';' at end of declaration" after the previous token.
  - Anywhere else, `__label__` is not a statement (clang's "expected
    expression").
- **Lookup** (`label_decl`, clang `LookupOrCreateLabel`).
  - `act_on_local_label` makes a fresh `LabelDecl` of the function and
    records it in the current scope's `Scope::labels`. It shadows any
    label of the same name, local or not. Declaring it twice in one
    block makes two labels, silently, as clang does.
  - A `goto`, `&&name` or `name:` looks in the enclosing block scopes,
    innermost first, and stops at the function scope. A lambda body or
    local-class member function starts a new search.
  - Otherwise it finds the function's ordinary label of that name, or
    creates one. So outside its block, the name refers to the function's
    label again.
- **Checks.**
  - A local label never defined is "use of undeclared label 'x'" at its
    declaration, even when nothing uses it. It is reported when its
    block is left (clang `CheckPoppedLabel`): for the function body's
    own block, when that scope is left at the end of the body.
  - The function's ordinary labels keep their end-of-function check.
  - A local label defined twice is "redefinition of label". The note
    "previous definition is here" points at the declaration, since a
    local label's location stays there.
- **Templates.** The `DeclStmt` substitutes into a fresh local label in
  the instantiation's block (`local_decl`, clang `VisitLabelDecl`). The
  substituted `goto`s and labels then find it by name, as before.
- **AST dump.** `LabelDecl <head> name`, as a child of the `DeclStmt`
  (spec/ast-dump.md §3). `xtask clang-ast` now keeps clang's `LabelDecl`.
- **Codegen.** Unchanged: a `LabelDecl` in a `DeclStmt` emits nothing,
  and its label statement is an ordinary block.
- **Tests.**
  - `tests/conformance/ext.gnu.label.local/local-label-{run,O2-run}.cpp`:
    a statement-expression macro expanded twice, shadowing, `&&`/`goto *`,
    and a function template with two blocks.
  - `tests/conformance/ext.gnu.label.local/local-label-errors.cpp`
    (strict-diags) and `local-label-ast.cpp`.
  - `tests/c/stmt/local-label{,-O2}.c`.
  - gcc.c-torture: compile/20000326-2.c, compile/20000518-1.c,
    compile/981006-1.c, execute/930406-1.c and execute/980526-1.c now
    pass. The other `__label__` tests need nested functions, which are
    out of scope; clang rejects them too.
