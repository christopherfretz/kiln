# WP-656 — Trial-fold fast path: leaf integer expressions fold without bytecode

Extends spec/oven.md "Interface" (`Oven::try_fold`, the trial-fold fast
path and its equivalence rule) and spec/sema.md's constant-folding
paragraph. The measurements, before/after counts and A/B tables are in
docs/status/perf-reflection.md "WP-656: trial-fold fast path"
(follow-up row F15). Nothing observable changes: diagnostics, the
statistics, `-fkiln-cfg-stats` and the emitted IR are byte-identical.

## The fast path (`crates/kiln_oven/src/leaf.rs`)

An outermost `Oven::try_fold` or `Oven::fold_rvalue` first walks the
expression directly (`leaf_first`), with no thunk compile, no VM run and
no context set-up. Where the walk answers, the job is not entered.

- **Domain.** A prvalue tree whose every node has `bool` or integer type
  of at most 128 bits and is one of: an integer, character or `bool`
  literal; `noexcept`; a type or expression trait; an enumerator;
  `sizeof` of a type or a non-VLA expression; `alignof` of a type; a
  parenthesis, a substituted non-type template parameter or a
  `ConstantExpr`; an integral, boolean or no-op cast whose target is not
  an enumeration; a unary `+ - ~ !`; a binary arithmetic, shift,
  comparison or logical operator; `?:`. At most 64 levels deep.
- **Declines** (the full path runs): any other node, including every
  variable read, member access, call and lvalue; any failing operation
  (overflow, `/ 0`, a shift out of range); either arm of `?:`, `&&` or
  `||` outside the domain, even the arm not taken; a fold inside a
  running evaluation; a pending one-shot setting (`-Wconstant-evaluated`,
  the overflow check, a potential constant expression, a plain, `void`
  or address result, a `source_location` root).
- **Arithmetic.** Each node is computed with the `crate::arith`
  operation the bytecode would run, on the register value the compiler
  would produce (`compile::scalar_bits`), and the result is frozen with
  `freeze_scalar`. So the answer is the full path's value, bit for bit.

## Equivalence

- `Oven::try_fold_full` runs the full path with the fast path bypassed
  and `Oven::try_fold_leaf` runs only the walk; `Sema::trial_fold_paths`
  returns both answers. All three are `#[doc(hidden)]`, for tests.
- `crates/kiln_sema/tests/trial_fold.rs` generates expressions over
  every integer type, both signs, every unary and binary operator,
  boundary values, overflow, `/ 0`, shifts by the width, enumerations
  with fixed and unfixed underlying types, nested casts, `?:` and
  depth, and asserts the answers are equal. It also pins that variable
  reads (locals, parameters, `const` locals, namespace-scope variables)
  are declined.
- The `kiln_oven/leaf-check` feature (off by default) runs the full
  path after every walk that answered and panics if the values differ.

## Statistics

The `op-stats` feature of kiln_oven also counts trial entries
(`trial_stats.rs`): per caller, per expression shape, thunk and
function compiles, memo hits and successes. It is off in release
builds and changes no output when off.

## Tests

- `cargo test -p kiln_sema --test trial_fold` (7 tests), also with
  `--features kiln_oven/leaf-check`.
- The corpus is unchanged: conformance, codegen and stress pass, and
  `-S -emit-llvm` is byte-identical on every IR-printing input.
