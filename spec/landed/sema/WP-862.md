# WP-862 — flow-based uninitialized-values warnings for locals

A port of clang 19's `UninitializedValues.cpp` and the uninitialized-variable
reporting in `AnalysisBasedWarnings.cpp`, on the kiln CFG. It closes WP-696
(the UNINIT-a part of WP-443) and the UNINIT-b warnings.

## Deliverables

- **Code: `crates/kiln_sema/src/uninit.rs`** (spec/sema.md §7.14).
  - Diagnostics: `-Wuninitialized`, `-Wsometimes-uninitialized`,
    `-Wconditional-uninitialized` and `-Wuninitialized-const-reference`.
    The notes are clang's: the declaration note, the "initialize the variable"
    fix-it, the "remove the condition" / "remove the `||`/`&&`" fix-its and the
    branch-condition note.
  - Algorithm:
    - The lattice is 2 bits per tracked variable, in dense `u64` rows, one row
      per block.
    - Each expression is classified as Init, Use, SelfInit, ConstRefUse or
      Ignore, which is clang's `ClassifyRefs`.
    - A worklist over the blocks in reverse post-order, then a reporting pass
      in clang's block order, so the first use reported per variable is
      clang's.
  - Fast path. Sema notes a tracked local declared without an initializer
    (`FnState.uninit_vars`). The CFG is built for the analysis only when that
    is true and one of the four diagnostics is enabled at the function's
    location (`uninit_enabled`, which honours system-header suppression). A
    function with no such variable allocates nothing and does not build a
    CFG for this analysis.
  - Scratch maps use `FxHashMap`, and the scratch buffers are reused across
    functions.
  - Self-initialization of a scalar local (`int x = x;`) is the SelfInit
    class of the dataflow, as in clang. The syntactic `self_ref.rs` walk keeps
    statics and locals of class or reference type, and now carries clang's
    two source ranges.
- **Spec**: spec/sema.md §7.14.
- **Design note**: docs/design/uninitialized-values.md is marked implemented.
- **Tests**: tests/conformance/basic.indet/uninit-*.cpp (10 files). They cover:
  - flow;
  - the const-reference warning;
  - what the analysis leaves alone: address taken, non-const reference
    binding, by-reference capture, unevaluated operands, a `(void)` cast,
    asm outputs, arrays, record members and statics. `[[indeterminate]]` and
    `__attribute__((uninitialized))` do not silence the warning, as in
    clang 19;
  - templates: each specialization is analyzed once, when it is
    instantiated, and its warnings carry the instantiation note;
  - recovery after errors;
  - group control: `-Wall`, `-Wno-uninitialized`, `-Wno-sometimes-uninitialized`
    and `-Werror=`.

  The driver test `crates/kiln_driver/tests/driver.rs` pins the fix-it
  output byte for byte.

## Cost

The kiln binary is the harness build of this branch. Instruction counts are
from callgrind and compare `-Wall` with `-Wall -Wno-uninitialized`. The
reproducible command lines are in docs/status/perf-history.md, "WP-862".

- fmt 12.1.0, `test/format-test.cc`: 15,430,093,412 vs 15,382,733,723
  instructions (+0.31%).
- nlohmann_json v3.12.0, `tests/src/unit-algorithms.cpp`: 11,347,626,373 vs
  11,347,646,152 instructions (0.00%).
- Synthetic worst case, `perf_small.cpp` (the generator is in perf-history.md): 300
  functions, each with 8 uninitialized locals assigned under branches in a
  loop. The counts are 981,406,398 vs 851,506,828 (+15.3%).
  - Most of that is the CFG build (`cfg_ensure` ≈ 148M inclusive). The
    dataflow itself is ≈ 38M.
  - clang pays the same: it builds the CFG for any function with an
    analysis-based warning enabled.
- `cargo xtask bench --compiler kwall.sh --compare-with knouninit.sh` (the
  wrappers add `-Wall` and `-Wall -Wno-uninitialized`). Over 50 entries × 5
  runs, at a host load of about 21:
  - geomean time 1.01x (1.0092), totals 37,258 ms vs 37,455 ms;
  - geomean memory 1.00x (1.0025).
  - That is within noise. The bench entries declare few uninitialized locals.

## Regression

- libc++ M3 gate: 642 = 636 pass + 6 unsupported, with no new warnings.
- fmt 12.1.0 and nlohmann_json v3.12.0 were compiled with every test TU,
  using `-Wall -Wextra -Wconditional-uninitialized`. Of 93 TUs, every one has
  0 uninitialized-value warnings under both kiln and clang++-19. No warning
  appears under kiln only.

## What remains of WP-443 UNINIT

- `-Wuninitialized-const-pointer` (clang 21+) is not implemented. A
  const-pointer argument is classified as Ignore (`uninit.rs`, the call
  argument classification).
- Uninitialized field uses in a constructor's mem-initializers (clang
  `DiagnoseUninitializedFields`, `-Wuninitialized` on `A() : x(y), y(1)`) are
  not implemented. That includes the qualified base-class wording
  (`self_ref.rs`, `check_self_reference`).
- The self-initialization check does not descend into a statement-expression
  inside a static local's initializer.
- In the `-Wsometimes-uninitialized` note for a switch on a `bool`, the
  source range of the case label differs from clang's (`uninit_branch`, the
  `CaseStmt` arm). The line and column match.
