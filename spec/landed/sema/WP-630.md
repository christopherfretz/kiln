# WP-630 — x86 target builtins

Extends spec/sema.md §5.4 (builtin functions), spec/pp.md
(`__has_builtin`) and spec/diag.md. The codegen half (feature checks,
1:1 intrinsics, custom lowering) is spec/landed/codegen/WP-630.md, the
`-march=` / `target("...")` half spec/landed/driver/WP-630.md, the Oven
half spec/oven.md "x86 builtins".

Before WP-630 kiln declared one x86 builtin, `__builtin_ia32_pause`
(WP-610). kiln's resource headers are clang 19's, and their x86
intrinsic headers name 1,932 distinct `__builtin_ia32_*` builtins, so
every TU that included `<immintrin.h>`, `<x86intrin.h>` or `<emmintrin.h>`
failed in `<uintrintrin.h>` (`__builtin_ia32_clui`), whatever `-march=`.

## Target builtins

- **Table.** `crates/kiln_ast/src/x86_builtins.rs` is generated by
  `scripts/gen-x86-builtins.py` (do not edit it). It holds every
  `__builtin_ia32_*` name `resource/include/*.h` references, plus
  `__builtin_ia32_pause` (libstdc++'s `<bits/atomic_wait.h>`), the seven
  others clang 19's `__has_builtin` answers 1 for by default
  (`features_table.rs`: `rdtsc`, `lfence`, `mfence`, `sfence`,
  `clflush`, `ldmxcsr`, `stmxcsr`) and the seven header builtins below:
  1,947 rows sorted by name. Each row has
  the prototype in `Builtins.td` notation, the `NoThrow` / `Const`
  attributes, clang's required-features string (empty: none), and the
  immediate checks.
- **Provenance.** There is no `BuiltinsX86.def` to read; the script
  probes a clang (21) binary:
  - *Declarations:* a TU naming each builtin, `-ast-dump=json`; the
    implicit `FunctionDecl` gives the type and attributes.
  - *Immediates:* each integer parameter passed a non-constant with the
    others constant; then a valid combination of values; then per
    parameter the diagnostic for 1000000 and 9 ("Immediates" below).
  - *Features:* one TU per builtin, codegen from a function without the
    feature (default flags, then `-mno-sse2`, `-mno-sse`, `-mno-mmx`,
    `-mno-fxsr`): clang's "needs target feature X".
  - *Lowering:* spec/landed/codegen/WP-630.md.
  clang 20 dropped the MMX builtins (its `mmintrin.h` is built on SSE2)
  and the `vpopcnt*` ones (now `__builtin_elementwise_popcount`); their
  clang 19 prototypes and features (105 rows) are in the script's
  `CLANG19_ONLY`. They are declared at every `-fclang-compat`, because
  the headers are clang 19's at every level.
- **Ids and lookup** (`kiln_ast::decl::builtin::x86`). A row's id is
  `x86::BASE` (0x2_0000) plus its index: a name lookup is a binary
  search, an id lookup an index. `builtin::by_name` sends names starting
  with `__builtin_ia32_` or `_mm_` there. `IA32_PAUSE` (id 2152) is gone;
  `__builtin_ia32_pause` is a table row.
- **Prototypes.** The NEON decoder (WP-558) covers them: `V<N>` vectors
  (including `V256i`, the AMX tile type), `x` `_Float16`, `y` `__bf16`,
  `LLi` `long long`, `I` an integer constant expression.
- **x86-64 only.** `target_has_builtin` declares them only for an x86-64
  triple (also in `is_builtin_name` and `recognize_builtin_decl`); on
  `AArch64` the names are undeclared identifiers, and a declaration of a
  header builtin's name is an ordinary function.
- **Declared unconditionally, checked at the call.** As in clang the
  required features are never checked in sema: a call `-fsyntax-only`
  accepts is diagnosed only when codegen emits it.

## Immediates (clang `SemaX86::CheckBuiltinFunctionCall`)

`check_builtin_ice_args` first requires every `I` parameter to be an
integer constant ("argument to '%0' must be a constant integer"), then
`check_x86_imms` applies the row's checks to the converted arguments, all
at the call's start, a value-dependent argument waiting for
instantiation:

| Check | Diagnostic |
|---|---|
| `Only32Bit` (`readeflags_u32`, `writeeflags_u32`) | `sema_x86_builtin_32_bit_only`, "this builtin is only available on 32-bit targets" |
| `Rounding(i)`: 4, 8, 9, 10, 11 | `sema_x86_invalid_rounding`, "invalid rounding argument" |
| `Sae(i)`: 4, 8, 12 | the same |
| `Scale(i)`: 1, 2, 4, 8 | `sema_x86_invalid_scale`, "scale argument must be 1, 2, 4, or 8" |
| `RangeError(i, lo, hi)` (the AMX tile numbers) | `sema_argument_invalid_range` (an error); the call is invalid |
| `DistinctTiles` | `sema_x86_tile_duplicate`, "tile arguments must refer to different tiles" |
| `Range(i, lo, hi)` | `sema_argument_outside_range`, "argument value %0 is outside the valid range [%1, %2]", `-Wargument-outside-range`, an error by default; the call stays valid |

The value printed is the argument converted to the parameter type (a
tile number is an `unsigned char`). `char` immediates clang checks
against [-128, 255] need no check (every value is in range).

## Header builtins

clang's x86 `TARGET_HEADER_BUILTIN`s with `ALL_LANGUAGES`: `_mm_clflush`,
`_mm_lfence`, `_mm_mfence`, `_mm_pause` (`<emmintrin.h>`), `_mm_getcsr`,
`_mm_setcsr`, `_mm_sfence` (`<xmmintrin.h>`). The headers declare them as
ordinary `extern "C"` functions; `recognize_builtin_decl` makes such a
declaration the builtin (it has the builtin's type in a namespace-scope
context with C language linkage). They are not predefined library
functions, so C++ lookup also declares one implicitly
(`lazily_create_builtin`), with clang's
`sema_implicit_lib_function_decl` "implicitly declaring library function
'%0' with type %1" (`-Wimplicit-function-declaration`, on by default) and
`note_include_header_or_declare` "include the header <%0> or explicitly
provide a declaration for '%1'". `__has_builtin` does not answer them.

## Generic builtins the headers use

- `__builtin_nontemporal_store(v, p)` / `__builtin_nontemporal_load(p)`
  (clang `BuiltinNontemporalOverloaded`; kiln-private ids 2153, 2154,
  `void(...)`, custom type-checking): `p` decayed must be a pointer
  (`sema_nontemporal_not_pointer`) to an integer, floating, pointer or
  vector type (`sema_nontemporal_bad_pointee`), both at the callee; a
  store copy-initializes `v` to the unqualified pointee and is `void`, a
  load has the unqualified pointee's type.
- `__builtin_nondeterministic_value(x)` (clang
  `BuiltinNonDeterministicValue`; id 2155, `NoThrow`): one argument of a
  builtin or vector type, kept unconverted (never evaluated), the call's
  type; another type is `sema_nondeterministic_value_arg` ("1st argument
  must be a vector, integer or floating-point type (was %0)"; clang 19's
  "floating point" at `-fclang-compat=19`).

## `__has_builtin`

`pp_cmd` installs a `kiln_pp::TargetBuiltins` for the prefix
`__builtin_ia32_` on x86-64, with the features the driver resolves
(`TargetFeatures::x86_enabled`: the `-march=` CPU's, else `x86-64`'s).
The answer is clang's `evaluateRequiredTargetFeatures`; a builtin without
a required feature answers 1 (`TargetBuiltins::answer`). Measured against
clang 21 under the default CPU, `westmere`, `haswell` and
`skylake-avx512`: every answer agrees except the `CLANG19_ONLY` rows,
which clang 21 lacks (kiln answers them from clang 19's features).

## Attributes

- `nodebug` (GNU, clang `NoDebugAttr`, `AttrKind::NODEBUG`): accepted
  and kept (dumped `NoDebugAttr`); kiln emits no debug information
  anyway. No subject check yet.
- `min_vector_width(N)` (`__attribute__` and `[[clang::]]`, clang
  `MinVectorWidthAttr`, `AttrKind::MIN_VECTOR_WIDTH`, `a` = N): one
  integer constant ("'min_vector_width' attribute requires an integer
  constant"), functions only; codegen starts the definition's
  `"min-legal-vector-width"` at N.

## Follow-ups

- `target("...")` strings are not validated: clang warns about an
  unknown feature, `arch=` or `tune=` and ignores the attribute
  (`warn_unsupported_target_attribute`); kiln ignores only an unknown
  `arch=` / `tune=`, silently.
- `nodebug` subject checks.
