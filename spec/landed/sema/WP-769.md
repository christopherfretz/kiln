# WP-769 — correctness bundle 4: member-typedef hard errors, friend redeclarations, C++14 exception-spec compatibility, linker options, C++23 lambda extensions

WP-761 and the WP-756 follow-ups: code kiln accepted that clang rejects,
wrong lookup after a friend redeclaration, and IR that differed from
clang 19.

## Changes

- **An error in a member typedef of a class template specialization is a
  hard error** ([temp.deduct.general]/8, P4149; WP-761). kiln already
  rejected it, as clang 19 and 22 do: the immediate context ends at the
  class template's instantiation. The rule is pinned in
  spec/sema-templates.md Q12.
  Tests: `tests/conformance/temp.deduct.general/member-typedef-hard-error.cpp`,
  `member-typedef-hard-error-19.cpp`.
- **A friend redeclaration neither makes a name visible nor hides one**
  ([namespace.memdef]/3, [dcl.meaning], [basic.lookup.argdep]/4). A
  friend redeclaration of a visible function keeps the earlier visible
  declaration as the ordinary-lookup entry (`visible_to_ordinary` in
  decl.rs), so its attributes and default arguments stay; a redeclared
  hidden friend stays hidden and is found by ADL across template
  redeclarations (`friend_of_any` in adl.rs). A friend declaration with a
  default argument must be a definition and the only declaration
  ([dcl.fct.default]/4, `check_friend_default_args`,
  `sema_friend_decl_with_def_arg_must_be_def`/`_redeclared`).
  Rules: spec/sema-class.md (friend row), spec/sema-overload.md §7.
  Tests: `tests/conformance/class.friend/friend-redecl-hidden-adl.cpp`,
  `friend-redecl-hidden-template.cpp`, `friend-redecl-keeps-visible.cpp`,
  `tests/conformance/dcl.fct.default/friend-default-arg-only-declaration.cpp`.
- **C++11/14 function-pointer conversions check exception
  specifications** ([except.spec]/5 in C++14; clang
  `CheckExceptionSpecCompatibility`). In initialization, assignment,
  argument passing and return, the target's specification must be at
  least as restrictive as the source's (`sema_incompatible_exception_specs`),
  and pointer-to-function parameters and return types must have
  equivalent specifications (`sema_deep_exception_specs_differ`). Not
  checked at C++17 and later, under `-fno-exceptions`, for casts, or
  after a user-defined conversion (`exc_spec_compat_error` in except.rs,
  `exc_spec_compat` in conv/mod.rs). Rule: spec/types.md §5.4.
  Tests: `tests/conformance/except.spec/fnptr-exception-spec-compat-cxx14.cpp`,
  `fnptr-exception-spec-compat-cxx11.cpp`,
  `fnptr-exception-spec-compat-no-exceptions.cpp`.
- **`!llvm.linker.options` only with C++20 modules at compat 19** (clang
  19 emits the empty list only when `LangOptions::CPlusPlusModules` is
  set). The driver passes `CodegenOptions::cxx_modules` (C++20 and later);
  module.rs emits the list only below compat 22 and with it set. Rule:
  spec/codegen.md (module metadata table).
  Tests: `tests/conformance/cpp.module/ir-no-linker-options-cxx17-19.cpp`,
  `ir-linker-options-cxx20-19.cpp`.
- **C++23 lambda forms warn before C++23** (P2173R1, P1102R2): attributes
  after the introducer (`-Wc++23-lambda-attributes`) and an omitted
  parameter clause before a specifier, `->`, attribute, `noexcept` or
  `requires` (`-Wc++23-extensions`, `() ` fix-it). Rule:
  spec/sema-lambda.md §2.
  Test: `tests/conformance/expr.prim.lambda/lambda-cxx23-extensions-cxx17.cpp`.
