# WP-490 — variable-specialization point of instantiation, `convert_vector` bool-vector fold, compound literal in a variable template

Three correctness items (WP-466 follow-ups). Each states its rule in the
spec paragraph it extends; this file is the index.

- **Point of instantiation of a variable template specialization**
  ([temp.point]/1, /7; [temp.inst]/7; [temp.expl.spec]/7). A
  specialization usable in constant expressions that is referenced before
  its template's definition is defined from that later definition, at a
  later reference or at the end of the TU (`templ/class.rs`
  `note_var_referenced`, `instantiate_late_var_spec`; `templ/pending.rs`
  `quiet_pending`). A definition instantiated at a reference is emitted
  before the namespace-scope declaration that contains the reference, as
  clang's `PassToConsumerRAII` (`TemplateTable::ref_var_insts`, codegen
  `emit_ref_vars`). An explicit specialization after an implicit
  reference is diagnosed as clang does. Rules: spec/sema-templates.md
  §4.6 "Points of instantiation" and "Initializers" (with the end-of-TU
  **Deviation**: clang and GCC leave such a variable undefined),
  spec/codegen.md §2a. Tests:
  `tests/conformance/temp.expl.spec/var-template-spec-after-reference.cpp`,
  `tests/conformance/temp.point/var-template-defined-after-reference-run.cpp`,
  `tests/conformance/temp.point/var-template-end-of-tu-instantiation-run.cpp`,
  `tests/codegen/var_template_point_of_instantiation.cpp`.
- **`__builtin_convertvector` of a `const` vector variable** (clang
  `ScalarExprEmitter::VisitConvertVectorExpr`, `tryEmitAsConstant`, the
  IRBuilder's `ConstantFolder`). Codegen folds the operand and the
  lane-wise `icmp`/`fcmp`/cast, to and from `bool` ext vectors, so the
  stored value is clang's constant. The Oven already evaluated the
  constant forms (WP-450); a float lane follows clang on both sides
  (the evaluator converts toward zero, the folded `fcmp une` compares
  with zero). Rules: spec/codegen.md §7w, spec/oven.md "Bool vectors".
  Tests: `tests/codegen/convertvector_const_fold.cpp`,
  `tests/conformance/ext.vector/convertvector-const-fold-run.cpp`.
- **Compound literal in a constexpr variable template or a class
  template's default member initializer instantiated from a function
  body** ([GNU], C99 6.5.2.5p5): at file scope at every compat level, as
  clang 19 and GCC 16. clang 21+'s `isInCFunctionScope` test
  (llvm-project 977d8a4bcd83) reads the parser's scope at the point of
  instantiation, so clang 22 makes the literal a temporary depending on
  where the first use is: a clang defect, not followed. Rule: spec/sema.md
  §5.8 "Compound literals", Deviations. Test:
  `tests/conformance/ext.gnu.compound.literal/variable-template-from-function-run.cpp`.

Deviations: docs/status/deviations.md (both rows are WP-490's).
