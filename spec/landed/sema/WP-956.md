# WP-956 — template declaration rules (accepts-invalid cluster 10)

This WP covers cluster 10 of WP-912's clang negative-test run. WP-1017
landed the base check for each of the five items. WP-956 extends four of
them and confirms the fifth. Every diagnostic is matched against clang 19
and clang 22, and each rejection test has a valid twin.

- **Partial specialization not more specialized than the primary**
  ([temp.spec.partial.general]/9.2, DR1495; spec/sema-templates.md §4.4).
  **Fixed for packs.**
  - `not_more_specialized_than_primary` (`templ/order.rs`) deduces both
    directions, as clang's `isMoreSpecializedThanPrimary` does. WP-1053
    landed the same two-direction check in parallel (with the CWG1432
    constraint tie-break); the merge keeps its version. Examples
    of what it rejects:
    - `B<Ts...>` for `template<class, class...>`;
    - `C<0, Ts...>`;
    - the variable-template forms;
    - `X0<Ts...>` for `template<class T, class U, class V = U>`.
  - A pack expansion argument for a non-pack parameter stops default
    arguments (`args.rs` `open_expansion`). Without this, `X0<Ts...>`
    gave a false "too few template arguments".
  - /9.3 unwraps pack arguments: `P<T...>`, `Q<N...>` and `S<TT...>`
    specialize nothing.
  - `Q<T, int, Cs...>` (a template template pack expansion) stays valid;
    WP-1053's `deduce_template_from_expansion` covers it, so WP-956's own
    `deduce_arg` branch for it was dropped at the merge.
  - The variable-template /9.3 error says "to define" for a non-`extern`
    declaration outside a class, as clang does. Otherwise it says "to
    declare".
  - Tests in `temp.spec.partial.general/`:
    - `pack-not-more-specialized.cpp`;
    - `pack-does-not-specialize.cpp`;
    - `pack-partial-specializations-valid.cpp` (the twin);
    - `var-does-not-specialize-wording.cpp`.
  - Still skipped: constrained partials and member-template partials
    (WP-1053).
- **CWG526 and the non-deduced checks in cwg5xx.**
  - CWG526 itself (`(N)` arguments) was fixed by WP-1017.
  - **New:** `check_partial_deducible` covers packs.
    - A non-trailing expansion makes the list non-deduced, e.g.
      `U<Types..., Tail>` and `Y<L<T..., V>>`.
    - So does the expansion of an expression, e.g. `X1<0, Values + 1 ...>`.
    - A non-trailing function parameter pack is skipped
      (`DeducedArgs::self_deduce`), so `Y<void(T..., V)>` reports only
      `T`.
    - Test: `temp.spec.partial.general/pack-not-deducible.cpp`. Its twins
      are in `pack-partial-specializations-valid.cpp`.
  - Not in scope: the remaining cwg5xx misses are pedantic and
    template-header rules. They are listed under follow-ups.
- **Float NTTPs before C++20** ([temp.param]/4).
  - Floating-point and class types were fixed by WP-1017.
  - **New:** `_Complex` and vector types get the "before C++20" error.
  - **New, in every mode:**
    - `void` gets "non-type template parameter has incomplete type";
    - `_Atomic` gets "cannot have type".
  - **New (C++20):** a class with an `_Atomic` member is not structural
    (`is_structural_at`). A redeclaration does not compare a parameter
    whose type was already rejected (`templ/equiv.rs`).
  - Tests:
    - `temp.param/ext-scalar-nttp-cxx{17,20}.cpp`;
    - `temp.param/atomic-member-not-structural.cpp`.
- **Conversion function template rules.**
  - CWG1878 (deduced return type) was fixed by WP-1017.
  - **New: dependent names.** `this->operator T()` and an unqualified
    `operator T()` with a dependent type are type-dependent
    ([temp.dep.expr]/3). They are looked up at instantiation instead of
    failing in the definition or at instantiation.
  - **New: ordering.** Conversion templates found by [temp.mem]/6
    deduction are template candidates and are ordered by
    `more_specialized_conversion` in overload resolution. The same
    ordering applies to explicit instantiation and explicit
    specialization; the ambiguous form names candidates by their
    specialization.
  - Tests in `temp.mem/`:
    - `conversion-template-dependent-ordering.cpp`;
    - `conversion-template-ambiguous.cpp`.
- **Constraint self-dependency is a hard error in SFINAE.** This was
  already fixed by WP-1017 (`temp.constr.atomic/self-dependent-constraint.cpp`).
  No change.

Follow-ups (not fixed):
- `templ/deduce.rs:382`: a non-trailing function parameter pack ends the
  deduction of a function type. clang skips it and deduces the rest.
  This is the rejects-valid `f1<int, int>(g)` at
  `temp.deduct.type/p9-0x.cpp:55`, and was already present before
  WP-956.
- An invalid `Z<int, Ts...>` whose expansion covers two or more non-pack
  parameters never matches. The result is an extra "implicit
  instantiation of undefined template" after the error.
- Wording only: `temp.mem/p5.cpp:79` says "rvalue" where clang says
  "lvalue" before C++23.
- Member variable template partials (`temp.class.spec/p8-1y.cpp:29,31`)
  are WP-1053.
- cwg5xx: `missing 'typename' ... C++20 extension` under
  `-pedantic-errors` (triage item 13), and the CWG531 `template<>`
  header rules (`cwg5xx.cpp:374/381/409/411`).
