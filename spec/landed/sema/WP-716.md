# WP-716 — protobuf through its own build and tests (M8 wave 3)

protobuf v33.1 built with kiln++ through its own CMake build with
`protobuf_BUILD_TESTS=ON` (Abseil and GoogleTest fetched at configure
time and compiled by the compiler under test), and run with CTest
(docs/status/oss/protobuf.md). Each behaviour below is a kiln bug the
build found, reduced to a standalone test; the rule is stated in the
spec named.

## Changes

- **Pointers to members of anonymous unions and structs**
  ([class.union.anon]/1, [expr.unary.op]/3, [expr.const]/5; spec/oven.md,
  spec/codegen.md). `&C::m` for a member of an anonymous union or struct
  names the member through its indirect field: the Oven's member pointer
  sums the offsets along the access path and checks that the anonymous
  union directly holding the member has it active; codegen's field offset
  sums the chain as clang's `getFieldOffset`. Both previously rejected it
  (extension_set.h's `kUnionMember` table).
  Tests: `tests/conformance/class.union.anon/member-pointer-to-anonymous-member-run.cpp`,
  `tests/conformance/class.union.anon/member-pointer-to-anonymous-member-inactive.cpp`.
- **A generic lambda in a member function sees the enclosing `this`**
  ([expr.prim.lambda.capture]/7-8, [expr.prim.this]/2,
  [class.mfct.non.static]/2; spec/sema-lambda.md). An instantiated
  generic lambda's call operator takes the enclosing member function's
  class, not the closure, as the implicit object class of an unqualified
  member call; a dependent call to member functions under `[&]` captures
  `this` when every candidate is an instance member (potentially, when
  some are static), as clang's `BuildImplicitMemberExpr`. Before, the call
  was rejected, and under `[&]` the instantiation used an uncaptured
  `this` (wrong code; map.cc).
  Test: `tests/conformance/expr.prim.this/generic-lambda-implicit-this-member-template-run.cpp`.
- **A qualified mem-initializer-id may name an inherited
  injected-class-name** ([class.base.init]/2, [temp.local]/1-2;
  spec/sema-class.md §4.9). `E::E(int v) : E::Entry(v)` names the base
  class template specialization through the injected-class-name `E`
  inherits from it (struct.pb.cc).
  Test: `tests/conformance/class.base.init/qualified-inherited-injected-class-name-run.cpp`.
- **`__builtin_offsetof` finds members of base classes** (GNU extension;
  [support.types.layout]/1, [class.member.lookup]; spec/sema.md). The
  first member designator is found by class member lookup (an ambiguity
  is the member-access error), the base subobject's offset along the
  unique path is added, and a member of a virtual base is clang's
  `invalid application of 'offsetof' to a field of a virtual base`
  (empty.pb.cc, descriptor.pb.cc).
  Tests: `tests/conformance/ext.gnu.offsetof/base-member-run.cpp`,
  `tests/conformance/ext.gnu.offsetof/base-member-diagnostics.cpp`.
- **The GNU `section` attribute** (GNU extension; [dcl.attr.grammar]/6;
  spec/sema.md, spec/codegen.md §8). `__attribute__((section("s")))` and
  `[[gnu::section("s")]]` take one string literal and apply to functions
  and to variables with static storage duration, as clang's
  `handleSectionAttr`; codegen sets the LLVM section on declarations and
  definitions, static locals and template instantiations. It was ignored,
  so the linker-defined `__start_s`/`__stop_s` bounds were undefined
  (generated_message_util.cc's `pb_defaults`, every protobuf link).
  Tests: `tests/conformance/ext.gnu.section/section-run.cpp`,
  `tests/conformance/ext.gnu.section/section-diagnostics.cpp`,
  `tests/codegen/section_attr.cpp`.
- **A member function template is a non-static member for access
  checking** ([class.protected]/1, [class.access.base]/5;
  spec/sema-class.md). A member function template is non-static when its
  pattern is, so [class.protected] checks the object's class for it: a
  friend of a class that derives privately from the base reaches a
  protected member template through an object of that class
  (repeated_ptr_field.h), and `b->Add<int>()` through a base object from a
  derived class is now the protected-access error it is for a member
  function.
  Tests: `tests/conformance/class.protected/member-template-friend-of-derived-run.cpp`,
  `tests/conformance/class.protected/member-template-object-diagnostics.cpp`.
