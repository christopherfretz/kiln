# WP-704 — cereal through its own build and tests (M8 wave 2)

cereal v1.3.2 built with kiln++ through its own CMake build and its
doctest unit tests (docs/status/oss/cereal.md). Each fixed behaviour
below is a kiln bug the build found, reduced to a standalone conformance
test; the rule is stated in the spec named.

## Changes

- **A base specialization's injected-class-name is a type**
  ([temp.local]/1, [class.qual]/2, [class.member.lookup];
  spec/sema-templates.md §4.7). The injected-class-name of a base class
  template specialization found by lookup in a derived class
  (unqualified inside it, or qualified `D::V` through the derived class
  or a typedef of it, and `typename C::V` after instantiation) and not
  followed by `<` names that specialization
  (`Sema::injected_specialization_name`, used by the parser's
  `scan_name_walk` and `parse_qualified_type_rest`); followed by `<` it
  is the template. kiln classified it as the class template and asked
  for template arguments (rapidjson's `Document::GenericValue`, in
  every cereal TU).
  Test: `tests/conformance/temp.local/base-specialization-injected-name.cpp`.
- **A type-dependent new-initializer makes a new-expression
  value-dependent, not type-dependent** ([temp.dep.expr]/3-4;
  spec/ast.md §5.7). `Builder::cxx_new` turns the type dependence of the
  array bound, the initializer and the placement arguments into value
  dependence (clang's `turnTypeToValueDependence`); only the allocated
  type makes the expression type-dependent. `std::unique_ptr<B> p(new
  D(f()))` with a dependent `f()` in a template is therefore a
  direct-initialization checked at definition time with the type `D *`,
  choosing the explicit constructor; it was rejected as a
  copy-initialization ("no viable conversion").
  Test: `tests/conformance/temp.dep.expr/new-expression-dependent-initializer.cpp`.
- **A conversion template returning a reference keeps the reference
  target's cv in deduction** ([temp.deduct.conv]/4-5, [over.match.ref],
  [dcl.init.ref]/5.1.2; spec/sema-overload.md §10.8). For a target
  `U cv &`, A is the referee with its cv when the template's result is
  a reference, else P and A both drop their cv (clang's workaround of a
  defect in /4). `template <class T> operator T const &()` deduces
  `T = U` for `U const &` and binds directly to the returned lvalue;
  it failed deduction there, so the reference was bound to a temporary
  copy, or, next to a deleted `template <class T> operator T()`
  (cereal's `NoConvertConstRef`), the conversion was ambiguous.
  Test: `tests/conformance/temp.deduct.conv/reference-target-keeps-cv.cpp`.

## Harness row

`scripts/oss/projects.toml` `[cereal]` is `verified = true` with
`-DSKIP_PORTABILITY_TEST=ON` (no `-m32` multilib on aarch64) and
`-Wno-error=` for clang 19's default-error
`-Wmissing-template-arg-list-after-template-kw` and
`-Wc++11-narrowing-const-reference`; both are needed by the clang++-19
control build, not by kiln.
