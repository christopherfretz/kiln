# WP-1081 — break/continue in expansion-statement headers

WP-1075 left one question open: what a GNU statement expression that jumps does in a `template for` header (init-statement or expansion-initializer). clang 22 has no P1306, so the oracles were GCC 16.1, clang's P1306 branch (its parser, codegen and constant evaluator, read from source) and its prebuilt fork. They agree. Kiln already matched them; the work found one unrelated miscompile on the way. Rules: spec/sema.md §7.6a "Jumps in the header".

- **Behaviour** (no change needed):
  - The expansion statement is a loop for its body only, so header `break`/`continue` need an enclosing loop or switch (an outer expansion statement counts). Without one they are diagnosed at the keyword, also in a template definition.
  - At run time the init-statement, an iterating range and a destructuring initializer reach the enclosing loop or switch. An enumerating element's jump ends that element (`continue`) or the expansion statement (`break`), because the element is initialized inside its block.
  - `return`/`goto` leave as usual, and destructors run on every path.
  - CFG: the init-statement's `break` can fall off the end (-Wreturn-type); an element's cannot.
  - Constant evaluation: a taken jump gives clang's "this use of statement expressions is not supported in a constant expression"; an untaken one evaluates.
- **Fix** (`kiln_sema/src/gnu.rs`): a statement expression now sets aside the enclosing full-expression's pending cleanups (`Sema::cleanup`) and merges them back at its end, as clang's `ParentCleanup` does. Before, the first full-expression inside took them. A temporary created before the statement expression (`D{1}.v + ({ 0; })`) was then destroyed at the end of the block, not of the full-expression. This affected every statement expression, not only expansion statements.
- **Oracle disagreements**:
  - GCC evaluates jumps out of statement expressions in constant evaluation; kiln follows clang.
  - GCC accepts a jump in an iterating range by making `__range` non-constexpr (CWG3131); kiln keeps P1306R5's `static constexpr __range` and diagnoses it.
- Tests, all in `stmt.expand/`:
  - `header-jump-run.cpp`: init/element/destructuring × continue/break, switch, nested, template, return/goto, destructors; GCC oracle.
  - `header-jump-errors.cpp`: no loop, switch only, lambda, template definition, nested (valid), iterating range.
  - `header-jump-cfg.cpp`: -Wreturn-type.
  - `header-jump-consteval.cpp`: untaken jumps, inner loops, nested.
  - `header-jump-consteval-neg.cpp`: taken jumps, with notes.

  And `ext.gnu.stmt.expr/temporary-before-stmt-expr-run.cpp`, for the fix.
- **Follow-ups**:
  - Enumerating-element temporaries die at the end of the element block in kiln but at the end of the declaration in GCC (CWG3043, a TODO in clang).
  - clang's main branch now opens `while`/`do`/`for` only for the body (spec/sema.md §7.4a "Newer clang"); revisit when the oracle moves past 22.
