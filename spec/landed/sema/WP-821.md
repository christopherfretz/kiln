# WP-821 — concepts follow-ups from WP-776 (atom identity, mapping completeness, dependent sizeof)

Closes the four items WP-776 left in "Remaining" (BACKLOG WP-821).

## Changes

- **Dependent `sizeof`/`alignof` operands checked at substitution**
  ([expr.sizeof]/1, [expr.alignof]/1, [temp.res.general]/6). A dependent
  operand type (`sizeof(void(T))`, `sizeof(T)`) is no longer diagnosed
  in the template definition; the instantiation that makes it a
  function type is diagnosed with its instantiation note
  (`expr.rs` `check_trait_operand`, `act_on_trait_expr`). `typeid`,
  `__alignof` and `__builtin_offsetof` already deferred dependent
  operands.
- **Converted mapping arguments for non-integral non-type parameters**
  ([temp.constr.atomic]/2, [temp.arg.nontype]/2, [temp.type]/2; §8.2).
  A non-dependent written argument of a pointer, reference, class-type
  or `auto` parameter maps as its converted template argument
  (`normal.rs` `converted_mapping_arg`), so `C<&x>`/`C<&(x)>` and
  `C<S{1}>`/`C<S{0 + 1}>` share atoms and the more constrained overload
  wins instead of an ambiguity.
- **Structural profiles for dependent reflections** (spec/types.md §7.2;
  §8.2). `^^A<T>`, `^^T*`, `^^typename A<T>::type`, `^^A<T>::x`, `^^TT`
  and `^^TT<T>` profile by operand kind and the operand's dependent
  profile (`kiln_ast/src/types/profile_expr.rs` `reflected_type_words`),
  so the same reflection written in two templates is equivalent.
- **Used-parameter walk through lambdas and bodies** ([temp.constr.atomic]/1;
  §8.2). `concepts/used.rs` walks a lambda's captures, template head,
  parameters, trailing requires-clause, body and call-operator type
  (`used_in_lambda`), every statement kind (`used_in_stmt`), the
  declarations a body holds including local classes and enums
  (`used_in_local_decl`), closure and local tag types (`used_in_tag`),
  statement expressions, expansion statements and a function type's
  exception specification. The whole mapping is kept only for a
  dependent member class/enum, an unresolved using type, an invalid
  type, a friend/using-declaration in a body and an index past 63.

## Oracles

clang 19 for items 1, 2 and 4 (lambda subsumption and the note text);
GCC 16.1 for item 3 (`skip(clang)`) and for expansion statements
(`requires: clang>=23`). GCC 16.1 never treats two lambda atoms as
identical, so it is no subsumption oracle for lambdas.

## Remaining

- A generic lambda in a concept's constraint expression fails
  substitution during satisfaction (`templ/subst/lambda.rs`
  `lambda_declarator`, :77), so the atom reads as ill-formed.
- An instantiated closure call operator's trailing requires-clause is
  not checked at the call (accepts-invalid).
- `typeid` of an incomplete local class in a template is accepted
  (`rtti.rs` `act_on_typeid`).
- A dependent member class/enum still keeps the whole mapping
  (`used.rs` `used_in_tag`).
- Note wording: a lambda atom prints as `...()` (clang `[] {`), and the
  substitution note says "while substituting template arguments into
  constraint expression here" where clang 19 says "in instantiation of
  requirement here".
