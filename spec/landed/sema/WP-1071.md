# WP-1071 — re-lookup of a member named through a specialization

WP-1054 left `relookup_member` (kiln_sema `templ/subst/mod.rs`) handling
one shape: a member of a class template's pattern, named through a
qualifier `B<T>::` that kiln resolved to the pattern, whose specialization
`B<A>` turned out to be an explicit or partial specialization. Only a tag
of the same kind was found again; anything else was "not yet implemented",
a hard error on valid code. Specs: spec/sema-templates.md, the
`find_instantiated_decl` row of the substitution table, and the qualified
friend paragraph of §[temp.friend].

- **Repro matrix (kiln before / after / clang 19 / clang 22 / g++).**
  - Overload sets and using-declarations reached through `A<T>::f`,
    `this->f`, `obj.f`, `&A<T>::f`, `using Base<T>::f` (with hiding and
    overriding, [namespace.udecl]/14-15) and `using Base<T>::Base`: kiln
    already matched clang. These are dependent names looked up again at
    instantiation by the ordinary path; none reaches `relookup_member`.
  - `class B<T>::In::Deep` where `B<A>::In` is an alias, a typedef or a
    `using Base::In`: was "not yet implemented"; now finds `Deep` in the
    class `In` denotes (g++ agrees; clang 19 and 22 crash).
  - `friend int B<T>::f(W<T>&);` with an explicitly specialized `B<long>`
    declaring several `f`: was "not yet implemented"; now matches clang and
    g++.
  - The same friend against the primary template granted no access (the
    instantiated friend was declared as a namespace function) and, for a
    partial specialization, made the member use the primary template's
    definition (a miscompile); both fixed.
  - A deduction guide whose constraint names a member of the primary
    template, deduced to an explicit or partial specialization: was "not
    yet implemented"; now clang 22's substitution failure (clang 19 accepts).
- **`relookup_member`.** A class or enum is looked up as a nested-name
  component (`act_on_nested_name_spelled`), so typedefs, aliases and
  using-declarations naming a class are followed and ambiguity and access
  are diagnosed as for a written qualifier. A function is chosen from the
  overload set by its substituted canonical type; another member must be
  the one declaration of its kind found. The found member's access is
  checked. The "not yet implemented" path is gone.
- **Deduction guides.** When the innermost instantiation frame substitutes
  into a `CXXDeductionGuide`, the mismatch is
  `sema_specialization_not_primary_template` (clang's
  `err_specialization_not_primary_template`), a SFINAE failure of the
  guide.
- **Qualified member friends.** `function_decl` gives a friend that
  redeclares a member function the instantiated class as its qualifier
  (`friend_member_class`), drops the storage class it inherited from a
  static member, and does not record it as a member instantiated from the
  friend pattern. The friend access check uses the member the friend
  redeclared.
- **Nested-name ambiguity.** `nested_name_from_found_written` (decl.rs)
  reports `member 'In' found in multiple base classes of different types`
  for an ambiguous component; `typename B<T>::In::Deep` with an ambiguous
  `In` was accepted.
- **Other "not yet implemented" sites in the subst module.** None of the
  remaining sites is reached by these shapes. `pattern_specialization`'s
  two "reference to a member of a dependent context" sites (a member of a
  non-class-pattern parent, or a still-dependent specialization) were not
  reached by any probe.
- **Tests.** `temp.dep.type/member-qualifier-relookup-alias-run.cpp`,
  `temp.dep.type/member-qualifier-relookup-ambiguous.cpp`,
  `temp.dep.type/member-qualifier-ambiguous-typename.cpp`,
  `class.friend/friend-member-of-specialization-run.cpp`,
  `over.match.class.deduct/guide-member-of-specialization.cpp`
  (`requires: clang>=22`), and the xfail
  `class.friend/friend-member-dependent-signature-run.cpp`.
- **Follow-ups.** A dependent-type friend of a non-template class's member
  (`friend int B::f(W<T>&);`) is matched when the template is defined and
  rejected (the xfail above). The implicit guide note omits the guide's
  requires-clause (clang 22 prints it). `friend class B<T>::In` where
  `B<A>::In` is an alias says `no class named 'In'`; clang says `type
  alias 'In' cannot be referenced with the 'class' specifier`
  (`dependent_tag_name`).
