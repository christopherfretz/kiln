# WP-756 — correctness bundle 3: pre-C++17 noexcept, GNU noreturn on friends and lambdas, predefined names

Three findings of WP-750 (WP-751, WP-752, WP-753), each a change of
type identity, ABI or program output, or code clang rejects.

## Changes

- **Before C++17 `noexcept` is not part of the function type**
  ([except.spec]/1 pre-P0012; clang `ASTContext::getFunctionType` with
  `NoexceptInType` false; WP-751). The representation and the rule are in
  spec/types.md §5.4: the canonical type has no specification, the
  written one survives as sugar (`exc_protos`, `proto`, `exc_pointee`),
  template arguments are converted without it (`without_exc_sugar` in
  `check_template_arg`, `record_deduction` and the call-argument
  resugaring), and redeclarations compare it through `exc_identity`
  (`same_type_and_exc` in decl.rs). Mangling, `typeid`, `is_same`,
  overloading and template-argument identity follow the canonical type;
  `noexcept(p())`, the can-throw analysis (`callee_can_throw`,
  `member_call_can_throw`) and codegen's `nounwind` on a call through a
  pointer or member function pointer read the written pointee.
  Tests: `tests/conformance/except.spec/ir-noexcept-mangling-cxx11.cpp`,
  `ir-noexcept-mangling-cxx14.cpp`, `ir-noexcept-mangling-cxx17.cpp`,
  `ir-noexcept-indirect-call-cxx14.cpp`, `noexcept-not-in-type-cxx14.cpp`,
  `typeid-noexcept-cxx14-run.cpp`, `typeid-noexcept-cxx17-run.cpp`,
  `tests/conformance/dcl.fct.def.general/predefined-noexcept-instantiated-cxx14-run.cpp`.
- **A specialization's deferred exception specification is resolved in
  templates too** ([except.spec]/13, [temp.inst]/14; clang
  `ResolveExceptionSpec` on any `DeclRefExpr`). `resolve_exc_for_type`
  and `exc_spec_needed` resolved it only outside templates, so
  `decltype(&h<true>)` lost `noexcept` in a template body, a template
  parameter's type or a default template argument (spec/types.md §5.4).
  Tests: `tests/conformance/except.spec/noexcept-resolved-in-template.cpp`,
  `noexcept-resolved-in-template-run.cpp`.
- **A friend declaration keeps GNU `noreturn` and `nothrow`**
  ([class.friend], spec/types.md §5.4 `noreturn`; clang applies type
  attributes in `GetTypeForDeclarator` for every declarator; WP-752).
  The friend path (`class/friend.rs`) applies the declaration's and the
  declarator's GNU type attributes to the function type as
  `act_on_declarator` does, so calls through the friend and through a
  later redeclaration are `noreturn` calls followed by `unreachable`, and
  falling off a function that calls one is not `-Wreturn-type`.
  Tests: `tests/conformance/dcl.attr.noreturn/gnu-noreturn-friend-redecl.cpp`,
  `ir-gnu-noreturn-friend-redecl.cpp`.
- **Lambda-declarator attribute placement** ([expr.prim.lambda.general]/1,
  [dcl.fct]/1; clang `ParseLambdaExpressionAfterIntroducer` and
  `ParseLambdaSpecifiers`): C++11 attributes may precede the parameter
  clause (appertaining to the call operator); GNU and `__declspec`
  attributes follow `)` (or the introducer when there is no parameter
  clause), before the lambda specifiers. A GNU attribute after the
  specifiers or the noexcept-specifier, or between the introducer and
  `(`, ends the declarator: "expected body of lambda expression". An
  attribute-specifier-seq after the specifiers, the noexcept-specifier or
  the trailing return type appertains to a type (type-position
  attributes), where a declaration attribute is an error ("'noreturn'
  attribute cannot be applied to types").
  Tests: `tests/conformance/expr.prim.lambda/noreturn-attr-placement.cpp`,
  `noreturn-attr-placement-errors.cpp`,
  `noreturn-attr-placement-gnu-scoped.cpp` (clang 22),
  `noreturn-attr-placement-gnu-scoped-19.cpp` (clang 19).
- **`noreturn` lambdas** (clang `err_noreturn_lambda_has_return_expr`,
  `CheckFallThroughForBody`): falling off the end of a lambda whose call
  operator is `noreturn` (GNU or `[[noreturn]]`) is the error "lambda
  declared 'noreturn' should not return" (not
  `-Winvalid-noreturn`), and a `return` statement in one whose call
  operator *type* is GNU `noreturn` is the same error at the `return`;
  `[[noreturn]]` is a declaration attribute and does not make `return`
  an error. The fall-off check is skipped once the body has an error.
  New diagnostic `sema_noreturn_lambda_has_return_expr`.
  Tests: `tests/conformance/dcl.attr.noreturn/lambda-noreturn-falloff.cpp`,
  `lambda-noreturn-falloff-cxx11-attr.cpp`, `lambda-noreturn-return.cpp`.
- **Predefined names** ([dcl.fct.def.general]/8; clang
  `PredefinedExpr::ComputeName`; WP-753). A function, function pointer
  or member pointer template argument prints in `__PRETTY_FUNCTION__`'s
  ` [T = ...]` list as clang prints the type (`void (*)() noexcept`,
  nothing for a potentially-throwing one); that half was already fixed on
  main by WP-730's canonical argument printing and is now pinned by run
  tests. A member template's parameters re-created at instantiation keep
  the implicit flag (`templ/member.rs` `param_list`), so an instantiated
  generic lambda's invented parameter prints `auto` in the signature
  (`operator()(auto)`, `v:auto` in the list), not `v:auto`. The
  partial-specialization scope chain prints its arguments scoped when the
  specialization's are (`write_arg_list_prefix_scoped`, dump/names.rs).
  Tests: `tests/conformance/dcl.fct.def.general/predefined-noexcept-args-run.cpp`,
  `predefined-noexcept-instantiated-run.cpp`,
  `predefined-noexcept-instantiated-cxx14-run.cpp`,
  `predefined-partial-spec-scopes-run.cpp` (clang 22).
