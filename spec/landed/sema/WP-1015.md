# WP-1015 — accepts-invalid fixes, part 2: declaration rules

These are the five declaration-rule clusters of WP-912's clang negative-test run (docs/status/accepts-invalid.md, triage items 2-6). It closes WP-949, WP-950, WP-951, WP-952 and WP-953. Every new error follows clang 19's wording, location and recovery, and is paired with a valid form that must keep compiling. The contract is spec/sema.md §4.4.1. All 15 seed repros flipped from xfail; no xfail was added.

- **WP-949, members named as their class** (`class/member_name.rs`).
  - A static data member, member type, member template, unscoped enumerator or using-declaration named as its class is "member 'X' has the same name as its class" (clang `DiagnoseClassNameShadow`).
  - A non-static data member is reported only when the class has a user-declared constructor, once, as the definition completes.
  - Tests: `class.mem/member-named-as-class{,-ok}.cpp`, `class.mem/static-member-named-as-class.cpp`.
- **WP-950, allocation functions and `main`** (`alloc_decl.rs`, `main_decl.rs`).
  - `operator new`/`delete`: namespace scope, `static` at global scope, return type (dependent or not), template arity, first parameter type (dependent or not; clang 19's "first parameter" wording via `_19` rows), default argument on the first parameter (clang `CheckOperatorNew/DeleteDeclaration`). Destroying and type-aware forms are not checked.
  - `main`: parameter forms and count, template, deleted, not overloaded, a global (or block-scope `extern`) variable named `main`. All off under `-ffreestanding`, which the driver now passes to sema.
  - Tests: `basic.stc.dynamic/new-delete-*.cpp`, `basic.start.main/*.cpp`.
- **WP-951, unions, static data members, bit-fields** (`class/member_rules.rs`).
  - A second initializer for a static data member initialized in-class ([class.static.data]/4) is reported at the new initializer with a note and dropped.
  - A second variant member with a default member initializer (CWG1460), anonymous members included, with a note at the first.
  - Virtual functions in a union; qualifiers on an anonymous bit-field.
  - Tests: `class.static.data/initializer-*.cpp`, `class.union/*.cpp`, `class.bit/anonymous-bit-field-qualifiers*.cpp`.
- **WP-952, redeclarations** (`overload/redecl.rs`, `class/member_rules.rs`, `using.rs`).
  - Mixing ref-qualified and unqualified overloads ([over.load]/2.3) before C++23; from C++23 such a pair with matching cv-qualifiers is a member redeclaration. The virtual-override form (CWG2496) reports once per base function.
  - A member tag redeclared in its class (`-Wredeclared-class-member`), a qualified member tag (extra qualification or an error), a repeated dependent using-declarator ([namespace.udecl]/10).
  - Tests: `over.load/ref-qualifier-*.cpp`, `class.virtual/override-ref-qualifier-*.cpp`, `class.mem.general/member-*tag*.cpp`, `dcl.meaning/qualified-member-tag*.cpp`, `namespace.udecl/dependent-using-*.cpp`.
- **WP-953, default arguments, block-scope `inline`, lambda shadowing, friend template defaults**.
  - [dcl.fct.default]/3: a default argument on a declarator that is not the function declaration's own clause is dropped with clang's "default arguments can only be specified for parameters in a function declaration". The parser calls `act_on_nonfunc_default_arg`; exception-declarations are skipped (as clang, `Parser::in_exception_decl`).
  - [dcl.fct.default]/8-9: `this` (even unevaluated), a capturing lambda, and an odr-use of a local variable. The local check runs after conversion of the full-expression (clang's visitor runs then too), so a constant read by value stays valid. In a template definition, where kiln does not mark non-odr-uses, the constant uses are computed from the potential results.
  - [dcl.inline]/5: `inline` on a block-scope function declaration (non-member).
  - [expr.prim.lambda.capture]/5: a lambda parameter named as an explicit capture, with the "explicitly captured here" note.
  - [temp.param]/12: a default template argument on a friend template that is not a function template definition, at each defaulted parameter; skipped for a friend class template in a dependent context, as clang. The written default stays in the AST but no longer counts for the redeclaration rules.
  - Tests: `dcl.fct.default/{local-entity,nonfunction-declarator}-default-arg*.cpp`, `dcl.fct.spec/inline-block-scope-*.cpp`, `expr.prim.lambda.capture/param-shadows-capture*.cpp`, `temp.param/friend-template-default-arg*.cpp`.

## Not done

- clang's `-Wmain` warnings (no group yet); a friend class template in a local class is not diagnosed; clang's follow-on "reference to 'w' is ambiguous" after an init-capture is shadowed; a braced default argument is not searched by the `this`/parameter check.
- Reported only at instantiation by clang and not by kiln: a ref-qualifier mix in a class template's member list.

## Interface changes

- `kiln_parse::ParseOptions::freestanding` and `kiln_sema::Sema::freestanding` (set from `-ffreestanding` by both driver paths).
- `kiln_ast::decl::FieldData::HAS_DEFAULT_INIT` (bit 16): a default member initializer was written, known before it is parsed.
- `Sema::act_on_nonfunc_default_arg(&mut ParamInfo, Loc)`, called by the parser's parameter clause.
- New diagnostics at the tail of the table; no existing row changed.
