# WP-891 — attribute correctness and the dangling-walk gaps

Closes WP-889, WP-890, WP-878, WP-839, WP-874, WP-875 and WP-876, each
matched against clang 19 (clang 22 where the behaviour differs). WP-877
(clang 20+/22 lifetime parity) is untouched.

- **WP-889, `[[__clang__::x]]`** (spec/parse.md §6.2 "Attribute
  scopes"): `__clang__` expands to `1` before the parser sees it; a
  number whose expansion is spelled `__clang__` is read as the `_Clang`
  scope with clang's `'__clang__' is a predefined macro name, not an
  attribute scope specifier` [-Wignored-attributes] and a fix-it, in a
  scope, a name position and a `using` prefix. Tests:
  `dcl.attr.grammar/clang-scope-predefined-macro{,-silenced}.cpp`.
- **WP-890, mutual exclusions** (spec/sema.md §4.5 "Mutual
  exclusions"). clang 19 Attr.td `MutualExclusions`, by outcome:
  - added (errors): `hot`/`cold`, `no_destroy`/`always_destroy`;
  - already checked: `likely`/`unlikely`, `naked`/`disable_tail_calls`,
    `always_inline`/`not_tail_called`, `Owner`/`Pointer`,
    `speculative_load_hardening`/`no_speculative_load_hardening`,
    `optnone` with `always_inline`/`minsize`, the `target` family;
  - not applicable to C++ on kiln's targets: `common`/`internal_linkage`
    (`common` is C only), `randomize_layout`/`no_randomize_layout`,
    CUDA host/device/global/shared/constant, Mips16/MicroMips/interrupt,
    Objective-C direct/designated;
  - not implemented (class C, accepted silently): `cf_audited_transfer`/
    `cf_unknown_transfer`.
  Test: `dcl.attr.grammar/mutually-exclusive-attributes.cpp`.
- **WP-890, asm in constexpr functions** (spec/sema.md §5.20): kiln
  already accepted `asm` in a C++20 constexpr body and failed its
  evaluation, as clang does; added clang's pre-C++20 extension warnings
  for an asm or try-block statement and a function-try-block. Tests:
  `dcl.constexpr/constexpr-asm-{evaluated,try-cxx17}.cpp`, and the xfail
  `constexpr-asm-never-constant.cpp` (the IFNDR never-constant error for
  a function with parameters).
- **WP-878, GNU attribute recovery** (spec/parse.md §6.2): a malformed
  `__attribute__((...))` list ends at the first non-name and reports each
  missing `)` as `expected ')'` without a `to match this '('` note. Test:
  `dcl.attr.grammar/gnu-attribute-list-recovery.cpp`.
- **WP-839**: kiln's IR was right; clang 19 differs from 22 only in the
  AArch64 datalayout and `frame-pointer`, so
  `dcl.attr/ir-used-retain-aligned.cpp` now `requires: clang>=22` with a
  `-19` sibling.
- **WP-874/875/876, dangling walk** (spec/sema-class.md §5.4 "Lifetime
  analysis"):
  - default member initializers: in an aggregate variable initializer,
    clang 19's `lifetime extension ... is not yet supported` under
    `-fclang-compat=19` and silent extension at 20+; in a constructor
    (implicit, user-provided, or a member's aggregate mem-initializer)
    the `would be shorter` error at the constructor;
  - new-initializers (`LK_New`): `temporary bound to reference member of
    allocated object` and the two `array backing ... allocated` forms;
  - base mem-initializers judged member by member; delegating ones not
    checked (as clang);
  - implicit variables: the range-for `__range` (skipped under P2718 at
    compat 22, as clang 22) and structured-binding holding variables,
    with the implicit wordings and notes;
  - GNU `?:`: only the false operand is walked (the common operand is
    opaque, as in clang); compound literals and clang 19's
    parenthesized aggregate initialization already matched and are
    pinned.
  Tests: `class.temporary/dangling-default-member-init{,-19}.cpp`,
  `class.temporary/dangling-compound-literal.cpp`,
  `class.base.init/dangling-default-member-init-ctor.cpp`,
  `class.base.init/dangling-base-mem-init.cpp`,
  `expr.new/dangling-new-expression.cpp`,
  `stmt.ranged/dangling-range-init{,-19,-cxx20}.cpp`,
  `dcl.struct.bind/dangling-holding-variable.cpp`,
  `expr.cond/dangling-gnu-binary-conditional.cpp`.

Follow-ups:
- `coro_lifetimebound` needs the coroutine attributes promoted out of
  class C (`crates/kiln_sema/src/attr_triage.rs:167-170`).
- `-fclang-compat=19` builds the structured-binding `tuple_element`
  index as an unconverted `size_t` value, so a user `tuple_element`
  declared with an `unsigned` index misses its explicit specialization
  (rejects-valid; `crates/kiln_sema/src/struct_bind.rs:673`).
  xfail: `dcl.struct.bind/tuple-element-unsigned-index-19.cpp`.
- The never-constant check for constexpr functions only tries
  parameterless functions (`crates/kiln_sema/src/constexpr_body.rs:59`;
  xfail above).
- Non-breakages (wording or missing warnings): `[[clang::warn_unused_result]]`
  is ignored (`crates/kiln_sema/src/attr_triage.rs:343`) and the `gnu::`
  spelling's message says `nodiscard` (`crates/kiln_sema/src/decl.rs:11409`);
  `noinline` on a variable lacks clang's message
  (`crates/kiln_sema/src/class_b_attrs.rs:1127`); the condition of
  `&k ?: nullptr` lacks `-Wpointer-bool-conversion`
  (`crates/kiln_sema/src/null_compare.rs:218`).
