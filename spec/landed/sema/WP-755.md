# WP-755 — contracts (P2900R14) part 3: the sema gaps and coroutine postconditions

Closes the gaps spec/contracts.md §9 listed after WP-707 (the WP-731
follow-ups) and the coroutine postcondition (WP-744). The target is the
Croydon DIS; GCC 16.1 is the oracle where it follows the wording, and
§9 records each place kiln follows the wording instead.

## Changes

- **Lambdas in a predicate capture the function's parameters and result
  binding** ([expr.prim.lambda.capture]/3.3, [basic.pre]/9,
  [expr.prim.id.unqual]/7; spec/contracts.md §5). Explicit captures,
  `[=]` and `[&]`, by copy and by reference; the captures are const as
  the names are. Sema (`kiln_sema/src/lambda/capture.rs`), the Oven
  (`kiln_oven/src/compile.rs`) and codegen (`kiln_codegen/src/expr.rs`).
  Tests: `tests/conformance/basic.contract/lambda-capture-params.cpp`,
  `tests/conformance/basic.contract.eval/run-lambda-capture.cpp`.
- **Explicit specializations have their own seq** ([temp.expl.spec]/12,
  [dcl.contract.func]/4-5; spec/contracts.md §4, §5). `Ast::contract_first`
  skips the implicit declaration an explicit specialization's chain
  starts with, so a redeclaration that adds or changes the seq is
  diagnosed and the first written declaration's seq is checked.
  Tests: `tests/conformance/dcl.contract.func/p4-explicit-spec.cpp`,
  `tests/conformance/basic.contract.eval/run-explicit-spec.cpp`.
- **Friend redeclarations without a seq** are checked against the
  postcondition-parameter const rule ([dcl.contract.func]/7;
  `kiln_parse/src/class.rs` `check_friend_without_contracts`).
  Test: `tests/conformance/dcl.contract.func/p7-friend-redecl.cpp`.
- **The dump prints a result binding's type as written** (`'const T'`
  in a pattern; spec/contracts.md §4). Golden:
  `tests/conformance/dcl.contract.func/dump-lambda-template.cpp.expected`.
- **No spurious "control reached end of constexpr function"**: the
  postcondition-parameter const rule no longer invalidates the
  parameter, so the body keeps its return statement (spec/contracts.md
  §5, §9). Test: `tests/conformance/basic.contract.eval/ignore-error-recovery.cpp`.
- **Coroutine postconditions** (P2900R14 §3.5.2,
  [dcl.fct.def.coroutine]/7, [dcl.contract.res]/1; spec/contracts.md
  §6.2): evaluated once, when the coroutine first returns to its caller,
  on the return object. Codegen checks them in the return block, which
  follows `llvm.coro.end`, so only the ramp reaches it; the
  `unsupported` error is gone. The Oven never evaluates a coroutine.
  Tests: `tests/conformance/basic.contract.eval/run-coroutine-post-{observe,enforce,quick-enforce,ignore}.cpp`
  (compared with GCC 16.1), `crates/kiln_codegen/tests/contracts.rs`
  `coroutine_precondition_and_postcondition`.
- **Virtual functions**: the rejection stays, now on the DIS's
  [dcl.contract.func]/6 ("A virtual function ... shall not have a
  function-contract-specifier-seq"); P3097 lifts it for C++29 (§9).

  observe 0.23 s, ignore 0.14 s, without contracts 0.14 s; 12-13 MiB

  13 MiB). Unchanged.
- `tests/stress/contracts-lambda-capture-1e5.cpp` (new): 1e5 calls whose
  `pre` and `post` each call a capturing lambda. enforce and observe

  reclaimed at once: Oven peak 24 bytes, no allocations; the budget pins
  `peak_bytes<=64`.
