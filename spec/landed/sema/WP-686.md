# WP-686 — abseil-cpp through its own build and tests (M8 wave 1b)

abseil-cpp LTS 20260107.1 built with kiln++ through its own CMake build
with `ABSL_BUILD_TESTING=ON` and `ABSL_USE_GOOGLETEST_HEAD=ON`, and run
with CTest (docs/status/oss/abseil.md). Each behaviour below is a kiln
bug the build found, reduced to a standalone test; the rule is stated in
the spec named.

## Changes

- **An object of the current instantiation's type names member
  templates** ([temp.dep.type]/1.2, [temp.names]/3.2; spec/sema.md).
  Inside class template `X`, a member access on an object of type
  `X<P...>` (or `X<P...> *`) looks the name up in the current
  instantiation, so `copy.DivMod<10>()` starts a template argument list
  without `template`.
  Test: `tests/conformance/temp.dep.type/p1-current-instantiation-object-member-template-run.cpp`.
- **Implicit nullability of the standard smart pointers** (clang
  extension, `_Nullable`/`_Nonnull` on a class type; spec/sema.md). As
  clang's `inferNullableClassAttribute`, `std::auto_ptr`,
  `coroutine_handle`, `exception_ptr`, `function`, `move_only_function`,
  `shared_ptr` and `unique_ptr` (directly in `std`, inline namespaces
  skipped) are nullable, so `_Nonnull std::unique_ptr<int>` is valid.
  Test: `tests/conformance/dcl.type.class/nullability-std-smart-pointers.cpp`.
- **A UTF-8 string literal is an array of `char` before C++20**
  ([lex.string]/8 as of C++17; P0482; spec/sema-conv.md). WP-691 landed
  the same rule first (`string_literal_elem`); the merge keeps its code
  and this test.
  Test: `tests/conformance/lex.string/u8-literal-char-before-cxx20-run.cpp`.
- **`&N::m` through a dependent base forms a pointer to member**
  ([expr.unary.op]/3; spec/sema-templates.md). Inside a class template
  with a dependent base, `N::m` of a class `N` that `*this` may derive
  from is kept as `this->N::m` until instantiation; as the operand of
  `&` it is the qualified name itself. Overload sets remain a gap.
  Test: `tests/conformance/expr.unary.op/p3-qualified-member-unrelated-class-dependent-base-run.cpp`.
- **A parenthesized member callee** ([expr.call]/1; spec/ast.md):
  `(o.f)()` finds its implied object argument through the parentheses;
  constant folding panicked on it (abseil's random tests, `(g.min)()`).
  Test: `tests/conformance/expr.call/p1-parenthesized-member-callee-run.cpp`.
- **`__has_builtin` answers 0 for clang 22 builtins kiln does not
  declare** ([cpp.cond]; spec/pp.md). At `-fclang-compat=22` the
  feature table advertised clang-22-only `__builtin_*` functions that
  kiln never declares (`__builtin_infer_alloc_token`).
  Test: `tests/conformance/ext.gnu.builtins/has-builtin-undeclared-clang22-builtin.cpp`.
- **A user-provided move operation is not default-movable**
  ([class.prop], `__builtin_is_cpp_trivially_relocatable`;
  spec/sema-templates.md). The implicit copy operation stands in only
  when the move operation is not user-declared.
  Test: `tests/conformance/ext.traits/is-cpp-trivially-relocatable-user-move.cpp`.
- **Value-dependent array bounds mangle as `A <expression> _`**
  ([temp.over.link]/1, Itanium C++ ABI `<array-type>`; spec/abi.md).
  `f(const T (&)[sizeof(T)])` overloads for `char` and `wchar_t`
  mangled alike, so one silently replaced the other at link time (a
  miscompile in `absl_log_format_test`).
  Tests: `tests/mangle/dependent_array.cpp`,
  `tests/conformance/temp.over.link/dependent-array-bound-overloads-distinct-run.cpp`.
- **Inherited constructors convert in implicit conversion sequences**
  ([namespace.udecl]/13, [over.best.ics]/4, [class.conv.ctor];
  spec/sema-overload.md). A constructor inherited by a
  using-declaration is a converting constructor of the derived class
  in a user-defined conversion (abseil's hash-container `=` tests).
  Test: `tests/conformance/namespace.udecl/p13-inherited-ctor-implicit-conversion-run.cpp`.
- **A base-specifier's class-name is a type-only lookup**
  ([class.derived.general]/2; spec/parse.md). A data member or
  function named like a base class template no longer hides it
  (abseil `btree`).
  Test: `tests/conformance/class.derived/p2-base-class-name-type-only-lookup-run.cpp`.
- **Class-scope `operator new` templates are allocation candidates**
  ([expr.new]/19-20, [temp.over]/1; spec/sema-overload.md). When no
  non-template class `operator new` matches, its function templates go
  through overload resolution with `(size_t[, align_val_t],
  placement...)`, and the deduced specialization is instantiated on
  use. A placement `operator delete` template is not matched.
  Test: `tests/conformance/expr.new/class-operator-new-template-run.cpp`.
- **The injected-class-name of a base class template specialization
  names that specialization** ([temp.local]/1-2, [class.qual]/2;
  spec/parse.md). `B`, `D::B` and `typename D::B` for
  `struct D : B<int>` are the type `B<int>` when no `<` follows
  (`Sema::inherited_injected_class`). As a nested-name-specifier
  component (`D::B::m`) it is not handled yet.
  Test: `tests/conformance/temp.local/p2-base-specialization-injected-name-run.cpp`.
- **Class template allocation functions are instantiated on use**
  ([temp.inst]/11, [basic.def.odr]/7; spec/sema-overload.md). The
  matching deallocation function of a new-expression and the
  deallocation function of a delete-expression are odr-used at the
  expression, so a member `operator delete` of a class template
  specialization is instantiated (abseil's
  `exception_safety_testing_test` failed to link).
  Test: `tests/conformance/temp.inst/class-template-allocation-functions-instantiated-run.cpp`.

## Not in this WP

- `absl_statusor_test` (two runtime failures) was fixed by WP-683's
  `9825ed31c` (a dependent template-id call keeps its definition's
  namespace-scope lookup). With it merged, all 232 abseil tests pass.
