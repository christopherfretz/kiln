# WP-801 — clang and lld 19 built by kiln: frontend fixes

Fixes found building LLVM 19.1.7 with `LLVM_ENABLE_PROJECTS=clang;lld`
(the `llvm/` tree, clang, lld, the AArch64 and X86 backends and both
projects' unit tests) with kiln++ as the OSS project `llvm_clang`
(docs/status/oss/llvm_clang.md). Each is pinned by a test that also
passes under clang 19.

## Changes

- **`friend class X;` finds `X` in a base class's scope**
  ([dcl.type.elab]/4, [class.friend]/2; `kiln_sema/src/decl.rs`
  `act_on_friend_tag`). The lookup of an unqualified elaborated friend
  stops at the innermost enclosing namespace, but it searches the class
  scopes on the way, base classes included. kiln skipped the bases. It
  missed the injected-class-name of a private base specialization and
  declared a new class instead, so the base was not befriended. LLVM's
  `friend class TrailingObjects;` is written this way, and about 500
  clang TUs failed with `cannot cast to its private base class`. Spec:
  spec/sema-class.md (friend lookup).
  Test: `tests/conformance/dcl.type.elab/friend-class-found-in-base-class-scope-run.cpp`.
- **[expr.cond]/6 built-in `operator?:` candidates**
  ([expr.cond]/6, [over.built]/25-26). `b ? ref : (F *)nullptr` with
  `operator const F *()` (clang's `PPDirectives.cpp`) needs the built-in
  candidate step. WP-787 landed the same step on main concurrently
  (`kiln_sema/src/expr.rs` `act_on_conditional`,
  `overload/builtin.rs` `add_conditional_builtin_candidates`); the merge
  keeps main's implementation and WP-801's tests pass on it. Arms of one
  class that differ only in cv-qualification never reach the step, so
  `c ? DB() << x : DB()` with `operator bool` stays a `DB` (clang's
  `Parser.cpp`; spec/sema-templates.md, *[expr.cond]/6 cv-only differing
  class arms*).
  Tests: `tests/conformance/expr.cond/p6-builtin-candidates-convert-class-arm-run.cpp`,
  `p6-builtin-candidates-ambiguous.cpp`,
  `p4-cv-differing-class-arms-not-builtin-run.cpp`.
- **A using-directive and a namespace alias look up namespace names
  only** ([namespace.udir]/1, [namespace.alias]/1;
  `kiln_sema/src/using.rs` `lookup_namespace_name`,
  `kiln_parse/src/decl.rs` `parse_using_attrs`). `using namespace
  index;` now finds `clang::index` although the global function `index`
  from `<strings.h>` hides it for ordinary lookup (clang's `lib/Index`).
  Spec: spec/sema.md (Namespace aliases).
  Test: `tests/conformance/namespace.udir/p1-function-does-not-hide-namespace-run.cpp`.
- **A placement `new` argument converts derived-to-base pointer**
  ([expr.new]/19, [conv.ptr]/3; `kiln_sema/src/new_delete.rs`
  `placement_arg_match`). `new (C) T` where `C` is an `ASTContext`-derived
  pointer and the allocation function takes `const ASTContext *` matched
  no candidate (clang's `AST/Decl.cpp`). The match is not exact, and it
  is not ranked against a `void *` candidate by [over.ics.rank] (a gap
  in spec/sema-overload.md, operator new).
  Test: `tests/conformance/expr.new/p19-placement-arg-derived-to-base-pointer-run.cpp`.
- **A dependent qualified member template-id keeps its qualifier**
  ([temp.names]/3, [basic.lookup.qual]/1; `kiln_sema/src/templ/funcs.rs`
  `act_on_member_template_args`). `this->Base::getObj<T>()` in a class
  template dropped `Base::` from the dependent member expression, so instantiation looked `getObj` up in the derived class
  and found a non-template (lld's `ELF/InputFiles.h`). Spec:
  spec/sema-templates.md (member template-ids; the parse gap
  `(*this).Base::g<T>()` is listed there).
  Test: `tests/conformance/temp.names/p3-qualified-member-template-id-dependent-args-run.cpp`.
- **A qualified namespace-scope definition redeclares a hidden friend**
  ([dcl.meaning.general]/2.3, [namespace.memdef]/3;
  `kiln_sema/src/decl.rs` `find_prev_function`). A function first
  declared by a friend declaration is a member of the namespace, invisible
  to qualified lookup but nominable there, so `void N::f(C &) {}` after
  `friend void f(C &);` in `N::C` redeclares the friend instead of
  failing to match (clang's `unittests/Basic/DiagnosticTest.cpp`,
  `clang::DiagnosticsTestHelper`). Only the hidden friends are added: a
  declaration ordinary qualified lookup found was already considered and
  filtered (the clang 19 missing-`typename` rule stays). Spec:
  spec/sema-class.md ([dcl.meaning.general]/2).
  Test: `tests/conformance/dcl.meaning/qualified-definition-of-hidden-friend-run.cpp`.
- **`&Class::f<Args>` in a template keeps its qualifier**
  ([expr.unary.op]/3; `kiln_sema/src/templ/subst/exprs.rs`
  `respecialized_member_template`). Instantiating a qualified member
  template specialization dropped the nested-name-specifier, so
  `&Self::checkIntersectImpl<const APSInt &>` formed an ordinary function
  pointer instead of a pointer to member (clang's
  `unittests/StaticAnalyzer/RangeSetTest.cpp`). Spec:
  spec/sema-templates.md (qualified overload sets, WP-801 sentence).
  Test: `tests/conformance/expr.unary.op/p3-member-template-specialization-pointer-to-member-in-template-run.cpp`.
- **A volatile read in an unused internal variable's initializer is a
  side effect** ([intro.execution]/7, [basic.start.dynamic];
  `kiln_codegen/src/global_init.rs` `may_have_side_effects`). An
  lvalue-to-rvalue conversion of a volatile glvalue makes the
  initializer side-effecting, so `static int D = S;` with `extern
  volatile int S;` is emitted although nothing uses `D`. kiln dropped it,
  so LLVM's anchor idiom no longer pulled `JSONCompilationDatabase.o` out
  of `libclangTooling.a` and `clang-check` found no JSON compilation
  database (check-clang `Index/skip-parsed-bodies`, `Tooling/*`). Spec:
  spec/codegen.md (emission pipeline, step 1).
  Test: `tests/conformance/basic.start.dynamic/unused-static-volatile-read-init-ir.cpp`.
- **A local entity of a unique-external specialization is internal**
  ([basic.link]/8; `kiln_abi/src/mangle.rs` `has_internal_linkage`,
  `tag_externally_visible`). A lambda, a local class's member and a
  static local of `f<(anonymous)::A>` take the specialization's linkage,
  template arguments included. kiln checked only the function's own
  internal linkage and emitted them `linkonce_odr`; two TUs instantiating
  `checkDataflow<(anonymous)::ConstantPropagationAnalysis>` (clang's
  `unittests/Analysis/FlowSensitive`) had their lambdas merged, and one
  TU's `std::function` ran the other's lambda (an `llvm::any_cast`
  assertion, and unbounded memory growth). Spec: spec/abi.md §8.10.
  Test: `tests/conformance/basic.link/local-entity-of-internal-specialization-ir.cpp`.
- **An initializer-list constructor call in a template keeps its list**
  ([dcl.init.list]/3.7, /5, [over.match.list]/1.1;
  `kiln_sema/src/templ/subst/exprs.rs` `construct_list`). Instantiating
  `const V v = {{"check.h", H1}, {"othercheck.h", H2}}` rebuilt the
  `std::initializer_list` construct as a list holding the argument
  (`{{...}}`). That one-element list initialized one pair from the two
  inner lists, the second `std::string` through its iterator-pair
  constructor from two pointers into different strings, so clang's
  `ChromiumCheckModelTest.*` threw `std::bad_alloc` under the test
  `ulimit`. The list is now the one the argument was built from, as
  clang's `TransformInitializer` unwraps it. Spec:
  spec/sema-templates.md (analyzed initializations as operands).
  Test: `tests/conformance/dcl.init.list/initializer-list-ctor-in-template-keeps-list-run.cpp`.
- **Fixed on main during the WP:** `return {a, b};` disabling NRVO
  (WP-799, the `InterfaceStubs/*` check-clang failures) and the clang
  `ToolingTests` `InterpolateTest.*` failures (an object compiled by
  run 3's kiln++ fails, the same object from the merged tree passes).
  WP-799's `@rsp` link fix brought `libclang-cpp.so` back.

## Harness

`scripts/oss/projects.toml` gains the `llvm_clang` row. It builds
`all clang-test-depends ClangUnitTests lld-test-depends LLDUnitTests` and
runs `check-clang` then `check-lld` through make. `test_timeout` is
18000 s, and there is no `vmem_kb` override, so the wrapper's default
3000000 KB applies. The row uses WP-782's `test_timeout`, `vmem_kb` and
`lit_summary` keys (spec/landed/sema/WP-782.md, Harness).
