# WP-613 — braced aggregate initializer with an omitted array member in a template

[dcl.init.aggr]/5, [dcl.init.list]/3.4, [temp.inst]. The rule is in
`spec/sema.md` §6 (`init_from_list`, "In a templated entity") and
`spec/sema-templates.md`, "Braced lists".

- `struct S { unsigned short fam; char path[108]; };` with `S addr{};`
  (or `S addr{1};`, `= {}`, `static`, a dependent `T`) in a function
  template, a lambda in one or a member of a class template failed at
  instantiation with "cannot initialize an array element of type 'char'
  with an rvalue of type 'char[108]'", without a location. The
  definition's semantic list holds an `ImplicitValueInitExpr` of type
  `char[108]` for the omitted member; `Substituter::init_list` fed it
  back as a written clause, which brace elision turned into the
  initializer of `path[0]`. The rebuilt list now drops the trailing
  `ImplicitValueInitExpr`s along with the `CXXDefaultInitExpr`s it
  already dropped, so it is the written list again (clang's syntactic
  form) and the omitted members are value-initialized anew. Nested
  aggregates (`O o{};`, `O p{{4}};`), a member holding the array, arrays
  of the aggregate (`S arr[2]{};`, `S brr[2] = {{1}};`) and `a = {2};`
  take the same path.
- An element without a location (an implicit node) that fails to
  initialize is now diagnosed at its list's `{` instead of without a
  file:line (`init_element_at`).
- Tests: `tests/conformance/dcl.init.aggr/array-member-filler-in-template.cpp`
  (`-std=c++26`), `-cxx17.cpp`, `-cxx20.cpp` (one body,
  `Inputs/array-member-filler-in-template.h`, run tests checking the
  array contents are zero, plus a constant-evaluated instance) and
  `array-element-from-array.cpp` (a genuine array-from-array element
  error, located at the element, also in a template pattern; strict
  diagnostics, matches clang 19).
- Not changed (clang 19 and 22 behave the same; GCC 16.1 accepts): a
  parenthesized aggregate initialization `S a(1);` in a template.
