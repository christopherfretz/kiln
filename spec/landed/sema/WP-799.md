# WP-799 — duckdb and z3 through their own builds and tests (M8 wave 4)

duckdb v1.5.6 and z3 4.15.8 built with kiln++ through their own CMake
builds and test programs (docs/status/oss/duckdb.md,
docs/status/oss/z3.md). Each fixed behaviour below is a kiln bug the
build found, reduced to a standalone conformance test; the rule is
stated in the spec named.

## Changes

- **A statement expression with a class lvalue result** (GNU
  extension; spec/sema.md §5.8 "Statement expressions"). The result
  object is copy-initialized from the last expression: a class prvalue
  is kept, a class glvalue is copied by its copy (or move) constructor,
  as clang `InitializeStmtExprResult`. Codegen (`expr.rs`
  `agg_stmt_expr`) emits the statements, then the result into the
  aggregate destination, inside the statement expression's scope, so the
  copy precedes the destruction of its locals; the oven
  (`compile.rs` `stmt_expr_to`) initializes a class result object the
  same way, so a class-typed statement expression is a constant
  expression when its parts are. kiln said "a statement expression with
  a class lvalue result is not supported yet" (duckdb's bundled zstd,
  `zstd_lazy.cpp`, via `arm_neon.h`'s `vld2q_u16` macro, which ends in
  a local `uint16x8x2_t`).
  Test: `tests/conformance/ext.gnu.stmt.expr/class-lvalue-result-run.cpp`.
- **NEON structure loads and stores** (`__builtin_neon_vld{2,3,4}[q]_v`,
  `__builtin_neon_vst{2,3,4}[q]_v`, `__builtin_neon_vsli[q]_n_v`; codegen
  `neon.rs` `Shape::LdN`, `Shape::StN`, `Shape::Sli`; spec/codegen.md
  NEON). As clang 19 `EmitAArch64BuiltinExpr`: `vldN` takes the result
  pointer and the source pointer, calls
  `llvm.aarch64.neon.ldN.<VTy>.p0(ptr)` returning a literal struct of N
  `VTy`, and stores it to the result object with the struct's natural
  alignment; `vstN` takes the pointer then N vectors (bitcast to `VTy`)
  (every operand emitted first, then the bitcasts) and calls
  `llvm.aarch64.neon.stN.<VTy>.p0(v1, .., vN, ptr)`, declared with a
  `nocapture` pointer (`kiln_llvm::intrinsics::neon_store_n`); `vsli_n`
  bitcasts both operands to `VTy` and calls
  `llvm.aarch64.neon.vsli.<VTy>(a, b, i32 n)` with n checked in
  0..width-1 (`vsri_n` keeps 1..width). kiln said "code generation for
  `__builtin_neon_vld2q_v` is not supported yet" (the same zstd TU).
  Tests: `tests/conformance/target.neon/ldn-stn-sli-run.cpp`,
  `tests/conformance/target.neon/ir-ldn-stn-sli-19.cpp`.
- **An elaborated-type-specifier redeclares a hidden friend class**
  ([basic.scope.pdecl]/7, [namespace.memdef]/3; spec/sema-class.md
  "A plain reference `class X`"). After `friend class X;` in a class, a
  member `class X *p;` finds no visible `X`; it declares `X` in the same
  namespace, which redeclares the hidden friend class (clang `ActOnTag`'s
  redeclaration lookup) instead of creating a second, unrelated class.
  kiln created two classes, so the later definition was not the
  befriended one: "'m' is a protected member of 'context'" (z3's
  `smt/smt_parallel.h`, 2 TUs).
  Test: `tests/conformance/class.friend/friend-then-elaborated-member.cpp`.
- **A conditional with a class prvalue arm and a `const` class lvalue
  arm is a `const` prvalue** ([expr.cond]/4.3, /7; spec/sema-templates.md
  "[expr.cond]/4 class unification"). The arm converted to the other's
  class type now has that type with its cv-qualifiers (a `NoOp` cast, as
  clang `TryClassUnification`), so both arms are `const V` and the result
  is a `const V` prvalue. kiln stripped the `const`, and `auto &r = b ?
  f() : cref;` was "non-const lvalue reference to type 'vector<...>'
  cannot bind to a temporary" (duckdb's
  `extension/core_functions/scalar/generic/system_functions.cpp`).
  Test: `tests/conformance/expr.cond/class-prvalue-unified-const-run.cpp`.
- **[expr.cond]/6 built-in candidates** (spec/sema-templates.md
  "[expr.cond]/4 class unification"). Arms of different types, one a
  class, that /4 converts neither way now go through overload resolution
  among the built-in `?:` candidates (`overload/builtin.rs`
  `add_conditional_builtin_candidates`, `expr.rs` `conditional_overload`,
  as clang `FindConditionalOverload`), and both arms are converted to
  the best candidate's parameter types. New diagnostic
  `sema_conditional_ambiguous_ovl` (clang
  `err_conditional_ambiguous_ovl`). kiln said "incompatible operand
  types ('const expr_ref' and 'app *')" (z3's `api/api_solver.cpp`:
  `s.guard ? s.guard : m.mk_true()`).
  Tests: `tests/conformance/expr.cond/p6-builtin-candidates-run.cpp`,
  `tests/conformance/expr.cond/p6-builtin-candidates-errors.cpp`.
- **Response files** (spec/driver.md "Response files";
  `kiln_driver::rsp`). `@file` arguments are expanded as clang's driver
  does (GNU tokenizer, nested, an unreadable file left as written). kiln
  said "no such file or directory: '@CMakeFiles/shell.dir/objects1.rsp'"
  when CMake linked z3's `shell` and `test-z3` through response files.
  Tests: `kiln_driver` unit tests `rsp::tests`, and
  `tests/conformance/driver.response.file/response-file-run.cpp`.
- **A thrown class object's destructor is odr-used** ([except.throw]/5;
  spec/sema.md §5.5). A throw-expression of class type with a
  non-trivial destructor marks it referenced (clang
  `CheckCXXThrowOperand`), so an implicit destructor is defined in the
  TU. kiln passed `__cxa_throw` the complete-object destructor of a class
  whose implicit destructor nothing else in the TU used, leaving it
  undefined: z3's `catch (z3_error & ex) { throw ex; }` (in
  `factor_tactic.cpp` and three more TUs) failed to link `shell` with
  "undefined reference to `z3_error::~z3_error()`".
  Test: `tests/conformance/except.throw/rethrow-copy-implicit-dtor-run.cpp`.
- **A generic lambda's conversion odr-uses the call operator
  specialization** (spec/sema-lambda.md §3.2;
  `lambda/mod.rs` `define_lambda_conversion`). The invoker specialization
  forwards to `operator()<Args>`; kiln marked only the call operator
  template, so with a written return type (nothing else instantiates the
  specialization) it was left undefined: z3's
  `alloc(dependent_expr_state_tactic, m, p, [](auto& m, auto& p, auto &s)
  -> dependent_expr_simplifier* { ... })` in a dozen tactic headers
  failed to link `shell` ("undefined reference to `...::{lambda(auto:1&,
  auto:2&, auto:3&)#1}::operator()<...>`").
  Test: `tests/conformance/expr.prim.lambda.closure/generic-conversion-explicit-return-run.cpp`.
- **A `return` of a braced-init-list disables NRVO** (spec/sema-class.md
  §5.5; `forms.rs` `act_on_return_list`). It now updates the scopes'
  return slots with no candidate, as clang `BuildReturnStmt` calls
  `updateNRVOCandidate(nullptr)` for every return. kiln left a named local
  returned on another path as the NRVO variable, so the braced return
  constructed into the return slot over the live local, whose destructor
  then ran on the returned object: duckdb's `Catalog::TryLookupEntry`
  (`return {nullptr, nullptr, ErrorData(except)};` beside `return
  result;`) aborted `unittest` with "double free" in "Test errors in C
  API".
  Test: `tests/conformance/class.copy.elision/nrvo-disabled-by-braced-return-run.cpp`.
