# WP-954 — clang attribute checks: unavailable, carries_dependency, require_constant_initialization, annotate

WP-912's clang negative-test run found that kiln accepted invalid uses of four attributes, mostly without their subject or argument checks. Each is now checked as clang 22 does, and as clang 19 under `-fclang-compat=19`. The rules are in spec/sema.md §4.5.

- **`unavailable`** (`AttrKind::UNAVAILABLE`, `annotate_attr.rs`, `deprecated.rs`).
  - Before: parsed and ignored, so a use compiled.
  - Now:
    - At most one argument, which is a string literal; it is the message.
    - A use is `'f' is unavailable[: msg]` with a `marked unavailable here` note. It goes through the `deprecated` use-site machinery, which is generalized to both kinds: the same uses, inheritance by later redeclarations, and delayed diagnostics.
    - A use inside an unavailable function or class is allowed.
  - Tests in `dcl.attr/`: `unavailable-call.cpp` (flipped from xfail), `unavailable-attribute.cpp`.
- **`require_constant_initialization`** (`AttrKind::REQUIRE_CONSTANT_INIT`, `const_init_attr.rs`).
  - Before: ignored.
  - Now:
    - It applies only to a variable with static or thread storage duration.
    - The initializing declaration must have a constant initializer. The error and notes follow clang: the error at the variable, a note at the attribute, then the Oven's notes.
    - Before C++11, the check is clang's syntactic `isConstantInitializer`, with a single `subexpression not valid` note.
    - Adding the attribute after the initializing declaration is a warning, and the attribute is dropped.
    - Its immediate invocations are checked with the whole initializer, as for `constinit`.
  - Tests in `dcl.attr/`: `require-constant-init.cpp`, `require-constant-init-cxx03.cpp`.
- **`annotate`** (`AttrKind::ANNOTATE`, `annotate_attr.rs`, `templ/subst/anon.rs`).
  - Before: arguments skipped, attribute ignored.
  - Now:
    - At least one argument; the first is a string literal.
    - The other arguments are decayed and evaluated by the Oven. A failure is `requires parameter N to be a constant expression` with the evaluation's notes, and the attribute is dropped.
    - Value-dependent arguments are checked at instantiation. Pack expansions are accepted, and a pack outside an expansion is an error.
    - On a statement, clang 22 accepts it and clang 19 rejects it.
  - Tests in `dcl.attr/`: `annotate-attribute.cpp` and `-19`, `annotate-statement-run.cpp` and `annotate-statement-19.cpp`.
- **`carries_dependency`** (`carries_dep_attr.rs`, from the parser's parameter clause and the function-redeclaration paths in `decl.rs`).
  - [dcl.attr.depend]/1: on a parameter of a declarator that declares no function or lambda, it is an error.
  - [dcl.attr.depend]/2: a function or parameter that gains it after its first declaration is an error, with a note at the first declaration.
  - Tests in `dcl.attr.depend/`: `carries-dependency-after-first.cpp` (flipped from xfail), `carries-dependency-placement.cpp`.
- **Valid forms**: `dcl.attr/clang-attr-valid-forms-run.cpp` runs all four and checks that each leaves the program's values unchanged.
- **clang-neg** (CXX + SemaCXX):
  - accepts-invalid: 64 → 60 of 1250 files, 75 → 69 of 1946 cases;
  - missed errors: 3888 → 3776 of 28065;
  - rejects-valid stays at 28; 0 crashes.
  - `attr-unavailable.cpp`, `attr-annotate.cpp`, `attr-require-constant-initialization.cpp` (all RUN lines) and `dcl.attr.depend/p1.cpp` and `p2.cpp` now miss no error.
- **Not done (follow-ups)**:
  - `annotate` codegen (`llvm.global.annotations`, `llvm.var.annotation`, `llvm.ptr.annotation`).
  - Oven note wording for a non-literal type, and for an implicit non-constexpr constructor (clang names the constructor; kiln names the uninitialized subobject).
  - `-Wglobal-constructors`.
  - clang's `attribute ignored when parsing type` warning for a GNU attribute after a trailing return type.
