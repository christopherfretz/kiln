# WP-805 — attribute triage, truthful feature tests, silent drops

kiln never accepts a semantics-changing construct without implementing
it. Before this work package an attribute clang knew but kiln did not
implement was either warned about as unknown or dropped silently, and
`__has_attribute` / `__has_builtin` reported clang's answer whether or
not kiln honoured it. `docs/status/silent-drops.md` is the inventory
this work started from, with each remaining row's owner.

## Attribute triage (`crates/kiln_sema/src/attr_triage.rs`)

- One table, `attr_triage::TABLE`, lists every attribute clang 19 and 22
  know on aarch64 and x86-64 that kiln does not implement: its name
  (without `__` affixes), the spellings clang knows per target and
  release (`G` `__attribute__`, `GS` `gnu::`, `CL` `clang::`, `STD`
  unscoped, `GSL`, `MS`, `OMP`), its class and a one-line reason. It
  replaces the old `THREAD_SAFETY_ATTRS` / `IGNORED_CLANG_ATTRS` lists.
- `attribute_support(name, syntax, scope, compat, cxx26, x86)` answers
  `Implemented(kind)`, `Ignored(class)`, `Unsupported` or `Unknown`.
  `Sema::act_on_attribute` (decl.rs) trims the name's `__` prefix and
  suffix independently, as before, and then:
  - **Implemented**: as before.
  - **Class B** (optimization, instrumentation, debug info, hardening)
    and **class C** (diagnostics or analyses kiln does not run, or one
    clang ignores for kiln's targets): accepted silently, nothing
    attached.
  - **Class A** (semantics, ABI or layout): the error
    `sema_attribute_unsupported_by_kiln`, `'X' attribute is not
    supported by kiln yet`. It is an error, so system headers and `-w`
    do not suppress it. When in doubt a name is class A. Names owned by
    sibling work packages (FP semantics, constructors/destructors and
    linkage attributes, calling conventions) stay class A until those
    land.
  - **Unknown** to clang: the `unknown attribute 'X' ignored` warning,
    unchanged.
- `crates/kiln_driver/tests/attr_triage_coverage.rs` checks the table
  against clang's `__has_attribute` / `__has_cpp_attribute` tables on
  both targets at 19 and 22 (C++26), both ways. Every spelling clang
  knows is implemented or triaged. Every spelling bit a row sets is one
  clang knows. `carries_dependency` is the exception: it was removed
  from C++26 by P3475R2 (WP-743). `__declspec` spellings are not
  triaged, because kiln has no `-fms-extensions` mode.

## Truthful feature tests (`crates/kiln_driver/src/pp_cmd.rs` `StagedFeatures`)

In compile modes (not `-E`, which keeps clang's raw answers):
- `__has_attribute`, `__has_cpp_attribute` and
  `__has_declspec_attribute` report 0 for a class-A name
  (`unsupported_attribute`, the same lookup and trim as sema). Class B
  and C names keep clang's value.
- `__has_builtin` reports 0 for a builtin kiln declares but codegen
  cannot lower: `kiln_codegen::UNLOWERED_BUILTINS`, a sorted list
  (`is_unlowered_builtin`). Today it holds the scalar and poly NEON
  forms, a few `__builtin_arm_*` system-register builtins and x86
  `__builtin_ia32_maskmovq`.
- `crates/kiln_driver/tests/builtin_lowering.rs` reads back every
  builtin kiln reports on each target at clang 19 and 22. It calls each
  one with 0 to 6 operands of a type that converts to anything, and
  compiles the calls sema accepts to IR. A "not supported yet", "IR
  lowering failed" or "not a library builtin" error fails the test. At
  clang 22 each list entry must still fail on some target, so the list
  cannot go stale. The test's coverage limits (NEON `_v` type-code
  forms, x86 immediates, coroutine builtins) are in its module docs.
- The probe found three gaps, fixed here:
  - `__builtin_arm_clrex()` takes no operands and lowers to
    `llvm.aarch64.clrex`
    (`tests/conformance/target.acle/ir-clrex.cpp`).
  - A non-literal `__builtin_nanf16` / `nanf128` / `nansf16` /
    `nansf128` calls the library function, as clang
    (`tests/conformance/c.math/ir-nan-f16-f128-library-call.cpp`).
  - `@llvm.used` / `@llvm.compiler.used` were never emitted in a TU
    without a dynamic initializer (`global_init.rs`
    `emit_used_lists`).
- Test: `tests/conformance/dcl.attr.unknown/has-attribute-truthful.cpp`.

## Attributes that gained codegen

- **`used`**: the entity is emitted even when it is unreferenced
  (clang `DeclMustBeEmitted`). On ELF it is listed in
  `@llvm.compiler.used`.
- **`retain`**: the entity is listed in `@llvm.used`. clang 19 marks
  the section `SHF_GNU_RETAIN` from that list
  (`CodeGenModule::addUsedOrCompilerUsedGlobal`).
- **`aligned(N)` / `alignas` on a function**: the definition gets
  `align N` (clang `SetLLVMFunctionAttributesForDefinition`,
  `Decl::getMaxAlignment`). Thunks keep their own alignment.
- **`[[clang::no_destroy]]`, `[[clang::always_destroy]]` and
  `-f[no-]c++-static-destructors[=all|thread-local|none]`**: a static
  or thread-local variable that clang `VarDecl::isNoDestroy` excludes
  registers no destructor (`Cg::is_no_destroy`; spec/driver.md "Codegen
  flags").
- Tests:
  - `tests/conformance/dcl.attr/ir-used-retain-aligned.cpp`
  - `used-section-run.cpp`
  - `no-destroy-run.cpp`
  - `no-static-destructors-run.cpp`

## `__builtin_assume`

`__builtin_assume(e)` never evaluates `e`. When `e` has possible side
effects (`has_possible_side_effects`), sema warns as clang's `-Wassume`
does, `assumption is ignored because it contains (potentially)
side-effects`, and flags the call `ExprFlags::ASSUME_IGNORED`. Codegen
then emits nothing for it. Otherwise it is `llvm.assume(e)`, as clang
19. `[[assume(e)]]` already followed this rule (WP-160).
Test: `tests/conformance/dcl.attr.assume/builtin-assume-side-effects-run.cpp`.
