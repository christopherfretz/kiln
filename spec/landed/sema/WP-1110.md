# WP-1110 — friend declaration matching (covers WP-1098, WP-1099)

Three gaps in how kiln_sema matches a friend declaration to the entity it
names, left by WP-1071 and WP-1072. The rules are in spec/sema-templates.md
§4.8.

1. **Dependent method friends are matched at instantiation** ([temp.friend]/1,
   [class.friend]/10, [temp.res.general]/3; rejects-valid). A qualified friend
   naming a member function in a templated class was matched against the
   member when the class template was defined. Examples:
   `friend int B::f(W<T>&)` and `template <class U> friend int B<T>::g(U, W<T>&)`.
   When the declarator depends on the enclosing template's parameters, the
   pattern's parameters alias the class's (`W<T>` in `B<T>` and in `W<T>`).
   So the match either failed ("does not match any declaration") or
   succeeded spuriously against the primary pattern.
   - `Sema::defers_method_friend` (`kiln_sema/src/decl.rs`) defers the
     friend in these cases:
     - its own head, its type or its specifier is dependent;
     - and its class is not the current instantiation or an enclosing one;
     - and no member matches it now.
   - A dependent specifier (`B<T>::`) always defers, because an explicit
     specialization may declare other members.
   - A specifier that resolves to the class template itself (`C<T>::`
     inside `V<X, T>`, not the current instantiation) defers too.
   - The deferred friend records its written specifier in
     `Sema::friend_qualifier_nns`. The friend's substitution
     (`templ/subst/decls.rs` `function_decl`) resolves that specifier
     against the instantiation's arguments. It then matches the friend
     against that class's members with the substituted signature, so a
     mismatch is "friend declaration of 'f' does not match any declaration
     in 'B'" at instantiation, as clang reports it.
   - A friend member template whose specifier names none of its own head's
     parameters keeps that head (`Sema::friend_head_is_own`,
     `class/member_friend.rs`). Before, `take_template_head` gave the head to
     the qualifier's class template.
   - Non-dependent method friends are matched eagerly, as before.
   - Tests: `class.friend/friend-member-dependent-signature-run.cpp` and
     `friend-member-template-of-specialization-run.cpp` (xfails flipped),
     `friend-member-deferred-variants-run.cpp`, and
     `friend-member-dependent-mismatch-at-instantiation.cpp`.
2. **Member function template friends compare heads** ([temp.friend]/5,
   [temp.over.link]/4-6; WP-1098). `template <class T> template <class V>
   friend int A<T>::h(const B&)` befriends only a member template of A<X>
   that meets all of these:
   - its head is equivalent to the friend's inner head: the same length,
     and the same kind, packness and non-type parameter types (substituted);
   - template template parameters compare by `heads_equivalent`;
   - its type equals the friend's once the friend's inner parameters are
     renamed to the member's (an extra substitution level in
     `member_friend_match_uncached`).

   A friend without an inner head never names a member template, and one
   with a head never names a non-template. Constraints are not compared.
   Test: `temp.friend/dependent-member-friend-template-head-denied.cpp`.
3. **Kind mismatch** ([temp.friend]/5, [dcl.type.elab]/5; WP-1099). In
   `template <class U> friend struct A<U>::M;`, if the primary template's M
   is a function or variable, the friend is ill-formed. The same holds for a
   function friend naming a member class.
   - The friend is rejected with "redefinition of 'M' as different kind of
     symbol" and "previous definition is here" (`member_friend_kind_mismatch`),
     and is marked invalid.
   - clang 19/22 accept all three cases with -Wunsupported-friend. g++
     rejects them. Test: `temp.friend/dependent-member-friend-kind-mismatch.cpp`.
