# WP-612 — A using-declaration's base member is hidden by a derived-class member (template) with the same signature

[namespace.udecl]/14, [basic.scope.scope]/4, [temp.over.link]/6. The rule
is in `spec/sema.md`, "Conflicts", "Member hiding".

- A member function template declared in a class never hid a base member
  function template a using-declarator of the class introduced: the
  declarator path compared the template's *pattern* (a `CXXMethod`) with
  the shadow's `FunctionTemplate` target, which never matched, so both
  were candidates and the call was ambiguous (`Map<T>::operator=<O>` vs
  `MatrixBase<D>::operator=<O>` via `using Base::operator=;`). The
  template itself is now compared.
- Member `operator=` declarations (special-member declarator path) did
  not check the shadows at all; they now do, like conversion functions.
- The comparison is `member_hides_using_target`: template-ness agrees and
  the signatures correspond with the return type ignored (clang's
  `UseMemberUsingDeclRules`; `NewFn::member_using`,
  `signatures_correspond`). Previously non-template members compared the
  full function type, so `M& operator=(int)` did not hide
  `B& operator=(int)`.
- Members that do not correspond overload as before (different
  parameter types, cv- or ref-qualifiers, template vs non-template,
  non-equivalent constraints).
- Deferred: a constrained member template of a class template
  specialization vs a constrained one of a non-template base (constraints
  kept at the pattern's depth) is not found equivalent.
