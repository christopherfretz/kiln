# WP-683 — Small header-only trio (magic_enum, doctest, tl_expected) with kiln++

WP-683 builds magic_enum v0.9.7, doctest v2.5.3 and tl_expected v1.3.1
through their own CMake builds and test suites, using `scripts/oss`. The
per-project results are in docs/status/oss/magic-enum.md,
docs/status/oss/doctest.md and docs/status/oss/tl-expected.md, with a
summary in docs/status/oss/small-trio.md. Each fixed behaviour below has
a test and a sentence in the spec that owns it.

## Fixed behaviours

- **A rebuilt call of a custom-checked builtin keeps the builtin's own
  checks** ([expr.call]/12 does not apply). A template instantiation can
  rebuild `__builtin_constant_p(s)` for a non-trivial class object `s`.
  The rebuilt call now goes through the builtin's custom checks again.
  Before, it took the variadic path and failed as a `-Wnon-pod-varargs`
  error. magic_enum's bundled Catch2 v2 `REQUIRE` expands to this call.
  - Spec: spec/sema-templates.md, the "Landed (WP-088)" builtins bullet.
  - Test: tests/conformance/ext.gnu.builtins/constant-p-class-arg-template.cpp.
- **Values of an enumeration with underlying type `bool` print as
  enumerators** (clang `TemplateArgument::print`, which
  [dcl.fct.def.general]/8 `__PRETTY_FUNCTION__` uses). They print as
  `X<B::Nay>` and `[V = B::Nay]`, not `1`. magic_enum reads enumerator
  names from these strings.
  - Spec: spec/ast.md, template-argument print styles.
  - Tests: tests/conformance/dcl.fct.def.general/predefined-bool-enum-arg.cpp
    and predefined-bool-enum-note.cpp.
- **A structured binding's ADL-only `get<i>` is not a written
  template-id** ([dcl.struct.bind]/4, [temp.names]/3). In C++17, the
  implicit `get<i>(xvalue)` of a tuple-like binding no longer warns
  `-Wc++20-extensions` "use of function template name with no prior
  declaration". Under `-Werror`, that warning turned every `std::pair`
  binding into an error.
  - Spec: spec/sema.md, structured bindings.
  - Test: tests/conformance/dcl.struct.bind/tuple-get-adl-cxx17.cpp.
- **`-Qunused-arguments` is accepted.** As in clang, it silences the
  `-Wunused-command-line-argument` warnings of a compile-only run.
  doctest's CMake passes it to every clang-identified compiler, so all
  84 doctest TUs were rejected with "unknown argument".
  - Spec: spec/driver.md, unused inputs.
  - Test: crates/kiln_driver/tests/codegen.rs, `driver_errors_and_warnings`.
- **A dependent unqualified template-id call keeps the declarations its
  definition found** ([temp.dep.candidate]/1). For `declval<const T &>()`
  in a partial specialization's arguments, `Substituter::callee` now
  keeps the stored namespace-scope declarations and the substituted
  explicit template arguments. Before, it looked the name up again from
  the scope where the specialization is named. Outside the template's
  namespace that lookup found nothing, so doctest's `is_std_string`
  partial specialization never matched and `String(std::string)` had no
  viable constructor.
  - Spec: spec/sema-templates.md, §3.5.
  - Test: tests/conformance/temp.dep.candidate/template-id-definition-lookup.cpp.

## Fixed by WP-680 (merged into this branch)

magic_enum's bundled Catch2 v2 hit the same three clusters that WP-680
fixed in Catch2 v3:

- protected `using` from a dependent base;
- an inherited protected constructor;
- `R(A)` vs `R(A...)` partial ordering.

WP-683's duplicate fixes were dropped in favour of WP-680's. Two run tests
that WP-680's tests do not cover are kept:

- tests/conformance/class.protected/using-decl-dependent-base-run.cpp
  (a member class of the template; a protected member function);
- tests/conformance/class.protected/inherited-ctor-derived-object-run.cpp
  (direct-, list- and functional-cast initialization; a dependent base).
