# WP-703 — taskflow through its own build and tests (M8 wave 2)

taskflow v3.10.0 built with kiln++ through its own CMake build and
doctest test suite (docs/status/oss/taskflow.md). Each fixed behaviour
below is a kiln bug the build found, reduced to a standalone conformance
test; the rule is stated in the spec named.

## Changes

- **An init-capture's variable is not an unused variable**
  ([expr.prim.lambda.capture]/6, [dcl.attr.unused]; spec/sema.md "Unused
  variables"). The variable an init-capture declares is referenced by
  its capture, so `[&res = v[i]]() { ... }` with `res` unused in the body
  is no longer `unused variable 'res'` [-Wunused-variable] (clang reports
  such a capture only under -Wunused-lambda-capture, which kiln does not
  implement yet), by copy or by reference, in a generic lambda and in a
  lambda instantiated with its enclosing template. One that is only
  assigned in the body is still `variable 'y' set but not used`
  [-Wunused-but-set-variable], as in clang.
  Test: `tests/conformance/expr.prim.lambda.capture/init-capture-not-unused-variable.cpp`.
