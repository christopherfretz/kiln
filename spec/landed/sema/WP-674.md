# WP-674 — lifetimebound and gsl Owner/Pointer in the dangling analysis

kiln's `-Wdangling` family was a set of special cases: returned locals
(WP-204), dangling pointer variables (WP-227), dangling reference
members and temporaries bound to references. This work package replaces
them with one port of clang 19's `CheckExprLifetime.cpp`, which honours
`[[clang::lifetimebound]]`, `[[gsl::Owner]]` and `[[gsl::Pointer]]`. It
also closes WP-741 (gsl Owner/Pointer). The contract is
spec/sema-class.md "Lifetime analysis"; the attribute subjects are in
spec/sema.md "Lifetime attributes".

## The walk (`crates/kiln_sema/src/class/temporary/lifetime.rs`)

- Four entry points: `check_var_lifetime` (variables, including each
  element of a braced aggregate initializer), `check_member_init_lifetime`
  (mem-initializers, `-Wdangling-field`), `check_return_lifetime`
  (returns, `-Wreturn-stack-address`) and `check_assignment_lifetime`
  (built-in assignment and compound assignment to a pointer, and a gsl
  Pointer's `operator=`, `-Wdangling-assignment[-gsl]`).
- They call clang's two walks: reference binding
  (`visitLocalsRetainedByReferenceBinding`) and initializer
  (`visitLocalsRetainedByInitializer`). The path entries match clang's
  (address-of, var-init, lvalue-to-rvalue, lifetimebound call, temporary
  copy, lambda capture, gsl reference/pointer init), and so do the path
  truncation and the `TemporaryVisitor` judgement per entity kind.
- Lifetimebound arguments (`visitLifetimeBoundArguments`): parameters,
  the implicit object (written after the declarator) and constructor
  parameters. Assignment operators that return an lvalue reference are
  implicitly lifetimebound, and so are the `std` builtins `addressof`,
  `__addressof`, `as_const`, `forward`, `forward_like`, `move` and
  `move_if_noexcept`.
- gsl (`handleGslAnnotatedTypes`, only while `-Wdangling-gsl` is on):
  - Pointer construction from an Owner or Pointer.
  - The tracked `std` member names (`shouldTrackImplicitObjectArg`).
  - The tracked free functions (`shouldTrackFirstArgument`).
- The existing per-site checks are gone: `stack_addr.rs`, the dangling
  temporary checks behind `BindingSite`, `check_dangling_field`, and the
  initializer_list return special case.
- Entities of dependent type are skipped, as clang does. This covers a
  return in a generic lambda inside a template, where the return type is
  still dependent.

## gsl classes (`crates/kiln_sema/src/class/temporary/gsl.rs`)

- An explicit attribute on any redeclaration makes a class an Owner or a
  Pointer.
- clang 19's implicit `std` lists (`StdOwners`, `StdPointers`) also apply.
- So do nested `iterator`-named classes of `std` containers.
- So does the typedef inference (`inferGslPointerAttribute(TypedefNameDecl)`).
  It runs at the typedef's declaration, and at instantiation only for a
  dependent-name pattern.
- The name rules apply to definitions and patterns, never to
  specializations.
- An instantiation from a partial specialization takes only that
  partial specialization's own attribute. So `std::vector<bool>` is not
  an Owner under either library.

## Tests

`tests/conformance/class.temporary/`:

- `lifetimebound.cpp`: a user function, member function and constructor
  through variables, returns, mem-initializers, assignment and a
  template.
- `gsl-owner-pointer.cpp`: mock Owner and Pointer classes with explicit
  attributes.
- `dangling-gsl-libstdcxx.cpp` and `dangling-gsl-libcxx.cpp`: std::min
  and max, string_view, optional, map and vector `[]` on a temporary,
  c_str, data, begin, unique_ptr::get, span, vector<bool>, returns and
  mem-initializers.
- `dangling-assignment.cpp`: assignment, aggregate and initializer_list
  members.
- `lifetime-negatives.cpp`: lifetime extension done right, and arguments
  and views that outlive their uses.

`tests/conformance/dcl.attr/lifetime-attributes.cpp` covers the
attribute subjects.

Every test is clang 19's output (`requires: clang<22`). clang 20+
diagnoses more, which is listed as a follow-up.
