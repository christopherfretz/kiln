# WP-957 — accepts-invalid: lookup and type checks, exception specs laxer than the base

Closes the remaining gaps of docs/status/accepts-invalid.md items 11 and 12
(WP-912's clang negative-test run). WP-1017 had already landed the main
rules of all five items; this WP fixes what it left partial. Every case is
matched against clang 19 and clang 22.

## Items

1. **Ambiguous elaborated-type-specifier lookup.** The qualified ambiguity
   landed in WP-1017. New: an unqualified `struct A` whose tag lookup finds
   an outer class while a nearer scope declares `A` as a typedef, type
   alias, class template or alias template is rejected (`typedef 'A' cannot
   be referenced with the 'struct' specifier`; [basic.lookup.elab]/1,
   [dcl.type.elab]/2). The same holds for `friend class-key A;` naming such a
   type name in the innermost enclosing namespace. spec/sema.md
   "Elaborated-type-specifier checks". Tests:
   `dcl.type.elab/tag-hidden-by-type-name{,-ok}.cpp`.
   **Deferred:** a qualified ambiguity between plain types lists its
   candidates in discovery order.
2. **The `enum` keyword on a non-enum and the reverse.** Fixed in WP-1017
   for declarations. Instantiation-time wrong-tag errors at the class-key
   belong to WP-1054 (#435). **Deferred:** an elaborated specialization
   through a template template parameter bound to an alias template
   (`struct F<int>` with `F = Id`) is not diagnosed at instantiation.
3. **`alignas` with an incomplete type.** Fixed in WP-1017 for a
   non-dependent operand. New: a dependent operand is checked at
   instantiation (class templates, pack expansions, function templates).
   Tests: `dcl.align/alignas-dependent-incomplete.cpp`,
   `dcl.align/alignas-dependent-type-ok.cpp`.
4. **Differing user-defined suffixes in a string literal concatenation.**
   Fixed in WP-1017 (`lex.ext/differing-ud-suffixes.cpp`). The diagnostic
   was re-checked here against clang for raw, `u8`, three-piece, macro
   and template operands. No change was needed.
5. **Exception specifications laxer than the base.** Explicit `noexcept`,
   `noexcept(expr)` and dynamic lists landed in WP-1017. New:
   - Implicit destructors and copy or move assignment operators are
     checked against every overridden function: a computed
     noexcept(false) is lax against a non-throwing base. Before C++17, a
     computed type list (the union of the implicit callees' lists) is
     compared type by type.
   - One error is reported per overridden function, as clang does.
   - The implicit assignment operators of a dynamic class now record their
     overrides. This was a miscompile: a call through the base's virtual
     `operator=(const D&)` ran the base's function, not D's implicit one.

   spec/sema.md "Overriders". Tests:
   `class.virtual/exception-spec-implicit{,-dynamic}{,-ok}.cpp`,
   `class.virtual/implicit-assignment-override-run.cpp`.
   **Deferred:**
   - An implicit assignment overriding a `final` function, with clang's
     note `while declaring the implicit copy assignment operator`.
   - The return-type check for implicit overriders.
   - The nested function-type rule (`CheckParamExceptionSpec`:
     `exception specifications of argument types differ`).
