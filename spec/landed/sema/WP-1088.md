# WP-1088 — P2719 type-aware allocation

Type-aware `operator new` and `operator delete` (P2719R5, in the C++26 DIS), and the access check on a destroying delete found through a using-declaration (WP-1089). The rules are in spec/sema.md §5.9 ("Type-aware allocation"). The oracle is clang 22, which implements the paper; clang 19 rejects it. clang's `type-aware-*.cpp` tests are ported as `//@ verify` tests with `requires: clang>=22`. Neither compiler defines a feature-test macro (checked with `-dM`).

- **Declarations** (`alloc_decl.rs`).
  - `check_type_aware_signature`:
    - The first parameter is a `std::type_identity` specialization.
    - Then `std::size_t` (new) or `void *, std::size_t` (delete), then `std::align_val_t`. These are not dependent and have no default argument.
    - A template's `T` is deduced only from the first parameter.
    - A type-aware destroying delete is an error.
    - Each declaration warns `-Wext-cxx-type-aware-allocators`, as clang 22 does. The first one sets `GlobalOps::seen_type_aware`. Without it, lookup and selection do not change.
  - At class completion, `check_type_aware_allocator_pairs` checks that a class declaring a typed new has a typed delete of the same form, and the reverse. The error is at the class, with an `unmatched` note.
  - A malformed `std::type_identity`, such as one that is not a template, makes a function untyped. clang reports an error for it (follow-up).
  - Tests: `basic.stc.dynamic/type-aware-{free,member}-declarations.cpp`, `basic.stc.dynamic/type-aware-invalid-type-identity.cpp`, `basic.stc.dynamic/type-aware-linkage-spec.cpp`, `class.free/type-aware-mismatched-constraints.cpp`.
- **Selection** (`new_delete.rs`, `overload/alloc.rs`).
  - A new-expression follows clang `resolveAllocationOverload`. It tries the typed candidates with `std::type_identity<T>{}` first, with the alignment and then without it. The untyped candidates are tried only after that.
  - A deleted typed best candidate gets `call to deleted function`, with a note for every candidate.
  - The delete-expression, the deleting destructor and the cleanup of a new-expression all choose typed usual deallocation functions first (`typed_usual_delete`, `resolve_usual_dealloc`).
  - The cleanup must match the `operator new`:
    - it must be typed exactly when the new is (`sema_mismatching_type_aware_cleanup_deallocator`);
    - a placement new needs the typed placement delete.
  - Tests: `expr.new/type-aware-{resolution,placement,qualifiers,arrays}.cpp`.
- **Codegen** (`kiln_codegen/src/new_delete.rs`).
  - Every call passes an empty `std::type_identity<T>` first. This includes the cleanup when a constructor throws.
  - The cleanup reuses the new-expression's `type_identity` temporary.
  - A typed `operator new[]` gets an array cookie, as in clang. With a cookie, the alignment that is passed is at least `size_t`'s (clang `cookieAlign`).
  - A global cleanup prefers the sized form, and the aligned form only for an over-aligned type. Neither depends on the alignment that a typed new always takes. Before this, kiln chose the implicit aligned unsized delete.
  - Tests:
    - `expr.new/type-aware-run.cpp` covers class and global forms, an over-aligned type, a cookie, a virtual destructor, and constructors that throw;
    - `expr.new/ir-type-aware.cpp` (`min-oracle: 22`).
- **Constant evaluation** (`kiln_oven/src/compile/new_delete.rs`).
  - [expr.const] as P2719R5 amends it: a namespace-scope typed function of replaceable form is usable (`is_type_aware_global_alloc`). The Oven allocates the storage itself and never calls the function.
  - A class-scope typed function is not usable, the same as an untyped one.
  - This follows the DIS and clang 22 (`type-aware-new-constexpr.cpp`). The brief said type-aware allocation is not usable in constant expressions. The DIS says otherwise.
  - Test: `expr.const/type-aware-new.cpp`.
- **Coroutines** (`coroutine.rs`).
  - The frame's new and delete lookups ignore typed functions.
  - `-Wcoro-type-aware-allocation-function` warns about the ignored functions. When the untyped new is unusable, the error gets a note and a "declared here" note for each typed function.
  - Test: `dcl.fct.def.coroutine/type-aware-allocators.cpp`.
- **Access through a using-declaration** (WP-1089).
  - `AllocFns::via` records the using-shadow for each class-scope function, and `found_decl` returns it. The access checks for new and delete, for the cleanup, for the deleting destructor and for the virtual-destructor usability test all use the shadow.
  - A destroying delete's `this` is formed at the first parameter. If it fails to convert, the destructor gets `while checking implicit 'delete this' for virtual destructor`.
  - Kiln now matches clang's `cxx2a-destroying-delete.cpp` lines 40, 45 and 48. The type is spelled unscoped ('D' rather than 'convert_param::D'), which is a separate bug (follow-up below).
  - Test: `expr.delete/destroying-delete-using-access.cpp` (clang 19 and 22).
- **Interface changes**:
  - New diagnostics:
    - `ext_cxx_type_aware_allocators` (group `ext-cxx-type-aware-allocators`);
    - `sema_type_aware_{operator_new,operator_delete}{,_dependent}_param_type`, `sema_type_aware_new_delete_too_few_parameters` and `sema_type_aware_destroying_operator_delete`;
    - `sema_type_aware_allocator_missing_matching_operator` and `note_unmatched_type_aware_allocator_declared`;
    - `sema_mismatching_type_aware_cleanup_deallocator` and `sema_ambiguous_suitable_delete_member`;
    - `sema_coroutine_type_aware_allocator_ignored` (group `coro-type-aware-allocation-function`), `note_coroutine_unusable_type_aware_allocators` and `note_type_aware_operator_declared`;
    - `note_implicit_delete_this_in_destructor_here`.
  - `AllocFns` gains `via` and `found_decl`. `dtor_dealloc_fn` and `matching_operator_delete` also return the using-shadow.
  - New Sema functions:
    - `is_type_identity`, `is_type_aware_alloc_fn` and `std_type_identity`;
    - `typed_usual_delete` and `resolve_usual_dealloc`;
    - `check_type_aware_allocator_pairs`.
  - Oven: `is_type_aware_global_alloc`.
- **Not done** (follow-ups):
  - `-Wmismatched-new-delete` and `-Wimplicit-exception-spec-mismatch`.
  - An ambiguous typed `operator new` (clang `err_ovl_ambiguous_call`).
  - The error for a malformed `std::type_identity`.
  - The extension warning is not repeated when a member template is instantiated.
  - In constant evaluation, a direct call to a global typed operator.
  - The promise type's spelling in `err_coroutine_unusable_new`.
  - Scoped class names in base-access diagnostics (`class/access.rs:979`).
