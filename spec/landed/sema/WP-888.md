# WP-888 — sema correctness and error-recovery bundle

Closes WP-833, WP-837, WP-849, WP-848 and WP-832, which came out of
WP-818, WP-823 and WP-826 (Boost.Math error recovery). The oracle is
clang 19, and every test also passes under clang 22. The rules are in
spec/sema.md §1.2, spec/sema-overload.md "Member overload sets used other
than called" and spec/sema-templates.md §5.6.

- **WP-833: a member template-id in a template body.** A template-id
  whose template arguments are dependent, or that names a member of a
  dependent class, now builds a type-dependent overload set
  (`overload_set_is_dependent` at the three `unresolved_lookup_in`
  sites in templ/actions.rs). So `auto p = F::tm<T>;` in a template body
  waits for instantiation, as clang's does, and a template that is never
  instantiated is not diagnosed. clang's `tryToRecoverWithCall` gives no
  hint when the member access is type-dependent (`this->f`, `F::tm<long>`
  in a dependent class). Kiln now checks the same thing
  (`diagnose_member_set_not_called_at`, `diagnose_bound_member_as`).
  For a template-id set it adds clang's "possible target for call" notes.
  A variable whose initializer is an object-less non-static member
  function name (`auto p = C::f;` in a static member function) is
  reported once, when the initializer is attached
  (`reject_objectless_method_init`, decl.rs). It is then recovered as an
  erroneous expression, so no deduction or conversion error follows.
- **WP-837: attributes written only on a late out-of-line member-template
  definition.** `function_spec_attrs` (templ/subst/anon.rs) now applies
  the class-instantiation cutoff to every attribute, not just
  `always_inline` and `noinline`. It also merges every attribute of an
  earlier redeclaration that carries over unsubstituted
  (`merges_unsubstituted`). `nodiscard`, `deprecated`, `pure`, `const`
  and `cold` written only on a definition that follows `A<int> a;` no
  longer reach `A<int>::f<U>`. The IR test checks, on both targets, that
  pure, const and cold are dropped after the cutoff and kept before it.
- **WP-849: a failed call keeps its variable.** A call that fails
  overload resolution, or a member call whose arguments don't convert,
  records `Sema::call_recovery` with clang's `chooseRecoveryType`. A
  variable instantiated from it stays valid, with an erroneous
  initializer (`var_init`, the Substituter's `recovered_call`). Its
  later uses are diagnosed: `n == 1 ? T() : 0`, and a `void`
  recovery's "cannot initialize ... with an rvalue of type 'void'".
- **WP-848: a failed block-scope typedef is `int`.** `typedef_decl_in`
  declares an invalid `int` typedef outside SFINAE, as clang's
  `InstantiateTypedefNameDecl` does. Uses then print `'T2' (aka 'int')`.
- **WP-832: recovery by call.** A bound member function, or a set of
  non-static member functions, used where a value is needed is replaced
  by its zero-argument call wherever clang runs `CheckPlaceholderExpr`.
  That covers operator operands, cast operands, braced-init-list
  elements (`act_on_init_clause` at parse), `sizeof`/`alignof`,
  `decltype`, implicit conversions and placeholder deduction. Follow-on
  errors are therefore about the `int` result. The diagnostic is at the
  outermost parenthesis (`paren_loc_of`). `auto a = g.f;` reports it
  twice, as clang does (deduction diagnoses a copy). Braced initializers
  report it once, as clang does.
- **WP-834 (part): a deleted temporary destructor is an error.**
  `maybe_bind_temporary` (class/temporary.rs) returns an erroneous
  expression when the destructor is deleted, as clang's
  `MaybeBindToTemporary` returns `ExprError`. `auto l = [x = B()] {};`
  with a protected `~B` no longer gets a second "attempt to use a
  deleted function" at `l`.

  shapes, never-instantiated templates, and static member functions.

## Not done

- `this->tm<long>` in a template body, where `tm` is a member of the
  current instantiation: clang diagnoses it at the definition, kiln at
  instantiation.
- A list-initialization conversion error is located at the expression's
  operator location (conv/mod.rs:118). clang uses its begin location.
- `-Wint-to-void-pointer-cast` is missing after recovery by call.
- A failed call that is not in a template, initializing a class-type
  variable: clang's typed `RecoveryExpr` diagnostics are not reproduced.
- A member template declared `deprecated` only on an early out-of-line
  definition: clang warns for both `g` and `g<int>`, kiln only for
  `g<int>`.
- WP-834 order: outside a template, clang delays a temporary's
  destructor access error to the end of the declarator
  (`ParsingDeclarator`), after the deleted-destructor error. Kiln emits
  access errors from `special_member_access` at once, so it reports
  them first. It needs a delayed-diagnostic path for special-member
  access. WP-850 (Boost.Math recovery wording) was not started.
