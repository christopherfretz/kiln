# WP-580 — explicit instantiation of member function templates by signature

[temp.explicit]/4, /10, /11, /12, [temp.deduct.decl], [temp.mem]/6,
[temp.param]/12. The rule is in `spec/sema-templates.md`, "Explicit
instantiation", "By signature".

- `[extern] template C::C(params);` and `[extern] template
  C::operator T *() const;` for a constructor or conversion function
  template of a class (or of a class template specialization,
  `template B<int>::B(char);`) reached sema through the special-member
  declarator path, which matched only non-template members and reported
  "out-of-line definition of 'C' does not match any declaration in 'C'".
  When no non-template member matches, the declarator now names a member
  template specialization: the class's constructor templates (redeclaration
  lookup of the constructor name) or every conversion function template of
  the class are deduced against the declarator's type
  (`Sema::act_on_explicit_special_template_inst`, which shares
  `match_function_spec_in` with the named-function path) and the match is
  explicitly instantiated as a named function template's is
  (`act_on_explicit_function_inst`). The constructor shape of a
  string-like class header (`template <typename T, EnableIfString<T> = 0>
  explicit Cord(T &&)` with `extern template Cord::Cord(std::string &&);`)
  compiles; the defaulted non-type template parameter is deduced from its
  default.
- An out-of-line definition of a member function template whose template
  parameter list leaves out the declaration's defaults already matched
  ([temp.param]/12); now pinned by a test.
- Diagnostics, matching clang 19 and 22: "candidate template ignored"
  notes sit at the candidate template's most recent declaration (its
  out-of-line definition), for explicit instantiations and explicit
  specializations alike; a conversion function template that does not
  deduce is not noted; an ambiguous explicit instantiation (free or
  member) is `sema_explicit_inst_ambiguous` "partial ordering for explicit
  instantiation of '{0}' is ambiguous" with
  `note_explicit_instantiation_candidate` notes in declaration order,
  instead of the explicit-specialization wording.
- Linkage follows clang at -O0: the definition form is `weak_odr` in a
  comdat, the `extern` form leaves a use as an external `declare`, also
  for an inline template.
