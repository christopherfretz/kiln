# WP-884 — concepts and reflection correctness follow-ups (WP-880, WP-881, WP-882, WP-883, WP-869)

Closes the four rows WP-821 left (WP-880 to WP-883) and WP-869 from
WP-830.

## Changes

- **Generic lambdas in constraint expressions** (WP-880,
  [temp.constr.atomic]/3, [expr.prim.lambda.general]/6;
  spec/sema-templates.md §8.3). A generic lambda's first `auto`
  parameter opens the lambda's own invented head even while the
  enclosing head is still open, as in a concept's constraint-expression
  (`lambda/mod.rs` `in_headless_lambda_declarator`, used by
  `templ/mod.rs` `act_on_invented_template_param`). Satisfaction then
  instantiates the lambda instead of failing substitution.
- **Trailing requires-clause of a templated lambda at the call**
  (WP-881, [expr.prim.lambda.closure]/9, [over.call.object]/2;
  spec/sema-lambda.md §3.2, spec/sema-overload.md). The conversion
  function and the invoker share the call operator's trailing
  requires-clause and constraint levels (`share_call_constraints`). A
  surrogate call candidate checks its conversion's constraints
  (`overload/surrogate.rs` `add_surrogate`), and its note is left out
  when it fails them (`overload/diag.rs`). A closure whose call operator's
  constraints fail is then "no matching function" in a
  requires-expression and in a function body.
- **`typeid` of an incomplete dependent record** (WP-882, [expr.typeid]/4;
  spec/sema.md §5.6). A type-id operand naming a dependent class with no
  definition, which is not a class template's pattern or specialization
  (a local class or a member class of the current instantiation), is
  diagnosed in the template definition at the `typeid` keyword, as in
  clang (`rtti.rs` `is_incomplete_dependent_record`).
- **Used parameters of a dependent member class** (WP-883,
  [temp.constr.atomic]/1; §8.2). `concepts/used.rs` `used_in_tag` walks
  the enclosing classes of a member class or enumeration up to namespace
  scope instead of keeping the whole mapping. On that walk, a local class
  whose declaration was already walked adds nothing, a specialization
  walks its arguments, a partial specialization walks its written
  arguments, and a class template's pattern marks its parameters.
- **Scoped enumerations of a local class** (found while testing WP-883;
  [temp.inst]/3, CWG1484; spec/sema-templates.md lazy scoped member
  enumerations). Such an enumeration is now defined together with its
  class. Before the fix, `L::E::e` in a function template's instantiation
  found no enumerator, and the statement was dropped without a
  diagnostic (`subst/decls.rs` `enum_decl`).
- **Structural profiles for dependent splices** (WP-869, P2996
  [temp.over.link]; spec/types.md §7.2, §8.2). `CXXSpliceExpr` is no
  longer UNIQUE. It profiles as (form, explicit args), then the
  operand's profile, then the object expression's profile for a member
  splice (`kiln_ast/src/types/profile_expr.rs`). A type splice was
  already canonicalized by its operand's profile.
- **`splice_fast` in the Oven report** (WP-869; spec/oven.md "Reporting
  protocol", spec/reflection.md, spec/harness.md). The fast-path count
  moved from `ParsedTu`/`Sema::splice_fast_count()` to
  `EvalTotals::splice_fast`. It is noted by `OvenBridge::into_parts` and
  written as the total line's `splice_fast` key. That key is total-only
  and is not cross-checked against the evaluation lines. The xtask
  `oven:` budgets accept `splice_fast` as an extra counter.

## Oracles

- WP-880, WP-881, WP-882 and WP-883: clang 19. WP-880 also agrees with
  GCC 16.1 (`oracle: gcc`).
- WP-882: GCC 16.1 diagnoses only at instantiation; kiln follows clang.
- WP-883: GCC 16.1 rejects the forward member references inside the
  lambda, so it cannot serve as an oracle there.
- WP-869: GCC 16.1 (`-freflection`). GCC calls the subsumption through a
  type splice in a concept-id ambiguous, against [temp.constr.atomic]/2,
  so that test is `skip(gcc)`. GCC does match the same type splice in
  redeclarations.

## Remaining

- Kiln accepts `sizeof(L::N)` for a member `N` of a local class `L` in a
  template. clang 19 requires `typename` ("missing 'typename' prior to
  dependent type name"). This is accepts-invalid and has no repro test.
- A substitution failure that leaves a statement out of an instantiated
  local class member function body can be silent: only `-Wreturn-type`
  showed the missing enumerator before the CWG1484 fix.
