# WP-652 — The x86 builtin table as plain data (start-up RSS)

Extends spec/landed/sema/WP-630.md "Target builtins" (the table and its
lookups). The measurements and the before/after tables are in
docs/status/perf-reflection.md "WP-652: start-up RSS". Nothing
observable changes: the rows, their ids, prototypes, attributes, features
and immediate checks are those WP-630 generated, and every lookup answers
as before.

## The cost it removes

kiln++ is a position-independent executable. Before this package the x86
table was a `const` slice of rows holding `&'static str` and
`&'static [Imm]` fields:
- each crate that inlined its accessor got its own copy, four in the
  release binary (155,760 bytes each in `.data.rel.ro`);
- each copy carried about 6,384 `R_AARCH64_RELATIVE` relocations
  (153 KB of `.rela.dyn` each), which the loader reads and applies at
  every start, dirtying every page of the copy.

Together that was about 1.2 MB of binary read or dirtied before `main`,
on every compile, the empty TU included.

## Layout

`scripts/gen-x86-builtins.py` writes `crates/kiln_ast/src/x86_builtins.rs`
as three `static`s, so the binary holds one copy:
- `STRS: &str`: the names in row order, then each distinct prototype and
  features string once (ASCII; about 63 KB);
- `IMMS: [Imm; N]`: each distinct immediate-check list once;
- `X86: [Packed; 1947]`: per row, `(offset, length)` of the name,
  prototype and features in `STRS`, the attributes, `(offset, length)` of
  the checks in `IMMS`, and the header mark (`h` rows). 20 bytes a row,
  no pointers.

The rows are plain data in `.rodata`: no relocation (one for `STRS`
itself), nothing dirtied, and a page is read only when a lookup touches
it. The generator's `--reemit` rewrites the file from its own rows (this
layout or the pre-WP-652 one) without probing clang; it was used for this
change, and parsing both layouts gives the same 1,947 rows.

## Lookups (`kiln_ast::decl::builtin::x86`)

- `by_name` is a binary search over the packed rows, comparing names
  sliced from `STRS`; `is_x86` is a range check.
- `row(id) -> Option<Row>` decodes the row and returns it **by value**
  (it returned `Option<&'static Row>`). `Row` is unchanged: `info`
  (`&'static str` name and prototype), `features`, `imms`, `header`.
- `all()` is replaced by `rows()` (an iterator of decoded rows) and
  `len()`.
- `builtin::info(id)` returns `Option<Info>` by value (it returned
  `Option<&'static Info>`), since an x86 row's `Info` is decoded on
  access. Its callers in kiln_sema and kiln_codegen are updated.

## Tests

`crates/kiln_ast/tests/x86_builtin_table.rs`: every row decodes, its id is
`BASE` plus its index, `by_name` and `builtin::by_name` find it, the
names are sorted and distinct, seven rows are header builtins; sample
rows carry their prototype, attributes, features and checks (`aadd32`,
`addpd512`, `tdpbf16ps` with four checks, `readeflags_u32`, `_mm_pause`,
`_mm_getcsr`); ids outside the table are not x86 builtins.
