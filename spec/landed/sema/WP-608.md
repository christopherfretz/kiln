# WP-608 — Injected-class-name in pointer-to-member types and expressions; base-qualified data members in class templates

[temp.dep.type]/1, [temp.local]/1, [dcl.mptr]/1, [expr.unary.op]/3,
[expr.mptr.oper]/4, [class.qual]/1. The rule is in `spec/sema.md` §5.21,
"The injected-class-name in pointers to members; base-qualified members"
(pointer in `spec/sema-templates.md` §4.7).

libstdc++'s <regex> did not compile: `_Scanner<_CharT>` stores
`&_Scanner::_M_eat_escape_ecma` in a `void (_Scanner::*)()` and calls it
through `this->*`, and `_State<_CharT>::_M_opcode()` returns
`_State_base::_M_opcode`. The non-template spelling of each shape already
compiled; three causes, each about the class template's pattern:

- `Scan::` as a nested-name-specifier named the pattern's plain record
  type (`Sema::nns_component` used `tag_type`), so
  `typedef void (Scan::*Fn)()` was the non-dependent `void (Scan::*)()`,
  never substituted, and `this->*fn` with `Scan<char>*` was rejected. The
  specifier now takes the class's `this_class_type`: the
  `InjectedClassName` type `Scan<P...>` in a class template or partial
  specialization (clang's `InjectedClassNameType` specifier).
- `&Scan::f` in the pattern had the class type `tag_type(pattern)`, and its
  operand `DeclRefExpr` dropped the qualifier, so instantiation rebuilt
  the name as the implicit member access `(*this).f` and `&` of it was
  "cannot create a non-constant pointer to member function".
  `Sema::member_pointer_of` now types it with `this_class_type` of the
  declaring class and keeps the written qualifier on the operand.
- `Base::m` for a data member formed `(*this).Base::m` without recording
  the qualifier on the `MemberExpr` (`field_access` dropped it), so the
  instantiation looked `m` up by name in `Scan<char>` and found the
  member function `m()`. `member_of_object` now records it
  (`Sema::field_access_extra`), and instantiation looks `m` up in `Base`.

`std::regex` construction, `regex_match` and `regex_search` compile and
run under libstdc++ 14 (system), libstdc++ 16.1 and libc++.
