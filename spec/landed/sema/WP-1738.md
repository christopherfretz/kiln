# WP-1738 — no static gaps: operators

WP-1738 removed the static gaps GAP-052..GAP-058 of
`docs/status/static-gaps.md` (operators). Two follow the standard now,
five were dead and became exhaustive matches, `unreachable!` arms or
were deleted with the state behind them. Testing them found four bugs,
three fixed and one left as an `xfail(kiln)` repro. Tests are under
`tests/conformance/`.

## GNU binary conditional on class types (GAP-052)

- `x ?: y` with a class-typed `x` ([expr.cond] with `x` as the second
  operand; clang `ActOnConditionalOp`): a class or array prvalue `x` is
  materialized, so it is evaluated once; it is contextually converted
  to `bool` (a conversion function); code generation (`agg_conditional`
  for an aggregate result) and the Oven (`init_inner`) bind the common
  operand once and evaluate it once
  (`expr.cond/gnu-binary-conditional-class-{run,constexpr,errors}.cpp`,
  `ast/expr.cond/gnu-binary-conditional-class.cpp`).
- [expr.cond]/7: when one class-typed arm is a glvalue and the other a
  prvalue, the copy of the glvalue is a temporary bound to the
  full-expression, so it is destroyed
  (`expr.cond/p7-glvalue-arm-copy-destroyed-run.cpp`).

## Overload resolution with constraints (GAP-053, dead)

- The overload set's "uncertain" flag was set only from
  `decls.cold.requires_clause`, which nothing wrote (trailing
  requires-clauses are in `templates.trailing_requires`). The flag, its
  setters and readers, and the cold map are deleted; the more-constrained
  rule ([over.match.best.general]/2.6) already decided every set. PCH
  format 74 (`over.match.best/more-constrained-operators-{run,ambiguous}.cpp`).

## Template rebuild of operator calls (GAP-054, GAP-058, dead)

- Every `CXXOperatorCallExpr` overload resolution forms is rebuilt:
  `()`, `[]`, `->`, `co_await` (`operator_coawait`), one operand (or
  postfix `++`/`--` with its `int`) as unary, two as binary. Other shapes
  are `unreachable!`. A `CXXRewrittenBinaryOperator` always stores its
  two written operands and is formed again from them
  ([over.match.oper]/3.4, /8; P2468)
  (`over.match.oper/template-operator-calls-rebuilt-run.cpp`).

## Built-in unary and binary operators (GAP-055, GAP-056, dead)

- `builtin_unary` never sees `__extension__` (built by `act_on_unary`
  first) or `co_await` (a `CoawaitExpr`): an `unreachable!` arm.
- `builtin_binary` lists the compound assignments explicitly, so its
  match is exhaustive and has no fallback arm.

## Member access through a mixed lookup result (GAP-057)

- A member function or typedef-name redeclaring a member as a different
  kind of entity ([basic.scope.scope]/4) is invalid (clang
  `MergeFunctionDecl`, `MergeTypedefNameDecl`); `member_access` drops
  invalid declarations while a valid one remains (clang
  `LookupResult::resolveKind`), so `s.m(1)` after `int m; void m(int);`
  is "called object type 'int' is not a function or function pointer".
  Any other set that is not all member functions is "reference to 'm'
  is ambiguous" ([basic.lookup.general]/4)
  (`expr.ref/member-redefined-as-different-kind.cpp`).

## Bugs found and fixed

- A non-member `operator co_await` (or other operator) found only at
  instantiation and not viable for the operands no longer draws the
  two-phase "neither visible in the template definition nor found by
  argument-dependent lookup" error: `two_phase_operator` resolves a
  candidate set and diagnoses only a viable best function (clang
  `DiagnoseTwoPhaseOperatorLookup`)
  (`expr.await/operator-coawait-nonviable-in-template-run.cpp`).
- The Oven bridge defines a defaulted comparison under `lend_oven`
  (building the body folds constants), and every synthesized definition
  (`push_synth`) is built with the dependent depth zeroed, so a defaulted
  comparison first required inside a template's definition values its
  immediate invocations
  (`class.compare.default/first-required-in-template-run.cpp`).

## Remainder

- A non-template member function after a member variable template of its
  name is not diagnosed (`pick_prev_function` skips templates for a
  non-template function): `xfail(kiln)` in
  `basic.scope.scope/member-function-after-variable-template.cpp`.
