# WP-566 — Deduction through a non-type pack expansion of consteval calls on the deduced pack

Extends spec/sema-templates.md §6.1 step 2 (a P whose template parameters all sit in
non-deduced contexts).

A call parameter `const Spec<conv<Args>()...>&` (spelled out, or through an alias
`FS<Args...>`) against a string literal failed with "could not match": the CWG1391 skip
asks `has_deducible_pack_expansion` (crates/kiln_sema/src/templ/deduce_call.rs) whether a
template-argument pack expansion in P is deducible, and it answered yes for every non-type
pattern. Now a non-type pattern is deducible only when it names a non-type template
parameter of the deduced depth as a bare reference (`nttp_of_expr_at`, the same
look-through `deduce_expr_arg` uses: implicit casts, parens, alias substitutions). Any
other expression (`conv<Args>()`, `sizeof(Args)`) is a non-deduced context
([temp.deduct.type]/5.3): the failed match is ignored, `Args` is deduced from the trailing
`const Args&...` (or is empty), and the literal converts to the substituted P through its
consteval constructor before the function type is substituted. `Spec<N...>` with
`template <int... N>` still deduces, and a mismatch there still fails; a parameter used
only in a non-deduced argument still reports "couldn't infer template argument".

Tests: `tests/conformance/temp.deduct.type/nttp-pack-expansion-non-deduced-{alias,spelled,empty,fail}.cpp`.
