# WP-1053 — partial-specialization ordering tails

WP-1017 left three gaps in how class and variable template partial specializations are checked and ordered (`templ/order.rs`). Every behaviour below is matched against clang 22 and clang 19, which agree on all of it. The rules are in spec/sema-templates.md §4.4 step 4 and "Landed (WP-1017, WP-1053)".

- **Constrained partial specializations** ([temp.spec.partial.order], [temp.func.order]/6.2.2, [temp.constr.order]).
  - Root cause, partial vs partial: `partial_more_specialized` compared constraints whenever both directions of deduction succeeded. So `requires C<T> Y<T*, U*>` and `requires D<T> Y<U*, T*>` picked the `D` one for `Y<int*, int*>`. Clang reports that as ambiguous: it compares constraints only when the template heads are equivalent and the arguments are the same.
  - Fix, partial vs partial: that condition is now applied (`same_template_heads`, `flat_canonical`). The constraints come from `partial_constraints`, which takes a redeclared member partial's constraints from the original.
  - Root cause, partial vs primary: the check against the primary skipped constrained partials, so `template <D T> struct K; template <C T> struct K<T>` was accepted.
  - Fix, partial vs primary: `primary_at_least_as_specialized` became `not_more_specialized_than_primary`, a port of clang's `isMoreSpecializedThanPrimary`. It deduces in both directions with packs taken as a whole and the deduction finished. When the partial is equally specialized, it compares constraints under the same conditions, from C++20.
    - The "similar constraint expressions" notes follow the diagnostic. `similar_atom_notes` was split out of the overload-ambiguity helper.
  - Tests:
    - `temp.spec.partial.general/constrained-not-more-specialized.cpp`;
    - `temp.spec.partial.order/constrained-partial-ordering-ambiguous.cpp`;
    - `temp.spec.partial.order/constrained-partial-selection-run.cpp`;
    - `temp.constr.order/class-template-partial-specializations.cpp`, a `verify` port of clang's test less its `E` case (see follow-ups).
- **Member-template partial specializations** ([temp.spec.partial.member]).
  - Root cause: a partial specialization of a member template of a class template was never checked against its primary. When the enclosing class was instantiated, `Substituter::member_partial_spec` redeclared it without running the checks, and the deducibility error was printed only once.
  - Fix: `member_partial_spec` runs `check_partial_more_specialized` and `check_partial_deducible` on the redeclared partial, the way clang does at instantiation. This covers in-class and out-of-line partials.
    - The deducibility error is `per_instantiation`, so it prints at the definition and once per instantiation, as with clang.
    - Ordering among member partials after instantiation was already right; the run test covers it.
  - Test: `temp.spec.partial.member/member-partial-checked-per-instantiation.cpp`.
- **Pack expansions not last** ([temp.deduct.type]/9, [temp.spec.partial.general]/8-9).
  - Root cause, deduction: `deduce_arg_list_packs` deduced the arguments that come before a non-final pack expansion.
  - Root cause, deducibility: `check_partial_deducible` skipped every partial that had a pack.
  - Root cause, primary arguments: `check_partial_args` missed the primary's own arguments when one of them is a pack (`G<Ts...>`).
  - Fix: a pack expansion before the end of the list now makes the whole list non-deduced, as clang's `hasPackExpansionBeforeEnd` does. The deducibility check now deduces pack expansions as a whole, and `check_partial_args` looks through the one-element pack.
    - `F<T..., int>` is reported unusable. It still matches `F<int>` with `T` empty, as with clang.
    - In partial ordering, a template template pack expansion `Bs'...` is now deduced as a whole, as a type one already was (`template_expansion_parts`). Without that, the new primary check rejected `ext<B, Bs...>` of `template <template <class> class... Bs> struct ext` (`temp.variadic/template-template-pack-expansion-partial-spec-run.cpp`).
  - Test: `temp.spec.partial.general/pack-expansion-partial-spec-checks.cpp`.

Follow-ups:

- A partial specialization that repeats the primary's arguments with different constraints gets "redefinition of 'E'" where clang reports "requires clause differs in template redeclaration" / "type constraint differs in template redeclaration". Both reject; only the wording differs. `templ/spec.rs` `check_partial_args`.
- A primary non-type parameter typed `auto` or by another parameter is still not checked against the primary (`templ/order.rs` `not_more_specialized_than_primary`).
