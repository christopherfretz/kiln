# WP-1109 — class triviality per eligible special member ([special]/6)

WP-1090 left `N(...) = delete; N() = default;` with `__has_trivial_constructor(N)` and `__is_pod(N)` 0 (clang: 1). The cause was one triviality bit per kind that required every declared member to be trivial, and no [special]/6 eligibility for constrained members. Rules: spec/sema-class.md §4.3 ("Two bits per kind") and §4.7.2; ABI: spec/abi.md §8.13.

- **Eligibility** (`class/special/prospective.rs` `select_eligible_special_members`, called at `}` after destructor selection):
  - It marks ineligible user-declared constructors and assignment operators `FnSpec::not_selected`, as clang `SetEligibleMethods` does.
  - A member is ineligible if its constraints are unsatisfied, or if another satisfied, constrained member of the same kind is at least as constrained (`subsume.rs` `at_least_as_constrained`).
  - "Same kind" (`same_special_kind`) compares the first parameter type and the object parameter.
  - Deleted members stay eligible (clang).
- **Two bits per kind** (`kiln_ast` `DefinitionBits`):
  - `TRIVIAL_*` now means clang `HasTrivialSpecialMembers`: some eligible member is trivial.
  - New `NONTRIVIAL_{DEFAULT_CTOR,COPY_CTOR,MOVE_CTOR,COPY_ASSIGN,MOVE_ASSIGN}` (bits 57–61) mean clang `hasNonTrivial*`.
  - Both are computed in `implicit.rs` `special_member_bits` from eligible members only.
  - `TRIVIALLY_COPYABLE` is now "no non-trivial copy/move, and a trivial destructor" (`with_trivially_copyable`).
  - New helpers `Sema::has_nontrivial` and `Sema::all_trivial`.
- **Readers audited**:
  - Type traits (`traits.rs`, `traits/special.rs`, `traits/cxx26.rs`):
    - `__has_trivial_*`, `__is_trivial` and the `__has_nothrow_*` shortcuts use `all_trivial`.
    - `__is_pod` uses clang `isTrivial`.
    - The `can_pass_in_registers` and implicit-lifetime loops skip `not_selected` members.
  - `kiln_abi::call::can_pass_in_registers` skips deleted and `not_selected` constructors.
  - The `isValidVarArgType` checks (sema `expr.rs`, oven `compile/class.rs`) read `NONTRIVIAL_*`.
  - `new_class_default` in `new_delete.rs` now always selects the default constructor. It elides the construct expression only when the selected constructor is trivial.
  - Unchanged, because they already match clang: `trivial_abi.rs`, the C++03 union check (`decl.rs`), `class_b_attrs.rs` (loader_uninitialized), the lambda capture side-effect check, the uninitialized-use POD check (`ctorinit.rs`), the literal-type note (`members.rs`), debug info (`DIFlagNonTrivial`, constructor homing), and every codegen/oven construct site, which reads the selected constructor's `FnSpec::is_trivial`.
- **Breakage fixed**: an accepts-invalid. `new D` / `new D[2]` with a deleted default constructor, or with an implicitly deleted one (reference or const member, deleted member constructor), compiled without an error, because the `TRIVIAL_DEFAULT_CTOR` shortcut skipped selection. Regression test: `tests/conformance/expr.new/default-init-deleted-ctor.cpp`.
- **Tests**:
  - `class.prop/trivial-eligible-special-members.cpp`: 42 trait asserts; kiln, clang++-19 and clang++-22 agree.
  - `class.default.ctor/eligible-ctor-side-effects-run.cpp`: counts constructor calls through new, new[], default-init, value-init, arrays and members.
  - `tests/codegen/abi_matrix_eligible.cpp`: constrained copy, move and destructor, plus a deleted copy constructor; IR is equal to clang 19 and 22 on both targets.
- **BMI**: no triviality bits are serialized yet. WP-1065's class-layout serialization must carry `NONTRIVIAL_*` and `not_selected` on special members.
- **Not done**: kiln omits the `candidate constructor` notes after `call to constructor of 'N' is ambiguous` (both var-init and new). This was already on main and is a diagnostic-only issue.
