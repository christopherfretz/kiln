# WP-610 — `__builtin_prefetch`, `__builtin_ia32_pause` and a GCC builtin audit

Extends spec/sema.md (builtins), spec/codegen.md (builtin lowering) and
spec/oven.md (builtins not evaluated).

## `__builtin_prefetch(addr [, rw [, locality]])`

- Table: `PREFETCH` = 976 (clang 19 `Builtin::BI__builtin_prefetch`),
  signature `vvC*.`, `NoThrow, Const` (`kiln_ast::decl::builtin` EXTRA).
- Sema (`Sema::check_prefetch`, after `check_builtin_ice_args`; clang
  `BuiltinPrefetch`):
  - `addr` is converted as a `const void *` parameter. The variadic tail
    takes the default argument promotions.
  - More than three arguments: `too many arguments to function call, expected at
    most 3, have N` at the `)`.
  - Arguments 2 and 3 must fold, unless they are value-dependent
    (`argument to '__builtin_prefetch' must be a constant integer`, a
    floating `1.0` included). They must also lie in [0, 1] and [0, 3]
    (`argument value V is outside the valid range [0, M]`). Both
    diagnostics point at the callee.
  - Dependent arguments are checked on the instantiated call.
- Codegen: `call void @llvm.prefetch.p0(ptr addr, i32 rw, i32 loc, i32 1)`.
  `rw` defaults to 0 and `loc` to 3. A folded argument is a constant;
  otherwise it is truncated or extended to i32. Under oracles 19 and 22 the
  IR equals clang's (`tests/codegen/builtin_prefetch.cpp`).
- Oven: the call is **not** a constant expression. The brief proposed a
  no-op, but clang 19, clang 22 and GCC 16 all reject
  `constexpr int g() { int x; __builtin_prefetch(&x); return 1; }`
  (`subexpression not valid in a constant expression`). kiln follows the
  oracle: the builtin is on the Oven's "not evaluated by clang" trap list
  (`kiln_oven/src/compile/builtins.rs`).

## `__builtin_ia32_pause()`

- `IA32_PAUSE` = 2152, a kiln-private id like the NEON rows' (clang
  numbers it 1644 at 19 and 2231 at 22, so the dump's `BuiltinAttr`
  value differs). The signature is `v` with `NoThrow`, giving
  `void () noexcept`.
- `Sema::target_has_builtin` makes it exist only for an x86-64 target:
  `lazily_create_builtin` and `is_builtin_name` both consult it. On any
  other target it is `use of undeclared identifier`.
  `__has_builtin` already answered from `kiln_pp` `features_table.rs`.
- Codegen: `call void @llvm.x86.sse2.pause()`, declared `nounwind`.
  Oven: trapped like prefetch.
- libstdc++ 14's `<bits/atomic_wait.h>` calls it, reached from `<memory>`
  on x86-64.

## Audit (common GCC/clang builtins referenced from a function body)

- Every builtin on the WP-610 list is declared, except these three:
  - `__builtin_memcpy_inline`
  - `__builtin_unpredictable`
  - `__builtin_cpu_supports`

  These are deferred.
- IR at `-fclang-compat=19` against clang 19 for the declared ones
  differs only for `__builtin_constant_p(x)` on a non-constant at `-O0`.
  clang emits `llvm.is.constant.*` + `zext`; kiln emits no intrinsic call. This is
  deferred.
