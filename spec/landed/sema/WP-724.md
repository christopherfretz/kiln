# WP-724 — rocksdb through its own build and tests (M8 wave 3)

rocksdb v10.7.5 built with kiln++ through its own CMake build and a
bounded selection of its gtest suites (docs/status/oss/rocksdb.md). Each
fixed behaviour below is a kiln bug the build found, reduced to a
standalone conformance test; the rule is stated in the spec named.

## Changes

- **offsetof designates a member of a base class**
  ([class.member.lookup], [support.types.layout]/1; spec/sema.md
  `__builtin_offsetof`). The member name is found by class member lookup
  instead of the class's own table, and the base subobject's offset is
  added; an ambiguous lookup and a member of a virtual base are
  diagnosed as clang does. kiln said "no member named" (rocksdb's
  `cache/cache.cc` options table).
  Tests: `tests/conformance/ext.gnu.offsetof/base-class-member-run.cpp`,
  `tests/conformance/ext.gnu.offsetof/base-class-member-diagnostics.cpp`.
- **A class using-declarator through another class is not a
  redeclaration** ([namespace.udecl]/10; spec/sema.md "Class scope").
  Only two using-declarators naming the member through the same class
  are an error; `using TDB::Write; using PDB::Write;`, where PDB already
  re-exports TDB's overloads, is valid and adds no second shadow. kiln
  rejected it per shadow (rocksdb's `write_prepared_txn_db.h`).
  Tests: `tests/conformance/namespace.udecl/p10-same-member-through-other-class-run.cpp`,
  `tests/conformance/namespace.udecl/p10-class-redeclaration-same-class.cpp`.
- **NEON widening multiply** (`__builtin_neon_vmull_v`, codegen
  `neon.rs` `Shape::Mull`; spec/codegen.md NEON). Reached by
  `vmull_{s,u,p}{8,16,32}` and `vmull_high_*`. The type code names the
  wide `VTy` (16-, 32- or 64-bit elements; any other is "invalid type
  code"); both operands are bitcast to `VTy`'s lanes at half the width
  and the result is one call `llvm.aarch64.neon.{p,u,s}mull.<VTy>`:
  `pmull` for a poly element, `umull` for the unsigned bit, else
  `smull`, as clang 19 `EmitAArch64BuiltinExpr`. kiln said "not
  supported yet" (rocksdb's `util/hash.cc` and `util/xxhash.cc` via
  xxhash's `vmull_u32`).
  Tests: `tests/conformance/target.neon/ir-mull-19.cpp`,
  `tests/conformance/target.neon/mull-run.cpp`.
- **ACLE builtins** (spec/sema.md §5.4; spec/pp.md `__has_builtin`;
  codegen `arm.rs`). `kiln_ast::decl::builtin::arm` holds every
  `__builtin_arm_*` row of clang 19's `BuiltinsAArch64.def` outside the
  NEON/SVE/SME tables (prototype, attributes, required features;
  the prototype modifier `Z` is the 32-bit `int32_t` width: `Zi` `int`,
  `ZUi` `unsigned int`), declared only when the target is AArch64. Calls type-check
  from the prototype, except the exclusive accesses (clang
  `CheckARMBuiltinExclusiveCall`): `__builtin_arm_ldrex`/`ldaex(p)` and
  `__builtin_arm_strex`/`stlex(v, p)` take `p` decayed, a pointer (else
  "address argument to atomic builtin must be a pointer") to an integer,
  floating or pointer type (else "... must be a pointer to integer,
  floating-point or pointer (`<A>` invalid)", `<A>` the address as clang
  converts it: `const volatile T *` for a load, `volatile T *` for a
  store); a load has the pointee type, qualifiers kept, a store converts
  `v` to the unqualified pointee and is `int`. Codegen first checks the
  row's features against the function's (a missing one is clang's
  "needs target feature" error and the call is `poison`), then lowers as
  clang 19 `EmitAArch64BuiltinExpr`: `crc32{b,cb,h,ch,w,cw}` call
  `llvm.aarch64.crc32*(i32, i32)` with the data zero-extended,
  `crc32d`/`cd` `llvm.aarch64.crc32x`/`cx(i32, i64)`; `rbit`/`rbit64`
  `llvm.bitreverse`; `clz`/`clz64` `llvm.ctlz(x, false)` converted to
  the result type; `cls`/`cls64` `llvm.aarch64.cls`/`cls64` (`i32`);
  `nop`, `yield`, `wfe`, `wfi`, `sev`, `sevl` `llvm.aarch64.hint` 0-5;
  `dmb`/`dsb`/`isb` `llvm.aarch64.dmb`/`dsb`/`isb(i32)`. Any other ACLE
  builtin is "code generation for `<name>` is not supported yet" when
  its caller is emitted. For the hint and barrier names clang 22
  declares as `arm_acle.h` header builtins (`__dmb`, `__dsb`, `__isb`,
  `__sev`, `__sevl`, `__wfe`, `__wfi`, `__yield`), `__has_builtin`
  answers clang 19's table at either compatibility level (0 outside the
  MS modes), because kiln ships clang 19's header, which defines them
  only when `__has_builtin` says no.
  kiln said "use of undeclared identifier `__builtin_arm_chkfeat`" and
  "undeclared `__yield`" (rocksdb's `util/crc32c.cc` and
  `util/crc32c_arm64.cc`).
  Tests: `tests/conformance/target.acle/header-only.cpp`,
  `tests/conformance/target.acle/data-processing-run.cpp`,
  `tests/conformance/target.acle/ir-data-processing-19.cpp`,
  `tests/conformance/target.acle/exclusive-address-argument.cpp`,
  `crates/kiln_ast/tests/arm_builtin_table.rs`.
- **An inheriting using-declarator names the base through a typedef**
  ([class.qual]/2.2; spec/sema.md "Class scope"). In a class's
  using-declarator whose qualifier nominates class `C`, a name that is
  `C`'s injected-class-name names `C`'s constructors however the
  qualifier is spelled, not only when it repeats the last spelled
  component: `using BC::B;` with `typedef B<char> BC` inherits
  `B<char>`'s constructors. kiln said "no member named 'basic_regex' in
  'std::basic_regex<char>'" (rocksdb's `test_util/testharness.cc`,
  `using std::regex::basic_regex;`).
  Test: `tests/conformance/class.qual/p2-injected-class-name-after-typedef-run.cpp`.
- **A member of a pattern typedef after a specialization qualifier is
  classified after parsing the qualifier** ([dcl.ambig.res]/2;
  spec/parse.md lookahead). In `X<args>::type::name` with `type` a
  member typedef of `X`'s pattern naming a dependent type (`typedef T
  type;`), the lookahead cannot classify `name` in the pattern; it now
  parses the qualifier ahead as an unresolved specialization scope, so
  `sizeof(rr<V>::type::value_type)` is `sizeof` of a type-id. kiln said
  "'value_type' does not refer to a value" (rocksdb's
  `memtable/vectorrep.cc`,
  `sizeof(std::remove_reference<decltype(*bucket_)>::type::value_type)`).
  Test: `tests/conformance/dcl.ambig.res/sizeof-member-typedef-of-specialization-run.cpp`.
- **A braced argument of one element of the parameter's class converts
  as that element** ([over.ics.list]/3, [dcl.init.list]/3.10;
  spec/sema-overload.md [over.ics.list]). For an aggregate parameter
  type `X`, `{x}` with `x` of class `X` or derived from it is `x`'s own
  conversion, not aggregate initialization of `X`'s first member from
  `x`; for a reference parameter whose referee is reference-related to
  `x` the reference binds `x` (a failed binding is not viable, with the
  binding's note). kiln said "no matching function for call to
  'GetLiveFilesStorageInfo'" (rocksdb's `db/db_write_test.cc`,
  `db_->GetLiveFilesStorageInfo({lf_opts}, &files)`).
  Tests: `tests/conformance/over.ics.list/aggregate-single-element-of-class-run.cpp`,
  `tests/conformance/over.ics.list/aggregate-single-element-of-class-errors.cpp`.
