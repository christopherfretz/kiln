# WP-724 — rocksdb through its own build and tests (M8 wave 3)

rocksdb v10.7.5 built with kiln++ through its own CMake build and a
bounded selection of its gtest suites (docs/status/oss/rocksdb.md). Each
fixed behaviour below is a kiln bug the build found, reduced to a
standalone conformance test; the rule is stated in the spec named.

## Changes

- **offsetof designates a member of a base class**
  ([class.member.lookup], [support.types.layout]/1; spec/sema.md
  `__builtin_offsetof`). The member name is found by class member lookup
  instead of the class's own table, and the base subobject's offset is
  added; an ambiguous lookup and a member of a virtual base are
  diagnosed as clang does. kiln said "no member named" (rocksdb's
  `cache/cache.cc` options table).
  Tests: `tests/conformance/ext.gnu.offsetof/base-class-member-run.cpp`,
  `tests/conformance/ext.gnu.offsetof/base-class-member-diagnostics.cpp`.
- **A class using-declarator through another class is not a
  redeclaration** ([namespace.udecl]/10; spec/sema.md "Class scope").
  Only two using-declarators naming the member through the same class
  are an error; `using TDB::Write; using PDB::Write;`, where PDB already
  re-exports TDB's overloads, is valid and adds no second shadow. kiln
  rejected it per shadow (rocksdb's `write_prepared_txn_db.h`).
  Tests: `tests/conformance/namespace.udecl/p10-same-member-through-other-class-run.cpp`,
  `tests/conformance/namespace.udecl/p10-class-redeclaration-same-class.cpp`.
