# WP-685 — CLI11 through its own build and tests (M8 wave 1)

CLI11 v2.6.1 built with kiln++ through its own CMake build (library
tests, the Catch2 v2 single-header test suite, the examples and the
fuzz-corpus test) and CTest (docs/status/oss/cli11.md). Each fixed
behaviour below is a kiln bug the build found, reduced to a standalone
conformance test; the rule is stated in the spec named.

## Changes

- **An ignored narrowing warning still fails a substitution**
  ([temp.deduct.general]/8, [dcl.init.list]/3.7, [expr.const];
  spec/sema-templates.md "What SFINAE mode does"). clang's narrowing
  diagnostics (`-Wc++11-narrowing` in a list-initialization: type,
  variable and constant narrowing; in a converted constant expression)
  are `SFINAEFailure` ExtWarns: a substitution that forms a narrowing
  list-initialization fails whatever the warning's mapping. kiln failed
  it only while the warning mapped to an error, so under `#pragma GCC
  diagnostic ignored "-Wnarrowing"` (CLI11's `is_direct_constructible`)
  or `-Wno-narrowing` a probe `decltype(T{std::declval<double>()})` was
  well-formed for a `T` constructible only from an integer, and the
  overload it selected then narrowed outside SFINAE. Outside a
  substitution the ignored warning stays ignored.
  Test: `tests/conformance/temp.deduct.general/narrowing-ignored-still-substitution-failure.cpp`.
- **A default template argument after an instantiation-dependent
  argument is substituted with its value** ([temp.arg.general]/9,
  [temp.arg.nontype]/2, [temp.dep.constexpr]/2; spec/sema-templates.md
  §3.1 "value-dependent"). In a member of a class template
  `sizeof(member)` is instantiation-dependent (the current
  instantiation's `this`) but not value-dependent: kiln keeps it as
  written and folds it for the canonical argument list, but a default
  after it was substituted with the written expression, so
  `aligned_storage<sizeof(__buf_)>` kept a dependent
  `__find_max_align<…>::value` second argument and named the primary
  template, a one-byte union, instead of the `alignas(16)` partial
  specialization. libc++'s `std::function` swap then overflowed that
  temporary and every CLI11 binary built with `-stdlib=libc++` crashed in
  its static initialization (a miscompile; with libstdc++ CLI11 was not
  affected). The converted prior arguments are now kept as the arguments
  are checked, and a default substitutes them.
  Test: `tests/conformance/temp.arg.general/default-after-instantiation-dependent-argument.cpp`.
