# WP-663 — Memory report flag and fold/deduction constant factors

This WP changes spec/driver.md (the `-fkiln-memory-report` row),
spec/sema-overload.md ("Accounting": `Sema::memory`), spec/oven.md
("Trial folds": the variable-read, member-read and scalar-glvalue
whitelist entries; `Oven::memory`; `is_constant_initialized` through the
leaf walk) and spec/ast.md §4 item 10 (the recorded minimum argument
count). The measurements, the ranking of the eight items and the A/B
tables are in docs/status/perf-reflection.md, section "WP-663:
memory report and fold/deduction constant factors" (follow-up rows F13,
F15).

Nothing observable changes without the new flag. The following stay
byte-identical: every diagnostic and note and their order, every fold
result, the instantiation report's rows, the AST and the emitted IR.

## Changes

- **A1: `-fkiln-memory-report`** (`kiln_driver`). After the diagnostics,
  one `memory: <name> count=N live=N reserved=N` line per row of
  `ParsedTu::memory`, then `memory: total live=N reserved=N`. The rows
  are their producers': `Ast::memory` (with the type context's `types.*`
  and the `journal.*` and `instantiation.*` rows), the new
  `Sema::memory` (`sema.ovl.*`, `sema.redecl_index`,
  `sema.explicit_memo`) and the new `Oven::memory`, whose `oven.*`
  reserved bytes sum to `Oven::footprint`. A measurement aid, not a
  stable format.
- **B1: variable reads in the leaf walk** (`kiln_oven/src/leaf.rs`). A
  trial fold's lvalue-to-rvalue read of a variable is answered without
  bytecode in two cases: the known value of a usable constant integer
  whose global is resolved to a constant object, and a definite failure
  for a parameter or automatic variable that is neither usable nor
  laxly readable. `Oven::leaf_effects` then redoes the full path's Oven
  state changes in its order (provisional resolutions forgotten, global
  entries created in compile order, the first faulting read's global
  resolved, the static peak noted).
- **B2: `Oven::is_constant_initialized`** first walks the initializer
  with the leaf walk, with the variable's placeholder object placed as
  the full path places it. A reference variable, or anything the walk
  declines, takes the full path.
- **B4: member reads and scalar glvalue roots.** A read of a `.` member
  chain (non-static, non-reference, non-bit-field members of non-union
  classes) over a parameter or non-usable automatic variable is the
  same definite failure as a read of the variable. A fold of a scalar
  (`bool`, integer up to 128 bits) glvalue `DeclRefExpr` or
  `MemberExpr` is walked as its lvalue-to-rvalue read, except under
  `is_constant_initialized`. `->`, unions, bit-fields, reference members
  and usable bases decline.
- **A2: the minimum argument count with the parameter list**
  (`kiln_ast/src/decl.rs`). `DeclArena::set_params` records each
  function's minimum argument count in a one-byte side vector parallel
  to the function payloads (`DeclArena::min_args`; `decls.min_args` in
  the memory report). A default argument added to a parameter of a set
  list marks it unknown until `Ast::refresh_min_args` (called after an
  instantiated declaration's defaults are marked pending); more than
  254 counted parameters is unknown too. `Sema::fn_min_args` reads the
  byte and counts only when it is unknown; debug builds assert the
  byte against the count. The side vector stays out of
  `Ast::node_live_bytes`, so the instantiation report's `bytes` column
  is unchanged; counting it there would have added one byte per
  function and reordered the report's rows.

## Measured and not landed

- **A3: explicit-argument substitutions that create nodes.** Every
  repeat of such a key creates fresh expressions (and so new type
  nodes), so a memo of them would change the AST. Report-only.
- **A4: `LookupTables::insert_with_flags` scans** are at most 0.16% of
  S8 at N = 1,600. Unchanged.
- **B3: retained failed trial thunks.** A failure cannot be cached in a
  few bytes (a fold that fails can succeed later in the translation
  unit), and a failed thunk's code and functions can only be dropped
  when nothing was appended after them. After B4 the remaining failed
  thunks are about 8 K on rw and 12 K on tf, about 1.9 MB (0.7% of
  peak RSS) and 2.8 MB (2.4%) at the 237 bytes per thunk that B4's
  removals freed on rw. Unchanged.

## Test-only entries

`crates/kiln_driver/tests/driver.rs`: `memory_report_rows` (both modes;
the rows the specs name, no numbers). `crates/kiln_sema/tests/
trial_fold.rs`: `oven_memory_rows_sum_to_footprint`,
`variable_reads_agree`, `constant_init_agrees` and `member_reads_agree`
compare each answer and the Oven state (global entries, static space,
`static_bytes`, `globals_digest`) with a second Sema that runs the full
path only, in strict and lax mode. The `kiln_oven/leaf-check` feature
asserts every walk answer against the full path.
