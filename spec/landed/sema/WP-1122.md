# WP-1122 — closing the C++26 partials P3394R4 and P2686R5

The two DIS papers still marked `partial` in docs/STANDARD_SUPPORT.md were re-checked against main, the P2686 remainder was implemented, and both rows are now `done`. Rules: spec/sema.md §4.9 "Lifetime-extended temporaries of a constexpr local reference" and "Expansion statements" / "Binding a constexpr range"; spec/oven.md "Freezing"; spec/annotations.md §9.

- **P3394R4 (annotations)**: all four gaps listed on 2026-11-05 had already been fixed by WP-830, WP-866 and WP-867. Probes re-run against GCC 16.1 agree. Only the documentation was stale.
  - Base-specifier annotations, including per-element substitution over a base pack: `meta.reflection.annotation/base-specifier*.cpp`.
  - Per-parameter substitution of a function parameter pack's annotations: `meta.reflection.annotation/parameter-pack*.cpp`.
  - `[[="abc"]]` is `sema_annotation_invalid_value` ([temp.arg.nontype]/6.2). GCC 16.1 accepts it, so `dcl.attr.annotation/string-literal-neg.cpp` has no oracle.
  - A C++11 attribute-specifier-seq after a label's colon belongs to the sub-statement: `dcl.attr.annotation/label-colon*.cpp`.
- **P2686R5, lifetime-extended temporaries** ([expr.const.init]/2, [class.temporary]/6).
  - **Before**: `constexpr const int& r = 42;` in a function was rejected with "reference to temporary is not a constant expression". The temporary is an automatic object, so the static-storage freeze refused it.
  - **After**: it is constant-initialized at C++26 and the temporary lives on the stack. Before C++26 the program is rejected as before.
  - **Oven** (`kiln_oven`):
    - `compile/class.rs` `begin_static_extended` allocates a `constexpr` local's `Automatic` extended temporaries as `Origin::Let` objects, alongside the static ones, so the frozen pointer is `PtrBase::Temporary(t)`.
    - `value.rs` `automatic_referent` reports a temporary whose extending variable is a local. Sema's scoped usability (lambda capture) and codegen's no-fold rule therefore apply to it unchanged.
  - **Codegen**: no change. The temporary is emitted as an alloca, not a `_ZGR` global.
  - A non-const temporary (`constexpr int&& m = 3;`) is constant-initialized but not readable in a constant expression ([expr.const]/4), as clang reports at namespace scope.
- **P2686R5, automatic expansion range** ([stmt.expand]/5, `constexpr_opt auto&&`).
  - **Before**: a glvalue `constexpr` range of a local fell back to a `static constexpr auto` copy.
  - **After**: it is bound by reference.
  - **Sema** (`kiln_sema/src/expansion.rs`):
    - `RangeBind` is tried in the order Static, then Automatic, then Copy.
    - Automatic is a non-static `constexpr auto&&` with automatic `__begin`, `__end` and `__iter`. It is tried at C++26 only, and only for a `constexpr` for-range-declaration. Otherwise `iterating-neg.cpp`'s by-value parameter range would be accepted.
    - `expansion_decomp` takes the same choice for the destructuring form.
- **Tests**:
  - `expr.const/constexpr-ref-automatic-temporary{,-errors,-run}.cpp` and `stmt.expand/constexpr-range-automatic{,-run,-neg}.cpp` are `skip(clang)`: neither clang 22 nor GCC 16 implements P2686's automatic references.
  - `expr.const/constexpr-ref-automatic-temporary-cxx23.cpp` pins the C++23 rejection against clang.
- **Left (deliberate)**: the non-constexpr reference case of [expr.const.init]/2 (`auto& e = local;` constant-initialized) waits for an oracle (WP-514).
