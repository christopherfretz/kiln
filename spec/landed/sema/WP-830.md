## Divergences from GCC 16.1 (kiln follows the DIS)

- A private member function's name in `^^C::f` (GCC accepts).
- `[[="abc"]]` and other annotation values pointing into a string literal
  (GCC accepts).
- `lbl: [[=4]];` (GCC warns that the attribute is ignored).
- `Y<[: ^^vt :]<2>>` is accepted by both; read strictly, a splice
  followed by `<` in a template-argument is a splice-specialization-
  specifier only after `template`, so the draft arguably makes it
  ill-formed. Kiln matches GCC here (open question).

## Interface changes

- New diagnostics: `parse_splice_template_arg_unparenthesized`,
  `sema_annotation_invalid_value`.
- `AnnotArena::of_base` / `attach_base` (memory row `annot_bases`).
- `Sema::bad_tparg_base` is `pub(crate)`.
- Labels: the labeled-statement parse (`kiln_parse` `stmt.rs`) takes GNU attributes only.
