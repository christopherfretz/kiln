# WP-543 — template-id member calls on the implicit object rank the implicit object parameter

Extends spec/sema-overload.md §2.3. Clang 19 and 22 and GCC 16.1 agree on
every case below.

## Template-id callees naming members ([over.match.funcs]/4-5, [class.mfct.non.static]/2)

- `B::get<0>()`, unqualified `get<0>()` found in a base class, and
  `B::get<I>()` inside `B` were resolved as a plain `UnresolvedLookupExpr`
  call with no object argument, so `template<int> int& get()` and
  `template<int> const int& get() const` tied ("call to 'get' is
  ambiguous"); `this->get<0>()` and the non-template `B::get()` already
  went through the member-call set. `resolve_unresolved_call`
  (`overload/call.rs`) now turns a template-id whose candidates are
  members into the member overload set on the implicit `*this`
  (`implicit_member_template_id`, `overload/member.rs`) and resolves it
  with `resolve_member_call`; a dependent `this` (or a dependent base on
  the way) gives the dependent `this->get<I>`, resolved at instantiation.
  The recursive variadic tuple whose `get<I>()` recurses through
  `Base::template get<I - 1>()` compiles (a downstream
  binding library).
- A call whose candidates all need an object and where no implicit
  `this` exists is "call to non-static member function without an object
  argument" at the name (`lacks_implicit_object`), not an ambiguous call,
  for template-ids and non-template sets alike.

Tests: `tests/conformance/over.match.funcs/template-id-implicit-object*.cpp`.
