# WP-1072 — access through a [temp.friend]/5 member friend

`template<class T> friend class A<T>::Member;` was accepted (WP-1054) but
granted nothing, so `A<int>::Member::get` could not read the befriending
class's private members: a rejects-valid on code libc++, Boost and LLVM
write. Spec: spec/sema-templates.md §4.8 "A member of every
specialization", spec/sema-class.md §2.4.

- **Model: the standard's rule, by deduction.**
  - `Sema::declare_member_friend_{class,fn}` (class/member_friend.rs)
    recognise a friend with its own template head whose
    nested-name-specifier names a specialization of a class template (also
    through member classes, `A<T>::X::Y`) with the head's parameters among
    its arguments. The parser now records the declarator's qualifier
    (`Declarator::qualifier_nns`) and the befriended name of a dependent
    class-key reference (`DeclSpec::dependent_tag_name`).
  - Each is recorded as a `MemberFriend` (template, written arguments,
    member path, name, function type) against its `FriendDecl`, which goes
    in the class's friends list.
  - `effective_context` asks, for every class and function of the context,
    which member friends befriend it (`member_friend_grants`): same kind,
    name and member path, the head deduces from the written arguments
    against the specialization's, and a function's substituted type is the
    member's. Members of a pattern or partial specialization are
    speculative friends, re-checked per instantiation (the existing
    `dependent_access` replay). Answers are cached per (friend, member).
  - In a class template the friend is re-registered per instantiation with
    the substituted specifier (`instantiate_member_friend`).
- **Why not clang's shortcut.** clang turns off access control for the
  befriending class. That accepts every program the rule accepts, plus
  programs that read members the rule denies (a sibling member, another
  template's `Member`, a non-matching specialization or function type;
  g++ 14 denies those too). kiln keeps the rule; the extra programs clang
  accepts are the denied test, `skip(clang)`. Where clang accepts a
  declaration form kiln follows it: a nested path, a member function
  template, any class-key.
- **Diagnostic.** clang's `-Wunsupported-friend` (`sema_unsupported_friend`)
  once per declaration in its pattern, at the befriended name, also for a
  function; the specifier is spelled `'A<T>'` (clang 22) or `'A<T>::'`
  (`-fclang-compat=19`). The text is clang's although kiln does not turn
  off access control.
- **Tests** (`temp.friend/`): `dependent-member-class-friend-run.cpp`
  (flipped from xfail), `dependent-member-friend-variants-run.cpp`
  (member class with mem-initializers and member functions, nested
  `X::Y`, member function, member function template, explicit and partial
  specializations), `dependent-member-friend-class-template-run.cpp`,
  `dependent-member-friend-warning{,-clang19}.cpp` (every warning matched
  against clang 22 / 19), `dependent-member-friend-denied.cpp`.
- **Gap.** Member friends are a Sema side table: a precompiled header or a
  module replays its source and so declares them again, but the module
  declaration image (`-fkiln-bmi-image`, off by default) does not record
  them.
