# WP-865 — warnings kiln accepted and ignored, and two default errors

Ports of clang 19's checks for flags real `-Werror` builds pass. Groups
and nesting are clang's (spec/diag.md §3.1); none of these is in `-Wall`
except `-Wunused-lambda-capture` (through `unused`), and only
`deprecated-copy` (with its user-provided-copy subgroup) is in `-Wextra`.

- **`-Wmissing-template-arg-list-after-template-kw`** ([temp.names]/6,
  an error by default; parser `templ.rs`/`expr.rs`,
  `Sema::act_on_template_kw_member_q`): a name after the `template`
  keyword (`T::template f`, `e.template f`, `N::template v`,
  `typename T::template X`) that is not followed by a template argument
  list is diagnosed at the name, unless it names a class or alias
  template used as a type or is a template template argument. Dependent
  and non-dependent contexts alike; not again at instantiation. Tests:
  `temp.names/missing-template-arg-list-after-template-kw*.cpp`.
- **`-Wc++11-narrowing-const-reference`** (an error by default, in
  `c++11-narrowing`; `conv/narrow.rs`, `init.rs`): a braced initializer
  element that binds an aggregate's reference member, or a list
  constructor call's reference parameter (`class/special/define.rs`
  `ctor_args`, [dcl.init.list]/3.7), to a temporary of arithmetic type
  narrows like the temporary's own initialization ([dcl.init.list]/3.10,
  [dcl.init.ref]/5.4). The ids name the referenced type; the cast note is
  given only when the reference type is spelled through a typedef, as
  clang. Tests: `dcl.init.list/narrowing-const-reference*.cpp`.
- **`-Wdeprecated-copy` family** ([depr.impldec]/1;
  `class/special/define.rs`, clang `diagnoseDeprecatedCopyOperation`):
  when an implicitly declared copy constructor or copy assignment is
  defined and the class has a user-declared other copy operation, the
  warning is `deprecated-copy` (user-declared, defaulted) or
  `deprecated-copy-with-user-provided-copy` (user-provided); with a
  user-declared destructor instead, `deprecated-copy-with-dtor` or
  `deprecated-copy-with-user-provided-dtor`. At the user-declared member,
  once per implicit member, with a note where the definition was first
  required. `-Wextra` enables only the first two; `-Wdeprecated` all four
  (`deprecated-copy-dtor` ⊃ `deprecated-copy-with-dtor`). Tests:
  `depr.impldec/deprecated-copy*.cpp`.
- **`-Wunused-lambda-capture`** (in `unused`; `lambda/capture.rs`, clang
  `DiagnoseUnusedLambdaCapture`): at the end of a non-dependent lambda,
  an explicit capture the body never odr-used is "lambda capture 'x' is
  not used", one named only in unevaluated operands or as a constant
  "is not required to be captured for this use", with a fix-it removing
  the capture with the comma before it (or after it, when no used
  capture or default precedes it). Exempt: captures whose copy may have
  side effects (volatile, an incomplete or not trivially copyable or
  destructible class type, an init-capture whose initializer may have
  side effects), an init-capture `_`, a generic lambda's init-capture
  named without an odr-use; clang gives up on a lambda with a rejected
  explicit capture. Each element of an expanded capture pack warns. An
  instantiated lambda is checked per instantiation. A name in a
  discarded statement is not odr-used and is not captured
  (`discarded-statement-no-capture.cpp`). Tests:
  `expr.prim.lambda.capture/unused-lambda-capture*.cpp`.
- **`-Wshadow` family** (`shadow.rs`, clang `CheckShadow`,
  `CheckShadowInheritedFields`): a local variable, parameter, typedef,
  alias or structured binding whose name hides a declaration found by
  redeclaration lookup in an enclosing scope warns "declaration shadows a
  {local variable|variable in …|field of 'C'|…}" with a note at the
  previous declaration. Redeclaration lookup searches the block and class
  scopes, then only the innermost enclosing namespace scope (plus, for an
  out-of-line definition, the namespaces semantically between), with its
  inline and unnamed namespaces: not an outer namespace, nor one a
  using-directive nominates. Through a using-declaration the hidden
  entity is the one it names (one entity found twice, through a
  using-declaration and a using-directive in the same scope, is missed).
  An unnamed namespace prints `'(anonymous)'` (`'N::(anonymous)'`).
  Members of base classes are not candidates (only
  classes that enclose the declaration's context); `extern` locals, the
  `_` placeholder and instantiations do not warn. A field hidden in a
  static member function does not warn; clang 22 also exempts explicit
  object member functions and lambdas inside either (`-fclang-compat=22`;
  clang 19 checks the declaration's own context only). Flavours:
  - `shadow-uncaptured-local`: a lambda local hiding an enclosing local
    the lambda does not capture (a captured one is `shadow`, with a note
    at an explicit capture); a field follows whether `this` is captured.
  - `shadow-field-in-constructor`: a constructor parameter hiding a field,
    at the end of the constructor; if the body modifies the parameter,
    `shadow-field-in-constructor-modified` at the modification instead.
  - `shadow-field`: a non-static data member or member function
    parameter hiding a non-private member of a base reachable through a
    path whose base-specifiers after the first are not private, once per
    base (a virtual base once).
  - an enumerator of an unscoped enumeration (clang `ActOnEnumConstant`)
    hiding a variable, function, field, binding or enumerator: diagnosed
    before the redefinition error clang then gives, not for an overload
    set or a scoped enumeration, once for a template. clang 19 warns for
    every such enumerator; at `-fclang-compat=21` and later a member
    enumeration's enumerator warns only on a member of its own class, and
    at 22 not on a field from a static or explicit object member function.
    An enumerator with a template parameter's name is the error
    "declaration of 'T' shadows template parameter" ([temp.local]/6).
  - `shadow` holds the modified-constructor form; `shadow-all` holds
    `shadow` and the three others.
  Tests: `basic.scope.block/shadow*.cpp` (`shadow-redeclaration-lookup.cpp`),
  `class.base.init/shadow-*.cpp`, `class.member.lookup/shadow-field.cpp`,
  `class.mfct.non.static/shadow-static-member-function*.cpp`,
  `expr.prim.lambda.capture/shadow-*.cpp`, `dcl.enum/shadow-enumerator*.cpp`,
  `temp.local/enumerator-shadows-template-param.cpp`.
- **`-Wimplicit-int-float-conversion`** (`impcast.rs`, `int_range.rs`;
  clang `CheckImplicitConversion`, `GetExprRange` approximate): an
  integer (not enumeration) operand converted to a floating type outside
  a braced list (any element below an `InitListExpr` is exempt) is
  checked when the likely bit range of the operand (`expr_int_range`:
  folded value, narrowing implicit casts, `&`, `%`, `/` and `>>` by a
  constant, `1 << n`, comparisons, conditionals, bit-field widths,
  unfixed enumerations by their enumerators; other arithmetic joins its
  operands) exceeds the target significand (float 24, double 53 bits).
  Each arm of a conditional is checked on its own. A constant whose
  value changes under round-to-nearest-even is
  `-Wimplicit-const-int-float-conversion` (on by default; "changes value
  from 16777217 to 16777216", the new value printed with the significand
  precision), a run-time behavior diagnostic (`diag_if_reachable`: not in
  unevaluated operands, unreachable code, consteval bodies or constexpr
  variable initializers); any other operand is "may lose precision"
  (off by default). A non-dependent conversion in a template warns at
  the definition and again in each instantiation. Groups:
  `implicit-float-conversion` ⊃ `implicit-int-float-conversion` ⊃
  `implicit-const-int-float-conversion`; `conversion` ⊃ the first. Tests:
  `conv.fpint/implicit-{int,const-int}-float-conversion*.cpp`.
