# WP-1106 — expansion-statement element temporaries (CWG3043)

WP-1081 recorded that an enumerating element's temporaries outlived the element's declaration in kiln but not in GCC 16.1. The rule that decides it is CWG3043 as accepted into the C++26 DIS: [class.temporary]/8 adds a context in which a temporary created in an element E of an enumerating expansion-init-list persists for the lifetime of the for-range-declaration that E initializes, and /9 extends a destructuring expansion-initializer's temporaries to the lifetime of its reference. GCC 16.1 implements the earlier resolution, with no extension. Upstream clang implements the DIS (llvm#218710); clang 22 has no P1306. Kiln follows the DIS. Rules: spec/sema.md §7.6a "Element temporaries" and *destructuring*.

- **Before**, kiln was right only by accident:
  - At run time, `auto x : {D{2}.v}` printed `x2 ~D2`, but only because the element's initializer had lost its `ExprWithCleanups`. The pattern declaration's head-time `act_on_init` took the parse-time cleanup state, so the temporaries fell through to the element block.
  - In constant evaluation the Oven never destroyed them, so their constexpr destructors never ran (`01` for `0a1b`).
  - A destructuring initializer's temporaries were destroyed before the first element (`~W1 d4 d5`). This was wrong under the DIS and under GCC alike.
- **Sema** (`kiln_sema`):
  - `class/temporary.rs` `extend_init_temporaries` marks every full-expression `MaterializeTemporaryExpr` of an automatic variable's initializer as `Automatic`, extended by the variable. It does not enter nested full-expressions or unevaluated operands.
  - `expansion.rs`:
    - `expansion_select` re-marks the element's temporaries for the declaration (`note_shared_temporaries`).
    - `expansion_element` extends them and skips `check_var_lifetime` (`expansion_element_init`), so there is no false -Wdangling-gsl.
    - `expansion_decomp` extends the destructuring initializer's temporaries.
  - Found on the way: an immediate invocation in an element was never evaluated. The element's `ConstantExpr` was built before any full-expression that used it, so a consteval call reached codegen and failed to link (GCC accepts). `expansion_select` now hands its unevaluated invocations to the declaration's full-expression (`consteval.rs` `note_deferred_invocations`). `extend_init_temporaries` does not enter a `ConstantExpr`: a temporary inside an immediate invocation ends with it.
- **Codegen**: no change. `push_temporary_cleanup` already destroys `Automatic` temporaries after the variable, in reverse order.
- **Oven** (`kiln_oven`):
  - `compile.rs`:
    - A block whose non-reference local extends temporaries opens a cleanup scope (`extends_temporaries`).
    - A scalar register local preallocates its extended temporaries (`begin_extended`/`end_extended`), as memory locals and references already did.
  - `compile/class.rs` `mte`: a temporary that a non-reference variable outside the evaluation extends is destroyed within the evaluation. Without this, codegen's fold prepass turned `auto [a, b] : {T{{1, 2}}.p}` into a constant and dropped `~T`.
- **Oracle disagreement**: GCC 16.1 destroys enumerating element temporaries before the body (`~D2 x2`, and `E{...}.self()` dangles). The enumerating tests carry kiln goldens with `oracle: none`; the destructuring test agrees with GCC (`oracle: gcc`).
- Tests (`tests/conformance/stmt.expand/`):
  - `element-temporaries-run.cpp` covers:
    - value, `const auto&` and `auto&&` declarations;
    - multiple elements;
    - two temporaries in one element (reverse order);
    - a mixed list;
    - `self()` without dangling;
    - a gsl view of an owner temporary (strict-diags: no -Wdangling-gsl);
    - a structured-binding declaration;
    - dependent and value-dependent templates.
  - `element-temporaries-constexpr-run.cpp`: the same ordering in constant evaluation, logged by constexpr destructors; the compile-time and run-time logs match; constexpr and const declarations stay constant.
  - `destructuring-temporaries-run.cpp`: destructuring at run time and in constant evaluation, the init-statement and an iterating range; GCC oracle.
  - `element-immediate-invocation-run.cpp`: an immediate invocation in an element, in a function, a function template and a constexpr function, is evaluated (GCC oracle).
  - `element-discarded-temporary-run.cpp`: `xfail(kiln)` (below).
- **Follow-ups**:
  - A discarded class prvalue in an element (`(void)D{1}`, a comma's left operand) is bound but not materialized, so it is not extended (`element-discarded-temporary-run.cpp`, xfail). It needs a materialization of discarded class prvalues in sema, or an extended `CXXBindTemporaryExpr` cleanup in codegen and the Oven.
