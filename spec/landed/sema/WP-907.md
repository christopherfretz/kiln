# WP-907 — variable template specializations of unknown array bound

A variable template specialization declared as an array of unknown bound
kept `T[]` after instantiation, so `sizeof(arr<int>)` was rejected
(rejects-valid). The rule is in spec/sema-templates.md §4.11
"Variable templates"; every case is matched against clang 19 and 22.

## Changes

- **Completion at the use** ([temp.inst]/4, [dcl.array]/3; clang
  `completeExprArrayBound`). `complete_expr_array_bound` (kiln_sema
  `expr.rs`), added for static data members by WP-730, now also takes an
  implicit variable template specialization (primary or partial
  specialization pattern, static data member template). It instantiates
  the definition and rebuilds the reference with the completed type. It
  runs for `sizeof`/`alignof` (point of instantiation at the outer
  parenthesis, as clang's note column), call arguments (`act_on_call`,
  deduction of `T (&)[N]`), the initializer of a reference or
  placeholder variable (`act_on_init`) and a range-for range
  (`range_for.rs`). A constexpr specialization is instantiated when
  referenced, so `decltype` and constant-expression subscripts see the
  bound.
- **Explicit instantiation definition** ([temp.explicit]/3, /5; clang
  `ActOnExplicitInstantiation`). `act_on_explicit_var_inst`
  (`templ/var.rs`) instantiates the definition before comparing the
  declared type: `template short arr<short>[2];` is accepted, and
  `template char arr<char>[];` is the type-mismatch error against
  `char[2]`.

## Tests

- `tests/conformance/temp.inst/p4-var-template-unknown-bound.cpp`
  (flipped from xfail), `var-template-unknown-bound-completed.cpp`,
  `var-template-unknown-bound-constexpr.cpp` (`requires: clang>=22`:
  clang 19 rejects reading an element of a constexpr variable template
  of unknown bound), `var-template-unknown-bound-errors.cpp`.
- `tests/conformance/temp.explicit/var-template-unknown-bound.cpp`,
  `var-template-unknown-bound-errors.cpp`.
- `tests/codegen/var_template_unknown_bound.cpp`: the globals have the
  completed array types, IR identical to clang 19 and 22.

## Not covered

- clang does not instantiate a constexpr specialization referenced only
  in an unevaluated operand (`decltype(carr<int>)` is `const int[]`
  before any other use); kiln does, as GCC does (`note_var_referenced`,
  `templ/class.rs`).
- clang's other `getCompletedType` sites are not wired: a reference
  bound by a one-element braced list, constructor arguments and
  overloaded-operator arguments.
