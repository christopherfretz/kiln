# WP-1040 — accepts-invalid tails from WP-1015 and WP-946

The remaining declaration checks from WP-1015's clang negative-test run (spec/sema.md §4.4.1). This WP covers WP-1040, WP-1041, WP-1042 and WP-1063. Every diagnostic is matched against clang 19 and clang 22 for wording and location; where the two differ, a `requires: clang>=22` test has a `-19` sibling. Each rejection test has a valid form next to it.

- **main and allocation functions** (WP-1040).
  - `main`, in `main_decl.rs`:
    - A C-linkage variable named `main` is an error in any namespace. clang 22 reports it at the decl-specifiers; clang 19 reports only the global one.
    - A variable template named `main` stays valid, as in clang.
    - A C-linkage function named `main` in a namespace is `main` for clang 22.
    - clang's `-Wmain` warnings are now issued:
      - `extern "C"` on `main` (clang 22, P3618R0);
      - one parameter;
      - a variadic `main`;
      - a `bool` literal returned from `main`;
      - under `-pedantic`, a use of `main` in an expression.
    - Tests: `basic.start.main/main-{c-linkage-*,extern-c,used-pedantic,variadic,wmain}.cpp`.
  - Destroying operator delete, in `alloc_decl.rs` and `new_delete.rs`:
    - The first parameter is `C *`, with clang 22 and clang 19 wording. In a class template, a dependent type other than the injected-class-name's is checked at instantiation.
    - Only a usual parameter tail is allowed, and the function is not a template.
    - A delete-expression that finds a destroying delete considers only destroying candidates and rejects a deleted selection. A cv-qualified operand is valid.
    - CWG2889 (clang 20+): a non-virtual destructor need not be accessible. The `-19` sibling pins clang 19's error.
    - Tests: `basic.stc.dynamic/destroying-delete-*.cpp`, `expr.delete/destroying-delete-*.cpp`.
  - Type-aware (P2719) allocation functions are **not done**.
- **Declarations** (WP-1041).
  - Braced default arguments and their nested lists are searched for `this` and for parameters. Test: `dcl.fct.default/braced-default-arg-references-param{,-ok}.cpp`.
  - A friend class template in a local class gets "templates cannot be declared inside of a local class". Test: `temp.mem/p2-local-class-friend-class-template{,-ok}.cpp`.
  - Ref-qualifier mix:
    - Conversion functions and copy assignment operators are now checked. A conversion to a dependent type is checked at instantiation.
    - From C++23 the two forms correspond and are a member redeclaration.
    - CWG2496 virtual overrides are checked in every mode under clang 22, but only before C++23 under `-fclang-compat=19`.
    - Tests: `class.conv.fct/ref-qualifier-*.cpp`, `class.virtual/override-ref-qualifier-mix-cxx23{,-19}.cpp`.
  - CWG2553: an explicit object parameter cannot override. It is reported at `this` with a note at the overridden function, and the declaration is invalid. Allocation and deallocation functions cannot take one either. Test: `class.virtual/explicit-object-override{,-ok}.cpp`.
- **Clang tests still missed** (WP-1042).
  - `dcl.fct.spec/p4.cpp`: an `inline` redeclaration after a non-inline definition (`Sema::inline_after_definition`). The file now matches clang fully. Test: `dcl.fct.spec/inline-after-definition{,-ok}.cpp`.
  - Template-parameter shadowing ([temp.local]/6) is now checked for:
    - alias-declarations and alias templates;
    - nested template-head parameters;
    - function parameters and handler parameters;
    - namespace aliases;
    - friend class templates and classes.
  - `friend struct T` naming an NTTP `T` is now accepted; it was a rejects-valid.
  - Results on the clang tests: `temp.res/temp.local/p6.cpp` matches except 63:12 (an elaborated `struct T *` in a function body). `p2-0x.cpp` and `alias-template.cpp` match. Test: `temp.local/p6-shadow-alias-params{,-ok}.cpp`.
  - `class.union/p1.cpp`: C++03 non-trivial union and anonymous-struct members (`cxx03_nontrivial_member`). Only the errors are produced; clang's "because ..." notes are not. Test: `class.union/cxx03-nontrivial-member{,-ok}.cpp`.
  - `namespace.udecl/p11.cpp`: using-declaration conflicts now compare parameter-type-lists only, not return types. A block scope is not compared again at its instantiation, as in clang and gcc. The file matches clang fully. Test: `namespace.udecl/p11-return-type-conflict{,-ok}.cpp`.
- **Templates** (WP-1063).
  - "enumeration cannot be a template".
  - clang 22's "templates can only be declared in namespace or class scope". The `-19` sibling covers clang 19's "expected expression".
  - Tests: `temp.pre/enum-template{,-ok}.cpp`, `temp.pre/local-template-declaration{,-19,-ok}.cpp`.
- **Interface changes**:
  - New diagnostics:
    - `sema_main_{c_linkage_variable,extern_c,one_arg,returns_bool_literal,used,variadic}`;
    - `sema_destroying_operator_delete_{param_type,dependent_param_type}{,_19}` and `sema_destroying_operator_delete_not_usual`;
    - `sema_inline_decl_follows_def`;
    - `sema_illegal_union_or_anon_struct_member`.
  - New and changed Sema functions:
    - `Sema::check_template_param_shadow_in(name, loc, tag)`;
    - `Sema::inline_after_definition`;
    - `Sema::cxx03_nontrivial_member`;
    - `using_conflicts` now compares parameter-type-lists.
