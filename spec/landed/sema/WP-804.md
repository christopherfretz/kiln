# WP-804 — Sema fixes from the Boost compiled libraries

- [dcl.init.list]/3.7: in a template instantiation, a list-initializing
  `CXXConstructExpr` that calls an initializer-list constructor
  (`ConstructInfo::std_init_list`) is rebuilt from the braced list of its
  one argument, the `std::initializer_list` over the whole written list
  (`Substituter::construct_list`,
  `crates/kiln_sema/src/templ/subst/exprs.rs`). Before, that argument
  was rebuilt as one element, so `V v{"2", 1}` became `V v{{"2", 1}}`
  and `V v{}` became `V v{{}}` whenever the element type also had an
  initializer-list constructor. Boost.JSON's `value b{"2", 1}` in a
  function template was the object `{"2":1}` instead of the array
  `["2",1]` (boost_json-tests, value_from.cpp: a miscompile).
  spec/sema-templates.md "Analyzed initializations as operands". Test:
  `tests/conformance/dcl.init.list/init-list-ctor-element-list-in-template.cpp`.
- [temp.deduct.general]/7, [temp.deduct.call]/10 (CWG1391): in a call
  with explicit template arguments, a return type written before the
  parameters is substituted with them in §6.1 step 1, before the
  non-dependent parameters' conversions are checked
  (`subst_explicit_param_types`, `crates/kiln_sema/src/templ/deduce_call.rs`).
  Before, the conversion from `const char*` to `basic_string<char,
  traits, CustomAllocator<wchar_t>>` instantiated that string, a hard
  `static_assert` error in libstdc++, although the candidate's
  `enable_if` return type removed it (Boost.Locale
  `utf_to_utf<wchar_t, char, Alloc>`, locale test_encoding.cpp).
  spec/sema-templates.md §6.1 step 1. Tests:
  `tests/conformance/temp.deduct.call/explicit-args-return-sfinae-before-nondep-conversion.cpp`;
  the trailing-return case is the xfail
  `explicit-args-trailing-return-sfinae-before-nondep-conversion.cpp`.
- [expr.throw]/2, [except.throw]/5: `throw x` of an abstract class type
  or of a class whose destructor is inaccessible or deleted is rejected,
  as clang `CheckCXXThrowOperand` (`build_throw`,
  `crates/kiln_sema/src/except.rs`; new diags `sema_throw_abstract`,
  `sema_throw_object_dtor_access`). Before, kiln accepted it, so
  Boost.Exception's compile-fail test exception_fail.cpp failed.
  spec/sema.md §5.5. Test:
  `tests/conformance/expr.throw/abstract-and-inaccessible-dtor.cpp`.
  The same check odr-uses a non-trivial destructor, which replaces
  WP-799's separate `use_exception_dtor`: run together, the two
  diagnosed an inaccessible destructor twice.
