# WP-730 — LLVM 19.1.7 Support and ADT through their own build and unit tests (M8 wave 3)

LLVM llvmorg-19.1.7 (`llvm/` only: lib/Demangle, lib/Support, lib/ADT
headers, LLVM's bundled googletest, `SupportTests` and `ADTTests`) built
with kiln++ through LLVM's own CMake build (docs/status/oss/llvm_project.md).
Each behaviour below is a kiln bug the build found, reduced to a
standalone test; the rule is stated in the spec named.

## Changes

- **A static data member of the current instantiation declared as an
  array of unknown bound** ([temp.dep.expr]/3, [temp.inst]/4,
  [dcl.array]/3; spec/sema-templates.md §3.2). A reference to it in the
  template is type-dependent, so `sizeof(Ops)` is checked at
  instantiation; there a reference to the specialization's member
  instantiates its out-of-line definition and names it with the bound
  its initializer gives (clang `completeExprArrayBound`).
  Test: `tests/conformance/temp.dep.expr/static-member-array-unknown-bound.cpp`.
- **`__builtin_assume_aligned` with an enumerator alignment** (clang
  `BuiltinConstantArg`; spec/sema.md "Library builtins"). The alignment
  is an integer constant of integral or unscoped enumeration type, so
  LLVM's `LLVM_ASSUME_ALIGNED(p, (PickAlignment<T, A>::value))` (an
  enumerator) in Endian.h is accepted; it blocked 78 of the 86 rejected
  TUs. Tests: `tests/conformance/ext.gnu.builtins/assume-aligned-enum-alignment.cpp`,
  `assume-aligned-enum-alignment-errors.cpp`.
- **GNU `deprecated(message, replacement)`** (clang
  `handleDeprecatedAttr`; spec/sema.md attributes). The GNU spelling
  takes an optional replacement string (LLVM's `LLVM_DEPRECATED`); the
  standard, `[[gnu::]]` and `__declspec` spellings take at most a
  message, a second one an error that still applies the attribute.
  Test: `tests/conformance/dcl.attr.deprecated/gnu-replacement-argument.cpp`.
- **No rewritten or reversed comparison candidates before C++20**
  ([over.match.oper]/3.4; clang `CreateOverloadedBinOp`;
  spec/sema-overload.md §5.1). In C++17 `a != b` no longer considers
  `operator==`, which made LLVM's `iterator_facade_base::operator!=`
  ambiguous with `iterator_adaptor_base`'s friend `operator==`
  (StringRef.cpp, YAMLParser.cpp).
  Test: `tests/conformance/over.match.oper/no-rewritten-before-cxx20.cpp`.
- **Default arguments of an allocation function** ([expr.new]/19,
  [dcl.fct.default]; clang `GatherArgumentsForCall` in `BuildCXXNew`;
  spec/sema.md §5.9). Parameters past the placement arguments take their
  default arguments (LLVM's YAML `Node::operator new(size_t,
  BumpPtrAllocator &, size_t Alignment = 16)`), instantiated with a class
  template's member; an instantiation re-adds them.
  Tests: `tests/conformance/expr.new/placement-default-arguments.cpp`,
  `placement-default-arguments-errors.cpp`.
- **Global allocation function templates** ([expr.new]/19, [temp.over];
  spec/sema-overload.md §10.6). The global lookup of `operator new`
  keeps the function templates it finds as candidates, as the class
  lookup did: LLVM's `template <...> void *operator new(size_t,
  BumpPtrAllocatorImpl<...> &)` behind `AllocatorList::create`
  (YAMLParser.cpp).
  Test: `tests/conformance/expr.new/global-operator-new-template.cpp`.
- **A class template's name with a pack expansion for a parameter that
  is not a pack** ([temp.local]/1, [temp.variadic]/5;
  spec/sema-templates.md §3.4). Inside `Templates<Head_, Tail_...>`,
  `Templates<Tail_...>` (googletest's type-parameterized test lists) was
  probed as a partial specialization's own arguments and its template
  pack expansion rejected for the template template parameter `Head_`;
  it is now a dependent specialization (gtest-all.cc, gmock-all.cc).
  Test: `tests/conformance/temp.local/injected-name-pack-expansion-args.cpp`.
- **An explicit instantiation definition marks the vtable used**
  ([temp.explicit]/10, [class.virtual]/12; spec/sema-templates.md
  "explicit instantiation definition"). The class's virtual members,
  and those of each member class it defines, are odr-used there, so an
  implicit virtual destructor is defined: LLVM's `template class
  cl::opt<std::string>` left `cl::opt<...>::~opt()` undefined at link
  (SupportTests, ADTTests).
  Test: `tests/conformance/temp.explicit/vtable-implicit-virtual-destructor-run.cpp`.
- **An alias template naming a member template of a class template
  specialization** ([temp.alias]/2; spec/parse.md §2.5 lookahead). For
  `template <class... Ty> using FixedSizeStorage =
  TrailingObjects::FixedSizeStorage<Ty...>;` the lookahead classified
  `with_counts` in the instantiated member template, whose definition is
  not instantiated yet, as dependent, so `alignof(Class1::FixedSizeStorage<short>::with_counts<1>::type)`
  was parsed as an expression (TrailingObjectsTest.cpp). It now classifies
  in the member template that one was instantiated from.
  Test: `tests/conformance/temp.alias/alias-names-member-template-of-specialization-run.cpp`.
- **`decltype` of a template's local variable with a type that is not
  dependent** ([temp.dep.type]/7; spec/sema-templates.md "Type flags").
  The reference is instantiation-dependent in kiln only so that
  instantiation rebinds it, so `decltype(V)` was a `DependentDecltype`
  and `mapped_iterator<decltype(V)::iterator, FuncT>` asked for
  `typename` (MappedIteratorTest.cpp). It is now the plain `Decltype`,
  as in clang.
  Test: `tests/conformance/dcl.type.decltype/template-local-nested-name-run.cpp`.
- **`__PRETTY_FUNCTION__` prints a type template argument canonical**
  (clang `PredefinedExpr::ComputeName`; spec/sema.md §7.8). The
  ` [T = ...]` list printed the argument as written, so
  `getTypeName<N1::S1>()` gave `N1::S1` where clang gives
  `(anonymous namespace)::N1::S1`; LLVM's `TypeNameTest.Names` failed
  at run time. Typedefs and alias templates are now looked through as
  well (`[T = std::basic_string<char>]`).
  Test: `tests/conformance/dcl.fct.def.general/predefined-type-arg-canonical.cpp`.
