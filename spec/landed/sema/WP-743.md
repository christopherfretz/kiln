# WP-743 — C++26 DIS: trivial unions, union lifetime, carries_dependency

Three papers from the Croydon DIS draft (WP-732): P3074R7 (trivial
unions), P3726R2 (union lifetime adjustments) and the core part of
P3475R2 (`[[carries_dependency]]` removed). GCC 17 is the only
implementation of the first two, so kiln follows the DIS wording and
records each deviation in the spec named below. Every rule applies at
`-std=c++26` only. Earlier modes keep their old behaviour, and tests
pin it.

## Changes

- **Trivial unions** ([class.union], [class.default.ctor]/2-3,
  [class.dtor]/7-8; spec/sema-class.md §4.2 "Trivial unions").
  - A variant member's non-trivial default constructor or destructor no
    longer deletes the union's default constructor or destructor, and
    no longer makes it non-trivial.
  - The all-const bullet is gone.
  - What still deletes them is a variant member with a default member
    initializer, and the CWG3041 form of the destructor rule
    ("user-provided" for "not trivial"). Anonymous unions in classes are
    covered.
  - Codegen emits nothing for the trivial members.
  - `__cpp_trivial_union` is 202603L at C++26, the DIS value, whatever
    the `-fclang-compat`.

  Tests: `tests/conformance/class.union/trivial-union-cxx26.cpp`,
  `trivial-union-deleted-cxx26.cpp`, `trivial-union-cxx23.cpp`,
  `trivial-union-run-cxx26.cpp`,
  `tests/conformance/cpp.predefined/trivial-union-macro.cpp`,
  `trivial-union-macro-cxx23.cpp`. Pinned to `-std=c++23` because their
  diagnostics are the old rule's:
  `class.default.ctor/implicitly-deleted.cpp`, `class.dtor/deleted.cpp`,
  `expr.delete/element-destructor-deleted-or-private.cpp`,
  `basic.life/constexpr-lifetime-local.cpp`,
  `class.union/constexpr-destroy-member-then-union.cpp`,
  `dcl.attr.grammar/attribute-subjects.cpp`.

- **Union lifetime in the Oven** ([class.union.general], [basic.life],
  P3726R2; spec/oven.md "C++26 union lifetime").
  - A union with no active member is valid storage.
  - Constructing an element of an inactive array member activates the
    array, and its other elements stay uninitialized (the
    `inplace_vector` pattern). This follows GCC 17; the DIS wants
    `std::start_lifetime`, which kiln does not provide.
  - Destroying the active member leaves the union alive with no active
    member.
  - Destroying a member that is not active is diagnosed.
  - Constructing over an active member of another type does not run its
    destructor, so a resource it owned leaks, and the leak is diagnosed.
  - `Types::extent_in` prefers an array member's extent inside a union,
    so `&u.a[0] + 1` is `&u.a[1]`.

  No new memory state: element lifetimes use the per-byte bitmap, and a
  union's side-map entry is removed when its member is destroyed.
  Tests: `tests/conformance/class.union/constexpr-trivial-union-lifetime-cxx26.cpp`,
  `tests/conformance/expr.const/constexpr-trivial-union-invalid-cxx26.cpp`,
  `tests/conformance/basic.life/union-member-destroyed-cxx26.cpp`.

- **`[[carries_dependency]]` removed** ([dcl.attr], P3475R2; spec/sema.md
  attributes, spec/parse.md).
  - `__has_cpp_attribute(carries_dependency)` is 0 at C++26.
  - The attribute is an unknown attribute: `unknown attribute
    'carries_dependency' ignored` [-Wunknown-attributes], with any
    argument list skipped.

  Tests: `tests/conformance/dcl.attr.depend/carries-dependency-removed-cxx26.cpp`,
  `carries-dependency-cxx23.cpp`.

## Measurements

Release kiln++ on this aarch64 host. The `inplace_vector`-style test
pushes 1e5 elements that own heap memory into capacity 1024 and pops
them all at each full buffer, under `-fconstexpr-steps=100000000`.
- **Union storage** (`union { S data[1024]; }`): about 90 ms of
  constant evaluation (`wall_us`), 0.55 s for the whole compile, 45 MiB
  peak RSS.
- **`std::allocator<S>` storage**: about 55 ms, 0.55 s, 45 MiB. A char
  buffer with `construct_at` is not a valid constant expression, so the
  allocator is the comparison.

Steps, bytes (1.6 MB) and peak bytes (16 KiB) are the same for both, so
lifetime state is reclaimed as it goes. The union's extra time is the
existing active-member walk (`Vm::union_path`, WP-644) on every access
to an element in union storage. A callgrind profile of a reduced run
does not separate the new placement and destruction code from the
interpreter loop.

`cargo xtask bench` compared head and base (623bc53a2) against a
baseline recorded from base. Every constexpr counter (steps, bytes,
inst) is unchanged on all 44 entries. The time and RSS flags are host
noise: base judged against its own baseline flags the same entries
(`frontend/accessor-wide-emit`, `frontend/simd-generate`,
`overload/arrow-chain`).

## Not done

- `std::start_lifetime` ([obj.lifetime], P3726R2): a library function
  that needs a builtin. kiln activates the array member implicitly
  instead.
- Copying, returning by value, or freezing an object whose union array
  member has unconstructed elements is rejected with "subobject 'a' is
  not initialized". That is clang's rule for any uninitialized
  subobject, and kiln shares it. GCC accepts the copy. P3726R2's
  constituent-value change would allow such a constant.
