## Unused-result attributes merged across function template redeclarations

[dcl.attr.nodiscard]/2: a name declared without `nodiscard` may later be
redeclared with it, and a call to a function "previously declared"
nodiscard is diagnosed. clang substitutes a function template
specialization from the latest redeclaration of the template, onto which
`mergeDeclAttributes` carried every earlier declaration's inheritable
attributes, so the attribute reaches calls however the template was first
declared.

- `Substituter::function_spec_attrs` (`templ/subst/anon.rs`, called from
  `function_spec_signature`): the specialization gets the pattern's
  attributes (`class_attrs`, as before), then each `nodiscard`, `pure` or
  `const` attribute (the `-Wunused-result` family) found on another
  declaration of the template's pattern (`redecls_of`, latest first) that
  the specialization does not already have.
- The set is the one seen when the specialization is formed: a
  specialization formed before a later declaration adds the attribute
  keeps what it had (clang does not warn on it either).
- An explicit specialization is unchanged (it already warns as clang
  does).
- libc++ shapes: `get` (array, tuple, pair, variant, complex) and the
  valarray `begin`/`end` forward-declared without the attribute and
  defined with it; `any_cast` forward-declared, befriended by `any`, then
  defined with it.
- Test: `tests/conformance/dcl.attr.nodiscard/redeclared-function-template.cpp`.
