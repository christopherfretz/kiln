# WP-491 — `[[nodiscard]]` across redeclarations and on hidden friends, P2748R5, `MEM_UNSUPPORTED` measured

Extends spec/sema.md §4.5 (attributes) and spec/sema-templates.md
(instantiated declarations' attributes).

## Unused-result attributes merged across function template redeclarations

[dcl.attr.nodiscard]/2: a name declared without `nodiscard` may later be
redeclared with it, and a call to a function "previously declared"
nodiscard is diagnosed. clang substitutes a function template
specialization from the latest redeclaration of the template, onto which
`mergeDeclAttributes` carried every earlier declaration's inheritable
attributes, so the attribute reaches calls however the template was first
declared.

- `Substituter::function_spec_attrs` (`templ/subst/anon.rs`, called from
  `function_spec_signature`): the specialization gets the pattern's
  attributes (`class_attrs`, as before), then each `nodiscard`, `pure` or
  `const` attribute (the `-Wunused-result` family) found on another
  declaration of the template's pattern (`redecls_of`, latest first) that
  the specialization does not already have.
- The set is the one seen when the specialization is formed: a
  specialization formed before a later declaration adds the attribute
  keeps what it had (clang does not warn on it either).
- An explicit specialization is unchanged (it already warns as clang
  does).
- libc++ shapes: `get` (array, tuple, pair, variant, complex) and the
  valarray `begin`/`end` forward-declared without the attribute and
  defined with it; `any_cast` forward-declared, befriended by `any`, then
  defined with it.
- Test: `tests/conformance/dcl.attr.nodiscard/redeclared-function-template.cpp`.

## Attributes of hidden friends of class templates

A friend function declared in a class template is instantiated with the
class ([temp.inst]/4); clang's `TemplateDeclInstantiator::VisitFunctionDecl`
runs `InitFunctionInstantiation` → `InstantiateAttrs` for it as for any
member, so a `[[nodiscard]]` hidden friend found by argument-dependent
lookup ([basic.lookup.argdep]/4) on the specialization warns when its
result is discarded.

- The instantiated friend (and the pattern of an instantiated friend
  function template) gets the pattern friend's attributes (`class_attrs`
  in `templ/subst/decls.rs`). Until WP-491 friends were skipped.
- A friend that redeclares a namespace-scope function adds the pattern's
  attributes to its own declaration; the function's earlier declarations
  keep theirs, and `find_attr` walks the redeclaration chain.
- Operator syntax is reported where the compatibility level says
  (`unused_warning`: clang 22 the expression's start, clang 19 the
  operator).
- libc++ shapes: `iter_move` of the filter and join_with iterators, the
  iota/repeat iterator `operator+`/`operator-`, join_with's `operator==`.
- Tests: `tests/conformance/dcl.attr.nodiscard/hidden-friend-class-template.cpp`,
  `tests/conformance/dcl.attr.nodiscard/hidden-friend-operator-clang22.cpp`,
  `tests/conformance/dcl.attr.nodiscard/hidden-friend-operator-clang19.cpp`.
