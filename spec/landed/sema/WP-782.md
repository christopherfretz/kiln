# WP-782 — all of LLVM 19 (`llvm/`) built by kiln: frontend fixes

Fixes found building LLVM 19.1.7's `llvm/` tree (every library, the
AArch64 and X86 backends, every tool and the unit tests) with kiln++ as
the OSS project `llvm_full` (docs/status/oss/llvm_full.md). Each is
pinned by a test checked against clang 19 too. Clusters the
concurrent WP-775/WP-779 fixed first are listed in the status page, not
here.

## Changes

- **A dependent braced default argument of a member function is kept as
  written** ([dcl.fct.default]/5, [temp.inst]/3;
  `kiln_sema/src/class/mod.rs` `act_on_param_default_list`).
  `const O (&ids)[N ? N : 1] = {}` in a class template was
  list-initialized at definition time against `const O[0]`. A list is now left
  unconverted when the parameter type is dependent or the list is
  type-dependent (LLVM `Option/ArgList.h`).
  Test: `tests/conformance/dcl.fct.default/member-dependent-array-reference-braced.cpp`.
- **An out-of-line member template's own parameters are not hidden by
  class members** ([temp.local]/7; `kiln_sema/src/lookup.rs`
  `own_template_param_outside`). In `template<unsigned size> int P::f()`,
  `size` names the template parameter even though `P` has member
  functions called `size`. The parameter scope lies outside the
  re-entered class scope, so the Record branch of `lookup_name_scoped`
  checks the definition's own template parameters first (LLVM
  `AArch64InstPrinter::printGPRSeqPairsClassOperand`).
  Test: `tests/conformance/temp.local/p7-member-template-param-not-hidden-out-of-line.cpp`.
- **`auto(x)` and CTAD `W(x)` with a type-dependent argument are
  type-dependent** ([temp.dep.expr]/3; `kiln_ast/src/templates.rs`
  `unresolved_construct`). WP-775 made `T(args)` with a non-dependent
  `T` only value-dependent. When `T` is a placeholder for a deduced type
  (`auto`, a deduced template specialization), the argument's type
  dependence is kept instead.
  Test: `tests/conformance/temp.dep.expr/p3-placeholder-functional-cast-type-dependent-run.cpp`.
- **`d.E::e` with an unscoped enumeration of a base class names a member**
  ([expr.ref]/4, [class.access.base]/5; `kiln_sema/src/class/member_expr.rs`
  `enum_qualifier_class`, `qualifier_names_base`, `member_access`). The
  qualifier-is-a-base check looks through an unscoped (transparent)
  enumeration to its class. A name found in an enumeration qualifier has
  no naming class, so it gets no member access check, as in clang (LLVM
  `TLI.ReciprocalEstimate::Disabled` in `DAGCombiner.cpp`).
  Test: `tests/conformance/expr.ref/qualified-enumerator-of-base-class-run.cpp`.
- **A name in an uninstantiated member enumeration is classified through
  its pattern** ([dcl.ambig.res]/1; `kiln_sema/src/decl.rs`
  `classify_uninstantiated_member`). `N c(N::US::Lazy);`, where `US` is a
  member enumeration of the base `G<N>`, was disambiguated as a function
  declaration. The parser's lookahead found nothing in the
  not-yet-instantiated enumeration. Enumerations now go through the
  pattern as member classes do (LLVM `CloningTest.cpp`).
  Test: `tests/conformance/dcl.ambig.res/member-enum-of-base-specialization-enumerator-run.cpp`.
- **An integral promotion is never narrowing** ([dcl.init.list]/7.4,
  [conv.prom]/3; `kiln_sema/src/conv/narrow.rs` `narrowing_kind`). A
  non-constant unscoped enumeration with no fixed underlying type
  initializes its promotion type (`int` for `enum { A, B = 30000 }`, whose
  underlying type is `unsigned int`) without a diagnostic. clang checks
  integral conversions only. A conversion that is not the promotion, such
  as to `short` or from a fixed `enum : unsigned` to `int`, still narrows
  (LLVM `X86FixupVectorConstants.cpp`).
  Tests: `tests/conformance/dcl.init.list/enum-promotion-not-narrowing-run.cpp`,
  `tests/conformance/dcl.init.list/enum-conversion-still-narrowing.cpp`.
- **`__builtin_thread_pointer()`** (`kiln_ast/src/decl.rs`
  `builtin::THREAD_POINTER`, `kiln_codegen/src/builtins.rs`,
  `kiln_llvm/src/intrinsics.rs` `thread_pointer`). It lowers to
  `call ptr @llvm.thread.pointer()`, or to `@llvm.thread.pointer.p0()`
  when the consuming LLVM is 20 or later (`llvm_major`; the LLVM 19
  backend would leave the `.p0` name an undefined symbol). It is never a constant expression (Oven
  note at the call). LLVM `llvm-exegesis` `BenchmarkRunner.cpp`.
  Tests: `tests/codegen/builtins_thread_pointer.cpp`,
  `tests/conformance/ext.gnu.builtins/thread-pointer-run.cpp`,
  `tests/conformance/ext.gnu.builtins/thread-pointer-not-constant.cpp`.
- **An unnamed class defined in an alias-declaration is not anonymous**
  ([class.union.anon]/1; `kiln_parse/src/class.rs` `parse_record_body`,
  `in_type_id`). The `}` of `using I = struct {...};` is followed by
  `;`, which marked the class `ANONYMOUS`. A member `I i{};` was then
  treated as an anonymous struct member, and the constructor left it
  uninitialized: its default member initializer was dropped. This was a
  miscompile. LLVM's `MachObjectWriter::VersionInfo` read heap garbage,
  and every Mach-O `llc`/`llvm-lto` test in `check-llvm` hit
  `unencodable update target version` or an `llvm_unreachable`.
  Test: `tests/conformance/class.union.anon/alias-of-unnamed-class-is-not-anonymous-run.cpp`.
- **A reference to a const pointer bound to a derived pointer keeps the
  base adjustment** ([dcl.init.ref]/5.4.2, [conv.ptr]/3;
  `kiln_sema/src/conv/mod.rs` `qualify_prvalue`). Retyping the
  `DerivedToBase` cast to the temporary's `cv T` dropped its base path,
  so `const S *const &r = d;` stored the unadjusted `D *` whenever `S` was
  not at offset 0. This was a miscompile. LLVM's `SCEVUnknown::deleted`
  passed `this` as an `ArrayRef<const SCEV *>` 32 bytes off, and the
  `IndVarSimplify` tests under `-verify-scev` hit `dyn_cast on a
  non-existent value`.
  Test: `tests/conformance/dcl.init.ref/const-pointer-ref-to-derived-pointer-run.cpp`.

## Harness

`scripts/oss/projects.toml` gains the `llvm_full` row.
`scripts/oss/projects.py` gains two optional per-project keys,
`test_timeout` (seconds for the test step) and `vmem_kb` (the wrapper's
`ulimit -v`, at most 6000000), plus `lit_summary`, which reads lit's
result block into `report.json` `tests`. See
spec/landed/harness/WP-666.md.
