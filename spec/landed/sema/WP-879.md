## Mangling scaling study (kiln vs gcc form)

Generator (`gen.py N D W [dup]`): N empty types `lib::Tnnnnn`, four
`template <class... Ts> struct NodeK`, and for each i the key
`X(i, D)` where `X(i, 0) = lib::Ti` and `X(i, d) = lib::Node<d%4><X(i,
d-1), args...>` with W-1 more arguments chosen by `a % 5` from `lib::Tj`,
`int`, `const lib::Ti*`, `long`, `lib::Tj&` (`j = (i*7 + d*13 + a) % N`).
With `dup`, the last argument repeats `X(i, d-1)` as well, so the source
doubles per level. Each key is used as `&f<^^X>` and `&S<^^X>::count`,
with `template <info R> int f()` (a local static) and
`template <info R> struct S { static int count; }`. Bench shape S10 is
`N=200 D=6 W=6`.

Commands: `kiln++ -std=c++26 -freflection [-fkiln-reflection-mangling=gcc|kiln-hashed] -c` and `-S -emit-llvm`;
`g++-16 -std=c++26 -freflection -c` and `-S`. The release kiln++ is from
this branch. CPU time (user+sys, best of 11) is used because
`perf_event_open` is blocked, so there are no instruction counts. The box
is shared, and medians move by ±12% between runs. Symbol bytes are the
reflection-keyed symbols in the `.o` (`nm`). In every configuration the
gcc-mode symbols equal g++-16's.

`-c`, best CPU ms (kiln / gcc / kiln-hashed / g++-16), peak RSS KiB
(kiln / gcc / g++-16) and symbol KB (kiln / gcc / kiln-hashed):

- N=500 W=6 D=2: 108 / 112 / 107 / 168 ms; 68708 / 68708 / 51448; 192 / 183 / 82
- N=500 W=6 D=4: 155 / 154 / 141 / 184 ms; 69940 / 69876 / 57844; 327 / 318 / 82
- N=500 W=6 D=6: 207 / 200 / 190 / 229 ms; 70764 / 70684 / 59052; 444 / 435 / 82
- N=500 W=6 D=8: 267 / 240 / 224 / 262 ms; 71700 / 71636 / 66352; 561 / 552 / 82
- N=500 D=6 W=16: 353 / 349 / 328 / 330 ms; 74900 / 74864 / 82372; 984 / 975 / 82
- N=4000 D=6 W=6: 1511 / 1574 / 1425 / 1645 ms; 130812 / 130436 / 254068; 3556 / 3484 / 652

In-process mangling only (`mangle_decl` over every specialization, best
of 30 runs, after a full compile):

- D=2/4/6/8 (N=500, W=6), kiln: 5.7 / 9.8 / 12.7 / 17.1 ms; gcc: 5.7 /
  9.7 / 12.8 / 16.5 ms; kiln-hashed: 6.0 / 10.2 / 13.8 / 17.3 ms
- W=4/8/16 (N=500, D=6), kiln: 6.6 / 13.8 / 30.8 ms; gcc: 6.6 / 13.9 /
  28.3 ms
- N=250/1000/4000 (D=6, W=6), kiln: 6.9 / 29.8 / 117 ms; gcc: 6.5 / 26.1 /
  112 ms
- dup, D=4/6/8 (N=200, W=4): kiln 2.3 / 2.7 / 3.4 ms, max name length
  129 / 161 / 193 bytes, while the source grows 0.3 / 1.3 / 5.1 MB

Findings:

- Both forms are linear in N, D and W, at about 30 ns per emitted byte.
  The gcc form is not superlinear.
- The name length is linear in D × W. `Dm` saves 6 bytes per reflection
  literal over `u6__info`, 1-5% of the name on these keys.
- Substitutions work: in the dup keys each level adds 16 bytes to the
  name, and mangling time follows the name, not the source.
- Mangling is about 6% of a `-c` compile at D=6. kiln-hashed saves
  object bytes but not mangling time, because it hashes the full name.
- Wall time, CPU time and RSS of kiln and gcc mode agree within noise
  (best-CPU deltas from -10% to +8% with no consistent sign), and RSS is
  identical to within 0.3%.
- Default-mode output and cost are unchanged by this WP (the mangler is
  untouched).

Recommendation (operator decision, not taken here): switch the default
to gcc. It costs the same within noise, is 1-5% smaller on deep keys,
and links against g++-16 objects.

## Reflection bench

`cargo xtask bench bench/reflect` (5 runs, load about 22 on 24 cpus): S9
75.8 ms / 15.1 MB, S10 109.6 ms / 15.1 MB. Constexpr steps match the
baselines. S7 and S8 report `REGRESSED (time)` against their 2026-11-05
baselines (+32% and +53% wall, with memory -20% and -8%). A binary built
from a newer main without this branch's changes runs equally slowly: in 11
interleaved runs, best CPU time was 0.50 vs 0.51 s for S7 and 0.69 vs 0.70 s
for S8 (this branch vs the other binary). The drift therefore comes from
main or the host load, not from WP-879.

## Perf finding (not mangling)

kiln's frontend on very large sources of repeated nested template-ids is
linear but about 2.8x slower than g++-16. The dup keys at D=8 (5.1 MB of
source) take 1331 ms CPU for kiln `-c` against 474 ms for g++-16, and
mangling is 3.4 ms of that. It is logged in docs/status/perf.md.
