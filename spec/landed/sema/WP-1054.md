# WP-1054 — no silent drop of class template members

A class template member whose declaration failed at instantiation could
vanish without a diagnostic, so kiln accepted programs clang rejects and
could compile a class with a member missing (a data member that changes
layout). Found by WP-1017 on clang's
`CXX/dcl.dcl/dcl.spec/dcl.type/dcl.type.elab/p3.cpp` (the `C<T>::foo(class
B<T>::Member)` instantiations). Specs: spec/sema-templates.md §2.4 table,
§4.6 "No silent drop", §5.3 table; spec/sema.md §1.2 "Nothing fails silently"; docs/VALIDATION.md
oracle defects.

- **Silent-drop sites found and fixed.**
  - *A class-key reference through another template's specialization.*
    `class B<T>::Member` in a member of `C<T>`, with `B<T>`'s arguments at
    the positions of `B`'s own parameters, was parsed entering `B<T>`'s
    scope and resolved to the pattern's `Member`. At instantiation
    `find_instantiated_decl` looked for that pattern member in `B<int>`; an
    explicit specialization (or a partial one) was not instantiated from
    the pattern, so the lookup failed with a silent `SubstFail` and the
    member was dropped. A reference or friend does not enter the
    qualifier's scope (clang `ActOnTag`: `computeDeclContext(SS, false)`):
    `parse_tag_specifier` now builds the dependent class-key type for every
    qualifier that names an unentered dependent class
    (`Sema::is_unentered_dependent_class`); WP-1017's
    `is_unknown_specialization_tag` did so only when the pattern had no
    tag of that name, and is removed. Then `dependent_tag_name` reports
    `no class named 'Member' in 'B<int>'` or the wrong-tag error at
    instantiation, the latter at the class-key (`note_tag_keyword_loc` /
    `tag_keyword_loc`, as clang). This covers every member kind: data
    member, static data member, member function parameter and return
    type, typedef, alias, friend, nested class member, member template,
    pointer and reference members, enum.
    Tests: `temp.inst/member-elaborated-qualifier-{no-tag,wrong-tag,specialization-run}.cpp`.
  - *A member of such a class reached through a nested qualifier*
    (`class B<T>::In::Deep`): the leading component stays a type, and
    `find_instantiated_decl`'s last branch dropped `Deep` silently when
    `B<long>::In` came from an explicit or partial specialization. It now
    looks the name up again in the instantiated parent (`relookup_member`):
    nothing is `no member named 'In' in 'B<int>'` at the written component
    (`WrittenKey::Nns` for a record component, §5.8), one declaration of
    the same kind is used, anything else is "not yet implemented". The
    explicit-member-specialization branch shares `no_member`. clang 19
    and 22 get this case wrong (they accept the invalid uses and crash in
    codegen on the valid one; g++ 14 agrees with kiln), so both tests
    carry `skip(clang)`.
    Tests: `temp.inst/member-elaborated-qualifier-nested{,-run}.cpp`.
  - Every other way a member fails in `class_body_with` (a field,
    typedef or enumeration whose type fails is declared `INVALID`; a
    static data member or member function whose type fails, a failed
    `static_assert`, friends, member templates, anonymous members) goes
    through the guard below. With it on, neither the conformance corpus
    (5532 tests) nor clang's negative tests (`CXX`, `SemaCXX`) report a
    dropped member.
- **Guard.** `Sema::emit` counts every error-class emission, whether it
  prints, is captured in a SFINAE context, or is suppressed (`failures`).
  `class_body_with` runs each member (and each unnamed member class)
  through `guarded_member`, which takes `failure_mark()` first; when the member fails and
  `failed_silently_since(mark)` holds (no failure emitted since and no
  error in the TU), `member_dropped` emits
  `kiln: internal error: member 'x' of 'A<int>' was not instantiated and no
  diagnostic says why` (`sema_inst_member_dropped`) at the member.
  - Why a counter and an error rather than a proof value or an assert: a
    proof type (`SubstFail` constructed only by emitting) would have to be
    threaded through every `?` in the substituter, several hundred sites,
    for the same guarantee at the one place a member is dropped. A
    `debug_assert!` would leave release builds compiling a class with a
    member missing, and a panic turns a recoverable gap into a crash on
    user code. An error makes the program fail to compile in every
    build, names the member, and costs one counter increment per
    emission.
  - The TU-error condition mirrors clang's `hasUncompilableErrorOccurred`:
    a failure caused by a declaration an earlier error left invalid stays
    quiet, and the program already fails to compile.
  - SFINAE is untouched: a member *declaration* failing during class
    instantiation is never in the immediate context (the class definition
    pushes a non-SFINAE frame, §5.7), and a captured SFINAE failure counts
    as emitted.
- **Friend templates of a dependent member class.** The same parser
  change makes `template<class T> friend class A<T>::Member;` a dependent
  friend type instead of "redefinition of 'Member' as different kind of
  symbol" (clang accepts it with `-Wunsupported-friend` and turns off
  access control for the befriending class). kiln does not grant the
  access yet: `temp.friend/dependent-member-class-friend-run.cpp` is
  `xfail(kiln)`.
- **clang negative tests** (`cargo xtask clang-neg -j 4 CXX SemaCXX`,
  harness profile, before = base `dcf205fc1`): accepts-invalid 68 files /
  80 cases before and after; missed `expected-error` lines 4276 to 4270
  (p3.cpp line 60, three standards); rejects-valid 28 cases unchanged;
  six spurious errors gone (the friend templates above, in
  `CXX/drs/cwg{6,18,19}xx.cpp`, `class.friend/p3-cxx0x.cpp`,
  `temp.friend/p5.cpp`); no case gained an unexpected error. No case reports
  `sema_inst_member_dropped`.
- **Interface changes**: `Sema::is_unknown_specialization_tag` removed
  (callers use `is_unentered_dependent_class`); `Sema::note_tag_keyword_loc`,
  `tag_keyword_loc` and `TemplState::tag_keyword_locs`;
  `Sema::failure_mark` / `failed_silently_since` and the `failures`
  counter; new diagnostic `sema_inst_member_dropped`.
- **Overlap with WP-946** (sema tag handling): WP-1054 changes only the
  reference/friend branch of `parse_tag_specifier` and
  `dependent_tag_reference` (kiln_parse decl.rs) and the wrong-tag
  location in `dependent_tag_name`; tag definitions are untouched.
- **Follow-ups**: the friend access above; `relookup_member` reports
  "not yet implemented" when the specialization's member is not one
  declaration of the same kind (an overload set, a using-declaration);
  kiln emits no `-Wunsupported-friend`; p3.cpp line 41 prints
  `'B<float>'` where clang prints `'union B<float>'` in the wrong-tag
  error (wording).
