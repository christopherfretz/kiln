# WP-1102 — exception specifications in distant places, implicit-overrider calling conventions, local tags named early

Closes the tail WP-1078 deferred: WP-1102 (Part A) and WP-1103 (Part B).
Every case is matched against clang 19 and clang 22.

## Items

1. **Distant exception specifications (WP-1102).** C++14
   [except.spec]/2 (removed by C++17, [diff.cpp14.except]). Clang's
   `CheckDistantExceptionSpec` only allows an exception specification on
   a function declarator, or on the function type that a top-level
   pointer, reference or pointer to member of a declaration denotes.
   kiln now runs the same check in `type_for_declarator_at` for every
   pointer, reference, array and pointer-to-member chunk
   (`Sema::is_distant_exception_spec`, except.rs). The error is
   `exception specifications are not allowed beyond a single level of
   indirection` (`sema_distant_exception_spec`). It is reported:
   - at the declarator-id;
   - for an abstract declarator, at the place its name would go;
   - for a pointer to member, at the nested-name-specifier.

   As in clang, the type is still built, except that no pointer to
   member is formed (`int`), and the declaration is invalid. The invalid
   flag sticks for the rest of the declaration group, so in
   `void (**g1)() throw(), (*g2)();` `g2` is not declared. An invalid
   function redeclares nothing, so there is no "functions that differ
   only in their return type" error (clang p2-places.cpp:38/64).
   spec/sema.md §4.7 "Beyond one level of indirection". Tests:
   `except.spec/p2-distant-exception-spec-cxx14.cpp` (24 diagnostics) and
   `except.spec/p2-distant-exception-spec-ok-cxx{14,17}.cpp`.
2. **C++17 written nested specifications in overriders (WP-1102).**
   From C++17, `void (*)() noexcept(false)` and `void (*)()` are one
   type, so the overrider overrides. Clang's `CheckParamExceptionSpec`
   still compares the written specifications and reports `exception
   specifications of argument types differ` (and `... of return types
   differ`). kiln compared the canonical prototypes, which lose the
   written spec from C++17. `underlying_fn_proto` now walks type sugar
   (`sugared_pointee`) and reads the first prototype it finds. Tests:
   `except.spec/override-nested-exception-spec-noexcept-false-cxx{17,26}.cpp`.
3. **Implicit overriders: calling convention (WP-1103).** An implicit
   destructor or copy/move assignment operator whose calling convention
   differs from the virtual function it overrides now gets clang's
   `virtual function '~D' has different calling convention attributes`.
   It is reported at the class name, under `while declaring the implicit
   destructor for 'D'`. `check_implicit_overrider` runs
   `check_override_cc` before the return-type and `final` checks, as
   for a declared overrider. Test: `dcl.attr.cconv/override-cc-implicit-dtor.cpp`
   (`preserve_most`, target-neutral).
4. **Local tags named before their declaration statement (WP-1103).**
   `enum V *pv;` in a function template body: kiln gave the correct
   forward-reference error, plus a spurious "not yet implemented:
   reference to a member of a dependent context" at each instantiation.
   The valid `struct L *p; struct L {...};` got the same spurious error.
   `find_instantiated_decl` now declares such a local class or
   enumeration on demand, without diagnostics, as clang's
   `FindInstantiatedDecl` (`NeedInstantiate`) does
   (`local_tag_used_early`). The later definition statement defines that
   same declaration. Tests:
   `dcl.enum/forward-ref-enum-function-template.cpp` and
   `temp.inst/local-class-named-before-declaration-run.cpp`.

## Deferred (not breakages)

- C++17 overriders whose specification clang checks at the declaration
  (no written spec) are reported by kiln at the end of the class, so
  relative order against other errors differs
  (`class/virtual/complete.rs` delayed checks).
- clang's `-Wc++17-compat-mangling` and the C++11 "variable templates
  are a C++14 extension" warning are not emitted (seen while probing).
