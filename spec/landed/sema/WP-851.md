# WP-851 — correctness bundle 3 (WP-843, WP-847, WP-647, WP-659, WP-678)

Five correctness rows, each reproduced and compared against clang 19
(clang 22 for the feature macros).

- **WP-843, `decltype(e)::name` in a parameter declaration** (spec/parse.md,
  the decltype-scope lookahead): fixed. `peek_decltype_scope_name`
  classifies the name by lookup in the declared type of a plain
  id-expression operand. The xfail is removed from
  `dcl.type.decltype/decltype-qualified-type-parameter-declaration.cpp`.
  New test: `dcl.type.decltype/decltype-qualified-name-declarator-paren.cpp`.
- **WP-847, delete-expression operand alignment** (spec/codegen.md §3.3):
  fixed. The operand goes through `pointer_with_alignment`, as clang's
  `EmitPointerWithAlignment` does. Its alignment reaches the vtable,
  offset-to-top and destroying-delete loads. The array cookie is loaded at
  `min(align, cookie offset)`. The null test of a constant address folds.
  New IR test, byte-exact against clang 19: `codegen/delete_operand_alignment.cpp`.
- **WP-647**, items (1) to (5):
  - (1) C++20 `a[i++, j]`: already fixed on main (WP-681). It is pinned by
    `expr.sub/p1161-probe.cpp`, which has no xfail.
  - (2) and (3) `__cpp_static_assert` and the C++20 `__cpp_constexpr`
    (spec/pp.md): fixed at clang 22's values, `202306L` and `202002L`.
    Tests: `cpp.predefined/static-assert-macro-cxx11.cpp` and
    `static-assert-constexpr-macros-cxx20.cpp`.
  - (4) `I<V<V<int> >::type::type(3)>::value`: already accepted on main.
    It is pinned by `temp.names/n1757-functional-cast-argument.cpp`.
  - (5) `-Wnull-conversion` for `std::nullptr_t` operands and conditional
    arms (`!nullptr`): fixed. Test: `conv.bool/nullptr-null-conversion.cpp`.
- **WP-659, pending full-expression state across nested full-expressions**
  (spec/sema.md §5.14):
  - The leak: a misaligned-member candidate, `f((char *)&p.i, A<ft<short>()>::w)`,
    was reported by the full-expression nested inside the argument list
    (the template argument, a lambda body, an instantiated body) before the
    end-of-expression walk could see the cast. This gave a spurious
    `-Waddress-of-packed-member`.
  - The fix: explicit casts drop the candidate when they are built, which
    is clang's timing.
  - Deleted-function and typeid-warning state: probes showed no difference
    from clang.
  - Neither clang nor kiln sets the state aside in `in_inst_context`.
  - Test: `expr.unary.op/address-of-packed-member-nested-full-expression.cpp`.
- **WP-678, GNU attribute name normalization** (spec/sema.md "Attribute
  names"): fixed. Exactly one leading and one trailing `__` is stripped,
  and only when both are present (clang `normalizeAttrName`). This applies
  to every attribute in GNU syntax, and in `[[...]]` with no scope or the
  `gnu` or `clang` scope. `__const` is also an alias of `const`. Test:
  `dcl.attr.grammar/gnu-attribute-name-normalization.cpp`.
