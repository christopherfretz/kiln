# WP-905 — no silent drop in local classes of templates

A local class of a function template (or of a lambda or generic lambda in
one) is instantiated with the enclosing function ([temp.inst]/3, CWG1484).
WP-884 found that a reference from such a class's members could fail to
resolve at instantiation and vanish without a diagnostic. Specs:
spec/sema-templates.md §4.6 "No silent drop", §4.9, §5.6 "Local classes".

- **Reproduction.** Local classes, also nested in a lambda and in a
  generic lambda, inside function templates, whose member bodies use a
  local enumeration and its enumerators, a local typedef and alias, a
  static local, another local class, a local using-declaration and the
  members of an enclosing local class. Every form resolved correctly in
  member function bodies (WP-884's enumeration case was already fixed by
  CWG1484 instantiation). The silent drops were all in the *other*
  complete-class contexts ([class.mem.general]/7) of the members:
  - *Default arguments* were substituted at the member's declaration
    (`defer_default_args_to`). One naming a member declared later
    (`int g(int x = LATE)` before `enum { LATE = 4 }`) hit
    `find_instantiated_decl`'s silent "member not instantiated" `Err`, and
    the argument was dropped: the call then failed with "too few
    arguments".
  - *Default member initializers of a member class* were substituted at
    that class's own `}`, so `struct I { int a = LATE; int b = O::sf(); }`
    inside `O` dropped both references silently. The fields were 0, a
    miscompile.
  - *noexcept-specifiers* were instantiated on demand
    (`instantiate_exception_spec`) by a fresh substituter that does not
    have the function's locals. `noexcept(FNE)` with a function-local
    enumerator, or `noexcept(NE)` with a member enumerator, failed
    silently and the member became potentially-throwing, so `noexcept(o.g())`
    was wrong.
  - *Default member initializers of anonymous members* took the lazy
    class-template path, which has no function locals. The result was
    "not yet implemented: reference to a member of a dependent context".
    This was a rejects-valid, not a silent drop.
- **Fix.** These parts now wait for the outermost local class to be
  complete, as the parser replays them, instead of being resolved by a
  different lookup. `Substituter::local_late` collects `LocalLate`
  items while the outermost local class (`local_class`) and its member
  classes are declared. `local_late_parts` then substitutes them with the
  body's own substituter, in re-entered class scopes, in clang's order:
  1. default arguments and dependent noexcept-specifiers, in member order;
  2. default member initializers;
  3. member function bodies (`local_methods`, unchanged).

  Meanwhile a default argument is pending (`unparsed_default_args`) and a
  specification is `ExcSpec::Deferred(f)` in `unparsed_exc`, so a use too
  early is diagnosed as for a class being parsed. A closure type's call
  operator is not deferred.
- **Oracles.** clang 19 and 22 reject a default argument or
  noexcept-specifier that names a later enumerator ("no member '' in 'O';
  it has not yet been instantiated"). This is a clang bug: the
  non-template twin compiles. g++ 14 accepts it and prints what kiln
  prints, so those two tests carry `skip(clang)`. g++ 14 ICEs on a static
  local in an anonymous struct's initializer, while clang and kiln agree
  there.
- **Guard (WP-1054's, extended).** The new `sema_inst_part_dropped` reads
  `kiln: internal error: {part} in {context} was not instantiated and no
  diagnostic says why`. It uses the same `failure_mark` /
  `failed_silently_since` contract.
  - `Substituter::stmt` reports a statement that fails silently; it
    exempts a pack probe that stopped by design (`probe_done`).
  - `local_late_parts` reports a silently failed default argument,
    noexcept-specifier or default member initializer.
  - With it on, the conformance corpus and the libc++ m3 gate report
    none.
- **Tests** (`tests/conformance/class.local/`):
  - `template-local-class-names-run.cpp`: the six reference kinds, in a
    function template, a lambda and a generic lambda.
  - `template-local-class-nested-default-member-init-run.cpp`
  - `template-local-class-noexcept-run.cpp`
  - `template-local-class-anonymous-member-init-run.cpp`
  - `template-local-class-later-member-default-arg-run.cpp` (`skip(clang)`)
  - `template-local-class-later-member-noexcept-run.cpp` (`skip(clang)`)
  - `ir-template-local-class-late-parts.cpp`: IR equal to clang 22's
    (`min-oracle: 22`).
- **Not in scope.** kiln looks up unqualified names in a local base class
  of a template's local class (`struct B : A { int g() { return Z; } }`),
  which clang and g++ reject because the base is dependent ([temp.dep]/3).
  This is an accepts-invalid. kiln also accepts the WP-884 item
  `O::In2()` without `typename`.
