# WP-1065 — modules declaration image S3: classes

Extends spec/modules.md §11.11 "Part 2a" with stage S3 ("Classes (S3,
WP-1065)", the coverage list, the encoding grammar's access byte,
special names, decl kind table, type tags 13 and 14 and the class,
field, access-specifier, implicit-member and ctor-initializer payloads,
the body fallbacks, "Part 2a coverage and follow-ups" item 2, "What
`import std;` still needs after S3", and the S3 rows of
"Measurements"). The design, the encoding and the numbers are there.
This file records what landed and where.

## What landed

- **Records** (`crates/kiln_sema/src/bmi_image.rs`): `IMAGE_VERSION` 3.
  Declaration header gains an access byte; name words at or above
  `N_OP` are special names (constructor, destructor, conversion,
  `operator@`) that the importer recomputes. New payloads `Record`
  (`TagKind`, frozen `DefinitionBits`, end, bases), `Field`, `Access`,
  `Implicit` (`SpecialKind`); `Function` gains its declaration kind
  (`FN_KINDS`: function, method, constructor, destructor, conversion),
  the deferred-exception-specification byte and ctor-initializers
  (`InitRec`: base by position, field by record, delegating). Type tags
  13 (class) and 14 (`ElabQ`, an elaborated type with a
  nested-name-specifier of `::`, namespace and type steps).
- **Writer**: carries non-template, non-polymorphic classes without
  virtual bases, their members (fields, member functions, constructors,
  destructor, conversion functions, static data members, nested
  classes, member enumerations and typedefs, access specifiers),
  out-of-line member definitions, the implicit special members sema
  had declared, and a constructor's ctor-initializers. Each unsupported
  construct falls back with its own `-v` reason.
- **Bodies** (`crates/kiln_sema/src/bmi_image/body.rs`): `EXPR_KINDS`
  40 to 47 (member access, `this`, member calls, constructions,
  temporary objects, default member initializers, bound temporaries);
  new reference classes `Member`, `Field`, `Ctor`, `Dtor`; a cast's
  base path is carried as (class record, base position) steps; the
  use context of a default argument or member initializer (`Dc::Ctx`)
  may be any carried declaration context. `expr_reason` gives the
  remaining class expressions their own reasons.
- **Reader**: builds each class with `begin_record_definition`, its
  members in record order, closes it at its end with
  `complete_record_definition` and the carried bits, declares carried
  implicit members through `declare_implicit`, then attaches field
  widths and initializers, ctor-initializers and bodies after every
  record exists.
- **Narrow hooks**: `DefinitionBits::from_bits` and
  `DeclArena::set_field_bit_width` (`crates/kiln_ast/src/decl.rs`),
  `SpecialKind::any_needs_overload`
  (`crates/kiln_sema/src/class/special/mod.rs`). No other sema change;
  image off is unchanged (no image section is written or read).
- No new diagnostic id; no driver or harness change.

## Deviations

- The importer recomputes the implicit special members (from the
  carried `DefinitionBits`) instead of carrying them; layout and
  special names are recomputed too.
- Kept on fallback (follow-ups): polymorphic classes and virtual
  functions, virtual bases, friends (WP-1072/WP-1097), anonymous unions
  and structs, classes whose implicit members need overload resolution,
  inherited constructors, defaulted comparisons and out-of-line
  defaulted functions, class-specific allocation functions,
  `[[no_unique_address]]`, member side maps, implicit builtin library
  declarations, a qualifier naming a namespace outside the image; in
  bodies `new`/`delete`, `typeid`/`dynamic_cast`,
  `std::initializer_list`, pseudo-destructor calls and lambdas.
- The flag stays off by default.

## Tests

- `crates/kiln_sema/src/bmi_image.rs`: `class_round_trip` (a sample with
  two classes, a base, a field, a constructor with base and field
  initializers, an implicit destructor and a qualified type);
  `rejects_corrupt_class_records` (implicit kind out of range,
  duplicate implicit member, implicit member inside its class, field
  outside a class, access byte at namespace scope, class end before its
  members or past its parent, bad base access, a base that is not a
  class or is the class itself, base and field initializer targets, a
  constructor with an ordinary name, a qualifier step naming a
  non-namespace and `::` not first). `fuzz_never_panics` now also runs
  on the class sample.
- `crates/kiln_driver/tests/modules_bmi.rs`:
  `kind2_declaration_image_classes` (blanks the capsule's source; the
  importer derives from, constant-evaluates and runs the classes from
  the image alone, `-v` notes the image import, and replaying the blank
  source fails); `kind2_declaration_image_fallback` drops the class
  cases S3 carries and gains a polymorphic class, a virtual base, a
  friend, an anonymous union, `new`/`delete` and a defaulted
  comparison.
- `tests/conformance/module.interface/`: `image-class-run.cpp`
  (`Inputs/img-class.cppm`, taking the image) and
  `image-virtual-run.cpp` (`Inputs/img-virtual.cppm`: inheritance
  across the module boundary, `constexpr` virtual calls on imported
  classes; falls back as a polymorphic class, so it pins the replay's
  behaviour for the follow-up). Both pass with the image on and off and
  under clang++-19.

## Measurements

In spec/modules.md, "Measurements", under "Part 2a, stage S3". On the
class-heavy synthetic module (10,000 records) import goes from 0.10 s to
0.05 s (`-fsyntax-only`), peak RSS 15.3 to 16.6 MiB; the file grows
6.8x (WP-1095). Image on and off give identical diagnostics and LLVM IR
for both measured importers.
