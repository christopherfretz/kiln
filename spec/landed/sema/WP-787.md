# WP-787 — Boost metaprogramming libraries: sema fixes

These fixes came from building the Boost 1.90 header-only
metaprogramming libraries and their tests with kiln++ (`boost_meta`;
docs/status/oss/boost_meta.md has the cluster table). The harness side is
in spec/landed/harness/WP-787.md. Every fix is one commit with its spec
sentence and a conformance test, and every test also passes under
clang++-19.

## Changes

- **Undeduced member template as a dependent use** ([dcl.spec.auto]/11;
  spec/sema.md). Inside a class template, a member function template
  specialization whose return type is still undeduced is a dependent use.
  It is not "used before it is defined" (`deduce.rs`
  `undeduced_dependent_use`; hana, 63 TUs in the first build).
  - Test: `dcl.spec.auto/deduced-member-template-used-in-class-template.cpp`.
- **Injected-class-name of a variadic partial specialization**
  ([temp.local]/1; spec/sema-templates.md). The injected-class-name's
  arguments spread its pack (`templ/actions.rs` `partial_injected_type`).
  This removes fusion `vector.hpp:233` "must be a type" (171 TUs).
  - Test: `temp.local/partial-pack-injected-name-in-alias-template.cpp`.
- **Partial ordering finishes the deduction**
  ([temp.spec.partial.order], [temp.deduct.partial]/12;
  spec/sema-templates.md §4.4 step 4). After deducing one specialization's
  arguments from the other, the substituted arguments must match the
  other's arguments, non-deduced contexts included. They are compared with
  packs flattened (`templ/order.rs` `partial_at_least_as_specialized`,
  `partial_args_match(.., ordering)`). This removes the hana and yap
  "ambiguous partial specializations" errors (~350 TUs).
  - Test: `temp.spec.partial.match/order-non-deduced-context-must-match.cpp`.
- **Braced NSDMI in a class template** ([class.mem.general],
  [dcl.init.list]/3; spec/sema-templates.md §4.9). A default member
  initializer written `m{…}` is instantiated as direct-list-initialization,
  so an explicit constructor is a candidate (`templ/class.rs` `nsdmi`;
  hana `laws/base.hpp:248`, 39+ TUs).
  - Test: `class.mem.general/default-member-initializer-direct-list-dependent.cpp`.
- **Recursive request during partial specialization selection**
  ([temp.inst]/2; spec/sema-templates.md §4.4). While a class template
  specialization's partial specializations are being matched, a nested
  request for that same specialization sees it incomplete. It does not
  re-enter the instantiation (`InstState::selecting`,
  `templ/class.rs` `instantiate_class_as`). Before the fix, a
  static_string TU hit the panic "class properties are already set".
  - Test: `temp.inst/partial-match-recursive-request-incomplete.cpp`.
- **Empty pack expansion as a parenthesized initializer**
  ([temp.variadic]/7, [dcl.init.general]/16.4; spec/sema.md). `T x(a...)`
  with `a` empty is `T x()`, which value-initializes a scalar
  (`init.rs`, `paren_value_init`; variant2 `emplace<I>()`).
  - Test: `temp.variadic/empty-expansion-paren-init-value-initializes.cpp`.
- **Type-dependent class-typed initializer** ([temp.dep.expr]/3,
  [dcl.init.general]/16.6.2; spec/sema-templates.md table "dependent
  forms"). Take `T x(U(a))` with `a` type-dependent. `U(a)` is a
  `CXXUnresolvedConstructExpr` whose type is the class `U`. It is kept
  unconverted, and the initialization runs at instantiation, where it is
  direct-initialization and `explicit T(const U&)` is a candidate
  (`init.rs` `init_from_expr`). Before the fix, Boost.Exception
  `exception_ptr.hpp:185` was rejected in the template definition, which
  failed every outcome test and Boost.Thread.
  - Test: `temp.dep.expr/direct-init-from-dependent-functional-cast-explicit-ctor.cpp`.
- **C-style cast to or from an inaccessible base** ([expr.cast]/4;
  spec/sema-conv.md §3). A C-style or functional cast between a derived
  class and a private or protected base skips the access check
  (`Sema::cast_ignores_base_access`; `ref_cast.rs` `class_relation`,
  `static_downcast`). Before the fix, the SFINAE probe `(D*)(B*)` failed
  for a non-public base, so Boost.TypeTraits `is_virtual_base_of` was false
  for non-public virtual bases. That failed type_traits
  `is_virtual_base_of_test` and describe `bases_test` and
  `compute_base_modifiers` at run time.
  - Test: `expr.cast/c-style-cast-inaccessible-base.cpp`.
- **`bool += pointer`** ([expr.ass]/6, [conv.bool]; spec/sema.md
  "operators"). `b += p` for a `bool b` is `b = b + p`: the computation
  types are `int` and the pointer, and the result converts back to `bool`
  (`expr.rs` `compound_assign`). Constant evaluation rejects it as clang
  does (`kiln_oven` `compound_assign`). Before the fix, type_traits
  `has_plus_assign_test` failed at run time.
  - Test: `expr.ass/bool-add-assign-pointer-run.cpp`.

## Not changed

docs/STANDARD_SUPPORT.md: no row changes state.
