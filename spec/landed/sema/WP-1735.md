# WP-1735 — no static gaps: initialization, conversions and special members

WP-1735 removed the static gaps GAP-020..GAP-040 of
`docs/status/static-gaps.md` (initialization, conversions, special
members). Each site either follows the standard now or gives clang's
diagnostic for an ill-formed program; four were dead and became
`unreachable!` or were deleted, with the reason in the code. Tests are
under `tests/conformance/`.

## Explicit type conversion, functional notation

- **`T(...)` and `T{...}` of an array, reference or incomplete type**
  ([expr.type.conv]/2, [dcl.init.general]/16, [basic.def]/5; clang
  `BuildCXXTypeConstructExpr`, which checks array, then function, then
  `RequireCompleteType`, then the initialization sequence):
  `paren_cast_rejected` gives "array types cannot be value-initialized"
  for `A()`, "reference to type 'int' requires an initializer" for `R()`,
  "reference cannot be initialized with multiple values" for `R(a, b)`;
  `require_complete_construct` gives "invalid use of incomplete type"
  with the forward-declaration note. An undefined class template
  specialization is reported only by its "implicit instantiation of
  undefined template" error; a declared but undefined explicit
  specialization is incomplete
  (`expr.type.conv/incomplete-array-reference-construct.cpp`).
- **CWG2351 `void{}`** ([expr.type.conv]/2): a prvalue of type `void`,
  usable as an expression statement, a discarded operand and a returned
  expression; `void{x}` is ill-formed. clang 19 says "illegal
  initializer type 'void'" (kiln at `-fclang-compat=19`). clang 22
  rejects `void{}` in an instantiated template; kiln does not
  (docs/status/deviations.md;
  `expr.type.conv/void-braced-prvalue-run.cpp`, `-19.cpp`,
  `-in-template-run.cpp`, `void-braced-nonempty.cpp`).
- **A variable-length array type** has no initializer form: `V{}`,
  `decltype(a){}` and the compound literal `(int[n]){...}` are
  "variable-sized object may not be initialized"
  (`expr.type.conv/vla-list-init.cpp`).

## Initialization

- **A reference from a parenthesized expression-list**
  ([dcl.init.general]/16.1, [dcl.init.ref]/5): `T& r(a, b)` is
  "reference cannot be initialized with multiple values"; a
  mem-initializer `r()` of a reference member is "reference to type 'int'
  requires an initializer" ([class.base.init]/9)
  (`dcl.init.ref/paren-multiple-expressions.cpp`,
  `class.base.init/reference-member-empty-parens.cpp`,
  `dcl.init.general/paren-aggregate-multiple-expressions-run.cpp`).
- **A variable or default argument of incomplete class type**
  ([basic.def]/5, [dcl.fct.default]/1; clang
  `ConvertParamDefaultArgument`): "variable has incomplete type 'I'" at
  the variable or parameter, after the argument's own checks, with the
  forward-declaration note (`incomplete_class_rejected`;
  `dcl.init.general/incomplete-class-variable.cpp`,
  `over.match.copy/incomplete-class-target.cpp`).
- **An ambiguous initializer-list constructor** ([over.match.list]/1.1):
  "call to constructor of 'B' is ambiguous" with the candidates as notes,
  through `use_ctor` (`over.match.list/ambiguous-initializer-list-constructors.cpp`).
- **An empty braced list and a constructor template**
  ([class.default.ctor]/1, [dcl.init.list]/3.5): a constructor template
  callable with no argument is a default constructor, so `A a{}`
  value-initializes through it (`has_default_ctor_cheap`;
  `over.match.list/empty-list-constructor-template-default-run.cpp`).
- **A nested designator into a non-aggregate member** ([dcl.init.aggr]/3.1):
  `S s{.n.x = 1}` where `N` is not an aggregate is "initialization of
  non-aggregate type 'N' with a designated initializer list", after
  clang's -Wc99-designator warning. clang accepts it; this is a
  deviation (docs/status/deviations.md;
  `dcl.init.aggr/nested-designator-non-aggregate-member.cpp`).

## Conversions

- **An implicit conversion to an incomplete class type** ([over.match.copy],
  [dcl.init.general]/16.6): "no viable conversion from 'int' to incomplete
  type 'I'" with the forward-declaration note (`incomplete_class_target`,
  id `sema_nonviable_conversion_incomplete`); no error when the
  incompleteness was already reported. A user-defined conversion that
  cannot be applied is "no viable conversion" (`apply_udc`).
- **static_cast and C-style cast to a class type** ([expr.static.cast]/4,
  [expr.cast]/4): the class must be complete ("'I' is an incomplete
  type" with the forward-declaration note);
  reinterpret_cast and const_cast to a class type are bad casts
  (`expr.static.cast/class-and-incomplete-targets.cpp`).
- **Conditional operator, two glvalues of the same category**
  ([expr.cond]/4.2): `same_category_conditional` handles xvalues as well
  as lvalues, so `b ? f() : g()` with `int&&` and `const int&&` is an
  xvalue of type `const int` (`expr.cond/xvalue-cv-composite-run.cpp`).

## new-expressions

- **Braced placement arguments** ([expr.new]/1, /19; the new-placement is
  an expression-list): a braced-init-list argument is an initializer-list
  argument of overload resolution for `operator new` ([over.ics.list]) and
  copy-list-initializes its parameter; also in a template
  (`new_expr` substitutes with `call_arg_list`). A non-viable candidate's
  note is "cannot convert initializer list argument to 'P'"
  (`expr.new/braced-placement-arguments-run.cpp`,
  `expr.new/braced-placement-arguments-no-match.cpp`).

## Special members

- **Subobject assignment in a defaulted assignment operator**
  ([class.copy.assign]/12; clang `buildSingleCopyAssignRecursively`):
  when selection does not give one usable function, the defaulted
  operator is defined by the member call `to.operator=(from)`, which
  reports the overload failure
  (`class.copy.assign/defaulted-out-of-line-bad-subobject.cpp`).
- **A reference or const member** ([class.copy.assign]/7, /12): an
  assignment operator defaulted after its first declaration is "cannot
  define the implicit copy assignment operator for 'R<int>', because
  non-static reference member 'r' cannot use copy assignment operator"
  at the class, with a "declared here" note at the member (clang's
  wording, "copy" also for a move;
  `class.copy.assign/defaulted-out-of-line-reference-const-member.cpp`).
- **Variadic explicitly-defaulted special members**
  ([dcl.fct.def.default]/2; clang `CheckExplicitlyDefaultedSpecialMember`):
  from C++20, on its first declaration, deleted with
  -Wdefaulted-function-deleted ("its declared type does not match");
  otherwise "an explicitly-defaulted copy constructor cannot be variadic"
  (`dcl.fct.def.default/variadic-special-member.cpp`, `-cxx17.cpp`).
- `Selected::Unsupported` and `DeleteReason::Unsupported` are removed:
  nothing produced them (overload sets are never "uncertain", and
  `HAS_INHERITED_ASSIGN` is never set).
