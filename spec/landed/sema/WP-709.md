# WP-709 — eigen 3.4.1 (a 132-test subset) with kiln++

WP-709 builds eigen 3.4.1 through its own CMake build and runs a
132-test subset of its ctest suite, using `scripts/oss`. The subset is
539 TUs. The results are in docs/status/oss/eigen.md. Each fixed
behaviour below has a test and a sentence in the spec that owns it.

## Fixed behaviours

- **A declarator qualifier that leaves arguments to their defaults
  finds the partial specialization** ([temp.spec.partial.general]/7,
  [temp.arg.general]/9, [temp.class.general]/3). A partial
  specialization is registered with its converted arguments, which
  include the primary template's default arguments. Eigen's
  `unary_evaluator<T, Kind = ..., Scalar = typename T::Scalar>` has a
  dependent default argument. Its member is defined out of line as
  `unary_evaluator<CwiseUnaryOp<UnaryOp, ArgType>, IteratorBased>::InnerIterator`.
  The qualifier writes two of the three arguments, so looking it up by
  the written arguments found nothing. Kiln then reported "out-of-line
  definition of 'InnerIterator' does not match any declaration in
  '<error type>'". Now `entered_partial_by_converted_args` also
  converts the arguments with `check_template_args` and looks again
  when fewer arguments are written than the template has parameters.
  This blocked 33 TUs: every sparse test and the tests that include
  `Eigen/Sparse`.
  - Spec: spec/sema-templates.md, "Non-type arguments in a declarator
    scope".
  - Test: tests/conformance/temp.spec.partial.member/out-of-line-member-defaulted-args.cpp.
- **A dynamic exception specification is valid before C++17 and is
  substituted in templates** ([except.spec], C++14 [except.spec]/1;
  [temp.inst]). Kiln rejected `throw(T)` in every language mode.
  Eigen's `CommaInitializer` destructor has
  `EIGEN_EXCEPTION_SPEC(Eigen::eigen_assert_exception)`, and eigen
  compiles its tests as C++11. The error now applies only from C++17
  on. A member of a class template with a dynamic specification is
  also instantiated now: the list is substituted. Before, substitution
  stopped with "not yet implemented: dependent exception
  specification". The deprecation warning before C++17
  (`-Wdeprecated-dynamic-exception-spec`) is not implemented.
  - Spec: spec/sema.md, `act_on_dynamic_exception_spec`.
  - Test: tests/conformance/except.spec/dynamic-exception-spec-cxx11.cpp.
- **`typeid` of a vector type or a `_Complex` type**
  ([expr.typeid]/4, Itanium C++ ABI §2.9.5). The C++ runtime has no
  `type_info` objects for these types. Like clang, kiln now emits the
  `__fundamental_type_info` object `{vtable, name}` as `linkonce_odr`
  where the type is used. This covers GNU vectors and NEON types such
  as `__Float32x4_t`. Before, codegen reported "RTTI for type ... is
  not supported yet", which blocked eigen's `packetmath` (10 TUs). The
  emitted IR matches clang's.
  - Spec: spec/codegen.md, RTTI.
  - Test: tests/conformance/expr.typeid/vector-complex-type-info-run.cpp.

## Not fixed here

- **A class template's `operator new`/`delete` is instantiated on
  use.** This is the 4 link failures in `dynalloc` and
  `geo_quaternion_{1,2,3}`. WP-686 fixed it, and it is on main as
  `91621d627` and `6fb6c7666`. It was not re-fixed here.
