# WP-946 — forbidden type definitions (closes WP-947, WP-987)

This WP implements clang 19's `ActOnTag` / `GetDeclSpecTypeForDeclarator` family of "'S' cannot be defined in …" errors, together with the two declaration rules that came up while matching clang's recovery. It also confirms that the two crashes found by WP-912's clang negative-test run are fixed. The rules are in spec/sema.md §4.4.1, under "Forbidden type definitions", "Template-declarations define no declarators" and "Incomplete result type".

- **Crashes** (WP-946 panic, WP-947 stack overflow): both were already fixed at the root by WP-962. Its landed note gives the causes:
  - `tag_home` keeps a tag out of a frozen complete class.
  - An empty `initializer_list` is built directly, and a visited guard stops re-entry.
  - The sibling search found no new crash. It covered every out-of-line member context that can declare a tag (default arguments, `noexcept`, `decltype`, handlers, static member initializers, class-template members), the `set_templ` "not templatable" panic under every template-head misuse, and the `init.rs` list-constructor paths.
- **Forbidden contexts.**
  - The parser classifies each tag site (`TagSite` on `DeclSpec`, `Parser::next_tag_site`).
  - `Sema::diag_type_defined_in` reports the error at the tag's name. It covers type-ids (`sizeof`, `alignof`, `typeid`, casts, `__builtin_offsetof`, `decltype`, `new (T)`, template arguments, type-parameter defaults), non-type template parameter types, conversion-type-ids, handlers, dynamic exception specifications, enumerators, prototype scope, conditions, alias templates and result types.
  - Result types are reported once per function chunk.
  - A rejected tag makes the declaration specifiers an error. An enumeration body is skipped; a class body is parsed.
  - A tag nested in another declaration does not take that declaration's template heads (`hide_open_heads`).
  - The allowed contexts are pinned by `dcl.type/type-definition-allowed-contexts-run.cpp` and `temp.param/lambda-local-class-in-parameter-type.cpp`.
- **Naming.**
  - The tag type is printed fully scoped, and a scope stops at the first enclosing function, as in clang's `AppendScope`. This changes `write_scope` for every local class.
  - The enclosing enumeration is printed at 19. At 22 it is dropped when the enumeration is unscoped.
- **Dynamic exception specifications.** Rejected types are dropped, so `throw(struct S {})` becomes `throw()`, as in clang.
- **[temp.pre]/5.** A class defined by any template-declaration takes no declarator: clang's "expected ';' after struct". A concept consumes its head before its constraint.
- **[dcl.fct.def.general]/2.** "incomplete result type 'X' in function definition" (new id `sema_func_def_incomplete_result`).
- **Tests.**
  - `class.conv.fct/type-defined-in-conversion-type.cpp` is flipped from xfail.
  - New tests: `dcl.type/type-defined-in-type-specifier.cpp`, `dcl.fct/type-defined-in-{default-argument,result-type}.cpp`, `stmt.pre/type-defined-in-condition.cpp`, `temp.alias/type-defined-in-alias-template.cpp`, `except.handle/type-defined-in-handler.cpp`, `expr.new/type-defined-in-new-type-id.cpp`, `dcl.enum/type-defined-in-enumeration{,-19}.cpp`, `temp.pre/class-definition-takes-no-declarator.cpp` and `dcl.fct.def.general/incomplete-result-type.cpp`.
  - New xfail repro: `temp.param/lambda-in-parameter-type-mangle-run.cpp`. A lambda in a template parameter type cannot be mangled yet.
