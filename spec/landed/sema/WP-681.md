# WP-681 — Catch2 v3.16.1: protected access through using-declarations, pack deduction, comma subscripts, dependent char arrays

Found building Catch2 v3.16.1 with kiln++ (docs/status/oss/catch2.md).
Each behaviour below was reduced to a standalone program that clang++-19
accepts (or diagnoses identically), and is pinned by a conformance test
that also passes under clang++-19. This WP also takes in the
protected-using-declaration cluster that BACKLOG row WP-671 names.

## Behaviour

- **Protected member named through a using-declarator in a class
  template** ([namespace.udecl]/19, [class.protected]/1,
  [temp.dep.type]/1; spec/sema-class.md, access control). A
  `using B::m;` whose path to `B` passes through a dependent base is
  checked speculatively on the template and replayed per instantiation
  (`replay_dependent_access`). The replay now maps the pattern's object
  class, and the pattern's enclosing classes, to the matching classes of
  the instantiation (`instantiated_classes`). Before this, it rejected
  Catch2 clara's `'m_type' is a protected member of 'ResultBase'`.
  Test: `tests/conformance/namespace.udecl/protected-member-through-dependent-base.cpp`.
- **Inherited protected constructor** ([namespace.udecl]/19,
  [class.protected]/1; spec/sema-class.md). Initializing a `C` through a
  constructor that `C` inherits by `using B::B;` checks the protected
  base constructor with `C` as the object class, as clang's
  `CheckConstructorAccess` does with the using-shadow's class. A static
  member of `C` may therefore construct a `C`, while an unrelated
  derived class of the base may not. The note for a protected
  constructor or destructor reached through the wrong object is clang's
  "protected {constructor|destructor} can only be used to
  {construct|destroy} a base class subobject"
  (`note_access_protected_restricted_ctordtor`).
  Test: `tests/conformance/class.inhctor.init/protected-base-ctor-object-class.cpp`.
- **Pack-expansion A against a non-pack P** ([temp.deduct.type]/10;
  spec/sema-templates.md, deduction). When deducing a
  parameter-type-list, an A that came from a function parameter pack
  fails against a P that is not one, so partial ordering ranks
  `R (C::*)(A) const` above `R (C::*)(A...) const`. kiln used to report
  ambiguous partial specializations for clara's `UnaryLambdaTraits`.
  Test: `tests/conformance/temp.deduct.type/function-parameter-pack-vs-single.cpp`.
- **Comma in a subscript before C++23** (C++20 [expr.sub]/1,
  [depr.comma.subscript]; spec/sema-overload.md, `a[b...]`). Before
  C++23 the index is one expression, so `x[0, 1, 2]` is a comma
  expression and a class's `operator[]` gets one argument. In C++20 the
  top-level comma (built-in or overloaded) warns
  `-Wdeprecated-comma-subscript` at the outermost comma
  (`sema_deprecated_comma_subscript`, in the `-Wdeprecated` umbrella).
  C++23 keeps the expression-list.
  Tests: `tests/conformance/depr.comma.subscript/comma-index-cxx{17,20,23}.cpp`,
  `tests/conformance/expr.sub/p1161-probe.cpp` (its `xfail(kiln)` is
  removed; docs/STANDARD_SUPPORT.md P1161R3 is now done).
- **String literal initializing an array of dependent element type**
  ([dcl.init.string]/1, [temp.dep.type]/9; spec/sema.md, initialization).
  In a template, `T a[N] = "abc";` with a dependent `T`, or any
  type-dependent initializer, is kept as written until instantiation.
  It used to be rejected at definition with "array initializer must be
  an initializer list".
  Tests: `tests/conformance/dcl.init.string/string-literal-dependent-element-{run,errors}.cpp`.
