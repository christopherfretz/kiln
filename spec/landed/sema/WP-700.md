# WP-700 — glog v0.7.1 with kiln++: GNU noreturn as a function type attribute

WP-700 built glog v0.7.1 with kiln++ through its own CMake build and
CTest suite (M8 wave 2, docs/status/oss/glog.md). It found one kiln
cluster, a spurious `-Winvalid-noreturn` on glog's `noreturn` member
`LogMessage::Fail()`, whose body only calls through the pointer
`g_logging_fail_func` of type
`typedef void (*logging_fail_func_t)() __attribute__((noreturn))`. The rule below is also stated in spec/types.md §5.4.

- **GNU `noreturn` is a function type attribute** (clang
  `handleFunctionTypeAttr` for `AT_NoReturn`; `FuncInfo::noreturn`,
  spec/types.md §5.4). `__attribute__((noreturn))` and
  `[[gnu::noreturn]]` (not `[[noreturn]]`, not `_Noreturn`) written on a
  declarator set the bit on the declared function type, or on the
  function type a pointer, reference or member pointer to function
  designates (typedefs, variables, parameters, fields), and on a lambda's
  call operator (`[]() __attribute__((noreturn)) { ... }`); the
  declaration attribute stays as well
  (`Sema::apply_noreturn_attrs`, `crates/kiln_sema/src/decl_attrs.rs`).
  - Redeclarations merge it in either direction (clang
    `MergeFunctionDecl`); the redeclaration type comparison ignores it.
  - An explicit specialization or explicit instantiation's type adopts
    the template's bit before deduction (clang `adjustCCAndNoReturn`,
    `crates/kiln_sema/src/templ/deduce_call.rs`).
  - A function pointer conversion ([conv.fctptr]) may drop it, as it may
    drop `noexcept`, but never adds it (clang `IsFunctionConversion`,
    `crate::conv::is_function_conversion`); the same rule applies to
    reference binding and to taking the address of an overload set
    ([over.over]). So `void (*)()` and its `noreturn` form are distinct
    types, a conditional operator's composite type is the plain one, and
    overload resolution prefers the exact match.
  - A call whose callee has a `noreturn` function type (directly or
    through a pointer or reference) ends control flow for
    `-Wreturn-type` and `-Winvalid-noreturn` (clang `getFunctionExtInfo`
    in the CFG); codegen already marked such calls `noreturn`.
  - Mangling ignores the bit, as clang's does.

Tests: `tests/conformance/dcl.attr.noreturn/gnu-noreturn-function-type.cpp`,
`tests/conformance/dcl.attr.noreturn/gnu-noreturn-function-type-conv.cpp`.

Not done: GNU `noreturn` in a pointer chunk of an abstract declarator
(`using F = void (* __attribute__((noreturn)))();`) or inside grouping
parentheses (`void (__attribute__((noreturn)) *p)();`) is not yet applied
to the function type (`crates/kiln_parse/src/decl.rs`
`skip_type_position_attrs`).
