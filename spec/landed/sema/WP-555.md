# WP-555 — default arguments of static member functions called through a member access

Extends spec/sema-overload.md §7 ("Calls"). Clang 19 and 22 and GCC 16.1
agree on every case below.

## Static member calls through `.`/`->` ([expr.ref], [dcl.fct.default]/1, [temp.dep.type]/7)

- A call whose callee is a `MemberExpr` naming a static member function
  (`o.f(1)`, `p->f(1)`, `this->f(1)`) is not a bound-member call, so it
  took `act_on_call`'s plain path, which recorded a named callee only for
  a `DeclRefExpr`: `convert_call_args` saw no parameter declarations and
  dropped every default argument ("too few arguments to function call,
  expected 2, have 1"). The same call by name (`f(1)`, `S::f(1)`) was
  correct. The `named` callee now also covers a `MemberExpr` naming a
  function (`expr.rs`, `act_on_call`), so the call takes the defaults of
  the omitted trailing parameters (instantiating lazy ones, spec/
  sema-templates.md §4.4), notes "'f' declared here" on an arity error,
  runs the `format` attribute check, and a consteval callee is an
  immediate invocation. The "invalid definition" short-cut stays for
  calls by name only (`direct`).
- The motivating shape: `this->ucopy(first, last, out)` in a class
  template deriving from a dependent partial specialization whose static
  member template `ucopy` ends in a SFINAE-guard parameter
  `enable_if_t<...>* = nullptr`; the call is resolved at instantiation and
  now uses the guard's default.
