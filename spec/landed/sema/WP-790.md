# WP-790 — CWG2352 reference binding, first-spelling mangling, needed-function set

Three codegen and ABI follow-ups found by WP-783 in real-world code.

## 1. CWG2352: similar pointers bind directly (`conv/qual.rs`, `conv/mod.rs`, `overload/ics.rs`)

- `conv::qual::similar_ref_relation(t1, t2)` is clang 19's
  `CompareReferenceRelationship` qualification loop. For similar types
  ([conv.qual]/2) it returns `Some(true)` (reference-compatible) when a
  prvalue "pointer to cv2 T2" converts to "pointer to cv1 T1" by a
  qualification conversion, `Some(false)` (only related) when they are
  similar with the same `P_i` at every level, and `None` otherwise. An
  array of unknown bound against one of known bound therefore stays
  unrelated, as in clang 19.
- `bind_reference` binds a compatible glvalue directly with a `NoOp`
  qualification adjustment. `const int *const &r = p` (with `int *p`)
  creates no temporary, so `&r == &p` in a constant expression and
  `vector::begin()`-style code loses the extra alloca and store. A
  related-only pair is the new error
  `sema_reference_bind_incompatible_quals` ("... not permitted due to
  incompatible qualifiers", clang's `FK_ReferenceInitDropsQualifiers`
  select 2).
- `ref_ics` ranks the direct binding with third step `Qualification`
  ([over.ics.rank]/3.2.5): an identity `T *const &` beats it, the
  less-qualified similar binding beats the more-qualified one, and it
  beats binding an rvalue reference to a converted temporary.
- The oven's array-extent lookup (`Types::alike`: equal up to cv at any
  pointer/array level) accepts the qualified view the reference now
  names (`ty.rs` `extent_in`, `vm.rs` `extent_of`).
- Rule: spec/sema-conv.md §5. Tests:
  `tests/conformance/dcl.init.ref/cwg2352-similar-pointer-binds-directly.cpp`
  (address identity, array, member pointer, xvalue, `begin()`),
  `cwg2352-similar-pointer-binds-directly-run.cpp`,
  `cwg2352-incompatible-qualifiers.cpp` (strict diags),
  `tests/conformance/over.ics.rank/cwg2352-similar-reference-binding.cpp`,
  `tests/codegen/cwg2352_similar_ref_binding.cpp` (IR equal to clang 19).

## 2. Dependent expressions mangle from the first spelling of their canonical type (`kiln_ast` types, `kiln_abi` mangle)

- `Types` records, per canonical `TypeId`, the written argument list
  (`note_arg_origin`, only when it holds an expression) or expression
  (`note_expr_origin`) that first created a canonical template
  specialization, dependent template specialization, dependent
  `decltype` or dependent-sized array. The mangler reads them back
  (`arg_origin`, `expr_origin`), as clang keeps the first spelling in
  its canonical node.
- The choice is per enclosing canonical type, not per expression
  profile. It matches clang 19 in both orders, within one TU and across
  TUs that agree on the first spelling. Rule: spec/abi.md §8.15. Tests:
  `tests/codegen/dependent_expr_first_spelling.cpp` (both orders, one
  TU; TST, `decltype` and array bound),
  `tests/conformance/temp.over.link/dependent-expr-first-spelling-two-units-run.cpp`
  (two linked TUs, names pinned by asm labels).

## 3. `allocator_traits::max_size` emission: not reproduced

On small `std::vector` / allocator TUs (`push_back`, `reserve`,
`resize`, `insert`, copy, `max_size`) at `-O0`, the set of defined
functions in kiln's IR equals clang 19's. That holds with libc++ (79/79
and 344/344 functions) and with libstdc++ (251/251). The WP-783
difference does not reproduce on main 75d7f9612, so there is no
needed-function rule to fix here.

## Follow-ups (pre-existing libc++ mangling differences, present before this WP)

- A requires-clause that kiln cannot encode mangles as `Qu7unknown`
  (`crates/kiln_abi/src/mangle/constraint.rs:190`). For example, libc++
  `reverse_iterator::operator->` gets that where clang gives
  `Qoo12is_pointer_v...`.
- Alias templates in a dependent `enable_if` / `decltype` are expanded,
  where clang keeps the alias name:
  - `__to_address`'s `_And<...>::value` becomes
    `DTclsr3stdE12__and_helper...` (clang: `sr4_AndI...E`).
  - `std::prev`'s `__has_input_iterator_category<T>` is expanded the
    same way.
