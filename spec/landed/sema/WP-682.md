# WP-682 — googletest v1.17.0 with kiln++: driver, deduction, override and attribute fixes

WP-682 built googletest v1.17.0 with kiln++ through its own CMake build
and CTest suite (M8 wave 1b, docs/status/oss/googletest.md) and fixed
the four kiln clusters it found. Each rule below is also stated in the
spec it extends.

- **Bare `-W`** (spec/diag.md §4): the driver takes clang's old spelling
  of `-Wextra` (clang `Options.td` `W`). googletest's `cxx_strict_flags`
  pass it to `libgtest`. Test:
  `tests/conformance/dcl.fct/unused-but-set-parameter-bare-w.cpp`.
- **Compile thread that cannot be created** (spec/driver.md "Output,
  diagnostics, exit status"): when the thread with the
  `-fkiln-stack-size=` stack cannot be spawned (for example under an
  address-space cap), the driver prints `<prog>: error: cannot create the
  compile thread with a N-byte stack: <os error> (lower it with
  -fkiln-stack-size=)` and exits 70. It no longer exits 70 silently.
  `scripts/oss/kiln-cxx` classifies that line as `oom`
  (spec/landed/harness/WP-666.md). Test:
  `crates/kiln_driver/tests/driver.rs`
  `compile_thread_spawn_failure_is_diagnosed`.
- **Deduction against the bases of an uninstantiated A**
  ([temp.deduct.call]/4.3, [temp.inst]/2; spec/sema-templates.md):
  before deducing a class template-id P against the base classes of a
  class template specialization A, kiln instantiates A, silently, as
  clang's `DeduceTemplateBases` does through `isCompleteType`. Before
  this, only an unqualified call worked, because ADL had already
  instantiated A. A qualified call such as libstdc++ 14's
  `std::__get_helper<I>(t)` inside `std::get` failed whenever the tuple
  type had not been instantiated earlier in the TU. Tests:
  `tests/conformance/temp.deduct.call/derived-base-instantiates-argument-class.cpp`,
  `tests/conformance/temp.deduct.call/libstdcxx-get-uninstantiated-tuple.cpp`.
- **`-Winconsistent-missing-override` and system-header macros**
  (spec/sema-class.md): if a method's name is a macro argument, kiln
  follows it to the parameter token in the macro body. If that token is
  spelled in a system header, there is no warning (clang
  `DiagnoseAbsenceOfOverrideControl`). This covers googletest's
  `MOCK_METHOD` under `-isystem`. Test:
  `tests/conformance/class.virtual/inconsistent-missing-override-system-macro.cpp`.
- **`disable_tail_calls`** ([dcl.attr.grammar]/5; spec/sema.md,
  spec/codegen.md): it is known in GNU syntax and as
  `clang::disable_tail_calls`. `__has_attribute` already reported it.
  - It takes no arguments.
  - It is function-only: elsewhere it warns and is ignored.
  - It is mutually exclusive with `naked`. The later of the two is an
    error and is dropped.
  - It emits `"disable-tail-calls"="true"` on the function's declaration
    and definition, not on call sites (clang `ConstructAttributeList`).
  - googletest's `GTEST_NO_TAIL_CALL_` uses it.
  - Tests: `tests/conformance/dcl.attr/gnu-disable-tail-calls.cpp`,
    `tests/codegen/disable_tail_calls_o2.cpp`.

The `-Wunknown-attributes` warnings on `no_sanitize_address`,
`no_sanitize_memory` and `no_sanitize_thread` in googletest's build were
WP-667's cluster (spec/landed/sema/WP-667.md). WP-682 did not touch them.
