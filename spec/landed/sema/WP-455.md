# WP-455 — computed-goto jump check through lambda bodies; constexpr missing return (WP-1056)

Two accepts-invalid / wrong-verdict fixes left over from WP-444 (computed goto) and WP-945 (never-constant builtins). The contract is spec/sema.md §7.4 ("the walk enters lambda bodies") and §5.20 ("Missing return statement", "When the rules run").

- **Item A: indirect goto into a lambda's labels.**
  - Root cause: clang's `JumpScopeChecker` reaches a lambda's body through `LambdaExpr::children`, so a function's indirect `goto *p` sees the labels whose address a lambda in it takes. Kiln's walk (`jump_scope.rs` `expr`) stopped at the lambda expression and accepted such jumps.
  - Fix: `expr` walks the lambda body as a nested scope at the point of the lambda expression. The lambda's labels, `&&l` operands, gotos and indirect gotos join the outer check. Default arguments and local classes' members are not walked, as in clang.
  - clang reports an error inside a lambda twice (once for the lambda, once for the enclosing function); kiln merges the duplicate (`dup(clang)` in the test).
- **Item B: no return statement (WP-1056).**
  - Root cause: kiln had no `err_constexpr_body_no_return`. `constexpr int f() { __builtin_unreachable(); }` fell through to the never-constant check, which reported "never produces a constant expression" where clang reports "no return statement in constexpr function".
  - Fix: `constexpr_body.rs` `check_constexpr_missing_return`, following clang `CheckConstexprMissingReturn`: an error before C++14 for any return type; from C++14 unless the return type is void or dependent; nothing from C++23. The function is made invalid, so never-constant skips it. Constructors are exempt; a `return` in a lambda or statement expression does not count.
  - C++11: iteration statements and `continue` are "statement not allowed in constexpr function" (they are not C++14 extensions in clang).
  - Ordering: the virtual-base, statement/variable and missing-return rules now run in `end_function_body` (`check_constexpr_definition`) right after the jump-scope check and before the flow warnings, as clang's `CheckConstexprFunctionDefinition` does. An error there now suppresses the stray `-Wreturn-type` kiln used to emit (`struct NL { NL(); }; constexpr int f(int x) { NL n; if (x) return 1; }`).
  - Lambdas declared only `consteval` now count as explicitly constexpr for these rules (kiln used to skip every body rule for them, and accepted a `consteval` lambda coroutine, which it made non-consteval).
- **clang probes** (clang++-19 and clang++-22 agree everywhere) for `__builtin_unreachable()`, `__builtin_trap()`, a `[[noreturn]]` call, `std::unreachable()`, `for(;;);`, `while(true){}` as the whole body of `constexpr int f()`:
  - c++11: the four calls are "no return statement" (plus a C++14-extension warning kiln lacks); the loops are "statement not allowed in constexpr function";
  - c++14, c++17, c++20: all "no return statement in constexpr function" (`consteval`: "consteval function");
  - c++23, c++26: accepted; under `-Winvalid-constexpr`, "never produces a constant expression" with clang's note.
  - kiln matches all of them except the C++14-extension warning.
- **Tests:** `stmt.goto/computed-goto-jump-scope-lambda.cpp`; `dcl.constexpr/no-return-cxx{11,14,20,23}.cpp`, `no-return-invalid-constexpr-cxx26.cpp`, `no-return-type-warning-after-{error,goto}-cxx20.cpp`; `dcl.fct.def.coroutine/consteval-lambda-coroutine.cpp`. Each matches clang++-19 and clang++-22.
- **Known gaps** (follow-ups):
  - the C++11 literal-type check of a constexpr function's return and parameter types (`err_constexpr_non_literal_return` / `_param`) is missing: kiln reports `constexpr void f() {}` in C++11 as "no return statement" where clang reports "return type 'void' is not a literal type", and accepts `constexpr NL f();` before C++23;
  - a never-constant error (`-Winvalid-constexpr`) still comes after the function's `-Wreturn-type`, which clang then suppresses (the check needs the attached body);
  - lambdas get no never-constant check (`[]() constexpr -> int {}` under `-Winvalid-constexpr` in C++23; `[]() constexpr { static int i = 0; return i; }` in C++20);
  - warnings only: the C++11 "use of this statement in a constexpr function is a C++14 extension", the C++11 constexpr-not-const warning, `-Wc++98-c++11-compat`'s no-return warning, and "definition of a static variable in a constexpr function is a C++23 extension".
