# WP-765 — P3598R0 const splices in contract assertions and the WP-755 contracts gaps

Implements P3598R0 and closes the gaps spec/contracts.md §9 listed
after WP-755. The target is the Croydon DIS; GCC 16.1 is the oracle
where it follows the wording, and §9 records each place kiln follows
the wording instead.

## Changes

- **P3598R0: splices in a predicate are const-ified**
  ([expr.prim.splice]/2.5, [expr.prim.id.unqual]/7; spec/contracts.md
  §5). A splice designating a variable or a structured binding is built
  through `build_decl_ref`, so the contract watermark const-ifies it
  exactly as the id-expression (also for a reflection that is a template
  argument, on the instantiation). A splice of an object (/2.3,
  `object_of`) is not const-ified: `splice_object_expr` builds it with
  the contract context cleared. Tests:
  `tests/conformance/expr.prim.splice/contract-constify.cpp`,
  `contract-constify-run.cpp` (compared with GCC 16.1),
  `contract-constify-object.cpp`.
- **Implicit captures only for contract assertions are ill-formed**
  ([expr.prim.lambda.closure]/10; spec/contracts.md §5, §8): new
  `sema_contract_only_implicit_capture` (GCC's wording) with a
  "declared here" note, checked when the lambda ends
  (`kiln_sema/src/lambda/capture.rs` `note_contract_capture_use`,
  `check_contract_only_captures`; `LambdaScope::contract_caps`).
  Tests: `tests/conformance/expr.prim.lambda.closure/p10-contract-only-capture.cpp`
  (Example 6, compared with GCC), `p10-contract-only-capture-kiln.cpp`.
- **The postcondition-parameter const rule on template definitions**
  ([dcl.contract.func]/7, [temp.res.general]/6): a non-dependent
  parameter of a member or friend of a class template or of a function
  template is checked on the definition, once for the pattern
  (`Sema::post_param_pattern_locs`); a friend without a seq is checked
  against the function it will redeclare (`Sema::friend_pattern_prev`).
  Test: `tests/conformance/dcl.contract.func/p7-template-definition.cpp`.
- **Violation site name of a member explicit specialization**: the
  name is `__PRETTY_FUNCTION__`'s, and `Sema::function_pattern` now
  stops at an explicit specialization of a member of a class template
  specialization, so it prints `int C<long>::m(long) [T = long]` as
  clang 22 does. Tests:
  `tests/conformance/basic.contract.eval/run-site-name-explicit-spec.cpp`,
  `tests/conformance/dcl.fct.def.general/predefined-member-explicit-spec.cpp`
  (compared with clang).
- **P3097** (contracts on virtual functions, C++29): not implemented; a
  precise note in spec/contracts.md §9 Decisions.
