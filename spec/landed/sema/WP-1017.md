# WP-1017 — accepts-invalid fixes, part 3

These are the access, abstract, deleted, template-declaration, lookup and exception-specification checks from clusters 9–12 of WP-912's clang negative-test run. It closes WP-955–957 (follow-ups below). Every diagnostic is matched against clang 19 for wording and location. Each rejection test has a valid form next to it.

- **Access, abstract and deleted checks** (WP-955; spec/sema-class.md §2.4, §3.4).
  - Friend declarations of another class's member function are access-checked from the befriending class. A dependently scoped one is checked again for each instantiation. Test: `class.friend/friend-private-member.cpp`.
  - Virtual bases' destructors, inherited ones included, must be accessible from a destructor: `inherited virtual base class 'P' has private destructor`. Test: `class.dtor/virtual-base-dtor-access.cpp`.
  - Deleted `operator delete` for a virtual destructor:
    - a definition that uses it is ill-formed;
    - an implicit or defaulted virtual destructor whose lookup finds it is deleted ([class.dtor]/7.3), with clang's override and `= default` diagnostics.
    - Test: `class.dtor/virtual-dtor-deleted-operator-delete.cpp`.
  - Abstract temporaries. These are now rejected:
    - a braced list or converting constructor binding a reference;
    - an explicit type conversion;
    - a by-value parameter of a deduced specialization;
    - a variable of a class template specialization found abstract once instantiated.
    - Test: `class.abstract/abstract-temporary-for-param.cpp`.
- **Template declaration rules** (WP-956; spec/sema-templates.md §4.4, §6.10, §5.7 constraints; spec/sema-class.md §4.7).
  - A class or variable partial specialization that is not more specialized than its primary is rejected (`check_partial_more_specialized`, `primary_at_least_as_specialized`, renamed `not_more_specialized_than_primary` by WP-1053).
    - The check is conservative. It skips packs, constraints, member templates of class templates, and primary NTTPs whose type is a placeholder or dependent.
    - A partial NTTP whose type differs from the primary parameter it is deduced from (`signed char C` from `long N`) fails deduction ([temp.deduct.type]/20), so the partial specialization is more specialized.
    - Test: `temp.spec.partial.general/not-more-specialized.cpp`.
  - CWG526: a parenthesized NTTP argument `(N)` is a non-deduced context. Test: `temp.deduct.type/parenthesized-nttp-non-deduced.cpp`.
  - Before C++20, a floating-point or class type NTTP is an error ("before C++20"), and any other non-structural type gets the plain error. Tests: `temp.param/float-nttp-cxx{17,20}.cpp`.
  - CWG1878: `auto`, `C auto` or `decltype(auto)` as a conversion function template's type is an error. It is reported at `Declarator::conv_type_loc`, which is new. Test: `class.conv.fct/conversion-template-deduced-type.cpp`.
  - "satisfaction of constraint ... depends on itself" is a hard error inside SFINAE (`is_sfinae_report`). Test: `temp.constr.atomic/self-dependent-constraint.cpp`.
- **Lookup and type checks** (WP-957; spec/sema.md §4.4, §4.5; spec/parse.md literals).
  - Wrong class-key or `enum` (`Sema::diag_wrong_tag`):
    - reported at the keyword, with `previous use is here`;
    - for references, friends, friend class templates, explicit and partial specializations, references to specializations (`'B<float>'`), and dependent `struct T::X` at instantiation;
    - a reference recovers to the found tag.
    - Test: `dcl.type.elab/wrong-tag-kind.cpp`.
  - `-Welaborated-enum-class` (error by default) at the `class`/`struct` keyword, with recovery as a plain `enum` reference. Test: `dcl.type.elab/elaborated-enum-class.cpp`.
  - `-Wfriend-enum` + `remove 'enum' to befriend an enum`, also on the dependent path. Test: `class.friend/friend-enum.cpp`.
  - Ambiguous qualified elaborated-type-specifier: candidates are listed latest-nominated first, and a not-found qualified reference declares a hidden invalid tag. Test: `dcl.type.elab/ambiguous-qualified-elab.cpp`.
  - `alignas(incomplete)` gets `invalid application of 'alignas' to an incomplete type`. Test: `dcl.align/alignas-void.cpp`.
  - Differing ud-suffixes in string literal concatenation are an error. Test: `lex.ext/differing-ud-suffixes.cpp`.
  - Rejects-valid fix: `struct A<T>::K` naming a member of another template's unknown specialization ([temp.dep.type]/6) is dependent, not looked up. Test: `temp.dep.type/elaborated-unknown-specialization.cpp`.
- **Exception specifications more lax than the base** (WP-957; spec/sema.md §4.7).
  - An overrider's dynamic `throw(T...)` list is compared type by type with the base's, using [except.handle]/3 matching (`override_exc_spec_lax`, `handler_can_catch`).
    - `handler_can_catch` gained clang's `std::nullptr_t` case and its const-reference-to-pointer rule.
    - Lists with dependent types or pack expansions wait for instantiation.
  - Declaration-time checks (an overrider with no written specification) are reported before the delayed ones, as clang orders them.
  - Tests: `class.virtual/exception-spec-dynamic.cpp`, `class.virtual/exception-spec-dynamic-pack-nested.cpp`.
- **Interface changes**:
  - `kiln_sema::declspec::Declarator::conv_type_loc`;
  - `Sema::is_unknown_specialization_tag`;
  - `parse_tag_key` returns the `class`/`struct` keyword location;
  - `act_on_friend_class_template` / `act_on_qualified_friend_class_template` take `(kw, nloc)`;
  - new diagnostics:
    - `sema_elaborated_enum_class` (`-Welaborated-enum-class`);
    - `sema_friend_enum` (`-Wfriend-enum`);
    - `note_remove_enum_friend`;
    - `lex_string_concat_mixed_suffix`;
    - a new `sema_auto_not_allowed` site (`CONVERSION_TEMPLATE = 24`).
- **Not done** (follow-ups):
  - members of a class template whose declaration fails at instantiation are dropped silently, so instantiation-time tag errors are missed;
  - constrained and member-template partial specializations skip the more-specialized check;
  - `F<T..., int>` is not diagnosed as non-deducible;
  - plain-type qualified ambiguity lists candidates in discovery order;
  - implicit members with a computed type-list exception specification are not compared with the base;
  - the nested function-type exception-specification rule for overriders is not checked.
