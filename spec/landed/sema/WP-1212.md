# WP-1212 — partial ordering with a template template parameter's deduced defaults

A pre-release OSS pass found Boost.Container's `container_rebind` rejected as
ambiguous for `vector<int>` (clang 19, clang 22 and GCC accept). The rules are
in spec/sema-templates.md, the `deduce_ttp_id_args` paragraph.

- **Root cause.** WP-812 made `Cont<V>` of `template <class> class Cont`
  match `vec<int>` of `template <class T, class A = int> struct vec`
  ([temp.arg.template]/3, P0522, CWG2398 as clang deduces it). Ordering that
  partial against `Cont<V, A>` of `template <class, class> class Cont`,
  `Cont<V>` deduces from the synthesized `Cont'<V', A'>` with `A'` bound as
  `Cont`'s default (clang's `DeducedTemplateName`), but finishing the
  deduction ([temp.deduct.partial]/12, `partial_args_match` with `ordering`)
  compared the substituted `Cont'<V'>` with `Cont'<V', A'>` and failed. The
  reverse direction fails too (`A` has no argument), so the two were
  unordered and every type both matched was ambiguous. WP-1053 and WP-1105
  are not involved; the variadic `Cont<V, A, An...>` one only completes the
  trio.
- **Fix.** `same_arg_with_deduced_defaults` / `same_type_with_deduced_defaults`
  (`templ/order.rs`): in ordering, a template-id of a synthesized template
  template parameter whose arguments are a prefix of the synthesized one's
  compares equal, through pointers, references, arrays, member pointers and
  template arguments.
- **Test.** `temp.spec.partial.order/ttp-deduced-defaults-rebind-run.cpp`:
  the trio with a plain and an allocator-rebinding body, the pair in both
  orders, nested in `*`, `const &` and a template argument, a one-parameter
  template, a template without defaults (only the variadic one matches) and
  the C++03 fixed-arity chain.
- **Not changed.** With the variadic one and `Cont<V, A>` alone, clang 22
  picks the variadic one and clang 19 and GCC the two-parameter one; kiln
  picks the two-parameter one at both `-fclang-compat` levels (every choice
  names the same type in the trio). The variadic one against `Cont<V>` stays
  ambiguous, as in clang 19 and GCC (clang 22 picks the variadic one).
