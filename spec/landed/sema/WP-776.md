# WP-776 — concepts follow-ups from WP-771 (lambda packs, P2963 patterns, used-parameter walk)

Closes the three gaps WP-771 left (BACKLOG WP-776).

## Changes

- **Lambda declarators track unexpanded packs** ([temp.variadic]/5, /12;
  spec/sema-templates.md, "Unexpanded packs"). In a lambda's
  template-head requires-clause, trailing requires-clause and template
  parameter default arguments, the lambda's own packs are diagnosed at
  the site ("requires clause contains unexpanded parameter pack",
  "default argument contains ..."), and an enclosing template's packs
  make the lambda-expression contain them, so `[]<class U>() requires
  C<U, Ts> {}...` expands and an unexpanded use is diagnosed at the
  enclosing full-expression. The lambda's lazily checked constraints see
  the expansion's element (`concepts/mod.rs` `act_on_requires_clause`,
  `templ/pack.rs`, `lambda/mod.rs`, `subst/lambda.rs`).
- **P2963 fold patterns** ([temp.constr.normal]/1.4-1.5,
  [temp.constr.fold]; §8.2). A `&&`/`||` fold over type or non-type
  packs is a fold expanded constraint whatever its pattern
  (`(C<Ts, int> && ...)`, `(C<Box<Ts>> && ...)`). Through a concept the
  mapped elements are substituted into the concept's pattern
  (`fold_over_mapping`): an expansion element `X...` gives a fold over
  `X`'s packs with `X` in the parameter's place, other elements give the
  pattern normalized with that element, joined in order
  (`AllC<int, Ts...>`). So `AllC<Box<Ts>...>` is the written
  `(C<Box<Ts>> && ...)` (`templ/concepts/normal.rs`).
- **Used-parameter walk** ([temp.constr.atomic]/1; §8.2). `concepts/used.rs`
  lists every expression, type, template-name and nested-name-specifier
  kind, reflection splices included (no fallback arm). The whole mapping
  is kept only for lambdas, statement-expressions, expansion-statement
  selectors, dependent class/enum types and unresolved using types.
- **Canonical atom mappings** ([temp.constr.atomic]/2; §8.2, spec/types.md
  §7.2). A non-dependent argument kept as written maps as its converted
  value (integral/enumeration parameter) or its profile
  (`written_mapping_arg`), so `C<1, int>` and `C<2 - 1, long>` share
  atoms. A reflect-expression profiles by its value, and `^^T` of a
  template type parameter by its canonical type, so `C<^^T>` in two
  templates is equivalent (`kiln_ast/src/types/profile_expr.rs`).

## Wording over clang 22

clang 22 identifies a concept's fold elements by the concept's pack
parameter, not the mapped pattern; `temp.constr.fold/p1-fold-expanded-concept-mapping.cpp`
is `skip(clang)`. GCC 16.1 lacks P2963. The template-head form of the
lambda test is `requires: clang<22` (clang 22 mis-evaluates it).

## Remaining

- The walk keeps the whole mapping for lambdas, statement-expressions,
  expansion-statement selectors and dependent class/enum types
  (`templ/concepts/used.rs`).
- A non-dependent written argument of a non-integral parameter (class
  type, pointer) maps by profile, so value-equal spellings that are not
  equivalent stay distinct atoms (`written_mapping_arg`).
- A dependent reflection other than `^^T` (`^^T::x`, `^^A<T>`) is unique
  in profiles (`profile_expr.rs`).
