# WP-572 — static data member explicit specialization without initializer is a declaration

Extends spec/sema-templates.md (variable template specializations as declarations)
and spec/codegen.md §7h (linkage table).

[temp.expl.spec]/14: `template<> const char *C<char>::zones[14];` and
`template<> int S::v<char>;` declare, they do not define. Sema already skipped their
default-initialization but `is_var_definition` still called them definitions and
codegen emitted a strong zero-initialized global, so every unit including libstdc++'s
`<locale>` (`__timepunct_cache<char>::_S_timezones`) defined the symbol and two such
objects failed to link. The rule is now `Ast::is_member_spec_declaration`
(crates/kiln_ast/src/templates.rs), used by Sema's `is_var_definition`, the Oven's
notes and `emit_global_var`: uses name an `external global`; a later specialization
with an initializer is the definition, and one without an initializer after the
definition is a redeclaration, not a redefinition (`act_on_static_member`).

`template<> X C<int>::x();` declares a function ([dcl.ambig.res]/1). An out-of-line
member function declaration whose lookup finds only a non-function, non-tag member
now reports clang's "redefinition of 'x' as different kind of symbol" with the note at
the member (`non_function_member`), for explicit specializations
(`templ/funcs.rs`) and ordinary members alike, instead of "out-of-line declaration of
'x' does not match any declaration".

Tests: `tests/conformance/temp.expl.spec/static-member-spec-declaration-{ir,run,errors}.cpp`.
