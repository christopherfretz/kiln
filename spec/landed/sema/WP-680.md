# WP-680 — spdlog through its own build and tests (M8 wave 1)

spdlog v1.17.0 built with kiln++ through its own CMake build and Catch2
test suite (docs/status/oss/spdlog.md). Each fixed behaviour below is a
kiln bug the build found, reduced to a standalone conformance test; the
rule is stated in the spec named.

## Changes

- **Protected members through a dependent base, replayed with the
  instantiated object class** ([class.protected]/1, [temp.dep.type]/6,
  [namespace.udecl]/19; spec/sema-templates.md §4.8). In a class template
  `R<T> : M<T>` with `M<T> : B`, `using B::m;` and an implicit `B::m`
  naming a protected member of `B` are accepted in the pattern (the
  derivation is unknown) and re-checked per instantiation; the replay
  substitutes the recorded object class (the pattern `R<T>`) with the
  instantiation `R<int>`, as clang substitutes the dependent
  diagnostic's base object type, instead of rejecting with "can only
  access this member on an object of type 'R<int>'". An implicit
  `B::m` records `*this`'s class as its object. An unrelated object
  (`b.m` with `B &b`) is still rejected in the instantiation.
  Test: `tests/conformance/class.protected/dependent-base-current-object.cpp`.
