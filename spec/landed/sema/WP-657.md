# WP-657 — Deduction attempts: call pre-filter, NTTP fast path, buffer reuse

This WP extends spec/sema-templates.md §6.1. The new paragraph there is
"Shortcuts that change no outcome". The measurements, counts and A/B
tables are in docs/status/perf-reflection.md, in the section
"WP-657: deduction attempts" (follow-up row F13).

Nothing observable changes. The following stay byte-identical: the
viable set, the chosen candidate, ambiguities, SFINAE outcomes, every
`Tdk` and note and their order, the instantiations triggered,
`-fkiln-instantiation-report` and the emitted IR.

## Changes

- **Call pre-filter** (`templ/deduce_call.rs` `deduce_head`,
  `deduce_call_prefail`, `deduce_head_failure`; `overload/call.rs`
  `add_template_candidate`, `add_arity_failed_candidate`).
  - Before any argument list is built, a template candidate is tested
    for the checks that precede explicit-argument substitution: an
    invalid template, or fewer arguments than the template's minimum.
  - On failure, the candidate is added exactly as the full path adds it.
  - A `TooFewArguments` failure is formed only when the pattern's own
    arity check leaves the candidate viable.
- **Substituted integer NTTP** (`templ/args.rs`
  `substituted_int_nttp_arg`).
  - It applies to an explicit argument that is a substituted non-type
    parameter over an integer literal, whose type is the parameter's
    builtin integral type, with a value that fits.
  - Such an argument converts to `TemplateArg::value` without a
    constant evaluation.
  - It applies only when no evaluation side state is pending (member
    references, pending deleted functions, misaligned accesses,
    potential-constant captures).
- **Scratch reuse** (`Sema::cand_scratch`, `Sema::deduce_scratch`).
  - The per-candidate argument and option vectors are pooled, and so is
    the template-parameter list of `deduce_spec`.
  - `Substituter::args` reads the argument list in place and copies it
    only from the first changed element.
  - `MultiLevelArgs::lookup` takes an accessor instead of a slice.
- **Redeclaration matching** (`overload/redecl.rs` `fn_corresponds`).
  - It reads the old declaration's parameters, variadic flag and
    qualifiers from its stored type.
  - It forms the declared function type only to compare return types of
    template heads.

## Test-only entry

`Sema::full_deduction` (`#[doc(hidden)]`, also
`ParseOptions::full_deduction`) turns off the pre-filter and the NTTP
fast path. `crates/kiln_parse/tests/deduction_prefilter.rs` compiles
generated calls both ways and asserts that the diagnostics (every
candidate note, in order) and the AST dump are equal. The generated
calls cover packs, defaults, explicit arguments, non-dependent
parameters, constraints, deleted and SFINAE'd candidates, ambiguities,
and integer, `bool`, character and enumeration NTTPs.

## Statistics

The `op-stats` feature of kiln_sema (`templ/deduce_stats.rs`) counts
the following and prints them at exit:
- deductions by step and `Tdk`;
- candidates per set;
- repeated attempts;
- redeclaration scans;
- per-function timers.

It is off in release builds.
