# WP-1084 — local classes inside templates are dependent (with WP-904)

A class declared in a dependent context is a dependent type that is not
the current instantiation, except inside the class itself. This covers a
local class of a function template, of a generic lambda, or of a member
of a class template, and also a member class of a class template.

Kiln already marked these classes `DEPENDENT_CTX`. However, the parser
and lookup treated names inside them as non-dependent, which caused
three bugs:
- accepts-invalid: a missing `typename` was not diagnosed;
- accepts-invalid: unqualified names were found in dependent bases;
- wrong code: a dependent base's member shadowed a namespace-scope
  declaration.

The rules are in spec/sema-templates.md §3.1.1.

- **Missing `typename` through a dependent local or member class**
  (WP-904).
  - Root cause: `L::N`, with `N` a type member, scanned as a type, so
    `L::N()` built a functional cast and `sizeof(L::N)` a type operand.
    clang treats the qualifier as dependent and diagnoses these at
    instantiation.
  - Fix:
    - The parser's lookahead scans the name as dependent, and
      `dep_member_nns` defers types (values still bind at definition).
    - `parse_template_type_name` and `check_missing_typename_in_class`
      use `is_unentered_dependent_qualifier`.
    - Instantiating a `DependentScopeDeclRefExpr` that finds a type
      emits clang's `err_typename_missing` ("missing 'typename' prior to
      dependent type name") at the qualifier. It replaces the old "does
      not refer to a value" wording; this also fixes `T::N()` with a
      type `N`.
  - Tests: `temp.res/local-class-missing-typename.cpp` and
    `temp.res/member-class-dependent-clang-ported.cpp` (from clang CWG108
    and `typename-specifier.cpp`).
- **Unqualified lookup into dependent bases** ([temp.dep.general]/3).
  - Root cause: class-scope unqualified lookup searched every base,
    including a base that is itself a dependent local class. `z` in
    `struct B : A { ... return z; }` was accepted. When a namespace
    variable had the same name, `A`'s member won (base kiln printed 39,
    clang 78).
  - Fix: `lookup_in_class_unqual` (`lookup.rs`) skips `DEPENDENT_CTX`
    bases that do not enclose the context, during definition only.
    Qualified lookup, member access, and instantiation are unchanged.
  - Tests: `temp.dep/local-class-dependent-base.cpp` (diagnostics) and
    `temp.dep/local-class-dependent-patterns-run.cpp` (valid patterns,
    run).
- **Dependent call to a member of a dependent base.**
  - Root cause: once the base was skipped, `z(u)` failed at
    instantiation with "use of undeclared identifier".
  - Fix: `resolve_unresolved_call` falls back to
    `diagnose_member_found_in_class`, which gives clang's "explicit
    qualification required to use member 'z' from dependent base class"
    with the declaration note.
  - Tests: `temp.dep/local-class-dependent-base.cpp`.

clang-neg (CXX, SemaCXX, SemaTemplate): missed errors fell from 4364 to
4350. Accepts-invalid, rejects-valid, and crash counts are unchanged.
