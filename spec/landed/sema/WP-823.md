# WP-823 — correctness bundle (WP-676, WP-684, WP-697, WP-699, WP-788)

Five small accepts-invalid / rejects-valid gaps, each matched against
clang 19 (and GCC 16.1 for reflection).

- **WP-676, a typename-less member of the current instantiation**
  (spec/parse.md, the `X<args>::m::name` lookahead): the WP-668
  `tid_member` classification no longer applies when the qualifier is the
  current instantiation, so `is_same<X<T>::jp::string_t, ...>` inside `X`
  is clang's "template argument for template type parameter must be a
  type; did you forget 'typename'?". Fixed. Test:
  `temp.res.general/missing-typename-current-instantiation-member-typedef.cpp`.
  Found on the way: `basic<long>::m::name` inside `basic<T>`'s own
  definition is looked up in the pattern instead of being "implicit
  instantiation of template 'basic<long>' within its own definition"
  (xfail `temp.inst/specialization-within-own-definition-member-typedef.cpp`).
- **WP-684, a protected destructor** (spec/sema-class.md §2.4): already
  fixed on main by WP-680's `TryDiagnoseProtectedAccess` note. Pinned
  for every destructor-use site: `class.protected/dtor-restricted-note.cpp`.
- **WP-697, `-fchar8_t` / `-fno-char8_t`** (spec/sema.md "String literal
  initializers"): the literal types, `__cpp_char8_t`, the keyword,
  overloads and mangling already matched clang (WP-808). Missing were
  the [dcl.init.string]/1 literal-kind checks: `char8_t a[] = "x"`,
  `wchar_t a[] = "x"`, `char16_t a[] = U"x"`, `char a[] = L"x"`, and
  `signed char a[] = u8"x"` with `char8_t` on, were all accepted. Fixed
  (`Sema::string_init_compat`); a mismatched literal in braces now
  initializes the elements. Tests:
  `dcl.init.string/literal-kind-mismatch{,-cxx17-fchar8t}.cpp`,
  `dcl.init.string/utf8-literal-fno-char8t.cpp`.
- **WP-699, parenthesized template-id callees** (spec/sema-overload.md
  §2): `(operator+<A>)(x, y)`, `(::operator+<A>)(x, y)` and
  `(template [: r :]<A>)(x, y)` stay overload sets for the call. Fixed.
  Tests: `temp.arg.explicit/parenthesized-operator-template-id-callee.cpp`,
  `temp.names/parenthesized-splice-template-id-callee.cpp`.
- **WP-788, member template-ids and member sets** (spec/sema-overload.md
  "Member overload sets used other than called", §2.3):
  `auto q = g.Is<3>;` deduces from a single static specialization; a
  bound member set used other than called is clang's "reference to
  non-static member function must be called" with its hint and notes; a
  qualified mixed set called from an unrelated class resolves against
  `*this` ("no matching member function", and a static winner is now
  accepted where kiln rejected it); a member template's object-argument
  mismatch notes the template. Fixed. Tests:
  `dcl.spec.auto/member-template-id-single-static-specialization-run.cpp`,
  `dcl.spec.auto/member-set-placeholder-and-unevaluated-use.cpp`,
  `class.mfct.non.static/qualified-mixed-set-from-unrelated-class.cpp`.
