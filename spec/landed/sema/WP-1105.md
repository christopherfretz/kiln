# WP-1105 — partial specialization vs primary ordering for placeholder / parameter-typed non-type parameters, CWG1432

Origin: WP-1053. spec/sema-templates.md §4.4 (steps 3 and 4) and the
"Landed (WP-1017, WP-1053)" declaration checks describe the rules.

## More specialized than the primary ([temp.spec.partial.general]/9.2)

`not_more_specialized_than_primary` (`templ/order.rs`) used to accept any
partial specialization whose primary had a non-type parameter typed by a
placeholder (`template<auto N>`) or by another parameter
(`template<class T, T N>`). It now deduces that type from the synthesized
argument ([temp.deduct.type]/20) and, finishing the reverse deduction,
substitutes the deduced arguments into the partial's non-type parameter
types and compares them with the primary's synthesized arguments
(`deduced_nttp_type_mismatch`); a synthesized `auto` is a unique type that
only a placeholder or a type parameter matches. Before → after, against
clang 19 and 22 (all three agree after):

- `template<class T, T N> B; template<class T, int N> B<T, N>`: accepted →
  "not more specialized".
- `template<auto N> A; template<class T, T N> A<N>`: accepted → rejected.
- `template<int N> F; template<auto N> F<N>` (also with `requires true`,
  and `decltype(auto) N`): accepted → rejected.
- `template<int N> X; template<class T, T V> X<V>`: accepted → rejected.
- Still valid: `template<auto N> A; template<int N> A<N>`, `template<class
  T, T *P> A<P>`, `template<int N> X; template<short S> X<S>`, `template<auto
  N> requires true A<N>`.
- `template<class T, T> V; template<bool B> V<int, B>`: clang 22 rejects,
  clang 19 accepts (it converted `B` to `int` first). kiln follows clang 22,
  and `-fclang-compat=19` follows clang 19 (`DeducedArgs::converted_values`,
  `converted_values_fit`); probed over 14 type pairs, all match both.

Tests: `temp.spec.partial.general/placeholder-typed-primary-not-more-specialized.cpp`,
`temp.spec.partial.general/param-typed-primary-converted-arg-not-more-specialized.cpp`
(`requires: clang>=22`); the existing
`temp.spec.partial.match/narrowing-nttp-dependent-type-clang19.cpp` pins
the compat-19 side.

## Matching: a deduced value must fit its parameter's type

Enabling the check exposed a matching bug: a deduced value of an `auto`
primary bound any non-type parameter. `deduce_partial` now checks each
deduced value with `deduced_value_fits` (was `deduced_int_fits`, integral
only). Before → after (clang 19 and 22 agree with after): `A<nullptr>`,
`A<&x>`, `A<1.0>`, `A<SE::s1>`, `A<&Q::m>` no longer match `template<int N>
A<N>`; `B<0>`, `B<nullptr>`, `B<&Q::m>` no longer match `template<auto *P>`;
`C<nullptr>`, `C<(const int *)&x>` not `template<int *P>`; `H<1.0f>`, `H<1>`
not `template<double D>`; `K<S{1}>` not `template<T t>`; `M<f1>` (another
enum) not `template<E V>`; `N<0>` not `template<decltype(nullptr) V>`;
`R<1, 300>` not `template<char... Cs> R<1, Cs...>` (packs element-wise).
`G<&Q::m>` still matches `template<auto Q::*M> G<M>`
(`nttp_placeholder_matches` looks through the member pointer, which
`deduce_match` does not). Test:
`temp.spec.partial.match/nttp-deduced-value-type-run.cpp`.

## CWG1432

`partial_more_specialized` applies clang's speculative CWG1432 tie-break
(`cwg1432_tie_break`) when both directions deduce. kiln's list deduction
already fails a pack expansion against a non-pack parameter, so every
probed shape (`C<T>` vs `C<T, U...>`, `common_type<T, U>` vs `<T, U,
V...>`, nested `L<T>` vs `L<T, U...>`, function types, constrained,
variable templates, function templates through `L<T, U...>`, `T, U...`
and a template template parameter) was already ordered as clang 22 orders
it, before and after; the rule is a backstop. `g(L<T>*)` vs `g(L<T,
U...>*)`: clang 19 is ambiguous, clang 22 and kiln pick `L<T>*`. Tests:
`temp.spec.partial.order/cwg1432-trailing-pack-run.cpp`,
`temp.func.order/cwg1432-trailing-pack-run.cpp`,
`temp.func.order/cwg1432-pointer-to-pack-specialization-run.cpp`
(`requires: clang>=22`).

## Not done

- `auto Q::* p = &Q::m;` is rejected (clang accepts): `deduce_match`
  (`crates/kiln_sema/src/deduce.rs`) has no member-pointer case.
- `template<auto... Vs> S; template<int... Is> S<Is...>` is "not more
  specialized" in kiln at every compat level; clang 19 accepts it.
