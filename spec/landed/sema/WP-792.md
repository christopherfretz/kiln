# WP-792 — Sema fixes from the wave 4 constexpr projects

- `T::template f<A>` at instantiation (`member_template_named`,
  `crates/kiln_sema/src/templ/subst/types.rs`) names the first template
  that the lookup of `f` finds, not the first declaration. An overload
  set mixing non-template functions with a function template is resolved
  over the whole set. Before, it was rejected with "'f' following the
  'template' keyword does not refer to a template" when a non-template
  overload came first (reflect-cpp's `Literal::contains`; 32 TUs).
  spec/sema-templates.md §2.3. Test:
  `tests/conformance/temp.names/template-kw-mixed-overload-set.cpp`.
- [temp.arg.nontype]/6: a pointer or reference template argument that
  designates a string literal, a `typeid` result or a temporary is
  rejected (`invalid_template_arg_base`, `crates/kiln_sema/src/templ/args.rs`;
  hooked into `convert_ref_nttp_arg` for references). Before, `X<"ab">`
  was accepted, so reflect-cpp's `make_field<"name">` was ambiguous
  between its class-type-NTTP overload and its `template <auto p>`
  overload (19 TUs). New diag `sema_constexpr_invalid_template_arg`.
  spec/sema-templates.md "Disallowed bases". Tests:
  `tests/conformance/temp.arg.nontype/string-literal-typeid-argument.cpp`,
  `tests/conformance/temp.arg.nontype/string-literal-argument-sfinae-run.cpp`.
- [temp.param]/5: a non-type template parameter `C<A...> auto V` carries
  the associated constraint `C<decltype(V), A...>` (a fold for a pack),
  as clang's `AttachTypeConstraint`, so it takes part in partial
  specialization matching and ordering. An NTTP's type is compared for
  [temp.over.link]/6.2 with its top-level placeholder's type-constraint
  ignored (`crates/kiln_sema/src/templ/{mod,order}.rs`,
  `concepts/sat.rs`; spec/sema-templates.md). mp-units. Test:
  `tests/conformance/temp.param/nttp-constrained-auto.cpp`.
- `template<int N, C<N> auto V>`: once `N` is known, the type-constraint
  of `V` is substituted, so `V`'s argument is evaluated. Before, it stayed
  an unevaluated expression, `box<7, f()>` and `box<7, zero>` were
  different specializations, and a `static_assert` that clang and GCC
  accept failed (mp-units `quantity_point<R, default_point_origin(R)>`)
  (`templ/subst/types.rs`; spec/sema-templates.md). Test:
  `tests/conformance/temp.param/nttp-constrained-auto-dependent-constraint.cpp`.
- A static data member of a class template whose type is a deduced class
  type (`static constexpr std::array const tbl = f<T>();`) is
  instantiated with its class, as `auto` is (clang `isUndeducedType`).
  Before, a member function instantiated first saw the undeduced type
  (daw_json_link, every TU) (`templ/subst/decls.rs`;
  spec/sema-templates.md). Test:
  `tests/conformance/temp.inst/static-member-deduced-class-type.cpp`.
- The `noexcept` of an instantiated constructor, destructor or conversion
  function is instantiated with `this` available (daw_json_link
  `json_writer_t`, 5 TUs) (`except.rs`; spec/sema.md). Test:
  `tests/conformance/except.spec/special-member-noexcept-this-instantiation.cpp`.
- [dcl.spec.auto.general]/9: in a non-templated function, a `return` in a
  discarded `if constexpr` branch does not deduce the return type and its
  operand is not converted (scnlib `get_file_tag`) (`stmt.rs`;
  spec/sema.md). Test:
  `tests/conformance/dcl.spec.auto/discarded-return-not-deduced-run.cpp`.
- The CFG folds an `if constexpr` condition that has a condition
  variable, so `-Wreturn-type` sees no path off the end of an
  instantiation (mp-units `are_ingredients_convertible` under `-Werror`)
  (`cfg/build.rs`; spec/sema.md). Test:
  `tests/conformance/stmt.if/constexpr-condition-variable-falloff.cpp`.
- A class list cast `T{y}` whose initialization is `y`'s conversion
  function is wrapped in a no-op functional cast to `T`, as clang does,
  so instantiation converts to `T` again (glaze's chrono reader,
  `sys_seconds{sys_days{ymd}}`) (`forms.rs`; spec/sema.md). Test:
  `tests/conformance/expr.type.conv/list-cast-conversion-function-in-template.cpp`.
- A friend function template defined in a class template is linked to its
  saved body even when a specialization of the class is instantiated
  while that body is parsed (`act_on_delayed_body`, as clang's
  `willHaveBody`). Before, its use was "function with deduced return type
  cannot be used before it is defined" (mp-units `pow<-1>(magnitude<>)`)
  (`class/mod.rs`, `templ/member.rs`; spec/sema-templates.md). Test:
  `tests/conformance/temp.friend/friend-template-body-names-own-specialization.cpp`.
