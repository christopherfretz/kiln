# WP-1137 — exception-specification accepts-invalid tails

Closes the follow-ups WP-1052 left open. Every case is matched against
clang 22 and clang 19.

## Items

1. **C++98 lists during deduction.** A function template's dynamic list
   is substituted with the declaration; while deducing, its types are
   checked under the specialization's instantiation frame
   (`as_spec_instantiation`, except.rs; clang `InitFunctionInstantiation`),
   so a failing type is a hard error, not a deduction failure. Test:
   `except.spec/dynamic-exception-spec-deduction-cxx98.cpp`.
2. **C++17 implicit lists.** The redeclaration check of an implicit
   destructor specification reads the redeclaration's written list
   (`exc_of`, excspec.rs). Test:
   `except.spec/implicit-exception-spec-type-list-cxx17.cpp`.
3. **C++17 overriders.** The override check reads the overrider's
   written list (`resolved_exc`, class/virtual/mod.rs), dependent or
   not. Test: `except.spec/dynamic-exception-spec-override-cxx17.cpp`.
4. **Nested function types.** Each type of a substituted nested
   function type's list is checked (`templ/subst/types.rs`, clang
   `TransformExceptionSpec`). Test:
   `except.spec/dynamic-exception-spec-nested-instantiation-cxx14.cpp`.

## Follow-ups

- Instantiation errors still find the list's `)` by content
  (`dyn_exc_rparen_of`, except.rs).
