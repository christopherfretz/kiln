# WP-807 — no silent drops, part 3: semantic GNU/clang attributes

Before this package kiln parsed these attributes and then dropped them
with no diagnostic. A program that relied on them compiled, but behaved
differently. Each attribute now has clang's semantics and clang's
diagnostics (clang 22 wording, and clang 19 where `-fclang-compat=19`
differs). The sources are GCC's "Common Function / Variable Attributes"
pages and clang's `AttrDocs` (`clang/include/clang/Basic/AttrDocs.td`).

## Semantics

- **`constructor` / `destructor` [(N)]** (`AttrDocs` "constructor,
  destructor"; clang `handleConstructorAttr`):
  - The function runs before `main` (for `destructor`, after it) through
    `@llvm.global_ctors` / `@llvm.global_dtors`.
  - The priority is `N`, or 65535 if none is written.
  - `N` must be a `uint32` constant.
  - A value-dependent `N` is an error under clang 19. Under clang 22 it is
    checked when the function is instantiated.
  - On a non-function: the warning `-Wignored-attributes`.
- **`init_priority(N)`**: already implemented by WP-189.
- **`cleanup(f)`** (`AttrDocs` "cleanup"; clang `handleCleanupAttr`):
  - Allowed only on a local variable with automatic storage.
  - `f(&v)` runs when `v` leaves scope, on every exit, including unwinding.
    It runs before `v`'s destructor (a `NormalAndEHCleanup`).
  - `f` must name a single function with one parameter.
  - The parameter type is checked against `T *` under C's assignment rules:
    at the declaration under clang 19, and once the type is deduced under
    clang 22.
  - A `bool` parameter receives `true`.
- **`internal_linkage`** (`AttrDocs` "internal_linkage"; clang
  `mergeInternalLinkageAttr`):
  - The variable, function or class has internal linkage, as if it were
    declared `static`. A class's members have it too.
  - At namespace scope the name mangles with the `L` prefix, including in
    the template-prefix and unscoped-template positions.
  - Errors:
    - on a local variable with automatic storage;
    - when added by a redeclaration (`err_attribute_missing_on_first_decl`);
      after a definition it is a warning instead.
- **`common`**: an error in C++ (clang `handleCommonAttr`,
  `err_attribute_not_supported_in_lang`), so the mutual exclusion with
  `internal_linkage` cannot arise.
- **`tls_model("m")`** (`AttrDocs` "tls_model"; clang `handleTLSModelAttr`):
  - Allowed on a thread-local variable only.
  - The argument must be one of `global-dynamic`, `local-dynamic`,
    `initial-exec`, `local-exec`.
  - The model is set on the global (`thread_local(initialexec)` and so on),
    and is inherited across redeclarations and from a template's pattern.
  - A lifetime-extended thread-local temporary takes its variable's model.
  - The `__tls_guard` stays global-dynamic, as in clang.
- **`returns_twice`** (`AttrDocs` "returns_twice"):
  - The function's declaration, definition and every call carry the LLVM
    `returns_twice` attribute.
  - It is inherited across redeclarations.
  - The C library names (`setjmp`, `_setjmp`, `sigsetjmp`, `vfork`, ...)
    carry it implicitly when declared `extern "C"`.
  - Functions that call such a function are never outlined.
  - On a non-function: the warning `-Wignored-attributes`.
- **`mode` on a dependent type** (clang `instantiateDependentModeAttr`):
  - The attribute stays on the declaration (`AttrNode::MODE_DEFERRED`).
  - It is applied to the substituted type of the instantiated variable,
    field or typedef. A mismatch is diagnosed at instantiation.
  - On a function parameter of dependent type it is a hard error for now
    (xfail repro `ext.gnu.mode/mode-dependent-param-run.cpp`).

`__has_attribute` / `__has_cpp_attribute` report 1 for each of these, as
clang does (`common` included: clang reports it and rejects its use).
