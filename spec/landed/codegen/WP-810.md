# WP-810 — no silent drops, part 6: SVE fixed-length types, builtin aliases, multiversioning

Before this package kiln parsed these constructs and dropped them with no
diagnostic, so a program that relied on them compiled with a different
meaning. Each is now implemented as clang does it, or is a hard error. The
sources are clang's `AttrDocs` (`clang/include/clang/Basic/AttrDocs.td`)
and the Arm C Language Extensions (ACLE) specification.

## `arm_sve_vector_bits(N)` (ACLE §3.7.3.3, AttrDocs "arm_sve_vector_bits")

Sema, layout and mangling are in spec/types.md "Fixed-length SVE types".
Codegen and the AAPCS64 lowering (clang `CGCall.cpp`, `AArch64ABIInfo`):

- In memory a fixed-length type is its LLVM fixed vector: `<N/bits x T>`
  for data, `<N/64 x i8>` for a predicate (`kiln_codegen` `lty`).
- A parameter or return of a fixed-length type is passed as its scalable
  register type, `<vscale x 128/bits x T>` or `<vscale x 16 x i1>`, with
  `noundef` (`kiln_abi` `call.rs` `aarch64_sve_fixed`, checked before the
  large-vector rule).
- The prolog extracts the fixed value: `llvm.vector.extract.<fixed>.<sc>`
  at index 0; a predicate is first bitcast from `<vscale x 16 x i1>` to
  `<vscale x 2 x i8>` (`func.rs` `sve_to_fixed`).
- A return value and a call argument are loaded as the fixed vector and
  inserted with `llvm.vector.insert.<sc>.<fixed>` into `undef` (`poison`
  at `-fclang-compat=22`), then bitcast for a predicate (`sve_to_scalable`).
- A call result is extracted for data; for a predicate it is stored as
  the scalable type into a `<N/64 x i8>` temporary and reloaded, as clang's
  coerced store does.
- `CK_BitCast` between a fixed and a sizeless type uses the same insert or
  extract when the element types agree, and otherwise goes through a
  memory temporary (aligned 16 for a scalable source, to the fixed type's
  power-of-two size for a fixed one), as clang's `CreateCoercedLoad`.
- LLVM bitcasts between scalable vectors compare the minimum size and the
  scalable flag (`kiln_llvm` `check_cast`).
- Aggregates at `-fclang-compat=19` are lowered as any aggregate, with a
  128-bit fixed-length vector a valid HFA/HVA base (`[N x <4 x i32>]`).
  From clang 20 a fixed-length vector is no HFA/HVA base, and an AAPCS64
  *pure scalable type* (a non-union record or nonempty array whose
  non-empty members are, at every depth, fixed-length vectors and
  predicates, at least one; clang `passAsPureScalableType`) is passed
  expanded in Z and P registers. kiln does not lower that convention yet:
  at `-fclang-compat=22` a definition or call that passes or returns one
  by value is the hard error "passing or returning 'T' by value is not
  supported yet: it is an AAPCS64 pure scalable type (an aggregate of
  fixed-length SVE types)" (`module.rs` `check_pure_scalable`; the call at
  the call expression's begin), never a silently different ABI.
- Tests: `ext.arm.sve/ir-sve-fixed-length{,-calls}{,-19}.cpp`,
  `ir-sve-fixed-length-aggregates-19.cpp`, `layout-sve-vector-bits.cpp`,
  `sve-vector-bits-*.cpp`; the run test `sve-vector-bits-run.cpp`
  (`requires: host-sve`, spec/harness.md); `kiln_driver` test
  `sve_pure_scalable_by_value`.
