# WP-810 — no silent drops, part 6: SVE fixed-length types, builtin aliases, multiversioning

Before this package kiln parsed these constructs and dropped them with no
diagnostic, so a program that relied on them compiled with a different
meaning. Each is now implemented as clang does it, or is a hard error. The
sources are clang's `AttrDocs` (`clang/include/clang/Basic/AttrDocs.td`)
and the Arm C Language Extensions (ACLE) specification.

## `arm_sve_vector_bits(N)` (ACLE §3.7.3.3, AttrDocs "arm_sve_vector_bits")

Sema, layout and mangling are in spec/types.md "Fixed-length SVE types".
Codegen and the AAPCS64 lowering (clang `CGCall.cpp`, `AArch64ABIInfo`):

- In memory a fixed-length type is its LLVM fixed vector: `<N/bits x T>`
  for data, `<N/64 x i8>` for a predicate (`kiln_codegen` `lty`).
- A parameter or return of a fixed-length type is passed as its scalable
  register type, `<vscale x 128/bits x T>` or `<vscale x 16 x i1>`, with
  `noundef` (`kiln_abi` `call.rs` `aarch64_sve_fixed`, checked before the
  large-vector rule).
- The prolog extracts the fixed value: `llvm.vector.extract.<fixed>.<sc>`
  at index 0; a predicate is first bitcast from `<vscale x 16 x i1>` to
  `<vscale x 2 x i8>` (`func.rs` `sve_to_fixed`).
- A return value and a call argument are loaded as the fixed vector and
  inserted with `llvm.vector.insert.<sc>.<fixed>` into `undef` (`poison`
  at `-fclang-compat=22`), then bitcast for a predicate (`sve_to_scalable`).
- A call result is extracted for data; for a predicate it is stored as
  the scalable type into a `<N/64 x i8>` temporary and reloaded, as clang's
  coerced store does.
- `CK_BitCast` between a fixed and a sizeless type uses the same insert or
  extract when the element types agree, and otherwise goes through a
  memory temporary (aligned 16 for a scalable source, to the fixed type's
  power-of-two size for a fixed one), as clang's `CreateCoercedLoad`.
- LLVM bitcasts between scalable vectors compare the minimum size and the
  scalable flag (`kiln_llvm` `check_cast`).
- Aggregates at `-fclang-compat=19` are lowered as any aggregate, with a
  128-bit fixed-length vector a valid HFA/HVA base (`[N x <4 x i32>]`).
  From clang 20 a fixed-length vector is no HFA/HVA base, and an AAPCS64
  *pure scalable type* (a non-union record or nonempty array whose
  non-empty members are, at every depth, fixed-length vectors and
  predicates, at least one; clang `passAsPureScalableType`) is passed
  expanded in Z and P registers. kiln does not lower that convention yet:
  at `-fclang-compat=22` a definition or call that passes or returns one
  by value is the hard error "passing or returning 'T' by value is not
  supported yet: it is an AAPCS64 pure scalable type (an aggregate of
  fixed-length SVE types)" (`module.rs` `check_pure_scalable`; the call at
  the call expression's begin), never a silently different ABI.
- Tests: `ext.arm.sve/ir-sve-fixed-length{,-calls}{,-19}.cpp`,
  `ir-sve-fixed-length-aggregates-19.cpp`, `layout-sve-vector-bits.cpp`,
  `sve-vector-bits-*.cpp`; the run test `sve-vector-bits-run.cpp`
  (`requires: host-sve`, spec/harness.md); `kiln_driver` test
  `sve_pure_scalable_by_value`.

## Builtin aliases (`__clang_arm_builtin_alias`, AttrDocs "__clang_arm_builtin_alias")

`<arm_sve.h>` declares every intrinsic as an overloadable function with
`__attribute__((__clang_arm_builtin_alias(__builtin_sve_*)))`; a call is
the builtin. Before WP-810 kiln dropped the attribute, so every SVE
intrinsic was an undefined external call.

- Sema (`kiln_sema` `sve.rs` `builtin_alias_attribute`, `AttrKind::
  BUILTIN_ALIAS`, `Ast::builtin_alias`): the spellings are
  `__clang_arm_builtin_alias` and `clang_builtin_alias` / `[[clang::
  builtin_alias]]`. The argument is exactly one identifier ("takes one
  argument", "requires parameter 1 to be an identifier"); for the arm
  spelling on AArch64 it must name a `__builtin_sve_` or `__builtin_sme_`
  builtin ("can only be applied to an ARM builtin"); the subject must be a
  function ("only applies to functions"). A definition of an aliased
  function is "definition of builtin function 'f'". A reference other than
  a direct call is "builtin functions must be directly called"; a direct
  call decays the callee without that check (`expr.rs` `act_on_call`).
  Deviations: a name with the right prefix that is not a real builtin is
  accepted (clang knows the builtin table), and the missing-feature error
  is reported only in codegen (clang also reports it under `-fsyntax-only`).
- Types: the SVE tuple types `sv<T>x{2,3,4}_t` / `svboolx{2,4}_t`
  (spec/types.md "SVE tuple types").
- Codegen (`kiln_codegen` `sve.rs`, from `expr.rs` `emit_call_inner`):
  without the `sve` or `sme` feature a call is "'f' needs target feature
  sve|sme" (clang's wording). The lowered families, as clang 19 and 22
  emit them: `svcnt{b,h,w,d}[_pat]` (`cnt*` with pattern 31 = `SV_ALL`);
  `svptrue[_pat]_b{8,16,32,64}`; `svwhile{lt,le}_b*_{s,u}{32,64}`
  (unsigned as `whilelo`/`whilels`); `svld1_*`, `svst1_*`, `svdup_n_*`;
  `sv{add,sub,mul,div,max,min,and,orr,eor,mla}[_n]_*_{m,x,z}`; and
  `sv{add,max,min,and,or,eor}v_*` (an integer `svaddv` returns 64 bits).
  Operands are emitted in order, then a predicate is narrowed with
  `convert.from.svbool` (not for 8-bit lanes), an `_n` scalar is splatted
  (`insertelement` + `shufflevector` zeroinitializer), an `_z` operand 1 is
  selected against zero, `_x` uses the `.u` intrinsic, and a predicate
  result is widened with `convert.to.svbool`. An immediate (a pattern) must
  fold to a constant integer. Intrinsic attributes follow the LLVM version
  of the IR being emitted (`speculatable` and `captures(none)` from 21/22;
  `kiln_llvm` `intrinsics.rs` `TargetMem::Speculatable`, `sve_store`).
- Hard errors, never a call to an undefined function: an aliased builtin
  outside the lowered families (bf16, `_vnum`, multi-vector `x2`/`x4`,
  tuple `svcreate`/`svget`/`svset`, gathers and scatters, SME, ...: 7029 of
  the 7749 `<arm_sve.h>` aliases, 720 lowered; the `kiln_codegen` unit test
  `sve::tests::arm_sve_h_coverage` pins both counts) is "code generation
  for SVE builtin 'B' (called as 'f') is not supported yet"; an alias whose
  declared signature does not match the builtin's is "the function called
  does not have the signature of SVE builtin 'B'" (clang emits invalid IR
  there); taking the address of one in codegen is "'B' is a builtin with no
  function body; it can only be called directly" (`module.rs` `get_fn`).
- SVE tuples by value: clang 19 passes a tuple as its wide vector, which
  kiln does. From clang 20 a tuple is a struct of vectors passed as a pure
  scalable type; at `-fclang-compat=22` a definition or call that passes
  or returns one by value is "passing or returning 'T' by value is not
  supported yet: it is an SVE tuple type, which clang 20 and later pass as
  a struct of vectors" (`module.rs` `check_pure_scalable`). Tuple locals
  at compat 22 stay the wide vector in memory (same size and layout).
- Tests: `ext.arm.sve/ir-sve-builtins{,-19}.cpp`,
  `builtin-alias-attribute-errors.cpp`, the run test
  `sve-builtins-run.cpp` (`requires: host-sve`); `kiln_driver` test
  `sve_builtin_alias_errors`.

## Function multiversioning (AttrDocs "target_version", "target_clones", "cpu_dispatch", "cpu_specific")

clang's driver enables the `fmv` target feature only with the compiler-rt
runtime library; kiln has no `--rtlib=compiler-rt`, so it implements clang
with `-fmv` (the `target-features` list says `-fmv`, and a user `fmv` entry
is not forwarded: `target_features.rs` `feature_map`). Before WP-810 the
four attributes were dropped, so every version of a function was one
function and the last body won.

- Parsing (`kiln_parse` `attr.rs`): the first argument of `target` and
  `target_version` and every argument of `target_clones` must be a string
  literal token; another token is "expected string literal as argument of
  'A' attribute" (the name as written) at that token, it is not parsed as
  an expression, and the attribute is dropped, as is one whose argument has
  an error. `cpu_dispatch` / `cpu_specific` take identifiers.
- Sema (`kiln_sema` `fmv.rs`; `AttrKind::TARGET_VERSION`, `TARGET_CLONES`,
  `CPU_DISPATCH`, `CPU_SPECIFIC`): the attributes are checked in source
  order: argument count, the subject ("only applies to functions", a
  warning for `cpu_*`), then the mutual exclusion of `target` /
  `target_version` with another multiversioning attribute on the same
  declaration ("'N' and 'E' attributes are not compatible", note
  "conflicting attribute is here"; the new one is dropped).
- AArch64: a `target_version` string is split at `+` and trimmed; each
  part is `default` or a clang feature name (58 names at
  `-fclang-compat=19`, 45 from 22), else "unsupported 'X' in the
  'target_version' attribute string; 'target_version' attribute ignored".
  The default version (the string exactly `default`) is an ordinary
  function; at `-fclang-compat=22` it is "attribute declaration must
  precede definition" after the definition. A non-default version is never
  declared and its body is not checked (as clang does without `fmv`), so
  calls reach the default version. As a member or friend it is the hard error "function
  multiversioning with 'target_version' is not supported yet" (clang
  crashes on a definition, and drops a later ordinary definition of a
  friend). `target_clones` is an ordinary function. `cpu_dispatch` /
  `cpu_specific` are "invalid option 'X' for cpu_dispatch" at the first
  name and not attached.
- Codegen (`module.rs`): a `target_version` definition is emitted at the
  end of the TU (clang `MayBeEmittedEagerly`), and from clang 22 a function
  whose declarations carry `target_version` has the valueless
  `"fmv-features"` attribute.
- x86-64, where clang multiversions without a feature: `target_clones`,
  `cpu_dispatch`, `cpu_specific`, `target("default")`, `target` strings
  that differ across redeclarations, and `target_version` before clang 22
  (an unknown attribute from 22) are the hard error "function
  multiversioning with 'A' is not supported yet": kiln emits no resolvers
  or ifuncs.
- Tests: `ext.multiversion/multiversion-attribute-errors.cpp`,
  `fmv-feature-names{,-19}.cpp`, `target-version-after-definition{,-19}.cpp`,
  `ir-multiversion{,-19}.cpp`, the run test `multiversion-run.cpp`;
  `kiln_driver` test `multiversion_unsupported_errors`.
