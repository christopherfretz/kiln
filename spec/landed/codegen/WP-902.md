# WP-902 — Codegen parity batch

Bundles four codegen gaps where kiln's IR differed from clang 19 and 22:
WP-902 (constant image of a shared virtual base), WP-938 (nothrow
library builtins declared by the user), WP-940 (folding library calls
and static data member access) and WP-998 (a constant read through a
reference template argument). The contract is in spec/codegen.md
("Constant globals" and the `fold.rs` folding rules), spec/sema.md
"Library functions" and spec/oven.md "Builtins". This file records what
landed and how it was checked.

## Standard

- [class.mi], [class.virtual], [expr.const] (P3533 makes a class with
  virtual bases constant-initializable).
- [expr.ref], [class.static.data], [temp.arg.nontype], [expr.const]/2
  (usable in constant expressions).
- [library.c] / C [string.h]: the library functions clang treats as
  builtins.

## Rules (what landed)

1. **WP-902, shared virtual base.** A base laid out with a nearly empty
   primary virtual base (Itanium C++ ABI 2.4) has that virtual base as
   slot 0 of its LLVM type and no separate vptr slot. `record_elems`
   (`kiln_codegen/src/consts.rs`) now puts the base subobject's vtable
   address point there, so a class whose two bases share a virtual base
   is a constant global. clang 19 and 22 initialize it dynamically; the
   run test checks that kiln's constant is the object the constructors
   build. Tests: `class.mi/shared-virtual-base-constant-init-run.cpp`
   (xfail flipped), `class.mi/shared-virtual-base-constant-init-paths-run.cpp`.
2. **WP-938, nothrow `abort`.** A user declaration of a library builtin
   gets the builtin's attributes only when its type matches the
   builtin's ignoring the exception specification, and the noreturn
   bit is part of the match (clang `AddKnownFunctionAttributes`,
   `hasSameFunctionTypeIgnoringExceptionSpec`). `abort` and the other
   rows clang 19 and 22 carry (`complex.h`, GNU string functions) are in
   the table, so a call under a pending cleanup is a nothrow `call`, not
   an `invoke`. Tests: `ext.gnu.builtins/library-abort-*-ir.cpp`,
   `library-complex-nothrow-ir.cpp`, `library-gnu-string-*-ir.cpp`.
3. **WP-940, library calls.** The functions clang's evaluator evaluates
   (`builtin::lib_evaluated`: `strlen`, `strcmp`, `memcmp`, `bcmp`,
   `memchr`, `memcpy` and their `wcs`/`wmem` forms) are evaluated by the
   Oven behind clang's constant-expression note. A constant expression
   still rejects them; a fold accepts them, so `__builtin_constant_p`
   is true, a GNU-folded array bound folds, and codegen emits the
   integral or floating result as a constant without emitting the
   arguments. `memcmp` and `bcmp` gained table rows. Tests:
   `ext.gnu.builtins/library-strlen-fold-ir.cpp` (xfail flipped),
   `library-strlen-fold-run.cpp`, `library-strlen-constant-folding.cpp`.
4. **WP-940, static member access.** A `MemberExpr` naming a const
   non-volatile static data member of scalar type with a constant
   initializer folds like a `DeclRefExpr` (clang
   `tryToConvertMemberExprToDeclRefExpr`), and an integral or enum
   member access folds when the whole access is constant (clang
   `EvaluateAsInt`). A base with side effects is still emitted. Test:
   `expr.ref/ir-constexpr-static-member-fold.cpp` (xfail flipped).
5. **WP-998, reference template argument.** Constant-reference loads look
   through `SubstNonTypeTemplateParmExpr` (clang
   `VisitSubstNonTypeTemplateParmExpr`), so `ref<cg>()` with
   `template <const int &R>` returns the constant. The BACKLOG example
   `deref<&cg>()` (`*P`) is a load in clang 19 and 22 too and stays one.
   Tests: `temp.arg.nontype/reference-arg-const-fold-ir.cpp`,
   `reference-arg-const-fold-run.cpp`.

## Remaining

- Calls clang lowers inline that kiln still emits as calls: `bcopy`,
  `bzero`, `mempcpy`, `alloca`, `conj`, `creal`, `cimag`, `finite`.
- clang 19 and 22 attach a `DIGlobalVariable` to string literal globals
  under `-g`; kiln does not.
