# WP-469 — WP-459 follow-ups: AArch64 predefines and -march/-mcpu, SVE codegen (splats, `?:`, compares, subscript, alignment), member through a function typedef in class templates, `friend F;` with a qualified function typedef

- **`-march`/`-mcpu`/`-target-feature`** (spec/driver.md "Target
  features"): `features.rs` models LLVM's AArch64 ExtensionSet:
  armv8-a..armv9.7-a (9.6/9.7 clang 22 only), `+ext`/`+noext` with the
  dependency closure and cascading disables, `-mcpu=generic`; unknown
  values get clang's error. `-msve-vector-bits=N` sets
  `vscale_range(N/128,N/128)` per oracle (`ext.arm.sve/ir-sve-vector-bits.cpp`,
  `ir-target-features-march-levels.cpp`, driver.rs
  `aarch64_target_feature_options`).
- **AArch64 predefines** (spec/pp.md "AArch64 target macros"): `__ARM_ARCH`,
  `__ARM_FP*`, `__ARM_NEON*` and the `__ARM_FEATURE_*` set (SVE, SVE2*,
  SVE_BITS, SVE_VECTOR_OPERATORS, FP16_*, crypto, dotprod, matmul, ...)
  derive from the resolved features under the clang 19 and 22 rules
  (`cpp.predefined/arm-feature-macros-*.cpp`, 14 `-dM` goldens incl.
  baseline, `+sve`, `+sve2`, `+fp16`).
- **SVE alignment** (`kiln_abi` target type table): data vectors align 16,
  `svbool_t`/`svcount_t` 2 (clang `getTypeInfo`).
- **SVE scalable constants, `?:`, comparisons** (spec/codegen.md §7aa):
  `ConstData::Splat` prints `splat (T c)` at LLVM 20+ and LLVM 19's
  `shufflevector (insertelement ...)` constant before; `v + 1`, `-v`,
  vector `?:` (an svbool condition selects directly at compat 22, clang 19
  compares against zero first) and comparisons yielding
  `<vscale x N x i1>` match clang (`ext.arm.sve/ir-scalable-constants.cpp`).
- **SVE subscript** (spec/sema.md §5.19a): `v[i]` on a sizeless SVE data
  vector is a vector element (clang `getSveEltType`); `svbool_t` is
  "subscript of svbool_t is not allowed" (`ext.arm.sve/subscript.cpp`,
  `subscript-element-reference.cpp`, `ir-subscript.cpp`).
- **Member through a function typedef in a class template** (spec/sema.md
  §4.3): `subst/decls.rs` `function_decl` substitutes the sugared function
  type; `act_on_function` synthesizes unnamed parameters for any
  typedef-declared function (clang `BuildParmVarDeclForTypedef`) so an
  out-of-class definition's body instantiates with its parameters bound
  (`temp.inst/member-function-typedef.cpp`).
- **`friend F;` with a qualified function typedef** (spec/sema.md §4.3):
  "non-member function of type ... cannot have '...' qualifier" at the
  start of the declaration; dependent substitution stays silent as in
  clang (`class.friend/friend-qualified-function-typedef.cpp`).
- Not done: C++26 auto-init of SVE locals (`auto_init.rs`), the
  `arm_sve_vector_bits` attribute, SVE tuple types, CPU names other than
  `generic`, clang-style re-reports of invalid SVE locals (`sve.rs:154`).
