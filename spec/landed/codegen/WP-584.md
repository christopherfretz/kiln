# WP-584 — C++26 erroneous-value zero init at -O2

- **Report.** A formatting library's `format("{:08b}", 5)` threw
  `argument not found` when kiln compiled it with `-std=c++26 -O2`;
  `-std=c++23`, `-O0`/`-O1`, `-ftrivial-auto-var-init=uninitialized` or
  `=pattern`, and clang 19 with `-ftrivial-auto-var-init=zero` all
  printed `[00000101]`.
- **Root cause: not the fill.** The zero fill (spec/codegen.md §7r) of
  the failing frame is byte for byte clang's. The library's argument-id
  check reads, under `if (is_constant_evaluated() && ...)`, a field of a
  derived compile-time parse context through a `static_cast` of the
  run-time context, i.e. bytes past the object. libstdc++ implements
  `std::is_constant_evaluated()` with `if consteval` from C++23, and the
  Oven compiled `if consteval` to its first substatement unconditionally,
  so codegen's trial fold of the run-time `if` condition
  ([expr.const]/20: not manifestly constant-evaluated) folded to true and
  emitted the guarded read. The read landed in the enclosing frame's
  zero-filled buffer (argument count 0, so argument 0 was "not found");
  with the stack's old contents, or the `0xAA` pattern, the count was
  large and the program happened to work. Valgrind on an
  `=uninitialized` build flags the same read.
- **Fix** (`crates/kiln_oven/src/compile.rs`, `IfStmt`): `if consteval`
  reads the evaluation context (`IsConstEval` aux 16, `vm.rs`) and
  branches on it, as clang's `EvaluateStmt` does; spec/oven.md
  "Manifestly constant-evaluated context". Constant initializers, array
  bounds, template arguments and `constexpr`/`const` integral locals
  still take the first substatement.
- **Minimal shape** (rewritten, `tests/codegen/consteval_if_fold.cpp`):
  ```cpp
  constexpr bool is_ce() { if consteval { return true; } else { return false; } }
  struct ParseCtx { const char *begin; int next_id; void check_id(int); };
  struct CompileCtx : ParseCtx { int num_args; };
  void ParseCtx::check_id(int id) {
    if (is_ce() && sizeof(int) == 4)
      if (id >= static_cast<CompileCtx *>(this)->num_args) fail("argument not found");
  }
  struct Handler { ParseCtx ctx; char buf[24]; };   // `Handler h;` is zero-filled
  ```
  kiln emitted the `num_args` load and the call to `fail`; clang (and
  now kiln) fold the guard to false and emit neither.
- **Tests.** `tests/codegen/consteval_if_fold.cpp` (C++26) and
  `consteval_if_fold_cxx23.cpp` (`-std=c++23
  -ftrivial-auto-var-init=zero`), IR-identical to clang 19 and 22;
  `tests/conformance/basic.indet/run-consteval-guard-zero.cpp` and
  `tests/conformance/stmt.if/run-consteval-if-fold.cpp` (run at `-O2`,
  every constant and non-constant context).
