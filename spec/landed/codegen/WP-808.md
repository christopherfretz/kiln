# WP-808 — no silent drops, part 4: ABI-changing attributes and flags

Before this package kiln parsed these attributes and flags and then
dropped them (docs/status: A6, A9, A16, F-A1, F-A2, F-A3). Code that used
them compiled, but did not link or call compatibly with clang-built
objects. Each one now behaves as in clang 19 / 22, or is a hard error.
The sources are clang's `AttrDocs` (`clang/include/clang/Basic/AttrDocs.td`:
"Calling Conventions", "no_builtin", "pass_object_size,
pass_dynamic_object_size") and GCC's "x86 Function Attributes" and
"C Dialect Options" (`-ffreestanding`, `-fno-builtin`) /
"C++ Dialect Options" (`-fno-sized-deallocation`, `-fchar8_t`) pages.

## Standard

- **[dcl.attr.grammar]/6.** "The use of an attribute-token ... not
  specified in this document is implementation-defined"; kiln follows
  clang for each GNU/clang attribute below.
- **[expr.delete]/10-11, [basic.stc.dynamic.deallocation]/3.** Whether
  the sized `operator delete(void*, size_t)` is selected. With
  `-fno-sized-deallocation` the sized forms are not usual deallocation
  functions for the selection (P0722 / clang `SizedDeallocation`).
- **[lex.key], [lex.ccon]/3, [lex.string]/6, [basic.fundamental]/9.**
  The `char8_t` keyword and the type of UTF-8 literals; `-fno-char8_t`
  is the pre-C++20 dialect (P0482) as an extension.

## Calling conventions (item 1; spec/types.md "Calling conventions")

- `ms_abi`, `sysv_abi`, `regcall`, `vectorcall`, `preserve_most`,
  `preserve_all`, `preserve_none`, `aarch64_vector_pcs`,
  `aarch64_sve_pcs`, `intel_ocl_bicc`, `regparm(N)` and
  `no_caller_saved_registers` are function-type properties
  (`FuncInfo`): pointer types, overloading (ignored, `IsOverload`),
  redeclaration merge, override check, mangling (`U6ms_abi`,
  `__regcall3__`) and the IR `cc` on definitions, declarations and every
  call site (`x86_64_win64cc`, `preserve_mostcc`, `aarch64_vector_pcs`,
  ...). `ms_abi` uses Win64 argument classification on x86_64 and
  aarch64.
- A convention that is the target default (`sysv_abi`, `cdecl`) is the
  default type; one the target ignores (`stdcall`, `fastcall`,
  `thiscall`, `pascal`, `pcs`, `m68k_rtd`, `regparm` on aarch64, ...)
  warns `-Wignored-attributes` like clang.
- **Hard errors (not implemented):** `swiftcall`, `swiftasynccall`, x86
  `interrupt`; `va_start` in an `ms_abi` function on a SysV target
  (`__builtin_ms_va_list` is not provided).

## no_builtin, -ffreestanding, -fno-builtin[-name] (item 2)

spec/codegen.md "no-builtin", spec/sema.md §4.5 / §5.4, spec/pp.md: the
`"no-builtins"` / `"no-builtin-<name>"` function attributes and the
`nobuiltin` call-site attribute as clang's `addNoBuiltinAttributes`;
sema recognizes no library builtin under the flags; `__has_builtin`
answers 0 for library builtins; `-ffreestanding` sets
`__STDC_HOSTED__` 0 and drops `uwtable`. Deviations: the definition's
attribute is used for all declarations; `std::move` keeps folding under
the wildcard (clang 19 leaves an undefined reference).

## -fno-sized-deallocation (item 3; spec/sema.md, the deallocation rules)

The implicit global declarations omit the sized `operator delete` and
its array and aligned twins, and a global usual-deallocation lookup
(delete-expression, deleting destructor, new-expression cleanup,
coroutine frame) never prefers a sized function, even a user-declared
one (clang 19 `usual_delete`). A class's own only `operator delete(void*,
std::size_t)` still gets the size. `-fsized-deallocation` (the C++14+
default) restores the sized calls.

## pass_object_size completion (item 4; spec/codegen.md, spec/oven.md)

The hidden size argument is folded as clang's `tryEvaluateObjectSize`:
the Oven evaluates `__builtin_object_size(arg, N)` statically
(`Oven::fold_object_size`, `Job::ObjectSize`) with no side-effect
default; else the caller's own compatible `pass_object_size` parameter;
else 0 for type 3; else `llvm.objectsize`. This covers member, static,
operator and constructor calls. A string literal has no whole-object
type (clang `getObjectType`), so types 0/2 of it are not constant.
Not yet: clang's lenient designator for out-of-bounds offsets,
reinterpreted pointers and invalid bases (xfail repro
`ext.clang.pass.object.size/pass-object-size-lenient-xfail.cpp`); kiln
emits a dynamic computation there, which only weakens -O0 checks.

## -fno-char8_t / -fchar8_t (item 5; spec/lex.md)

Without char8_t (the C++17 default, or `-fno-char8_t`), `char8_t` is
an identifier, `u8''` is `char` and `u8""` is `const char[N]` (lexer,
`#if` evaluation, sema). Overloads, mangling (`c`, not `Du`) and the
`#if` signedness of `u8''` follow, and `__cpp_char8_t` is undefined.
`-fchar8_t` restores the keyword under C++17 (clang `KEYCHAR8`).

## Feature queries and the attribute triage

`attr_triage::attribute_support` answers `Implemented` for the
conventions, `regparm` and x86 `no_caller_saved_registers`
(`cconv::cc_attr_kind`, in each spelling clang gives them) and for
`no_builtin` (also `[[clang::no_builtin]]`); their WP-805 rows are gone,
and so is WP-805's interim declaration-only `aarch64_vector_pcs`
(`AARCH64_VECTOR_PCS_DECL`). So `__has_attribute` /
`__has_cpp_attribute` answer clang's table for them. `swiftcall`,
`swiftasynccall` and x86 `interrupt` stay class A (the `not supported by
kiln yet` error, `__has_attribute` 0); x86 `interrupt` is class A at
clang 19 too, where clang handles it although its `__has_attribute`
answers 0.
