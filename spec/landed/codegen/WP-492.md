# WP-492 — WP-462 follow-ups: `__builtin_expect` at `-O1`, variadic return-adjusting thunks, access groups, constant function-pointer casts, structor asm labels, incomplete-class tracking, `extern` in `extern "C"`

- **`__builtin_expect` above `-O0`** (clang `Builtin::BI__builtin_expect`,
  `BI__builtin_expect_with_probability`): the value and the expected
  value are emitted at every level; at `-O0` the value is the result,
  above it the result is `llvm.expect.T(value, expected)`, or
  `llvm.expect.with.probability.T(value, expected, double P)` whose
  probability the fold prepass evaluates (`builtins::folded_arg`) and
  which is emitted as a `double` constant
  (`tests/codegen/builtin_expect_o1.cpp`, clang 19 and 22).
- **Return-adjusting variadic thunks** (clang `GenerateVarArgsThunk`,
  spec/codegen.md "Return-adjusting variadic thunks"): the thunk is a
  clone of its method's finished `Fir`, `this` adjusted before its
  entry-block store and the first `ret`'s value adjusted, appended to
  the module with the method's header, linkage and its own comdat;
  byte-exact against clang 19 on both targets at `-O0` and `-O1`
  (`tests/codegen/variadic_thunk_ret{,_o1}.cpp`,
  `class.virtual/variadic-covariant-thunk-run.cpp`). `isVTableHidden`
  is not done: kiln has no visibility model.
- **Access groups of inserted instructions** (spec/codegen.md §7z,
  "`assume_safety` access groups"): every kiln insert away from the
  insertion point was checked against how clang makes the instruction;
  the conditional full-expression `llvm.lifetime.start` (clang's builder
  at the outermost conditional) now gets the access group, and the
  `cleanup.dest` load of a cleanup's exit switch (`createLoadInstBefore`,
  appended directly) no longer does
  (`tests/codegen/loop_parallel_inserts{,_o1}.cpp`).
- **Function-pointer casts in constant initializers** (spec/oven.md
  "Pointers that point at nothing", spec/codegen.md "Static
  initialization"): a cast to or from a function pointer is a `Cce`
  that a fold continues past, keeping the function; a call through such
  a pointer folds only when the call's type is the function's; a lax
  variable whose constant initialization failed reads its non-manifest
  re-fold; initializer lists are re-folded like scalars. `(void
  (*)())&f`, `reinterpret_cast<void (*)(long)>(&f)`, arrays and structs
  of them are static initializers, as in clang 19 and 22
  (`tests/codegen/fnptr_cast_const_init.cpp`,
  `expr.const/5.15/fnptr-cast-fold.cpp`). `(long)&g` (a pointer to an
  object as an integer) still stays dynamic.
- **Structor asm labels with virtual bases and `D0`** (spec/codegen.md
  §7z "Shared asm labels"): a labelled structor variant defined after
  another keeps the earlier body and appends its own unreachable blocks
  when its type is the same (a virtual destructor's `D0`), and replaces
  the earlier definition at the end of the module when it differs (the
  complete-object variant of a class with virtual bases;
  `kiln_llvm::Module::redefine_function_to_end`); byte-exact against
  clang 19 and 22 (`tests/codegen/asm_label_structors_vbases.cpp`,
  `dcl.asm/asm-label-structors-vbases-run.cpp`). Inline (deferred)
  labelled structors of a class with virtual bases still differ in
  emission order.
- **Duplicate mangled names** (spec/codegen.md §7z): a definition under
  a symbol another entity already defined is clang's
  `err_duplicate_mangled_name` with the representative's definition as
  the note, reported once (`cg_duplicate_mangled_name`;
  `crates/kiln_driver/tests/codegen.rs` `duplicate_mangled_name`,
  compared with clang 19).
- **Incomplete-class tracking for instantiated classes** (spec/codegen.md
  §7z "Incomplete class in a signature"): completeness to the top-level
  walk is the class-completion epoch at the end of the top-level
  declaration being emitted (recorded by the parser,
  `DeclArena::end_top_level_decl`), so a class template specialization,
  a member class of one or an explicit specialization completed by a
  later declaration gives clang's `void ()` placeholder, and a class
  defined later inside the same namespace or `extern "C++"` block no
  longer does (it did: the walk tracked namespace members one by one).
  Local classes were already right (complete with their enclosing
  function). Byte-exact against clang 19 and 22 on both targets
  (`tests/codegen/incomplete_class_inst.cpp`,
  `temp.inst/incomplete-specialization-signature-run.cpp`).
