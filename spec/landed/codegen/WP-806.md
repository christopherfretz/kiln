# WP-806 — floating-point contraction, fast-math and the floating-point environment

No floating-point option or pragma is silently dropped. Each one is
either implemented the way clang 19 implements it (clang 22's rules under
`-fclang-compat=22`), or it is an error. The driver flags are in
spec/driver.md "Floating-point flags", the pragma syntax in spec/parse.md
§2.3, and the summary in spec/codegen.md §3.2.

## Standard

- **[expr.pre]/6 and C23 7.12.2 (contraction).** "The values of the
  floating operands and the results of floating expressions may be
  represented in greater precision and range than that required by the
  type." C23 7.12.2: "The FP_CONTRACT pragma can be used to allow (if the
  state is 'on') or disallow (if the state is 'off') the implementation
  to contract expressions. ... Each pragma can occur either outside
  external declarations or preceding all explicit declarations and
  statements inside a compound statement." So `a * b + c` may be
  evaluated with one rounding, as `fma`. Under `ON` this happens within
  one expression only; under `OFF` it never happens.
- **[cfenv.syn] and C23 7.6.1 (FENV_ACCESS).** `<cfenv>` is C's
  `<fenv.h>`. C23 7.6.1: "If part of a program tests floating-point status
  flags, establishes non-default floating-point mode settings using any
  means other than the FENV_ROUND pragmas, or runs under non-default mode
  settings, but was translated with the state for the FENV_ACCESS pragma
  'off', the behavior is undefined." The default state is
  implementation-defined. kiln's is `OFF`, and it does not implement
  `ON` (below).
- **C23 7.6.2 (FENV_ROUND), 7.3.4 (CX_LIMITED_RANGE).** These follow the
  same placement rule as FP_CONTRACT.

## Contraction (`FpContract`, `kiln_ast::fp`)

- **`on`** (the C++ default, `-ffp-contract=on`, `#pragma STDC
  FP_CONTRACT ON`, `#pragma clang fp contract(on)`). A single-use `fmul`
  operand of an `fadd`/`fsub` in the same expression becomes
  `llvm.fmuladd.*`. This follows clang's `tryEmitFMulAdd` and the operand
  rules in spec/codegen.md §3. Products in separate statements are not
  fused.
- **`off`**. Plain `fmul` and `fadd`, with no `llvm.fmuladd` and no
  `contract` flag. `llc`'s default (`-fp-contract=on`, which fuses only
  `fmuladd`) leaves them unfused.
- **`fast`** (`-ffp-contract=fast`, `fast-honor-pragmas`, `#pragma clang
  fp contract(fast)`, `-ffast-math` and its parts). The `contract`
  fast-math flag goes on every FP operation, and there is no
  `llvm.fmuladd`. With exactly `-ffp-contract=fast`, the driver also
  passes `llc -fp-contract=fast` (clang's `AllowFPOpFusion`).
  `fast-honor-pragmas` lets pragmas override it.
- `#pragma STDC FP_CONTRACT DEFAULT` returns to the command line's mode.

## Fast-math flags and function attributes (`kiln_codegen/src/fp.rs`)

- **Where the flags go.** The FP scope (command line plus pragmas) gives
  the LLVM fast-math flags (`reassoc nnan ninf nsz arcp afn contract`,
  clang `SetFastMathFlags`). `reassoc` needs `-fassociative-math` together
  with `-fno-signed-zeros`. The flags go on:
  - FP binops, `fneg` and `fcmp`;
  - FP-typed `select` and `phi`;
  - calls of LLVM intrinsics and of library builtins (the scope's flags).
  A call of any other function with an FP result gets the command line's
  flags, not the pragma's (clang).
- **LLVM 20 and later.** These also take flags: `fpext`/`fptrunc`, and
  calls returning a homogeneous FP struct (`{double, double}`, the
  complex libcalls). kiln_llvm emits flags on them only when
  `Module::ir_version` is 20 or more (`is_fp_math_type`). The default
  backend is LLVM 19, which rejects them, so kiln omits them. The
  oracle-22 `ir_vs_clang` cases allowlist the difference as
  `Allow::Structure`.
- **Function attributes.** Every declaration and definition carries the
  command line's attributes (clang `getTrivialDefaultFunctionAttributes`):
  - `no-infs-fp-math`, `no-nans-fp-math`, `approx-func-fp-math`;
  - `unsafe-fp-math` (reassoc, arcp, nsz, afn and contract fast);
  - `no-signed-zeros-fp-math`;
  - `denormal-fp-math`;
  - `"no-trapping-math"="true"` (always).
- **Pragma scopes in attributes.** A definition containing a non-empty
  pragma scope that turns one of the infs, nans, signed-zeros or unsafe
  attributes off gets that attribute as `"false"` (clang
  `mergeFnAttrValue`).
- **`nofpclass`.** Under `-ffinite-math-only` (or both of
  `-fno-honor-nans` and `-fno-honor-infinities`, or one of them alone),
  FP parameters and returns get `nofpclass(nan inf)`, or the part that
  applies (clang `getNoFPClassTestMask`). This includes FP vectors and
  flattened FP aggregates.
- **`math-errno`.** `-fno-math-errno` (part of `-ffast-math`) marks the
  errno-setting math library functions `memory(none)`. They are then
  lowered to their intrinsics (`sqrt` to `llvm.sqrt`, `fmod` to `frem`,
  `sin`, `exp`, `pow`, ...). `ldexp` and `exp10` stay library calls, as
  in clang 19.
- **Pragmas and `errno`.** `#pragma float_control(precise, on)` turns
  `errno` back on. `float_control(precise, off)` turns it off, and the
  call is lowered only at `-O1` and above (clang `GenerateIntrinsics`).
- **Macros.** `__FAST_MATH__`, `__FINITE_MATH_ONLY__`, `__NO_MATH_ERRNO__`
  and AArch64 `__ARM_FP_FAST` follow the resolved flags (spec/driver.md).

## Pragma scopes (`kiln_parse/src/fp_pragma.rs`, `kiln_sema/src/stmt.rs`)

- **Supported pragmas:**
  - `#pragma STDC FP_CONTRACT`, `CX_LIMITED_RANGE` and `FENV_ACCESS OFF`;
  - `#pragma clang fp contract|reassociate|reciprocal`, plus
    `exceptions(ignore)` and `eval_method(source)`;
  - `#pragma float_control(precise, on|off[, push])`, `(push)`, `(pop)`
    and `(except, off)`.
- **Placement.** These apply at namespace scope and at the start of a
  compound statement, before its first statement (clang's annotation
  tokens).
- **Placement errors**, with clang's wording:
  - elsewhere in a block: `'#pragma <name>' can only appear at file scope
    or at the start of a compound statement`;
  - in a class: `this pragma cannot appear in struct declaration`;
  - `float_control` push/pop inside a function: `'#pragma float_control
    push/pop' can only appear at file or namespace scope or within a
    language linkage specification`;
  - a pop on an empty stack: `#pragma float_control(pop, ...) failed:
    stack empty` (warning).
- **What sema records.** Sema keeps the current state as an `FpOverride`
  relative to the command line, so `fast-honor-pragmas` and `DEFAULT` can
  refer back to the command line. It records that state on each compound
  statement (`Stmts::compound_fp`) and restores the enclosing state at the
  closing `}`.
- **Codegen.** Codegen applies a compound statement's override for its
  body. A template instantiation keeps its pattern's state.
- **`float_control(precise, …)`** sets the whole fast-math set, `errno`
  and the contraction mode, as clang's `setFPPreciseEnabled` does.
- **`CX_LIMITED_RANGE ON|OFF`** selects the `Basic` or `Full` complex
  range (spec/codegen.md §7n) for `*` and `/` in its scope. `DEFAULT`
  selects the command line's range.

## The floating-point environment (rejected)

kiln implements only the default floating-point environment:
round-to-nearest, no status-flag access, no traps and
`FLT_EVAL_METHOD == 0`. There are no constrained intrinsics. Everything
that needs another environment is an error, never ignored.

- **Pragmas.** These are sema `unsupported` errors, `'<pragma>' (the
  floating-point environment) is not supported yet`, at the pragma name:
  - `#pragma STDC FENV_ACCESS ON`;
  - `#pragma STDC FENV_ROUND <mode>`, with any mode except
    `FE_TONEAREST`. clang's `pragma STDC FENV_ROUND is not supported`
    warning is issued too;
  - `#pragma float_control(except, on)`;
  - `#pragma clang fp exceptions(maytrap|strict)`;
  - `#pragma clang fp eval_method(double|extended)`.
- **Driver flags.** These are `drv_unsupported_flag` errors, one per flag
  (spec/driver.md):
  - `-ftrapping-math`, `-ffp-exception-behavior=maytrap|strict`;
  - `-frounding-math`;
  - `-ffp-model=strict`, unless later flags undo its rounding and trapping;
  - `-ffp-eval-method=double|extended`;
  - `-fexcess-precision=16`.

## clang 22 (`-fclang-compat=22`)

- **`-ffp-model=fast`.** It means fast-math without the finite-math
  flags: no `nnan`/`ninf`, no `__FAST_MATH__` or `__FINITE_MATH_ONLY__`.
  It also selects promoted complex division.
- **`-ffp-model=aggressive`.** This is clang 19's `fast`. At compat 19 it
  is `unsupported argument 'aggressive' to option '-ffp-model='`.
- **Complex range.** `precise` and `strict` set the complex range to
  full, and `-fno-fast-math` clears it.
- **Promoted division** (`-ffp-model=fast` as the last complex-range
  setting) is not implemented. It is the error `'-ffp-model=fast
  (promoted complex arithmetic; add -fcomplex-arithmetic=basic)' is not
  supported by kiln`, never full or basic silently.

## Deviations (follow-ups)

- An expression outside any compound statement (a namespace-scope
  initializer, a default argument, an NSDMI) takes the command line's FP
  state, not the namespace-scope pragma state in effect there.
- The `"false"` attribute merge is per compound statement, where clang's
  is per expression.
- `#pragma STDC FP_CONTRACT ON junk`: clang also reports a stray
  `expected unqualified-id` at the end of the directive; kiln reports
  only the `expected end of directive` warning.
- Not issued: `-Wnan-infinity-disabled`, `-Woverriding-option`,
  `-Whigher-precision-for-complex-division`, clang 19's `-Ofast`
  deprecation warning, and clang's `err_setting_eval_method_used_in_unsafe_context`.
- With `-fno-math-errno`, the complex library functions (`cabs`, ...)
  are not marked `memory(none)`.
- clang's `optnone` rule for `errno` lowering is not modelled.
- A complex compound assignment is not promoted.
