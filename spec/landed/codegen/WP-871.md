# WP-871 — UBSan checks accepted but not instrumented

Closes WP-853 (`_Atomic` `++`/`--`/`op=`) and WP-854 (`_BitInt`
descriptors) and most of WP-852. The contract is in spec/codegen.md
"Sanitizers". docs/design/sanitizers.md §1.5 has the per-check port
notes and the coverage table, which says what is done and what is a
follow-up. This file records what landed, how it was measured and what
remains.

## What changed

WP-675 accepted `-fsanitize=undefined` but emitted only the arithmetic
checks (overflow, shift, divide) and `__builtin_unreachable`. Each new
check is a port of the named clang 19 function, with the clang 22
deltas behind `-fclang-compat=22`:
- null, alignment and object-size type checks (`EmitTypeCheck`) at
  loads, stores, member access, reference binding, `this`, upcasts and
  downcasts, constructors, `new` and `delete`, member pointers and the
  memcpy-family builtin arguments;
- array-bounds (`EmitBoundsCheck`, with the clang 22 index form);
- bool and enum load range checks (`EmitScalarRangeCheck`, with the
  clang 22 range form for odd-width `_BitInt`);
- float-cast-overflow, including complex sources;
- pointer-overflow (`EmitCheckedInBoundsGEP`);
- nonnull-attribute, also on glibc's memcpy, memmove and memset,
  and returns-nonnull-attribute;
- builtin (`ctz`/`clz` of zero);
- implicit-integer truncation and sign-change, and
  implicit-bitfield-conversion;
- unreachable after a call that does not return: the callee and the
  call lose `noreturn`, `__asan_handle_no_return` goes before the call
  under ASan, and the block ends in a `builtin_unreachable` check;
- the same checks on `_Atomic` `++`, `--` and compound assignment;
- `_BitInt` type descriptors (`EmitCheckTypeDescriptor`), and canonical
  class and enum descriptors printed with their full scope.

Loads that clang does not check, such as the implicit move of a
returned local, are not checked.

One fix outside sanitizers fell out of this. A call through the vtable
to a `[[noreturn]]` virtual function no longer ends the block. clang 19
and 22 only end it when the call site or the called `llvm::Function` is
`noreturn`, and an indirect call has neither
(`dcl.attr.noreturn/ir-noreturn-virtual-dispatch.cpp`).

Without `-fsanitize` none of the new code runs. `cargo xtask bench` is
unchanged (log `.build/wp871-bench.log` on the dev host).

## fmt smoke

fmt 12.1.0 was built through the OSS harness with
`CXXFLAGS=LDFLAGS=-fsanitize=undefined` (`-O3`, libstdc++; fmt's own
flags). The table counts UBSan handler call sites: the
`__ubsan_handle_*` relocations in every object file
(`llvm-objdump-19 -r`, with `_abort` folded into its handler). All 21
ctest tests pass under kiln, with no runtime reports.

|---|---|---|---|
| type_mismatch_v1 | 0 | 43071 | 39138 |
| pointer_overflow | 0 | 24415 | 20473 |
| builtin_unreachable | 2815 | 5370 | 5091 |
| load_invalid_value | 0 | 5362 | 5249 |
| add_overflow | 3921 | 3144 | 3063 |
| shift_out_of_bounds | 2119 | 2432 | 2113 |
| sub_overflow | 2743 | 2066 | 2036 |
| nonnull_arg | 0 | 679 | 671 |
| mul_overflow | 578 | 581 | 581 |
| out_of_bounds | 0 | 544 | 544 |

| **total** | **12532** | **88146** | **99203** |

Without vptr and function, which are not implemented, clang has 79441
call sites and kiln 88146. Measured on the frontend output instead
(`-O3 -Xclang -disable-llvm-passes`, counting handler calls in the IR),
kiln and clang agree almost exactly:
- `src/format.cc`: identical counts for every handler.
- `test/format-test.cc`: nonnull_arg +4, type_mismatch +17,
  builtin_unreachable -1 and load_invalid_value -1.
- `test/chrono-test.cc`: nonnull_arg +4, type_mismatch +5,
  sub_overflow +2.
- `test/xchar-test.cc`: nonnull_arg +4 and type_mismatch +6.

The extra call sites in the object files therefore come from the
optimizer, not from extra checks. The pipeline handles kiln's IR
differently: kiln folds fewer constants (below), and clang's vptr and
function checks change the inlining decisions in clang's own build.

The frontend differences that remain have two causes, both outside
sanitizers and both with xfail repros:
- kiln does not fold library builtins such as `strlen` to constants
  the way clang's `EmitBuiltinExpr` does. gtest's
  `strlen(prefix)` then gets the nonnull_arg check: the +4
  (`ext.gnu.builtins/library-strlen-fold-ir.cpp`).
- A member access naming a constexpr static data member is a load in
  kiln and a constant in clang. This is fmt's `static_named_arg::name`
  in `init_named_arg`, the type_mismatch excess
  (`expr.ref/ir-constexpr-static-member-fold.cpp`).

The builtin_unreachable and load_invalid_value -1 in format-test.cc
(`__distance`) were not reduced.

The brief cited 1219 kiln and 17112 clang handler calls from WP-675.
That method is not recorded and could not be reproduced, so the table
uses static call sites, which do not depend on the test inputs.

## Tests

`tests/conformance/driver.sanitize/` has exact-IR tests for every check
in recover and trap modes (`-fsanitize-trap=all`), and trap-run tests
that execute the trap. Some IR only clang 22 produces; those tests set
`min-oracle: 22`.

xfail repros:
- `ubsan-desc-identity-ir.cpp`: type descriptors keyed by type, not
  by the sugared `QualType`.
- `ubsan-lambda-returns-nonnull-ir.cpp`: sema puts a lambda's
  trailing `returns_nonnull` on `operator()`.
- `ubsan-noreturn-asan-ir.cpp`: no value names under
  `-fsanitize=address`, and no clang 22 `alloca_name_altered`
  annotation.
- `ext.gnu.builtins/library-strlen-fold-ir.cpp` and
  `expr.ref/ir-constexpr-static-member-fold.cpp`, from the smoke.

## Not done (follow-ups)

- vptr (`dynamic_type_cache_miss`) and function
  (`function_type_mismatch`).
- nullability-arg/-assign/-return.
- local-bounds (an LLVM pass kiln does not schedule).
- `pass_object_size` in object-size checks.
- Range checks at load sites other than scalar loads.
- nonnull-attribute through member-pointer calls.
- Descriptor identity by sugared type.
