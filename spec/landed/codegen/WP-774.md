# WP-774 — discarded member-call chains, variadic `dead_on_return`, `__builtin_clear_padding`

Three codegen gaps found while building open-source projects with kiln.
The contracts are in spec/codegen.md, spec/abi.md §3.3, spec/sema.md and
spec/oven.md; this file records what landed and what was deferred.

## Discarded member calls on class prvalues ([expr.call]/7, [class.temporary]/4)

WP-777 matched clang for one discarded member call on a temporary. A
discarded comma whose operands are such calls (`M{}.b(), M{}.b();`) made
one extra result temporary for the comma. kiln now ignores each operand,
as clang `AggExprEmitter::VisitBinComma` does (`expr.rs` `emit_ignored`).
These shapes now match clang 19's temporary count, order and IR:
- chained calls on a returned temporary (`M{}.a().b();`);
- calls through a returned reference;
- temporary arguments with non-trivial destructors;
- nested calls in arguments;
- discarded conditionals.
Tests:
- `tests/codegen/discarded_member_call_chain.cpp`;
- `tests/conformance/expr.call/run-discarded-member-call-chain-order.cpp`.

## `dead_on_return` on callee-destroyed and variadic arguments (compat 22)

clang 21+ marks an indirect, non-`byval` argument `dead_on_return` when
its lifetime ends in the callee. This includes a `[[clang::trivial_abi]]`
class with a non-trivial destructor (`isParamDestroyedInCallee`), and
it covers variadic arguments too. kiln marked only trivially
destructible types (`module.rs` `sig_attrs`, now also
`kiln_abi::call::is_destroyed_in_callee`). Test:
`tests/conformance/expr.call/ir-clang22-dead-on-return-variadic.cpp`.
That test compares exactly, because `ir_norm` treats the attribute as
non-ABI.

## `__builtin_clear_padding` (GCC)

The brief assumed clang implements this builtin. It does not: neither
clang 19 nor clang 22 has it (LLVM issue 64830). GCC does, at run time
only, and libstdc++ 14 `<atomic>` and libc++ 22 `atomic_ref` use it
under `__has_builtin`. kiln implements it as a GCC-only builtin:
- **Sema.** GCC's argument checks and wording
  (`sema_builtin_clear_padding_invalid_arg`). The `gcc_only` table makes
  `__has_builtin` 1 at both compat levels; `__has_constexpr_builtin` is
  0.
- **ABI.** `kiln_abi::padding_mask` follows GCC's `clear_padding_type`.
  It covers padded and nested structs, arrays, bit-fields (named:
  declared bits; unnamed: padding), unions (the bits that are padding in
  every member), empty classes, empty bases and `[[no_unique_address]]`
  members, non-POD base tails, x87 `long double` (10 value bytes) and
  `_BitInt`. `bool`, pointers and member pointers keep all their bytes.
- **Codegen** (`clear_padding.rs`). A run of whole padding bytes becomes
  a `memset`. A byte that mixes value and padding bits becomes a load, an
  `and` and a store. Arrays over 64 bytes are cleared by a loop. A
  volatile pointee makes every access volatile.
- **Oven.** `bi::CLEAR_PADDING` is an extension (GCC rejects the call in
  constant expressions). It checks that the storage is writable and does
  nothing else, because padding is not modelled. This keeps libstdc++'s
  `constinit std::atomic<Padded>` a constant.

Tests are in `tests/conformance/ext.gnu.clear_padding/`. The run test
prints the bytes of two dozen objects, and its output is compared with GCC
16.1's. There are also diagnostic and constant-evaluation tests, both
valid and invalid.

## Deferred

- The Oven does not model padding bits. After `__builtin_clear_padding`
  in a constant, a `bit_cast` that reads padding is still non-constant;
  in GCC the call itself is non-constant.
- libstdc++ `std::atomic<T>` of an 8-byte struct: the generic
  `__atomic_load`/`__atomic_store` see the pointee type's alignment
  through `std::__addressof(_M_i)`, not the member's `alignas`, so LLVM
  emits libatomic calls and the program fails to link. This predates
  WP-774 and is unrelated to clearing padding. Xfail repro:
  `tests/conformance/atomics.types.generic/run-libstdcxx-atomic-struct-align.cpp`.
