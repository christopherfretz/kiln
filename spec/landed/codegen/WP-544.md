# WP-544 — `-fvisibility=` / `-fvisibility-inlines-hidden` and a symbol visibility model

- **Driver** (`args.rs`, spec/driver.md): `-fvisibility={default,hidden,
  protected,internal}` (last wins; `internal` is hidden),
  `-f[no-]visibility-inlines-hidden`, `-fvisibility-ms-compat` (hidden
  values, default type visibility, silently, as clang does),
  `-f[no-]semantic-interposition` and `-f[no-]direct-access-external-data`
  reach codegen; `-f[no-]pic/PIC/pie/PIE` now select the relocation
  model as well as the macros (default PIE). An unknown visibility value
  is clang's `invalid value 'V' in '-fvisibility=V'` (exit 1), reported
  even under `-E`, and overridden by a later valid value.
- **Sema** (`kiln_sema/src/visibility.rs`, spec/sema.md "Visibility
  attributes"): `visibility` / `type_visibility` attributes are checked
  and kept (one string literal argument, known value, not on a typedef,
  `type_visibility` only on types and namespaces, mismatch across
  redeclarations, after-definition warning). `#pragma GCC visibility
  push/pop` keeps a stack that supplies an implicit attribute to
  externally visible namespace-scope functions, variables and classes;
  a namespace with a `visibility` attribute suspends it and diagnoses
  unbalanced use with clang's errors and notes.
- **Codegen** (`kiln_codegen/src/visibility.rs`, spec/codegen.md §8):
  clang's `getLVForDecl` for the visibility half: explicit attribute
  (own, then the template pattern's) > template arguments > enclosing
  class > namespace / pragma > `-fvisibility`; members, vtables, VTTs,
  construction vtables, typeinfo and typeinfo names, thunks and D1/C1
  aliases follow their class; `-fvisibility-inlines-hidden` hides inline
  functions that are not explicit instantiations; replaceable allocation
  functions stay default. Declarations are hidden only when known to be.
- **`dso_local`** (coordinator extension; clang `shouldAssumeDSOLocal`):
  internal or non-default visibility implies it; static: every
  definition; PIE: definitions; PIC: only non-comdat function definitions
  under `-fno-semantic-interposition`; declarations under direct access
  to external data (non-TLS variables, and functions only when static).
  Module flags `PIC Level`, `PIE Level`, `SemanticInterposition` and
  `direct-access-external-data` match clang.
- **isVTableHidden**: the opportunistic emission of a vtable whose key
  function is elsewhere is skipped when the vtable would be hidden (at
  `-O1` and above), as clang does.
- **Deviations** (spec/codegen.md §8): template-parameter LV not merged;
  entities named inside class-type or array NTTP values not merged; no
  `getLVForClosure`; linkage is not part of LV; `-fvisibility-global-new-
  delete=` / `-fvisibility-from-dllstorageclass`, `weak` and `dllexport`
  do not affect visibility.
- **Tests**: `tests/codegen/visibility_*.cpp`, `tests/codegen/
  dso_local_*.cpp` (IR vs clang); `tests/conformance/ext.gnu.visibility/`,
  `tests/conformance/cpp.pragma/gcc-visibility-namespace.cpp`;
  `kiln_driver/tests/driver.rs` `visibility_flags`,
  `kiln_driver/tests/codegen.rs` `pic_visibility_and_objects`.
