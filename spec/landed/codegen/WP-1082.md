# WP-1082 — Coverage mapping: clang 20+ rules and fidelity tail (also WP-1083)

The contract is spec/codegen.md §5.4 "Instrumentation". This WP builds on
[WP-1003](WP-1003.md), which landed the clang 19 mapping and listed these
two rows as follow-ups. WP-1082 ports the clang 20+ mapping rules under
`-fclang-compat=20` or later. WP-1083 fixes the remaining differences
from clang in every mode.

## What landed

### WP-1082: clang 20+ rules (`coverage/mapping.rs`, `Builder::v20`)

- **Gaps between logical operands.** In clang 20+, the right operand of
  `&&`/`||` is counted from the end of the left operand. When the two
  are apart, that span is a gap region. Before, kiln wrote no region
  there.
- **Folded branches.** When a branch condition folds to a constant,
  clang 20+ keeps the counter on the side the constant takes and zeroes
  only the other side. clang 19 zeroes both, and kiln still does so in
  compat 19.
- **Branch counter order.** For a `switch` without `default`, clang 20+
  gives the cases' sum to the true side and the rest to the false side.
  clang 19 orders them the other way.
- **Equal counts start no region.** clang 20+ `IsCounterEqual` treats an
  out count as equal to the parent's when their difference simplifies to
  zero, and then starts no region (loops, `if`, `?:`).
- **`do ... while (0)` in a macro.** A `do` body's termination now
  survives the loop only when the loop's exit starts a region. This
  gives a `CHECK`-style `do { ... } while (0)` its extra region.
- **Statement expressions.** A `return` inside a statement expression
  does not end the enclosing region (clang 20+ `VisitStmtExpr`).

### WP-1083: fidelity tail

- **Zero records for instantiations used only in constant evaluation.**
  - clang calls `HandleTopLevelDecl` at the end of
    `InstantiateFunctionDefinition`. That defers a zero record for every
    instantiated function, member function and conversion function.
  - kiln now records each instantiated definition, together with the
    top-level declaration it happened in. The new
    `kiln_ast::Decls::note_fn_def_inst` is called from `kiln_sema`
    `instantiate_function_definition`.
  - `CovModule::cov_defer_insts` defers them in that order, before each
    later top-level member is emitted (`module.rs` `member_ends`), and
    the remaining ones at the end of the TU.
  - Some functions get no zero record this way, as in clang:
    - constructors and destructors;
    - immediate functions;
    - the std builtins (`std::move`, `std::addressof`, ...), because
      their calls never reference them.
- **Lambda records.**
  - A lambda's conversion function and static invoker are implicit, and
    so are a generic lambda's specializations of them. None of these is
    instrumented now (`pgo.rs` `prof_begin`, `closure_thunk`).
  - A closure type is not a top-level declaration, so an unused lambda's
    call operator gets no zero record (`cov_defer_class`).
  - The "immediate-invocation helpers" of WP-1003 did not reproduce.
- **Stringizing.** A `#x` in a macro body now maps a nested expansion
  at the `#x`, as clang's `getNonScratchExpansionLoc` does for a
  scratch-space token (`mapping.rs`). The string literal ends there
  and gets its own region. To support this, a concatenated string
  literal now records its last piece's end (`Builder::record_end_loc`,
  `kiln_sema` `act_on_string_literal`).
- **Skipped range of a discarded `if constexpr` branch.**
  - WP-1003 filed this as "a skipped range after an init-capture ends 2
    columns late". The real cause was the discarded branch.
  - kiln instantiated the discarded branch as an empty compound at the
    branch's start. clang spans the written branch's begin and end
    (`TransformIfStmt`).
  - The empty compound now ends at the branch's `getEndLoc`
    (`templ/subst/stmts.rs`, using `uninit_stmt_end`). The skipped
    region therefore ends after the branch's last token.
- **Qualified base initializer.** `N::B(x)` now starts at `N`, clang's
  `ElaboratedTypeLoc` begin (`kiln_parse` `parse_mem_initializer`).
  The location of diagnostics on that initializer moves with it.
- **Compound literal end.** `(T){...}` with a scalar `T` now ends at its
  `}` (`kiln_sema` `act_on_compound_literal` records it).

## Validation

- **Mapping-level tests** (`tests/codegen/coverage_*.cpp`, through
  `ir_vs_clang`). These are exact at oracle 19 and structural at 22.
  Every test pins both modes, and the first four differ between clang
  19 and 22:
  - `coverage_logical_gaps.cpp`;
  - `coverage_folded_branches.cpp`;
  - `coverage_switch_branches.cpp`;
  - `coverage_do_while_macro.cpp`;
  - `coverage_stringize.cpp`;
  - `coverage_consteval_insts.cpp`;
  - `coverage_generic_lambda.cpp`;
  - `coverage_locations.cpp`;
  - `coverage_discarded_branch.cpp`.
- **Decoded records.** The `__llvm_covfun` records were decoded and
  compared with clang++-19 and clang++-22 at the matching
  `-fclang-compat`. All of the tests above are equal, as are
  `coverage_mapping.cpp` and `coverage_prefix_map.cpp`.
- **Sweep over `tests/codegen/*.cpp`** (compat 22, 588 programs):
  - The remaining differences are the same as on main before this WP:
    ABI-matrix macro ends, extern templates, modules and others.
  - The exception is the order of some zero records, listed below.
  - The changes to records improved 6 programs and regressed none.
- **Lambda and NEON corpus** (68 conformance programs with
  init-captures, 28 `target.neon` programs and the SVE programs). These
  are equal apart from lambda `$_N` name hashes and the function
  emission order (both WP-941).
- **`scripts/coverage-compare.py`** exits 0 in both forms below. The
  WP-1003 `KNOWN` map entries for `control_flow.cpp` and `macros.cpp`
  are gone, because the two programs are now equal.
  - The default run (LLVM 19).
  - `--mode map --llvm 22 --clang clang++-22 --link clang++-19`.

## Remaining differences (follow-ups)

- **Zero-record order.** kiln instantiates a class-template member at
  its first use, where clang does so at the end of the TU. Their zero
  records therefore come before the function-template ones. `llvm-cov`
  totals are the same.
  (`crates/kiln_codegen/src/coverage/records.rs` `cov_defer_insts`;
  `tests/codegen/trivially_recursive.cpp` at `-O1`.)
- **Folded `new` conditions.** clang's constant folder folds
  `(bool)new T` to true, and kiln's does not, so `c || new int(4)`
  keeps both branch counters (`tests/codegen/new_conditional.cpp`).
- **Duplicate zero-length regions at system-header NEON macros.** These
  did not reproduce on the NEON and SVE corpus at -O0.
