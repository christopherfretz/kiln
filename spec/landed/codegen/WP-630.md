# WP-630 — x86 target builtins: codegen

The x86-64 half of clang's `checkTargetFeatures`, and the lowering of the
x86 builtins (`crates/kiln_codegen/src/x86.rs`). The declarations are
spec/landed/sema/WP-630.md; the `-march=` and `target("...")` feature
maps spec/landed/driver/WP-630.md.

## Target features

- **Feature map** (`target_features.rs` `x86_feature_map`, clang
  `getFunctionFeatureMap`): the `-march=` CPU's features
  (`CodegenOptions::target_features`, `+name` each; empty: `x86-64`'s
  `cmov cx8 fxsr mmx sse sse2 x87`), then the map the driver's x86 parser
  gives for the function's `target("...")` attribute
  (`CodegenOptions::target_attr`). A `target("arch=<cpu>")` replaces the
  module's features by that CPU's.
- **Attributes** (`module.rs` `target_attrs_of`): `"target-features"`
  prints the map (enabled features sorted, then disabled ones sorted), as
  clang. `"target-cpu"` is the attribute's `arch=` CPU, else `-march=`'s,
  else `x86-64`; `"tune-cpu"` is the attribute's `tune=` CPU, else
  `-mtune=`'s, else `generic` unless a CPU was named.
- **Builtin calls** (`x86_builtin_features_ok`): the row's
  required-features string must hold for the caller's map, else
  `cg_builtin_needs_feature` ("'%0' needs target feature %1", the whole
  string) at the call's start, and the call's value is poison. An SSE
  compare (`cmpps`, `cmppd`, `cmpss`, `cmpsd`) whose predicate is above 7
  needs `avx` instead (clang's special case).
- **`always_inline` calls**: WP-558's `target_feature_call_check` now runs
  on x86-64 too, so calling a header intrinsic (`always_inline`,
  `target("crc32")`) from a function without the feature is clang's
  "always_inline function '_mm_crc32_u8' requires target feature 'crc32',
  but would be inlined into function 'f' that is compiled without
  support for 'crc32'".
- **`min_vector_width(N)`** raises a definition's starting
  `"min-legal-vector-width"` to N (clang `StartFunction`).

## 1:1 intrinsics

`crates/kiln_codegen/src/x86_intrinsics.rs` (generated by
`scripts/gen-x86-builtins.py`) lists the 1,129 builtins clang lowers to
one `llvm.x86.*` call taking the builtin's arguments in order: the
intrinsic, its return and parameter types as LLVM prints them (an
`immarg` parameter marked), and its attributes
(`kiln_llvm::intrinsics::TargetMem`: `memory(none)`, `memory(read)`,
`memory(argmem: read)`, `memory(argmem: readwrite)`, `nounwind`, and
`nounwind` with `memory(argmem: readwrite)` / `memory(inaccessiblemem:
readwrite)`). The script finds them by calling each builtin from a
wrapper with its features, twice with different immediates, and reading
clang's IR after `opt -passes=mem2reg`: a body of loads, bitcasts, one
`llvm.x86.*` call with the arguments in order (immediates as the
constants passed) and a store is 1:1.

The table is plain data (WP-660, spec/landed/codegen/WP-660.md "Layout"):
a string blob and 24-byte integer rows sorted by builtin name;
`x86::by_name` binary-searches them and returns the row (`Map`) by value.
`--reemit` rewrites the file from its own rows without clang.

`x86_mapped` emits clang's generic `ClangBuiltin` lowering: every
argument, an integer constant one as a constant of the intrinsic's
parameter type; each bitcast to the intrinsic's parameter type when it
differs (equal widths); the call; the result bitcast to the builtin's
type.

## Custom lowering (clang `EmitX86BuiltinExpr`)

| Builtins | Lowering |
|---|---|
| `cmp{eq,lt,le,unord,neq,nlt,nle,ord}{ps,pd}` | `fcmp oeq/olt/ole/uno/une/uge/ugt/ord`, `sext` to the same-width integer vector, `bitcast` back |
| `cmp<cc>{ss,sd}` | `llvm.x86.sse.cmp.ss` / `llvm.x86.sse2.cmp.sd` with the condition (0 to 7) as the `i8` immediate |
| `cmpps`, `cmppd` (and `256`) | `fcmp` of the immediate's low four bits (`oeq olt ole uno une uge ugt ord ueq ult ule false one oge ogt true`), as above |
| `sqrtps`, `sqrtpd` (and `256`) | `llvm.sqrt` |
| `sqrtss`, `sqrtsd` | element 0, `llvm.sqrt`, inserted back |
| `shufps`, `shufpd` (and `256`) | `shufflevector` of both, the immediate repeated per 128-bit lane |
| `pshufd`, `pshuflw`, `pshufhw` (and `256`) | `shufflevector` with `poison` |
| `pslldqi128_byteshift`, `psrldqi128_byteshift` (and `256`) | byte `shufflevector` with zero per lane; zero above 15 |
| `palignr128` (and `256`) | byte `shufflevector` of the second then the first operand; zero shifted in past 16, zero past 31 |
| `blendpd`, `blendps`, `pblendw128`, `pblendd128` (and `256`) | `shufflevector` selecting by immediate bit |
| `pmuludq128`, `pmuldq128` (and `256`) | `<N x i64>` operands, `and 0xffffffff` / `shl`+`ashr 32`, `mul` |
| `vec_ext_v*`, `vec_set_v*` | `extractelement` / `insertelement`, index modulo the element count (`i64`) |
| `movnti`, `movnti64`, `movntss`, `movntsd` | an `align 1` store (of element 0 for the vector forms) with `!nontemporal !{i32 1}` |
| `undef128/256/512` | `zeroinitializer` |
| `rdrand*_step`, `rdseed*_step`, `rdtscp` | the `{iN, i32}` intrinsic: the value stored through the pointer, the flag returned (`rdtscp`: the aux stored, the counter returned) |
| `addcarryx_u32/u64`, `subborrow_u32/u64` | `llvm.x86.addcarry.N` / `subborrow.N` (`memory(none)`): the sum stored, the carry returned |
| `lzcnt_u16/32/64`, `tzcnt_*` | `llvm.ctlz` / `llvm.cttz` with `i1 false` |
| `_mm_getcsr` / `stmxcsr`, `_mm_setcsr` / `ldmxcsr` | `llvm.x86.sse.stmxcsr` (`nounwind memory(argmem: write)`) / `ldmxcsr` through an `i32` temporary |
| `__builtin_nontemporal_store` / `_load` | a store / load through the pointer with its known alignment, TBAA as any access, `!nontemporal !{i32 1}` |
| `__builtin_nondeterministic_value` | `freeze poison` (new FIR `Op::Freeze`), the operand not evaluated |

## MMX (`x86_mmx.rs`)

clang 19 lowered its MMX builtins to `x86_mmx` intrinsics, which LLVM 21
no longer has, and clang 20 dropped the builtins, rebuilding the `__m64`
intrinsics of `<mmintrin.h>`, `<xmmintrin.h>`, `<emmintrin.h>` and
`<tmmintrin.h>` on generic vector code and the 128-bit builtins. Each of
clang 19's MMX builtins is emitted as clang 21's header defines the
intrinsic that calls it:

- `padd*`, `psub*`, `pmullw`, `pand`, `por`, `pxor`, `pandn` (`xor -1`
  then `and`): the 64-bit vector operation; `padds*` / `paddus*` /
  `psubs*` / `psubus*`: `llvm.{s,u}{add,sub}.sat`; `pmaxsw`, `pmaxub`,
  `pminsw`, `pminub`: `llvm.{s,u}{max,min}`; `pabs*`: `llvm.abs`;
  `pcmpeq*` / `pcmpgt*`: `icmp eq` / `sgt` and `sext`; `punpck*`:
  `shufflevector`; `vec_init_v*`: `insertelement`s into `poison`;
  `pshufw`: `shufflevector` with a zero vector; `cvtpi2pd`: `sitofp`;
  `cvtpi2ps`: `sitofp` of the operand zero-extended to 128 bits, lanes 0
  and 1 replacing the first operand's; `movntq`: an `align 8` store with
  `!nontemporal`; `vpopcnt*`: `llvm.ctpop`.
- The rest call the 128-bit builtin (through the 1:1 table, or
  `pmuludq128`'s custom lowering) and keep the low 64 bits (`__trunc64`,
  a `shufflevector` to `<1 x i64>`), on operands widened as clang 21
  does: `__anyext128` (`<2 x i32>` to `<4 x i32>`, upper lanes poison)
  for `pmulhw`, `pmaddwd`, `pmulhuw`, `pavgb`, `pavgw`, `pmaddubsw`,
  `pmulhrsw`, `psign*`, `pmuludq` and the shifts (the `*i` forms keep a
  scalar count); `__zext128` for `psadbw` and `pmovmskb` (no truncation);
  the two operands concatenated with a zero second operand for `packss*`,
  `packuswb`, `phadd*`, `phsub*`; `pshufb` repeats the first operand in
  both halves; `palignr` shifts `b` then `a` right with
  `psrldqi128_byteshift`; `cvt(t)ps2pi` zero the upper half first
  (`__zeroupper64`), `cvt(t)pd2pi` take `cvt(t)pd2dq`'s low half.

`maskmovq` (clang 21 branches on the page offset) stays unsupported.

## Other builtins

Every other x86 builtin is the error "code generation for `<name>` is
not supported yet" when emitted (mostly AVX-512 and newer families with
custom lowerings: masked loads and stores, compress / expand, gathers
and scatters, mask registers, rounding-control forms with the default
rounding, `vpermil*`, `vperm2f128`, `vinsertf128`, ...). A declaration,
or an unused inline header function, is never emitted.

An x86 builtin with a pointer operand is not a fold candidate
(`is_fold_candidate`): the Oven evaluates `addcarryx`, whose store must
stay. The integer constant operands of an x86 builtin are fold
candidates (`folded_arg`), so the immediates are constants however they
are spelled.
