# WP-630 — x86 target builtins: codegen

The x86-64 half of clang's `checkTargetFeatures`, and the lowering of the
x86 builtins (`crates/kiln_codegen/src/x86.rs`). The declarations are
spec/landed/sema/WP-630.md; the `-march=` and `target("...")` feature
maps spec/landed/driver/WP-630.md.

## Target features

- **Feature map** (`target_features.rs` `x86_feature_map`, clang
  `getFunctionFeatureMap`): the `-march=` CPU's features
  (`CodegenOptions::target_features`, `+name` each; empty: `x86-64`'s
  `cmov cx8 fxsr mmx sse sse2 x87`), then the map the driver's x86 parser
  gives for the function's `target("...")` attribute
  (`CodegenOptions::target_attr`). A `target("arch=<cpu>")` replaces the
  module's features by that CPU's.
- **Attributes** (`module.rs` `target_attrs_of`): `"target-features"`
  prints the map (enabled features sorted, then disabled ones sorted), as
  clang. `"target-cpu"` is the attribute's `arch=` CPU, else `-march=`'s,
  else `x86-64`; `"tune-cpu"` is the attribute's `tune=` CPU, else
  `-mtune=`'s, else `generic` unless a CPU was named.
- **Builtin calls** (`x86_builtin_features_ok`): the row's
  required-features string must hold for the caller's map, else
  `cg_builtin_needs_feature` ("'%0' needs target feature %1", the whole
  string) at the call's start, and the call's value is poison. An SSE
  compare (`cmpps`, `cmppd`, `cmpss`, `cmpsd`) whose predicate is above 7
  needs `avx` instead (clang's special case).
- **`always_inline` calls**: WP-558's `target_feature_call_check` now runs
  on x86-64 too, so calling a header intrinsic (`always_inline`,
  `target("crc32")`) from a function without the feature is clang's
  "always_inline function '_mm_crc32_u8' requires target feature 'crc32',
  but would be inlined into function 'f' that is compiled without
  support for 'crc32'".
- **`min_vector_width(N)`** raises a definition's starting
  `"min-legal-vector-width"` to N (clang `StartFunction`).

## 1:1 intrinsics

`crates/kiln_codegen/src/x86_intrinsics.rs` (generated by
`scripts/gen-x86-builtins.py`) lists the 1,129 builtins clang lowers to
one `llvm.x86.*` call taking the builtin's arguments in order: the
intrinsic, its return and parameter types as LLVM prints them (an
`immarg` parameter marked), and its attributes
(`kiln_llvm::intrinsics::TargetMem`: `memory(none)`, `memory(read)`,
`memory(argmem: read)`, `memory(argmem: readwrite)`, `nounwind`, and
`nounwind` with `memory(argmem: readwrite)` / `memory(inaccessiblemem:
readwrite)`). The script finds them by calling each builtin from a
wrapper with its features, twice with different immediates, and reading
clang's IR after `opt -passes=mem2reg`: a body of loads, bitcasts, one
`llvm.x86.*` call with the arguments in order (immediates as the
constants passed) and a store is 1:1.

The table is plain data (WP-660, spec/landed/codegen/WP-660.md "Layout"):
a string blob and 24-byte integer rows sorted by builtin name;
`x86::by_name` binary-searches them and returns the row (`Map`) by value.
`--reemit` rewrites the file from its own rows without clang.

`x86_mapped` emits clang's generic `ClangBuiltin` lowering: every
argument, an integer constant one as a constant of the intrinsic's
parameter type; each bitcast to the intrinsic's parameter type when it
differs (equal widths); the call; the result bitcast to the builtin's
type.

## Generic x86 lowering (`x86_gen.rs`, WP-1242)

The builtins clang's `EmitX86BuiltinExpr` lowers to generic IR, or to an
intrinsic with a changed operand list, are grouped into families
(`x86_gen.rs` `family`), each lowered as clang 19 and 22 do (they agree
on every one): the operands are emitted first, in order, an integer
constant one as a constant of its parameter type, then the family's IR.

| Builtins | Lowering |
|---|---|
| `extract128i256`, `vextractf128_{ps,pd,si}256`, `extract{f,i}*_mask` | `shufflevector` of the subvector the immediate (modulo the subvector count) names; the masked forms then `select` with the passthrough |
| `insert128i256`, `vinsertf128_*`, `insert{f,i}*` | a widening `shufflevector` of the subvector (`poison` lanes), then a `shufflevector` taking it into the lanes the immediate names |
| `permti256`, `vperm2f128_*` | `shufflevector` of `a` and `b`: each 128-bit half the source half its nibble's bits 0-1 select, a `zeroinitializer` operand for a half whose bit 3 is set |
| `vcvtph2ps`, `vcvtph2ps256`, `vcvtph2ps*_mask` | the `<8 x i16>` operand (its low four lanes shuffled out for the 128-bit form) `bitcast` to `half` and `fpext` to float; the 512-bit form with a rounding other than 4 `llvm.x86.avx512.mask.vcvtph2ps.512` |
| `vfmadd{ps,pd,ph}{,256}`, `vfmadd*512_mask{,z,3}`, `vfmsub*512_mask3`, `vfmaddsub*512_*`, `vfmsubadd*512_mask3` | `llvm.fma.*`; a 512-bit form with a rounding other than 4, and every 512-bit add-sub, `llvm.x86.avx512{,fp16}.vfmadd{,sub}.{ps,pd,ph}.512`; `vfmsub*` an `fneg` of `c`; then the mask `select` (the 128/256-bit `vfmaddsub*` are 1:1 `llvm.x86.fma.vfmaddsub.*`) |
| `vfmadd{ss,sd}3`, `vf{madd,msub}{ss,sd,sh}3_mask{,z,3}`, FMA4 `vfmadd{ss,sd}` | `llvm.fma` of lane 0 (`llvm.x86.avx512.vfmadd.f32`/`f64` for a rounding other than 4), inserted into the first operand (FMA4: into a zero vector; masked: a scalar `select` on mask bit 0) |
| `k{and,andn,or,xnor,xor,not,mov,unpck,shiftli,shiftri,ortestc,ortestz}{qi,hi,si,di}` | the `iN` mask `bitcast` to `<N x i1>` and the bit operation (`kunpck`: low halves concatenated by `shufflevector`, `kortest`: `icmp` of the `or`) |
| `{,u}cmp{b,w,d,q}*_mask`, `cmp{ph,ps,pd}*_mask` | `icmp` / `fcmp` of the predicate the immediate names (`false`/`true` constants), the `<N x i1>` `and` the mask, widened to 8 lanes and `bitcast` to the integer mask |
| `vpcom{,u}{b,w,d,q}` (XOP) | `icmp` of the predicate the immediate's low three bits name and `sext` (6: zero, 7: all ones) |
| `select{b,w,d,q,ph,pbf,ps,pd}_*`, `select{sh,ss,sd}_128` | `select` on the `bitcast` mask (scalar: lane 0 on mask bit 0) |
| `pternlog{d,q}*_mask{,z}` | `llvm.x86.avx512.pternlog.*` and a `select` with `a` (zero for `maskz`) |
| `loadu*_mask`, `loada*_mask`, `loaddqu*_mask`, `load{sh,ss,sd}128_mask`, `movdqa{32,64}load*_mask`, and the stores | `llvm.masked.load` / `llvm.masked.store`, the alignment 1 (unaligned) or the vector type's (aligned); clang 22 puts it in a call-site `align` attribute, clang 19 in an `i32` operand |

| `gather3{div,siv}*`, `scatter{div,siv}*` (AVX-512VL) | `llvm.x86.avx512.mask.gather3*` / `scatter*` with the mask a `<N x i1>` of the fewer of the data and index lanes |
| `reduce_f{add,mul,max,min}_*` | `llvm.vector.reduce.f{add,mul}` with `reassoc` (the start value first), `f{max,min}` with `nnan` |
| `vprot*` (XOP), `prol{,v}{d,q}*`, `pror{,v}{d,q}*`, `vpsh{l,r}d{,v}{w,d,q}*` | `llvm.fshl` / `llvm.fshr` (a rotate: both operands the source) |
| `vplzcnt*`, `sqrt{ph,ps,pd}512`, `sqrt{sh,ss,sd}_round_mask` | `llvm.ctlz` / `llvm.sqrt` (rounding other than 4: the `llvm.x86.avx512` intrinsic) |
| `{,v}cvt{,u}{dq,qq,w}2{ps,pd,ph}512_mask` | `sitofp` / `uitofp` (rounding other than 4: the intrinsic), then the mask `select` |

| `vpermil{pd,ps}{,256,512}`, `permd{f,i}{256,512}`, `align{d,q}*`, `shuf_{f,i}{32x4,64x2}{,_256}` | `shufflevector` with clang's index arithmetic |
| `fpclass*_mask`, `vp2intersect_*`, `vpshufbitqmb*`, `cvtneps2bf16_*`, `cvtsbf162ss_32`, `vf{c}maddc*`, `xsave*`/`xrstor*`/`xsetbv`, `prefetchi` | clang's intrinsic and its `<N x i1>` / split-operand calling convention |

**Required vector width.** As clang's `getRequiredVectorWidth`, a call of
an x86 builtin raises the calling function's `"min-legal-vector-width"`
to the widest vector in the builtin's prototype (pointees included;
`x86_gen.rs` `required_width`), with clang's exceptions: the MMX
`cvt{,t}{pd,ps}2pi` / `cvtpi2{pd,ps}` 64, `pblendd128` / `vpermilvar{pd,ps}`
256, `extract128i256` 256 at `-fclang-compat=19` and 128 at 22, the AMX
`*_internal` 0. Without it a 512-bit target intrinsic in a function
compiled for a CPU that prefers 256-bit vectors (`-march=skylake-avx512`)
is split and the backend aborts.

**Unlowered.** `maskmovq` (clang 21 branches on the page offset), the
Key Locker `aes{enc,dec}{,wide}{128,256}kl_u8` / `encodekey{128,256}_u32`
(an aggregate return) and the AMX `t*_internal` tile builtins (the
`x86_amx` type) are in `UNLOWERED_BUILTINS`, so `__has_builtin` answers 0
for them; crates/kiln_driver/tests/builtin_lowering.rs compiles every
other declared x86 builtin under every feature and keeps that list exact.

## MMX (`x86_mmx.rs`)

clang 19 lowered its MMX builtins to `x86_mmx` intrinsics, which LLVM 21
no longer has, and clang 20 dropped the builtins, rebuilding the `__m64`
intrinsics of `<mmintrin.h>`, `<xmmintrin.h>`, `<emmintrin.h>` and
`<tmmintrin.h>` on generic vector code and the 128-bit builtins. Each of
clang 19's MMX builtins is emitted as clang 21's header defines the
intrinsic that calls it:

- `padd*`, `psub*`, `pmullw`, `pand`, `por`, `pxor`, `pandn` (`xor -1`
  then `and`): the 64-bit vector operation; `padds*` / `paddus*` /
  `psubs*` / `psubus*`: `llvm.{s,u}{add,sub}.sat`; `pmaxsw`, `pmaxub`,
  `pminsw`, `pminub`: `llvm.{s,u}{max,min}`; `pabs*`: `llvm.abs`;
  `pcmpeq*` / `pcmpgt*`: `icmp eq` / `sgt` and `sext`; `punpck*`:
  `shufflevector`; `vec_init_v*`: `insertelement`s into `poison`;
  `pshufw`: `shufflevector` with a zero vector; `cvtpi2pd`: `sitofp`;
  `cvtpi2ps`: `sitofp` of the operand zero-extended to 128 bits, lanes 0
  and 1 replacing the first operand's; `movntq`: an `align 8` store with
  `!nontemporal`; `vpopcnt*`: `llvm.ctpop`.
- The rest call the 128-bit builtin (through the 1:1 table, or
  `pmuludq128`'s custom lowering) and keep the low 64 bits (`__trunc64`,
  a `shufflevector` to `<1 x i64>`), on operands widened as clang 21
  does: `__anyext128` (`<2 x i32>` to `<4 x i32>`, upper lanes poison)
  for `pmulhw`, `pmaddwd`, `pmulhuw`, `pavgb`, `pavgw`, `pmaddubsw`,
  `pmulhrsw`, `psign*`, `pmuludq` and the shifts (the `*i` forms keep a
  scalar count); `__zext128` for `psadbw` and `pmovmskb` (no truncation);
  the two operands concatenated with a zero second operand for `packss*`,
  `packuswb`, `phadd*`, `phsub*`; `pshufb` repeats the first operand in
  both halves; `palignr` shifts `b` then `a` right with
  `psrldqi128_byteshift`; `cvt(t)ps2pi` zero the upper half first
  (`__zeroupper64`), `cvt(t)pd2pi` take `cvt(t)pd2dq`'s low half.

`maskmovq` (clang 21 branches on the page offset) stays unsupported.

## Other builtins

Every declared x86 builtin is lowered (above) except the unlowered ones
of "Generic x86 lowering", which are the error "code generation for
`<name>` is not supported yet" if emitted (`__has_builtin` is 0 for
them). A declaration, or an unused inline header function, is never
emitted.

An x86 builtin with a pointer operand is not a fold candidate
(`is_fold_candidate`): the Oven evaluates `addcarryx`, whose store must
stay. The integer constant operands of an x86 builtin are fold
candidates (`folded_arg`), so the immediates are constants however they
are spelled.

## Verification

Against clang 21 (`-S -emit-llvm -O0`, modules equal after dropping
comments and the producer): builtin calls, `target("sse4.2")`, and the
`target-features` of 25 `target("...")` strings under four `-march=`
values. Run tests compared with clang 21's output. The generic x86
lowering (WP-1242) against clang 19 and clang 22.1 (`-O0 -emit-llvm
--target=x86_64-linux-gnu`, every feature on): one wrapper function per
declared builtin, the function bodies equal, and each wrapper's
`"min-legal-vector-width"` equal to clang's.
