# WP-675 — sanitizers (`-fsanitize=`)

`-fsanitize=` builds a sanitized program as clang 19 does. The driver
reads the sanitizer options with clang's grammar, groups, defaults and
errors (spec/driver.md "Sanitizers"). Codegen marks the IR as clang's
frontend does (spec/codegen.md §5.2). The driver runs clang's pass
pipeline for the pass sanitizers, and the linking `clang++` picks the
runtime. The design and the clang inventory are in
docs/design/sanitizers.md.

## Standard

The standard does not mention sanitizers. They diagnose undefined
behavior ([defns.undefined]) at run time. The contract is clang 19's
(`SanitizerArgs`, `CodeGenFunction::EmitCheck`, `CGExprScalar`'s
`EmitOverflowCheckedBinOp`/`EmitShl`/`EmitShr`/`EmitUndefinedBehaviorIntegerDivAndRemCheck`,
`SetLLVMFunctionAttributesForDefinition`, `SanitizerMetadata`,
`BackendUtil`'s `addSanitizers`). At `-fclang-compat=22` the clang 22
deltas apply (below).

## Driver

- Lists: `-f[no-]sanitize=`, `-f[no-]sanitize-recover[=]`,
  `-f[no-]sanitize-trap[=]`, `-f[no-]sanitize-undefined-trap-on-error`,
  read left to right with clang's group expansion and silent drops.
  Diagnostics use clang 19's wording. The incompatible pairs are checked
  in clang's order, and each side is printed as the argument that last
  enabled it.
- Implemented sanitizers (`SanitizerSet::KILN_SUPPORTED`,
  `crates/kiln_ast/src/sanitize.rs`): address, hwaddress, thread,
  memory, leak, fuzzer, fuzzer-no-link, `undefined`,
  unsigned-integer-overflow and unsigned-shift-base. Any other is
  `'-fsanitize=<x>' is not supported by kiln`.
- Pass pipeline: `asan<>`, `hwasan<>`, `tsan`/`tsan-module`, `msan<>`
  at clang's extension points, at every `-O` level, with clang's
  `cl::opt` flags (use-after-scope, use-after-return, recover,
  track-origins).
- Link: `-fsanitize=<enabled>` (plus `-shared-libsan`/`-static-libsan`)
  is passed on to the linking `clang++`. When only trap-mode UB checks
  are on, no runtime is linked.
- `__has_feature(*_sanitizer)` follows the set. From
  `-fclang-compat=22`, `__SANITIZE_ADDRESS__`, `__SANITIZE_THREAD__` and
  `__SANITIZE_HWADDRESS__` are predefined as well.

## Attributes (sema and codegen)

- `no_sanitize("...")`, `no_sanitize_address`,
  `no_address_safety_analysis`, `no_sanitize_thread` and
  `no_sanitize_memory` attach a sanitizer mask (spec/sema.md). It
  removes the matching `sanitize_*` function attribute, or adds the
  global `no_sanitize_address`/`no_sanitize_hwaddress` marker.
- `disable_sanitizer_instrumentation` drops every `sanitize_*`.
- Definitions get `sanitize_address`, `sanitize_hwaddress`,
  `sanitize_thread`, `sanitize_memory`, and `optforfuzzing` under
  fuzzer.
- Dynamically initialized globals get `sanitize_address_dyninit`.
- Lifetime markers are emitted at `-O0` under ASan (use-after-scope) and
  HWASan. TBAA is emitted under TSan.

## UBSan checks (`crates/kiln_codegen/src/ubsan.rs`)

Each check below follows docs/design/sanitizers.md §1.4.

- **signed-integer-overflow**: `+`, `-`, `*`, unary `-`, `++`/`--`, and
  compound assignment. The check uses `@llvm.s{add,sub,mul}.with.overflow`,
  and operands promoted from a narrower type skip it where clang does
  (`isPromotionCheckable`/`CanElideOverflowCheck`). Under `-fwrapv` the
  arithmetic is unchecked unless the check is on.
- **unsigned-integer-overflow**: the same, with the `u*` intrinsics.
- **integer-divide-by-zero**: `/` and `%`. Signed division also checks
  `INT_MIN / -1`, and the two checks share one `divrem_overflow` report.
- **shift-exponent**: the exponent is compared with the width minus one.
- **shift-base**: signed `<<`, only before C++20, guarded by the
  exponent check through a `phi`.
- **unsigned-shift-base**: unsigned `<<`.
- **return**: at the fall-off of a value-returning function, an abort
  call to `missing_return` at the function's name, then `unreachable`.
- **unreachable**: `__builtin_unreachable()` becomes an abort call to
  `builtin_unreachable`.
- **vla-bound**: a VLA bound must be positive, reported by `vla_bound_not_positive`.

Modes:

- In trap mode the check calls `@llvm.ubsantrap(i8 <handler id>)`. The
  trap block is shared per handler, except at `-O0`/`optnone`.
- In recover mode the check calls `@__ubsan_handle_<name>`.
- In abort mode it calls `@__ubsan_handle_<name>_abort`, which is
  `noreturn`.
- Checks of one operation are and-ed per mode, and the modes are emitted
  in order (trap, recover, abort).
- The failure branch has 1048575:1 weights. Every inserted instruction
  carries `!nosanitize !{}`.
- Static data matches clang: `.src` strings, `{ i16 kind, i16 info,
  [N x i8] name }` type descriptors, and per-check data globals.

At `-fclang-compat=22`:

- The trap branch is also weighted.
- `nomerge` is on trap and handler calls at `-O0`/`optnone`, and for
  checks outside the default `-fsanitize-merge=` set. Those are the
  unsigned checks, whose trap blocks are then never shared.
- `@llvm.ubsantrap` has `memory(inaccessiblemem: write)` (LLVM 22).

## Deviations and gaps (follow-ups)

- The UB checks null, alignment, object-size, array-bounds,
  local-bounds, bool, enum, float-cast-overflow, pointer-overflow,
  vptr, function, nonnull-attribute, returns-nonnull-attribute, builtin,
  implicit-conversion and the rest of `integer` are accepted (as members
  of `undefined` or `integer`) but emit no check.
- No checks on atomic `++`/`--` or atomic compound assignment.
- No `_BitInt` type descriptors.
- `.src` strings were always new globals, where clang reuses an
  identical `.str`; fixed by WP-1032, which reuses them as clang does.
- `-ftrapv` and `-fsanitize-merge=` were still rejected; fixed by
  WP-1032.
- Ignorelist files were checked but not applied; fixed by WP-1032
  (string literals and coroutine suspend wrappers by WP-1043).
- kiln emits no local value names, while clang keeps them under ASan and
  MSan. As a result ASan frame descriptors carry empty local names, and
  ASan and MSan cannot be exact IR tests. clang 22 also adds alloca
  `!annotation`s there.
- `opt` reads the module from stdin, so ASan's module name is `<stdin>`
  where clang has the source file.
- The ASan/TSan module constructors lack clang's `"target-cpu"` and
  `"target-features"`.
- Recover-mode run tests need compiler-rt and a `requires:
  sanitizer-runtime` harness capability. CI must also install
  `libclang-rt-19-dev` and `libclang-rt-22-dev`.
