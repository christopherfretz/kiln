# WP-809 — no silent drops, part 5: musttail, transparent_union, selectany, ms_struct, address_space, `[[clang::]]` vector spellings, mode

Before this package kiln dropped these attributes (or mis-applied them)
with no diagnostic. Each now has clang's semantics and diagnostics, or is
a hard error. Sources: clang's `AttrDocs`
(`clang/include/clang/Basic/AttrDocs.td`: "musttail",
"transparent_union", "selectany", "ms_struct", "address_space",
"neon_vector_type") and GCC's "Common Type Attributes", "Common Variable
Attributes" and "x86 Type Attributes" pages; clang 19.1.7 and 22.1.8 are
the oracles.

## Semantics

- **`[[clang::musttail]]` / `__attribute__((musttail))`** on a `return`
  statement (`crates/kiln_sema/src/musttail.rs`; clang
  `checkAndRewriteMustTailAttr`, `checkMustTailAttr`):
  - The operand must be a call (after implicit conversions, no
    non-trivial temporaries); caller and callee must agree on member
    kind (static, non-static, pointer to member), structors are
    rejected, and calling convention, variadic-ness and the signature
    must match (clang's notes name the mismatch). A failed check drops
    the attribute after the error.
  - The scopes the return leaves must have no destructors, `try` or
    `cleanup` (the jump-scope pass, `jump_scope.rs`).
  - A dependent return is checked again at instantiation.
  - Lowered as `musttail call` followed directly by `ret` on every
    path (direct, member, virtual, pointer-to-member, `sret`, `byval`).
  - Any other statement attribute that does not apply to a statement now
    gets its subject error instead of being dropped.
- **`transparent_union`** (`transparent_union.rs`): C-only, so clang
  ignores it in C++ with `'transparent_union' attribute ignored`. clang's
  delayed class-head handler still checks the subject (a non-template
  union), the definition and the fields (no floating or vector first
  field; same size, no larger alignment), and keeps the attribute when
  they pass. A kept union is passed by value as its first field
  (`kiln_abi::call`, clang `useFirstFieldIfTransparentUnion`). No
  argument conversions are made in C++, as in clang.
- **`selectany`** (GNU; `selectany.rs`): external-linkage variables only
  (an error on functions and internal or no-linkage variables), no
  arguments, ignored with a warning when added after the definition.
  The variable is `weak_odr` in its own comdat (clang; not
  `linkonce_odr`), dynamically initialized unordered with a comdat
  guard; a `selectany` or weak `thread_local` is accessed through its TLS
  wrapper. Hard error: `selectany` on an `extern` declaration without an
  initializer (clang makes it a zero-initialized definition).
- **`ms_struct` / `gcc_struct` / `#pragma ms_struct`** (`ms_struct.rs`,
  `kiln_abi::layout`): the Microsoft bit-field rules within the Itanium
  layout (clang `IsMsStruct`): a bit-field starts a new storage unit when
  its type's size differs from the previous one's, a zero-width
  bit-field only matters after a bit-field, and the IR uses one storage
  unit per run (`isDiscreteBitFieldABI`). The attribute is inherited
  from a forward declaration; `#pragma ms_struct on` marks each class
  definition begun while it is on. clang 22's `gcc_struct` asks for the
  default layout and overrides both; the two on one declaration
  conflict. Diagnostics: an overwide bit-field (`width of bit-field ...
  exceeds the width of its type`), bases or virtual functions
  (`ms_struct may not produce Microsoft-compatible layouts ...`, an
  error by default), an attribute after the definition. clang's
  power-of-two builtin-alignment rule is skipped (a no-op on LP64).
- **`address_space(N)`** (GNU and `[[clang::]]`): not implemented. Both
  spellings are the error `the 'address_space' attribute is not
  supported yet` (they were an unknown attribute, silently dropped).
  The qualifier, its overloading and conversions, `U3AS<N>` mangling and
  `ptr addrspace(N)` are a follow-up (xfail repro
  `ext.clang.address_space/address-space-run.cpp`).
  `__has_attribute(address_space)` still reports clang's 1 (the
  generated feature table).
- **`[[clang::neon_vector_type(N)]]`, `[[clang::neon_polyvector_type(N)]]`,
  `[[clang::ext_vector_type(N)]]`** (`vector.rs`, `decl_attrs.rs`): routed
  to the GNU implementations. `ext_vector_type` has its `[[clang::]]`
  spelling only from clang 22 (an unknown attribute at
  `-fclang-compat=19`). In type position (after the decl-specifiers)
  they modify the type; in a declarator chunk the NEON ones are `'X'
  attribute cannot be applied to types`. Written after a declarator (or
  leading a declaration) clang slides them onto the declared type and
  still applies them: on a typedef with `'X' attribute cannot be applied
  to a declaration`, elsewhere with -Wdeprecated-attributes `applying
  attribute 'X' to a declaration is deprecated; apply it to the type
  instead`; nothing when the vector could not be built. clang 22
  applies `ext_vector_type` there silently. An alias-declaration's
  type-id attributes are type attributes, its own (after the name)
  declaration attributes.
- **`mode`** (`vector.rs`, `templ/subst/decls.rs`):
  - On a function parameter of dependent type it stays on the parameter
    and applies to the substituted type (pack elements included); the
    instantiated function type is built from those parameters (clang
    `instantiateDependentModeAttr`). A mismatch is a substitution
    failure. This was a hard error (WP-807).
  - In a type-id that declares nothing it is dropped, as clang drops it
    (kiln applied it: `sizeof(char __attribute__((mode(DI))))` was 8,
    clang 1). clang `ActOnTypeName`'s warning `'mode' attribute ignored
    when parsing type` (-Wignored-attributes) is given for `sizeof`,
    `alignof`, C-style casts, template arguments and trailing return
    types; a named cast, a new-type-id and an alias-declaration's type-id
    drop it silently.

## Follow-ups

- `address_space(N)`: the type qualifier (ExtQual), overloading,
  conversions, `U3AS<N>` mangling and `ptr addrspace(N)`.
- `float * [[clang::neon_vector_type(4)]] p;` (a declarator chunk) is an
  error with other wording than clang's `invalid vector element type
  'float *'`.
- A class attribute such as `packed` added after the definition is
  accepted silently (clang warns `must precede definition`; kiln does so
  only for `ms_struct` / `gcc_struct`).
- A dependent-width bit-field in an `ms_struct` class template is not
  checked for overwidth at instantiation.
