# WP-1073 — library-builtin attributes and inline lowering of library calls

Each function was compared with clang 19 and 22 first: the declaration
and call-site attributes, the `-O0` IR, the warnings, `-Wformat`, and
`__builtin_object_size`. Only the real differences were changed. The
rules are in spec/sema.md "Library functions", spec/codegen.md §3
("library builtins") and §3.1, and spec/oven.md "Builtins".

## Differences found

| function | before | after |
|---|---|---|
| `setjmp`, `_setjmp`, `sigsetjmp`, `__sigsetjmp`, `savectx`, `vfork`, `getcontext` | already clang's: `returns_twice` on both the declaration and the call (WP-807, `builtins::returns_twice`) | unchanged; a run test with a modified local pins it |
| `abort` | already clang's: `noreturn nounwind`, a `call` even under a pending cleanup (WP-938) | unchanged |
| `malloc`, `calloc`, `realloc`, `aligned_alloc` | the IR `allocsize` / `align` were already clang's (codegen matched them by name); no sema attribute, so `__builtin_object_size` of the result was the unknown value | sema adds the implicit `alloc_size` / `alloc_align`; codegen reads them; the Oven folds the object size |
| `memalign` (GNU) | no attributes | `allocsize(1)`, `alloc_align` |
| `scanf`, `fscanf`, `sscanf`, `vscanf`, `vfscanf`, `vsscanf` | no implicit `format`; a written `format(scanf)` was accepted but never checked | implicit `format(scanf, F, A)` and clang's scanf `-Wformat` rules |
| `alloca` (GNU) | a call of `alloca` | a dynamic `alloca` aligned to `__BIGGEST_ALIGNMENT__` |
| `bzero`, `bcopy` (GNU) | calls | `llvm.memset` of 0, and `llvm.memmove` with the operands swapped |
| `mempcpy` (GNU) | a call | `llvm.memcpy` plus the end pointer |
| `finite{,f,l}` (GNU), `__finite{,f,l}` | calls | `__builtin_isfinite` |
| `creal`, `cimag`, `conj` `{,f,l}` | calls | the operand's parts (`conj` negates the imaginary part); `__builtin_creal` ... added |

Under `-std=c++*` the GNU-only rows are ordinary calls, as in clang
(`tests/codegen/lib_gnu_inline_std.cpp`).

## Not done (follow-ups)

- `-Wfortify-source`, which clang drives from the `alloc_size` object
  size.
- These scanf forms are not modelled:
  - `%l[` and `%ls` with wide pointees;
  - `%C` / `%S`;
  - a zero field width;
  - an unclosed `%[`;
  - the length-modifier undefined-behaviour warnings.
- `__builtin_malloc`, `__builtin_calloc`, `__builtin_realloc`,
  `__builtin_fscanf` and `__builtin_vfscanf`.
- The allocsize fold only reads constant sizes from literals,
  `constexpr` variables, `sizeof` and arithmetic on those. It does not
  handle `&p[3]` bases, and it does not handle member-call allocators.
