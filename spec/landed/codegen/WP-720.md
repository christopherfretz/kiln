# WP-720 — leveldb 1.23 with kiln++: -fno-rtti codegen

WP-720 built google/leveldb 1.23 with kiln++ through its own CMake build
and CTest suite (M8 wave 3, docs/status/oss/leveldb.md). leveldb builds
with `-fno-exceptions -fno-rtti`. The kiln build itself was clean, but a
mixed link (kiln objects against clang's `-fno-rtti` `libleveldb.a`)
failed with undefined `typeinfo for leveldb::Comparator` and friends:
kiln parsed `-fno-rtti` (sema rejected `typeid` / `dynamic_cast`) but
codegen still emitted RTTI as if it were on. The rule below is also
stated in spec/codegen.md "RTTI" and spec/driver.md (`-f[no-]rtti`).

- **Under `-fno-rtti` (`CodegenOptions::rtti` false) the RTTI slot of
  every vtable and construction vtable is null** (clang
  `GetAddrOfRTTIDescriptor` returns null when `!getLangOpts().RTTI` and
  the use is not for EH; `Cg::rtti_descriptor`,
  `crates/kiln_codegen/src/vtable.rs`). Vtables therefore never
  reference a `_ZTI` symbol, keyed or not.
- **Exception handling still needs `type_info`** ([except.throw]/2,
  [except.handle]/3): a `throw` expression's `__cxa_throw` argument and
  every typed handler's landing-pad clause keep their `_ZTI` object.
  For a class type with external linkage that object is defined
  `linkonce_odr` in the TU that needs it, even if the class is dynamic
  with an out-of-line key function (clang `ShouldUseExternalRTTIDescriptor`
  is false and `getTypeInfoLinkage` gives `LinkOnceODRLinkage` when
  `!RTTI`); its base-class `type_info` objects follow the same rule.
  Fundamental types still use the runtime's external `_ZTI` objects;
  internal-linkage and incomplete types are unchanged.
- The `dynamic_cast` and `typeid` lowering, and a constant whose base is
  a `type_info` object, also go through `rtti_descriptor`; sema rejects
  those uses under `-fno-rtti` already, so this only matters for
  constructs sema accepts (none today).

Tests: `tests/conformance/except.handle/ir-fno-rtti-type-info.cpp`
(clang>=22), `tests/conformance/except.handle/ir-fno-rtti-type-info-19.cpp`
(clang<22), `tests/conformance/except.handle/fno-rtti-catch-by-base.cpp`
(run).
