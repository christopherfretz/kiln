# WP-1745 — x86-64 function multiversioning

Before this package every form of function multiversioning clang has on
x86-64 (`target("default")` and differing `target` strings,
`target_clones`, `cpu_dispatch` / `cpu_specific`, and `target_version`
before clang 22) was the hard error "function multiversioning with 'A'
is not supported yet" (GAP-144), and on AArch64 so was a non-default
`target_version` member or friend. kiln now implements clang 22's
multiversioning on x86-64; the AArch64 member and friend case is a
deliberate error with its own wording.

- Sema: spec/sema.md "Function multiversioning" (clang
  `CheckMultiVersionFunction`, `checkTargetClonesAttrString`,
  `isBetterMultiversionCandidate`). The versions are entities of their
  own, the multiversioned property computed from attributes
  (`kiln_ast` `multiversion.rs`): no AST field. The PCH format is 83
  only because the diagnostic id table changed. `attr_triage` reports `target_clones`, `cpu_dispatch` and
  `cpu_specific` as implemented on x86-64 (so `__has_attribute` answers
  clang's 1), `target_version` before clang 22, and an unknown attribute
  from 22.
- Codegen: spec/codegen.md §10 "Function multiversioning" (clang
  `CodeGenModule::emitMultiVersionFunctions`,
  `emitCPUDispatchDefinition`, `GetOrCreateMultiVersionResolver`,
  `CodeGenFunction::EmitX86MultiVersionResolver`). The tables (the
  `__builtin_cpu_supports` feature words and bits, `__builtin_cpu_is`
  fields and values, FMV priorities, the `cpu_specific` processors with
  their mangling letters and feature masks) are clang 22's
  `X86TargetParser.def` / `X86TargetParser.cpp`, in `kiln_abi`
  `x86_fmv.rs`.
- Harness: an IR test's normalization also drops LLVM's
  `; No predecessors!` comment (spec/harness.md "IR tests"), which kiln's
  printer does not write.
- Deviations (docs/status/deviations.md): the AArch64 member or friend
  error (clang 19 and 22 accept and crash on a member's definition);
  kiln does not check a `target` string's features for being known to
  the target, so `target("cmov")` beside a `target("default")` is
  "function multiversioning doesn't support feature 'cmov'" where clang
  warns that the attribute is ignored and then rejects the declaration
  as missing its `target` attribute.
- Not done: ODR metadata rows for the versions, resolvers and ifuncs
  (none are written); `target` after a definition is not "attribute
  declaration must precede definition" (clang warns on every target).
- Tests: `tests/conformance/ext.multiversion/x86-target-ir.cpp`,
  `x86-target-clones-ir.cpp`, `x86-cpu-dispatch-ir.cpp`,
  `x86-multiversion-misc-ir.cpp`, `x86-multiversion-errors.cpp` and its
  valid twin `x86-multiversion-valid.cpp`,
  `x86-multiversion-after-use{,-19}.cpp`,
  `x86-target-clones-list{,-19}.cpp`, `x86-target-version{,-19}.cpp`,
  the run test `x86-multiversion-run.cpp` (`requires: target-x86_64`),
  `target-clones-x86.cpp` (no longer an xfail),
  `aarch64-target-version-member-hidden.cpp`; `kiln_driver` tests
  `codegen` `multiversion_x86_and_hidden_members` and `mason_defs`
  `decided_forms`.
