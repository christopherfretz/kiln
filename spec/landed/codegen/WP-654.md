# WP-654 — Textual IR printer cost and FxHash in kiln_llvm

The contract is spec/llvm.md §1 (dependencies) and §7 (printing). This
file records where the change lives and the tests. Numbers are in
docs/status/perf-reflection.md "WP-654: IR printer".

- **Problem.** `Module` printing wrote through `&mut dyn fmt::Write`,
  reached via `Display`/`to_string`, so each character paid two dynamic
  calls (`write_char` was 101 M Ir on `accessor-wide-emit`). Every type
  and attribute set was re-printed at each use, and every global name was
  re-scanned for quoting at each use. Integers went through `write!`.
  kiln_llvm's interning tables used std `HashMap` with SipHash13 (1.0% to
  3.6% of the frontend shapes).
- **Fix.**
  - `crates/kiln_llvm/src/print.rs`:
    - The printer writes whole tokens into one concrete `String`.
      `Module::to_text` pre-sizes it from a count hint
      (`text_size_hint`). `Module::print` (io) and `Module::write_to`
      (fmt) flush it in chunks of at least 64 KiB, at global, function
      and metadata-line boundaries. `Display` is `write_to`. The
      `IoAdapter` is gone.
    - Names: a 256-entry table decides quoting. Escaping writes runs of
      verbatim bytes and `\XX` escapes. `write_u64`/`write_i64` are a
      local two-digit itoa.
    - `TextCache`: one arena `String` plus `(offset, len)` spans, filled
      lazily, holds the text of each type and each inline attribute set
      once per printed module.
    - Each global and function carries a `Cell<Quote>`
      (`Plain`/`Quoted`/`Escaped`), set at first use.
  - `crates/kiln_llvm/src/{attr,constant,function,module,types}.rs`:
    every `HashMap`/`HashSet` is `kiln_source::fx::FxHashMap`/`FxHashSet`.
    None is iterated, so the printed order cannot change.
    `crates/kiln_llvm/Cargo.toml` depends on `kiln_source`. No external
    dependency is added. kiln_codegen already used Fx.
  - `crates/kiln_driver/src/codegen_cmd.rs`: `-emit-llvm` and the
    `opt` pipe take `Module::to_text()`.
- **Unchanged.** The printed bytes: `-S -emit-llvm` output is identical
  to main (6f8937391) on every corpus program and bench entry compared.
- **Not done.** No bitcode writer. The parse saving it would buy is
  0.35% of the `-c -O2` wall on the bench shapes (NO-GO; numbers in the
  report).
- **Tests.** `print.rs` unit tests:
  - `integers_match_display`: `write_u64`/`write_i64` against `Display`
    on 0..20000 and the edge values.
  - `escaping_writes_runs_and_escapes`: names that need quoting or
    escaping, and string escapes.
  - `every_entry_point_prints_the_same_text`: a module of 10,000 globals
    (several chunks) gives the same bytes from `to_text`, `to_string`,
    `write_to` and `print`. Its globals `a$b`, `a"b`, `0x` and `plain`,
    with users, pin the three quoting states.
  The IR goldens (`//@ expect: ir`), `ir_vs_clang` and the emit-llvm
  corpus pin the rest.
