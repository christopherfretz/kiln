# WP-1032 — UBSan completion

Bundles WP-855 (`.src` string reuse), WP-856 (`-ftrapv` and
`-fsanitize-merge=`) and WP-857 (applying `-fsanitize-ignorelist=`),
the three WP-675 follow-ups left open after WP-871. The contract is in
spec/driver.md "Codegen flags" and "Sanitizers" and spec/codegen.md
§5.2; docs/design/sanitizers.md has the design. This file records what
landed, how it was checked and what remains.

## WP-855: `.src` strings

Nothing to change. Since WP-871, `ub_loc` gets its file name string
from `string_global_named(.., ".src")`, whose cache it shares with
string literals: one private `.src` constant per distinct file name per
TU, reused by a `__FILE__` literal with the same text and the reverse,
named and ordered as clang 19 and 22 emit it. No `ir_vs_clang`
normalisation existed for it, so none was removed. The WP-675 note's
"`.src` strings are always new globals" is stale.
`tests/conformance/driver.sanitize/ubsan-src-sharing-ir.cpp` pins the
sharing (two files, `__FILE__` literals, both orders) against both
oracles.

Measured on a check-heavy TU (200 functions of signed arithmetic,
shifts, divisions, casts and array accesses, `-fsanitize=undefined
-fno-sanitize=function -O0`), with the sharing disabled (a fresh
string per site) against this branch:

| | textual IR | `.src` globals | object |
|---|---|---|---|
| a fresh string per site | 2,192,006 B | 2601 | 695,592 B |
| shared | 1,978,497 B | 2 | 669,608 B |
| change | −213,509 B (−9.7%) | | −25,984 B (−3.7%) |

## WP-856: `-ftrapv`, `-ftrapv-handler=`, `-fsanitize-merge=`

- `-ftrapv` (clang `SOB_Trapping`): signed `+ - *`, negation (as a
  subtraction from 0), `++`/`--` and compound assignment the sanitizer
  does not check use `with.overflow` and a bare `llvm.ubsantrap`
  (`EmitTrapCheck`, ids add 0, sub 21, mul 12); `_Atomic` operands take
  the compare-exchange loop. It beats `-fwrapv`; signed-integer-overflow
  takes precedence where enabled. `-fno-trapv` (GCC's) cancels it.
- `-ftrapv-handler=<name>` with `-ftrapv`: clang's
  `EmitOverflowCheckedBinOp` handler block for every overflow check,
  the sanitizers' included.
- `-f[no-]sanitize-merge[=]` (clang 20+): merge set read like the
  recover list; checks outside it get their own trap block and a
  `nomerge` trap or handler call, as clang 22.

Tests: `trapv-ir.cpp`, `trapv-o2-ir.cpp`, `trapv-ubsan-ir.cpp`,
`trapv-handler-ir.cpp`, `trapv-run.cpp` (the trap fires: a `SIGILL`/
`SIGTRAP` handler exits 3), `ubsan-merge-trap-ir.cpp`,
`ubsan-merge-all-trap-ir.cpp`, `ubsan-nomerge-ir.cpp` (clang 22),
and the driver's flag-spelling and reject-list tests
(`crates/kiln_driver/tests/codegen.rs`). The IR equals clang 19's and
22's.

## WP-857: ignorelists

`kiln_codegen::ignorelist` parses LLVM's special case list format
(sections, globs, categories, LLVM's error text) and answers clang's
`NoSanitizeList` queries; the driver reads the files, adds the resource
directory's `share/{asan,hwasan,msan}_ignorelist.txt` (clang's, now in
`resource/share/` and the dist layout) and reports
`malformed sanitizer ignorelist: '...'` as clang 19. Codegen applies:
- `fun:`/`src:`/`mainfile:` to functions (attributes and UB checks,
  also in outlined and global-initialisation helpers);
- `global:`/`src:`/`mainfile:`/`type:` to globals, `=init` to the
  dynamic-initialisation marker;
- at `-fclang-compat=22`, `type:` to overflow and implicit-conversion
  checks (clang 20+).

Tests: `ignorelist-ubsan-ir.cpp`, `ignorelist-type-ir.cpp` (clang 22),
`ignorelist-ubsan-run.cpp` and `ignorelist-asan-run.cpp` (the UBSan and
ASan runtimes report the unlisted access only), the driver tests
`sanitizer_ignorelist_asan` and `sanitizer_ignorelist_errors` (ASan IR
cannot be an exact test: kiln names no values there), and the
`kiln_codegen::ignorelist` unit tests.

The run tests need compiler-rt, so the harness gained `requires:
sanitizer-runtime` (spec/harness.md): it probes every linking clang and
lifts the address-space cap for the program run, which ASan's shadow
reservation needs. In this container clang 19 has the runtimes and
clang 22 does not, so they run under `KILN_ORACLE=19`.
