# WP-817 — The front-end cost of `-g`

WP-814 measured `-g` adding about +47% to kiln's front end. WP-817 split
that increment, cut the front-end part, and added two bench entries that
track it. Nothing observable changes: the IR text is byte-identical
with and without `-g` (format-test, templates_wide, every
`tests/codegen/debug_*` and `tests/debuginfo` test), and so is every
diagnostic. The commands, all the numbers and the comparison with clang
19 are in docs/status/debuginfo.md, "WP-817: the front-end cost of
`-g`". This WP changes spec/llvm.md §2.6 (the metadata representation)
and spec/driver.md (the `opt` decision scan).

## The split, before and after

Targeted timers in a throw-away instrumented build (`perf_event_open`
is blocked on the dev host; callgrind's inclusive numbers do not survive
thin-LTO inlining). The `-g` increment of kiln's front end
(`-Xclang -disable-llvm-passes -S -emit-llvm`, `-O0`):

| part | format-test before | after | templates_wide before | after |
|---|---|---|---|---|
| building DI in codegen (without interning) | +0.17 s | +0.19 s | +0.125 s | +0.11 s |
| interning and storing metadata (`kiln_llvm`) | 0.11 s | 0.040 s | 0.075 s | 0.05 s |
| printing the IR text and dropping the module | +0.20 s | +0.07 s | +0.13 s | +0.03 s |
| whole front end, user time (medians of 7) | +0.39 s (+17%) | +0.17 s (+7.5%) | +0.31 s (+86%) | +0.14 s (+40%) |
| LLVM: `llvm-as-19` parse / `llc-19 -O0` object | +0.69 / +0.92 s | same | +0.37 / +0.34 s | same |

The instrumented parts are single runs and overlap the timers' own cost,
so they do not add up exactly to the medians. The LLVM rows depend only
on the IR text, which did not change. On format-test's `-S -emit-llvm`
path the driver also runs `opt-19` twice (an `always_inline` module),
which adds about 1.1 s with `-g`; that is the text round trip as well.

Peak RSS with `-g` fell from 250 to 181 MiB (format-test front end), 247
to 206 MiB (format-test `-S -emit-llvm`), and 182 to 117 MiB
(templates_wide). Without `-g` it is unchanged.

The target (front-end increment at most 15%) is met on format-test. On
templates_wide the module grows 13x (1.1 to 14 MB of IR: one global of
the outermost type describes 20,100 class specializations), and what
remains is about 1.2 microseconds for each of the 120,656 nodes, built
and printed. 15% would be 0.05 s, less than printing 14 MB of text.
clang 19's own increment on that TU is +0.18 s user.

## Changes

- **Static names and keys** (`kiln_llvm/src/metadata.rs`).
  `MdNode::Specialized` holds `name: &'static str` and
  `fields: Box<[(&'static str, MdField)]>`. `MdField::Raw` holds a
  `Cow<'static, str>`, so an enumerator such as `DW_TAG_member` or
  `DIFlagPrototyped` is borrowed and only computed text (a
  `DIExpression`, an `extraData` constant) is owned.
  `Module::md_specialized` and `Module::md_set_field` take
  `&'static str` keys. Before, every node allocated its class name and
  each field key as a `Box<str>`, built, hashed, cloned into the
  uniquing map and freed again.
- **Hash-once interning** (`kiln_llvm/src/module.rs` `md_intern`). The
  uniquing index is a `hashbrown::HashTable<(u64, MetadataId)>`. A node
  is hashed once with `md_hash` (FxHash over the same data its `Eq`
  compares). A candidate is compared in place against `md[id]`, and a
  new node is moved into `md` and never cloned into the index. Distinct
  nodes still bypass the index. `md_set_field` and `md_set_operand`
  touch only distinct nodes, and `md_replace` replaces only a distinct
  placeholder, so no indexed hash goes stale. `md_replace` indexes a
  uniqued replacement only when no equal node is indexed, as before.
- **Printer fast paths** (`kiln_llvm/src/print.rs` `md_body`). Node
  names and keys are written with `write_str`, integers with the
  printer's `write_i64`/`write_u64`, and booleans as literals, with no
  `fmt::Arguments` for each field. `TypeFinder::md` reuses one operand
  buffer for the whole walk.
- **Codegen** (`kiln_codegen/src/debuginfo/mod.rs` `Fields`, `types.rs`).
  `Fields` is a `Vec<(&'static str, MdField)>` with room for 12 fields.
  `flags`/`sp_flags` borrow a single flag and join only two or more.
  `di_derived` and `di_basic_node` take static tag and encoding names.
- **Driver** (`kiln_driver/src/codegen_cmd.rs` `code_part`). The scans
  that decide whether `-O0` IR needs `opt` (`always_inline`, coroutine
  intrinsics) stop at the first top-level `!` line: no attribute group or
  function follows it. When no `opt` run follows, `-S -emit-llvm`
  writes the printed text directly, without first converting it to bytes
  and back to a string.

## Bench entries

- `bench/frontend/templates-wide-g.cpp`: `templates_wide.cpp` emitted as
  IR at `-g` (`mode: emit-llvm`, `args: -g`).
- `bench/frontend/format-like-g.cpp`: 90 test functions that format
  through `<format>`, with `<string>`, `<vector>` and `<map>` locals,
  at `-g`. This is a library-heavy TU, as format-test is.

## Tests

The behaviour is unchanged, so the tests are the existing ones, passing
unchanged: the IR corpus (`tests/codegen`, with every `debug_*` golden),
`tests/debuginfo`, and the `kiln_llvm` metadata unit and corpus tests
(`md_set_field_cycle`, `md_replace_placeholder`). The new unit test
`code_part_stops_at_metadata` (`kiln_driver/src/codegen_cmd.rs`) pins the
scan boundary.
