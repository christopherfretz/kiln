# WP-763 — GNU `alias`, `ifunc` and `weakref` codegen

GNU `alias("sym")` and `ifunc("resolver")` are no longer accepted and
ignored: sema checks them as clang does (spec/sema.md §4.5, `alias` /
`ifunc` / `weakref`), and codegen emits each as an IR alias or ifunc of
the named mangled symbol, with clang's linkage, visibility, forward
references and end-of-module checks (spec/codegen.md §9 "Aliases and
ifuncs"). The IR model gained ifuncs and global replacement
(spec/llvm.md §2.5). `weakref` keeps its existing lowering (an
`extern_weak` reference to the target); a weakref variable target now
prints as clang's (no `align`, not `constant`).

- `crates/kiln_codegen/src/alias.rs`: `emit_alias_definition`,
  `alias_target_needed`, `check_aliases`.
- `crates/kiln_sema/src/decl_attrs.rs`: `check_alias_definition`,
  `check_alias_redefines`; `crates/kiln_sema/src/decl.rs`: argument
  checks and the attribute's end location (`AttrNode.b`).
- `crates/kiln_llvm/src/module.rs`: `add_ifunc`,
  `replace_function_with_ifunc`, `replace_global_with_alias`,
  `set_aliasee`, `resolve` over globals; `print.rs` prints aliases then
  ifuncs.

Motivation: folly's `memcpy_select_aarch64.cpp` defines `__folly_memcpy`
and `__folly_memset` as ifuncs and aliases (docs/status/oss/folly.md).
