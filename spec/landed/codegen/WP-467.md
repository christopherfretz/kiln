# WP-467 — WP-454 follow-ups: constexpr decomposition emission

- **Static local tuple-like holding variables are folded.** A block-scope
  `static constexpr` (or `static` with a constant initializer)
  tuple-like decomposition's holding variables are not in its
  `DeclStmt` ([dcl.struct.bind]/4); `fold::Collect::local_decl` now
  visits them after `e`, each as a static local, so `static_local`
  finds their constant initializers and emits them as clang does:
  `@_ZZ1fvE1x = internal constant ptr @_ZZ1fvEDC1x1yE`, no guard
  variable and no run-time `get` call. Test:
  `tests/codegen/struct_bind_constexpr_emit.cpp` (`min-oracle: 22`).
- **A decomposition its holding variables require is emitted.**
  `var_must_emit` (clang `ASTContext::DeclMustBeEmitted`) is also true
  for a decomposition `e` one of whose tuple-like holding variables must
  be emitted (not discardable, or itself `var_must_emit`). An internal
  namespace-scope `constexpr auto [x, y] = V{...};` whose `get` returns
  by value has external holding references bound to temporaries
  (`@x = constant ptr @_ZGR1x_`) that never refer to `e`; `e`
  (`@_ZDC1x1yE = internal constant ...`) is now emitted with them, at
  its declaration's position (before the holding variables, as clang),
  where it used to be dropped (or, when a holding variable referred to
  it, emitted late as a deferred reference). A `static` one, whose
  holding variables are internal too, is still not emitted unless
  used. Test: `tests/codegen/struct_bind_constexpr_emit.cpp`.
