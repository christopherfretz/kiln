# WP-910 — Debug information is total

WP-814 made a construct that debug information could not describe a hard
error (`debug information for <what> is not supported`, with no file or
line). WP-910 removes every such path. `-g` at any level (`-g`, `-g1`,
`-gline-tables-only`, `-gdwarf-4`/`-5`) now compiles every program that
kiln compiles without it. What kiln cannot describe degrades the way clang
19 degrades. The summary is in spec/codegen.md §5.1. The status and the
remaining differences from clang (all class D) are in
docs/status/debuginfo.md "Gaps".

## Standard

The standard does not mention debug information ([intro.compliance]). The
contract stays clang 19's `CGDebugInfo`. For reflection, where clang has
no answer, kiln emits what clang emits for an opaque pointer-sized builtin
type.

## Rules (`kiln_codegen::debuginfo`)

- **No hard error.** `CodegenCtx::di_fail`, the error slot and
  `take_debug_info_error` are gone, and module emission
  (`module.rs`, the end of `emit`) no longer turns a debug-info failure
  into an error. Every `debuginfo/` builder returns `Option`. A type it
  cannot build (`di_type` → `None`) leaves out the field or node that
  would refer to it, which is the same rule as clang's null `DIType`.
  Nothing outside debug information depends on it.
- **`std::meta::info`** (`types.rs`, the `T::MetaInfo` arm of the builtin
  types) is a `DIBasicType` named `std::meta::info`, `DW_ATE_unsigned`,
  of pointer size. The choice of a base type rather than
  `DW_TAG_unspecified_type`:
  - The mangling already treats it as a builtin of that spelling (`Dm`),
    not as a class in `std::meta`.
  - LLVM's DWARF writer emits only the name of an unspecified type, so
    that form would lose the size.

  gdb prints a value of the type as a number. lldb names it
  `unsigned long` in a class name (`Holder<unsigned long>`; a D item).
- **Template value arguments** (`di_template_arg`): an argument that
  lowers to no IR constant (a `std::meta::info`, or a value kiln cannot
  lower) keeps its `DITemplateValueParameter` with `value: null`. This is
  what clang emits when its `ConstantEmitter` gives no constant
  (`CollectTemplateParams`). It is not left out, as the WP text guessed,
  so the parameter keeps its name and type. A null pointer argument is
  `i8 0`, including a null member function pointer (which used to print
  as `{ i64, i64 } zeroinitializer`). A null data member pointer is the
  ABI's `-1`, as before.
- **Template template arguments**: a template name that resolves to no
  template declaration leaves its parameter out. clang's
  `createTemplateTemplateParameter` needs the template's name. A pack
  leaves out the elements it cannot describe (`filter_map`).
- **SVE ACLE types** (`di_sve`) match clang 19's
  `CreateType(const BuiltinType *)` exactly, with no opaque fallback:
  - The type is a `DW_TAG_array_type` with `flags: DIFlagVector` over
    the element type (`signed char` … `double`, `__bf16`; `unsigned char`
    for a predicate).
  - Its subrange has `lowerBound: 0` and an upper bound of
    `!DIExpression(DW_OP_constu, N/2, DW_OP_bregx, 46, 0, DW_OP_mul,
    DW_OP_constu, 1, DW_OP_minus)`. Register 46 is `VG`, and N is the
    elements per 128 bits times the tuple size.
  - `svcount_t` has `upperBound: 1`.
  - The name reaches the type through the implicit typedef of the
    builtin's spelling (`__SVInt32_t`, `__clang_svint8x2_t`), which is
    in the main file with no line, as in clang.
- **Files of implicit declarations** (`di_main_file`, `mod.rs`): clang's
  `getOrCreateFile` of an invalid location is the compile unit's file
  name made a `DIFile` like any other. It is split against the
  compilation directory, and it is not the unit's own node. `di_file` of
  an invalid location returns it, which replaces the old `cu_file`
  shortcut. A typedef with no line leaves `line:` out.
- **Unnamed global variables** (`di_global_var`, `func.rs`): the variable
  of a namespace-scope structured binding ([dcl.struct.bind]) has no
  name. Its `DIGlobalVariable` gets only `linkageName: "_ZDC…E"`, as in
  clang. LLVM rejects `name: ""` (`llc: 'name' cannot be empty`).
- **Dependent class scopes** (`di_scope`, `types.rs`): a declaration
  whose context is a template pattern (`DeclFlags::DEPENDENT_CTX`, a
  described template, a partial specialization) has the unit as its
  scope, as in clang's `getContextDescriptor` (a dependent `RecordDecl`
  is no scope). Sema keeps the pattern's typedef sugar on a
  non-dependent type of an instantiated member ([temp.dep.type]; clang
  does too), so `size_type` in `std::array<int, 3>::size` named the
  pattern typedef, and kiln described the pattern class: it laid out a
  class with members of dependent type and tripped `kiln_abi`'s
  overlapping-members assertion (`irtype.rs`, debug builds) on every
  `std::array` at `-g`.
- **Complex integer types**: clang's `DW_ATE_lo_user` (0x80) prints as
  `encoding: 128`, as clang's own IR prints it; LLParser has no name for
  it.
- **Struct types of metadata constants** (`kiln_llvm` printer,
  `TypeFinder::run`): a class-type template argument is an IR constant
  of the class's struct type in the `DISubprogram`'s template
  parameters. When nothing else uses that type, LLVM's `TypeFinder`
  (which does not walk function or global metadata attachments) leaves
  its definition out, and the text does not parse back: clang 19's own
  `-S -emit-llvm -g` of such a TU fails in `llc` with `initializer with
  struct type has wrong # elements`. kiln's printer walks the global and
  function attachments after LLVM's roots, so those types are defined
  last. A module whose text parsed before prints byte for byte the same.
- **Classes made by reflection** (`define_aggregate`,
  `__kiln_define_member`) are ordinary records by the time codegen sees
  them, and they get the normal class DI (members, bit-fields, template
  parameters).

Without `-g`, the IR is unchanged byte for byte. The proof: the 121
conformance `ir` tests (goldens of the raw IR, in `cargo xtask ci
--quick`) and the 529 non-debug `tests/codegen` cases of
`ir_vs_clang.rs` (byte-exact against clang 19) pass unchanged. The
printer change adds a type definition only to a module whose text did
not parse before.

## Tests

- `tests/codegen/debug_sve.cpp` covers every `__SV*` builtin, the
  `__clang_sv*xN_t` tuples (through pointers: clang 22 allocates a
  tuple local as a struct of vectors, a non-debug lowering difference).
  `tests/codegen/debug_structured_binding.cpp` covers unnamed globals,
  `debug_dependent_scope.cpp` a pattern typedef in an instantiated
  member, `debug_complex.cpp` the complex base types.
  `tests/codegen/debug_template_values.cpp` gains a null member function
  pointer and an array element address. All are byte-exact against
  clang 19 on aarch64 and x86_64 (`ir_vs_clang.rs`, `KILN_ORACLE=19`).
- Run tests at `-g`, one per breakage the sweep found, each reduced by
  hand and each failing before its fix:
  `tests/conformance/dcl.struct.bind/namespace-scope-debuginfo-run.cpp`,
  `temp.dep.type/pattern-typedef-debuginfo-run.cpp`,
  `ext.complex/complex-int-debuginfo-run.cpp` and
  `temp.arg.nontype/class-type-argument-debuginfo-run.cpp`.
  `crates/kiln_llvm/tests/corpus.rs` `debug_attachment_struct_constant`
  checks the printer rule.
- `tests/debuginfo/reflection.cpp` (gdb and lldb) covers a
  `define_aggregate` class, a `Holder<info R>` specialization and a
  `constexpr info` variable.
- `tests/conformance/expr.reflect/debuginfo-run.cpp` and
  `tests/conformance/meta.reflection.define.aggregate/define-debuginfo-run.cpp`
  are run tests at `-g` and `-g -gdwarf-4`. They cover info packs,
  consteval functions, templates over reflections, and defined classes
  with bit-fields and templates.
- `tests/conformance/ext.arm.sve/target-attribute-sve-locals.cpp`
  passes since WP-1417: sema's SVE type check honours a function's
  `target("sve")` (`kiln_sema/src/sve.rs`, `sve_features_of`).
- `cargo xtask test --debug-sweep` (spec/harness.md "Debug-info sweep")
  compiles every positive conformance test with and without `-g` and runs
  `llvm-dwarfdump --verify` on the `-g` object. The first reflection
  run found the structured-binding name (3 tests). The first run over
  `tests/conformance` then found 21 failures in three classes: the
  dependent class scope (15, users of `std::array`, `std::format`,
  `std::regex` and similar), the complex integer encoding (4) and the
  metadata struct types (2). After the
  fixes: 2539 swept, 0 failures, 5 min 25 s; the reflection directories
  alone: 130 swept, 0 failures, 83 s, so the sweep is documented
  (spec/harness.md, docs/VALIDATION.md) rather than in `ci`.
- `llvm-dwarfdump-19 --verify` is clean on every new form at `-g`, `-g1`
  and `-gdwarf-4`. The clang-compilable cases equal clang 19's
  `llvm-dwarfdump` output.
