# WP-819 — builtin pointer-argument alignment, callee-destroyed argument cleanups

Two follow-ups from WP-774. The contract is in spec/codegen.md §3.3
"Pointer alignment" and §7b ("Callee-destroyed arguments"). This file
records what landed and what was deferred.

## Pointer-argument alignment ([atomics.types.generic], [atomics.ref.generic])

libstdc++'s `std::atomic<T>` declares `alignas(sizeof(T)) T _M_i` for a
power-of-two size and passes `std::__addressof(_M_i)` to the generic
`__atomic_load`/`__atomic_store`/`__atomic_exchange`. kiln took the
pointee type's alignment there (4 for `struct { int a, b; }`), so LLVM
lowered the access to a libatomic call and the link failed without
`-latomic`.

kiln now mirrors clang's `EmitPointerWithAlignment` case by case in one
helper, `builtins.rs` `pointer_with_alignment`. It replaces the separate
`atomic.rs` `pointer_and_align` and `new_delete.rs` `pointer_with_align`.
It covers:
- no-op and bit casts (an explicit cast of a non-declaration operand takes
  the target's alignment);
- array decay and derived-to-base;
- `&lvalue` and the `addressof` library builtins;
- clang 22's pointer arithmetic (at compat 22 only);
- the natural pointee alignment, including an `aligned` typedef pointee
  (libc++ `atomic_ref`'s `_Aligned_Tp*`).

The `Decl` alignment source now follows clang for `->` members (always a
declaration's), reference variables (not) and `*p`/`p[i]` (the pointer's
source). It decides both explicit casts and the placement argument of a
new-expression.

Every user shares the helper:
- the atomics;
- memcpy/memmove/memset-like builtins;
- `__builtin_clear_padding`;
- `va_arg`;
- NEON loads and stores;
- checked arithmetic;
- VLA subscripts;
- placement new.

`__builtin_assume_aligned` takes its pointer as a plain scalar, as clang
does.

Under libc++, `std::atomic<T>` reaches its `_Atomic(T)` member through
`std::addressof`, and the `__c11_atomic_*` alignments match clang 19 and
22.

Tests:
- `tests/codegen/atomic_pointer_alignment.cpp` replicates the libstdc++
  `atomic`/`atomic_ref` and libc++ `__cxx_atomic_base_impl`/`atomic_ref`
  shapes for 1/2/4/8/16-byte structs. It also covers an over-aligned
  member, casts, decay, derived-to-base, memcpy, placement new and
  pointer arithmetic. It is byte-exact against clang 19.
- `tests/conformance/atomics.types.generic/run-libstdcxx-atomic-struct-align.cpp`
  (xfail flipped).
- `run-libstdcxx-atomic-struct-sizes.cpp` and
  `run-libcxx-atomic-struct-sizes.cpp` link without libatomic.

## Callee-destroyed argument cleanups ([class.temporary]/3, [except.ctor]/3)

The WP-774 "Deferred" note said kiln does not emit clang's `alloca i1`
"cleanup.isactive" flag when a `trivial_abi` argument's cleanup is
deactivated below a later argument's cleanup. That is no longer true.
`deactivate_arg_cleanups` goes through `eh.rs` `deactivate_cleanup_block`,
which creates the flag when the cleanup is not innermost. The IR is
byte-identical to clang 19 and 22 for these calls:
- free calls;
- member calls;
- static member calls;
- constructor calls;
- new-expression calls.

`tests/conformance/class.temporary/run-trivial-abi-cleanup-isactive.cpp`
destroys each object exactly once in each case:
- the second argument's constructor throws;
- a later argument throws;
- the callee throws.

Nothing needed fixing.

## Deferred

- The lvalue of `*p` and `p[i]` keeps the pointee's natural alignment
  (`expr.rs` `unary_lvalue`, `subscript_lvalue`). clang computes it with
  `EmitPointerWithAlignment`, so `__atomic_load(&*&x.m, ...)` loses the
  member's `alignas`, and a record with virtual bases uses its complete
  alignment instead of its non-virtual alignment.
- Full-header IR for padded types still differs from clang 19. kiln
  implements GCC's `__builtin_clear_padding` (WP-774), which libstdc++
  and libc++ call; clang 19 has no such builtin. Run-time behaviour is
  the same.
