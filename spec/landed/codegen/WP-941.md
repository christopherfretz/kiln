# WP-941 — Coverage: gcov and source-based coverage counters

The contracts are spec/driver.md "Coverage flags" and spec/codegen.md
§5.4 "Instrumentation". This file records what landed, how it was
validated, what it costs, and what was deferred.

## What landed

- **gcov** (`--coverage`, `-fprofile-arcs`, `-ftest-coverage`,
  `-fprofile-dir=`, `-fprofile-update=`): `!llvm.gcov`, clang's
  location-tracking-only debug information when no `-g` is given, `opt`'s
  `insert-gcov-profiling` at pipeline start, and `--coverage` on the link.
- **Source-based coverage counters** (`-fprofile-instr-generate[=path]`,
  `coverage/pgo.rs`): clang 19 `CodeGenPGO`'s region counters, function
  names and V3 hash, lowered by `opt`'s `instrprof`;
  `@__llvm_profile_filename` for `=path`.
- **Interface:** `kiln_codegen::CoverageOptions` (new field
  `CodegenOptions::coverage`); `kiln_driver` `coverage_flags.rs`
  (`CoverageFlags`); new diagnostic `drv_argument_only_allowed_with`.
  With no coverage flag the IR is unchanged, byte for byte.
- **Debug locations** fixed on the way, because gcov counts lines through
  them (they change `-g` output the same way): default-member-initializer
  stores at the member; the coroutine ramp wrapper's artificial
  subprogram (file of an invalid location = the compile unit's), the
  cleanup-destination switch and the shared `unreachable` block without a
  location, `mem2reg` phis with `RenamePass`'s merged location,
  `co_await`/`co_yield` end locations, and default arguments emitted with
  debug locations off (clang `DisableDebugLocationUpdates`; a libstdc++
  `std::string(const char*)` conversion put the header line of
  `const _Alloc& = _Alloc()` on the caller's allocator construction, and
  gcov counted the calling line twice).
- **clang 22** (`-fclang-compat=22`): coroutine `coro.id` without the
  promise `bitcast`, `internal` ramp wrapper; `tests/ir_norm`
  `coro_end_llvm22` upgrades LLVM 19's `i1 @llvm.coro.end` for `opt-22`.

consteval functions are never emitted, so they get no counters and no
profile record (clang behaves the same). The profile runtime is LLVM 19's
`libclang_rt.profile-<arch>.a` (`/usr/lib/llvm-19/lib/clang/19/lib/linux/`,
Debian `libclang-rt-19-dev`), added by the linking `clang++`.

## Not in this WP

- `-fcoverage-mapping` (clang `CoverageMappingGen`: `__llvm_covmap`,
  `__llvm_covfun`, so `llvm-cov show`/`report`/`export`): rejected with
  "source-based coverage mapping is not yet implemented, a WP-941
  follow-up". `-fcoverage-compilation-dir=` and `-fcoverage-prefix-map=`
  are parsed for it.
- Profile-guided optimization (`-fprofile-generate`,
  `-fcs-profile-generate`, `-fprofile-use`, `-fprofile-instr-use`,
  `-fprofile-sample-use`, `-fauto-profile`, `-fprofile-remapping-file=`):
  rejected as "a known kiln 1.0 limitation". `-fprofile-generate` is
  IR-level PGO instrumentation (its `.profraw` is not coverage), so it is
  rejected with the PGO flags rather than treated as coverage.
- `-fprofile-filter-files=` / `-fprofile-exclude-files=` (gcov filters):
  rejected.

## Validation

- **IR against clang** (`ir_vs_clang`, exact under `KILN_ORACLE=19`,
  structural under 22): `tests/codegen/gcov_coroutine.cpp`,
  `instrprof_control_flow.cpp`, `instrprof_classes.cpp`,
  `instrprof_filename.cpp`, `debug_cleanup_switch.cpp`,
  `debug_default_arg.cpp`, `debug_default_member_init.cpp`,
  `debug_logical_multiline.cpp`,
  `vector_logical.cpp`, `case_range_after_cases.cpp`; `tests/mangle/
  dependent_bitint.cpp` (`mangle_vs_clang`).
- **Driver:** `crates/kiln_driver/tests/codegen.rs`
  `coverage_flags_rejected` (mapping and PGO wording, accepted flags
  compile with empty stderr) and the `coverage_flags.rs` unit tests.
- **End to end** (`scripts/coverage-compare.py`, kiln debug build against
  clang++-19, LLVM 19 `llvm-profdata` / `llvm-cov`): every program EQUAL
  except the one listed `KNOWN` difference.

| program | instr functions / counters / executions | gcov lines / executed |
|---|---|---|
| classes_templates_lambdas.cpp | 31 / 36 / 31 | 38 / 38 |
| control_flow.cpp | 11 / 63 / 78 | 65 / 63 |
| coroutines.cpp | 10 / 11 / 28 | 20 / 18 |
| logical_multiline.cpp | 3 / 9 / 24 | 15 / 15 |
| macros.cpp | 2 / 11 / 9 | 7 / 7 |
| stdlib.cpp | 7 / 12 / 399 | 31 / 31 |
| signature_exprs.cpp (KNOWN) | kiln 6 / 6 / 5, clang 6 / 7 / 4 | 10 / 10 |

  Except for the KNOWN row, kiln's and clang's totals are the same. Local lambdas' `$_N`
  discriminators are compared modulo numbering (kiln numbers them in a
  different order; the counters are equal). `signature_exprs.cpp` is the
  KNOWN instr difference. clang's `MapRegionCounters` also walks the
  written signature (return-type template arguments, `decltype` and
  `noexcept` operands). That walk feeds clang's hash, and a `noexcept`
  `&&` gets a counter. Kiln walks only the body. gcov is equal.
- **OSS: fmt 12.1.0** (`git clone --depth 1 --branch 12.1.0
  https://github.com/fmtlib/fmt`), its test suite built at `-O0` with
  `-DFMT_TEST=ON` through `scripts/oss/kiln-cxx` (Unix Makefiles,
  `CMAKE_CXX_FLAGS="-O0 -fclang-compat=19 <mode>"`, the same flags on the
  link), once per compiler and mode, then `ctest` with
  `LLVM_PROFILE_FILE=<build>/prof/%p.profraw`. Kiln is the `harness`
  profile build, and the oracle is clang++-19 with LLVM 19 `llvm-profdata` / `llvm-cov`.
  - Every build succeeds (84 compiler invocations, one of them a rejected
    configure probe, the same for clang), and **21/21 tests pass** in all
    four builds.
  - instr (`llvm-profdata merge` of every run, then `show --all-functions
    --counts`): kiln 13144 functions / 44011 counters / 54585352
    executions, clang 13193 / 44060 / 54585161.
    - 132 names are only in kiln's profile and 150 only in clang's. Most
      are the unnamed-enumeration template-argument mangling: kiln writes
      `Ut_`, clang 19 writes `$_N`. The rest were attributed to
      constant-evaluation choices (WP-1008):
      - chrono-test's `make_tm` runs at run time in kiln, while clang
        constant-emits it. Fixed by WP-1008: it is the
        `std::initializer_list` backing array of `tm_list`, which clang
        copies from a `@constinit` constant (`EmitArrayInit`).
      - clang calls the `basic_format_args` constexpr constructors, while
        kiln folds them. WP-1008 found the `basic_format_args` calls equal;
        the constexpr constructors that did differ were array-list
        elements (`std::optional<int>` in std-test), which clang copies
        from `@constinit` and kiln called. Fixed by the same rule.
    - 13 functions differ in hash only (the signature walk, see the
      `KNOWN` entry). 20 differ in counts by a few executions, for example
      `basic_string_view(const char*)` 10020 against 10021.
  - gcov (`llvm-cov gcov -l -p` per `.gcda`): kiln 1287 `.gcov` files,
    clang 1290 (clang also covers `src/format.cc` from two TUs). Kiln has
    115738 lines with 41980 executed, clang 115791 with 41951.
    - 137 files differ in some count. Nearly all of the differing lines are
      libstdc++ `basic_string.h` (530 lines), `char_traits.h`,
      `ptr_traits.h` and `stl_iterator.h`, i.e. the run-time string work
      that remains after each compiler's own constant folding.
    - The multi-line `&&` difference (`format-inl.h:1150`, 2067 against
      3037) is fixed above.
  - Found and fixed on the way:
    - `_BitInt(N)` of a template parameter mangled as `DB`/`DU <expr> _`
      (`tests/mangle/dependent_bitint.cpp`). Before the fix, fmt's
      `value(bitint<N>)` and `value(ubitint<N>)` collided.
    - A value `&&`'s debug locations (`tests/codegen/
      debug_logical_multiline.cpp`, `scripts/coverage/logical_multiline.cpp`).

## Compile-time overhead

Measured with `/usr/bin/time -f "%e %M"`. Each figure is the best wall
time of three runs, and the peak RSS (KB) is the largest of the three.
GNU time's `%M` is the largest single process in the tree: kiln++, or
the `opt` / `llc` it runs. Kiln is the `harness` profile build
(`cargo build --profile harness -p kiln_driver`, opt-level 3, no LTO).
The oracle is clang++-19. Everything ran on the shared aarch64 host
with other jobs running, so treat a 5% difference as noise. The scripts
are reproduced here.

**fmt 12.1.0 `test/format-test.cc`** (the largest fmt TU, about 16 MB of
IR at `-O0`):

    $cc [-fclang-compat=19, kiln only] -DGTEST_HAS_STD_WSTRING=1 \
        -I fmt/include -isystem fmt/test/gtest -O0 <mode> -std=gnu++20 \
        -fvisibility=hidden -fvisibility-inlines-hidden \
        -c fmt/test/format-test.cc -o f.o

| compiler, mode | wall s | peak RSS KB | object bytes |
|---|---|---|---|
| kiln, none | 4.02 | 165152 | 4821096 |
| kiln, `--coverage` | 6.72 (+67%) | 252884 (+53%) | 7483448 |
| kiln, `-fprofile-instr-generate` | 4.17 (+4%) | 189548 (+15%) | 6641832 |
| clang, none | 3.53 | 328348 | 4809376 |
| clang, `--coverage` | 6.01 (+70%) | 336716 (+3%) | 7540728 |
| clang, `-fprofile-instr-generate` | 4.11 (+16%) | 332188 (+1%) | 6590760 |

**`scripts/coverage/stdlib.cpp`** (`$cc -std=c++26 <opt> <mode> -c
scripts/coverage/stdlib.cpp -o s.o`; kiln in its default clang-22 mode):

| compiler, opt | none (s / KB) | `--coverage` | `-fprofile-instr-generate` |
|---|---|---|---|
| kiln -O0 | 1.63 / 102528 | 2.21 / 131892 | 1.60 / 102832 |
| kiln -O2 | 2.92 / 103496 | 5.25 / 146728 | 3.02 / 103608 |
| clang -O0 | 1.39 / 207716 | 1.78 / 212780 | 1.47 / 208120 |
| clang -O2 | 2.83 / 210736 | 4.76 / 218548 | 2.74 / 210780 |

`stdlib.cpp` instruments almost nothing, because system-header
functions get no region counters. fmt's TU is the representative
figure.

Where the time goes:
- gcov's relative wall overhead is about the same as clang's (+67%
  against +70%).
- Most of it, and the peak RSS growth, is LLVM's own
  `insert-gcov-profiling` in the `opt` process kiln runs. With `-S
  -emit-llvm` (which already includes that pass), the IR grows from 16
  to 29 MB and the peak from 148 to 249 MB.
- Kiln's own share is the location-tracking debug information. Measured
  as `-gline-tables-only` without coverage, it adds 0.4 s and 16 MB.
- Because clang does all of this in one process, its peak barely moves.
  Kiln's peak with coverage is still 77% of clang's peak without it.

Region counters (`-fprofile-instr-generate`) cost kiln 4% wall time.

## Follow-ups

These were found while comparing against clang. None of them blocks
coverage. There is one xfail repro,
`tests/conformance/basic.link/unnamed-enum-internal-name-run.cpp`. The
one tolerated coverage difference is the `KNOWN` entry for
`signature_exprs.cpp` in `scripts/coverage-compare.py`.

- `-fcoverage-mapping`: clang `CoverageMappingGen` regions, `__llvm_covmap`
  / `__llvm_covfun` (`crates/kiln_driver/src/coverage_flags.rs:187`
  rejection, `crates/kiln_codegen/src/coverage/mod.rs` `mapping`).
- gcov filters `-fprofile-filter-files=` / `-fprofile-exclude-files=`
  (`crates/kiln_driver/src/coverage_flags.rs:131`).
- Local lambda `$_N` numbering order differs from clang's
  (`crates/kiln_abi/src/mangle.rs:41` `AnonIds`); profile names differ
  only by the number.
- `-g`: the coroutine ramp wrapper's parameter `dbg.declare`s and
  `retainedNodes` (`crates/kiln_codegen/src/coro.rs:624`,
  `debuginfo/func.rs:153` `di_wrapper_start`); conversion-operator
  `DISubprogram` names (`debuginfo/types.rs:958` `di_fn_name`); the
  `DIFlag` order on implicit constructors (`debuginfo/func.rs:97`);
  `!dbg` on string-literal globals.
- `llvm.coro.done` attributes: kiln declares `nocapture readonly`
  (`crates/kiln_llvm/src/intrinsics.rs:987`), clang 19 `memory(argmem:
  readwrite)`.
- The region-counter walk covers only the body
  (`crates/kiln_codegen/src/coverage/pgo.rs:140` `map_region_counters`).
  clang's `MapRegionCounters` also walks the written function type
  (return-type template arguments, `decltype` and `noexcept` operands).
  This causes the hash differences and clang's extra counter for a
  `noexcept(a && b)`. Its gate is the `KNOWN` entry in
  `scripts/coverage-compare.py`.
- An unnamed enumeration that is not externally visible mangles as `Ut_`
  in kiln but as `$_N` in clang 19 and 22. clang `mangleUnqualifiedName`
  uses `Ut` only for an externally visible unnamed type
  (`crates/kiln_abi/src/mangle.rs:2339`). The xfail repro is
  `tests/conformance/basic.link/unnamed-enum-internal-name-run.cpp`, and
  this accounts for most of the fmt profile names found in only one of
  the two compilers. These names have internal linkage, so linking is not
  affected.
- Constant-evaluation choices that differ from clang at `-O0`: resolved
  by WP-1008 (`spec/landed/codegen/WP-1008.md`). The `make_tm` difference
  was clang's `EmitArrayInit` constant copy of an array init list, which
  kiln now matches. The `basic_format_args` calls were already equal; the
  constexpr constructors that differed were array-list elements, under
  the same rule.
- `-g` locations from `branch_on_bool` (`crates/kiln_codegen/src/expr.rs:1816`)
  differ from clang's. clang `EmitBranchOnBoolExpr` emits a condition
  `&&`/`||`'s left-hand side under the operator's location, and the `if`
  condition's last branch is in the function scope. gcov counts are not
  affected (checked with nested multi-line conditions).
