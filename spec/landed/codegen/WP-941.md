# WP-941 — Coverage: gcov and source-based coverage counters

The contracts are spec/driver.md "Coverage flags" and spec/codegen.md
§5.4 "Instrumentation". This file records what landed, how it was
validated, what it costs, and what was deferred.

## What landed

- **gcov** (`--coverage`, `-fprofile-arcs`, `-ftest-coverage`,
  `-fprofile-dir=`, `-fprofile-update=`): `!llvm.gcov`, clang's
  location-tracking-only debug information when no `-g` is given, `opt`'s
  `insert-gcov-profiling` at pipeline start, and `--coverage` on the link.
- **Source-based coverage counters** (`-fprofile-instr-generate[=path]`,
  `coverage/pgo.rs`): clang 19 `CodeGenPGO`'s region counters, function
  names and V3 hash, lowered by `opt`'s `instrprof`;
  `@__llvm_profile_filename` for `=path`.
- **Interface:** `kiln_codegen::CoverageOptions` (new field
  `CodegenOptions::coverage`); `kiln_driver` `coverage_flags.rs`
  (`CoverageFlags`); new diagnostic `drv_argument_only_allowed_with`.
  With no coverage flag the IR is unchanged, byte for byte.
- **Debug locations** fixed on the way, because gcov counts lines through
  them (they change `-g` output the same way): default-member-initializer
  stores at the member; the coroutine ramp wrapper's artificial
  subprogram (file of an invalid location = the compile unit's), the
  cleanup-destination switch and the shared `unreachable` block without a
  location, `mem2reg` phis with `RenamePass`'s merged location,
  `co_await`/`co_yield` end locations, and default arguments emitted with
  debug locations off (clang `DisableDebugLocationUpdates`; a libstdc++
  `std::string(const char*)` conversion put the header line of
  `const _Alloc& = _Alloc()` on the caller's allocator construction, and
  gcov counted the calling line twice).
- **clang 22** (`-fclang-compat=22`): coroutine `coro.id` without the
  promise `bitcast`, `internal` ramp wrapper; `tests/ir_norm`
  `coro_end_llvm22` upgrades LLVM 19's `i1 @llvm.coro.end` for `opt-22`.

consteval functions are never emitted, so they get no counters and no
profile record (clang behaves the same). The profile runtime is LLVM 19's
`libclang_rt.profile-<arch>.a` (`/usr/lib/llvm-19/lib/clang/19/lib/linux/`,
Debian `libclang-rt-19-dev`), added by the linking `clang++`.

## Not in this WP

- `-fcoverage-mapping` (clang `CoverageMappingGen`: `__llvm_covmap`,
  `__llvm_covfun`, so `llvm-cov show`/`report`/`export`): rejected with
  "source-based coverage mapping is not yet implemented, a WP-941
  follow-up". `-fcoverage-compilation-dir=` and `-fcoverage-prefix-map=`
  are parsed for it.
- Profile-guided optimization (`-fprofile-generate`,
  `-fcs-profile-generate`, `-fprofile-use`, `-fprofile-instr-use`,
  `-fprofile-sample-use`, `-fauto-profile`, `-fprofile-remapping-file=`):
  rejected as "a known kiln 1.0 limitation". `-fprofile-generate` is
  IR-level PGO instrumentation (its `.profraw` is not coverage), so it is
  rejected with the PGO flags rather than treated as coverage.
- `-fprofile-filter-files=` / `-fprofile-exclude-files=` (gcov filters):
  rejected.

## Validation

- **IR against clang** (`ir_vs_clang`, exact under `KILN_ORACLE=19`,
  structural under 22): `tests/codegen/gcov_coroutine.cpp`,
  `instrprof_control_flow.cpp`, `instrprof_classes.cpp`,
  `instrprof_filename.cpp`, `debug_cleanup_switch.cpp`,
  `debug_default_arg.cpp`, `debug_default_member_init.cpp`,
  `vector_logical.cpp`, `case_range_after_cases.cpp`.
- **Driver:** `crates/kiln_driver/tests/codegen.rs`
  `coverage_flags_rejected` (mapping and PGO wording, accepted flags
  compile with empty stderr) and the `coverage_flags.rs` unit tests.
- **End to end** (`scripts/coverage-compare.py`, kiln debug build against
  clang++-19, LLVM 19 `llvm-profdata` / `llvm-cov`): every program EQUAL.

| program | instr functions / counters / executions | gcov lines / executed |
|---|---|---|
| classes_templates_lambdas.cpp | 31 / 36 / 31 | 38 / 38 |
| control_flow.cpp | 11 / 63 / 78 | 65 / 63 |
| coroutines.cpp | 10 / 11 / 28 | 20 / 18 |
| macros.cpp | 2 / 11 / 9 | 7 / 7 |
| stdlib.cpp | 7 / 12 / 399 | 31 / 31 |

  The totals are kiln's and clang's alike. Local lambdas' `$_N`
  discriminators are compared modulo numbering (kiln numbers them in a
  different order; the counters are equal).
- **OSS:** the brief's fmt run in both modes could not be done: the
  container has no DNS, so the fmt clone fails. `scripts/coverage/
  stdlib.cpp` (libstdc++ containers, algorithms, `std::format`,
  `std::regex`, `std::variant`, streams) stands in until a networked run.
