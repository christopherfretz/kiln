# WP-581 — captured reference locals inside generic lambdas

- **Problem.** A header-only configuration library's table comparison
  (`[&](const auto& lhs) { return lhs == *reinterpret_cast<
  std::remove_reference_t<decltype(lhs)>*>(&rhs); }` passed to a
  per-alternative `visit`) failed at every `-O` level with "reference to
  an unemitted local variable" (`kiln_codegen/src/expr.rs`, the local
  lookup of `decl_lvalue`).
- **Minimal repro.**
  `bool f(const int& r) { const int& rr = r; auto g = [&](const auto& x)
  { return x == rr; }; return g(r); }` — no `reinterpret_cast`, `visit` or
  `-O2` needed: any generic lambda with a capture-default naming an
  enclosing local that might be usable in constant expressions (a
  reference, a `const` integral variable) in its body.
- **Root cause (sema).** Such a name's capture is deferred to the end of
  its full-expression ([basic.def.odr]/5), but inside a template
  definition the deferral list was never filled, and the closure type is
  complete before any call operator specialization exists, so the
  capture was never recorded; codegen then fell back to the enclosing
  function's local. A second gap: a lambda nested in a generic lambda,
  formed again for each specialization of the outer call operator, did
  not capture the variables named in its body's shared (non-dependent)
  expressions, even an `int` local.
- **Fix.** Potential captures (spec/sema-lambda.md §4.2, clang
  `CheckIfAnyEnclosingLambdasMustCaptureAnyPotentialCaptures`) and
  captures from shared expressions in rebuilt lambda bodies
  (`note_shared_captures`). Codegen is unchanged; spec/codegen.md
  "Captured locals" states the invariant. Closure layouts now match
  clang's speculative captures (`[=](auto x) { return x + n; }` with a
  constant `n` has an `int` member), and a reference that can never be
  constant named in a captureless generic lambda is diagnosed in the
  definition, as clang does.
- **Tests.** `tests/conformance/expr.prim.lambda/`:
  `run-generic-captured-reference.cpp` (+ `-O2` sibling),
  `run-generic-captured-reference-decltype.cpp`,
  `run-generic-captured-reference-nested.cpp`,
  `generic-captured-reference-visit.cpp` (compile-ok, the visitor shape
  with two alternatives), `generic-captured-reference-layout.cpp`
  (closure sizes), `errors-generic-captured-reference.cpp`
  (strict-diags).
