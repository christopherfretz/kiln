# WP-846 — AArch64 target bundle: ACLE builtins, MS barrier names, branch protection

Closes WP-736, WP-737 and WP-842. The contracts are spec/codegen.md §3.4
"Target builtins", spec/driver.md "Codegen flags" (the
`-mbranch-protection=` row) and deviation 21, and spec/pp.md "Feature
queries" and "AArch64 target macros". This file records what landed and
what was deferred.

## ACLE builtins (WP-736)

Every `__builtin_arm_*` row kiln declares is now lowered (`arm.rs`); the
arm entries left `UNLOWERED_BUILTINS`. New: the exclusive accesses
(`ldrex`, `ldaex`, `strex`, `stlex`, with `elementtype(iN)` and the
128-bit pair forms), the system registers (`rsr`, `rsr64`, `rsrp`,
`wsr`, `wsr64`, `wsrp`, and the `d128` forms `rsr128`/`wsr128`, whose
declarations are new), `rint{32,64}{x,z}[f]`, `jcvt`, `rndr`, `rndrrs`,
the `FEAT_LS64` loads and stores, `gcspopm`, `gcsss`, `chkfeat`,
`prefetch` and `trap`. `kiln_llvm::intrinsics` gained the attribute
shapes these need. `fold_cast` now folds a floating constant bit-cast to
an integer, as LLVM's constant folder does (a `strex` of a constant
`__fp16`).

The operand checks of clang `CheckAArch64BuiltinFunctionCall` are new
(`kiln_sema` `arm_builtins.rs`): the special-register string (literal,
five-field encoding ranges, PSTATE immediates), the `prefetch` and barrier
ranges, and the exclusive accesses' discarded-qualifier ExtWarn. New
diagnostics: `sema_arm_invalid_specialreg`,
`sema_expr_not_string_literal`, `sema_passing_discards_qualifiers` (group
`-Wincompatible-pointer-types-discards-qualifiers`, under the new
umbrella `-Wincompatible-pointer-types`). The encoding's first field is at
most 1 under `-fclang-compat=19` and 3 under 22, as each clang.

Behaviour that matches clang and looks wrong: clang 19 encodes a
`"1:op1:CRn:CRm:op2"` string as `op0` 1, an instruction that traps; kiln
emits the same IR. An exclusive retry loop at `-O0` can spin forever on
hardware under both compilers, so the run test is `-O2`.

Tests (`tests/conformance/target.acle/`): `ir-exclusive-19.cpp`,
`ir-sysreg-19.cpp`, `ir-sysreg128-19.cpp`, `ir-rint-jcvt-rndr-19.cpp`,
`ir-ls64-19.cpp`, `ir-gcs-chkfeat-prefetch-trap-19.cpp` (exact under
oracle 19), `exclusive-sysreg-run.cpp` (run, `-O2`),
`operand-checks.cpp` (verify), `special-register-o0-19.cpp` and
`special-register-o0.cpp` (the compat-dependent `o0` range); `kiln_sema`
`arm_builtins::tests::encodings`.

## MS barrier names (WP-737)

clang 19 declares `__dmb`, `__dsb`, `__isb`, `__sev`, `__sevl`, `__wfe`,
`__wfi` and `__yield` as language builtins only under `-fms-extensions`,
and `__has_builtin` answers 1 for them only there. kiln++ has no MS
extensions mode and rejects the flag (spec/driver.md deviation 21), so in
every mode it accepts, `__has_builtin` already agrees with the
declarations: without `<arm_acle.h>` the names are undeclared, with it
they are the header's inline functions. A real MS mode (keywords,
`__declspec`, about 270 MS builtins) is far outside this package and is a
follow-up. Tests: `ms-barrier-builtins-undeclared-19.cpp` (clang < 22,
which keeps the names out of `__has_builtin`) and
`ms-barrier-builtins-acle.cpp`.

## Branch protection (WP-842)

`-mbranch-protection=` and `-msign-return-address=` are parsed as clang 19
(`kiln_abi::branch_protection`); kiln emits the function attributes on
definitions, declarations and call sites, the `Min` module flags (value 2
under clang 22) and the `__ARM_FEATURE_{PAC,BTI,GCS}_DEFAULT` predefines.
A `target("branch-protection=...")` attribute overrides the function's
attributes and is checked in sema. The driver errors (invalid item, an
x86 target) match clang's. Tests: `target.acle/ir-branch-protection-*.cpp`
(clang 19 and clang 22 variants), `branch-protection-predefines*.cpp`,
`branch-protection-target-attribute-{invalid,x86}.cpp`, `kiln_driver`
`hardening::branch_protection_flags`, `kiln_abi` `branch_protection`
unit tests.

## Deferred

- `standard` never adds PAuth-LR: kiln models no `-march=` extension
  enabling it (`kiln_driver` `codegen_flags.rs` `branch_protection`).
- An AArch64 `target("arch=...")` changes no target features
  (`kiln_driver` `features.rs`, the attribute item loop).
- An MS extensions mode (`-fms-extensions`).
- clang 22's `__builtin_arm_gcsss` takes `void *`; kiln declares clang
  19's signature (`kiln_ast` `decl.rs` arm rows).
