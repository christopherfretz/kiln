# WP-1400 — `-g`: debug names, canonical template arguments, anonymous unions

WP-1389 left four documented differences from clang 19 at `-g` that a
debugger shows: class names that elide default arguments and inline
namespaces, function `templateParams` that describe a sugared argument,
no variables for the members of a block-scope anonymous union, and no
`defaulted:` on template parameters.

## Rule: debug names

The `name:` of a class template specialization's `DICompositeType`
(clang `getClassName`) and of a function template specialization's
`DISubprogram` (`getFunctionName`) is printed under clang's
debug-information printing policy (`CGDebugInfo::getPrintingPolicy`,
`AstNames::for_debug_info`, `AstNames::debug_info`):

1. Every converted argument prints, canonical, trailing defaults
   included: `str<char, n::v1::traits<char>, n::v1::al<char> >`
   (`ClassTemplateSpecializationDecl::getNameForDiagnostic` prints
   `getTemplateArgs()` with no parameter list). Closers split (`> >`).
2. A name inside the arguments keeps its inline namespaces
   (`SuppressInlineNamespace = false`): `n::v1::traits<char>`.
3. An enumeration value argument prints as a cast to its canonical
   type, never as an enumerator (`UseEnumerators = false`):
   `lk<(n::Pol)2>`, `slk<(n::SPol)1>`.
4. An integral value argument prints with its type
   (`AlwaysIncludeTypeForTemplateArgument`): `arr<int, 3UL>`,
   `at<(n::Pol)1, 7UL>`; the members of a class-type value do not
   (`T<S{3, 4}>`).
5. No `preferred_name` (`UsePreferredNames = false`).
6. A conversion function to a class type is named `operator` and the
   class's bare name (`DeclarationName::print`: `operator
   basic_string_view`).

The policy is a switch on `AstNames` that only `kiln_codegen`'s debug
information sets; no diagnostic, dump or mangled name changes. clang 19
and 22 print every case above the same way.

## Rule: canonical arguments

`templateParams` (clang `CollectTemplateParams`) describe the
specialization's canonical converted arguments, of a function template
specialization too: `f<alloc<char>, alloc<char> >` for `template <class
A, class = typename enable_if<true, A>::type> void f(A)`, so
`enable_if<true, alloc<char> >` is not described; `g<int>` for
`g<Int>` with `using Int = int`; a value parameter of alias type has
the canonical type. In any described type, a substituted template
parameter is its canonical replacement (clang substitutes canonical
arguments): the parameter and locals of type `T` in `g<Int>` are `int`.

A class template specialization's trailing arguments that its name
suppresses as defaults (`SpecInfo::print_args`, clang's
`TemplateArgument::getIsDefaulted`) carry `defaulted: true`, at every
DWARF version (the back end drops it below DWARF 5). A pack, and every
argument of a function template specialization, never do. Deviation: a
non-trailing argument equal to its default and the arguments of an
explicit specialization are not marked (clang marks them; it needs a
per-argument bit on `SpecInfo`).

## Rule: block-scope anonymous union

Before the `#dbg_declare` of a block-scope anonymous union's unnamed
artificial variable ([class.union.anon]/1), each member of the union gets
an artificial `DILocalVariable` (its name, its type, no file, line 0)
declared on the same storage with the same expression and a line-0
location (clang `EmitDeclare`). An unnamed member is skipped unless its
type is a class (an anonymous struct member). With optimization the
variables join the subprogram's `retainedNodes`. A parameter or named
variable of a class with an anonymous union member gets none.

## Tests

- `tests/codegen/debug_template_names.cpp`,
  `debug_template_canonical_args.cpp`, `debug_anon_union_local.cpp`:

  (`crates/kiln_codegen/tests/ir_vs_clang.rs`).

  clang++-19.
