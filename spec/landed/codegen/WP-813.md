# WP-813 — no silent drops, part 7: class B attributes

Before this package kiln parsed these attributes and dropped them with no
diagnostic. Each now has clang 19's sema (spec/sema.md §4.5 "Class B
attributes", `crates/kiln_sema/src/class_b_attrs.rs`) and clang 19's IR
(`crates/kiln_codegen/src/class_b.rs`). Its paired driver flags are
implemented (spec/driver.md, class 1). Clang sources are clang 19's
`clang/lib/CodeGen`: `CGCall.cpp` (`ConstructAttributeList`,
`getDefaultFunctionAttributes`, `EmitFunctionProlog`, `EmitCall`,
`AssumeAlignedAttrEmitter`), `CodeGenModule.cpp`
(`SetLLVMFunctionAttributesForDefinition`, `SetFunctionAttributes`,
`EmitGlobalVarDefinition`, `Release`), `CodeGenFunction.cpp`
(`StartFunction`), `CGStmt.cpp` (`EmitAttributedStmt`) and
`CGLoopInfo.cpp`.

## Where an effect goes

- **Declaration, definition and direct call** (`ConstructAttributeList`;
  `Cg::class_b_fn_attrs`, `class_b_params`).
- **Definition only** (`SetLLVMFunctionAttributesForDefinition`,
  `StartFunction`; `Cg::class_b_def_attrs`, with a `StartDecl`). This is
  the function's `FunctionDecl` for user functions and lambdas, the
  `VarDecl` for `__cxx_global_var_init`, and none for `_GLOBAL__sub_I_*`,
  `__tls_init` and thunks. The `_ZTW` TLS wrapper gets none of these.
- **Flag defaults** (`getDefaultFunctionAttributes`;
  `Cg::class_b_default_attrs`). These go on definitions and declarations
  of user functions. A call site or a runtime helper never gets them.
- **Call site only** (`EmitCall`; `Cg::class_b_call_attrs`,
  `stmt_call_attrs`).
- **Definition parameters** (`EmitFunctionProlog`;
  `Cg::class_b_prolog_params`). Only a direct pointer parameter at
  offset 0 is affected.

## Per attribute

- **`no_stack_protector`**: removes `ssp` / `sspstrong` / `sspreq` from
  the definition. It adds nothing (`SetLLVMFunctionAttributesForDefinition`).
- **`patchable_function_entry(N[, M])`**: `"patchable-function-entry"="N-M"`.
  - If M > 0, also `"patchable-function-prefix"="M"`.
  - Applies to every `StartFunction` definition: thunks and inits
    included, `_ZTW` not.
  - The attribute overrides `-fpatchable-function-entry=`; a count of 0
    suppresses it.
  - Emitted only when N != 0 and M <= N (`StartFunction`).
- **`zero_call_used_regs(kind)`**: `"zero-call-used-regs"="kind"`, also
  `"skip"`. It overrides `-fzero-call-used-regs=` (`ConstructAttributeList`).
- **`speculative_load_hardening`** / **`no_speculative_load_hardening`**:
  - The first gives `speculative_load_hardening` (`ConstructAttributeList`).
  - The second removes `-mspeculative-load-hardening`'s default
    (`getDefaultFunctionAttributes`).
- **`no_split_stack`**: removes `-fsplit-stack`'s `"split-stack"`
  (`getDefaultFunctionAttributes`).
- **`no_instrument_function`**: none of `-finstrument-functions*`'s
  `"instrument-function-entry[-inlined]"` / `"instrument-function-exit[-inlined]"`
  (`StartFunction`, `ShouldInstrumentFunction`).
- **`no_profile_instrument_function`**: `noprofile` on the definition.
- **`xray_always_instrument` / `xray_never_instrument` / `xray_log_args(N)`**
  (`StartFunction`):
  - always gives `"function-instrument"="xray-always"`, and only under
    `-fxray-instrument`.
  - never gives `"xray-never"`, always.
  - always with log_args gives `"xray-log-args"="N"`, under the flag.
  - Without an XRay attribute, the flag gives
    `"xray-instruction-threshold"`.
- **`disable_sanitizer_instrumentation`**: `disable_sanitizer_instrumentation`
  on the definition.
- **`nocf_check`** (x86 with `-fcf-protection=branch|full`): `nocf_check`
  (`ConstructAttributeList`).
- **`function_return("thunk-extern"|"keep")`** (x86 only): thunk-extern
  gives `fn_ret_thunk_extern` on the definition.
  - keep suppresses `-mfunction-return=thunk-extern`.
  - The flag also adds the module flag `function_return_thunk_extern`.
- **`cfi_canonical_jump_table`**: `"cfi-canonical-jump-table"` on the
  definition.
- **`force_align_arg_pointer`** (x86 only): `"stackrealign"` on the
  definition.
- **`flatten`**: every call in the body is `alwaysinline`, except the
  following (`EmitCall`, `CurCodeDecl->hasAttr<FlattenAttr>()`):
  - calls of `noinline` functions;
  - calls in a `[[clang::noinline]]` statement.
- **`leaf`**: `nocallback`.
- **`noduplicate`**: `noduplicate`.
- **`convergent`**: `convergent`.
  (`leaf`, `noduplicate` and `convergent` all come from `ConstructAttributeList`.)
- **`nomerge`** (function, or `[[clang::nomerge]]` statement): `nomerge` on
  each direct call (`EmitCall`).
- **`[[clang::noinline]]` / `[[clang::always_inline]]` statements**:
  `noinline` / `alwaysinline` on each call in them (`EmitCall`, `InNoInlineAttributedStmt`).
- **`not_tail_called`**: the call is `notail call` (`EmitCall`).
- **`nouwtable`**: no `uwtable` on the definition.
- **`assume_aligned(N[, O])`**:
  - Without an offset, the call's return gets `align N`; N = 0 means 2^32.
  - With an offset, after the call:
    `call void @llvm.assume(i1 true) ["align"(ptr %r, i64 N, i64 O)]`.
  - Both happen at every `-O` level (`AssumeAlignedAttrEmitter`).
- **`align_value(N)`** (parameter, or a typedef of its type): `align N` on
  the definition's parameter (`EmitFunctionProlog`).
- **`callback(...)`** (`SetFunctionAttributes`): on the `declare` / `define`:
  `!callback !A`, `!A = !{!B}`, `!B = !{i64 callee, i64 payload..., i1 false}`.
  - `__` is -1.
- **`noescape`**: `nocapture` on the parameter, at declaration, definition
  and call (`ConstructAttributeList`, from `ExtParameterInfo`).
- **`maybe_undef`**: the IR argument is `freeze`d before the call (`EmitCall`).
- **`nonnull` / `returns_nonnull`**: `nonnull` on the named direct
  pointer parameters of the definition, and on the return.
  - Not under `-fno-delete-null-pointer-checks`.
  - `nonnull`'s index list counts `this`, and may be empty (every
    pointer parameter).
- **`code_align(N)`** (loop statement): the loop's
  `!{!"llvm.loop.align", i32 N}` (`CGLoopInfo.cpp`).
- **`loader_uninitialized`**: the global's initializer is `undef`
  (`EmitGlobalVarDefinition`).
- **`omp::assume("s")`**: `"llvm.assume"="s1,s2"`, the strings of every
  redeclaration joined (`ConstructAttributeList`).
- **No IR effect at clang 19** (sema only):
  - `lto_visibility_public` and `[[likely]]` / `[[unlikely]]` at `-O0`
    (`class_b_misc_attrs.cpp`);
  - `standalone_debug` (debug info only: WP-814);
  - `coro_await_elidable[_argument]` (clang 22 only; unknown at 19).

## Flags

- `-fcf-protection` on x86 adds the module flags
  `!{i32 8, !"cf-protection-return", i32 1}` and
  `!{i32 8, !"cf-protection-branch", i32 1}`.
- The rest of each flag's effect is listed above, beside the attribute
  that overrides it. The errors are in spec/driver.md.

## Tests

- **`tests/codegen/class_b_*.cpp`**: compared exactly against clang 19 on
  both triples by ir_vs_clang.
  - The `class_b_flag_*` cases carry `//@ args:` flags.
- **`tests/conformance/dcl.attr.class-b/`**: the diagnostics (`verify`)
  and the x86-only IR.
  - The `ir-x86-*-19.cpp` cases are `expect: ir`, pinned to x86-64.
- **`crates/kiln_driver/tests/hardening.rs`**: run tests.
  - The patchable NOP sled, checked with `llvm-objdump`.
  - No stack canary under `-fstack-protector-all` for `no_stack_protector`.
  - The `zero_call_used_regs` register clearing in the asm.
  - `-finstrument-functions` calls.

## Not done (follow-ups, xfail repros)

- **Branch weights when optimizing** (`ir-likely-branch-weights-O1-19.cpp`):
  - affects `[[likely]]` / `[[unlikely]]` and `__builtin_expect`;
  - the missing pieces are `!prof` and `llvm.expect`.
- **`noescape` on a parameter of a function type**
  (`ir-noescape-function-pointer-19.cpp`):
  - clang keeps it in `ExtParameterInfo`, so calls through the pointer
    get `nocapture`.
- **clang 22's `malloc_span`** (`malloc-span-22.cpp`):
  - kiln accepts it silently (a class B row of the WP-805 triage table),
    without clang's subject and argument checks.
- **clang 22 diagnostic wording**: the `*-19.cpp` verify tests are
  `requires: clang<22`, and kiln's `-fclang-compat=22` texts for them
  are not checked.
- **Debug info**: the debug effects of `nodebug`, `artificial` and
  `standalone_debug` are WP-814's.
