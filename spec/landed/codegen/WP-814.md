# WP-814 — DWARF debug information (`-g`)

`-g` emits the debug information clang 19 emits for the same program:
the same metadata, created in clang's order, so that `kiln++ -S
-emit-llvm -g` equals `clang++-19 -S -emit-llvm -g` after `opt-19`
(only the `DICompileUnit`'s `producer:` string differs). `llc-19` turns it
into DWARF. gdb and lldb can then break, step, finish and print
variables in a kiln binary as they can in a clang binary. A construct
that kiln cannot describe yet is a hard error. Nothing is dropped
silently.

The flags are in spec/driver.md "Debug information flags", the summary
is in spec/codegen.md §5.1, and the status, statistics and performance
are in docs/status/debuginfo.md.

## Standard

The standard does not mention debug information. [intro.compliance]
leaves it to the implementation. The contract here is clang 19's
(`CGDebugInfo`, `CodeGenFunction` locations) for the DWARF 5, Linux and
`-debugger-tune=gdb` configuration. Under `-fclang-compat=22`, the IR
corpus compares the debug cases structurally only.

## IR model (`kiln_llvm`)

- **Debug records.** `DbgRecord` / `DbgRecordKind` (`function.rs:23`)
  are LLVM 19's `#dbg_declare` / `#dbg_value` records. They are attached
  before an instruction with `Function::add_debug_record`
  (`function.rs:349`) and printed on their own line before it
  (`print.rs:1419`). A function's `!dbg` attachment prints before its
  `{`.
- **Metadata nodes.** `Module::md_set_field` (`module.rs:1514`) sets one
  field of a specialized node; it is used for the forward references
  that clang fixes up later (`retainedNodes`, a compile unit's lists, a
  class's `elements`). `Module::md_replace` (`module.rs:1537`) replaces
  a placeholder in place; it turns forward-declared classes into
  definitions or declarations.

## Codegen (`kiln_codegen::debuginfo`)

- `DebugOptions` and `DebugInfoKind` (`debuginfo/mod.rs:6`, `:27`) are
  set in `CodegenOptions::debug`. `emit_with_debug` (`lib.rs:695`) also
  takes the `SourceManager`, which supplies presumed locations and the
  main buffer's MD5 (`debuginfo/md5.rs`, RFC 1321).
- **Compile unit** (`start_debug_info`, `mod.rs:225`; `finish_debug_info`,
  `mod.rs:353`). These follow clang's `CreateCompileUnit` and
  `finalize`. The language is `DW_LANG_C_plus_plus{,_11,_14}`. The kind
  is `FullDebug`, `LineTablesOnly` or `DebugDirectivesOnly`. The CU also
  records `isOptimized` (whether `-O` is above 0), `splitDebugFilename`
  under `-gsplit-dwarf`, and the `enums`, `retainedTypes` and `globals`
  lists. `DIFile`s are split against the remapped compilation directory,
  with clang's `remapDIPath` (`mod.rs:98`).
- **Types** (`types.rs`). They follow clang's `getOrCreateType` after
  `UnwrapTypeForDebugInfo` (`types.rs:134`). Kiln builds basic types,
  pointers, references, member pointers, arrays (including flexible
  arrays), function types, enums, typedefs, `decltype(nullptr)`,
  complex, vector and `_BitInt` types, and classes. Classes carry their
  fields, bit-fields, static members (`DW_TAG_variable` at DWARF 5),
  bases (including virtual ones), methods (with `DIFlag*`, virtuality
  and `containingType`), `_vptr$X`, template parameters and anonymous
  unions. Classes are homed as clang does under `-fno-standalone-debug`:
  - by the key function or vtable;
  - by constructor homing at the default `Constructor` kind;
  - otherwise by full definition only where required (`di_home_class`,
    `types.rs:601`; `di_can_home`, `:581`; `di_omit`, `:569`, which
    `[[clang::standalone_debug]]` overrides as clang's
    `shouldOmitDefinition` does).
  A class that is never completed becomes a `DIFlagFwdDecl` declaration
  at the end of the unit.
- **Functions** (`func.rs`). `di_fn_start` (`func.rs:35`) creates the
  `DISubprogram`, including the linkage name, the declaration for
  methods, `DIFlagPrototyped`, `DIFlagAllCallsDescribed` above `-O0`,
  `spFlags` and the template parameters. Thunks and `nodebug` functions
  get artificial or no locations, as in clang. The function also gets
  the prologue-end location. Parameters, `this`, the VTT, the sized
  `delete` size and locals each get a `DILocalVariable` and a
  `#dbg_declare` (`di_declare`, `func.rs:162`). The NRVO flag is set
  under `-O0`. `di_finish_function` (`func.rs:484`) places the return
  location on the closing `}` or the single return, following clang's
  `EmitReturnBlock` / `NumSimpleReturnExprs` rule.
- **Globals.** `di_global_var` (`func.rs:320`) emits a global, static
  local, static member or variable template; `di_const_ref`
  (`func.rs:383`) emits a referenced constant (clang
  `EmitGlobalVariable(VD, APValue)`).
- **Locations** (`stmt.rs`, `mod.rs:403`–). These follow clang's
  `EmitStopPoint`:
  - for each statement, at its begin location;
  - for loop increments, conditions, `switch` cases and `return`.

  Expression locations follow `ApplyDebugLocation(CGF, E)` and use
  clang's `getExprLoc` (`stmt.rs:16`). The other location rules are:
  - lexical blocks for compound statements and the scopes of `if`,
    `for`, `while`, `switch` and range-`for`;
  - artificial (line 0) locations for cleanups and landing pads;
  - `llvm.loop` start and end locations (`di_loop_locs`, `stmt.rs:171`);
  - catch parameters;
  - the `this` adjustment in thunks.

## Driver

`DebugFlags` (`kiln_driver/src/debug_flags.rs`) handles the flag list
(spec/driver.md). `codegen_cmd` sets `DebugOptions` from it. Under any
`-g` it also passes `llc` the `-debugger-tune=gdb` flag, plus
`-split-dwarf-file=` / `-split-dwarf-output=` under `-gsplit-dwarf`.
Under `-gz` it compresses the object with `objcopy` and passes `-gz=` to
the link.

## Deviations (follow-ups)

Each item below is a hard error (E) or a documented difference (D) from
clang 19, never a silent wrong answer about a construct kiln claims to
describe. docs/status/debuginfo.md tracks them.

- E: a non-integral template value argument that does not lower to an
  IR constant (`types.rs:1175`). Pointers, functions, member pointers,
  floating-point and class-type values are described as clang does
  (`value: ptr @g`, `value: %struct.S { ... }`).
- D: a class template specialization with a floating-point argument is
  named `T<1.5e0>`, where clang 19 prints `T<1.500000e+00>` (its
  `GetApproxValue`); the name comes from kiln's canonical argument
  printer (`types.rs:535`).
- E: template template arguments other than a plain template name (a
  pack expansion of one), at `types.rs:1207`.
- E: SVE and other target builtin types, at `types.rs:340`.
- D: `defaulted: true` on template parameters. kiln's AST does not
  record whether an argument came from a default (`types.rs:1128`).
- D: `using` declarations and directives emit no `DIImportedEntity`. The
  compile unit's `imports` list stays empty (`mod.rs:382`).
- D: `__cxx_global_var_init` and the other synthesized functions
  (global initializers, `__tls_init`, atexit stubs) get no
  `DISubprogram`.
- D: structured bindings get no `DILocalVariable`s (clang describes
  each binding over the hidden object with a `DW_OP_plus_uconst`
  offset), so a debugger cannot print `x` of `auto [x, y] = ...`.
- D: labels emit no `DILabel`.
- D: a variable-length array local gets no `DILocalVariable`, and its
  type has `count: -1` where clang describes the bound with an
  artificial `__vla_expr` variable (`types.rs:363`).
- D: statement end locations are known only for compound and loop
  statements (`stmt.rs:82`), so a few `llvm.loop` end locations and
  cleanup locations fall back to the scope.
- D: alias template specializations are unwrapped to their target.
  clang 19 names them as typedefs (`types.rs:134`).
- D: a constant referenced through `di_const_ref` uses the existing
  definition in place of clang's `DeclMustBeEmitted` (`func.rs:383`).
  Static data members with a floating-point initializer get no
  `extraData`.
- D: above `-O0`, kiln emits no declaration `DISubprogram`s for call
  sites (clang `EmitFuncDeclForCallSite`), so DWARF has fewer
  `DW_TAG_call_site` targets.
- D (not debug): `n == nullptr` with `n` of type `decltype(nullptr)` is
  emitted as `icmp eq ptr null, null`. clang folds it to `true`.
- The `tests/debuginfo` debugger tests are not in `cargo xtask test`'s
  default roots, because CI has no gdb/lldb. They run when named
  explicitly.
