# WP-641 — outline runs of statements out of an oversized function

## Symptom

One function performing thousands of bindings, each a full-expression
whose temporaries need EH cleanups (a generated registration function:
`m.def(...); m.def(...); ...`), takes minutes in `opt -O2`. The
largest TU of a reflection-heavy codebase spent 250 s of its 264 s `-O2 -c` in
LLVM on one such function, 92,547 instructions and 6,455 landing pads.
clang 19 emits the same shape and takes longer. The cost is not in
kiln's IR: JumpThreading and MemCpyOpt are super-linear in one function's
size. JumpThreading merges each block into its only predecessor and
moves the accumulated block (headed by the entry block's thousands of
allocas) at each merge. MemCpyOpt's MemorySSA updates walk the same
chain.

## Rule

While optimizing (`-O1` and above), a compound statement whose direct
statements include at least **256** (`outline::MIN_STMTS`) *outlinable*
expression statements is emitted with its runs of outlinable statements
moved into helpers (crates/kiln_codegen/src/outline.rs,
`Cg::emit_stmt_list`):

- A *run* is a maximal sequence of consecutive outlinable statements of
  the compound. A run shorter than 4 (`MIN_RUN`) stays inline. A longer
  run is split into `ceil(len / 32)` (`CHUNK`) chunks of balanced size,
  each emitted as one helper and replaced by one call to it. Every other
  statement (declarations, labels, `case`, control flow, a nested
  compound) is emitted as before, between the calls. Nested compounds
  are judged on their own statements.
- An expression statement is *outlinable* when it contains a call or a
  construction (`CallExpr`, member or operator call, construct or
  temporary-object expression, `new`, `delete`, `throw`). A statement of
  plain arithmetic on locals stays inline, where SROA keeps the locals
  in registers. It must also contain none of:
  - a statement expression, label address, `co_await`/`co_yield`, splice,
    user-defined literal, or a construct that is still dependent or
    unresolved;
  - a call of `__builtin_alloca`/`__builtin_alloca_with_align`,
    `__builtin_va_start`, `__builtin_frame_address`,
    `__builtin_return_address`, `__builtin_object_size` or
    `__builtin_dynamic_object_size` (each is bound to its caller's frame,
    or sees a parameter instead of the caller's object);
  - a call of a function that returns twice (`setjmp`, `_setjmp`,
    `sigsetjmp`, `__sigsetjmp`, `savectx`, `vfork`, `getcontext`, by
    name as in clang).

  A structured binding's name is looked through to its binding
  expression.
- Outlining never applies inside these functions:
  - coroutines;
  - constructors and destructors;
  - a lambda call operator with an explicit object parameter;
  - a naked function, or an `optnone` one;
  - a function with an inherited-constructor argument;
  - a function with a VLA bound, an open conditional, an opaque-value
    or array-init-index context live;
  - a function emitted at `-O0`.

**The helper.** `<parent>.stmts.<n>` (n counts from 0 per parent
function), `internal` linkage, `void` result. Its parameters are one
`ptr nonnull noundef` per local of the parent that the chunk names, in
first-reference order, then `this`, then the closure object of a lambda.
A local keeps its storage in the parent, so a later statement and a
cleanup see what the helper wrote. The helper gets the parent's
definition attributes with `noinline`. It is `nounwind` exactly when
nothing in it can throw, and `noreturn` when no path through it returns,
in which case the call is followed by `unreachable`. Temporaries, their
cleanups, their landing pads and their lifetime markers live inside the
helper. An exception leaves it after its own temporaries are destroyed and
reaches the call, an `invoke` to the parent's landing pad for the
parent's live cleanups. So the order of destruction is the inline one
([except.ctor]/1-2). A statement in a helper cannot be a jump target,
since labels and `case` labels are not expression statements, so
`goto`/`switch` bypass is unaffected.

**Below the threshold the IR is byte-identical** to the emission before
WP-641. No symbol a program can name changes. The helpers are the only
new definitions, and their `noinline` keeps LLVM from rebuilding the
large function before its function passes run (an `alwaysinline` helper
would undo the split).

**Threshold.** Measured with `bench/frontend/registration-wide-obj.cpp`
(see "Tests") shortened to N bindings, `opt-19 -O2` wall time of the
function emitted inline and outlined:

| bindings | inline `opt` | outlined `opt` |
|---:|---:|---:|
| 128 | 0.17 s | (below the threshold) |
| 256 | 0.39 s | 0.34 s |
| 512 | 1.09 s | 0.66 s |
| 1,024 | 3.45 s | 1.35 s |
| 2,000 | 18.1 s | |
| 4,000 | 91 to 116 s | 6.2 s |

Below a few hundred statements, inline and outlined differ by milliseconds.
256 keeps every ordinary function, and every test in the corpus, on the
old path.

## Tests

- `tests/conformance/except.ctor/run-wide-function-unwind-O2.cpp` (`-O2`
  run test). A function of 300 binding statements, each building two
  temporaries, throws from a chosen temporary. The event log (construction,
  destruction and the enclosing block's locals) is compared with the one
  a loop over the same statements produces. Further cases cover a member
  function, a lambda capturing `this` and a local by reference, and
  `switch` cases and `goto` jumping between runs of outlined statements.
  It passes unchanged at `-O0` (no outlining) and under clang 19.
- `bench/frontend/registration-wide-obj.cpp` (`mode: obj`, `-O2`): 4,000
  bindings in one function. Its record is in
  `bench/baselines/frontend.json`. The new `obj` bench mode is
  `-c -o /dev/null` (spec/bench.md).
- The measurements, including the phase-1 IR-surgery table and the
  production A/B, are in docs/status/perf-reflection.md,
  "WP-641: shrinking the registration function".
