# WP-1389 — `-g`: complete-definition-required and deduced using-declarations

WP-1365 left two documented differences from clang at `-g`: kiln defined
every class limited debug info did not otherwise omit, where clang
declares a class the unit never required complete; and a
using-declaration of a function with a deduced return type was decided
by declaration order instead of clang's emission point.

## Rule: declaration or definition

At the reduced kinds (`-g`'s default `Constructor` and
`-fno-standalone-debug`'s `Limited`) kiln follows clang 19 and 22's
`shouldOmitDefinition` for C++, in order:

1. A class this unit never required complete is a `DIFlagFwdDecl`
   declaration.
2. A dynamic class follows vtable homing (WP-1372).
3. A required class that is an explicit instantiation declaration
   (`extern template`) with a member function defined in the class
   template (`hasExplicitMemberDefinition`) is a declaration.
4. Under `Constructor`, a class with a user-provided non-trivial
   constructor that this unit does not emit is a declaration
   (constructor homing, as before).

`-fstandalone-debug`, `-fno-limit-debug-info` and
`[[clang::standalone_debug]]` keep every definition; C structs are always
definitions.

"Required" is clang's `isCompleteDefinitionRequired`: one bit per class
definition, `DefinitionBits::COMPLETE_DEFINITION_REQUIRED`
(`kiln_ast/src/decl.rs`), set monotonically by sema
(`Sema::note_complete_required`, `templ/class.rs`) at the places clang's
`RequireCompleteType` succeeds:

- `require_complete` and every caller of `instantiation_fails`
  (variables, member access, `sizeof`, conversions, casts, `new`,
  exception types, base classes, ...); a nested-name-specifier
  (`&M::y`, `T::f`), including an out-of-line member definition;
- constructor initialization (`use_ctor`), the call of a class object,
  an anonymous struct or union member, an implicitly defined special
  member (a trivial `x = y` defines `operator=`), the coroutine traits,
  promise and handle lookups, and `FindInstantiatedDecl`'s completion of
  an instantiated class (a member named in an instantiated body); a
  class still being defined is not complete and stays unmarked, as
  clang's `isBeingDefined` check skips it;
- every closure type (clang describes closure types in full wherever
  they appear).

A completeness query (`is_complete`, `require_complete_silent`,
`require_complete_unnoted`) never sets it, so a class named only through
a pointer, a reference or a typedef stays a declaration. The
structured-binding `tuple_size` / `tuple_element` lookups use clang's
`isCompleteType`-first shape and do not mark a complete trait.

The bit is set after the closing brace too, and a module image does not
carry it (an importing unit marks its own uses). Without `-g` nothing
reads it: the IR is unchanged, and the six-unit measurement in
docs/status/debuginfo.md shows no compile-time or peak-RSS change at
`-g`.

## Rule: deduced-return-type using-declarations

clang emits a namespace-scope using-declaration when its whole top-level
declaration (a namespace or a linkage specification) is handed to
codegen, and a block-scope one when its function is emitted: at the end
of the function's top-level declaration, or at the end of the unit for
a deferred body (inline, internal linkage, an instantiation). The
return type is deduced by then exactly when the definition is in that
top-level declaration or an earlier one; otherwise clang emits nothing.
`undeduced_at` (`debuginfo/imported.rs`) compares top-level
declarations the same way.

## Not done

Key instructions (clang 22's default above `-O0`) are scoped in
docs/status/debuginfo.md "Key instructions" and not implemented. The
`-include-pch` imported-entity difference stays documented there.

## Tests

- `tests/codegen/debug_class_decl.cpp`: pointer-only and typedef-only
  classes are declarations; member access, a nested-name-specifier
  member pointer, a variable, a call of a class object, an implicit copy
  assignment and a closure are definitions; an `extern template`
  specialization with an in-class member is a declaration.
- `tests/codegen/debug_imported_deduced.cpp`: both orders at namespace
  scope, in a linkage specification and at block scope (a non-inline
  function, one whose definition follows in its namespace, an inline
  function, a local class's member).
- Both are byte-exact against clang 19 (`ir_vs_clang`, aarch64 and
  x86_64) and structurally equal under clang 22, as are the other
  `debug_*.cpp` cases.
- `tests/debuginfo/class_decl_two_units.cpp`: a class defined in a shared
  header, only used through a pointer in the test's unit, is a
  declaration there; gdb's `ptype` / `print *w` and lldb's
  `frame variable *w` complete it from the other unit (kiln, clang 19,
  clang 22).
