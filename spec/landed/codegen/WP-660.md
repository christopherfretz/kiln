# WP-660 — The x86 intrinsic and CPU tables as plain data (start-up relocations)

Extends spec/landed/codegen/WP-630.md "1:1 intrinsics" and
spec/landed/driver/WP-630.md "Tables" (the formats of the two tables).
The measurements and the A/B are in
docs/status/perf-reflection.md "WP-660: x86 tables and the
remaining start-up relocations". Nothing observable changes: the x86
lowering table, the `-march=` CPU features and predefined macros, and the
feature implications are the rows WP-630 generated, and every lookup
answers as before.

## The cost it removes

kiln is a position-independent executable, and every `&'static str` or
`&'static [T]` in a `static`/`const` table costs one `R_*_RELATIVE`
relocation (24 bytes of `.rela.dyn`) that the loader applies at every
start, dirtying the page of `.data.rel.ro` it lands in. WP-652 and
WP-653 made the x86 and NEON builtin tables plain data; three tables
were left:
- `kiln_codegen::x86_intrinsics::MAP`: 1,129 rows of four strings and a
  `TargetMem` (72 bytes each), 4,480 relocations, 81 KB of
  `.data.rel.ro`;
- `kiln_driver::x86_targets::CPUS` (72 CPUs: name, features, defined
  macros with values, undefined macros) and `IMPLIES` (118 features and
  their implications): 6,728 relocations, 108 KB of `.data.rel.ro`.

## Layout

Both files stay `@generated`, and both generators gain or extend
`--reemit`: rewrite the file from its own rows (either layout) without
probing clang. The change was made that way, and parsing the old file and
the new one gives the same rows.

**`x86_intrinsics.rs`** (`scripts/gen-x86-builtins.py`):
- `STRS: &str`: the builtin names in row order, then each distinct
  intrinsic, return-type and parameter-types string once (73,764 bytes);
- `MAP: [Packed; 1129]`, sorted by builtin name: per row the `u32` offset
  and `u8` length in `STRS` of the name, intrinsic, return type and
  parameter types, and the `TargetMem` (24 bytes a row, no pointers).

**`x86_targets.rs`** (`scripts/gen-x86-targets.py`; the decoder is part
of the generated file):
- `STRS: &str`: each distinct feature, CPU and macro text once (3,312
  bytes);
- `TEXT: [(u16, u8); 368]`: the offset and length of each text in
  `STRS`; everything else names a text by its index here;
- `LISTS: [u16; 6230]`: text indices, each distinct list once: a CPU's
  features (sorted), its defined macros as (name, value) index pairs, its
  undefined macros, and each feature's implications (sorted);
- `CPUS: [Row; 72]` (name, then `(start, len)` in `LISTS` of the
  features, defines and undefs; 14 bytes) and `IMPLIES: [Implies; 118]`,
  sorted by feature name (name and `(start, len)`; 6 bytes).

Every index fits its integer; the generator fails rather than truncate.
The rows are in `.rodata`: one relocation per table for `STRS` (and the
slices the decoder forms at run time), nothing dirtied at start-up.

## Lookups

`kiln_codegen::x86` (re-exported for its test as
`kiln_codegen::x86_intrinsic_table`):
- `Map { name, intr, ret, params, mem }` is returned **by value**;
- `by_name(name) -> Option<Map>` is a binary search over the rows,
  comparing names sliced from `STRS` (it was a binary search over
  `MAP`);
- `rows()` iterates the decoded rows in order, `len()` counts them.

`kiln_driver::x86_targets` (now `pub`):
- `cpu(name) -> Option<Cpu>` (linear find, as before) and `cpus()`;
  `Cpu { name, features: List, define: Pairs, undef: List }`, where `List`
  and `Pairs` are `Copy` views of `LISTS` that iterate `&'static str` and
  `(&'static str, &'static str)` and answer `len`, `is_empty` and (`List`)
  `contains`;
- `implies(feature) -> Option<List>` (binary search) and
  `implications()` (every `(feature, List)` in order).

`features.rs` reads through these: `-march=<cpu>` collects the CPU's
features as before, `x86_cpu_macros` its defines and undefs,
`target("...")` the implications. No allocation is added. The `-march=`
path (`features::resolve` plus `x86_cpu_macros`, release) takes 3.4 µs
for `skylake-avx512` and 7.9 µs for `diamondrapids`, the largest CPU
(median of 201).

## Tests

- `crates/kiln_codegen/tests/x86_intrinsic_table.rs`: every row decodes
  and `by_name` finds it, there are 1,129 rows, the names are sorted and
  distinct, an FNV-1a hash of the whole table equals the one computed from
  the pre-WP-660 file, and eleven old literal rows match field by field;
  names outside the table are absent.
- `crates/kiln_driver/tests/x86_targets_table.rs`: 72 CPUs and 118
  implications decode, lists are sorted, every CPU feature has an
  implication entry, each implication includes the feature itself and is
  closed; whole-table FNV-1a hashes of `CPUS` and `IMPLIES` equal those
  of the pre-WP-660 file; `nocona`, `skylake-avx512` and `diamondrapids`
  rows and seven implications are pinned; unknown names are absent.
