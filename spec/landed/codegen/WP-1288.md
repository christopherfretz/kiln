# WP-1288 — C-mode codegen: the GNU `?:` ICE, GNU builtins, NEON table lookups, `__builtin_constant_p`, `_Complex` asm operands

Extends spec/codegen.md §7 (builtins) and the AArch64 NEON section.

## The GNU binary conditional

- `a ?: b` binds `a` to an `OpaqueValueExpr` and reuses it as the true
  arm. When `a` is a zero-extended `i1` (a C `&&`, `||`, relational or
  `!` expression), the int-to-bool peephole of the condition erased the
  `zext` that the binding still referenced, and FIR lowering panicked
  ("phi operand %N is defined").
- A value bound to an `OpaqueValueExpr` is now kept out of the peephole
  (clang `protectFromPeepholes`).
- Tests: `tests/c/expr/gnu-binary-conditional-logical{,-O2}.c`,
  `tests/conformance/expr.cond/gnu-binary-conditional-logical{,-O2}-run.cpp`
  (the WP-1282 repros, flipped). An audit of the other phi-over-short-circuit
  shapes (`&&`/`||` conditions, `?:` with `throw` and `void` arms,
  statement expressions in conditions) is in
  `short-circuit-phi-shapes{,-O2}` in both directories.

## GNU builtins

- `__builtin_extract_return_addr(p)` and `__builtin_frob_return_addr(p)`
  return `p`: AArch64 and x86-64 Linux encode nothing (clang
  `TargetCodeGenInfo::decodeReturnAddress`/`encodeReturnAddress`).
- `__builtin___clear_cache(b, e)` is `call void @llvm.clear_cache(ptr b,
  ptr e)`.
- None of the three is a constant expression (spec/oven.md, beside
  `__builtin_return_address`).
- Tests: `tests/codegen/builtins_return_addr_codecs.cpp`,
  `tests/conformance/ext.gnu.builtins/return-addr-codecs-{run,not-constant}.cpp`.
- The other "undeclared identifier" builtins of gcc.c-torture that clang
  19 also rejects stay unsupported, as in clang: `__builtin_setjmp` /
  `__builtin_longjmp`, `__builtin_exit`, the `*_overflow_p` family,
  `__builtin_shuffle`, `__builtin_stack_save`, `__builtin_memcmp_eq`,
  `__builtin_cexpi`, `__builtin_va_arg_pack` and the stdio builtins
  (`__builtin_puts`, `__builtin_fputs`, ...).

## NEON table lookups

clang 19 `EmitAArch64TblBuiltinExpr` (`neon.rs`):

- `vqtbl{2,3,4}[q]`: `llvm.aarch64.neon.tbl{N}.v{8,16}i8` of the `N`
  `<16 x i8>` tables and the index.
- `vqtbx{1,2,3,4}[q]`: `llvm.aarch64.neon.tbx{N}.v{8,16}i8` of the
  fallback, the tables and the index.
- `vtbl{1,2,3,4}`: the 64-bit tables are concatenated in pairs into
  `<16 x i8>` tables, the last one padded with zero (clang
  `packTBLDVectorList`), then `tbl{P}.v8i8(pairs, i)`.
- `vtbx{2,4}`: `tbx{k/2}.v8i8(a, pairs, i)`.
- `vtbx{1,3}`: the `tbl` of the padded pairs, then `a`'s byte where
  `i >= 8k`: `or (and (sext (icmp uge i, 8k)), a), (and (not mask), tbl)`.
- Tests: `tests/conformance/target.neon/ir-tbl-tbx-family-19.cpp` (IR
  against clang 19; clang 22's `arm_neon.h` spills its temporaries
  differently, so there is no clang-22 sibling) and
  `tbl-tbx-family-run.cpp` (every form, run).

## `__builtin_constant_p` after the frontend

- When the frontend cannot fold the operand (spec/oven.md
  `EvaluateBuiltinConstantP`), codegen asks LLVM, as clang `CGBuiltin`:
  - an integer, enumeration or floating operand without side effects
    (`may_have_side_effects`) is `zext (call i1
    @llvm.is.constant.<ty>(x)) to i32`, so the answer becomes 1 once
    inlining or constant propagation makes `x` a constant;
  - any other operand, or one with side effects, is `0`, unevaluated.
- `llvm.is.constant.*` is declared `convergent nocallback nofree nosync
  nounwind willreturn memory(none)` (`intrinsics::is_constant`).
- Tests: `tests/codegen/builtins_constant_p_runtime.cpp` (IR) and
  `tests/conformance/ext.gnu.builtins/constant-p-after-inlining-run.cpp`
  (-O2, run). gcc.c-torture execute/bcp-1.c and builtin-constant.c pass
  at -O0 to -O3.

## `_Complex` inline-asm operands

- clang `EmitAsmStmt` returns an output by value only when its type has a
  scalar or aggregate evaluation kind, so a `_Complex` output is indirect
  (`=*r`, `elementtype({ T, T })`), as a memory output (`asm.rs`).
- A `_Complex` input, or the input half of `+r`, is not a scalar for
  `EmitAsmInput`/`EmitAsmInputLValue`: an integer load of its size when
  that is at most 64 bits and a power of two, else its address (`*`).
- kiln returned a `_Complex long long` by value as an `i128` tied to a
  `{ i64, i64 }` input, which crashed `llc` (gcc.c-torture
  compile/20000804-1.c). It now gets clang's IR and clang's backend error
  ("don't know how to handle tied indirect register inputs").
- Test: `tests/codegen/asm_complex_operand.cpp`.
