# WP-1008 — Constant emission of initializers (clang's choices)

WP-941's fmt coverage comparison found two places where kiln seemed to
decide differently from clang whether an initializer is evaluated at
compile time. This file records clang's rules, what kiln did, the fix
and how it was validated.

## Constant emission of initializers

clang 19 CodeGen (and clang 22, unchanged) decides with these rules.
None of them depends on the optimization level: `-O2 -Xclang
-disable-llvm-passes` gives the same choices as `-O0`.

- **Local variables** (`CGDecl.cpp` `EmitAutoVarAlloca` /
  `EmitAutoVarInit`).
  - `IsConstantAggregate`: an array or record variable whose initializer
    is constant, i.e. the variable is `constexpr`, or its type is POD and
    `Expr::isConstantInitializer` holds. `isConstantInitializer` walks
    init lists, trivial and constexpr constructor calls, casts and
    literals, and otherwise falls back to `isEvaluatable` (an rvalue
    evaluation, not in a constant context, without side effects), which
    does call constexpr functions. So `std::tm t = make_tm(...)` (POD,
    from a constexpr call) is constant.
  - An initializer `isTrivialInitializer` accepts (a trivial default
    constructor call) emits nothing. Otherwise such an aggregate, or a
    variable `mightBeUsableInConstantExpressions` (`constexpr`, or a
    `const` non-volatile integral or enumeration one), tries the
    constant: `ConstantEmitter::tryEmitAbstractForInitializer` →
    `tryEmitPrivateForVarInit` (`CGExprConstant.cpp`). That runs
    `ConstExprEmitter` on the initializer, then falls back to the value
    `VarDecl::evaluateValue()` (`EvaluateAsInitializer`) computed. A
    non-aggregate constant is one store.
  - A constant goes through `emitStoresForConstant`: one store for a
    scalar or vector; memset 0 plus stores
    (`shouldUseBZeroPlusStoresToInitialize`: all zero, or more than 32
    bytes with at most 6 non-zero stores); a bytewise memset (more than
    32 bytes, `isBytewiseValue`); else a memcpy from the
    `private unnamed_addr constant @__const.<fn>.<var>`. A `const` local
    is promoted to a global only under `-fmerge-all-constants` (off by
    default), and `shouldSplitConstantStore` splits only the
    `-ftrivial-auto-var-init` pattern stores.
  - Anything else (a non-POD class, a non-constant initializer) is
    emitted as an expression: `EmitExprAsInit` → `EmitAggExpr` /
    `EmitCXXConstructExpr` / a scalar store.
- **Array init lists** (`CGExprAgg.cpp` `AggExprEmitter::EmitArrayInit`,
  for an `InitListExpr` or `CXXParenListInitExpr` of array type wherever
  it is emitted as an aggregate: a non-POD local's member array, an
  `std::initializer_list` backing array, a temporary, a member
  initializer, a `new` initializer). When the explicit elements are more
  than 16 bytes (`NumInitElements * elementSize > 16`) and the element
  type is trivially copyable, clang tries
  `ConstantEmitter::tryEmitForInitializer` on the list. That emits each
  element with `tryEmitPrivateForMemory`, which falls back to
  `EvaluateAsRValue` (not a constant context, side-effect free). On
  success the list is one `memcpy` from a `private constant` global named
  `constinit` (uniqued `.N`; not `unnamed_addr`; aligned as the array
  type), and no element is emitted. On failure every element is emitted
  in order, then the filler loop.
- **Record init lists** never try a constant (the code is `#if 0` in
  `VisitInitListExpr`): a non-POD record list is emitted member by
  member even when every member is constant.
- **Constructor calls** (`EmitCXXConstructExpr`) never constant-fold a
  constexpr constructor. They elide trivial default constructors
  (zero-initializing first when the construct expression says so), turn
  trivial copies and moves into `EmitAggregateCopy`, and otherwise call
  the constructor, at `-O0` and `-O2` alike. A constexpr constructor is
  evaluated only through the paths above: a `constexpr` variable, a POD
  variable's `isConstantInitializer`, an array element in a constant
  list, or a static or thread-local variable's constant initializer
  (`tryEmitForInitializer` in `EmitGlobalVarDefinition`).

## What kiln did

- Locals already followed `EmitAutoVarInit` (§7y, `Cg::emit_var_init`,
  `Cg::stores_for_constant`; the `fold.rs` prepass folds a `constexpr`
  variable, a `const` integral one, and a POD array or record).
- **Case 1 (lacked a rule).** The fmt chrono-test `make_tm` difference is
  not the local `std::tm tm = make_tm(...)` (kiln constant-emits that, as
  clang does) but `std::vector<std::tm> tm_list = {make_tm(...), ...}`: an
  `std::initializer_list` backing array of seven `std::tm` constants. clang
  memcpies it from `@constinit` and never calls `make_tm` there; kiln
  emitted the seven calls. Kiln had no `EmitArrayInit` constant path.
- **Case 2 (the same missing rule; `basic_format_args` itself matches).**
  `basic_format_args`-style classes (a constexpr default constructor, a
  constexpr constructor from an argument store, one from a pointer and a
  count; as locals, temporaries, arguments, returns and `const` locals)
  give clang's IR on the base commit: kiln does not fold a constexpr
  constructor clang calls. In the fmt 12.1.0 test and library TUs (29
  compile with both compilers at `-std=gnu++20 -O0`) the calls to the
  `basic_format_args` constructors are equal in every TU, and so are the
  `-fprofile-instr-generate` function names of chrono-test, printf-test,
  base-test and format-test. What does differ is again an array list:
  an array of such objects (`Args a[2] = {Args(), Args()}`) or an
  `std::initializer_list<std::optional<int>>` is a `@constinit` copy in
  clang, while kiln called the constexpr constructors element by element
  (the opposite direction from the WP-941 note). That is the rule above.

## Effect on fmt 12.1.0 (`-O0`, defined functions and `@constinit`)

- chrono-test: `make_tm` is no longer defined (it has no run-time use
  left), and the `@constinit` `[7 x %struct.tm]` matches clang.
- std-test: five `std::optional<int>` / `_Optional_payload` in-place
  constructors are no longer defined; the `@constinit` matches.
- ranges-test (3) and ranges-odr-test (1) gain clang's `@constinit`s.
- Every other TU is unchanged. The remaining differences in defined
  names are unrelated (unnamed-enumeration and lambda-parameter
  mangling, libstdc++ `leap_second` comparison operators in chrono-test).

## The fix

- `fold.rs`: the prepass collects array lists of trivially copyable
  elements with their nearest covering initializer (an initializer the
  prepass folds as a whole: a static, `constexpr` or POD local array or
  record, or an outer array list). After the other folds, a list whose
  explicit elements are more than 16 bytes (`kiln_abi::type_size_align`)
  and that is not covered by a folded initializer is folded once with
  `Oven::fold_rvalue` (not a constant context, so
  `__builtin_is_constant_evaluated()` is false, as in clang). A value
  that designates an automatic object is dropped. No expression is
  evaluated twice: a list already tried by the main candidate loop, or
  under a folded or tried cover, is skipped, and sema's results for
  `constexpr` variables are reused as before.
- `expr.rs` `Cg::array_init` (clang `EmitArrayInit`): when the list has a
  fold, `array_init_from_constant` emits the constant as a `private`
  (not `unnamed_addr`) constant `@constinit` at the array's alignment and
  copies it with `Cg::agg_copy`.
- `class.rs`: `is_trivially_copyable` (array elements stripped; a record
  reads its definition's `TRIVIALLY_COPYABLE` bit).

## Validation

- `tests/codegen/array_init_constinit.cpp` (ir_vs_clang, exact under
  clang 19 and structural under clang 22, aarch64 and x86_64): an
  `initializer_list` of constexpr calls, a POD local, constexpr
  constructor elements, exactly 16 bytes (element-wise), a member array
  with a filler, non-constant and non-trivially-copyable elements,
  nested arrays, `__builtin_is_constant_evaluated()`, a member
  initializer and a lifetime-extended temporary.
- `tests/conformance/dcl.init.list/array-constant-emission-run.cpp`: the
  constant-emitted lists still behave, including a mutable local array
  modified after its constant initialization and a list re-evaluated per
  call with a side effect.
- Compile time (`harness` profile, best of 3, base 723a7700c against
  this branch, `-O0`): a generated stress TU of 9000 array lists (6000
  constant, 3000 not; `std::initializer_list<int>` and `int[8]`
  temporaries) 0.42 s / 51 MiB before, 0.39 s / 54 MiB after;
  `bench/frontend/trial-folds.cpp` 1.52 s → 1.53 s;
  `bench/frontend/constant-table-emit.cpp` 0.60 s → 0.61 s;
  `bench/oven/table.cpp` and `sort.cpp` unchanged (0.11 s, 0.20 s);
  fmt chrono-test `-c` 3.72 s → 3.71 s, format-test 3.63 s → 3.71 s.
  Peak RSS moves by at most 3 MiB.
