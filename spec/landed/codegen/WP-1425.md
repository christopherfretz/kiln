# WP-1425 — One body per function at explicit instantiation definitions

Found building a large open-source code base at `-g -O0`: every member
function of a class template explicitly instantiated in a reopened
namespace, after an explicit instantiation declaration, came out as one IR
function holding two copies of its body, the second after the first
`ret`, each with its own `DISubprogram`. LLVM's verifier rejected the
debug info ("!dbg attachment points at wrong subprogram for function",
"conflicting debug info for argument") and the backend dropped all of the
module's debug info. Without `-g` the module verified (the second copy is
unreachable).

## Cause

Sema records what an explicit instantiation definition defines under the
declaration that precedes it in its lexical context
(`TemplateTables::explicit_member_insts`), or under the context itself
when that context has no member yet. Codegen's walk asked for the key of
a namespace twice: at the start of the namespace's members
(`emit_members`) and right after the namespace in the enclosing context.
So an explicit instantiation that was the first declaration of a
namespace block (`namespace n { template class X<int>; }`), or the first
one after a namespace (`namespace a { ... } template int X<int>::f();`),
was emitted twice. `emit_global_fn` emits a definition that is not
discardable at once, without checking for a body, so the second emission
appended a second body. Members explicitly instantiated together with
their class (non-virtual and virtual member functions, member functions
of nested classes, member explicit instantiations) were affected.
Structors (the structor path checks for a body), static data members and
variable templates (the variable already had an initializer) and vtables
(emitted once per class) were not.

Both copies came from the same declaration (`emit_global_fn(def)` both
times; an explicitly specialized member is skipped on both walks), so they
were identical and only the first ran: invalid debug info, not wrong code.

## Rules

- **Key.** A namespace, linkage specification or export block as the key
  means "right after the block". In a block with no member yet the key is
  the declaration before the block in its own lexical context,
  recursively while the block is its context's first member; only the
  translation unit's start is keyed by the context itself
  (`Sema::explicit_inst_anchor`). That is the same point of the walk, and
  the class-completion epoch is the one of the enclosing top-level
  declaration, so a class the explicit instantiation completes is
  complete where its members are emitted.
- **Once per key.** `Cg::emit_explicit_member_insts` hands each key over
  once (`explicit_insts_done`). The walk asks for the translation unit's
  key at its start and for every other key after its declaration, also
  after a function explicitly instantiated before its template's
  definition (whose own definition is emitted at the end of the
  translation unit).
- **One body.** `gen_code_or_thunk`, the one entry point that builds a
  function body (definitions, structor variants, thunks), skips a function
  that already has a body, built or pending. Reaching it is a debug
  assertion unless the second definition is another entity's under the
  same mangled name, already diagnosed (`cg_duplicate_mangled_name`); the
  translation unit has failed then, and the second body is no longer
  appended. Structor variants that a GNU asm label gives one symbol are
  the exception, as in clang: each variant's body is built into that one
  function (`tests/codegen/asm_label_structors_vbases.cpp`).

## Audit

- Static data members, variable templates: emitted once already (the
  variable's initializer is checked); covered by the tests below.
- Member function templates (`template int X<int>::g<int>(int);`),
  function templates (`template int f<long>(long);` after `extern
  template`): the member explicit instantiation key; tested.
- Nested classes (`template struct X<int>::N;`), constructors and
  destructors (all variants), vtables and thunks: tested; structors and
  vtables were not doubled before either.
- The explicit instantiation declaration from a PCH, the definition in
  the consumer: the key is recorded when the consumer parses the
  definition, against the consumer's own member lists, so the same rule
  applies (it was doubled before too); tested. The body guard covers any
  other path, a module unit's included.

## Tests

- `tests/conformance/temp.explicit/definition-in-reopened-namespace-ir.cpp`
  (`-19` sibling): the IR equals clang's, with the explicitly specialized
  member, member templates, nested classes, a variable template, linkage
  specifications and the late explicit instantiation.
- `tests/conformance/temp.explicit/definition-in-reopened-namespace-run.cpp`:
  the explicitly specialized member's body runs, virtual functions,
  structors, nested classes and static data members once each.
- `tests/conformance/temp.explicit/definition-after-pch-declaration-run.cpp`:
  the declaration from a PCH, at `-g`.
- `kiln_driver/tests/codegen.rs` `explicit_instantiation_one_body_per_function`:
  one `ret` and one `DISubprogram` definition per `define`, and
  `opt -passes=verify` of LLVM 19 and 22 accepts the module with and
  without `-g`.
