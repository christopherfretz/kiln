# WP-1418 — x86-64 SysV: the AVX ABI level in argument and return classification

x86-64 passes and returns a vector wider than 128 bits in a `ymm`
(`zmm`) register only when the translation unit is built with AVX
(AVX-512F): psABI §3.2.3 with the AVX and AVX-512 supplements. kiln
classified every call at the no-AVX level until 1.2.0, so with AVX
enabled it passed such vectors `byval` and returned them through `sret`
where clang and GCC use registers. The classifier now follows clang's
`X86AVXABILevel`. Deviations from clang 19 and 22 (each at its `-fclang-compat`): none known.

## The level (`call::AvxLevel`, `IrTypes::with_avx_level`)

- **Rule.** The level is the translation unit's, from its feature map
  after `-march=`/`-mcpu=` and every `-m<feature>`/`-mno-<feature>` in
  command-line order (spec/driver.md "x86-64 target features"):
  `avx512f` on gives `Avx512` (native vector size 512 bits), else `avx`
  or `avx2` on gives `Avx` (256), else `None` (128). A function's
  `target("...")` attribute does not change it: clang builds its
  `TargetCodeGenInfo` once per module. kiln computes it in
  `kiln_codegen` `module.rs` `avx_level` from
  `CodegenOptions::target_features` (`AArch64`: always `None`, unused).
- **Sources read** (clang 19.1.7):
  - `clang/lib/CodeGen/CodeGenModule.cpp:266-275` (`createTargetCodeGenInfo`,
    `x86_64` case): `ABI == "avx512"` gives `X86AVXABILevel::AVX512`,
    `"avx"` gives `AVX`, anything else `None`; it is passed to both
    `X86_64TargetCodeGenInfo` and `WinX86_64TargetCodeGenInfo`.
  - `clang/lib/Basic/Targets/X86.h:341-348` (`X86TargetInfo::getABI`):
    `"avx512"` when `SSELevel >= AVX512F`, `"avx"` when `SSELevel >= AVX`
    (x86-64 only).
  - `clang/lib/Basic/Targets/X86.cpp:466-477` (`handleTargetFeatures`):
    `SSELevel` is the maximum over the module's `+avx512f`, `+avx2`,
    `+avx`, ... features, which `initFeatureMap` (lines 123-235) builds
    from the CPU's features and then the command line's, in order.
  - `clang/lib/CodeGen/Targets/X86.cpp:1195-1205`
    (`getNativeVectorSizeForAVXABI`: 512 / 256 / 128).

## Classification (`call.rs`, clang `X86_64ABIInfo`)

Transcribed with `native` = the level's native vector size and `named`
= clang's `isNamedArg` (an argument before the prototype's `...`; the
return value is named; a `va_arg` read and a call's variadic extras are
not):

- **`classify`, vectors** (clang `X86.cpp:1792`, vector arm at
  1913-1937): a vector of 128
  bits, or a named one of at most `native` bits, is SSE + SSEUP (the
  psABI's one SSE and three or seven SSEUP eightbytes, kept as Lo/Hi), except a
  256- or 512-bit vector of `__int128`, which is MEMORY
  (`passInt128VectorsInMem`, Linux). Any other vector wider than 64 bits
  is MEMORY. So a 256-bit vector passed through `...` goes in memory at
  every level.
- **Arrays** (`X86.cpp:2016-2019`): an array wider than 128 bits is
  MEMORY unless it is one element and at most `native` bits; that
  element is then classified.
- **Classes** (`X86.cpp:2111-2118`): a class wider than 128 bits is
  MEMORY at its first field unless that field is as wide as the class
  (any field, for a union) and the class is at most `native` bits. A
  class holding one 256-bit vector, through nested classes, empty bases
  or a one-element array, is therefore SSE + SSEUP under AVX; one with a
  second member (`{ f8 v; int i; }`, `{ f4 a, b; }`, `{ float a[8]; }`)
  stays in memory.
- **Bases, clang 21 and later** (clang 22 `X86.cpp:2086-2092`,
  `returnCXXRecordGreaterThan128InMem`, off at ABI compat 20 and below;
  arguments too, despite the name): after merging a base, a class wider
  than 128 bits whose base is not as wide as the class, or which is
  wider than `native`, is MEMORY. kiln follows it at `-fclang-compat=21`
  and later (`IrTypes::clang_compat`): `struct D : Empty { f8 v; }` is
  SSE + SSEUP under AVX at compat 19 and 20, MEMORY at 21 and 22, while
  `struct D : W {}` (a base as wide as the class) is SSE + SSEUP at every
  compat. Without AVX no class wider than 128 bits is in registers, so
  the rule changes nothing there.
- **`GetByteVectorType`** (`X86.cpp:2264-2296`): the IR type of an
  SSE + SSEUP value is its single element's vector type (the vector a
  wrapper holds), `<N x i64>` for a vector of `__int128`, `fp128`, or
  else `<N x double>` (a union of a vector and another member, which is
  no single-element class).
- **`IsIllegalVectorType`** (`X86.cpp:2186-2199`), used when an argument
  goes in memory (`getIndirectResult`): a vector of at most 64 bits,
  wider than `native`, or of `__int128` is passed `byval`; any other
  vector, e.g. an unnamed 256-bit vector under AVX, is passed directly
  as its IR vector type and LLVM puts it on the stack.
- **Returns** (`classifyReturnType`, `X86.cpp:2580-2706`): classified
  as named. A MEMORY vector is still returned directly
  (`getIndirectReturnResult`: not an aggregate); a MEMORY class through
  `sret`.
- **Register exhaustion** (`computeInfo`, `X86.cpp:2904-2984`): an SSE +
  SSEUP argument needs one SSE register; with none left it goes in
  memory as above.
- `_Complex`, `__int128`, `long double`, 128-bit vectors and the AArch64
  classification are unaffected. A class that is not trivially
  copyable is passed by address and returned through `sret` at every
  level. Calls through function pointers, member function pointers,
  member and static member functions, lambdas' call operators and
  virtual thunks use the same `classify_call`, so declarations, call
  sites and definitions agree.

## Varargs (`classify_va_arg`, clang `X86_64ABIInfo::EmitVAArg`)

`va_arg` classifies the type as not named (`X86.cpp:3036-3037`), so a
vector wider than 128 bits, or a class holding one, needs no register at
any level and is read from the overflow area (`EmitX86_64VAArgFromMemory`:
rounded up to its alignment, advanced by its size rounded to 8). The
IR is the same as without AVX; `ir-avx-abi-x86_64-*.cpp` pin it.

## Other conventions (checked against clang 19 and 22)

- `ms_abi` (`WinX86_64ABIInfo::classify`): no level dependence: a bare
  vector is passed and returned directly, a class wider than 8 bytes by
  address. Unchanged.
- `vectorcall` on x86-64 Linux and `sysv_abi`: the SysV classification
  above (clang delegates); match at every level.
- `regcall`: a vector argument and a class's vector members are
  classified as named SysV arguments (`classifyRegCallStructTypeImpl`
  passes `isNamedArg` true), so they follow the level; match at every
  level.

## Diagnostics

`-Wpsabi` (`cg_avx_calling_convention`) and the caller/callee mismatch
error (`cg_avx_calling_convention_mismatch`) are WP-187's and WP-1000's
(spec/codegen.md §7q). They use per-function feature maps, as clang's
`checkFunctionCallABI` does, independently of the module's level.

## Tests

- `tests/conformance/ext.vector/ir-avx-abi-x86_64-*.cpp` (shapes in
  `Inputs/avx-abi-shapes.h`): the IR equals clang's (19 and 22) with no
  AVX, `-mavx`, `-mavx2`, `-mavx512f`, `-march=haswell`,
  `-march=x86-64-v3`, `-march=x86-64-v4`, `-march=haswell -mno-avx` and
  `-march=x86-64-v4 -mno-avx512f`.
- `scripts/x86-avx-abi-matrix.py`: generated matrix of 49 types
  (vectors of every element kind and width, wrappers, mixed aggregates)
  times direct, indirect, variadic and stack-exhausted calls, in C and
  C++, under 12 flag sets, comparing every `define`, `declare` and call
  line with clang 19 and clang 22.
- `crates/kiln_driver/tests/codegen.rs` `x86_avx_abi_interop`: kiln and
  clang 19 objects call each other with 256/512-bit vectors and wrappers
  (both pairings, varargs included) and print the same values as the
  all-clang program; x86-64 hosts only, each level when the CPU has it.
- `crates/kiln_abi/src/call.rs` unit test `avx_level_from_features`.
