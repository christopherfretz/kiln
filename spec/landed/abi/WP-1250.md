# WP-1250 — dependent reflected template-ids in mangled signatures

WP-1246 taught the `^^` operand parser template-ids such as
`^^ns::operator== <T>` and found that, in a mangled signature, kiln kept
the template arguments of a dependent reflected template-id where GCC
16.1 drops them. This WP compared the two symbol by symbol, in the three
contexts that mangle a dependent reflect-expression: a decltype return
type (`d`), a parameter type through a dependent template argument (`p`)
and a requires-clause (`q`). The rule is spec/abi.md §8.14 "Dependent
reflected template-ids"; spec/reflection.md §8.3 states it with the
encoding.

## Symbols (`T = int`, `K<info>`, `nm` on each compiler's object)

GCC 16.1 (`g++-16 -std=c++26 -freflection`):

- `d(T) -> decltype(K<^^g<T>>{})`: `_Z2d1IiEDTtl1KILDmft1gEEEET_`;
  `^^ns::operator== <T>`: `_Z2d2IiEDTtl1KILDmft2nseqEEEET_`.
- `p(T, K<^^g<T>>)`: `_Z2p1IiEvT_1KILDmft1gEE`; `operator==`:
  `_Z2p2IiEvT_1KILDmft2nseqEE`; `^^ns::h<T>`: `…KILDmft2ns1hEE`;
  `^^Q::m<T>`: `…KILDmft1Q1mEE`.
- `requires(^^g<T> != ^^int)`: `_Z2q1IiQneLDmft1gELDmtyiEEvT_`, plus the
  unconstrained alias `_Z2q1IiEvT_`; `operator==`:
  `_Z2q2IiQneLDmft2nseqELDmtyiEEvT_`.
- `^^S<T>::template m<int>` and `^^T::template m<int>`, in every context:
  rejected at substitution ("'m' was not declared"), no symbol.
- `^^ns::nv<T>`: `…KILDmde2nvIS0_EEE`, the same as `^^nv<T>`'s.
- `^^vt<T>`: `_Z4p_vtIiEiT_1KILDmde2vtIS0_EEE`; `^^TT<T>`: `…ty2TTIS0_E…`;
  non-dependent `^^ns::h<int>`: `…fnN2ns1hIiEEiS0_…`.
- `^^AT<T>` (`AT = TT<T*>`): `_Z4p_atIiEiT_1KILDmta2ATIPS0_E_2TTIS2_EEE`;
  `^^F<T, int>` (`F<T, U> = TT<T>`): `…ta1FIS0_E_2TTIS0_E…`;
  `^^Arr<int, 3>` (`TT<T[N]>`): `ta3ArrIA3_iE_2TTIS0_E`; `^^D<int>`
  (`typename RC<T>::type`): `ta1D_i`.

Each lossy form collides with a distinct declaration: a TU holding
`p(T, K<^^g<T>>)` and `p(T, K<^^g<T*>>)`, `^^ns::nv<T>` and `^^nv<T>`,
`^^F<T, int>` and `^^F<T, long>`, or `f<^^D<int>>` and
`f<^^D<const int>>`, fails to assemble under g++-16 ("symbol … is
already defined").

Kiln, before and after (gcc mode; kiln mode writes `u6__info` and so
numbers later substitutions one higher, and its requires-clauses write
`LS0_tyiE`):

- function template-ids, unchanged: `_Z2d1IiEDTtl1KILDmde1gIT_EEEEES1_`,
  `_Z2p1IiEvT_1KILDmde1gIS0_EEE`, `_Z2q1IiQneLDmde1gIT_EELDmtyiEEvS0_`,
  `…desr2nsEoneqIS0_E…`, `…desr1SIS0_EE1mIiE…`, `…desr2nsE1hIS0_E…`.
- `^^ns::nv<T>`: was a "redefinition" error beside `^^nv<T>` (the parser
  dropped the qualifier of a variable template-id); now
  `…KILDmdesr2nsE2nvIS0_EEE`.
- `^^AT<T>`: was `…ty2TTIPS0_E…`, the same symbol as `^^TT<T*>`'s (two
  overloads, one symbol: a miscompile); now `…ta2ATIPS0_E_2TTIS2_E…`,
  equal to GCC's (kiln mode `…ta2ATIS0_E_2TTIPS0_E…`).
- `^^F<T, int>`, `^^D<int>`: were GCC's colliding forms in gcc mode; now
  the alias's own arguments, `…ta1FIS0_iE_2TTIS0_E…`, `ta1DIiE_i`.

## Decision

[temp.over.link]/5 makes declarations that differ only in the reflected
template-id's arguments or qualifier distinct, and their specializations
are `linkonce_odr` comdats that fold silently across TUs, so a lossy
symbol is a miscompile with no diagnostic. GCC's forms above are GCC
16.1 ABI bugs. Gcc mode matches g++-16 wherever g++-16's spelling is
injective (`^^vt<T>`, a dependent alias whose parameters its aliased
type deduces) and keeps kiln's spelling elsewhere; kiln mode always
keeps the arguments. The divergences are listed in spec/abi.md §8.14
"Known divergences from GCC 16.1".

## Code

- `kiln_abi::mangle::reflect`: a dependent `Reflectee::Type` goes through
  `reflected_type`, so an alias template-id keeps `ta`;
  `alias_args_recoverable` (each alias parameter deduced from the
  defining-type-id, [temp.deduct.type]/8; conservative) picks, in gcc
  mode, GCC's aliased-specialization arguments or the alias's own.
- `kiln_parse::reflect`: a qualified variable template-id operand records
  its qualifier (`set_template_id_qualifier`), as a qualified function
  template-id's already did, so the signature profile and the mangling
  see it.

## Tests

`tests/conformance/expr.reflect/`: `template-id-signature-mangle-run.cpp`
(the GCC-equal symbols, called by asm label from a unit),
`-mangle-divergent-run.cpp` (kiln's gcc-mode symbols where GCC's
collide), `-mangle-kiln-run.cpp` (every context in kiln mode),
`-distinct-run.cpp` (pairs GCC keeps apart, `oracle: gcc`) and
`-collide-run.cpp` (pairs GCC folds, `xfail(gcc)`); shared declarations
in `Inputs/template-id-signature*.h`. The driver's
`gcc_dependent_template_id_link` links a kiln object with a g++-16
caller and compares both compilers' definitions.

## Not done

- A dependent alias whose parameter appears only in a non-deduced
  context (`^^D<T>`): g++-16's `ta1D_N2RCIS0_E4typeE` (the aliased
  dependent type) cannot collide while the argument is dependent, but
  kiln's conservative rule writes the alias's arguments
  (`ta1DIS0_E_N2RCIS0_E4typeE`), so it does not link with g++-16.
- GCC's unconstrained compat alias beside a constrained template's
  symbol (`_Z2q1IiEvT_`) is not emitted (not reflection-specific).
