# WP-1260 — reflected alias template-ids with non-deduced parameters

WP-1250 made gcc mode write g++-16's `ta` form for a dependent reflected
alias template-id only when every alias parameter is deducible from the
defining-type-id (`alias_args_recoverable`). An alias whose parameter
appears only in a non-deduced context ([temp.deduct.type]/5) kept kiln's
form, which does not link with g++-16. This WP accepts that case when
the argument is dependent. The rule is spec/abi.md §8.14 "Dependent
reflected template-ids"; spec/reflection.md §8.3 states it with the
encoding.

## Symbols (`T = int`, `K<info>`, `nm` on each compiler's object)

Equal in g++-16 and kiln's gcc mode (before WP-1260 kiln wrote the
alias's own arguments, e.g. `ta1DIS0_E_N2RCIS0_E4typeE`):

- `D<T> = typename RC<T>::type`: `_Z3p_dIiEiT_1KILDmta1D_N2RCIS0_E4typeEEE`,
  `_Z3d_dIiEDTtl1KILDmta1D_N2RCIT_E4typeEEEEES2_`,
  `_Z3q_dIiQneLDmta1D_N2RCIT_E4typeEELDmtyiEEiS1_`; `^^D<T*>`:
  `…ta1D_N2RCIPS0_E4typeE…`.
- partly dependent: `D2<T, int>` (`typename RC2<T, U>::type`)
  `ta2D2_N3RC2IS0_iE4typeE`, `D2<int, T>` `ta2D2_N3RC2IiS0_E4typeE`,
  `DP<T, int>` (`TT2<typename RC<T>::type, U>`)
  `ta2DPIN2RCIS0_E4typeEiE_3TT2IS4_iE`, `DP<int, T>`
  `ta2DPIiS0_E_3TT2IiS0_E` (kiln's own form, textually GCC's).
- nested: `D<AT<T>>` `ta2N1_N2RCI2TTIPS0_EE4typeE`, `AT<D<T>>`
  `ta2N2IPN2RCIS0_E4typeEE_2TTIS5_E`, `D<D<T>>`
  `ta2N3_N2RCINS2_IS0_E4typeEE4typeE`, `TT<D<T>>`
  `ta1XIN2RCIS0_E4typeEE_2TTIS4_E`, `D<T>*` `ta1Z_PN2RCIS0_E4typeE`,
  `TT<typename RC<T>::type...>` `ta2DVIN2RCIS0_E4typeEE_2TTIS4_E`.
- non-type and decltype: `DN<N> = typename RN<N>::type`
  `ta2DN_N2RNIXT_EE4typeE`, `DT<T> = decltype(T{})` `ta2DT_DTtlS0_EE`,
  `NDS<T> = decltype(sizeof(T))` `ta3NDS_DTstS0_E`.

Kept in kiln's form (GCC's loses an argument; each pair below is one
symbol in g++-16, which then fails to assemble):

- `ND<T>`, `ND = int`: kiln `ta2NDIS0_E_i`, GCC `ta2ND_i` (also `ND<T*>`).
- `DL<T, int>` (`TT2<typename RC<T>::type, typename RC<U>::type>`): kiln
  `ta2DLIS0_iE_3TT2IN2RCIS0_E4typeEiE`, GCC
  `ta2DLIN2RCIS0_E4typeEiE_3TT2IS4_iE` (also `DL<T, const int>`).
- `DP<const int, T>`: kiln `ta2DPIKiS0_E_3TT2IiS0_E`, GCC
  `ta2DPIiS0_E_3TT2IiS0_E` (also `DP<int, T>`).
- Non-dependent `^^D<int>`: kiln `ta1DIiE_i`, GCC `ta1D_i` (WP-1250).

## Decision

A dependent qualifier stays a dependent name and is written structurally
([temp.dep.type]), so an alias argument that is dependent and appears in
a qualifier or decltype operand can be read back from the aliased type:
GCC's spelling is injective for that specialization. A non-dependent
argument resolves the qualifier and is lost. The choice is per
specialization (`alias_args_preserved`, beside `alias_args_recoverable`),
and the two forms never produce the same symbol: a kiln form carries an
argument list that differs from the aliased type's, and GCC's form for a
kept qualifier contains it.

A sema bug blocked the `ND<T>` case: `^^ND<T>` names an
instantiation-dependent but non-dependent type, and the reflect-expression
was given its value at definition time, so `p(T, K<^^ND<T>>)` was never
substituted and `p(1, K<^^ND<int>>{})` had no viable candidate.
`Builder::reflect_expr` now makes it value-dependent (spec/reflection-repr.md).
kiln's `^^ND<int>` and `^^ND<long>` are distinct reflections; g++-16's
compare equal.

## Code

- `kiln_abi::mangle::reflect`: `alias_args_preserved` (with
  `preserved_params`, `qualifier_params`, `expr_params`) and the gcc-form
  choice in `reflected_type`; `deducible_params` sees through
  `SubstTemplateTypeParm` sugar in a nested alias's pattern.
- `kiln_ast::builder::reflect_expr`: an instantiation-dependent type
  operand is value-dependent.
