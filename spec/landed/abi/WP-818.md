# WP-818 — libc++/libstdc++ mangling parity with clang 19

The rules below complete spec/abi.md §8.15 and §8.16. Each was found by
the mangling sweep (`scripts/mangle-sweep.sh`, spec/abi.md §8.29), which
compiles `tests/mangle-sweep/*.cpp` with kiln++ and clang++-19 against
both standard libraries and compares every `_Z` name in the IR. The
sweep went from 988 mismatches (before WP-818) to the count given in
§8.29.

- **No silent placeholder in a requires-clause** (Itanium `Q
  <constraint-expression>`). A constraint expression the mangler cannot
  encode used to mangle as `Qu7unknown`. It is now the error
  `cg_cannot_mangle_expression` ("cannot yet mangle expression type
  ...") at the expression, and the TU produces no output. A wrong name
  would link against the wrong definition; an error cannot.
- **Non-dependent `sizeof`/`alignof`** in a dependent expression is the
  literal of its value, `L <type> <value> E` (clang `mangleExpression`,
  `UnaryExprOrTypeTraitExprClass`). The type is the integer type the
  operand is implicitly converted to, else `size_t`: `sizeof(T) == 4`
  with a non-dependent right side gives `eqstT_Lm4E`, and
  `sizeof(wchar_t) == 4` in a requires-clause gives `eqLm4ELi4E`.
- **Substituted `sizeof...`.** A `sizeof...(P)` substituted to a length
  still mangles `sZ <param>` (clang keeps a non-dependent
  `SizeOfPackExpr`): sema records the pack of each such literal in
  `TemplateTables::size_of_pack_origin`. libc++ `tuple`'s
  `eqsZT_sZT_` depends on it.
- **CTAD in a dependent expression.** A class template name to deduce
  (`view(r, f)`, `ref{r}`) is its template name, `cvNS0_9iota_viewE_`,
  `tlNS0_8ref_viewE` (clang `DeducedTemplateSpecializationType`).
- **Alias templates in an instantiation-dependent qualifier** keep the
  alias name: `_And<T>::value` is `sr4_AndIT_E5value`, not the aliased
  helper's name, including an alias to a `decltype`.
- **A template template parameter's specialization** used as a qualifier
  is an unresolved type: `A<is_cc<T>...>::value` is
  `srT_IJ5is_ccIiES5_IlEEE5value`.
- **A non-dependent variable or function** named in a dependent
  expression is `L <encoding> E` (`L_Z4fourE`).
- **A substituted enumeration non-type parameter** is the template
  argument `L <enum> <value> E` (`LS0_2E`), not the cast the replacement
  spells (`XcvS0_Lj2EE`).
- **Abominable function types and member function pointers.** The
  method qualifiers of a function type are part of its `<function-type>`
  (`KFiiE`, `VFiiRE`) wherever it appears, so `W<int(int) const>` and
  `M1SKFivE` mangle alike.
- **Lambda numbering in pack expansions.** The probe that finds a pack
  expansion's packs substitutes the pattern once before the elements;
  the closure types it creates no longer take a discriminator, so
  `([&]{...}(), ...)` numbers its closures `_`, `0_`, ... as clang does.
- **abi_tag on an out-of-line class template member** (clang 19). The
  instantiated member takes its attributes from the pattern's most
  recent declaration when the class specialization is instantiated. An
  out-of-line definition seen earlier that does not repeat the tag drops
  it; one seen later does not. So `basic_string<char>::clear()` keeps
  `B8nn190107` because `<string>` declares `extern template class
  basic_string<char>` before the out-of-line definitions.
- **Template template parameter packs in a signature.** The arguments
  of a template template parameter's specialization that fill a pack are
  grouped `J...E`, as in any other template-args.
- **Injected-class-name in a constraint.** Inside a class template, the
  injected-class-name (`different_from<Z>` in a constrained constructor)
  is the specialization of the class with its own parameters, including
  non-type and non-type pack parameters, so it mangles as that
  specialization and takes a substitution (clang treats it as canonical).
- **Dependent CTAD identity.** Two dependent `T(args)` expressions that
  name different class templates to deduce are different expressions:
  the expression profile includes the canonical template name, so the
  first-spelling origin of WP-790 does not merge `slice(r, n)` with
  `cref(r, n)`.
- **CTAD names carry no abi_tag.** A class template named as a template
  to deduce mangles as the template (`cvNS_5sliceE_`), not the tagged
  pattern class: clang mangles the `ClassTemplateDecl`, whose name has
  no `B` tag.
- **always_inline and noinline across redeclarations.** Like
  `nodiscard`, they apply to a function template's specializations when
  any declaration of the template seen so far carries them (libstdc++
  declares `make_format_args` before its `always_inline` definition).
  For a member template of a class template, only the declarations seen
  before the class specialization was instantiated count, so libstdc++'s
  `basic_string<char>::__resize_and_overwrite` is not always-inline
  (`tests/conformance/dcl.attr/gnu-always-inline-member-template-late-def-run.cpp`).
- **Reference-binding diagnostics** that drop qualifiers carry a `~`
  range under the initializer, as clang's do.

The sweep's flags, its always-inline normalization, and the
mismatches that remain (all clang-only emission differences) are in
spec/abi.md §8.29.
