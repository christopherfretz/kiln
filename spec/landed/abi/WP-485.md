# WP-485 — reflection mangling placeholder, codegen of info-templated entities

- **Not link-compatible with GCC/clang.** A `std::meta::info` value in a
  template argument of an emitted symbol mangles as the kiln vendor
  literal (`Mangler::scalar_value`, `crates/kiln_abi/src/mangle.rs`):

  ```
  <expr-primary> ::= L <info-type> <number> E
  <info-type>    ::= u6__info
  ```

  `<number>` is the `ReflectionId` index (spec/reflection.md §2.3). The
  type `std::meta::info` is `u6__info` everywhere (`builtin_code`; it was
  `u7unknown`), routed through `Sub::Type` so it is a substitution
  candidate as clang treats a vendor type: `two<^^I, ^^J>` is
  `_Z3twoILu6__info4ELS0_5EEiv`, and `h<^^P>(Box<P>, P)` is
  `_Z1hILu6__info3E1PEi3BoxIT0_ES3_` (llvm-cxxfilt agrees). The full
  grammar and its properties are spec/reflection.md §8.3.
- **Linkage.** The index is TU-local, so `value_externally_visible`
  returns false for `Scalar::Reflection`: by the unique-external rule of
  §8.22 a specialization with a reflection argument (directly, inside a
  class-type NTTP's `ByteImage` relocs, or through a `_ZTA` template
  parameter object) is `internal`, and so are its statics, guards,
  vtable and RTTI. Before, they were `linkonce_odr` and two TUs could
  merge different entities under one name. A type argument `info`
  (`k<info>()`, `_Z1kIu6__infoEiv`) keeps its normal linkage.
- **Counter.** `AnonIds::reflection_literals()` counts the literals
  written over a module (no per-id cache: the encoding never reads the
  reflectee).
- → WP-102: GCC 16.1's encoding (`Dm`, `L Dm <kind> … E`; cxx-abi #208)
  and normal linkage, with a kiln/`g++-16` two-TU link test.
