# WP-766 — calling-convention audit: AAPCS64 and SysV x86-64 classification against clang

The rules below complete the classification of spec/abi.md §8.6, §8.12,
§8.13, §8.23, §8.25 and §8.26 and spec/landed/abi/WP-583.md. Each one was
found by the differential matrix described under **Gate**, which compares
kiln with clang 19 and clang 22 on aarch64-linux-gnu and x86_64-linux-gnu.

- **Empty classes** ([class.prop]/9, AAPCS64 §6.8.2, SysV §3.2.3).
  - What kiln does is correct for the compat level. Under clang 20+, an
    AArch64 empty-class *argument* is `i64` (GCC's convention); clang 19
    uses `i8`.
  - Kiln follows `-fclang-compat` (§8.23). It emits `i64` at the default
    of 22 and `i8` at 19. A by-value empty *return* is `void` under both.
    The reported "kiln `i64`, clang `i8`" was a compat-22 kiln build
    compared against clang 19.
  - Objects from kiln and clang agree when both use the same ABI release.
    Mixing clang ≤19 objects with kiln objects needs `-fclang-compat=19`.
  - On AArch64, a class whose only members are empty but are not
    `[[no_unique_address]]` (`{ E a; }`, `{ E a[1]; }`) is not empty
    for the ABI. It is a 1-byte aggregate: an `i64` argument and an `i8`
    return under both releases. x86-64 ignores it like an empty class.
  - An `[[no_unique_address]]` empty member does not stop a class from
    being an HFA. A `[[no_unique_address]]` empty member that follows four
    floats keeps a 5-member candidate at 4 members.
  - On x86-64 an empty class is `Ignore` both as a parameter and as a
    variadic argument.
  - `extern "C"` changes nothing on either target.
- **Unnamed bit-fields** ([class.bit]/2; Itanium C++ ABI §1.1 "empty
  class"; clang `FieldDecl::isZeroSize`).
  - An unnamed bit-field of non-zero width makes its class non-empty for
    `__is_empty`/`std::is_empty` and for layout as a base. Only a
    zero-width one, or an empty `[[no_unique_address]]` member, keeps the
    class empty.
  - This is `record_field_bits` in `crates/kiln_sema/src/decl.rs`.
    `struct U { int : 4; }` is not empty; `struct U0 { int : 0; }` is.
- **AArch64 pointer aggregates** (clang 21+
  `AArch64ABIInfo::classifyArgumentType`, `ContainsOnlyPointers`). These
  rules apply at `-fclang-compat` ≥ 21.
  - A composite argument of 8 or 16 bytes with 8-byte unadjusted
    alignment is coerced to `ptr` / `[2 x ptr]` instead of `i64` /
    `[2 x i64]` when its fields are only 64-bit pointers or references.
    The check recurses through bases, arrays and nested classes. A
    pointer whose pointee is extended-qualified (an address space) does
    not count, and an empty record never counts.
  - Returns keep the integer types. This is
    `only_pointers` in `crates/kiln_abi/src/call.rs`.
- **x86-64 ABI offset 8** (`ArgKind::Direct { offset: 8 }`; clang
  `emitAddressAtOffset`).
  - Some classes have a first eightbyte that holds only empty or padding
    members, for example `{ [[no_unique_address]] E pad[8]; long b; }`.
    Such a class is passed and returned in one register taken from its
    *second* eightbyte.
  - Codegen addresses the object through an inbounds `i8` GEP of the
    offset, `Cg::at_abi_offset` (`kiln_codegen/src/func.rs`). It does this in the callee prologue
    (`coerced_store_sized`, storing `size - offset` bytes), in the caller
    load, in the `ret` epilog, and for a call result stored into its
    destination.
  - Before this work the argument was rejected ("not supported yet"). The
    return was read from offset 0, which was a miscompile.
- **x86-64 `va_arg` temporaries** (clang `X86_64ABIInfo::EmitVAArg`,
  spec/codegen.md "va_arg").
  - A single-class register read copies into a temporary in three cases:
    the coerce type sits at offset 8; the type is wider than its register
    span; or an integer type is over-aligned. kiln applies the
    register-span case only at `-fclang-compat` ≥ 20.
  - Clang 19 reads the offset-8 case in place from the start of the save
    slot, which yields the wrong eightbyte. kiln keeps the correct read
    at 19, so that one `va_arg` is a deliberate difference from clang 19.
    The matrix reads that shape only through `ABI_SHAPE_NP`, which does
    no `va_arg`.
- **Gate.**
  - `tests/codegen/abi_matrix_{empty,scalars,pod,hfa,mixed,overaligned,
    bitfield,union,wide,nontrivial,member}.cpp` instantiate
    `tests/codegen/Inputs/abi_matrix.h` for every shape in WP-766's list.
    The positions are: declaration, definition, call, after the GPR and
    FPR argument registers are used up, after only the GPRs are used up,
    `extern "C"`, variadic argument and `va_arg`.
  - The member file covers `this`-adjusting and `sret`-with-`this` member
    calls.
  - `ir_vs_clang` compares them on both triples, exactly against clang 19
    and structurally against clang 22 with the ABI slice verbatim. The
    ABI slice is the signatures, `byval`/`sret`/`inreg`/`noundef`/
    `zeroext`/`signext` and their alignment. No matrix case has a
    `DEVIATIONS` entry.
  - The run test `crates/kiln_codegen/tests/abi_run_vs_clang.rs` builds
    `tests/abi_run/abi_run.cpp` as caller and callee with kiln and with
    `clang++-22` on the host. It links kiln caller with clang callee, then
    clang caller with kiln callee, then kiln with kiln. Each shape is
    checked member by member on both sides of every crossing.
  - Structured-binding packs (P1061R10) need clang 21 or later. The run
    test is therefore always against clang 22, and the test is skipped
    without it.
- **Tests.** `tests/conformance/class.bit/unnamed-bit-field-not-empty.cpp`,
  the matrix above, `abi_run_vs_clang`.
