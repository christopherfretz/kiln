# WP-1355 — dependent vector types and the `u7unknown` audit

The rules below complete spec/abi.md §8.15 ("Dependent signature
types"). Each is compared with clang 19 and clang 22 symbol for symbol
on both triples (`tests/mangle/*.cpp`, mangle_vs_clang under clang 19;
checked by hand under clang 22, which agrees).

- **Vector types** (Itanium <vector-type>; clang `mangleType(const
  VectorType *)`, `DependentVectorType`, `DependentSizedExtVectorType`):
  | type | spelling | example |
  |---|---|---|
  | constant count, any element (`Vector`) | `Dv <count> _ <element>` | `T __attribute__((ext_vector_type(4)))`: `Dv4_T_` |
  | dependent count (`DependentVector`, ext) | `Dv <expression> _ <element>` | `ext_vector_type(N)` of `T`: `DvT0__T_` |
  | dependent byte size or element (`DependentVector`, generic) | `Dv <expression> _ <element>` | `__vector_size__(N * sizeof(T))`: `DvmlT0_stT__T_`; `__vector_size__(16)` of `T`: `DvLi16E_T_` |
  | Neon / Neon poly / SVE fixed (constant only) | §8.6 / WP-558 / WP-810 | `11__Int32x4_t` |

  A `vector_size` vector of a dependent element stays dependent (its
  element count needs `sizeof(T)`), so it mangles the byte-size
  expression as written; an `ext_vector_type` with a constant count is
  a constant-count vector of the dependent element. The expression is the
  one written by the spelling that created the canonical type
  (`TypeContext::expr_origin`, recorded by `dependent_vector` as for a
  dependent array bound); a template parameter in it is a substitution
  candidate, so `ev<T, N>, T*` is `DvT0__T_PS0_`. The vector type is a
  candidate after its element (`b2(vs<T,N>, vs<T,N>*, const vs<T,N>&)`:
  `…S0_PS1_RKS1_`) and is qualified itself (`RKS1_`). An expression with
  no encoding is `cannot yet mangle expression type <kind>`, as for an
  array bound. Sema never forms a dependent Neon or SVE vector (a
  dependent count is rejected; clang cannot mangle one either). libc++'s
  `std::__all_of(__simd_vector<_Tp, _Np>)` is
  `_ZNSt3__18__all_ofB8ne190107IiLm1EEEbDvT0__T_`.
  `tests/mangle/dependent_vector.cpp`.
- **Dependent member template as a template template argument**
  (`W<T::template X>`; clang `mangleType(TemplateName)` for a
  `DependentTemplateName`): the unresolved prefix of its qualifier and
  its name (`1WIsrT_1XE`, `1WIsr1HIT_EE1XE`), a candidate shared with the
  dependent template prefix of `typename T::template X<int>` (key
  `Sub::DepTemplate`). `tests/mangle/dependent_template_template_arg.cpp`.
- **Variable-length array parameter types** (a Clang extension in C++):
  `A_ <element>`, as clang's canonical parameter type replaces every bound
  by `*` (`getVariableArrayDecayedType`). clang never uniques a
  `VariableArrayType`, so a variably modified type is pushed as a
  candidate but never matched: two `int (*)[n]` parameters are
  `PA_iPA_i`. `tests/mangle/vla_parameter.cpp`.
- **Dependent `_BitInt` width**: an unencodable width expression is now
  the `cannot yet mangle expression type` error, as clang's
  (`Mangler::dependent_dimension` serves `A`, `Dv`, `DB` and `DU`), not a
  silent `DBu7unknown_`.
- **Remaining `u7unknown` fallbacks**, each commented at its site as
  never reached by a mangled name: `Mangler::compound` (sugar and deduced
  placeholders canonicalize away, `Invalid` stops code generation,
  `ExtQual` is never formed, an `UnresolvedUsing` type only appears in a
  class template's pattern), `builtin_code` (the expression-only
  placeholder builtins), `dependent_tst` / `type_prefix` and
  `template_name` (operator templates and overload sets name functions;
  an unexpanded substituted template template parameter pack is rejected
  by sema and crashes clang 19 and 22). Still open, as reflection
  mangling (spec/reflection.md §8.3): a dependent splice type, a splice
  template name, and a splice nested-name-specifier.
