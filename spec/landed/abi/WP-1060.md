# WP-1060 — pack-index expressions, lambdas in template parameters, unresolved qualifiers

Three Itanium mangling gaps that WP-1029 and WP-946 left open (WP-1060,
WP-1061, WP-1062). clang 19 and 22 are the oracle; each rule below is
checked against their symbol names. The rules are in spec/abi.md §8.15.

## Pack-index expression after substitution (WP-1060)

- **Was:** `Substituter::pack_indexing_expr` (kiln_sema `templ/pack.rs`)
  replaced `I...[1]` with the selected element. A member template of
  `Y<1, 2>` with return type `decltype(u + I...[1])` then mangled the
  element (`DTplfp_Li2EE`).
- **Now:** the selected element is recorded in
  `TemplateTables::pack_index_origin`. The mangler (`mangle/dep.rs`
  `expression_node`, `skip_transparent`, `is_primary`,
  `substituted_value`) writes nothing for it, as clang does for its
  non-dependent `PackIndexingExpr`: `_ZN1YIJLi1ELi2EEE1gIiEEDTplfp_ET_`.
  The brief expected `sy`, but neither clang writes that.
- **Tests:** `tests/conformance/dcl.type.pack.index/substituted-expr-mangling-two-units-run.cpp`
  (the xfail flipped), and `tests/mangle/pack_indexing.cpp` (`Y`, `Z`:
  calls, subscripts, commas, template-ids around the index).

## Lambdas in template parameters and arguments (WP-1062)

- **LambdaExpr** (`mangle/dep.rs`): `L <closure type> E`. The closure in
  a template parameter type, a function parameter or return type, or a
  requires-clause is unnumbered (`$_N`):
  `_Z4nttpITnDTclL3$_0EEELi12EEiv`.
- **Default template arguments** (kiln_sema `lambda/mod.rs`
  `ManglingState::template_default`, set around the default's
  substitution in `templ/args.rs` `default_template_arg_in` and in
  `templ/member.rs` `param_list`): every use creates a new closure type
  ([temp.param]/10). That closure is numbered per <lambda-sig> in the
  template's namespace or class:
  - `f() + f()` calls `_Z1fIUlvE_Eiv` and `_Z1fIUlvE0_Eiv`.
  - `N::m()` is `_ZN1N1mINS_UlvE_EEEiv`, `R::d()` is `_ZN1R1dINS_UliE_EEEiv`.
  - `S<int>::m()` is `_ZN1SIiE1mINS0_UlvE_EEEiv`. Its default is
    substituted when `S<int>` is instantiated.
  Parsing the default numbers nothing.
- **Linkage** (kiln_abi `mangle.rs` `tag_externally_visible`): a numbered
  closure with no context declaration takes the linkage of its namespace
  or class. At file scope it has none, so `f<UlvE_>` is `internal` there.
- **Tests:**
  - `tests/conformance/temp.param/lambda-in-parameter-type-mangle-run.cpp`
    (the xfail flipped).
  - `tests/conformance/temp.param/lambda-default-arg-mangling-two-units-run.cpp`.
  - `tests/mangle/lambda_template_argument.cpp`.

## Unresolved-name qualifiers (WP-1061)

The audit checked about 70 global-, nested- and template-qualified
non-member names against clang 19 and 22. kiln already matched every
one, so no code changed. It covered:

- `gs` before a name and before `sr`;
- namespace levels, namespace aliases and inline namespaces;
- `srN` with a dependent type, `template` member templates and template
  template parameters;
- alias templates, operator names, enumerators and `abi_tag`ged classes;
- `std` levels and substitutions, `noexcept` and `sizeof` contexts.

An expression equivalent to one spelled earlier in the TU takes that
earlier spelling (§8.15, "first spelling").

- **Tests:**
  - `tests/conformance/temp.over.link/unresolved-{global,nested,template}-qualified-two-units-run.cpp`
  - `tests/mangle/unresolved_qualifiers{,_template,_std}.cpp`

## Left open

A function template whose parameter or return type holds a lambda
(`decltype([]{})*`) was `internal` in kiln but `linkonce_odr` in clang.
Fixed by WP-1077 (`spec/landed/abi/WP-1077.md`).
