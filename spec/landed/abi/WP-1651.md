# WP-1651 — RTTI names of unit-local types

## The marker

libstdc++ compares two `type_info` objects as "the same object, or
neither name starts with `*` and the names are equal" (`operator==`,
`before`, and the exception-handler and `dynamic_cast` matching in
libsupc++, which compare `type_info`s the same way); `name()` skips a
leading `*`. GCC writes `*` in front of the name string (`_ZTS`) of every
type whose `type_info` is local to the unit (`tinfo_name`'s
`mark_private`), so two units' twins of one name (two classes `S` in
unnamed namespaces) compare unequal, a handler for one does not catch the
other, and a `dynamic_cast` to one fails on the other ([expr.typeid]/2,
[except.handle]/3, [expr.dynamic.cast]/7, [basic.link]/4). Without the
marker (clang, and kiln before) all three go wrong under libstdc++.
libc++ on ELF compares addresses already, and its `name()` would print
the `*`.

**Rule.** With `CodegenOptions::rtti_local_name_marker` on, the `_ZTS`
string of a type `T` is `*` followed by the mangling when

1. `T`'s `type_info` linkage is `internal` (clang `getTypeInfoLinkage`:
   a type without linkage, or one built from such a type: a class or
   enumeration in an unnamed namespace, a local class of a function whose
   local entities do not take its linkage (not inline, not a template
   instantiation), a closure type there, a class template specialization
   with a unit-local template argument (a unit-local type, the address of
   an internal-linkage object or function), and every pointer, member
   pointer (either side), function type (return or parameter) and array
   built from one; top-level cv-qualifiers are dropped by `typeid`);
2. no incomplete class occurs in `T` (`contains_shared_incomplete_class`;
   the ABI gives those `type_info`s that may be duplicated and compares
   them by name) other than one in an unnamed namespace, which no other
   unit can name and GCC marks (`typeid(I *)` for `namespace { struct I;
   }` is `*PN12_GLOBAL__N_11IE`, and `I`'s own name is marked too; WP-1679);
3. the mangling names no class clang calls `$_N` outside a function (a
   closure type without a mangling number, an unnamed class or
   enumeration without a typedef name for linkage at namespace or class
   scope) other than the two forms below, and no entity that has internal
   linkage only by clang's `internal_linkage` attribute
   (`mangle_rtti_with_marker_check`): GCC names the former differently
   and marks only some of them (not a closure in a non-inline external
   variable's initializer, a closure-typed data member or an unnamed
   enumeration), and ignores the attribute. The two `$_N` forms that are
   marked (`mangle::anon_marker_provable`, WP-1679), both unit-local by
   [basic.link]/4 and marked by GCC 16.1:
   - an unnamed class (not an enumeration) whose semantic parent is a
     namespace (`struct { int a; } us;`);
   - a closure type at namespace scope that is the type of a variable of
     that namespace with internal linkage (`static`, `const` non-`inline`
     non-`extern`, or in an unnamed namespace) declared before the
     closure: the variable whose initializer created it (`static auto l
     = [] {};`). A later variable of the type is a copy (`static auto c =
     l4;` of an external `l4`'s closure) and does not count; a closure
     wrapped in another type (`static auto p = +[] {};`) is not found and
     stays unmarked. Only the run that decides the marker (the `_ZTS`
     mangling) makes this test, so no other mangling pays for it.

Everything else is unmarked: types with linkage (a local class of an
inline function, a class with a unit-local base, a hidden-visibility
class: hidden is not local), module-linkage types (`W1m2ML`: shared by
the module's units) and exported ones. The table of forms, checked
against GCC 16.1's `-S` output, is `crates/kiln_driver/tests/rtti_local_marker.rs`.
A marker is never written where GCC 16.1 writes none (a marker on a type
that is not local would make it unequal to itself across units); where
GCC writes one and kiln does not (condition 3's remaining `$_N` forms, a
local incomplete class of a non-inline function) the behaviour is the one
before WP-1651. Under `-fno-rtti` the `type_info` objects exception handling
still builds follow the same rule (GCC does the same).

Only the string changes: one byte in front, the array one byte longer.
The symbol, its `internal` linkage, section, alignment and the `_ZTI`
layout are unchanged, so objects link as before; kiln and GCC objects
mixed in one program agree in both directions (checked by hand: `==`,
`before`, `catch`, `dynamic_cast` across a GCC and a kiln unit). The
`.mason.meta` hashes do not hash RTTI strings.

**When.** `cg::vtable` `rtti_name_global_vis` writes the byte;
`local_name_marker` decides. The driver turns the option on when the C++
standard library is libstdc++ (`-stdlib=libstdc++`, the default on every
target kiln supports) and off with `-stdlib=libc++`;
`-fkiln-rtti-local-marker` / `-fno-kiln-rtti-local-marker` force it (the
last one wins; spec/driver.md), for a library the driver cannot see
(`-nostdinc++` with one's own include path). C never has it. Nothing is
stored in a PCH or module file: the importer's options decide.

## Found on the way

- An array or function type built from a unit-local type had
  `linkonce_odr` `_ZTI`/`_ZTS` (clang: `internal`), so two units' distinct
  `A[3]` were merged at link. `type_rtti_linkage` now also asks
  `mangle::type_externally_visible`.
- An unnamed class or enumeration without linkage (at namespace scope, in
  an unnamed namespace, local to a non-inline function) was mangled
  `Ut_`, where clang writes `$_N` (`mangleUnqualifiedName` tests
  `isExternallyVisible` first): an unnamed struct and an unnamed enum at
  namespace scope shared `_ZTIUt_`, one global, so their `typeid`s
  compared equal. Now `$_N` from the module-wide counter, as clang.
