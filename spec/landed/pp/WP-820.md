# WP-820 — header search and file loading at clang's system-call count (closes WP-824)

Extends spec/pp.md "Header search" ("Lookup caching"), spec/source.md
"SourceManager API" and spec/driver.md "Dependency output".

## What it cost before

On the bind-mounted workspace every file-system call blocks, so kiln's
per-TU wall time was set by its system-call count, not by its CPU time
(WP-694, WP-812). `strace -c` on three TUs (details and commands in
docs/status/header-search-syscalls.md):

- `SourceManager::load_file` ran `fs::canonicalize` on every open. glibc
  `realpath` makes one `readlinkat` per path component and a
  `faccessat2` per `..`, so a libc++ header under
  `.toolchain/llvm-project/...` cost a dozen calls. It was 6090 of the
  10630 calls of a libc++ `<algorithm>`/`<ranges>` TU.
- Header search probed each candidate with an uncached `metadata` call
  before opening it, then `fs::read` re-stat'ed it and read twice.
- Nothing was cached across lookups but the opened path, so the
  157-directory tree of WP-824 paid about 141,000 `statx` calls for
  the same few hundred names.

## The fix

**`kiln_source`.**

- A loaded file is identified by device and inode from the `fstat` of the
  opened file (`FileKey::Unique`; canonical path on non-Unix hosts),
  clang's `UniqueRealFiles`. No path is canonicalized. `#pragma once`
  and the guard optimization key on `FileId`, so they still see one file
  through symlinks, `..` and hard links.
- `read_open_file` reads the whole file in one sized read (the length is
  in the metadata already fetched). `fs::read` made a second `statx` and a
  probe read.
- `load_regular_file` (used by header search) refuses anything but a
  regular file, so a device found under a header's name is not read as
  one (as `RealFs` refused it before through its `metadata` probe).

**`kiln_pp::HeaderSearch`.**

- Directory existence is cached (`HeaderFs::is_dir`). A name with
  directory components checks each intermediate directory before
  opening, so `-I dir` without `boost/` rules out every `boost/...`
  header with one `stat`.
- clang's `LookupFileCache`: the result of a lookup is cached per
  (name, start index), so a repeated `#include` or `#include_next` makes
  no query.
- After the fourth failed lookup in a directory its listing is read
  (`HeaderFs::list_dir`) and later misses there make no query. Names
  compare ignoring ASCII case, so a case-insensitive file system never
  gets a false miss. Non-ASCII directories and components stay with
  `open`.
- `RealFs::open` is a single `open` + `fstat` + `read` (no `metadata`
  probe). `RealFs::read` (`#embed`) uses `read_open_file`.

**`-M` dependency output.** clang names each `FileID` by the path its
lookup used and lists skipped includes (`FileSkipped`), so a header
reached as `real/x.h`, `lnk/x.h` and `sub/../real/x.h` is three
dependencies. kiln listed it once (by `FileId`) before this WP, under
the old canonical identity as well. Now `ResolvedInclude::path` carries
the lookup's path, `PpCallbacks::file_skipped` reports `#pragma once`,
`#import` and guard skips, and `DepCallbacks` records each path. The output
is byte-identical to clang 19 on that case. `__FILE__`, line markers and
diagnostics keep the first-loaded name, as clang does.
`SearchEvent::HasInclude` carries the path too.

## Results

`-E`, harness-profile kiln against clang++-19 on the same host, as
meta / io / wall / sys. "meta" counts open, stat, fstat, readlink,
getdents and access calls; "io" counts read, pread and lseek. The
"after" and clang columns come from one run. Wall times are noisy: the
load average was about 24. `-fsyntax-only` rows, peak RSS and the exact
command lines are in docs/status/header-search-syscalls.md.

| TU | kiln before | kiln after | clang-19 |
|---|---|---|---|
| fmt 12.1.0 `test/format-test.cc` | 7363 / 873 / 0.96 s / 0.09 s | 1031 / 440 / 0.30 s / 0.04 s | 2363 / 359 / 0.44 s / 0.03 s |
| libc++ `<algorithm>`+`<ranges>` TU | 9184 / 1446 / 0.20 s / 0.02 s | 1547 / 727 / 0.17 s / 0.02 s | 2439 / 695 / 0.10 s / 0.01 s |
| 157 `-I` synthetic tree (WP-824 shape) | 197219 / 7012 / 61.4 s / 5.63 s | 8861 / 3510 / 6.27 s / 0.33 s | 32034 / 3522 / 18.5 s / 0.97 s |

The `-E` output of all three TUs is byte-identical before and after.

## Tests

- `crates/kiln_pp/tests/resolver.rs`: the query counts of each cache
  (`MemoryFs::queries`), as follows.
  - `a_repeated_lookup_makes_no_queries`
  - `a_missing_subdirectory_rules_out_its_headers_with_one_stat`
  - `a_directory_listing_answers_misses_after_four`
  - `a_listing_compares_names_ignoring_ascii_case`
  - `a_directory_with_a_non_ascii_name_is_not_answered_from_its_listing`
  - `a_header_is_found_by_its_spelled_path`
- `crates/kiln_driver/tests/depfiles.rs`
  `every_path_a_header_is_reached_by_is_a_dependency`: a symlinked
  directory, a `..` path, `#pragma once`, a guarded header and an
  `#include_next` chain. `-MMD` is checked against a literal and against
  clang++-19; `-E` is checked against clang++-19.
- `crates/kiln_source/tests/unit.rs`
  `cpp_include_file_identity_by_device_and_inode`: a hard link is the same
  file, and `load_regular_file` refuses a directory.
- `tests/conformance/cpp.include/`: each passes under kiln and under
  `--compiler clang++-19`.
  - `include-next-order.cpp`
  - `include-search-kinds.cpp` (`-iquote` / `-I` / `-isystem`)
  - `include-negative-cache.cpp` (a later directory after cached misses
    and a listing)
  - `pragma-once-paths.cpp`
- `scripts/perf/gen-include-tree.py` regenerates the synthetic tree.
