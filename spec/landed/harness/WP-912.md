# WP-912 — accepts-invalid hunt, step 1: clang's negative tests

`cargo xtask clang-neg` runs clang's own `-verify` tests
(`clang/test/CXX` and `clang/test/SemaCXX` at `llvmorg-22.1.8`) through
kiln and measures what kiln wrongly accepts: test files where clang
expects an error and kiln reports none, and `expected-error` lines with
no kiln error on them. Contract: spec/clang-neg.md.

## Landed

- `scripts/fetch-clang-tests.sh [<tag>] [<dir>]`: a shallow, blob-filtered,
  sparse checkout of `clang/test/{CXX,SemaCXX,SemaTemplate,Parser}` (plus
  the three files outside them that those tests include) into the
  gitignored `.oss/clang-tests` (about 50 MB). Idempotent. Nothing is
  vendored.
- `xtask/src/clang_neg/`:
  - `runline.rs`: RUN-line joining, `%clang_cc1 -verify` selection, the
    flag mapping to kiln++'s driver, `%std_cxx` ranges, `REQUIRES` /
    `UNSUPPORTED` lines and the skip reasons.
  - `outcome.rs`: `neutralize` (a sentinel inside every `expected-error`
    text, so kiln's own `-verify` reports every expected error and every
    kiln error with its line), `parse_report`, `classify`
    (ACCEPTS-INVALID, MISSED-ERROR, verifier complaints).
  - `report.rs`: the JSON report and the generated region of the status
    page (totals, per directory, top files, missed-error clusters,
    rejects-valid, crashes, "not supported yet", skips).
  - `mod.rs`: options, planning, the parallel run on the shared
    jobserver with per-case timeout and address-space cap, peak RSS.
- `cargo xtask clang-neg` in `xtask/src/main.rs`. It is not part of
  `cargo xtask ci` (its unit tests are).
- docs/status/accepts-invalid.md: the generated region of the
  2026-11-08 run and the hand-written triage (16 clusters, repros).
  docs/COMPATIBILITY.md "Rejecting invalid code" has the headline
  numbers: 7.2% of files (90/1249) accepted invalid, 17.9% of
  `expected-error` lines (5015/28043) missed, 11.7% rejects-valid
  (49/418). docs/VALIDATION.md and spec/README.md list the layer.
- kiln_sema `templ/concepts/sat.rs` `check_constraints`: an atomic
  constraint whose satisfaction depends on itself, for the same arguments,
  is unsatisfied (`sema_constraint_depends_on_self`) instead of recursing
  forever. It fixes the run's two timeouts.

## Tests

- xtask unit tests: `runline::tests::{run_lines_are_joined,
  flags_map_to_the_driver, std_ranges_expand, skip_reasons,
  requirement_lines}`, `outcome::tests::{neutralize_inserts_the_sentinel,
  report_is_parsed, cases_are_classified}`,
  `report::tests::summaries_count_files_and_lines`,
  `clang_neg::tests::{options, directory_keys, files_are_planned,
  runs_are_judged, case_arguments}`.
- 64 `tests/conformance` repros, each checked with clang++-19 and
  clang++-22 (clang-22-only behaviour carries `requires: clang>=22`):
  - 38 compile-fail `xfail(kiln): WP-912 follow-up, <cause>` tests for
    accepts-invalid cases (one of them,
    `dcl.fct/type-defined-in-member-parameter-crash.cpp`, panics kiln);
  - 25 compile-ok `xfail(kiln)` tests for rejects-valid cases, including
    `dcl.init.list/empty-initializer-list-no-default-ctor.cpp` (rejected,
    then a stack overflow) and the three WP-873 never-constant false
    positives under `dcl.constexpr/potential-constant-*`;
  - 1 passing compile-fail test,
    `temp.constr.atomic/self-dependent-constraint.cpp`, for the `sat.rs`
    fix.
  The full list, by cluster, is in docs/status/accepts-invalid.md
  "Triage".

## Deviations from the WP text

- A `-triple` with an `unknown`/`pc`/`none`/`elf` OS is widened to
  `<arch>-unknown-linux-gnu` instead of being skipped; other OSes skip.
- Directives in inactive `#if` branches and of other `-verify=` prefixes
  are resolved by kiln's own verifier, not by a textual scan.
- Directives written in included headers (`Inputs/*.h`) are not
  neutralized; they match only when kiln uses clang's wording.
- "File-level accepts-invalid" counts a file once when any of its RUN
  configurations is accepted.
- The runner pins no target for `%itanium_abi_triple` and untargeted RUN
  lines, so host-dependent tests see aarch64 (unsigned `char`);
  `SemaCXX/builtins-overflow.cpp` errors under clang there too.
- The `sat.rs` hang fix was not in the WP scope; it was needed to finish
  the full run.
