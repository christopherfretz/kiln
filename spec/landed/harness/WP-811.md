# WP-811 — M8 wave 4: Kitware CMake, Bitcoin Core and gRPC

Three application-sized projects run through the M8 OSS harness
(spec/landed/harness/WP-666.md), each with its own test suite and a
clang++-19 control build:

- Kitware CMake v4.4.5, with its 714-test CTest suite.
- Bitcoin Core v32.1: `bench_bitcoin -sanity-check`, the Python
  functional suite, and ctest (`test_bitcoin` and the secp256k1 and
  univalue tests).
- gRPC v1.85.1, the C++ core with every dependency from its submodules,
  plus `protoc` and `grpc_cpp_plugin` built by the compiler under test.

The status pages are `docs/status/oss/cmake_app.md`,
`docs/status/oss/bitcoin_core.md` and `docs/status/oss/grpc.md`, and the
index is `docs/status/oss.md`.

## Landed

- `scripts/oss/projects.toml`: the `cmake_app`, `bitcoin_core` and `grpc`
  rows (`wave = 4`).
- `scripts/oss/grpc-tests.txt` and `scripts/oss/grpc-tests.sh`. gRPC's
  CMake build registers no ctest tests, so the `grpc` row builds the
  binaries listed in `grpc-tests.txt` (its `build_targets`, which must
  list the same binaries) and `grpc-tests.sh` runs them. It runs at most
  4 at a time, each under `timeout 300`, from the source root. It prints
  one `PASS`, `FAIL` or `MISSING` line per test, then a ctest-style
  summary line for `report.json`. A binary that was not built counts as a
  failure. The end2end tests take their ports from gRPC's port server
  (`tools/run_tests/python_utils/port_server.py`, on localhost:32766),
  which the script starts first and stops at exit.
- The `bitcoin_core` row's exclusions, which apply under both compilers:
  - `feature_reindex_init` and `feature_reindex_readonly` make the data
    directory read-only, which root ignores;
  - `univalue_object_test` puts its checks inside `assert()`, which the
    Release build compiles out, and the control dies with SIGILL.

Front-end fixes, each with its spec sentence and a conformance test:

- A dependent using-declarator (`using A::f;` in a template whose `A`
  is a dependent base) conflicts with no later using-declarator of its
  name: `using A::f; using P::f;` is valid in the definition and is
  checked in each instantiation (spec/sema.md;
  `namespace.udecl/dependent-then-nondependent-same-name-run.cpp`).
- In `sizeof(decltype(e)::type)`, the `decltype` nested-name-specifier
  is resolved before the operand is classified as a type-id or an
  expression ([expr.sizeof]/1, [dcl.ambig.res]/2; spec/parse.md;
  `expr.sizeof/decltype-qualified-type-operand-run.cpp`).
- Partial ordering converts the substituted elements of a non-type pack
  before comparing, so `template <char... D> X<'0', 'x', D...>` is more
  specialized than `template <char... D> X<'0', D...>` (libstdc++'s
  `_Parse_int` for a hex chrono literal; spec/sema-templates.md;
  `temp.spec.partial.match/order-nontype-pack-leading-values-run.cpp`).
- A conversion function's result is bound once. `S{tl}` with
  `TL::operator S()` (CWG2327) wrapped the already-bound call in a second
  `CXXBindTemporaryExpr`, so the object was destroyed twice
  (spec/sema-class.md;
  `class.temporary/conversion-function-result-in-braced-cast-destroyed-once-run.cpp`).
- The AArch64 crypto-extension NEON builtins: `vaeseq_u8`, `vaesdq_u8`,
  `vaesmcq_u8`, `vaesimcq_u8`, `vsha1{c,m,p}q_u32`, `vsha1h_u32`,
  `vsha1su{0,1}q_u32`, `vsha256h{,2}q_u32` and `vsha256su{0,1}q_u32`
  (spec/codegen.md; `target.neon/crypto-run.cpp`,
  `target.neon/ir-crypto-19.cpp`).
- A source-location builtin in a constructor's default argument takes
  the location of the construction ([support.srcloc.cons]/2;
  spec/sema-templates.md;
  `expr.const/builtins-srcloc-constructor-default-arg-run.cpp`).
- A non-type template parameter whose substituted type is a function or
  array type has the adjusted pointer type, also in a member template of
  a class template ([temp.param]/10; gRPC's
  `ParseValue<F, G>::Parse<F f, G g>`; spec/sema-templates.md;
  `temp.param/nttp-substituted-function-array-type-adjusted-run.cpp`).
- `-Wframe-larger-than=N` is clang's backend stack-frame option, not a
  warning group: N must be an integer and the option has no effect.
  `-Wlarger-than=` and `-Wlarger-than-` are accepted and ignored
  (BoringSSL builds `bcm.cc` with `-Wframe-larger-than=25344 -Werror`;
  spec/diag.md section 4; `crates/kiln_diag/tests/policy.rs`).
- An enumerator named by a class member access (`case response.INITIAL:`,
  `q->B`) is a constant expression when the object expression is: the
  Oven evaluates the base as a glvalue (`.`) or a pointer (`->`) and
  discards it ([expr.ref]/7; gRPC's `grpclb.cc`; spec/oven.md;
  `expr.ref/enumerator-member-access-constant-run.cpp`,
  `expr.ref/enumerator-member-access-unknown-base.cpp`).
- A shift whose count has another integer width converts the count to
  the left operand's type element-wise, so a GNU vector shifted by a
  scalar of another width lowers (`v2u64 << int`, BoringSSL's Keccak
  rotate; spec/codegen.md;
  `ext.vector/shift-scalar-count-other-width-run.cpp`).

## Follow-ups

- `decltype(e)::name` as the type of a parameter declaration is still
  rejected: `dcl.type.decltype/decltype-qualified-type-parameter-declaration.cpp`
  is an xfail repro.
- `-mbranch-protection=` is not accepted, so Bitcoin's hardening probe
  drops it and the kiln build has no PAC/BTI.
