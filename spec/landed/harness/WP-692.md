# WP-692 — CI fan-out

GitHub CI runs `cargo xtask ci` as parallel slices instead of one serial
job per architecture (docs/VALIDATION.md "GitHub Actions" has the job
graph and the cache policy; docs/status/perf-history.md "WP-692: CI fan-out" the
times).

## Landed

- `cargo xtask test --shard K/N` ("Command line"): of the sorted test list
  after `--filter`, test `i` runs iff `i % N == K - 1`; shards `1..N`
  partition the unsharded run; an empty shard passes; not with
  `--external`. The run's first line names the shard.
- `cargo xtask ci --step <lints|unit|self-check|kiln>` (comma list or
  repeated; default all), `--shard K/N` (passed to both corpus runs; needs
  `self-check` or `kiln`) and `--unit-group <xtask|codegen|rest>` (one
  package group of the `unit` step; `rest` is the workspace minus the
  grouped packages) ("CI"). The `KILN_ORACLE` and `KILN_REQUIRE_GCC`
  checks run in every invocation; an unselected step prints
  `skipped (--step)`; misuse is exit 2. Each step prints its time.
- `.github/workflows/ci.yml` calls `.github/workflows/ci-lane.yml` once per
  architecture (`arm`, `x86_64`): `lints`, `unit` x3, `self-check` x2,
  `kiln-22` x6, `kiln-19` x6, with `S = 6` one anchored list
  (`&kiln-shards`) and `N` taken from `strategy.job-total`. The fan-ins
  `check` and `check-x86_64` (`if: always()`) pass only when their lane's
  result is `success`.
- `.github/actions/kiln-ci` is setup only (packages, GCC 16.1 check, Rust
  1.95.0, rust-cache with a per-architecture `shared-key`, saved by
  `unit rest` only, `cache-on-failure`). Workspace crates are not cached:
  fresh checkouts make them dirty for cargo anyway, and restoring commit
  mtimes could reuse a stale build.

## Tests

- `xtask/src/test/tests.rs` `shards_partition_the_test_list` (shards
  1/3, 2/3, 3/3 of `xtask/fixtures/ast/clang` against the unsharded run),
  `cli_parsing`.
- `xtask/src/main.rs` `ci_tests::step_and_shard_arguments`,
  `unit_groups_partition_the_workspace`, `workflow_lists_the_unit_groups`,
  `cargo_steps`.
- The GitHub run itself: every corpus test runs in exactly one shard, so
  the shard summaries add up to the unsharded counts.
