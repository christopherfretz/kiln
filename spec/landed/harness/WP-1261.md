# WP-1261 — GCC-under-test arg hygiene (with WP-1264 and WP-1266)

Three harness rows in one change, since all three touch
`xtask/src/test/runner.rs`.

- **WP-1261.** WP-1249 mapped the test file's compile into GCC's
  spelling when GCC is the compiler under test, but the other commands
  did not go through that mapping. The `unit:` compiles and the two-step
  link still passed the raw `args` and `-Qunused-arguments`. clang's
  diagnostic-only flags (`-Weverything`, `-R<remark>`, warnings GCC does
  not have) reached GCC in every command, and GCC rejects them.
- **WP-1264.** A crashing clang oracle wrote reproducers into `$TMPDIR`,
  because only kiln got `-fno-crash-diagnostics`.
- **WP-1266.** `--compiler $KILN_GCC` failed tests that GCC 16.1 should
  pass, or whose expectations are clang's own.

## Landed

- `xtask/src/oracle.rs`:
  - `gcc_args_with(args, warnings)` is the one GCC flag map. `gcc_args` is
    the same map with no warning list.
  - On top of WP-1249's drops and renames, it also drops
    `-Qunused-arguments`, `-Weverything`,
    `-f[no-]crash-diagnostics[=...]` and the `-R<remark>` flags. It turns
    `-Wno-everything` into `-w`.
  - It also drops every `-W`/`-Wno-`/`-Werror=`/`-Wno-error=` name that
    this GCC does not list for the test's language.
  - `GccWarnings::of(gcc, c)` reads that list once per process from
    `-Q --help=warnings -fsyntax-only -x c|c++ /dev/null`. An
    `[available in ...]` line belongs to another language, so it is not
    counted.
- `xtask/src/test/runner.rs`:
  - These commands now take their flags from `flags_for`/`args_for`: the
    test file's compile, `pch:`, `header-unit:`, `module:`, the `unit:`
    compiles and the two-step link. Both functions apply the map for GCC
    under test and leave the flags unchanged for anything else.
  - Under GCC, the `unit:` compiles also get the stand-in `kiln_meta.h`
    directory (`gcc_stand_in`).
  - Under GCC, the two-step link drops `-Qunused-arguments` and ends with
    `-lstdc++exp` (`GCC_LINK_LIB`).
  - `unsupported_by` lets a test whose only extra lines are `unit:` lines
    run under GCC.
  - The flag probe (`gcc_rejected_flags`) runs for a test that has `args`.
    It compiles a one-line file with `-fsyntax-only` and the mapped args.
    If GCC rejects a flag on the command line, the test is skipped with
    `GCC under test: GCC rejects the test's flags (<GCC's line>)` rather
    than failing.
  - Under GCC, a test that is itself a module unit or imports one
    (`module;`, `export module M;`, `import std;`, ...), or whose `args`
    name `-fmodule-file=`/`-fprebuilt-module-path=`, is skipped
    (`gcc_module_syntax`). GCC takes modules only with `-fmodules` and a
    `gcm.cache/` the harness does not drive, the same rule as `module:`.
  - Under GCC, the `stdc-predef.h` line marker is dropped from `-E`
    output before the `pp` comparison (`without_gcc_preinclude`). GCC
    includes that header before every hosted translation unit; kiln and
    clang do not.
  - `no_crash_reports` adds `-fno-crash-diagnostics` to every compile by
    kiln or a clang, whether it is the compiler under test or the oracle.
    That covers the clang oracle (WP-1264), and the module, header-unit
    and PCH builds as well.
- `xtask/src/test/gcc.rs` (the GCC oracle) and
  `xtask/src/test/external.rs` use `gcc_args_with` with the warning list.
- `xtask/fixtures/fake-gcc/g++`:
  - It answers `--help=warnings` with a short list.
  - It rejects `-Qunused-arguments`, `-fno-crash-diagnostics`, `-R*`,
    `-fsanitize-ignorelist=` and unlisted `-W`/`-Werror=` names, the way
    GCC does.
- `xtask/fixtures/gcc-compiler/` has three new fixtures, for 12 in total:
  - `pass-unit-two-step-run.cpp`, with `Inputs/unit-five.cpp`
  - `pass-clang-warning-flags.cpp`
  - `skip-flags-gcc-rejects.cpp`
- Tests:
  - `gcc_args_drop_clang_diagnostic_flags` (oracle.rs),
    `module_syntax_lines` and `gcc_preinclude_marker_dropped` (runner.rs).
  - `gcc_as_the_compiler_under_test` (tests.rs) now asserts that every
    GCC command of the `unit:` test is in GCC's spelling and the link ends
    with `-lstdc++exp`. It also asserts that the clang oracle keeps
    `-Qunused-arguments` and that the probe's skip reason is correct.
  - `clang_oracle_crash_is_retried_once` asserts that every compile by the
    fake clang oracle carries `-fno-crash-diagnostics`.

## WP-1266 classification

Before this change the GCC lane over the four named directories had 13
failures. All of them were in expr.prim.lambda, temp.inst and dcl.pre.
`meta.reflection.result` had 0 failures on base a33d20c60:
`reflect-constant.cpp` already passed.

- (a) harness:
  - `dcl.pre/p2741-static-assert-message-diags.cpp`: the clang-only
    `-Werror=invalid-static-assert-message` now gets dropped.
  - `temp.inst/builtin-call-no-adl-completion.cpp`: its placement
    `operator new` was declared but never defined, so GCC's link failed.
    It is now `#include <new>`.
- (b) clang-specific, marked `skip(gcc)`:
  - `expr.prim.lambda/generic-captured-reference-layout.cpp`: it pins
    clang's closure layout.
  - `expr.prim.lambda/gnu-attribute-before-specifiers.cpp`,
    `expr.prim.lambda/noreturn-attr-placement.cpp` and
    `expr.prim.lambda/noreturn-attr-placement-errors.cpp`: clang's
    GNU-attribute placements in a lambda-declarator.
  - `temp.inst/designated-init-contexts.cpp` and
    `temp.inst/designated-init-rewarn.cpp`: clang's C99 designator
    extensions.
  - `temp.inst/var-template-unknown-bound-completed.cpp`: clang's
    completion point for the bound.
- (c) GCC 16.1 deviations, marked `xfail(gcc)` (nothing was filed
  upstream):
  - `expr.prim.lambda/constexpr-capture-pack-nested.cpp`: GCC rejects
    `[ts...] { return (... + [ts] { return ts; }()); }` with "parameter
    packs not expanded" ([expr.prim.lambda.capture]/17, [temp.variadic]/5).
  - `expr.prim.lambda/constexpr-init-capture-forms.cpp` and
    `expr.prim.lambda/run-init-capture-forms.cpp`: GCC rejects
    `[q(ox)]`/`[q{ox}]` when the copy constructor is explicit. The
    init-capture is direct-initialization ([expr.prim.lambda.capture]/6).
  - `expr.prim.lambda/errors-default-arg.cpp`: GCC accepts
    `[](int x = 1, int y) {}` ([dcl.fct.default]/4).

Where a new directive line would have shifted the absolute `diag:` line
numbers, the header comment was reflowed to make room for it.
