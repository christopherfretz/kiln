# WP-614 — Rust 1.95: the pinned toolchain and MSRV

- **Pins** (`rust-toolchain.toml` channel `1.95.0`, `Cargo.toml`
  `rust-version = "1.95"`, `.github/actions/kiln-ci/action.yml`): Rust
  1.95 is the newest toolchain a downstream build of kiln has, so it is
  the only one kiln is built and checked with. The channel pin, not
  `rust-version`, is what enforces the MSRV: `rust-version` only refuses
  older toolchains, while a newer pinned channel would let a std API
  stabilized after 1.95 slip in unnoticed. Edition 2024 (stable since
  1.85) and every dependency (highest MSRV 1.71) are unaffected.
- **Code**: `u64::isolate_lowest_one()` (unstable in 1.95) in
  `kiln_abi::layout` is `offset & offset.wrapping_neg()`.
- **Lints** clippy 1.95 reports under `-D warnings` that 1.99 did not,
  each a false positive here and allowed at the narrowest useful scope:
  `collapsible_match` (workspace `Cargo.toml`; the suggested guards would
  fall through to the next arm), `match_same_arms` (one `match` in
  `kiln_pp::expand` whose arms differ only in a cfg'd-out profiling
  macro), `float_cmp` (the lexer's literal round-trip test and the xtask
  bench statistics), `duration_suboptimal_units` (xtask), and two
  `#[expect(dead_code)]` in `xtask::bench::record` that 1.95 does not
  fulfil (now `#[allow]`). `drop(push)` on a non-`Drop` closure in
  `kiln_ast::dump` is simply gone (NLL ends the borrow at its last use).
- **Rule** (`docs/AGENTS.md` rule 3): no std API, language feature or
  clippy lint name stabilized after 1.95.
