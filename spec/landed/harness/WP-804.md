# WP-804 — Boost compiled libraries in the OSS harness

The `boost_compiled` row builds the compiled Boost 1.90 libraries
(system through test, 25 of them) and their tests through the CMake
superproject. It shares the `boost` checkout with `boost_meta`
(spec/landed/harness/WP-787.md). The results are in
docs/status/oss/boost_compiled.md.

## Landed

- The `projects.toml` row `boost_compiled`:
  - The configure flags are `boost_meta`'s plus `-DBUILD_SHARED_LIBS=OFF`.
  - `build_targets = ["all", "tests"]`.
  - The test command is `ctest -j 4 --timeout 300 -E '<41 names>'`. Every
    excluded test also fails under the clang-19 control, and the row's
    `notes` gives the reason for each group.
- Extensions to `scripts/oss/shims/boost-jamfile-tests.cmake`, each covered
  by the selftest check "boost shim: library rules, variants, defines and
  links":
  - `KILN_BOOST_JAMFILE_RULES_<lib>` lists items of the form
    `<rule>=<type>|<name>|<sources>`. They cover the Jamfiles that wrap
    `run` in their own rules, such as thread's `thread-run2-noit`,
    serialization's `test-bsl-run_files` and Boost.Test's
    `boost.test-self-test`.
    - A statement that opens with `<rule>` is read from its first line,
      the same way as a builtin rule.
    - In each part, `{N}` is replaced by the statement's `:` field N.
      Field 0 is the first field after the rule name.
    - `<type>` is the test type. A type that is not a builtin test type is
      skipped.
    - `<name>` is the target name. When it is empty, the name is the base
      name of the first source.
    - `<sources>` is a `,` list. Each item is either a field number or a
      path template such as `{1}/{2}.cpp`.
      - A field number contributes that field's words.
      - A bare identifier among those words gets `.cpp` appended.
      - Words that are not sources are dropped.
  - `KILN_BOOST_JAMFILE_VARIANTS_<lib>` lists items of the form
    `<rule>|<define>|<suffix>`. A statement read through `<rule>` is
    registered once per variant. Each registration adds `<define>` and
    appends `<suffix>` to the target name. Serialization uses this for its
    text, binary and xml archive runs.
  - `KILN_BOOST_JAMFILE_TARGET_<lib>` names the library target that a
    library's tests link. The default is `Boost::<lib>`. Boost.Test
    builds `Boost::unit_test_framework`.
  - `KILN_BOOST_JAMFILE_DEFINES_<lib>` adds defines to every test of the
    library.
  - `KILN_BOOST_JAMFILE_LINK_<lib>` adds link libraries to every test of
    the library. Examples are serialization's `Boost::filesystem` and the
    `Boost::unit_test_framework` link that thread, iostreams, log and
    fiber need.
  - A `.c` source is skipped when C is not enabled in the root directory.
    regex's `c_compiler_checks` are an example. container enables C only
    in its own directory scope.
