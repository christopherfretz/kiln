# WP-666 — OSS build harness

The M8 harness (docs/ROADMAP.md M8, docs/status/oss.md) builds real
open-source projects through their own build systems with kiln as the C++
compiler. It lives in `scripts/oss/`, needs the network, and is never part
of `cargo xtask ci`. This file is the contract between the wrapper, the
build driver and the report: `oss-report.py` reads exactly what is
specified here, and a change to either side updates this file.

## Files

- `scripts/oss/projects.toml`: one table per project, keyed by the name
  the scripts take. Keys: `url`, `tag` (a pinned release tag, checked with
  `git ls-remote --tags`), `build` (`cmake` | `meson` | `make`), `cxx_std`,
  `configure` (list of extra configure flags; `@OSS@` in one expands to
  the absolute `scripts/oss` directory, for a project shim under
  `scripts/oss/shims/`, WP-726), `build_targets` (optional
  list; default all), `test` (a shell command run in the build dir),
  `c_compiler` (default `clang-19`: kiln is C++-only), `wave` (1/2/3),
  `verified` (true once the flags ran end to end), `submodules` (optional:
  clone with `--recurse-submodules --shallow-submodules`), `source_subdir`
  (optional CMake source dir inside the checkout), `notes`. `projects.py`
  validates the required keys (`url tag build cxx_std test wave`) and the
  `build` value. `deps` and `install_configure` are described under
Dependencies. Two optional keys (WP-782): `test_timeout` (seconds, a
positive integer, default 1800) bounds the test command, and `vmem_kb`
(default 3000000, at most 6000000, else a load error) is the wrapper's
address-space cap for the project; `$KILN_OSS_VMEM_KB` in the caller's
environment still wins. A raised cap is documented on the project's
status page.
- `scripts/oss/kiln-cxx`: the compiler wrapper (below).
- `scripts/oss/oss-build.sh <project> [--compiler kiln|clang] [--no-test]
  [--jobs N]`: clone, configure, build, test, `report.json` (below).
- `scripts/oss/oss-report.py [--root DIR] [--toml FILE] [--update FILE]
  [<project>...]`: tables, clusters, the status page.
- `scripts/oss/selftest.sh`: the self-test (Tests).

Everything a run produces is under `.oss/` in the kiln checkout
(`$KILN_OSS_ROOT` overrides; gitignored): `.oss/src/<project>` (the shallow
clone, reused while present; a checkout at another tag is warned about,
not refetched) and `.oss/build/<project>/<kiln|clang>/` (the build tree,
`configure.log`, `build.log`, `test.log`, `compile.jsonl`, `report.json`).

## Dependencies

A project whose build needs other projects installed (`find_package`)
names them in `deps` (a list of cmake projects of the same toml, built in
list order). Before configuring, `oss-build.sh` builds each dependency
with the SAME compiler (`--compiler`) and installs it into
`.oss/<dep>-install-<compiler>/`, unless that directory already holds the
stamp `.oss-installed` (delete the directory to rebuild). The dependency
is built by `oss-build.sh <dep> --compiler <c> --install <prefix>`: build
dir `.oss/build/<dep>/<compiler>-dep/` (its own `compile.jsonl`,
`report.json` and logs, so its TUs never count for the dependent), the
configure flags are the dependency's `install_configure` (for example
tests off, install on) plus `-DCMAKE_INSTALL_PREFIX=<prefix>` instead of
its `configure`, all targets, no tests, then `cmake --install`; the stamp
is written only when build and install both succeed, and a failed
dependency fails the dependent's run before its configure. The
dependent's configure gets
`-DCMAKE_PREFIX_PATH=<prefix>;<prefix>...` for its deps, in order. A
kiln build of the dependent therefore links kiln-built dependencies, and
the clang control links clang-built ones. Dependency builds happen before
the dependent's wall clock starts.

## The wrapper (`kiln-cxx`)

CMake's `CMAKE_CXX_COMPILER` for both builds. It runs `$KILN_OSS_CXX`
(default `clang++-19`, which makes the same wrapper do the control build)
with its own argv, unchanged, in a new session under `RLIMIT_AS` =
`$KILN_OSS_VMEM_KB` KiB (default 3000000, `ulimit -v 3000000`) and a timeout
of `$KILN_OSS_TIMEOUT` seconds (default 600; on expiry the whole process
group is killed). Standard output is inherited; standard error is copied
through as it arrives. SIGINT/SIGTERM/SIGHUP are forwarded to the group.
Exit status: the compiler's, `128+N` for death by signal N, 124 on timeout.

When `$KILN_OSS_LOG` is set, it appends one JSON object per invocation, on
one line, under an exclusive `flock`:

| field | value |
|---|---|
| `v` | 1 (schema version) |
| `ts` | UTC end time, `YYYY-MM-DDTHH:MM:SSZ` |
| `phase` | `$KILN_OSS_PHASE` (`configure`, `build`, `test`; `""` when unset) |
| `cwd` | working directory |
| `argv` | the command executed: `[$KILN_OSS_CXX, args...]` |
| `source` | the first argument ending in `.cpp .cc .cxx .c++ .cp .C .CPP` that is not the value of `-o -MF -MT -MQ -x -include -I -isystem -D -U`; else `"link"` when an argument ends in `.o .a .so .obj .lo` or starts with `@` and none of `-E -c -S -fsyntax-only` is given; else `"none"` (version queries, `-E` of stdin) |
| `output` | the `-o` value, or null |
| `rc` | the compiler's exit status; negative `-N` for signal N |
| `wall_s` | wall seconds, 3 decimals |
| `max_rss_kb` | `getrusage(RUSAGE_CHILDREN).ru_maxrss`: the largest RSS of the compiler and the tools it waited for (the backend, the linker) |
| `diag` | the first stderr line containing `error:`, `panicked`, `fatal`, `undefined reference`, `multiple definition`, `memory allocation of` or `LLVM ERROR` (a `panicked at` line gets ` \| ` and the next line, the panic message, appended), at most 500 chars; else `timed out after N s` / `killed by signal N` / `""` |
| `kind` | the first rule that applies: `timeout` (the timer fired); `ok` (rc 0); `oom` (stderr says `memory allocation of N bytes failed`, `out of memory`, `std::bad_alloc`, `Cannot allocate memory` or `cannot create the compile thread`, kiln++'s diagnostic for a stack reservation over the cap, WP-682); `panic` (`panicked at`, `has overflowed its stack`, or rc 101); `oom` for SIGKILL, `panic` for any other signal; `oom` for rc 70 with empty stderr (a kiln++ older than WP-682 cannot spawn its compile thread, whose 1 GiB stack is reserved up front, under the cap; diag `exit 70 without output (compile thread not spawned)`); `backend` (`backend command failed`, `LLVM ERROR`); `link` (`linker command failed`, `undefined reference`, `multiple definition`, or source `"link"` with no `error:` line); `reject` (an `error:` line); `other` |

Stderr is scanned from its first 256 KiB and last 64 KiB.

## `report.json`

Written by `oss-build.sh` (`projects.py report-json`) into the build dir,
from `compile.jsonl` and `test.log`:

| field | value |
|---|---|
| `schema` | 1 |
| `project`, `compiler` (`kiln`/`clang`), `compiler_path` | as run |
| `url`, `tag`, `cxx_std` | from the toml |
| `date` | UTC time of the report |
| `configure_rc`, `build_rc`, `test_rc` | exit statuses; `build_rc` null when configure failed, `test_rc` null with `--no-test` or when configure failed |
| `test_summary` | the last ctest `N% tests passed, F tests failed out of T` line of `test.log`; else, from the last lit summary (`Total Discovered Tests: T` followed by `  <Result> : N` lines, LLVM's `check-*` targets), `Total Discovered Tests: T, passed P, failed F`; else its last non-empty line |
| `tests` | `{passed, failed, total}` from that ctest line, or from the lit summary (`failed` = Failed + Unexpectedly Passed + Timed Out, `passed` = T − failed, which counts Unsupported, Skipped and Expectedly Failed as passing), else null |
| `wall_s` | configure + build + test wall seconds |
| `tus` | `{total, ok, failed, by_kind}` over the `phase == "build"` lines whose `source` is a file (not `link`/`none`); `by_kind` counts each `kind`. Configure-time probes (`try_compile`, many of which are meant to fail) are excluded by phase |
| `links` | `{total, ok, failed}` over the build lines with `source == "link"` |
| `peak_tu_rss_kb`, `peak_tu`, `max_tu_wall_s` | the largest `max_rss_kb` among those TUs and its source; the longest TU wall |

Each run of `oss-build.sh` truncates `compile.jsonl`, reconfigures with
`cmake --fresh` and runs `make clean` first, so a report always describes
one complete build.

## Build driver rules (`oss-build.sh`)

CMake: `cmake --fresh -S <src>[/<source_subdir>] -B <build> -G "Unix
Makefiles" -DCMAKE_CXX_COMPILER=<abs kiln-cxx> -DCMAKE_C_COMPILER=<c_compiler>
-DCMAKE_CXX_STANDARD=<cxx_std> -DCMAKE_BUILD_TYPE=Release <configure...>`,
then `make -k [<build_targets>]` at `nice 10`. `make` inherits the box's
GNU-make jobserver from `MAKEFLAGS` (`scripts/env.sh`); `-j <--jobs>`
(default 4) is passed only when `MAKEFLAGS` names no live jobserver fifo.
ninja is not a jobserver client, so `meson` projects build with
`meson compile -j <min(--jobs, 4)>`; `make` projects run the project's
Makefile in the source tree with `CXX=<kiln-cxx> CC=<c_compiler>`. The test
command runs under `timeout <test_timeout>` (default 1800) at `nice 10`, with `TMPDIR` and
`TEST_TMPDIR` set to `<build>/test-tmp`, emptied first, so that suites
writing to a fixed path under `/tmp` (leveldb) do not collide when the
kiln and clang builds, or two checkouts, test at once (WP-720). `--compiler kiln` takes
`$KILN_OSS_CXX`, else `$CARGO_TARGET_DIR/harness/kiln++`, prints which, and
exports `KILN_RESOURCE_DIR=<kiln>/resource` unless set; `--compiler clang`
uses `clang++-19` from `PATH`.

## Clusters (`oss-report.py`)

The failures of a build are its `phase == "build"` lines with `kind != ok`
and `source != "none"` (TUs and links). Their **signature** is
`<kind>: <normalized diag>`, where the diag is normalized in this order:

1. a leading location, `<file>:<line>[:<col>]:` or `<file>:(<section>):`,
   is dropped;
2. every quoted span, `'...'`, `"..."`, `‘...’` or `` `...' ``, becomes `Q`;
3. every object or archive name (`*.o`, `*.obj`, `*.a`) becomes `O`;
4. every remaining path (`dir/.../name`) becomes its last component;
5. every digit run becomes `N`;
6. whitespace runs collapse to one space.

Clusters are ordered by size (descending), then by signature. Each lists
its count, how many of its TUs also fail in the clang build (matched by
`source`, links by `output`), and its first TU in log order as the
representative, with its raw diag and its reproduction command:
`cd <cwd> && <basename of argv[0]> <argv[1:]...>` (shell-quoted), with the
kiln checkout (the parent of the `.oss` root) spelled `$KILN/`.

Per project the report prints a table, kiln vs clang-19: configure, build
(`ok`, `rc N`, `not run`), TUs ok / failed, links ok / failed, tests
passed / total (from `tests`, else `ok`/`rc N`), wall, peak TU RSS (MB);
then the clusters; then kiln's test summary line if its tests failed.

`--update FILE` replaces the text between `<!-- oss:<project> -->` and
`<!-- /oss:<project> -->` with the project's section (appending a new
marked block at the end when there is none), and regenerates the table
between `<!-- oss:projects -->` and `<!-- /oss:projects -->` from the toml:
`| project | wave | tag | status |`, ordered by wave then name. The status
of a project with a kiln report: `configuring` (configure failed);
`blocked (N clusters)`; `building` (build failed without TU failures, or
tests not run); `tests at parity` (kiln passes at least clang's count out
of the same total, or both test commands exit 0 without a ctest line);
otherwise `blocked (tests ...)`. A project without a local kiln report
keeps the status the table already had (`not started` when new), so a
partial local run does not reset other projects' rows.

## Tests

`scripts/oss/selftest.sh` (run by hand; it compiles, so it is not in
`ci`): `py_compile` of the three python files, the toml loads,
`bash -n oss-build.sh`; the wrapper on a hello world and a one-line
reject, with clang++-19 and with kiln++ (`$KILN_OSS_CXX`, else
`$CARGO_TARGET_DIR/harness/kiln++` or `debug/kiln++`; skipped without
one), checking every field of the ok, reject and query lines, the exit
status and the stderr pass-through; kiln++ under a 30 MB cap
(`KILN_OSS_VMEM_KB=30000`: `kind` `oom` with a diag); the timeout path
(`KILN_OSS_TIMEOUT=0.01`: rc 124, `kind` `timeout`); `oss-report.py` on
the two-cluster fixture `scripts/oss/fixtures/oss/build/demo/` (3 rejects
that differ only in location and quoted names, one of which also fails
under clang, plus one panic; a failing configure probe that must not
count) against `scripts/oss/fixtures/demo.expected.md`; and `--update` on
`fixtures/status.md` (section replaced, surrounding text kept, the
projects table regenerated with a report-less project's status kept).
