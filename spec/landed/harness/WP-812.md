# WP-812 — Boost heavy libraries in the OSS harness

The M8 harness (spec/landed/harness/WP-666.md) builds the heavy Boost 1.90
libraries (Asio, Beast, Cobalt, Graph, Geometry, Math) through the Boost
CMake superproject, on the shared checkout of WP-787 (`boost_meta`). The
results are in docs/status/oss/boost_heavy.md.

This WP builds on WP-804's version of the Jamfile shim (library rules,
variants, project defines and links), taken byte-identical in
`5c1e70012` so the two branches merge cleanly.

## Landed

- Extensions of `scripts/oss/shims/boost-jamfile-tests.cmake` (the
  WP-787 shim; its header comment is the full contract):
  - On the first line of a statement, a nested `[ requires ... ]` or
    `[ check-target-builds ... ]` is dropped, and so is a conditional
    property (`<toolset>intel:<cxxflags>x`) unless its condition is
    `<target-os>linux`. All of this compiler's features are present, and a
    missing `check-target-builds` dependency fails under the control too.
  - `KILN_BOOST_JAMFILE_SKIP_<lib>`: a regex of test names
    (`<subdir>_<name>`) that are not registered. Asio's `*_select` reruns
    differ only by a Jam variable's defines.
  - `KILN_BOOST_JAMFILE_SUBSET_<lib>` `<N>|<keep>`: a deterministic subset.
    Of all the library's test names, sorted, every N-th is kept (the 1st,
    the N+1-th, ...), plus every name that matches the regex `<keep>`.
    Boost.Math has about 1300 statements.
  - `KILN_BOOST_JAMFILE_FORCE_<lib>` `ON`: the b2 tests are registered even
    when the library's CMakeLists.txt added `test/` itself. Boost.Math's
    CMake tests are only its header compile tests.
  - `KILN_BOOST_JAMFILE_LIBS_<lib>`: items `<jam target>=<glob relative to
    test/>`. A statement whose sources field names `<jam target>` links a
    static library built from the glob, with the tests' includes and
    defines. The library is built only when a registered test needs it.
    Boost.Math uses this for `test_instances//test_instances` (the explicit
    instantiations its tests link) and `compile_test_main` (the
    `init_unit_test_suite` of the `*_incl_test` executables).
  - `KILN_BOOST_SUBSET_TARGETS` `<regex>|<N>|<keep>`: a deterministic
    subset of the `tests` target's dependencies, for a CMake suite too large
    to build whole. Boost.Geometry has about 400 test executables. The
    dependencies whose name matches `<regex>` are sorted; every N-th is
    kept, plus every one that matches `<keep>`; dependencies that do not
    match are all kept. The kept ones are the dependencies of the new
    target `kiln_tests`, which the row builds instead of `tests`. The
    dropped names go to `<build>/kiln-subset-excluded.txt`, one per line,
    for `ctest --exclude-from-file`; a dropped target's test has the
    target's name. Configure prints `kiln: subset /<regex>/: K of N test
    targets kept`.
- The `boost_heavy` row: tag `boost-1.90.0` with submodules, C++20,
  Release, `BUILD_SHARED_LIBS=OFF`, MPI and Python off.
  - `BOOST_INCLUDE_LIBRARIES` holds the six libraries.
  - The b2 tests of Asio, Graph and Math are registered through the shim.
    Math's are FORCEd and subset to every 8th plus the names matching
    `constexpr|float128|lanczos|ccmath`.
  - Geometry's CMake tests are subset to every 4th.
  - It builds `kiln_tests` and runs `ctest -j 4 --timeout 300` with the
    subset file, minus 19 tests that fail under the clang-19 control
    (listed with their causes in the status page).

## Tests

- `scripts/oss/selftest.sh`:
  - `boost shim: nested requires, conditionals, skip, subset, force`;
  - `boost shim: a Jam library target links a static library from its
    glob`;
  - `boost shim: a library with CMake tests is skipped without FORCE`;
  - `boost shim: target subset (every N-th plus keep regex)`.
- `scripts/oss/oss-build.sh boost_heavy`, once with `--compiler clang` and
  once with kiln, end to end (docs/status/oss/boost_heavy.md).
- System Boost: `/usr/include/boost` (1.83) never appears in a TU's
  dependencies. A `-M` of Geometry's `test/algorithms/area/area.cpp` lists
  the same 1795 in-tree Boost and system headers under clang++-19 and
  kiln++. The only difference is the 21 compiler resource headers: kiln's
  `resource/include` against `/usr/lib/llvm-19/lib/clang/19/include`.

## Compiler fixes (one commit per cluster)

1. P0522 template template argument deduction
   (`p0522-deduce-defaulted-args-run.cpp`,
   `p0522-partial-order-unique-ttp-clang{19,22}.cpp`; spec/sema-templates.md
   §6.2). `U<T>` deduces from a template-id whose trailing arguments are
   the template's defaults. Under partial ordering, a unique type follows
   clang 19 or clang 22 according to `-fclang-compat`.
2. A parenthesized yield-expression, `(co_yield x)`
   (`expr.yield/parenthesized-run.cpp`; spec/parse.md).
3. Two Boost.Cobalt promise fixes (spec/sema.md):
   - A dependent member using-declarator does not conflict with a
     function that a later using-declarator introduces
     (`namespace.udecl/dependent-member-using-overloads-run.cpp`).
   - A promise's `operator new` / `operator delete` compare parameter
     types without top-level cv
     (`dcl.fct.def.coroutine/promise-new-delete-const-size-run.cpp`).
4. An explicit instantiation definition skips the still-dependent
   partial specialization of a member class template. Members of an
   implicit specialization of a member template keep that
   specialization's kind (`temp.explicit/member-partial-spec-dependent-run.cpp`,
   `tests/codegen/explicit_inst_member_partial_spec.cpp`;
   spec/sema-templates.md, spec/codegen.md).
