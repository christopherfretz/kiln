# WP-792 — M8 wave 4: constexpr stress projects

Wave 4's constexpr-heavy projects run through the M8 OSS harness
(spec/landed/harness/WP-666.md): `ctre`, `glaze`, `mp_units`, `scnlib`,
`daw_json_link` and `reflect_cpp`. Their status pages are
`docs/status/oss/<project>.md`; the index and the "Constexpr performance"
section are in `docs/status/oss.md`.

## Landed

- `scripts/oss/projects.toml`: the six rows (`wave = 4`,
  `verified = true`), each with a `notes` line naming what is turned off
  and why.
- `control_cxx` (projects.toml key; default `clang++-19`): the control
  build's C++ compiler, looked up on `PATH` by `oss-build.sh
  --compiler clang`. `mp_units` sets `g++-16`, because clang 19 cannot
  build mp-units v2.5.0 and clang 22 rejects most of it. The build
  directory is still `.oss/build/<project>/clang/`. Reports name the
  control `clang-NN` or `gcc-NN`, from the control report's compiler
  path, and fall back to `clang-19`.
- `scripts/oss/shims/daw-pin-header-libraries.cmake`: a
  `CMAKE_PROJECT_<name>_INCLUDE` shim that pins daw_json_link's
  FetchContent of `header_libraries` to `v2.135.0`. The upstream default
  is the moving `v2` branch, and that branch no longer builds v3.38.1.
- `kiln-cxx` writes `cpu_s` on every JSONL line. It is the child's user
  plus system time from `RUSAGE_CHILDREN`, the same accounting as
  `max_rss_kb`.
- `oss-report.py --perf` adds a performance block to each project's
  section, over the TUs that compiled under both compilers. It uses the
  last `ok` build-phase line for each source.
  - Time is CPU seconds when every such line in both logs has `cpu_s`.
    Otherwise it is wall seconds.
  - The block gives the geomean of kiln/control time and RSS, the totals,
    the peak TU RSS, and the five heaviest TUs by control time.
  - It lists the TUs over 1.2x on either time or RSS. Only TUs that take
    the control at least 0.5 s are counted, because below that process
    start-up dominates the ratio. The 1.2x threshold is the brief's perf
    cluster bar.

## Tests
