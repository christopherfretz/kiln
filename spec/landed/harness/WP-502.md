# WP-502 — GCC 16.1 in the CI path: the reflection oracle in both CI jobs

- **CI image** (`.github/workflows/ci.yml`, "CI"): both jobs, `check`
  (aarch64) and `check-x86_64`, run in `gcc:16.1.0-trixie` instead of
  `debian:trixie`, with `KILN_GCC=/usr/local/bin/g++` and
  `KILN_REQUIRE_GCC=1` in the job env next to `KILN_REQUIRE_LLVM=1`. The
  image ships git, so the `Install git` step is gone. Debian's GCC 14
  stays the GCC installation that clang and kiln detect for libstdc++
  (`/usr/lib/gcc/<triple>/14`); GCC 16.1 is only the `oracle: gcc`
  reference. The composite action (`.github/actions/kiln-ci/action.yml`)
  checks `$KILN_GCC -dumpfullversion` is 16.1.x and that it compiles a
  `<meta>` TU with `-std=c++26 -freflection`.
- **`KILN_REQUIRE_GCC=1`** ("GCC oracle"): `cargo xtask test` and
  `cargo xtask ci` exit 2 when no usable GCC oracle is configured
  (`xtask/src/oracle.rs` `require_gcc_from_env`,
  `xtask/src/test/mod.rs` `gcc_oracle`); `--no-gcc`/`--no-oracle` under it
  are the same error. Test: `require_gcc_makes_a_missing_gcc_an_error`.
- **The log proves the oracle ran** ("Output"): the header names the GCC
  and its `--version` line; the summary gains `G compared with gcc; `
  (tests GCC compiled to a verdict; `TestResult::gcc_compared`). Test:
  `gcc_oracle_with_a_fake_gcc` (9 comparisons, none with an advisory),
  `report::tests`.
- **`tests/conformance/meta.reflection.ci/`**: four `run` tests with
  `oracle: gcc` on the reflection on `main` (info equality, type splices,
  info template arguments, `type_of` and names), compared with GCC 16.1's
  stdout and exit status in both corpus runs of both jobs.
- **Measured cost**: docs/status/perf-history.md "WP-502: GCC 16.1 in CI".
