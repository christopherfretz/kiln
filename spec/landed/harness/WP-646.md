# WP-646 — docs: the standard support table (every C++ standard, every core-language feature), linked from the README

- **The table** (`docs/STANDARD_SUPPORT.md`, `git mv`ed from
  `docs/status/cxx-features.md`, which is now a pointer): a summary table
  (Standard, `-std=`, `__cplusplus`, done / partial / todo / untested),
  then one section per standard. New sections C++98/03 (6 rows: the
  baseline areas by stable name plus CWG178), C++11 (43), C++14 (11),
  C++17 (36) and C++20 (54): every SD-6 core `__cpp_*` macro of those
  standards with its paper, plus the macro-less core features compiler
  support tables list. A "kiln extensions" section (5 rows, keyed by WP)
  covers `__kiln_define_member`, `__kiln_plainly_constant_evaluated`, the
  `__KILN__` predefines, `-fclang-compat` and the Oven budget flags. The
  C++23, C++26, C++26 reflection and DR sections moved unchanged in
  substance; "Macro gaps" gains the per-standard gaps.
- **Evidence**: rows cite existing corpus tests where they cover the core
  forms; 40 new one-file probes (`tests/conformance/<section>/<paper>-probe.cpp`,
  WP-185 style) cover the rest. Every probe passes under both oracles
  except `expr.sub/p1161-probe.cpp`, `xfail(kiln)`: at C++20 kiln parses
  `a[i++, j]` as a multidimensional subscript. No row is `untested`.
- **Checker** (`xtask/src/features.rs`, spec/harness.md "Feature table"):
  the default table is the new file; a table's standard comes from its
  macro header cell (`at -std=c++NN`), and macros are checked at it; macro
  cells may hold several macros; paper keys also take `N<n>`, `CWG<n>`,
  `WP-<n>` and `[stable.name]`; status `untested`; check (d), the summary
  against the per-section counts and each summary row's `__cplusplus`
  under kiln; `--summary`. Still outside `ci`.
- **Tests**: `summary_matches_sections`, `summary_parse_errors`,
  `macros_are_read_at_the_tables_standard`, the extended
  `xtask/fixtures/features/{good,bad}.md`, and
  `checks_the_real_table_parses` (now also checks the real summary).
- **Follow-ups found, not fixed**: `__cpp_static_assert` below C++26
  (clang 19's 200410 / 201411L; clang 22 has 202306L in every mode);
  `__cpp_constexpr` at C++20 (201907L; clang 22 202002L); the P1161
  subscript-comma parse above; kiln rejects a nested
  `V<V<int> >::type::type(3)` functional cast as a template argument
  ("'type' does not refer to a value"; clang accepts).
