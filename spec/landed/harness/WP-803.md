# WP-803 — M8 wave 4: oneTBB and OpenCV

Two runtime-heavy projects run through the M8 OSS harness
(spec/landed/harness/WP-666.md): oneTBB v2022.3.0 (task-parallel
runtime, atomics, `tbbmalloc`) and OpenCV 4.12.0 (`core`, `imgproc`,
`features2d`, `flann`, `calib3d` and the `ts` test framework, with the
default NEON dispatch). Their status pages are
`docs/status/oss/onetbb.md` and `docs/status/oss/opencv.md`; the index
is `docs/status/oss.md`.

## Landed

- `scripts/oss/projects.toml`: the `onetbb` and `opencv` rows
  (`wave = 4`, `verified = true`).
- `scripts/oss/opencv-gtest-exclude.txt`: the OpenCV gtest cases that
  fail under the clang-19 control because the `opencv_extra` test data
  is absent. The `opencv` test command passes them to `GTEST_FILTER`
  as a negative filter, for both compilers.
- `oss-build.sh` expands `@OSS@` in the `test` command as well as in
  `configure` flags.

Front-end fixes, each with its spec sentence and a conformance test:

- `-ffp-model=precise` is accepted; it is clang's default model
  (spec/driver.md).
- `#pragma weak name` makes a declared function or variable a weak
  symbol (spec/parse.md, spec/sema.md; `cpp.pragma/weak-*.cpp`).
- `__builtin___memcpy_chk` and the other `__builtin___*_chk` fortify
  builtins (spec/codegen.md, spec/oven.md;
  `ext.gnu.builtins/fortify-chk-run.cpp`).
- clang's `pass_object_size` and `overloadable` attributes, which
  glibc's clang `_FORTIFY_SOURCE` headers use (spec/sema.md,
  spec/sema-overload.md, spec/codegen.md, spec/abi.md;
  `ext.clang.pass.object.size/`). A using-declaration that names such
  an overload does not conflict with it (`namespace.udecl/`).
- `new (T().f()) U` is a placement new-expression, not a parenthesized
  type-id (spec/parse.md; `expr.new/placement-temporary-member-call-run.cpp`).
- Invalid UTF-8 is an error only inside a token, not inside a comment
  (spec/pp.md; `lex.phases/invalid-utf8-in-comment-run.cpp`).
- NEON `vshll_n`, `vrshrn_n`, `vqmovun`, `vpadal`,
  `vqneg` and `vqabs` (spec/landed/codegen/WP-628.md;
  `target.neon/ld2-st2-widen-run.cpp`, `target.neon/ir-ld2-widen-19.cpp`).
- NEON `vcvt{n,a,m,p}`, `vhadd`/`vrhadd`/
  `vhsub`, `vq{,r}shr{n,un}_n`, `vqshl_n`, `vrshr_n` and `vtbl1`/`vtbl2`
  (spec/landed/codegen/WP-628.md;
  `target.neon/ld34-cvt-qshrn-tbl-run.cpp`,
  `target.neon/ir-ld34-cvt-qshrn-tbl-19.cpp`).
- A base-specifier, and a `D::template f<U>` id-expression, that names a
  member of a dependent base of the current instantiation names a
  member of an unknown specialization ([temp.dep.type]/6;
  spec/sema-class.md; `temp.dep.type/`).
- An unqualified mem-initializer-id that the definition of a constructor
  in a class with a dependent base resolves to an enclosing typedef is
  bound to it there ([temp.res.general]/1; spec/sema-class.md §4.9;
  `class.base.init/typedef-bound-at-definition-run.cpp`).
- A friend declaration of a class being defined holds inside an
  instantiation that starts within that class's definition (spec/sema-class.md
  §2.4; `temp.friend/specialization-instantiated-in-befriending-class-run.cpp`).
- A friend class template declaration redeclares the template that
  ordinary lookup finds in a namespace the innermost enclosing namespace
  encloses, such as an unnamed namespace (spec/sema-class.md §2.4;
  `temp.friend/class-template-in-unnamed-namespace-run.cpp`).
- The `template<>` head of an explicitly specialized member is consumed
  by the member's declaration, so the body's local declarations are not
  under it (spec/sema-templates.md;
  `temp.expl.spec/special-member-spec-body-locals-run.cpp`).
- `e.operator T()` naming a conversion function template specialization
  deduces the object class's conversion templates against `T`
  ([temp.mem]/6; spec/sema-templates.md;
  `temp.mem/conversion-template-named-explicitly-run.cpp`).
- NEON `vaddlv`, `vshl`, `vrshl`, `vqshl`, `vqrshl` and the `dotprod`
  `vdot` family
  (spec/landed/codegen/WP-628.md; `target.neon/ld34-cvt-qshrn-tbl-run.cpp`,
  `target.neon/ir-ld34-cvt-qshrn-tbl-19.cpp`, `target.neon/dotprod-run.cpp`,
  `target.neon/ir-dotprod-19.cpp`).

  `temp.spec.partial.general/template-template-pack-expansion-arg-run.cpp`).
