# WP-787 — Boost superproject in the OSS harness

The M8 harness (spec/landed/harness/WP-666.md) builds Boost 1.90 through
its CMake superproject. The three Boost rows (WP-787 `boost_meta`, and its
two siblings) share one clone and differ only in their library lists.
The results are in docs/status/oss/boost_meta.md.

## Landed

- `projects.toml` key `checkout` (default: the project name). It names the
  directory under `.oss/src/` that `oss-build.sh` clones into and builds
  from (`SRC=$OSS/src/$P_CHECKOUT`). `projects.py load` refuses two rows
  that share a checkout but disagree on `url`, `tag` or `submodules`.
- `scripts/oss/shims/boost-jamfile-tests.cmake`, passed as
  `-DCMAKE_PROJECT_Boost_INCLUDE=@OSS@/shims/boost-jamfile-tests.cmake`
  (`@OSS@` is replaced with `scripts/oss`). Some libraries have only b2
  tests in a superproject build: there is no `test/CMakeLists.txt`, or the
  library adds its `test/` directory only when built standalone. For each
  library in `-DKILN_BOOST_JAMFILE_LIBRARIES=a;b;…` that is built and has
  no CMake tests, the shim registers its b2 tests with Boost's own
  `boost_test()`, so they build under `make -k` and run under ctest like
  the CMake tests:
  - Every `run`, `run-fail`, `compile`, `compile-fail`, `link` and
    `link-fail` statement in the library's `test/Jamfile*` files is read
    from its first line only. That gives the sources, the `<define>`
    requirements on that line and the target name.
  - A library whose Jamfile builds its list with a `glob` rule (hana,
    hof, type_traits, callable_traits) instead takes the list from
    `KILN_BOOST_JAMFILE_GLOB_<lib>`. Optional companions are
    `KILN_BOOST_JAMFILE_EXCLUDE_<lib>` (a regex of sources to leave out)
    and `KILN_BOOST_JAMFILE_INCLUDE_<lib>` (extra include directories
    under `test/`).
  - Test names are `<type>-<lib>-<subdir>_<name>`. Every test sees every
    library's `include/` directory, like b2's unified header tree.
  - Anything that needs more than the first line of a statement fails
    under the clang control too. Such tests are excluded with ctest `-E`
    in the project row, and the row's `notes` say why.
- The `boost_meta` row: tag `boost-1.90.0` with submodules, C++20, Release.
  `BOOST_INCLUDE_LIBRARIES` holds the 20 header-only metaprogramming
  libraries. The tests run with `ctest -j 4 --timeout 300`, minus the 12
  tests that do not compile under the clang-19 control either.

## Tests

- `scripts/oss/selftest.sh`: `checkout defaults to the project name`, `a
  shared checkout is accepted`, `a shared checkout at another tag is
  refused`.
- `scripts/oss/oss-build.sh boost_meta`, once with `--compiler clang` and
  once with kiln, end to end (docs/status/oss/boost_meta.md).
- System Boost: `/usr/include/boost` (1.83) never appears in a TU's
  dependencies. A `-M` of `libs/outcome/test/tests/comparison.cpp` lists
  510 in-tree Boost headers under clang++-19, 505 under kiln++, and 0
  under `/usr/include/boost` for either.
