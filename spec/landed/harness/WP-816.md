# WP-816 — debugger tests in GitHub CI

`tests/debuginfo` (the `expect: debugger` tests of WP-814, spec/harness.md
"Debugger tests") is a default root and runs in GitHub CI on both
architectures. Without the debuggers the tests still SKIP, with the
reason, except where `KILN_REQUIRE_DEBUGGERS=1` makes that an ERROR.

## Landed

- `xtask/src/test/discover.rs` `default_roots`: `tests/conformance`,
  `tests/debuginfo`, `tests/differential`, `tests/stress`. `cargo xtask
  test` with no paths and both `ci` corpus runs include the debugger
  tests.
- `KILN_REQUIRE_DEBUGGERS` (`test::REQUIRE_DEBUGGERS_ENV`; required by
  exactly `1`, as `KILN_REQUIRE_GCC`). `test::Options::require_debuggers`
  and `runner::Config::require_debuggers` carry it. The entry points read
  it (`cargo xtask test`, `ci_corpus`), never the harness's own tests.
- `runner::debugger_gate`: an `expect: debugger` test whose gdb (or
  `lldb-19`/`lldb`) is not on `PATH` is a SKIP, `requires `gdb` on PATH
  (`expect: debugger`)`, or with the requirement an ERROR,
  `KILN_REQUIRE_DEBUGGERS=1 and `gdb` is not on PATH (`expect:
  debugger`)`. Only the debuggers the test drives are needed.
- Each debugger session runs for at least `DEBUGGER_TIMEOUT` (60 s),
  whatever `--timeout` says. A session that runs out is a FAIL that names
  the timeout and shows the output so far. `DEBUGINFOD_URLS` is removed
  from the debugger's environment, so no session reaches the network.
- `.github/actions/kiln-ci`: the `debuggers` input (default `"false"`).
  When it is `"true"`, the first step also installs `gdb lldb-19` and
  prints both versions.
- `.github/workflows/ci-lane.yml`:
  - The lane env sets `KILN_REQUIRE_DEBUGGERS: "1"`.
  - `self-check`, `kiln-22`, `kiln-19` and `unit` run in the anchored
    container `&debugger-container` (`gcc:16.1.0-trixie` with
    `--cap-add=SYS_PTRACE`).
  - The three corpus jobs pass `debuggers: "true"`. `unit` passes it for
    the `xtask` group, where `debugger_fixtures_with_clang` then runs
    instead of returning early.
  - `lints` is unchanged.
- Docs: spec/harness.md "Debugger tests", "Command line" and "CI";
  docs/VALIDATION.md (a Debugger layer row, "What runs where",
  "GitHub Actions"); docs/status/debuginfo.md (the "not in CI" gap and
  follow-up are removed).

## Tests

- `runner::compat_tests::debugger_gate_skips_or_errors_without_the_debugger`:
  a SKIP without the requirement and an ERROR with it, for a missing gdb
  and for a missing lldb. A gdb-only test needs only gdb. A test that is
  not a debugger test is never gated.
- `test::tests::debugger_corpus_is_a_default_root`: the
  `KILN_REQUIRE_DEBUGGERS` values, and `tests/debuginfo` among the
  default roots.
- `ci_tests::workflow_installs_the_debuggers`: `ci-lane.yml` sets the
  requirement, and every job that runs `--step kiln` or `--step
  self-check` passes `debuggers: "true"` and uses the `SYS_PTRACE`
  container.
- `tests/debuginfo/*.cpp` themselves, now in every corpus run.

## Deviations

- The debuggers are installed with apt in each corpus job and are not
  cached; the workflows cache no apt packages.
- The containers keep Docker's default seccomp profile. It allows
  `ptrace` but blocks the `personality` call that disables ASLR, so the
  lldb scripts keep `settings set target.disable-aslr false` and the
  checks avoid addresses. The development container runs the tests the
  same way, without `CAP_SYS_PTRACE`.
