# WP-1241 — a missing OSS report fails the sweep job

A sweep `oss <project> <compiler>` job whose project could not be fetched
(sweep/rc-1.0.0: opencv under kiln, a DNS failure in the clone) used to
end green: `oss-build.sh` exited 1 before writing `report.json`, the step
printed the logs and exited 0, and `oss-summary` skipped the project. The
release gate could pass with a project unmeasured.

## Rules

- `oss-build.sh` writes `report.json` whenever it gets as far as
  configuring; a failed configure, build or test run is recorded in the
  report (`configure_rc`, `build_rc`, `test_rc`, spec/landed/harness/WP-666.md
  "`report.json`") and the script exits 0 (except `--install`, which
  exits non-zero on a failed dependency build). Every exit before that
  point (a usage or toml error, a missing compiler or scanner, a failed
  dependency, a failed clone or download) leaves no report. So "no report" means the
  project was not measured: an infrastructure failure, never a result.
- The fetch is retried once: a failed `git clone`, or a failed tarball
  download, runs again after `KILN_OSS_FETCH_RETRY_S` seconds (default
  30). A clone that fails after creating the checkout directory (a
  submodule) is not retried. Nothing else is.
- `.github/workflows/sweep.yml`, job `oss`: after `oss-build.sh`, a
  missing `report.json` prints `::error title=oss no report::` naming the
  project, the compiler and the exit status, and fails the job. With a
  report the step exits 0 whatever the build and tests did; parity is the
  summary's business.
- `oss-report.py --expect COMPILERS` (comma-separated, `kiln` and/or
  `clang`) takes the positional projects as the expected set: the output
  opens with `Reports: R of the N expected project/compiler pairs.`, and
  when R < N continues `**No report (infrastructure): K**:` with each
  missing pair. Every expected project keeps its section; a missing
  compiler gets a `**<compiler>: no report (infrastructure).**` line
  under the heading (the toml's tag names the heading when neither report
  does). Without a kiln report the clusters line says
  `Failure clusters (kiln): no kiln report.`, never `none.` (with or
  without `--expect`). `--expect` with an unknown compiler or no projects
  is a usage error.
- Job `oss-summary` runs `oss-report.py --expect "$OSS_COMPILERS"
  $OSS_PROJECTS`, the two env values spelling the oss matrix's compiler
  expression and project list once more (a job that timed out or never
  ran uploads no artifact, so the artifact names cannot list what is
  missing). `ci_tests::sweep_never_gates` checks that they equal the
  matrix's.

## Tests

- `scripts/oss/selftest.sh`: the five `--expect:` checks (the lead line,
  a project with no report keeps its section, a missing kiln report is not
  `none`, all present leaves the section as without `--expect`, an
  unknown compiler is a usage error).
- `ci_tests::sweep_never_gates` (xtask/src/main.rs): `OSS_PROJECTS` and
  `OSS_COMPILERS` against the matrix.
