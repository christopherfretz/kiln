# WP-1265 — the sweep's OSS lists are spelled once

`.github/workflows/sweep.yml` used to spell the oss matrix's project list
twice (the matrix's `project:` line and the oss summary's `OSS_PROJECTS`)
and its compiler expression twice (`compiler:` and `OSS_COMPILERS`), with
`ci_tests::sweep_never_gates` keeping the copies equal by comparing the
text. A project added to one place and not the other was caught only by
that test.

## Rules

- `scripts/oss/projects.toml` takes an optional boolean key `sweep`
  (default false; any other type is a load error). The rows with
  `sweep = true` are the x86_64 sweep's OSS projects; adding or dropping
  a project is that one key.
- `projects.py list --sweep` lists only those rows (combinable with
  `--wave`); `--json` prints the selected names as one JSON array on one
  line, in toml order, instead of one name per line.
- Job `oss-matrix` (`if: push || inputs.oss`, as job `oss`) runs
  `projects.py list --sweep --json` on a sparse checkout of
  `scripts/oss` and outputs `projects` (that array; an empty list fails
  the job) and `compilers`: `["kiln", "clang"]` when
  `github.event_name == 'push' || inputs.control` (a push has no
  inputs, so it always runs the clang 19 control; a dispatch follows
  `control`), else `["kiln"]`.
- Job `oss` needs `oss-matrix`; its matrix is
  `project: ${{ fromJSON(needs.oss-matrix.outputs.projects) }}` and
  `compiler: ${{ fromJSON(needs.oss-matrix.outputs.compilers) }}`.
- Job `oss-summary` needs `oss-matrix` and `oss` and runs whenever the
  oss jobs ran (`!cancelled() && needs.oss.result != 'skipped'`, as in
  WP-1241); its `OSS_PROJECTS` is
  `join(fromJSON(needs.oss-matrix.outputs.projects), ' ')` and its
  `OSS_COMPILERS` `join(fromJSON(needs.oss-matrix.outputs.compilers),
  ',')`, passed to `oss-report.py --expect "$OSS_COMPILERS"
  $OSS_PROJECTS`. So a pair whose job timed out or was never scheduled is
  still expected and still shows as "no report (infrastructure)"
  (spec/landed/harness/WP-1241.md). If `oss-matrix` itself fails, `oss`
  and the summary are skipped and the run is red at `oss matrix`.

## Tests

- `ci_tests::sweep_never_gates` (xtask/src/main.rs): the triggers (no
  `pull_request` or `merge_group`), as before; `oss-matrix` outputs both
  lists from `projects.py list --sweep --json` and the control rule;
  `oss` and `oss-summary` need it, their matrix and `OSS_*` env read its
  outputs and no other `fromJSON` list, neither job names a sweep
  project, and the summary keeps its WP-1241 `if:`; projects.toml has at
  least one `sweep = true` row.
- `scripts/oss/selftest.sh`: `list --sweep --json` is one JSON line
  equal to the `sweep = true` rows; a non-boolean `sweep` is refused.
