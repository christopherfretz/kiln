# WP-1169 — template-ids, `typeof` and pack indexing in an out-of-line member's signature

WP-1169 closes the two WP-1154 gaps: a template-id inside a signature
expression, and the `typeof`, pack-indexing and profile-only array forms.
The rule is in spec/sema-class.md §8.3, under "Out-of-line declarator
scope". Every case is checked against clang 22 and clang 19 (pack
indexing against clang 22 only, since clang 19 does not implement P2662).

- **The rule** ([temp.dep.type]/1, /6, [temp.over.link]/5, /7). The
  signature of an out-of-line member of a class template is rebuilt in
  the current instantiation, so it is equivalent to the in-class
  declaration. WP-1169 rebuilds four more forms:
  - a template-id naming a member of the current instantiation:
    `I<C<X>::template f<U>() + C<X>::N>`, `I<C<X>::template vk<2>>`.
    `ci_member_ref` forms the class's own template-id
    (`ci_member_template_id`), and keeps `template` for the mangling;
  - a `typeof`/`__typeof__` operand, both as the whole decl-specifier and
    nested in a type (`rebuild_ci_expr_type`, through
    `Substituter::ci_expr_operand_ty`);
  - a pack-indexing type `Ts...[I]` nested in a type, and the index of a
    pack-indexing expression `Ns...[I]`. A pack expansion in a qualifier's
    arguments (`D<Ns...>::K`) rebuilds its pattern;
  - a dependent array whose bound is stored only as a profile
    (`profile_expr` gives back its expression).
- **Still not equivalent** (clang agrees):
  - a pack-indexing type that is the whole decl-specifier. clang's
    `RebuildDeclaratorInCurrentInstantiation` does not rebuild it, so
    `Ts...[C<Ts...>::M]` is not the in-class `Ts...[M]`;
  - a pack index whose rebuilt form is no longer value-dependent:
    `Ns...[D<Ns...>::K]` and `Ns...[sizeof(typename D<Ns...>::T)]`.
    clang converts the index only when it is not instantiation-dependent,
    and the written qualifier keeps the rebuilt one so.
    `ci_index_value_dependent` keeps the written index there. It treats
    `sizeof`/`alignof` of a non-dependent canonical type as not
    value-dependent, because kiln's elaborated `typename D<Ns...>::T`
    is still flagged dependent;
  - an operand or bound that really differs (`N + 1` for `N`).
- **Profiles** (spec/types.md §7.2). The explicit arguments of an
  unresolved name used to be profiled by their canonical list word. A
  non-dependent expression argument is canonical only by identity, so
  `C::template g<1>()` never matched itself. A list holding one is now
  profiled per argument (`push_args`, crates/kiln_ast/src/types/profile_expr.rs).
- **Mangling** (spec/abi.md). An unresolved qualifier that names a class
  template specialization with no written template-id, such as the
  current instantiation `C::` or `C<X>::` in a member of `C<int>`, is
  clang's `Type::Record` case: the bare name `sr1CE1f`, not `sr1CIiEE1f`.
  This was wrong in-class too.
- **Tests** (tests/conformance/temp.dep.type/):
  - `out-of-line-current-instantiation-template-id-run.cpp` and `-neg.cpp`;
  - `out-of-line-current-instantiation-typeof-run.cpp` and `-neg.cpp`;
  - `out-of-line-current-instantiation-pack-index-run.cpp` and `-neg.cpp`,
    which need clang 22;
  - `ir-out-of-line-current-instantiation-template-id-typeof-mangling.cpp`;
  - the xfail `out-of-line-current-instantiation-var-template-unqualified-run.cpp`;
  - and in tests/mangle/, `current_instantiation_qualifier.cpp`.
- **Follow-ups:**
  - clang 22, unlike clang 19, treats a variable template-id written
    unqualified in the class and qualified out of line (`vt<3>` and
    `C<X>::template vt<3>`) as equivalent. The same holds for `N::v<T>`
    and `v<T>` at namespace scope. Kiln follows clang 19 here; the xfail
    test above records it;
  - `decltype(C<Ts...>::N)` and the in-class `decltype(N)`: clang rejects
    the pair, kiln accepts it. The qualifier keeps the rebuilt operand
    instantiation-dependent in clang.
