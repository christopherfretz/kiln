# WP-1152 — destructor-call correctness (the WP-999 subset)

WP-1152 takes the correctness items of WP-999. The rules are in
spec/sema-class.md §8.3, under "Member names" and "Out-of-line declarator
scope". Every case is checked against clang 22 and clang 19.

- **Oven lifetime** ([basic.life]/1, [expr.prim.id.dtor]/2,
  [expr.const]/10). This was already done on main by WP-222, so no code
  changed here.
  - An explicit destructor call or a pseudo-destructor call ends the
    object's lifetime during constant evaluation. This holds for
    `p->~I()`, `p->~U()` in a template, `x.I::~I()`, `x.~decltype(x)()`
    and `p->~S()`.
  - Each of these is then "... of object outside its lifetime is not
    allowed in a constant expression":
    - a later read,
    - an assignment,
    - a second destruction.
  - Placement new or `construct_at` starts a new lifetime
    (basic.life/constexpr-lifetime-local.cpp).
  - Lockdown test: `tests/conformance/class.dtor/explicit-destructor-call-lifetime-constexpr.cpp`.
- **Qualified destructor names** ([basic.lookup.qual.general]/4,
  [expr.prim.id.dtor], [expr.ref]/4, [class.virtual]/16).
  - **Lookup order.** In `p->N::C::~Q`, `Q` is looked up in these scopes,
    in order:
    1. the qualifier `N::C`,
    2. its prefix `N` (`nns_prefix_ctx`),
    3. the object's class,
    4. the enclosing scope.
    So `p->N::TT::~TT()` and `p->N::T::~TT()` find a typedef `TT` of
    namespace `N`.
  - **Template-ids.** A destructor template-id finds its template in the
    same scopes (`classify_member_destructor_template`). These forms are
    accepted:
    - `c->N::C<int>::~C<int>()`, `c->~C<int>()`;
    - `c->~C<X>()` on a dependent `N::C<X>*` ([temp.local]/1).
  - **Diagnostics** (`diagnose_destructor_non_template`):
    - a qualified name that is not a template:
      `sema_dtor_name_not_template`, "destructor name 'v' does not refer
      to a template";
    - an unqualified name that is not a template: "'v' does not refer to
      a template", plus the declared-here note;
    - a name that is not found: "no member named 'Nope' in 'N::C<int>'";
    - a template-id that names a different class: "no member named '~C'
      in 'N::C<int>'".
  - **Codegen.** A qualified call is non-virtual. An unqualified call
    dispatches virtually.
  - Tests:
    - `tests/conformance/expr.prim.id.dtor/run-qualified-destructor-template-id.cpp`
    - `tests/conformance/expr.prim.id.dtor/qualified-destructor-template-id-errors.cpp`
- **`typename C<X>::T` before an out-of-line declarator-id**
  ([temp.dep.type]/6, [temp.over.link]/5, [dcl.meaning]/1).
  - Template substitution already rebuilt `typename X::T` at every
    nesting depth, so it needed no change.
  - **Out-of-line rebuild.** `rebuild_in_current_instantiation` now also
    rebuilds the dependent name when it is nested in:
    - a function type (both the return type and the parameter types);
    - a member pointer;
    - an array;
    - declarator parentheses.
    Each of these can itself sit inside a template argument
    (`rebuild_ci_compound`). Examples: `W<void(typename C<X>::T)>`,
    `W<typename C<X>::T[2]>`, `W<typename C<X>::T C<X>::*>`.
  - **Declarator scope.** After a parenthesized declarator that holds the
    qualified declarator-id, the parser enters the declarator scope again
    for the outer suffixes. So `X (*C<X>::f())(T)` finds `T` in `C<X>`.
  - Test: `tests/conformance/temp.dep.type/out-of-line-current-instantiation-nested-declarator-run.cpp`.
  - **Gap.** A `decltype` operand is not rebuilt. clang does this with
    `RebuildExprInCurrentInstantiation`. Xfail test:
    `tests/conformance/temp.dep.type/out-of-line-current-instantiation-decltype.cpp`.
