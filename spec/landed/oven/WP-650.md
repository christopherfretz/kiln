# WP-650 — One decode per memory access, cheap-first access check in the Oven

No observable rule changes: spec/oven.md "Checks on every access" (the
order of the checks, so which fault and note an access reports), the
pointer encoding and every interface are unchanged. This file records
where the change lives and the tests.

- **Problem.** Every `Load`/`Store` ran `Memory::check`, an outlined
  call that ran `check_storage`, itself an outlined call: decode the raw
  pointer, look its slot up (`alloc_of`, matching the space a second
  time), test liveness, past-the-end, bounds, the `EXTERNAL` origin and
  `UNBACKED` in order, match the space a third time for the result, and
  return a `Result` through memory, which `rmw_check` (outlined from the
  `Load` arm) returned through memory again. Pointer arithmetic
  (`ptr_add`) called the outlined `extent_of`, which decoded the
  pointer again and returned its `Result` through memory. Measurement:
  docs/status/perf-reflection.md "WP-650: memory-access check".
- **Fix.** In `crates/kiln_oven/src/mem.rs`:
  - `check_plain` (always inlined): one predicate that is true exactly
    when the ordered checks accept the access without consulting the
    allocation's origin: the slot's allocation exists with the pointer's
    generation and is live, the offset with the past-the-end bit kept
    (so a past-the-end pointer's offset exceeds every size) plus the
    length is within the size, not `UNBACKED`, and no flag of a mask
    that always holds `EXTERNAL` (every allocation whose access depends
    on its origin carries it). Frame slot 0 is never live, so null
    fails it; the function-pointer slot is refused by name. No `Alloc`
    flag bit is added (all eight are in use) and `Alloc` does not grow.
  - `check_ordered` (cold): the pre-WP-650 `check_storage` body,
    unchanged; it runs whenever `check_plain` is false, so the fault
    reported is the one the order picks.
  - `check` (always inlined): `check_plain` with `EXTERNAL | TRACKED`
    refused, else `check_slow` (cold): `check_plain` with `EXTERNAL`
    refused (tracked storage that passes, e.g. `std::allocator`
    storage) or `check_ordered`, then the lifetime test of tracked
    storage (`Space::is_live`) as before.
  - `check_storage` (placement new): `check_plain` with `EXTERNAL`
    refused, else `check_ordered`.
  In `crates/kiln_oven/src/vm.rs`, `rmw_check` is always inlined into
  `load` and the other read paths, and `extent_of` into `ptr_add` and
  `ptr_sub`.
- **Tests.** `mem.rs` unit test
  `plain_check_agrees_with_the_ordered_checks`: for null, function
  pointers, `NOWHERE`, stale and dead frame slots, live frame objects
  (const, temporary, size 0, lifetime-tracked with a dead range), live,
  freed and half-constructed `std::allocator` heap objects, statics
  (plain, const global, `EXTERNAL` global and external, a `LAX_READ`
  external, `Let`, unbacked label / unknown / external, freed), bad
  slots in every space and a flipped generation; at offsets 0, 1, 7, 8,
  size − 1, size, size + 1 and 2^32 − 1, with and without the
  past-the-end bit, lengths 0, 1, 4, 8, size, size + 1 and 2^33, reads
  and writes, lax and strict: `check_storage` returns what the
  pre-WP-650 body (kept as the test's `check_reference`) returns, and
  `check` what it returns followed by the lifetime test; every fault
  kind of the order is reached.
- **Bench.** `bench/oven/{churn-vector,sort-nohdr,table-nohdr,wide-struct-read,wide-struct-store,vector-alloc}.cpp`,
  S7 and S8 (`bench/reflect/`), `bench/frontend/templates_wide.cpp` and
  `accessor-wide-emit.cpp` (`-c -O2`); numbers are in
  docs/status/perf-reflection.md "WP-650: memory-access check".
