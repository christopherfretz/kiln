# WP-792 — The Oven: no constant address for a thread_local self

In `crates/kiln_oven/src/value.rs` (`ptr_of`), freezing a pointer to the
`thread_local` variable being initialized (`run.object`) fails with
`FailKind::NotConstant`, as freezing one to any other thread-local
variable already did. [expr.const]/14 permits the address of an object
with static storage duration only. Such a variable is dynamically
initialized for each thread (spec/oven.md, freezing pointers).

Before the fix, `thread_local S g;` with `S *self = this;`, or a
`thread_local std::string` (its small-buffer pointer), was emitted as a
constant `.tdata` initializer holding an absolute address. The linker
warned "R_AARCH64_ABS64 used with TLS symbol", and the program crashed
at run time (scnlib's `static thread_local std::string err_msg`: "free():
invalid pointer").

Test: `tests/conformance/basic.stc.thread/self-address-dynamic-init-run.cpp`.

## Member pointers formed in an incomplete class

`&C::m` in a static data member initializer of `C` (or of a class nested
in `C`) needs no layout when it is evaluated: the Oven interns a pending
entry (member and path) and lays it out in `mp_refresh` after
`Types::refresh`, once the classes are complete
(`crates/kiln_oven/src/memptr.rs`; spec/oven.md). glaze's
`exceptions_test` field metadata. Test:
`tests/conformance/expr.unary.op/member-pointer-in-incomplete-class.cpp`.
