# WP-438 — WP-187 follow-ups: Oven `bool` ext vectors as packed bits

**Already covered before this WP.** Deliverables 1–3 of the WP-438 brief
were moved to, and landed by, earlier work packages: the packed-bit
value model, lane load/store, list init, `!`/bitwise/`==`,
`__builtin_convertvector`, `__builtin_bit_cast`, subscripts and
`__builtin_reduce_*` per oracle, and constant initialisation of
bool-vector globals are WP-450 (spec/codegen.md §7s, spec/oven.md "Bool
vectors"); int→bool vector conversion and lane-read folds are WP-453
(§7w); linkage and 3-lane stores are WP-466 (§7ab). This WP is the clang
19/22 parity audit over that work plus the budget test (deliverable 4).
It added:

- **Element access on bool vectors is rejected** (`.x`, `.s0`, `.hi`, …),
  as clang's `CheckExtVectorComponent` does at both levels; kiln accepted
  it (accepts-invalid). `crates/kiln_sema/src/vector_ops.rs`,
  spec/sema.md §5.19.
- **clang 19's shuffle bit cast.** At compat 19 a shuffle whose lane
  count differs from its operands' has a GNU vector-of-`bool` type
  bit-cast to the ext vector; clang 19's `BitCastBuffer` writes the GNU
  vector a byte per lane, so lane `k` of the result is source lane `k/8`
  when `k % 8 == 0`, else false. The Oven folds that value (it faulted on the size mismatch, so a global got dynamic init)
  (`gnu_bool_vec_cast`, `crates/kiln_oven/src/vm/bitcast.rs`;
  spec/oven.md "Bool vectors", *Shuffles*).
- **Bool vectors as union members.** A union whose member is a bool
  vector could not be constructed or written in the Oven (rejects-valid;
  such globals got dynamic init): a lane is now a bit unit reachable
  through the vector for the active-member path
  (`Types::has_bit_unit`, `crates/kiln_oven/src/ty.rs`; *Union members*).
- **A lane store does not activate a union member**
  ([class.union.general]/6: only a member access chain of `.`/`[]` on
  class/array subobjects starts a lifetime; clang
  `StartLifetimeOfUnionMemberHandler`). `v[i] = …` / `v.x = …` on an
  inactive vector member is now an error at compat 22 for every vector
  element type (accepts-invalid before): the base is accessed as a
  read-modify-write (`lane_base_access`, `crates/kiln_oven/src/compile.rs`).
- **Array and member constants of bool vectors in clang's IR shape**: the
  element type is the memory form (`<N x i1>` → `iM`), clang's
  `CommonElementType` is taken over the initialised elements only, and an
  implicit value init of a bool-vector or record element is the null of
  its memory type (`bool_vec_mem_form`, `has_bool_vec`, `array_const`
  with the initialised count, `crates/kiln_codegen/src/consts.rs`;
  spec/codegen.md §7s *Arrays*).
- **Budget**: a 16384-lane sieve over 256 `b64` evaluates with
  `allocs<=0` and a 2 KiB `peak_bytes` (one byte per lane would be
  16 KiB).

Not a gap (left as is): the `splat` print difference (normalised by
`ir_vs_clang`); at compat 19 the note column for a vector-subscript
store into a union (wording/location, deferred).
