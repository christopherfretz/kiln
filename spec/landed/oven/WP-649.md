# WP-649 — Init-bit copy and one-granule shadow fast paths in the Oven

No observable rule changes; spec/oven.md "Spaces" (one initialized bit
per byte, one pointer mark per 8-byte granule) is unchanged. This file
records where the change lives and the tests.

- **Problem.** `Memory::copy` (`crates/kiln_oven/src/mem.rs`) copied the
  bytes of a range with one `copy_within`/`copy_from_slice` but its
  initialized bits one at a time, a `set_bits` call per byte. The
  measurement (docs/status/perf-reflection.md "WP-649: init-bit
  copy") showed that `copy` is a negligible cost: the four Oven shapes
  make no `copy` call at all, and S7 makes 1,920 (31 KB) for well under
  0.1% of its instructions. The shadow cost is in the per-access
  `all_bits`/`set_bits` (behind `Space::is_init`, `is_live`, `set_init`)
  and the byte loops of `Space::read`/`write`, which every `Load` and
  `Store` pays.
- **Fix.** In `mem.rs`:
  - `copy_bits` / `copy_bits_within`: a bit-range copy of the `init`
    map. When source and destination have the same offset into their
    granule, whole map bytes move as bytes (`copy_from_slice` /
    `copy_within`) between masked head and tail bits; otherwise 56-bit
    chunks (`get_bits`/`put_bits`, one little-endian `u64` of eight map
    bytes, built with `from_le_bytes`) are copied, away from the overlap
    in one space. Every source bit is read before a destination bit it
    overlaps is written (the bytes' `copy_within` semantics; the old
    per-bit loop read forward and so differed for an overlapping copy to
    a higher address, which no caller can observe: `bulk_copy` requires
    a fully initialized source and `copy_obj` never overlaps). The
    cross-space pointer marks of a granule-aligned copy move with one
    `copy_from_slice`.
  - `all_bits` / `set_bits`: a range within one granule tests or
    updates one map byte (`byte_mask`); a longer one is split into a
    masked head, whole map bytes (compared with `0xFF` / filled) and a
    masked tail (`split`, `set_bits_slow`). Both are `#[inline]`.
  - `Space::read` / `write`: up to 8 bytes are one 8-byte load (masked)
    or read-merge-store when the 8 bytes lie inside the space, else the
    byte loop as before.
  `Space::life` is never copied, so only its `all_bits`/`set_bits` change.
- **Tests.** `mem.rs` unit tests:
  `bit_ranges_match_the_bit_at_a_time_reference` (`all_bits`, `set_bits`
  for every start 0..16 and length 0..140, against a bit-at-a-time
  reference, and a range ending at the map's last byte);
  `copy_moves_init_bits_like_the_reference` (`Memory::copy` for every
  source offset 0..16, destination offset 0..16 and length 0..140, in
  one space in both overlap directions and across spaces, against the
  bit-at-a-time copy that reads every source bit first);
  `read_and_write_match_byte_at_a_time` (every length 0..=16, including
  ranges ending at the space's last byte).
- **Bench.** `bench/oven/{churn-vector,wide-struct-read,wide-struct-store,sort-nohdr}.cpp`,
  S7 and S8 (`bench/reflect/`), `bench/frontend/templates_wide.cpp`;
  numbers are in docs/status/perf-reflection.md "WP-649:
  init-bit copy".
