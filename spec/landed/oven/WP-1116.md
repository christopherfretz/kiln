# WP-1116 — The Oven: `-fconstexpr-stats` and `-fconstexpr-profile`

1.0 work item B3: a report of where constant evaluation spent its time
and memory, per function and per evaluation site, built on WP-1115's
trace hooks (spec/oven.md "Trace hook", "Profile counters"; the format
is spec/driver.md "Constexpr profile"; users: docs/USER_GUIDE.md
"Constexpr profile").

## Oven
- `profile.rs` (new): `Level` (`Off`, `Stats`, `Calls`), the sink
  (`Profile`: per-function and per-site `Row`s), `ProfileRows` (ranked,
  merged per declaration) and its text / NDJSON rendering, and
  `Oven::stats_summary` (the eight `constexpr:` lines).
- `hooks.rs`: the sink lives in the existing hooks. `Hooks` gained
  `trace_calls` and `prof`; `hook_eval_end` takes the evaluation's
  `Cost` and outcome; `hook_meta_begin` counts meta operations;
  `traced_compile` counts compiles. Each mark keeps its start steps,
  live bytes, saved peak and children, so steps are exact (the step
  budget's counter, read at every call boundary) and a call's peak is
  its own.
- Four new one-line hook sites, each a `hooks.calls` test (spec/oven.md
  "Trace hook"): `vm.rs` `enter` (memo hit), `exec` and `trial`
  (`hook_call_unwind` after `run_loop`) and `vm/exc.rs` `unwind`
  (`hook_call_ret` per popped frame). They close a call where its frame
  goes away, which WP-1115's lazy close did not do exactly.
- Counters: `EvalRecord::reclaimed_bytes` / `Cost::reclaimed`
  (allocated minus still held, `Memory::held`), `EvalStats::note_job` /
  `JobTotals` (every `eval_job`, so trials = jobs minus recorded
  evaluations), `EvalStats::failed`.

## Driver and Sema
- `constexpr_opts.rs`: `-fconstexpr-stats`,
  `-fconstexpr-profile[=text|json|<file>]`,
  `-fconstexpr-profile-limit=N`; `ConstexprLimits::profile` reaches
  `Oven::set_profile` through `kiln_parse` / `kiln_sema`.
  `write_profile` runs after the `-fconstexpr-report` in `-fsyntax-only`
  and codegen jobs; an unwritable file is `drv_cannot_open_output`.
- `module_cache.rs`: an in-process module build clears both flags, so an
  importer reports only its own evaluations.

## Tests
`crates/kiln_driver/tests/constexpr_profile.rs` (10),
`module_cache.rs` `constexpr_profile_is_the_importers_only`,
`constexpr_opts.rs` `profile_flags` / `errors_and_others`, and the
`profile.rs` unit tests (ranking tie-breaks, limit, JSON).

## Overhead
Measured on a loaded shared aarch64 host (load ~19 of 24 CPUs) against
WP-1115 + main, both release binaries on the same file system:

- `cargo xtask bench --filter oven/ --runs 5`, best of 3 passes, sum of
  the 26 entries: base 3921 ms, flags off 3986 ms (+1.7%, within the
  run-to-run noise of ±10% on small entries), `-fconstexpr-stats` 4000 ms
  (+2.0%), `-fconstexpr-profile` 4613 ms (+17.7%). Steps identical in
  every configuration; peak RSS within 1 MB.
- The Oven's own wall time (`-fconstexpr-report` `wall_us`, median of 7
  interleaved runs): off and stats within ±3% of base on `time-trace`
  (3M calls), `vector-alloc` (3.5M calls) and `churn-tree`; the profile
  adds 60 to 75 ns per call (two clock reads and a row update):
  +91% on `time-trace`, +174% on `vector-alloc`, +127% on `churn-tree`.
  The cost is per call, not per step, and memory stays flat.

## Found
- WP-1129 (two `ConstevalCall` chains for one `fib` evaluation): an
  immediate invocation in a variable's initializer is evaluated twice.
  `finish_immediate_invocations` (crates/kiln_sema/src/consteval.rs,
  the `deferred` test, line 796) runs `try_fold` over the whole initializer before
  `set_constant_value` stores the invocation's value, so the fold
  re-evaluates the call (a trial with the same step count). The profile
  shows it as `fib`'s steps being the site's plus one trial's.
