# WP-648 — Faster Oven interpreter dispatch in safe Rust

The rule is spec/oven.md "Dispatch — Landed (WP-648)" under "Bytecode
(KBC)". This file records where the change lives and the tests.

- **Problem.** About 70% of an executed KBC instruction's cost in
  `Vm::run_loop` was dispatch overhead: every operand word re-read
  `self.code`'s pointer and length and bounds-checked the index, every
  register access did the same for `self.regs`, and a 51.7 KB function
  with about 90 arms kept `pc`, `fb` and the base pointers on the stack.
- **Fix.**
  - `crates/kiln_oven/src/kbc.rs`: `WINDOW`, `window_ref` (one checked
    read of `&[u32; 8]` in place per instruction), `window` (its copy),
    `tail_window` (cold, zero-filled), `pad`/`unpad`, and a `const`
    assertion that every opcode fits the window.
  - `crates/kiln_oven/src/compile.rs` `Compiler::end_unit`/`here` and
    `crates/kiln_oven/src/vm/exc.rs` `Vm::unwind_pc`: the stream ends with
    `WINDOW - 1` `Nop` words, which the next unit truncates
    (`Oven::padded` in `lib.rs`), so only the last unit carries them.
  - `crates/kiln_oven/src/vm.rs`: `run_loop` reads operands through the
    borrowed window; the 48 rare opcodes run in `#[inline(never)] Vm::run_cold`,
    named in one arm so the `match` stays one jump table, and fetch their
    own window; in-place fusion
    of `Mov`→`Mov`, `Step`→`Mov`, `Step`→`Const`, `JmpIfNot`→`Step` and
    `ICmp`→`JmpIf`/`JmpIfNot`; the pure register arms index a local
    `&mut self.regs[fb..]` (`frame!`).
  - `crates/kiln_oven/src/vm/opstats.rs`: the `op-stats` feature (off by
    default, compiles to nothing): the dynamic opcode and adjacent-pair
    histograms at exit, counting a fused instruction as executed.
- **Unchanged.** The encoding, every pc (sites, step locations, notes,
  return addresses), results, diagnostics, step and fault counts, trap
  ids and counters.
- **Bench.** Six `bench/oven/` entries, S7, S8,
  `bench/frontend/templates_wide.cpp` and `accessor-wide-emit.cpp`
  (`-c -O2`); numbers in docs/status/perf-reflection.md
  "WP-648: interpreter dispatch".
- **Tests.** `kbc.rs` unit tests: `padded_unit_windows_are_in_bounds`,
  `next_unit_reclaims_the_padding`,
  `tail_window_holds_the_instruction_zero_filled`,
  `tail_window_of_a_truncated_instruction_panics`.
  `tests/limits.rs` `fused_dispatch_keeps_step_faults`: a source holding
  every fused pair, its exact step total, and at every smaller budget the
  step-limit note at the same location as the unfused interpreter (main
  at 8b6f177ea). The existing Oven corpus and `tests/limits.rs` step
  goldens pin the rest.
