# WP-948 — The Oven: undefined-behaviour checks and not-yet-visible initializers

The clang negative-test run (WP-912, docs/status/accepts-invalid.md
cluster 7) found constant expressions that the Oven folded although they
have undefined behaviour or read a value that is not yet usable.
[expr.const]/10 says such an expression is not constant, so accepting it
is a soundness bug. Each class now has one structural check, listed with
its note in spec/oven.md "Undefined behaviour checks".

- **Past-the-end pointers.** A frozen pointer one past the end of a
  subobject (`&s.a + 1`) used to come back as a pointer to the next
  member, which could then be read. `Scalar::Pointer` gained `past`
  (spec/ast.md; store flag `F_PAST`). It is set only when the pointer
  does not end its complete object, and `thaw_ptr_raw` restores the
  Oven's `PAST` bit from it. A member call through a past-the-end, dead
  or stale `this` (`EndLife` aux 4) now faults as a member-call access,
  not a plain read.
- **Lifetime.** The same check covers a member call after an explicit
  destructor call, or after the object's scope has ended.
- **Volatile.** `value::var_info` never treats a volatile variable as
  usable, so a read through `const_cast` faults with clang's "read of
  volatile object" and "volatile object declared here" notes.
- **Zero-size arrays.** A pointer subtraction whose pointee is a
  zero-size array type carries `PtrSub` aux 1, and faults when both
  pointers are in one allocation.
- **Virtual member pointers.** `Op::MpCmp` faults on an equality
  comparison where either operand points to a virtual member function
  ([expr.eq]/4.3). A comparison with the null member pointer is
  specified and still passes.
- **Reference past the end** (`-fclang-compat=22` only). `Op::RefChk`
  runs after a local reference variable is bound.
- **Not-yet-visible initializers.** Sema evaluates a namespace-scope
  `const` integral or enumeration variable where its initializer is
  (`fix_const_int_init`), silently, and caches the result, as clang
  does. `extern const int a; const int b = a; const int a = 1;` leaves
  `b` not constant instead of folding `a`'s later initializer.
- **`extern constexpr int m;`** is an error: "constexpr variable
  declaration must be a definition" ([dcl.constexpr]/1).

Known gaps (xfail repros):

- Parameter-object lifetime. A by-value parameter lives to the end of
  the full-expression, so a call through a pointer to it after the call
  returns is accepted (`expr.const/call-out-of-lifetime.cpp`).
- Volatile locals and heap objects
  (`expr.const/read-volatile-local-and-heap.cpp`).

Tests:

- The flipped repros under `tests/conformance/expr.const/` and

- Their `*-siblings*.cpp` files.

Measurements (aarch64, shared host):

- `bench/oven`, 25 entries × 11 interleaved runs against origin/main
  `122d1442c`: time geomean 1.002 (median) and 1.002 (min), peak RSS
  geomean 0.992. The `evaluations` counter grows by 9 to 22 in
  libc++-based entries because the `const` integral globals in the headers
  are now evaluated at their definitions; `static_bytes` grows by 72 to
  144 bytes.
- `cargo xtask clang-neg` for `CXX/expr/expr.const` and
  `SemaCXX/constant-expression*`: missed errors fall from 154 to 104
  (of 1228 lines). Eight false rejections in `constant-expression-cxx11.cpp`
  are gone.
