# WP-537 — Void nested immediate invocations in discarded-value position

The rule is spec/oven.md "Nested immediate invocations". This file
records where the fixes live and the tests.

- **Effect of an unvalued `ConstantExpr`.** A nested immediate
  invocation (P2564R3: `CONSTANT_ELIDED`, no cached value) in a
  discarded-value position — `f(x);` in a constexpr function template
  specialization, a comma fold `(defect(Rs, c), ...)` in a lambda, a
  call in a `template for` body — fell to "constant evaluation of
  ConstantExpr is not supported yet" and then to the follow-on "call to
  consteval function is not a constant expression" (rejects-valid).
  `effect()` now compiles its operand in place, as for `ParenExpr`; a
  valued or `void` `ConstantExpr` contributes nothing.
  `crates/kiln_oven/src/compile.rs` `effect`. The other paths (`rv_inner`,
  `lv`, `init_inner`, `tracked_list`, `fn_lv`) already handled it.
- **Top-level `void` immediate invocation.** `consteval void h(); ...
  h();` outside an immediate-escalating context (an expression
  statement in `main`, `(void)h()`, `h(), h()`) was rejected with
  "expression of type 'void' has no value" (rejects-valid; never
  supported). `Oven::evaluate` arms `void_next` for
  `EvalKind::Consteval` and `eval_at` freezes a `bool` stand-in for the
  `void` result (`crates/kiln_oven/src/lib.rs`, `value.rs`). The AST
  dump prints no value for a `void` `ConstantExpr`, as clang
  (`crates/kiln_ast/src/dump/mod.rs`), and codegen emits no code for it
  (`crates/kiln_codegen/src/expr.rs` `emit_scalar_opt`, clang
  `VisitConstantExpr`).

Tests: `tests/conformance/expr.const/immediate-invocation-nested-void-run.cpp`
(shapes found in real code: a plain call, a comma fold in a lambda
initializing a variable template, parenthesized/cast/comma operands, the
value-returning forms; clang-compared),
`immediate-invocation-nested-void-neg.cpp` (the ill-formed non-template
variant and a division by zero diagnosed through the escalated caller;
strict-diags, clang 19 and 22 agree),
`immediate-invocation-nested-void-reflection.cpp` (a void consteval call
per member in a `template for` inside a lambda, over libstdc++ 16.1's
`<meta>`; GCC-compared), `immediate-invocation-void-run.cpp` (top-level
void invocations; clang-compared).
