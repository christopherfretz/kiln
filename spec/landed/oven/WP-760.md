# WP-760 — The Oven: union storage costs about what allocator storage does

An access to an element in union storage (`union { T data[N]; }`, the
C++26 `inplace_vector` pattern, P3074R7) used to walk the allocation's
type from its root to the accessed object on every load and store to
check the active member (`union_path`, WP-644). That walk was about 65%
of the WP-743 measurement. It now answers from a memo, and the other
per-access costs of union storage are cut down to a few table lookups.
Every diagnostic is unchanged: the walk still produces every fault, and
no fault is remembered. spec/oven.md has the contract ("Union-path
memo", "Path cache", "Pointer steps", "Object lifetime outside
`std::allocator` storage").

## Changes

- **Union-path memo** (`crates/kiln_oven/src/vm/umemo.rs`). `union_path`
  and `place_in_unions` remember their `Ok` answers in a 512-entry
  direct-mapped table keyed by (walk, allocation, allocation type,
  accessed type, offset). An entry is valid while `Memory::union_epoch`
  (bumped by every change to the active-member maps, rollbacks included)
  and `Types::rebuilt` are unchanged. An entry answers one offset, or the
  same position in every element of an array reached through active
  members only, so one walk serves all of `data[0..N]`.
- **Union hull** (`TyInfo::uhull`): the bytes spanning a type's union
  subobjects. An access outside them, or to the whole object, skips the
  check.
- **Extent front table** (`ty/path.rs`, `ExtentFront`): whole-array answers
  of `Types::extent`, used by `ptr_add_front` (the `PtrAdd` op's step
  inside an array member, `&data[n]`) and by `Types::has_subobject`
  (`construct_at(&data[n])`).
- **Lifetime test inline**: `Memory::check` tests the lifetime bits of
  tracked storage (`Memory::live_at`) after the inlined plain checks
  instead of taking `check_slow`. An `inplace_vector` frame object becomes
  `LIFE`-tracked at its first `pop_back`. `Memory::life_hi` lets a scope
  exit skip `scope_life` when no tracked object can be released.
- Smaller cuts: a one-entry `Memory::may_be_active` memo, a
  `Types::holds_no_data` shortcut for classes with pointer, vptr or union
  subobjects, the memo probe inlined into `slow_access`, which is no
  longer `#[cold]`.

Tests:
- `tests/conformance/class.union/constexpr-union-memo.cpp`: a read is
  remembered, for one offset or for every element of an array member,
  and after an active-member change the same read is diagnosed.
- `constexpr-union-memo-trial.cpp`: a failed trial evaluation that made a
  heap union's member active is rolled back with its remembered checks.
- `constexpr-union-memo-place-cxx26.cpp`: constructing elements of the
  active array member is remembered, and once another member is active a
  construction activates the array again.
- `tests/conformance/basic.life/constexpr-scope-life-mark.cpp`: leaving a
  scope still diagnoses a destroyed object tracked after enclosing,
  ended or caller scopes (`life_hi`).
- Unit tests in `vm/umemo.rs`.
