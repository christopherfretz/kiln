# WP-554 — function types naming the injected-class-name; `class _Nullable X` after the class-key

Extends spec/parse.md §2.1 (tentative parsing) and §4 "Tags", and
spec/sema.md §4.1.1. clang 19 and GCC 16.1 accept every accepted case.

## `void(CT)` with `CT` the injected-class-name ([dcl.ambig.res]/3, [temp.arg.general]/2, [temp.local]/1)

- Inside an abstract declarator's parentheses, `(` followed by a type
  name starts a parameter list. The tentative scanner
  (`tentative.rs` `is_decl_specifier_start`) and the declarator parser
  (`decl.rs` `is_param_list_start`) counted only `NameClass::Type`. A
  class template's injected-class-name in its own scope is classified
  `TypeTemplate`, so `void(CT)` read as `void` with a parenthesized
  declarator. In a template argument that gave the expression reading
  ("'CT' does not refer to a value"); in a parameter, "argument may not
  have 'void' type". Both now ask `Parser::names_type_at`: a type name,
  or an injected-class-name not followed by `<`.
- Covered: `void(CT)`, `void(CT<Ts...>)`, `void(::ns::C)`, `void(T)`,
  `void(typename T::type)`, `int(C::*)()`, `void(CT, const CT &)` and
  `void (*)(CT)`, in template arguments, alias-declarations,
  parameters, `sizeof` and `decltype`. `int(x)` with `x` a variable
  stays a functional cast: a non-type argument, and for a type
  parameter "template argument for template type parameter must be a
  type".

Tests: `tests/conformance/temp.arg/type-id-injected-class-name-{accept,cast,ast}.cpp`.

## Nullability on classes (clang extension)

- `parse_tag_specifier`: after a class-key, `_Nullable` may appear any
  number of times, mixed with the attributes there, as in clang's
  `ParseClassSpecifier`. Each one is the keyword attribute
  `AttrKind::TYPE_NULLABLE` (clang `TypeNullableAttr`, dumped
  `TypeNullableAttr`), made by `Sema::act_on_class_nullable`. It is
  checked with the class-head attributes: on a union it is "'_Nullable'
  attribute only applies to classes". `_Nonnull`, `_Null_unspecified`
  and `_Nullable_result` are not parsed there, as in clang.
  `at_partial_specialization` (`templ.rs`) skips `_Nullable`, so
  `template<> class _Nullable X<int> {}` and `template class _Nullable
  X<int>;` take the specialization and instantiation paths.
- `can_have_nullability` (clang 19 `Type::canHaveNullability`):
  - A non-specialization class qualifies when any redeclaration is
    marked (`class _Nullable X; class X {};` and `class X; class
    _Nullable X {};` both qualify).
  - A class template specialization, dependent or not, qualifies only
    when a redeclaration of its primary template's pattern is marked. A
    mark on a partial or explicit specialization alone gives
    "nullability specifier '_Nullable' cannot be applied to non-pointer
    type 'X<int *>'".
  - The current instantiation `X<T>` and the injected-class-name `X`
    inside `X` never qualify (clang's `InjectedClassNameType`).

Tests: `tests/conformance/dcl.type.class/nullability-on-classes-{accept,reject}.cpp`.
