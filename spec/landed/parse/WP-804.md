# WP-804 — Parse: a dependent member before `<` in a nested-name-specifier

[temp.names]/3: in a nested-name-specifier, a `<` after a member of a
dependent type that is not known to be a template is the less-than
operator unless only a template argument list fits: the next token is
`>` or `>>`, or the list opens with an unambiguous type-id (clang
`isTemplateArgumentList`). `parse_nested_name_upto`
(`crates/kiln_parse/src/parser.rs`) used to read any `<` that closed
before `::` as a list, so `if_c<rank<T0>::value < rank<T1>::value, T1,
T0>::type` failed (Boost.Spirit classic phoenix `higher_rank`, 4 wave
TUs). spec/sema-templates.md. Test:
`tests/conformance/temp.names/dependent-member-less-than-before-scope.cpp`.
