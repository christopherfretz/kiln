# WP-519 — `^^` operand gaps: dependent qualified names, operator, conversion and destructor names, `^^tf<int>`, consteval-only gaps

The rules are spec/reflection-repr.md §2 (operands, node encoding) and §6
(consteval-only), and spec/reflection.md §2.2 and §8.3. This file records
what the implementation does beyond them, the tests, and what remains.

- **Where.** Parser: `kiln_parse/src/reflect.rs` (`parse_reflect_expr`
  keeps a dependent nested-name-specifier, `template`/`typename`
  qualified-ids, operator, conversion and destructor ids). AST: tag 12
  (`Reflectee::DEPENDENT_NAME_TAG`, `kiln_ast/src/reflect.rs`), built by
  `kiln_ast/src/builder.rs`, dumped as `name dependent`. Sema:
  `reflect_operand.rs` (operator/conversion lookup, `reflect_destructor_of`,
  `check_reflect_dependent_kind` for the missing-`typename` rule),
  `templ/subst/exprs.rs` `reflect_dependent_name` (instantiation through
  the ordinary dependent-name transform), `reflect_limit.rs`
  `build_reflect_expr` (now `intern_reflection`, the WP-471 helper),
  `consteval_only.rs` (`has_consteval_only_object_param`,
  `check_consteval_only_inst`, called from `templ/funcs.rs` and
  `templ/class.rs` when a definition is instantiated),
  `meta/query/mod.rs` (`type_of` fails for constructors and destructors).
- **`^^tf<int>`.** A template-id that selects exactly one specialization
  (defaulted template arguments filled in) reflects it; the overload-set
  error is kept for two viable templates.
- **Consteval-only.** Matches GCC 16.1 on: the implicit object parameter
  (members declared so far), explicit object parameters, constructors,
  destructors, conversion functions; defaulted functions skipped;
  members of class templates checked only per instantiated definition;
  system-header patterns skipped (kiln extension, so that libc++ 19's and
  libstdc++ 14's `vector<info>` stay usable:
  `meta.reflection.result/range-lib{cxx,stdcxx}.cpp`).

## Divergences from GCC 16.1 (kept; tests are kiln-only where they matter)
- `^^S::~U` (U not S): kiln rejects, GCC accepts.
  `^^T::~T` with T scalar: kiln rejects at instantiation, GCC gives an
  "unsupported reflection" error (`expr.reflect/destructor-names-neg.cpp`).
- `^^x` where x was found through a using-declaration: GCC rejects, kiln
  reflects the target (spec/reflection.md §2.3).
- `(void)g.s` (consteval-only static member through an object) in a
  runtime function: GCC accepts, kiln rejects like `G::s`
  (`basic.types.general/consteval-only-member-access.cpp`).
- GCC rejects `^^T::template inner` without arguments and
  `^^T::template tv<int>` / `^^T::template tf<int>`; the tests avoid them.
- `display_string_of(^^S::operator=)` is `operator=` in kiln; GCC prints
  the declaration (`S& S::operator=(const S&)`).

## Performance
`reflect-dependent-member-2k.cpp` instantiates `^^T::x` for 2,000
distinct `T` (binary-split recursion, depth 11): Oven 28,000 steps,
10,001 calls, 20,001 evaluations, 2,001 memo hits; kiln debug build
2.2 s and 45 MB peak RSS, GCC 16.1 0.64 s and 150 MB. Pinned by
`//@ oven:` and `//@ mem<=1024`.

## Follow-ups
- `(const void*)&f` in a `constexpr` initializer: GCC rejects, clang 19
  and kiln accept; not done (it conflicts with the clang oracle).
- `display_string_of` spelling of functions (`kiln_sema/src/meta/names.rs:222`).
- Spurious `-Wdefaulted-function-deleted` on a defaulted `operator==` of
  a consteval-only class (`kiln_sema/src/class/special/deletion.rs:712`).
- After a consteval-only error in an instantiated definition, kiln adds a
  "call to consteval function … is not a constant expression" error GCC
  does not give.
- A dependent reflect operand in a signature mangles `XLi0EE`, so
  overloads differing only in the operand collide (spec/reflection.md
  §8.3, → WP-102).
