# WP-571 — type_of for annotation reflections

The rules are spec/reflection.md §7 (the has-type bullet) and §3.5's
"Result types that follow GCC 16.1"; spec/reflection-queries.md §1.

- **Cause.** `type_of_reflectee` (`crates/kiln_sema/src/meta/query/mod.rs`)
  had no `Reflectee::Annotation` arm, so `type_of(a)` of every annotation
  failed with "'^^(annotation #1)' has no type", although P3394R4 makes an
  annotation have a type. A downstream annotation scanner
  reads `remove_const(type_of(a))` over `annotations_of` of a class and of
  every member, so any annotated class failed to bind.
- **Fix.** `type_of_reflectee` gives an annotation the type of its
  underlying constant, `Annotation::written_type` (none while the operand
  is dependent). `const_object` treats a class-type annotation as a const
  object (its constant is a template parameter object, as
  `annotation_constant` builds it), so `type_of(a)` is `const T`, exactly
  `type_of(constant_of(a))`; a scalar annotation stays cv-unqualified.
  `is_const` now consults `const_object` too, so `is_const(a)` of a
  class-type annotation, and of an object reflection of a const object
  (`object_of(^^cv)`, `reflect_constant(S{})`), is true as in GCC 16.1;
  it was false for the latter before.
- **Tests.** `tests/conformance/meta.reflection.annotation/type-of-annotation.cpp`
  (run, `oracle: gcc`, real `<meta>`): constexpr class variable, class
  prvalue, literal, float and enumerator annotations on member functions,
  data members, namespace-scope functions, variables, classes and a class
  template's member; `type_of(a) == type_of(constant_of(a))`; `is_const`;
  a consteval scan with `remove_const(type_of(a))` over
  `members_of(^^C, access_context::unchecked())`.
  `type-of-annotation-neg.cpp`: `type_of` of a class, namespace or type
  still fails with "'X' has no type".
- **Spec.** spec/reflection-members.md §7 drops the stale "type_of of a
  BaseSpec, FnParam or annotation" gap (bases and parameters were already
  done).
