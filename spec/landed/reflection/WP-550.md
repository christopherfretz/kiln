# WP-550 — expression splices of value and object reflections

The rules are spec/reflection.md §5 ("Value and object splices"), the
`expression` row of the splices table.

- **Cause.** `act_on_splice_expr` (`crates/kiln_sema/src/splice.rs`)
  sent both `Reflectee::Value` and `Reflectee::Object` to
  `Sema::nttp_value_expr`, which had no integer, enumeration, `bool` or
  character case (those live in `nttp_arg_expr`), named a class value only
  when its template parameter object already existed, and read an object
  reflection's interned `T*` as a pointer argument (`&x`, then a failed
  conversion to `T*`). Every value or object splice reported "splice of a
  value or object reflection is not supported yet"; a downstream
  generator reads the literal of a class-type template argument
  as `[: template_arguments_of(P)[0] :].data`.
- **Fix.** A value splices through `nttp_arg_expr` (`splice_value_expr`);
  an object splices through `object_lvalue`
  (`crates/kiln_sema/src/splice_object.rs`), which names the variable or
  template parameter object and walks the record layout from the byte
  offset to the subobject (non-virtual bases, the virtual bases of a
  complete or member object, fields, array elements).
  `nttp_value_expr` makes the template parameter object of a class value
  that has none (as `reflect_constant` does) and substitutes a pointer or
  reference argument into a subobject through the same walk; a pointer to
  a whole variable, or to its first element, keeps the old `&x` / decay
  form, so existing AST dumps are unchanged. The dependent path
  (`CXXSpliceExpr` substitution) calls `act_on_splice_expr` again and so
  needs nothing new.
- **Tests.** `tests/conformance/expr.prim.splice/value-scalars.cpp`,
  `object-class.cpp`, `value-dependent.cpp`, `value-object-run.cpp`,
  `value-object-errors.cpp`, all with the GCC 16.1 oracle.
- **Deviations.** GCC 16.1 accepts splices of `reflect_constant_string`
  / `reflect_constant_array` results (`PtrBase::Const`); kiln reports
  them as not supported yet. Diagnostics for the ill-formed
  uses are kiln's (clang-style) wording, not GCC's.
