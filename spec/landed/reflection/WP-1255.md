# WP-1255 — type_of of a reflected info value is not the info alias

The rule is spec/reflection.md §3, "The type of a reflected constant".
No code changed, because kiln already conforms. The work package
records why the comparison is false and pins the answer with a test.

- **Question.** `type_of(std::meta::reflect_constant(^^int)) ==
  ^^std::meta::info` is false in kiln and in GCC 16.1 (found under
  WP-1252). The candidate reasons were (a) the alias reflects
  differently from its target, (b) a `const info` template parameter
  object, or (c) a bug.
- **Answer: (a).** Paragraphs are from the current working draft.
  - [meta.syn]: `using info = decltype(^^::);`, so `std::meta::info`
    is a type alias.
  - [expr.reflect]/5.6.2: when lookup finds a type alias that is not a
    template parameter, `^^name` represents the alias. Example 4
    shows the same thing (`^^S<int>::type != ^^int`).
  - [basic.pre]/8: type aliases are entities, and their underlying
    entities are distinct from them (Note 6). Under [expr.eq]/7.4, two
    reflections are equal only when they represent the same entity.
    So `^^std::meta::info != ^^decltype(^^::)`, and
    `dealias(^^std::meta::info) == ^^decltype(^^::)`
    ([meta.reflection.queries]/54).
  - [meta.reflection.result]/2-4: for a non-class `T`, V is the value
    of `expr` and the result is `template_arguments_of(^^TCls<V>)[0]`.
    By [meta.reflection.queries]/59.3.3 that represents the value of
    the argument, not an object.
  - [meta.reflection.queries]/2.2: type_of of a value is the value's
    type. A constant template parameter of non-class type is a prvalue
    whose top-level cv-qualifiers are ignored ([temp.param]/11,
    Note 3 of /13), so that type is plain `decltype(^^::)`. Types are
    never aliases (/59.1, Note 7).
  - (b) applies only to class types. [temp.param]/13 gives the
    template parameter object the type `const T`, and /59.3.2 makes it
    the result, so `type_of(reflect_constant(S{1})) == ^^const S`.
- **Probes.** kiln and GCC 16.1 print the same 30 lines (scratch
  program, both compiled and run). For `info`:
  `dealias(type_of(r)) == dealias(^^std::meta::info)`,
  `type_of(r) == ^^decltype(^^::)`, `remove_cv(type_of(r)) ==
  type_of(r)` and `is_same_v<typename[: type_of(r) :], info>` are all
  true. `is_const_type` and `is_type_alias` are false. For `S`, the
  result is `const S`. For `42` and `Alias{7}` (where `using Alias =
  int`), it is `int`, which is `!= ^^Alias`. `display_string_of` is
  `std::meta::info`, `const S` and `int` in both compilers.
- **Tests.** `tests/conformance/meta.reflection.result/`
  `reflect-constant-type-of-alias-run.cpp` holds the true and false
  comparisons as static_asserts. It also runs and prints them, with
  stdout compared against GCC 16.1 (`oracle: gcc`, `skip(clang)`).
- **Deviations.** None, in kiln or in GCC.
