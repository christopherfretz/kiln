# WP-533 — Downstream header round 1: unbraced expansion bodies, qualified dependent consteval calls, linkage-spec parents, local `thread_local` lvalues

The rules are spec/sema.md §7.6a (expansion statements) and "Immediate
invocations" (References), spec/sema-class.md (implicit move), and
spec/reflection-queries.md §3/§4 (`parent_of`). This file records where
the four fixes live, the tests, and what was found but not fixed.

- **Unbraced expansion-statement body.** `kiln_parse/src/stmt.rs`
  `parse_expansion_rest` parses the body as a loop sub-statement and emits
  the off-by-default extensions `parse_ext_expansion_stmt_body_not_compound_stmt`
  / `parse_ext_expansion_stmt_body_attr` (group
  `expansion-stmt-missing-braces`, clang 23 wording); `kiln_sema/src/expansion.rs`
  `expansion_element` no longer assumes a `}` (a non-compound body's element
  block spans the body's location); `act_on_expansion_error` is gone.
  Tests: `stmt.expand/compound-body{,-default,-pedantic}.cpp`,
  `stmt.expand/non-compound-body-run.cpp` (GCC-compared).
- **Qualified dependent consteval call.** `templ/actions.rs`
  `dependent_call` drops the callee's pending immediate reference
  (`consteval.rs` `forget_immediate_ref`, shared with
  `check_immediate_invocation`), as the unqualified path already did by
  rebuilding the callee as an `UnresolvedLookupExpr`. Tests:
  `expr.const/consteval-qualified-dependent-call-{run,neg}.cpp`.
- **`parent_of` through linkage specifications.** `meta/query/entity.rs`
  `parent_of` refuses a parent only for a function or variable with C
  language linkage (`has_c_language_linkage`), not for everything declared
  lexically in an `extern "C"` block. Tests:
  `meta.syn/parent-of-linkage-spec{,-neg}.cpp` (GCC-compared).
- **Block-scope `thread_local`.** `kiln_sema/src/stmt.rs` `implicit_move`
  requires automatic storage (`has_automatic_storage`), so `return i;` of a
  local `thread_local` binds `int&`. Tests:
  `basic.stc.thread/local-lvalue-run.cpp`,
  `basic.stc.thread/ir-local-thread-local.cpp` (kiln already emits
  `internal thread_local global` like clang: the WP-127 "local
  `thread_local` not emitted as TLS" item is stale).

## Divergence from the brief (standard and GCC 16.1 kept)
- `extern "C" int cfn(int); parent_of(^^cfn)`: C++26
  [meta.reflection.queries] `has_parent` is false for an entity with C
  language linkage, and GCC 16.1 throws there, so kiln does too (no `^^::`
  pin). The repro's line 8 is the one remaining error.

## Found, not fixed
- `template for (constexpr auto R : arr)` over a constexpr
  `std::array<std::meta::info, N>` (or `info[]`) in a function that is
  code-generated: `error: reflection values cannot be emitted` (GCC 16.1
  compiles and runs it). `-fsyntax-only` is clean. Codegen of reflection
  results was out of scope.
- A label in an expansion-statement body is reported per element as
  `redefinition of label` (GCC: "identifier label in 'template for'
  body"); no dedicated diagnostic.
- `&::mv` of a consteval function in a template is reported once at the
  definition; clang also reports it again at each instantiation.
- `templ/nttp.rs` `is_automatic` ignores `thread_local` (a local
  `thread_local` counts as automatic there).
- `-pedantic` does not emit clang's `extra ';' inside a struct`
  (-Wextra-semi).
- GCC 16.1 rejects a constant-evaluated `break` out of an expansion
  statement ("flows off the end of the function"); not compared with GCC.
