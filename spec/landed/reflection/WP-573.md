# WP-573 — annotations_of on namespace aliases

The rules are spec/reflection-members.md §5 and spec/reflection.md §7.

- **Cause.** `Sema::annotation_source`
  (`crates/kiln_sema/src/meta/annot.rs`) had an arm for
  `Reflectee::Namespace` but none for `Reflectee::NamespaceAlias`, so
  `annotations_of(^^alias)` and `annotations_of_with_type(^^alias, T)`
  fell to the unsuitable-reflection failure. `is_namespace(^^alias)` is
  true ([meta.reflection.queries]), so [meta.reflection.annotation] makes
  the call constant. A downstream `members_of(ns,
  access_context::unchecked())` walk calls `annotations_of_with_type` on
  every member and aborted on a namespace-alias member.
- **Fix.** `Reflectee::NamespaceAlias(_) => Source::None`: an alias has
  its own annotations (as a type alias does) and a
  namespace-alias-definition admits none, so the result is empty, never
  the aliased namespace's. `annotations_of_with_type` shares the path.
  The unsuitable-reflection wording already says "namespace".
- **Tests.** `tests/conformance/meta.reflection.annotation/`
  `annotations-of-namespace-alias.cpp` (alias, alias of an alias, an
  annotated target, a `members_of` loop over a namespace holding a
  function, a variable, a nested namespace and two aliases) and
  `annotations-of-namespace-alias-neg.cpp` (a template and a value stay
  unsuitable), both with the GCC 16.1 oracle.
- **Deviations.** None.
