# WP-484 — libstdc++ 16.1's real `<meta>`: the name table, its layouts, feature macros, the header differential

Extends spec/reflection.md §1.3 and §1.5 (the library vehicle and the
macros), §3.1 (the name table), §3.5 (libstdc++ 16.1's layouts and the
result types that follow GCC) and §6.1 (`data_member_options`
annotations); spec/harness.md ("Header-differential mode",
`%{gcc_toolchain}`); spec/sema-templates.md (on-demand instantiation of
a queued constexpr member for the Oven). P2996R13, P3394R4,
[meta.syn]; GCC 16.1 is the reference compiler.

## The header

`kiln++ --gcc-toolchain=<GCC 16.1 prefix> -std=c++26 -freflection`
compiles libstdc++ 16.1's `<meta>` (with `<vector>`, `<string_view>`,
`<array>`, `<ranges>`, `<string>`): every consteval function it declares
without a body is dispatched to a `MetaOp` row, and every class it passes
is read or built by layout. `tests/support/kiln_meta.h` stays the test
vehicle of the corpus (it needs no GCC); the corpus also runs over the
real header (below).

## What the real header needed

- **The name table** (§3.1): `kiln_oven/src/meta/gcc16_meta_names.txt`,
  261 lines, each `intrinsic` or `library`; unit tests in
  `kiln_oven/src/meta/mod.rs` (`rows_cover_gcc16_meta`,
  `gcc16_meta_names_match_the_header` with `KILN_GCC16_ROOT`).
- **Body-less helpers as intrinsics**: `reflect_constant_string` and
  `reflect_constant_array`'s, `_S_exception_cvt_to_utf8` /
  `_S_exception_cvt_from_utf8` (`std::meta::exception`'s `u8string`
  members), `__builtin_is_string_literal`.
- **Result types as GCC 16.1 gives them** (§3.5): `type_order` returns
  `std::strong_ordering`; `symbol_of` a `string_view`; `type_of` of a
  const object or reflected constant is `const`-qualified; an empty
  `reflect_constant_array` reflects a `const std::array<T, 0>`;
  `display_string_of` qualifies names as GCC does; `identifier_of` of a
  parameter looks through redeclarations; the `reflection_range` trait
  forms and range traits take an `info` element.
- **`members_of` of a namespace** walks `extern "C"` / `extern "C++"` and
  `export` blocks in place (declaration order), which the C headers at
  global scope exposed (`meta.reflection.member.queries/namespace-blocks.cpp`).
- **On-demand instantiation for the Oven** (decision A, spec/sema-templates.md
  "As landed by WP-484"): a queued constexpr member whose pattern is
  defined by the evaluation is instantiated then; one still undefined
  keeps its diagnostic. `operator""s` and `std::meta::exception`'s
  `u8string` need it.
- **`data_member_options::annotations`** (§6.1): read through the
  `vector<info>` recipe; each element needs a type ("reflection does not
  have a type") and stands for its constant; the list is part of the
  description's identity; `define_aggregate` attaches one annotation per
  element to the injected member, with no source location.
- **Feature macros** (§1.5): `__cpp_impl_reflection` (kiln, WP-525) and
  the header's `__cpp_lib_reflection` 202603L / `__cpp_lib_define_static`
  202506L; docs/STANDARD_SUPPORT.md row.

## Header-differential mode (spec/harness.md)

`cargo xtask test --meta-header` reruns the reflection corpus with
`tests/support/meta-header/` first on the include path: its `kiln_meta*.h`
stand-ins include the real `<meta>` (and define `KILN_REAL_META`), and
kiln++ gets the GCC oracle's prefix as `--gcc-toolchain`. A test that
does not include `kiln_meta*.h`, needs a kiln-only signature or a known
library-cost difference opts out with `meta-header: skip <reason>`
(17 tests; the reasons are below and in the files). The rest pass, with
the same expectations as under `kiln_meta.h`, except the budgets, which
are not checked in the mode. `%{gcc_toolchain}` lets an ordinary test
name the prefix; such a test SKIPs where no GCC is found.

## Performance

`-fsyntax-only`, kiln++ of the `harness` profile (the one `cargo xtask
libcxx` builds), GCC 16.1 `-std=c++26 -freflection`, aarch64 container,
`/usr/bin/time`, median of 5 (kiln) and 3 (GCC) runs on a shared host:

| Entry | kiln wall | kiln peak RSS | GCC wall | GCC peak RSS | wall ratio | memory ratio |
|---|---|---|---|---|---|---|
| `#include <meta>` alone | 0.28 s | 29 MB | 0.25 s | 99 MB | 1.1× | 0.29× |
| `stress/real-meta-12k.cpp` (12,500 calls over 100 members) | 0.27 s | 29 MB | 0.32 s | 116 MB | 0.84× | 0.25× |
| `meta.syn/workload-names.cpp` | 0.45 s | 41 MB | 0.38 s | 145 MB | 1.2× | 0.28× |

The 12,500 calls cost kiln no measurable time over the bare header (GCC
0.07 s and 17 MB): the wall time is parsing `<meta>` and what it
includes, which is front-end speed (not this WP's), and is why kiln is
slower than GCC on the two header-bound entries. Its budgets
(`allocs<=1 steps<=70000 calls<=20000 peak_bytes<=16384`, `mem<=1024`)
keep the per-call cost of the header's classes at that of `kiln_meta.h`'s
(`stress/meta-names-2000.cpp`).

## Follow-ups

- `__builtin_is_structural` (GCC declares `is_structural_type` only with it).
- `define_static_array`/`define_static_string` pass a non-contiguous range
  (`iota_view`) to the `reflect_constant_*` helpers, which read contiguous
  ranges only.
- libstdc++'s constant-evaluated `_Destroy` / `basic_string` loops cost
  steps per element (`stress/define-aggregate-10k.cpp`,
  `stress/meta-members-2000.cpp` skip the mode for it).
- `__builtin_constexpr_diag`: the header uses it under `__has_builtin`,
  which is false in kiln, so its fallback path runs.
- Notes spell the real header's default argument `initializer_list<info>`
  where `kiln_meta.h`'s differ (8 substitute tests skip the mode).
- `type_of` of an annotation reflection, and a constexpr variable
  initialized from a result `vector` (P3032): WP-506.
