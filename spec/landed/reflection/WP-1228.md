# WP-1228 — members_of through a namespace alias; the implicit operator==

The rules are spec/reflection-members.md §2 and spec/reflection.md §3.5.

- **Cause (namespace alias).** `Sema::members_of`
  (`crates/kiln_sema/src/meta/member.rs`) matched only
  `Reflectee::Namespace`, so `members_of(^^alias, ctx)` fell to the class
  path and failed "neither complete class type nor namespace".
  [meta.reflection.member.queries]/1 dealiases the operand first.
- **Fix.** A `Reflectee::NamespaceAlias` is resolved through
  `Ast::resolve_alias` (aliases of aliases followed) and lists the
  namespace's members: the same reflections, `parent_of` the namespace.
  The other namespace queries already follow GCC 16.1 on an alias:
  `is_namespace` and `is_namespace_alias` are true, `parent_of(alias)`
  is the alias's scope, `dealias` is the namespace, `annotations_of` is
  empty (WP-573). The `has_*_linkage` queries stay false on an alias
  (a namespace alias is not an entity with linkage, [basic.link]/4;
  GCC 16.1 answers as for a namespace-scope name, an open deviation
  from GCC).
- **Cause (implicit `operator==`).** `build_class` skipped every
  implicit non-field member that is not a special member, which dropped
  the `operator==` that `declare_implicit_equality`
  (`crates/kiln_sema/src/class/compare/default.rs`) declares eagerly at
  the class's `}` for each defaulted member `operator<=>`
  ([class.compare.default]/5).
- **Fix.** `build_class` lists those implicit `operator==`s after the
  implicit special members (GCC 16.1's position), subject to the same
  trailing-requires check as other member functions. The existing
  queries already answer for the declaration as GCC 16.1 does
  (defaulted, not user-declared or user-provided, return type `bool`,
  the `<=>`'s access and ref-qualifier). A friend `<=>`'s implicit `==`
  is a friend and is not listed.
- **Tests.** `tests/conformance/meta.reflection.member.queries/`
  `members-of-namespace-alias.cpp` (an alias, an alias of an alias, a
  nested namespace's alias in another namespace; the alias queries) and
  `members-of-implicit-equality.cpp` (public, private, protected,
  ref-qualified and friend `<=>`; a user-declared defaulted, a
  user-provided and a differently-typed `==`; class template
  specializations with a satisfied and an unsatisfied requires-clause;
  a derived class), both with the GCC 16.1 oracle.
- **Deviations.** `has_linkage` / `has_external_linkage` of a namespace
  alias (above).
