# WP-534 — `template for` over a constexpr `std::meta::info` range in an emitted function

The rules are spec/codegen.md §4 "Consteval-only variables" and
spec/reflection-repr.md §6 (structured bindings). Delivered with WP-537.

- **Consteval-only variables are not emitted.** An expansion statement
  over a range of `info` in a function that is emitted
  (`template for (constexpr auto R : entries_v<H>)` with `entries_v` a
  `define_static_array` variable template) failed with "reflection
  values cannot be emitted" (`crates/kiln_codegen/src/consts.rs`): the
  prelude's `static constexpr` `__range`/`__begin`/`__end` (or the
  destructuring form's binding object) were lowered like any local.
  `emit_one_var_decl` now skips every block-scope variable of
  consteval-only type (`crates/kiln_codegen/src/expr.rs`), decided by
  `Cg::is_consteval_only` (`crates/kiln_codegen/src/module.rs`: a
  worklist walk over the canonical type through arrays, pointers,
  references, member pointers, function types, bases and fields,
  memoized per record in `consteval_only`). Each element's `R` is a
  constant, so no `info` value reaches the IR.
- **Bindings of a consteval-only decomposition.** `static constexpr auto
  [a, b] = arr;` over an `info` array, and so the destructuring form of
  `template for (constexpr auto R : arr)` with `static constexpr info
  arr[]`, reported "consteval-only expressions are only allowed in a
  constant-evaluated context" at each binding expression (`e[i]`), which
  was checked as a full-expression with no variable being initialized
  (rejects-valid). `decompose_array` and `decompose_members` now note
  the decomposed variable as the full-expression's initialized variable
  (`note_var_init_full_expr`, `crates/kiln_sema/src/struct_bind.rs`).

Tests: `tests/conformance/stmt.expand/reflection-info-range-run.cpp`
(the three range spellings: variable template, inline
`define_static_array` call, `static constexpr info arr[]` local; run and
GCC-compared), `tests/conformance/dcl.struct.bind/consteval-only-static-run.cpp`
(a static constexpr decomposition of an `info` array; run and
GCC-compared).

Not covered: a tuple-like decomposition (`get<I>` binding variables of
consteval-only type) is untested. The brief's third spelling, a
non-static `constexpr info arr[]` local iterated by `template for`,
compiles and runs under kiln (prints 2) but GCC 16.1 rejects it ("'arr'
is not a constant expression": the destructuring form binds a reference
to an automatic object), so the GCC-compared test uses a `static
constexpr` local; which reading P1306R5 and P2686R5 require is not
pinned.
