# WP-482 — the template family: template_of, template_arguments_of, substitute, can_substitute, template splices

Extends spec/reflection.md §3.3 (Template rows), §4.3 and §5 (the
`template` splice row). [meta.reflection.substitute] and [temp.names] of
P2996R13; GCC 16.1 is the reference compiler.

## Queries (`kiln_sema/src/meta/templ.rs`)

- **`template_of(r)`, `template_arguments_of(r)`** (Stable). `r` reflects a
  class, partial, variable, function or alias template specialization,
  instantiated or not: the specialization record exists once the
  template-id is named, and asking never instantiates. An alias of a
  specialization is not a specialization (`has_template_arguments`).
  A partial specialization's template is the primary. The arguments come
  in order, a pack's elements in place of the pack: types as types (alias
  sugar kept), templates as templates, a constant argument as the
  reflection `reflect_constant` would give it (a value), a reference
  parameter's argument as the referenced object or function, a class-type
  argument as its template parameter object. Anything else throws
  `std::meta::exception` ("… is not a template specialization").
- **`substitute(templ, args)`, `can_substitute(templ, args)`**
  (PointDependent). Each argument reflection is turned into a template
  argument ([meta.reflection.substitute]/2: a type, a template, a value's
  literal, an lvalue naming an object or variable, a function); a
  namespace, a non-static member or the null reflection throws from both
  (their *Constant When*). The template-id `templ<args...>` is then formed
  by `act_template_id` in a `FrameKind::MetaSubstitution` SFINAE frame.
  A definition is never instantiated; a function template needs a unique
  specialization whose type has no undeduced placeholder. The result is
  the specialization's reflection: the type (an alias template's alias
  kept), the variable or function specialization, or a concept-id's
  `bool` value.
- **Failure.** `substitute` throws "'T' cannot be substituted with these
  template arguments: <reason> (<first SFINAE diagnostic>)", the reason
  one of GCC's categories: wrong number of template arguments, template
  argument of the wrong kind, constraints not satisfied, substitution
  failure. `can_substitute` answers `false`. Neither emits a diagnostic.
- **Memo.** A success is memoized on the key (template name, the
  arguments' Oven bits), so the second query of a specialization is one
  hash lookup (`Sema::meta_subst`; `SubstMemo::hits` counts them, not yet
  a report counter). A failure is
  not memoized: it can depend on the point of evaluation.

## The trial (§4.3)

- Every uncached substitution runs inside `Oven::trial_begin` /
  `trial_end(keep)`, the first user of `TrialMode::Transactional`
  (spec/oven.md "Trial evaluation"), together with
  `InstReport::begin_trial` / `end_trial` (`templ/report.rs`): a journal
  of the report rows charged while a trial is open, undone newest first on
  failure. A failed substitution therefore leaves no Oven bytes, no
  instantiation-report row and no diagnostic. Reflections interned during
  the trial survive (append-only table, §2.4).
- Meta ops inside a nested trial see `in_trial`, so a Mutating op there
  fails silently (§4.3).
- **Re-entry.** The bridge lends sema the Oven for the nested
  evaluations (a constraint, a default argument) and keeps the replaced
  one as `spare_oven`, so nesting reuses one spare instead of allocating
  an Oven per level. kiln's constexpr depth limit spans the nested
  evaluations.

## Template splices (`kiln_parse/src/reflect.rs`, `kiln_sema/src/splice.rs`)

- **Type.** `typename [: r :] < args >`, and a bare `[: r :] < args >` in a
  type-only context, name the specialization of the class or alias
  template `r` designates (`act_on_splice_template_type`). A dependent
  `r` builds a `TemplateName::Splice` specialization type that the
  substituter resolves at instantiation (`Substituter::template_name`).
- **Expression.** `template [: r :] < args >` names a variable template
  specialization, a concept-id or a function template specialization
  (called or not: an uncalled one resolves through
  `resolve_single_template_id`); `template [: r :]` alone is a function
  template's overload set, its arguments deduced by the call. A splice
  call does no ADL. A dependent operand keeps its arguments in the cold
  `splice_args` map of its `CXXSpliceExpr` (spec/ast.md).
- **Scope.** `template [: r :] < args > ::` is a nested-name-specifier
  naming the class template specialization, in an expression, after
  `typename`, and as the leading decl-specifier of a declaration at
  namespace, class and block scope (the `template` keyword there is not
  an explicit instantiation).
- **Lookahead.** `scan_template_args` skips a whole splice and opens a
  nested argument list for `template`/`typename [: … :] <`;
  `decltype_scope_end` recognizes `template [: … :] < … > ::`.
- **Misfit.** A splice before an argument list that designates no
  template gets `sema_splice_not_template`; a variable template or concept
  in a type position gets `sema_splice_not_type`.
- **Frozen operands.** A non-dependent operand is read through the
  frozen fast path (`splice_frozen_id`, `splice_fast`) and costs no
  evaluation (`kiln_parse/tests/splice.rs`
  `splice_template_ids_read_frozen_operands`).

## Divergences kept from GCC 16.1

- The IS says `can_substitute(^^fn2, {^^int})` (an `auto` return type)
  is an error because `fn2<int>`'s body must be instantiated; kiln, like
  GCC, does not instantiate it and answers `false`
  (`is-substitute-fn2.cpp`).
- `[: r :] < args >` without `template` in an expression opens an
  argument list only when the operand is frozen and designates a
  template; GCC accepts it more widely. kiln also accepts
  `X<[: r :]<A>>` as a template argument without `typename`, and
  `template [: r :]<A>::type m;` as a member declaration (GCC parses the
  `template` as a template-declaration there and rejects it).
- A dependent nested-name-specifier splice of the wrong kind gets an
  extra "constexpr variable must be initialized" error after the misfit.
- A `std::meta::exception` escaping a constexpr variable's initializer
  gives two errors (the throw and the non-constant initializer); GCC one.
- Message wording differs (deferred, as for every diagnostic).

## Unsupported

- `obj.template [: r :] < args >` (a member template by splice): parsed,
  then "a member access naming a template by a splice" is unsupported.
- `template [: r :]` of a class template without arguments (CTAD).

## Performance (S5)

The S5 target (docs/plans/m6-reflection.md §3.8: ≤ 0.5× GCC 16.1 wall
and memory) is met. `bench/reflect/s5.cpp` itself also calls
`static_data_members_of` (WP-478) and `reflect_constant`/`extract`
(WP-479), which this WP's base lacks, so it stays `xfail(kiln)`; the
measured shape is S5 without those ops,
`tests/stress/substitute-roundtrip-10k.cpp` (10,000 distinct
`substitute` + `template_arguments_of` + `template_of` round trips, 100 per
evaluation). `-fsyntax-only`, debug kiln++ (a release build is faster),
GCC 16.1 `-std=c++26 -freflection`, aarch64 container, `/usr/bin/time`,
median of 5 (kiln) and 3 (GCC) runs on a loaded host:

| Entry | kiln wall | kiln peak RSS | GCC wall | GCC peak RSS | wall ratio | memory ratio |
|---|---|---|---|---|---|---|
| `stress/substitute-roundtrip-10k.cpp` | 0.90 s | 17 MB | 3.76 s | 398 MB | 0.24× | 0.04× |
| `stress/substitute-10k.cpp` (10,000 nested, then 10,000 memo hits) | 0.40 s | 20 MB | 1.62 s | 146 MB | 0.25× | 0.14× |

The constexpr counters of the round-trip entry: 150,600 steps, 10,000
allocations (one `template_arguments_of` vector per iteration, freed in
it), `peak_bytes` 56 and `peak_arena` 56 over 202 evaluations. Its
budgets (`peak_bytes<=64 peak_arena<=64 allocs<=10000 steps<=160000`)
and `substitute-10k.cpp`'s (`peak_bytes<=64 allocs<=0`) keep both flat.
