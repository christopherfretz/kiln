# WP-564 — `display_string_of` of a value or object reflection renders the value, not a placeholder

The rules are spec/reflection.md §3.9 ("`display_string_of` of a value
or object") and spec/ast.md §9.3 (`print_exact`, `enum_cast`).

- **Cause.** `Sema::display_string` (`crates/kiln_sema/src/meta/names.rs`)
  answered types, declarations and templates and sent everything else to
  the reflection's note form, so a value reflection (a constant template
  argument, `reflect_constant`) printed `^^(value of type long)` and an
  object reflection (`reflect_object`, a class or reference template
  argument) `^^(object of type Pt)`. A template-id that downstream
  code spells back into generated source from `template_arguments_of`
  (`std::ratio<86400, 7>`) did not re-parse.
- **Fix.** `Sema::value_spelling` prints the constant with the
  diagnostic constant printer (`ConstStore::print_exact`, template-
  argument style, no literal suffix, `enum_cast` so a value naming no
  enumerator stays a cast, no depth or element cut) through `SpellEnv`,
  which scopes type names canonically and spells nested value/object
  reflections as their `reflect_constant` / `reflect_object` call.
  `Sema::object_spelling` prints a template parameter object as its value
  (`Pt{3}`, as GCC 16.1) and any other object as its pointer without the
  `&` (`ns::nv`, `arr[1]`, `pt.x`). When any part has no source spelling
  the placeholder stays.
- **Differences from GCC 16.1** (implementation-defined; kiln keeps
  spellings that re-parse): floating point is the shortest round-trip
  (`1e-1`), pointers have no space after `&` and a function pointer keeps
  it, a null `int *` is `nullptr`, character escapes follow diagnostics,
  subobject designators are unqualified (`pt.x`). Pinned in
  `tests/conformance/meta.reflection.names/display-string-of-values-kiln.cpp`;
  the identical rows (`display-string-of-values.cpp`,
  `display-string-of-values-ratio.cpp` over libstdc++'s real `<meta>` and
  `<ratio>`) are compared with GCC.
