### The 2026-11-21 recording (WP-1886)

The same binary, host and method as the clang 22 recording of
[perf.md](perf.md) ("The 2026-11-21 recording"), run right after it:
kiln 1.3.0 plus the commits after it on `main`, at `45d9b1cf2`, as a PGO
build (`cargo xtask build --pgo`; 44 of the entries below are its
training cases), against GCC 16.1.0 (`g++-16`), with the flags mapped as
for the GCC oracle (`oracle::gcc_args`). The host was shared with other
agents' builds (load average 11.0 at the start, 12.7 at the end).

Nine entries are `FAIL` for GCC and left out of the means. The first
three use clang extensions that kiln implements and GCC does not; the
others stop at one of GCC's default limits or are rejected by GCC:

- `frontend/simd-generate`: clang's `__make_integer_seq` builtin, which
  GCC does not have.
- `oven/builtins-strlen`: clang's `__builtin_char_memchr`.
- `oven/time-trace`: `-ftime-trace=` and `-ftime-trace-verbose` are
  clang's options.
- `frontend/templates_deep`: 1000 nested instantiations, beyond GCC's
  default `-ftemplate-depth=900`.
- `oven/churn-string`, `oven/churn-vector`: GCC's constexpr operation
  limit (`-fconstexpr-ops-limit`, 33554432 by default).
- `oven/switch-dense`: GCC's constexpr loop limit
  (`-fconstexpr-loop-limit`, 262144 by default).
- `oven/builtins-memcpy`: GCC does not evaluate `__builtin_memcpy` of 16
  KiB in a constant expression.
- `oven/trial-rollback`: GCC reports "allocated storage has not been
  deallocated" for the entry's allocations (clang 22 accepts it).

The bench runs GCC with its default limits; raising them for GCC alone
would measure a different configuration from kiln's defaults.
