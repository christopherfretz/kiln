# libstdc++ header sweep

Every public header of the system libstdc++ (`/usr/include/c++/14`, GCC 14)
compiled as a one-line TU (`#include <header>`) with
`kiln -stdlib=libstdc++ -fsyntax-only`, next to `clang++-19` as the reference.
The tables between the `libstdcxx:<std>` markers are generated by
`cargo xtask libstdcxx --std <std> --report docs/status/libstdcxx.md`
(contract: [spec/libstdcxx.md](../../spec/libstdcxx.md)); the **Clusters**
section at the end is hand-written triage of those runs (WP-188, last refreshed WP-323) and must be
refreshed by hand when the numbers move.

Timings are a debug-profile kiln at `-j 2` on a shared host: compare runs, not
absolute numbers.

### Per-cluster detail

**X — `__builtin_memcpy` ambiguous.**

- `memcpy_decl` (crates/kiln_sema/src/class/special/define.rs:1598) builds its own implicit `extern "C"` declaration for the memberwise copy of array members.
- That declaration is not redeclaration-linked with the one that `lazily_create_builtin` (builtins.rs:227) creates for a written call.
- As a result, every written call after the first array-member copy sees two candidates.
- Repro:
  ```cpp
  struct A { int a[4]; };
  void f(char* d, const char* s) { __builtin_memcpy(d, s, 1); }
  void g(A& x, const A& y) { x = y; }
  void h(char* d, const char* s) { __builtin_memcpy(d, s, 1); }  // ambiguous
  ```
- WP: one declaration per builtin. `memcpy_decl` should reuse the lazily created builtin, or the lazy one should reuse it.

**N — member partial specializations.** `use of undeclared identifier '_Const'` / `'_Rep'` / `'_Iter'` (ranges:1888, chrono:2449, stl_list.h:189): the template parameters of a partial specialization are not in scope in its member bodies. `<generator>` and `<ranges>` cascade from here into about 80 errors each:

- tuple:980–1345 undeclared concept names
- constraints on alias templates
- constexpr-if conditions

WP: constrained partial specializations of member class templates, and the parameter scope for their members.

**Y — out_ptr.** `use of undeclared identifier '_Alloc'` at bits/out_ptr.h:233 (`<execution>`, `<memory>`). Not isolated.

**Z — braced-list pack expansion.** `{__lockables, defer_lock}...` at mutex:591 (`<mutex>`, `<future>`).

**T — out-of-line member of a constrained partial specialization.** `requires clause differs in template redeclaration` (`chunk_view<_Vp>::_Iterator`). It no longer shows as a first error.
