# Open-source builds (ROADMAP M8)

M8 is robustness: real open-source C++ projects that already build with
clang are built with kiln as the C++ compiler, through each project's own
build system and test suite, and every failure becomes a reduced
`tests/conformance` case plus a fix. The exit criteria are in
docs/ROADMAP.md M8; the harness contract is spec/landed/harness/WP-666.md.
This page is the index: the per-project sections between the
`<!-- oss:... -->` markers are generated by `oss-report.py --update`, not
hand-edited. Per-project working notes live in `docs/status/oss/<project>.md`.

## Running the harness

```sh
source scripts/env.sh                         # shared jobserver for make
cargo build --profile harness -p kiln_driver  # $CARGO_TARGET_DIR/harness/kiln++
scripts/oss/oss-build.sh googletest --compiler clang   # control build
scripts/oss/oss-build.sh googletest                    # kiln build
scripts/oss/oss-report.py googletest                   # table + clusters
scripts/oss/oss-report.py --update docs/status/oss.md googletest
```

Projects and pinned tags: `scripts/oss/projects.toml`. Checkouts and build
trees go to `.oss/` (gitignored); each build writes
`.oss/build/<project>/<kiln|clang>/{report.json,compile.jsonl,*.log}`.
Every compiler invocation runs under `ulimit -v 3000000` and `timeout 600`
(`scripts/oss/kiln-cxx`); `make` draws from the box's shared jobserver.
A project with `deps` in the toml (re2 needs abseil, googletest and
benchmark) first builds and installs each dependency with the same
compiler into `.oss/<dep>-install-<compiler>/` (once; delete the directory
to rebuild) and finds them through `CMAKE_PREFIX_PATH`; dependency TUs are
logged under `.oss/build/<dep>/<compiler>-dep/` and never counted for the
dependent (spec/landed/harness/WP-666.md "Dependencies").
`scripts/oss/selftest.sh` checks the scripts. In a repro command `$KILN` is
the kiln checkout the build ran in, and `kiln++` the binary it used.

The loop:

1. **Build**: control build with clang, then kiln (`oss-build.sh`).
2. **Cluster**: `oss-report.py` groups kiln's failed TUs by normalized
   diagnostic signature; the largest cluster first.
3. **Reduce + WP**: reduce the representative TU to a standalone
   `tests/conformance/<section>/` case, open a work package, fix, re-run.

## Constexpr performance (WP-792)

Wave 4 is the constexpr-heavy projects. Each was built with kiln and
with the control compiler on the same host, once each, and compared per
TU over the TUs that compile under both (`oss-report.py --perf`,
spec/landed/harness/WP-792.md). Time is the TU's CPU time (user plus
system). RSS is its peak, which includes the LLVM backend. A ratio below
1 means kiln is faster or smaller.

| project | control | TUs | time (geomean) | RSS (geomean) | Σ CPU kiln / control | peak TU RSS kiln / control | TUs over 1.2x |
|---|---|---|---|---|---|---|---|
| `ctre` | clang-19 | 25 | 1.06x | 0.45x | 28 s / 30 s | 166 / 414 MB | 0 of 13 |
| `mp_units` | gcc-16 | 64 | 0.92x | 0.39x | 235 s / 267 s | 573 / 1539 MB | 3 of 61 |
| `daw_json_link` | clang-19 | 159 | 1.06x | 0.41x | 351 s / 343 s | 137 / 304 MB | 3 of 152 |
| `glaze` | clang-19 | 87 | 0.97x | 0.47x | 869 s / 970 s | 1658 / 2171 MB | 2 of 81 |
| `scnlib` | clang-19 | 47 | 0.97x | 0.43x | 188 s / 190 s | 717 / 827 MB | 0 of 41 |
| `reflect_cpp` | clang-19 | 317 | 0.91x | 0.39x | 804 s / 884 s | 250 / 549 MB | 0 of 315 |

- RSS is 0.39x to 0.47x of the control's in every project.
- The heaviest TUs are kiln's best ratios: glaze's `json_test.cpp` is
  0.72x time and 0.57x RSS (103 s vs 144 s), and mp_units'
  `fmt_test.cpp` is 0.69x time and 0.31x RSS against gcc-16.
- The geomean time is above 1 for ctre and daw_json_link, and it comes
  from their many small TUs of 1 to 3 s.
- All eight TUs over 1.2x are on time, never on RSS, and all are 1.20x
  to 1.31x. They are filed as perf clusters on the project pages
  (mp_units P1, daw_json_link P1, glaze P1).
- mp_units is compared with g++-16, because clang 19 cannot build
  mp-units v2.5.0.

g++-16 on the five heaviest TUs of each clang-controlled project. Each
TU was re-run alone with kiln, clang++-19 and g++-16 with the control's
command line (clang-only `-W` flags dropped for gcc), under the
harness's 3 GB address-space cap. Geomean kiln/g++-16:

| project | time | RSS | note |
|---|---|---|---|
| `ctre` | 1.21x | 0.29x | g++-16 is the fastest of the three on ctre (2.0 to 3.0 s per TU) |
| `daw_json_link` | 0.49x | 0.20x | |

| `reflect_cpp` | 0.68x | 0.21x | |

Reduced repros (WP-666, kiln at main f3751eadd):

- Cluster 1, `-W`: kiln++ rejects clang's old spelling of `-Wextra`
  (`kiln++ -W -c x.cpp`; clang accepts it). googletest's
  `cxx_strict_flags` (`googletest/cmake/internal_utils.cmake:97`) passes
  it to the strict-flag targets, `libgtest` among them, so `libgtest`
  never builds and 61 of the 63 tests have no binary.
- Masked behind cluster 1 (found by an exploratory run with a shim mapping
  `-W` to `-Wextra`: 84/85 TUs and 62/63 tests then pass): libstdc++ 14
  `std::get` on a reference to a `std::tuple` that was not instantiated
  earlier in the TU fails deduction (`tuple:2452: no matching function for
  call to '__get_helper'`, candidate note "could not match '_Tuple_impl'
  against 'std::tuple'"): the base classes of the argument's class are not
  considered because the class template specialization is not completed
  first ([temp.deduct.call]/4.3, [temp.inst]/2). Repro, at any `-std`:

  ```cpp
  #include <tuple>
  int g(std::tuple<int, int>& a) { return std::get<0>(a); }
  ```

  A `std::tuple<int, int> x;` before `g` makes it compile; `-stdlib=libc++`
  is unaffected. googletest TU: `googlemock/test/gmock-actions_test.cc`.

Both are fixed by WP-682, which brought googletest to parity with the
clang build. Its working notes are in `docs/status/oss/googletest.md`.
