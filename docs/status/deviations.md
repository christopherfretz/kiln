# Deliberate deviations from the oracle

Behaviours where kiln follows the standard rather than clang (the oracle,
docs/VALIDATION.md), because clang's behaviour is a defect rather than a
choice. Each row names the rule kiln implements, what clang (and GCC)
do, the spec paragraph that states it, and the corpus test that pins it
(skipped under clang with `skip(clang)`, or pinned to a release with
`requires:`, spec/harness.md). Smaller, codegen-only differences are
listed where they live (spec/codegen.md "Deviation" paragraphs).

| Rule | kiln | clang / GCC | Spec | Test |
|---|---|---|---|---|
| [temp.point]/7, [temp.inst]/7: the end of the TU is a point of instantiation of a variable template specialization or static data member usable in constant expressions that is odr-used only before its template's definition (WP-490) | defined from the later definition at the end of the TU, no warning | clang instantiates such a variable only at a reference (`DoMarkVarDeclReferenced` never queues it) and leaves it undefined; GCC 14/16 too; both fail to link | spec/sema-templates.md §4.6 "Initializers" | tests/conformance/temp.point/var-template-end-of-tu-instantiation-run.cpp |
| [GNU] compound literal (C99 6.5.2.5p5), [temp.inst]: a literal in a constexpr variable template or a class template's default member initializer is at file scope wherever the specialization is instantiated from (WP-490) | a file-scope object of static storage duration at every compat level, as clang 19 and GCC 16 | clang 21+ (llvm-project 977d8a4bcd83, `Scope::isInCFunctionScope` on the parser's scope) makes it a block-scope temporary when it is instantiated from a function body: clang 22 warns `-Wdangling` and rejects the constexpr initialization | spec/sema.md §5.8 "Compound literals" Deviations | tests/conformance/ext.gnu.compound.literal/variable-template-from-function-run.cpp |

## GCC 16.1 reflection divergences

Behaviours where kiln's reflection follows the IS rather than GCC 16.1,
the reflection oracle (`oracle: gcc`, spec/reflection.md §1.2). Each was
triaged when the GCC differential found it (docs/plans/m6-reflection.md
§5, exit measure (e)).

| Rule | kiln | clang / GCC | Spec | Test |
|---|---|---|---|---|
| [meta.reflection.traits]/3.2: a [meta.reflection.traits] function whose associated trait specialization would have undefined behavior because of an incomplete type ([meta.rqmts]/5, [res.on.functions]/2.5; the Preconditions column of [meta.unary.prop] for `is_copy_constructible` asks for "a complete type, cv void, or an array of unknown bound") is not a constant subexpression: `std::meta::is_copy_constructible_type(^^T)`, and the other type-trait functions, with `T` an incomplete class type | the call is not a constant expression, with the note "invalid use of incomplete type 'T'"; kept by the operator's decision (2026-11-05) | clang has no reflection. GCC 16.1 returns a value: `false` for `is_copy_constructible_type(^^T)` and `is_constructible_type(^^T, {})`, `true` for `is_trivially_copyable_type(^^T)`; it diagnoses `is_empty_type(^^Tmpl<int>)` as kiln does | spec/reflection-traits.md §2.2 | tests/conformance/meta.reflection.traits/failures-neg.cpp |
| [temp.variadic]/5.4: the pattern of a base-specifier pack expansion is the whole base-specifier, so an annotation operand naming the pack (`[[=sizeof(Bs)]] Bs...`) is substituted per base, and one on a base-specifier that is not an expansion is the unexpanded-pack error | kiln: one annotation per base with that base's value; the error at the template definition | GCC 16.1: internal compiler error in `dependent_type_p` at instantiation (both forms); no error at definition | spec/annotations.md | `meta.reflection.annotation/base-specifier-pack-operand.cpp`, `base-specifier-pack-operand-neg.cpp` (WP-867) |
| [expr.const.const]/1, /3 (P4101R1): the null reflection is not a consteval-only value, so an object holding only null reflections is not an immediate object and needs no `constexpr` (`std::meta::info x;`, `S s;` of a class with an `info` member, `info* p;`, `const info c = info{};`, `thread_local info t;`) | accepted (WP-1328), and since WP-1361 they exist at run time: a run-time `info` is a pointer-sized null (spec/codegen.md "Run-time reflections") | GCC 16.1 (P2996R13 consteval-only types) rejects each: "consteval-only variable 'x' not declared 'constexpr' used outside a constant-evaluated context" | spec/reflection-repr.md §6 | `expr.const.const/p1-null-reflection.cpp`, `expr.const.const/p1-runtime-null-reflection-run.cpp`, `expr.reflect/reflection-mangle-neg.cpp`, `basic.types.general/consteval-only.cpp` |
| [expr.const.const]/2, /5 (P4101R1): a `constexpr` object whose reflections are all null is not an immediate object, so its other members may be read at run time (`puts(s.name)` of `constexpr S s{{}, "x"}`) | accepted; the reads fold (the object is an ordinary constant, WP-1361) | GCC 16.1 rejects the read: "consteval-only expressions are only allowed in a constant-evaluated context" | spec/codegen.md "Consteval-only variables" | `expr.const.const/p2-not-immediate-run.cpp` |
| [expr.const.imm]/3, [expr.const.const]/1.1 (P4101R1): a function whose type holds `std::meta::info` (a parameter, a return type, a class with an `info` member) need not be `consteval`; only its body's consteval-only values are judged (`info id(info x) { return x; }`, a virtual, lambda, template or member function, a function or member pointer to one) | accepted (WP-1361); a run-time `info` is the null reflection | GCC 16.1 (P2996R13) rejects each: "function of consteval-only type must be declared 'consteval'" | spec/reflection-repr.md §6 "Functions" | `expr.const.const/p1-runtime-null-reflection-run.cpp` |
| [expr.const.const]/1, /3.1, /4 (P4101R1, carrying P3603): a `constexpr` variable may hold a pointer to an immediate function (`constexpr auto b = plus1;`, a `constexpr` array or aggregate of them, `constexpr auto e = g();` of /5 Example 2), and calls through it are immediate constant expressions | accepted in every manifestly constant-evaluated context; outside one, a call through `b` escalates or is an error | GCC 16.1 rejects the variable: "constant evaluation returns address of immediate function" | spec/reflection-repr.md §6 "No permitted-result restriction" | `expr.const.const/p3-immediate-function-pointer-run.cpp`, `expr.const.const/p3-immediate-function-pointer-neg.cpp`, `expr.const.const/p3-example1-immediate-function.cpp`, `expr.const.const/p5-example2-immediate-result.cpp` |
| [bit.cast]/2 (P4101R1: "Constant When: Neither To nor From has constexpr-unknown representation"; [expr.const.core]/1.2): `std::meta::info` is scalar, so trivially copyable, and a bit cast from or to it (or a class holding one) is well-formed; only a constant evaluation of it is not a constant expression | accepted at run time; in a constant expression "bit_cast from a type with constexpr-unknown representation ('std::meta::info') is not allowed in a constant expression" | GCC 16.1 makes each cast ill-formed: "'__builtin_bit_cast' cannot be used with consteval-only types" (it agrees `info` is trivially copyable) | spec/reflection.md §2.5 | `reflection/bit-cast-info-run.cpp`, `reflection/bit-cast-info-neg.cpp` |

| [expr.const.const]/5.1, [expr.const.imm]/2.1 (P4101R1): a glvalue referring to an immediate object is an immediate constant expression, so copying a member of one into a non-`constexpr` local (`const char* n = e.name;` of an expansion variable or a `constexpr` local holding a reflection) is ill-formed outside an immediate function context | rejected | GCC 16.1 accepts it (it folds the initializer and finds no consteval-only type in it) | spec/reflection-repr.md §6 | `stmt.expand/consteval-only-element-copy-neg.cpp`, `expr.const.const/p5-immediate-glvalue-neg.cpp` |
