# libc++ M3 gate status

This page tracks kiln against the libc++ tests the M3 exit criteria name (ROADMAP M3; the gate list
is `GATE_M3` in `xtask/src/libcxx/mod.rs`). The contract is `spec/libcxx.md`. The section between
the `libcxx` markers is generated; everything outside it is written by hand.

Regenerate with:

```sh
scripts/fetch-libcxx-tests.sh                 # once: sparse llvmorg-19.1.7 checkout under .toolchain/
cargo xtask libcxx --gate m3 -j 2 --report docs/status/libcxx-m3.md
```

## Setup

- kiln: debug build of the WP-140 branch (commit in the generated "Run" table below), which
  includes main at `46231cd`.
- Tests and headers: libc++ `llvmorg-19.1.7`. The tests come from the sparse checkout. The headers,
  `libc++.so`, `libc++experimental.a` and `libc++abi` come from the clang 19 packages in the
  container.
- Host: aarch64 Debian 13 container, with `-j 2` and an 8 GiB address-space cap per process.
- Driver: lit-format subset with a static feature set. `.verify.cpp` tests are UNSUPPORTED by the
  driver because kiln has no `-verify`. See `spec/libcxx.md`.

## Reading

**Overall: 251/585 (42.9%)**, up from the WP-081 baseline of 20/585. Nearly every failure is still
at the compile stage; 3 tests reach link and fail there. There are no KILLED, TIMEOUT or hang
results. Peak RSS was 72 MiB and wall time about 3 minutes.

WP-140 removed the three harness-wide blockers of the baseline. Gate after each step:

| step | pass | what it unblocked |
|---|---:|---|
| baseline (WP-081) | 20 | — |
| GNU `asm` statements | 180 | `test_macros.h` `DoNotOptimize`/`ClobberMemory` (273 first errors) |
| `__PRETTY_FUNCTION__`/`__FUNCTION__`/`__func__` | 244 | `assert()` from `<cassert>` (102 first errors) |
| constexpr `__builtin_strcmp` and the other C string builtins | 244 | `<typeinfo>`'s comparisons; the first error moved to the next line of `<typeinfo>` |
| typedef-name qualifier at the start of a declaration | 251 | `<typeinfo>` `__impl::__type_name_t __type_name;` |

Per directory, baseline → now: meta 6 → 112/148, utility 6 → 25/145, array 2 → 23/37,
string.view 3 → 19/88, span 2 → 3/35, bit 0 → 12/15, support.limits 1 → 52/112,
initlist 0 → 5/5.

**What blocks the rest.** One crash dominates:

1. **Panic at `kiln_ast/src/decl.rs:1907` "decl has no Function payload" (214 tests, 64% of the
   failures).** Any test that transitively includes `<string>` reaches it, because the panic
   happens while instantiating `basic_string<char>` from `_LIBCPP_STRING_V1_EXTERN_TEMPLATE_LIST`
   (`templ/subst/decls.rs`). It accounts for nearly all of the utility, string.view and span failures
   and 25 of the 60 support.limits failures.

Behind it, the first-error clusters are small and spread out:

2. `'…' does not refer to a value` (22 first, 137 any). For example
   `__atomic/memory_order.h:40`, `underlying_type<__legacy_memory_order>::type` in an expression.
3. `expected '…' or '…'` (14 first, 249 any): `<tuple>:471`, together with the NYI
   `partially substituted pack expansion` (249 any).
4. `use of undeclared identifier` (13 first, 126 any). For example `__builtin_fabsf` in the
   `<limits>` tests.
5. `function '…' with deduced return type cannot be used before it is defined` (9 first):
   `__get_iter_concept`.

Then come the NYI `__is_trivially_assignable` and other type traits (8 first, 48 any), wrong
`static_assert` values, and `constructor cannot be redeclared` (93 any). Among the clusters that
are never first: `excess elements in scalar initializer` (238 any), anonymous member classes of
class templates (191 any) and the `basic_string::__short` layout (157 any) will surface once the
panic is fixed.

**Caveats.**
- The driver only checks that a `.compile.fail.cpp` test fails to compile without a crash, not
  that it fails with the diagnostic it targets.
- XFAILs written against compiler identity (`clang-*`, `gcc-*`) evaluate to false, because the
  feature set names only `kiln`.

**Candidate work packages, in order of gate impact:**
1. The `decl.rs:1907` panic on `<string>` (214 tests).
2. `'…' does not refer to a value` for a member type in an expression (`<atomic>`).
3. Partially substituted pack expansion (`<tuple>`).
4. Undeclared identifiers, such as the `__builtin_fabsf` builtin.
5. Deduced return type used before it is defined (`__get_iter_concept`).
6. `excess elements in scalar initializer` (238 any).
7. Anonymous member classes in class templates (191 any).
8. basic_string `__short` layout (157 any).
9. `__is_trivially_assignable` and other type-trait builtins.
10. `-verify` (51 driver-unsupported tests).
11. The `FnSpec` panic (`is_abstract.pass.cpp`).
