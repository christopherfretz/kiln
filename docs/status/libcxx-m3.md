# libc++ M3 gate status

This page tracks kiln against the libc++ tests the M3 exit criteria name (ROADMAP M3; the gate list
is `GATE_M3` in `xtask/src/libcxx/mod.rs`). The contract is `spec/libcxx.md`. The section between
the `libcxx` markers is generated; everything outside it is written by hand.

Regenerate with:

```sh
scripts/fetch-libcxx-tests.sh                 # once: sparse llvmorg-19.1.7 checkout under .toolchain/
cargo xtask libcxx --gate m3 -j 2 --report docs/status/libcxx-m3.md
```

## Setup

- kiln: debug build of the WP-167 branch (commit in the generated "Run" table below), which
  is main at `bcd1fdf7` (WP-154 merged) plus WP-167.
- Tests and headers: libc++ `llvmorg-19.1.7`. The tests come from the sparse checkout. The headers,
  `libc++.so`, `libc++experimental.a` and `libc++abi` come from the clang 19 packages in the
  container.
- Host: aarch64 Debian 13 container, with `-j 2` and an 8 GiB address-space cap per process.
- Driver: lit-format subset with a static feature set. `.verify.cpp` tests are UNSUPPORTED by the
  driver because kiln has no `-verify`. See `spec/libcxx.md`.

## Reading

**Overall: 364/585 (62.2%)** on the WP-167 branch, up from 332 on main (319 after WP-146, 317
after WP-149, 307 after WP-142, 254 after WP-141, 20 at the WP-081 baseline). WP-167 fixed the
template-head check for friend class templates declared in a class template (the `type
constraint differs in template redeclaration` cluster, 28 first): 35 gate tests reported it, and
12 of them now pass. 41 tests now compile and fail at link with undefined
`__shared_ptr_pointer` vtable members (`__on_zero_shared`, `__get_deleter`), which is WP-164.
There are no crashes, and no KILLED, TIMEOUT or hang results.

WP-149 (`docs/status/wp-149-progress.md`) cleared these clusters:

- operator names in using-declarators (28 first);
- destructor template-ids (8 first);
- local using-directives in templates (108 any);
- `_Atomic(T)` as a type specifier;
- explicit object parameters (58 any).

`<variant>` drops from 42 errors to 22.

**What blocks the rest:**

1. `use of undeclared identifier` (60 first, 158 any). These are now mostly the atomic builtins
   that `_Atomic(T)` exposes: `__c11_atomic_*`, `__atomic_*` and `__atomic_always_lock_free`.
2. The link stage (41 first): `__shared_ptr_pointer` vtable members are not emitted (WP-164).
   Of the 35 tests WP-167 unblocked, the 23 still failing stop at `redefinition of 'iter_move'
   as different kind of symbol` (13: a hidden friend `iter_move` in a view's nested iterator
   against the `ranges::__cpo::iter_move` variable), `too few template arguments for concept
   'same_as'` (3: `std::same_as<T> decltype(auto) v = ...`), `typename` using-declarators (3),
   initializer-list constructors (2), a `size` call (1) and the link stage (1).
3. NYI type traits (25 first, 77 any), such as `__is_trivially_assignable` and
   `__is_trivially_constructible`.
4. `variable template partial specialization does not specialize any template argument` (20
   first, 44 any).
5. `unknown type name '__SVFloat32_t'` (14 first, 52 any). These are the AArch64 SVE builtin
   types.
6. `call to 'operator new' is ambiguous` (14 first).

Among the clusters that are rarely first:

- `no member named` (103 any);
- out-of-line member class definitions of class templates. For example
  `class basic_ostream<_CharT, _Traits>::sentry {`, which gives `expected '(' for function-style
  cast` (58 any) and `expected expression` (60 any). These block `<chrono>`, `<ostream>` and
  `<format>`.
- `variant:1141`: partial substitution of a non-type template parameter pack.

**Caveats.**
- The driver only checks that a `.compile.fail.cpp` test fails to compile without a crash, not
  that it fails with the diagnostic it targets.
- XFAILs written against compiler identity (`clang-*`, `gcc-*`) evaluate to false, because the
  feature set names only `kiln`.
