# Precompiled headers: the declaration image consumer (WP-1036, 2026-11-11)

This page measures what the PCH declaration image (spec/driver.md, "The
declaration image") buys today, and how much of the standard library it
carries. The short answer is nothing yet. No standard header set larger
than the C-compatibility headers is carried. Every realistic prefix is
replayed, so a kiln PCH costs about what textual inclusion costs.
Widening coverage is WP-1283/1284. The consumer, the fallback and the
differential that keeps the two paths equal are in place for that work.

## Setup

The numbers below are generated by `cargo xtask bench bench/pch --record`
(spec/bench.md "The pch group", WP-1294). Re-run that command after a PCH
change; `--record --label <name> --compiler <kiln++>` adds a region for
another build, such as a branch that widens the image. Everything outside
the generated regions is hand-written and kept by the generator.

- kiln is the release build (`cargo build --release -p kiln_driver`),
  clang is clang 19 (Debian). Both run back to back on each row, on a
  shared aarch64 host whose load moves wall times about 1.4x, so the
  kiln-to-clang ratios are steadier than the absolute times. Peak RSS
  moves a few percent between identical runs (below); kiln's accounted
  memory does not.
- Each number is the median of 5 runs: wall time from the harness, peak
  RSS from `/usr/bin/time -f %M`.
- Header sets (`bench/pch/<case>.h`):
  - `gnu`: `#include <bits/stdc++.h>` (libstdc++ 14).
  - `lcx`: the 106 public libc++ 19 headers, one `#include` each, with
    `-stdlib=libc++` (the set of
    [pch-image-census.md](pch-image-census.md)).
  - `mid`: `<algorithm>`, `<map>`, `<string>` and `<vector>`
    (libstdc++ 14).
  - `c`: `<stdio.h>`, `<stdlib.h>`, `<string.h>` and `<zlib.h>`, as C17
    (`-x c-header`, then `-x c` for the unit).
- The C++ translation unit (`bench/pch/<case>.cpp`) uses `std::vector`,
  `std::sort`, `std::map` and `std::string`, with no `#include`s of its
  own. The C one calls `strncpy`, `crc32`, `printf` and `atoi`.
- Rows (`-std=c++26`, or `-std=c17` for `c`):
  - "no PCH": `-include <case>.h`.
  - "PCH build": `-fkiln-pch-image -x c++-header <case>.h -o <case>.pch`
    (clang without `-fkiln-pch-image`).
  - "PCH load": `-fkiln-pch-image=load -include-pch <case>.pch` (clang
    `-include-pch <case>.pch`). The row names the path kiln took.
  - "PCH replay": `-fno-kiln-pch-image -include-pch <case>.pch`, kiln only.
  - `-O0 -c` rows write an object file; nothing is written to `/dev/null`.
  - "check" (`-fkiln-pch-image=check`) is not timed: it compiles twice by
    design. The bench runs it, untimed, on every case whose consumer takes
    the image.

## Reading the numbers

A kiln consumer that replays costs the same as no PCH, within noise. The
record is the only part read, and replay parses the header in full.
On the C++ header sets, clang's PCH consumer is several times faster
than its own no-PCH build (each case's "Wall time of PCH load relative to
no PCH" line). That is the gap the image has to close once it carries
these headers. The C set is too small for a PCH to matter to either
compiler. kiln's peak RSS is already well
below clang's on every row, PCH or not.

### Memory noise and the accounted figure (WP-1303, 2026-11-11)

Five recordings of the `none` variants on one unchanged release
`kiln++` (load 10.6 to 17.2), 5 runs each:

- Peak RSS is not steady. The median moved by up to 6.4% between
  recordings (`c/none-syntax`, 13 MB), 3.5% (`gnu/none-obj`), and about
  2.2% (`gnu`, `lcx` and `mid` at `-fsyntax-only`). The minimum of the
  runs moved as much, and the high samples did not follow the load.
- kiln's accounted memory (`-fkiln-memory-report`, total reserved bytes)
  was byte-identical over 10 runs of every `none` variant and in two
  working directories, while the RSS of the same runs moved 4%. The
  noise is outside kiln's tables. Transparent huge pages (`always` on
  this host) are the suspect, unproven.
- At `-O0 -c` the RSS figure is the largest process, and for `mid` and
  `c` that is `llc`, not kiln (58 and 55 MB, against kiln's 56 and
  15 MB). Those rows measure LLVM.

So peak RSS is judged at 5% on every row, and the `none` rows are also
judged on the accounted figure at 2% (spec/bench.md "The pch group").

The re-record of 2026-11-11 (main `876dfe167`) reported six `-O0 -c`
rows of `mid` and `c` as about 10% smaller. Those rows are
llc-dominated, so this is not a kiln improvement.

## WP-1293: block-scope declarations (2026-11-11)

The image now carries block-scope `extern` and function declarations
as local records, listed in `local_externs` order, and a consumer
links its own namespace-scope redeclarations to them as replay does
([basic.link]/6). A PCH consumer also re-records the header's C-linkage
entities ([dcl.link]/6-7). The producer's state check now refuses only
a pending `#pragma weak`. kiln at the WP-1293 branch, `debug` profile
for the census and the corpus, `harness` for the libc++ gate.

- **libstdc++ 14 (109 headers):** all 109 pass the state check (73 were
  refused there before). None is carried yet: each is first refused for `a type the
  image does not carry`.
- **`<bits/stdc++.h>`:** the first remaining replay reason is `a type
  the image does not carry`, for `typedef decltype(nullptr)
  nullptr_t;` (`<bits/c++config.h>`:314). The census
  (`-fkiln-bmi-image-census`) counts 26733 top-level declarations,
  18247 carried. Its largest reasons are cascades from templates
  (767 specializations, 746 alias templates), 738 types, 652
  cascades from a type declared outside the image and 606 templates.
- **libc++ 19 (the 105 headers of `/usr/include/c++/v1`):** 9 carried,
  `<cfenv>` added. Their union is one image of 222 records. `<cfenv>`'s
  "internal image inconsistency" was the validator rejecting an
  unnamed unscoped enumeration with no typedef name
  (`enum { FE_INEXACT = ... };` in `<fenv.h>`); it is valid
  ([dcl.enum]/2) and now validates.
- **Corpus `--pch-diff check`** (conformance PCH and module
  directories, `tests/differential`, `tests/header-guard`): 147
  compared, all equal, 25 took the image (was 17 of 141). Replay
  reasons: a type 65, a template argument 22, a member function
  template 13, a specialization outside the image 7, an attribute 4, a
  class member outside its class 4, a default template argument 2,
  side data 2, and one each for a type declared outside the image, an
  adjusted parameter and a member template.
- **libc++ M3 gate under `--pch-diff check`:** 636 pass + 6
  unsupported, as without a PCH (199 s). 575 tests had a PCH and all
