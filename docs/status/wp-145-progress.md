# WP-145 — WP-141 follow-ups and panic sweep (kiln_ast, kiln_abi, kiln_llvm, kiln_driver)

Rule (docs/AGENTS.md item 5): anything derivable from user input is a
diagnostic, never a panic. This file records the sweep of `panic!`,
`unwrap()`, `expect(`, `unreachable!`, `assert!`, `todo!` and
`unimplemented!` in the four crates' non-test code (inline `#[cfg(test)]`
blocks and `tests.rs` excluded), as of branch
`wp/145-141-followups-panic-sweep`. It completes the sweep WP-141 began
(kiln_parse, kiln_sema, kiln_oven, kiln_codegen).

Classes: **(a)** an internal invariant (the input cannot reach it, or only
through a bug elsewhere); **(b)** reachable from user input; **(c)** dead.

## Result

No (b) or (c) site. `todo!` and `unimplemented!` have no occurrences.
The sweep's evidence that no (b) site hides behind an (a) label is
dynamic as well as by reading: the 131-header no-crash guard and the
libc++ verify/compile.fail sweep below found no crash.

## (a) internal invariants

### kiln_ast (167), by group

- **Kind/payload accessors (36 + 19 helper calls).** `Exprs::expect_kind`,
  `StmtStore::expect`, the decl payload accessor macro (`$mut_name`) and
  the `as_*`/`*_payload` asserts in decl.rs, expr.rs, stmt.rs,
  templates.rs and ast.rs. Sema calls each accessor on the kind it read;
  a mismatch is a Sema bug, never input (spec/ast.md). WP-141's two
  M3-gate crashes were of this group and were fixed at the Sema call
  sites, not here.
- **Aux/word decoding (36).** `from_u8(..).expect("valid …")`,
  `unreachable!()` over 2-bit tags, ConstStore record decoding and the
  lookup.rs "in range" iterators. They decode values the AST itself wrote;
  no external byte stream reaches them.
- **Fresh side-table inserts (25).** `builder.rs` `cold.*.insert(e, ..)
  .expect("fresh expression")` and `templates.rs:929` — the id was just
  allocated, so the slot is empty.
- **Late-setter discipline (21).** FnSpec/VarSpec LATE fields, MONOTONE
  flags, constant-evaluation state, the begin/end of enum and record
  definitions, member lists, `ast.rs` context setters and builder
  ordering (`builder.rs:405`, `1019`, `1540`–`1541`). They enforce the
  order Sema calls setters in.
- **Id and pool capacity (16).** `ids.rs:48`, `lists.rs:38`–`42`,
  `decl.rs:629`/`1824`/`2387`/`2390`, `expr.rs:1297`, `stmt.rs:297`/`349`,
  `lookup.rs:205`/`241`, `names.rs:55` and `strings.rs:104` (a 4 GiB string
  pool). Each needs more than 2^29–2^32 entries; the memory cap
  (`mem<=`, `ulimit -v`) stops a run long before.
- **Builder API preconditions (13).** `builder.rs:2182`/`2545`,
  `decl.rs:2192`/`2200`/`2279`/`2584`, `expr.rs:1656`/`1678`/`1802`/`1924`/`1968`/`2024`,
  `consts/value.rs:48` (IntBits width 1..=128; every caller passes a
  bounded bit width). These are argument contracts between Sema and the
  builder (operator kind, cast kind, value-dependence, storage duration).
- **Compile-time check (1).** `consts/mod.rs:74` `const _: () = assert!(..)`.

### kiln_abi (3)

### kiln_llvm (9)

runs only on a TU without errors, so Sema has already rejected anything
that could violate them.
- `intrinsics.rs:136` — `add_function` with a type `types.function` just built.
- `module.rs:631`, `680`, `697`, `734` — pointer type lookup and

- `module.rs:1155` — at most 255 sync scopes; codegen never interns a
  named sync scope (it uses the system default).
- `types.rs:621` — `write_definition` on an identified struct only.
- `value.rs:181`, `216` — decoding `Value::NONE`, and a block operand
  read from a slot the builder wrote as a block.

### kiln_driver (1)

## Dynamic checks

- **libc++ header no-crash guard** (`tests/header-guard`, generated by
  `cargo xtask gen-pp-corpus --no-crash`, run by `cargo xtask stress`):
  131 tests (libcxx 106, libcxx-c 19, libcxx/experimental 6) pass with no
  crash. It takes 74 s at `-j 2` (118 s CPU), over the 60 s `ci` budget,

- **libc++ verify/compile.fail sweep** (687 `*.verify.cpp` and

  no run crashed, hung or exited other than 0 or 1.

## Other items

- **Item 3 (invalid function template specializations).** A failed
  statement that adds an error makes the specialization INVALID, and an
  INVALID function's body yields an error-typed result, as clang does
  (spec/sema-templates.md §5.5). Exceptions: DeclStmt initializer failures,
  lambda bodies, and statements that only name invalid entities.
  Test: `tests/conformance/temp.inst/invalid-body-substitution-failure.cpp`.
- **Item 4 (`static_assert` requirement drops `&`).** Casts to a reference
  type print their `&`/`&&` (`dump/names.rs` `written_cast_type`).
  Test: `tests/conformance/dcl.pre/static-assert-reference-cast.cpp`.
- **Item 5.** `expect: no-crash` runs with `-ferror-limit=0` (spec/harness.md).
- **WP-157.** xtask's jobserver client returns its tokens on SIGINT and
  SIGTERM; `cargo xtask jobserver status|refill`; spec/harness.md says
  SIGKILL cannot be handled.
